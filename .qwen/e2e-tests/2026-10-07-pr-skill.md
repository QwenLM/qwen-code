# `/pr` Bundled Skill E2E Test Plan

Status: partially executed on 2026-10-07. Scenarios 1, 6 and 9 ran headless
against a disposable local repository; scenarios 3 and 4 and a no-template
`create` ran in the interactive TUI (tmux, `default` approval mode) against two
real GitHub repositories owned by the tester. Remaining scenarios are pending.

## Goal

Verify that `/pr` drafts a PR from repository conventions, never mutates
anything without confirmation, handles dirty trees, the default branch and
existing PRs, and binds created PRs to the session.

## Setup

- Use a disposable test repository or fork on GitHub with a
  `.github/pull_request_template.md`. Never run against upstream.
- Build and run the CLI from this branch: `npm run bundle && node dist/cli.js`
  inside the test repository.
- `gh auth status` succeeds for the test account. Have a feature branch with at
  least one commit ahead of the default branch.

## Scenarios

### 1. Prepare

1. Run `/pr`, then `/pr prepare`.
2. Expect a title and body that follow the repository template and commit style.
3. Expect no `git push`, no PR created, and no permission prompts for the
   read-only commands (`git status`, `git diff`, `git log`, `gh pr list`, etc.).

### 2. Dirty working tree

1. Modify a tracked file and add an untracked file, then run `/pr create`.
2. Expect the changed files listed and a question.
3. Answer "commit first": expect a ready-to-copy `/commit ...` line, and no
   commit and no push.
4. Re-run and answer "continue without them": expect the excluded files listed
   and the flow to proceed.

### 3. Create from the default branch

1. Check out the default branch with a local commit and run `/pr create`.
2. Expect a branch-name proposal, then a prompt for `git switch -c`, a prompt
   for `git push`, and a prompt for `gh pr create`.
3. Expect the PR URL printed, and the PR bound to the session.

### 4. Existing PR

1. Re-run `/pr create` on the branch from scenario 3.
2. Expect the existing PR found, a diff of title and body, and a question.
3. Answer "no": nothing changes. Re-run and answer "yes": expect a prompt for
   `gh pr edit` and the PR updated. Expect no duplicate PR.

### 5. Draft and base

1. Run `/pr create --draft --base <other-branch>` on a new branch.
2. Expect a draft PR targeting `<other-branch>`.

### 6. No `gh` or unauthenticated

1. Run with `gh` removed from `PATH`, then with `GH_CONFIG_DIR` pointing to an
   empty directory.
2. Expect a clear message in both cases and no push.

### 7. AUTO approval mode

1. Start in AUTO approval mode and run `/pr create`.
2. Expect the skill's allow rules to be active (not stashed), and mutating
   commands to follow the AUTO mode rules.

### 8. Model invocation disabled

1. Ask the model to open a PR for the branch.
2. Expect `pr` to be absent from the skills listing and not invoked by the model.

### 9. Unknown argument

1. Run `/pr bogus`.
2. Expect usage output and no commands executed.

## Results

Finding from the first interactive run (epyxid): the model prefixed every command with `cd <repo> &&`, which makes read-only `git status` / `git diff` ask for confirmation, and ran `mkdir` before writing the body. `SKILL.md` now forbids both; the tnk9x run after the fix showed no prompts for read-only commands.

Run with the built CLI (`node packages/cli/dist/index.js -p "/pr ..." --approval-mode yolo --output-format stream-json`)
in a disposable repository whose `origin` is a local bare repository, with a
`.github/pull_request_template.md` and two commits ahead of `main`. Headless
`-p` in `default` mode removes the shell and write tools entirely
(`packages/cli/src/config/config.ts`, non-interactive exclusion), so these runs
use `yolo` and check the skill's flow from the recorded tool calls; the
permission rules themselves are covered by unit tests.
