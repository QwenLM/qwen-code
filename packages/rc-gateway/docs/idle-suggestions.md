# Idle suggestions (opt-in)

When a session finishes a turn and goes idle, the gateway can surface a few
**next-step suggestions** (rendered as clickable chips in the web UI, and as an
`idle_suggestions` frame on `GET /rc/events`). They are suggestions only —
clicking one fills the prompt box; nothing is ever sent automatically.

This feature is **OFF by default.** This page explains why, and how to turn it
on.

## Why it's off by default

The OpenSpec design assumes the _daemon_ generates the suggestion in-process, so
the conversation never leaves the workstation. This fork takes a different route
(**Option B**): the gateway makes its **own** call to an external model, sending
a short tail of the session's recent transcript off-box to generate the
suggestions. It never touches the daemon session — no synthetic prompt, no
transcript pollution, no viewer noise — but it _does_ cross a trust boundary the
daemon design never crossed.

So the default is **opt-in**, not opt-out. A workstation that merely has model
credentials sitting in its environment must never start shipping transcript
content to a model until the operator deliberately enables it. (If no coherent
model credentials resolve at all, the feature is inert regardless of the flag —
the gateway never guesses where to send your content.)

The trade-off is **discoverability**: if you don't enable it, you won't see it.
That's the intended cost — see the per-session control below for the in-UI hint.

## Enabling it

Either is sufficient (the env flag forces it on regardless of the file):

- **Config file** — set `enabled: true` in `~/.qwen/rc/idle.yaml`:

  ```yaml
  enabled: true
  maxSuggestionsPerHour: 5 # per-session rolling-hour cap (1–60, default 5)
  maxSuggestions: 3 # suggestions per firing (1–10, default 3)
  ```

  The file is **hot-reloaded** (250 ms debounce) — no restart needed. A malformed
  edit keeps the previously-good config and audits `idle_config_parse_failed`
  (it never crashes the gateway or silently disables the feature).

- **Environment** — set `QWEN_RC_IDLE_SUGGESTIONS=1` (also `true`/`yes`/`on`).
  This forces `enabled: true` and survives idle.yaml reloads, so a file edit can
  never silently turn off something you enabled via the environment.

### Model credentials

Suggestions are generated by an external, OpenAI-compatible chat endpoint. The
`(apiKey, baseUrl, model)` triple is resolved as a **coherent set from one
source** (never a key from one provider against another's host), in this order:

1. `QWEN_RC_SUGGEST_API_KEY` + `QWEN_RC_SUGGEST_BASE_URL` — the dedicated knobs.
2. `OPENAI_API_KEY` + `OPENAI_BASE_URL` — reuse an existing OpenAI-compatible setup.
3. `DASHSCOPE_API_KEY` — uses the DashScope OpenAI-compatible base URL.

The model name (not host-sensitive) may be overridden with
`QWEN_RC_SUGGEST_MODEL`, then `OPENAI_MODEL`; otherwise it defaults to
`qwen-turbo`. If none of the above yields a coherent key+host, idle suggestions
are inert even when `enabled: true`.

The spec's `idleAfterSec` and `syntheticPrompt` keys are accepted but **ignored**
in this fork: idle is detected from the daemon's active-prompt edge (no timer),
and the gateway builds its own prompt. A spec-shaped file still loads.

## Per-session control (`/suggest on | off | status`)

A write-scoped client can override the setting for one session for the lifetime
of that session:

- `POST /rc/session/:id/idle-suggest-toggle` with `{ "enabled": false }` —
  **disable** suggestions for this session.
- `POST` with `{ "enabled": true }` — revert this session to the global default.
- `GET /rc/session/:id/idle-suggest-toggle` — report effective state:
  `{ sessionId, available, enabled, globalEnabled, maxSuggestionsPerHour,
remainingThisHour }`.

In the web UI this is an **"idle suggestions"** checkbox under the prompt box,
with a status line showing the remaining hourly budget.

**Important — the toggle can only narrow, never widen.** A per-session
`enabled: true` does **not** turn the feature on when the global switch is off:
the store records your intent, but the response reports `enabled: false` and no
suggestions fire. This is deliberate — a remote write-scoped client is not
necessarily the operator sitting at the workstation, so it must not be able to
start transcript egress that the operator hasn't enabled via `idle.yaml`. If you
POST `true` and see no suggestions, check `globalEnabled` in the status response
(or the UI hint) and enable the feature globally as above.

## Privacy & audit

- Idle suggestions are audited **count-only** (`idle_suggested` with a count) —
  never the suggestion text, the prompt, or any transcript content.
- Rate-limited firings audit `idle_suggest_rate_limited` (once per burst).
- Toggling audits `idle_toggle_set` with the boolean flag only.
- The recent-transcript tail sent to the model is bounded (a few recent turns,
  size-capped); it is sent only to the resolved model endpoint, only while the
  feature is enabled.
