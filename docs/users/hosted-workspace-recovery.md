# Hosted Workspace operator recovery

[English](hosted-workspace-recovery.md) | [简体中文](hosted-workspace-recovery.zh-CN.md)

Use this procedure only for a Linux durable local-process worker on the original host whose incomplete Hosted Shell capture has retained a Workspace lease. A reboot between `prepare` and `complete` does not clear the fence; the operator must still verify that all potential writers are stopped and cannot restart, then submit proof with `complete`. Recovery makes the physical Workspace available to new Sessions. It does not finish, retry, or certify the original Shell call.

The maintenance command is shipped as `qwen-managed-agent-server-*-operator-recovery.jar`. In the reference distribution, invoke it through `bin/qwen-managed-agent-operator-recovery`; from a module build, use `java -jar qwen-managed-agent-server-*-operator-recovery.jar`. Run it on the original worker host as the service OS account, using the service's database settings, complete Runtime credential key ring, and `QWEN_MANAGED_AGENT_RUNTIME_STATE_DIRECTORY`. The entry reads the active pair and `previous-credential-keys` from the same Spring configuration as the server. After rotation, the launcher loads `config/application.yml` from the distribution root; when the file lives elsewhere, set `SPRING_CONFIG_ADDITIONAL_LOCATION=file:<absolute-path>/application.yml`. Keep the new active pair and the previous keys needed by the target binding. The previous-key map cannot be supplied through `QWEN_MANAGED_AGENT_*` environment variables; follow the [rotation runbook](managed-agent-reference-deployment.md#rotate-the-runtime-credential-key) bracket-key rules. Its startup summary and unavailable-key errors contain escaped key IDs only, never secret values. Set `QWEN_MANAGED_AGENT_RUNTIME_DURABLE_LOCAL_PROCESS=true`, `QWEN_MANAGED_AGENT_RUNTIME_PROVISIONER=local-process`, and `QWEN_MANAGED_AGENT_RUNTIME_OPERATOR_RECOVERY_ENABLED=true` for this maintenance process. Keep the database and credential environment private. Apply the service database migration before running the command. The command does not start an HTTP listener, scheduler, or worker.

1. Find the affected run's `runtime.runtimeBindingId` and `runtime.generation`. If the run record is unavailable, an authorized DBA can use a read-only query against `qwen_runtime_binding` for the affected `tenant_id` and `workspace_id` to list `binding_id`, `runtime_generation` and `binding_state`; inspect each candidate and use only the one with the matching held lease and Shell capture. From the reference bundle, run `bin/qwen-managed-agent-operator-recovery inspect <bindingId> <generation>`; from a module build, use the equivalent `java -jar` command above. Record the returned `holderKey`, Runtime Session, Shell call, `captureStatus`, and `captureReason`. Recovery requires a saved `producer_lost` Shell result and an exact, still-held Workspace lease. An unsupported legacy worker, missing registration identity, or missing holder cannot be repaired by creating replacement identity records.
2. From the reference bundle, run `bin/qwen-managed-agent-operator-recovery prepare <bindingId> <generation> <holderKey> '<incident reason>'`; from a module build, use the equivalent `java -jar` command above. Save the returned `recoveryId`. A live or recovery-blocked binding is fenced as `OPERATOR_RECOVERY`; an already LOST binding remains LOST and is excluded from the background recovery scan. No Workspace lease is released. Repeating the same service OS account and reason is safe. A different recorded account, reason, generation, or holder is rejected. Record the human operator separately in the incident record; `operator_id` identifies the OS account running the command.
3. Stop the original worker and inspect **all** possible writers to the Workspace, including detached children and external supervisors. Prevent the original worker and writers from being restarted. Confirm that they have stopped. Process-group death, pipe EOF, elapsed time, and loss of the parent PID alone are insufficient. If this cannot be established, stop here and leave the Workspace fenced.
4. Create a regular, non-symlink UTF-8 JSON file of at most 8 KiB directly inside the private Runtime state directory, mode `0600`, with exactly these fields (replace the example values):

   ```json
   {
     "version": 1,
     "recoveryId": "<recoveryId>",
     "verifiedAt": "2026-09-29T03:00:00Z",
     "method": "host inspection",
     "actions": "Stopped worker and detached writers; disabled their external restart source; verified no writer remains",
     "restartPrevention": true
   }
   ```

   `verifiedAt` must be an actual UTC verification time no earlier than `prepare` and no more than five minutes ahead of the maintenance host's clock. Record concrete steps and the source of restart prevention; never write the statement before completing those checks. Keep the file and the incident record private.

5. From the reference bundle, run `bin/qwen-managed-agent-operator-recovery complete <recoveryId> <absoluteEvidenceFile>`; from a module build, use the equivalent `java -jar` command above. The command checks the exact saved worker identity and, on the same boot, its absence; after a reboot of the original host, it checks the changed boot identity. It then tombstones the registration, persists the immutable statement, and reclaims only the original holder. It may be retried with the **same file** after a crash or a temporary database failure. A changed statement is rejected. Successful output is `completed`.

After completion, start a **new** Session and verify it can use the Workspace. Inspect the original turn separately: its partial output and uncertain effects remain uncertain, and no Shell call is replayed. Do not clear SQL tables or registration files manually to bypass a refusal. If the original registration is absent or corrupt, or the worker is from an older ephemeral mode, this procedure is unsupported; escalate with the preserved evidence rather than fabricating it.

The software can check the registered worker identity and exact SQL holder, but it cannot prove that arbitrary escaped descendants have stopped. The operator's statement is the trust boundary for that fact.
