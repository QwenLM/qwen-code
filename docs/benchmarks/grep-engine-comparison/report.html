Grep 引擎性能基准报告

main GrepTool（git grep → system grep → JS 回退）vs v1.0.0-preview RipGrepTool（ripgrep）

测量日期：2026-11-17 · Apple M4 / 10 核 · git 2.50.1 (Apple Git-155) · BSD grep 2.6.0-FreeBSD · ripgrep 15.0.0

语料：qwen-code 工作树（15,131 个 git 跟踪文件 + 138MB gitignore 的 dist/ + node_modules）

配套 PR：GrepTool 回退链 gitignore scope 修复 · 原始数据见同目录 bench-grep-*.json · scope 边界复现见 scope-repro.sh

1 · 方法

  • argv 逐字取自两边工具源码：main git grep 含 NO_EXEC_CONFIG（-c core.fsmonitor= -c log.showSignature=false）+ --untracked -n -z -E --ignore-case -e P；main system grep 含 5 个 --exclude-dir（node_modules/.git/bower_components/.svn/.hg）+ -r -n -H -E --null -e P .；preview rg 含 --hidden + 6 个 VCS --glob（!.git/!.svn/!.hg/!.bzr/!.jj/!.sl）+ --max-columns 500，files 模式 -l --null、content 模式 --json -n，路径操作数 .。
  • rg 必须带路径操作数：无路径且 stdin 非 TTY 时 rg 读 stdin，会永久阻塞（基准 harness 曾踩此坑；preview 源码在 -- 后传 searchTarget）。
  • 采样：快引擎 1 预热 + 5 测量取中位；system grep（单轮 ~60s）与 JS 回退 1 预热 + 1 测量（样本量已披露）。每项完成即增量落盘。
  • 归一化组：rg 加 -i 对齐 main 默认忽略大小写，隔离"引擎速度"与"默认语义"两个变量。
  • 计时含 stdout 传输与流式计数（不累积全文：system grep 单轮输出 1.2GB，超 V8 字符串上限）。
  • 子进程生命周期：harness 对每个 child 挂 abort/超时 SIGKILL，并在父进程退出时清理——被 SIGKILL 的父进程不会运行 exit handler，孤儿 rg 会阻塞在写满的管道上（实测挂起 1h+、0 CPU）。

3 · 修复 main 回退链后的对照

修复（本 PR）：回退策略 2/3 改用 git ls-files -z --cached --others --exclude-standard 语料（与策略 1 同集合）；策略 2 显式文件列表 + 128KB ARG_MAX 分批（--include 对显式操作数生效，已验证）；策略 3 globStream 按语料 Set 过滤；新 spawn 均挂 abort kill。git 不可用时保留原递归行为。

4 · 换引擎的副作用清单（决策输入）

隔离临时仓库实证（复现见 scope-repro.sh）：

场景 main git grep preview rg（含 --hidden）
force-add 的被 ignore 文件（git add -f） 搜到 搜不到（rg 不读 index）
仓库植入 .rgignore/.ignore 不受影响 文件被隐藏（新的仓库可控搜索排除面）
submodule 内容 默认不递归 当普通目录扫
符号链接 读链接文本当内容（未跟踪 symlink） 默认跳过（--follow 才搜目标）
  • 依赖：main 现状零外部二进制；rg 需 preview 的多级解析链（系统 rg → Bun 内嵌 → vendor/ripgrep/<arch>-<platform> → 平台 npm optional 包）。main 无该发布管线；无 rg 环境必须保留回退。preview 特意用命令名 rg 而非解析路径防 PATH 劫持。
  • 性能正副作用：rg 不刷新 git index——消除冷 index 延迟与 core.fsmonitor helper 执行面（main 现以 NO_EXEC_CONFIG 防护）。
  • 性能负副作用：--json ~3× 字节；files 模式 mtime 排序 = O(匹配文件数) stat；保留 -i 放弃 rg 大小写敏感 SIMD 优化。
  • 生命周期：main 现 grep.ts 的 spawn 无 abort/timeout kill（孤儿风险）；本 PR 已为新 spawn 补 kill；换引擎需把 kill 接入调度器 abort 路径并映射 RipgrepTimeoutError。
  • 集成不匹配（整体照搬 preview 工具的成本）：权限 API（config.permission vs getPermissionManager）、执行契约（defineDeclarativeTool/executeWithContext vs class/execute(signal)）、grepReadTracking 缺失、声明 bundle 基础设施缺失、默认大小写与参数面 breaking。

5 · 结论

本 PR 范围：修复回退链 scope（必要但不充分）——消除 20× 污染与 8–11× 无效扫描；修复后回退 5.5–11.3s，仍比 rg 慢 32–78×，应作无 rg 环境兜底。
  • 建议后续（不在本 PR）：混合路线——main 保留集成层（PermissionManager、grepReadTracking、截断、默认 -i 与 -z null 格式保模型契约），主引擎换 rg（移植 preview 二进制解析链 + 超时 + deny 结果过滤）；git grep 降二级、修复后 grep/JS 三级回退。不整体照搬 RipGrepTool。若拒绝二进制分发：opportunistic 系统 rg 加速（零打包成本）。
  • follow-up：grep 回退加 -I、JS 回退二进制嗅探（匹配计数对齐）；deny 结果过滤移植；四类 scope 边界的接受/补偿决策。

验证：packages/core grep.test.ts 61/61 通过（含新增 scope 回归测试）；core tsc --noEmit 退出 0。原始数据：bench-grep-results.json（修复前矩阵，中位转录自完整运行日志 bench-grep-unfixed-run.log，逐样本数组未保留，json 内含 provenance）、bench-grep-js-results.json（JS 修复前 + scope 计数，含样本）、bench-grep-fixed-results.json（修复后矩阵，含样本）。
