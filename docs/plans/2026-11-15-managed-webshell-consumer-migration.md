## 1. Goals and non-goals

**Goal**: switch the web-shell browser client, the CLI local proxy/bootstrap, and the qualification scripts from the WebShell RPC surface (`/api/agent/web-shell/v1/**`, camelCase, POST .../query) to the Public REST surface (`/v1/agents/**`, snake_case, Idempotency-Key header), so 4c can delete the WebShell surface with zero UI behavior regression.

**Non-goals**:

- Do not delete any WebShell server route/record/schema (that is 4c); after b0 both surfaces coexist with identical semantics.
- Do not touch the `integration-tests/` SSE helpers (they test the server's two surfaces; they migrate in 4c).
- Do not modify the data-agent host repository (S5-2); do not touch `managed-surface.txt` (b0 adds no routes).
- Do not touch the provider view models or the ~100 downstream components (the boundary adapter absorbs every shape delta).

## 3. Verified current-state facts (verified by reading the code; implementation may cite these directly)

### 3.1 Client and consumer surface

- Single HTTP boundary: `packages/web-shell/client/components/managed/java-managed-agent-client.ts` (1482 lines, `API_PREFIX='/api/agent/web-shell/v1'`, 85 public methods). **All 85 methods have a Public twin route; no gaps**; `readArtifactRange`/`openArtifactStream`/`artifactContent` already call Public.
- Consumer layering: `managed-agent-provider.ts` (the view-model interface, imported by 117 files) itself has 42 generated-schema references; the `JavaAgent*` DTO aliases are consumed by only 13 files; the 4 DTO modules (extension/mcp-management/tool-result/side-query types) are alias layers over generated schemas, mixing `WebShell*` and shared `Managed*`/`Public*` names.
- Timestamp convention: downstream is uniformly millis (`ManagedSessionNavigationRow.tsx:37-39` does `new Date(updatedAt)` directly; the event projector uses `at: event.createdAt`).
- Capability flags: the provider's `toSessionSummary` (java-managed-agent-provider.ts:1121-1240) reads ~18 camelCase booleans + `capabilities.diagnostics` (a WebShell derived field = tasks) + `activeTurn.status==='recovery_blocked'` to derive phase/recoveryBlocked/admittedAt.
- Create flow: the provider's `createSession` (:1029-1049) **requires `result.turnId`** and does not use operationId; input is always non-empty (`request.input ?? [{type:'input_text',text}]`). submitPrompt/cancel require `result.operationId` (Public TurnCommandAdmission has `operation_id` ✓).
- `WebShellAdmission` shape: `{sessionId, turnId?, status, replayed, operationId?, admissionStage?, deliveryState?}` — turnId/operationId are both optional, so it can be synthesized from a PublicSession.

### 3.2 Shape-delta ledger

- **~48 methods need shape adaptation**: snake→camel, envelope mapping, and ×1000 for the four timestamp families.

- **replayed location**: rename/unarchive/create move it to the `X-Qwen-Idempotent-Replay` response header (the CLI proxy's RESPONSE_HEADERS already includes it ✓); action respond adds the header; operations/admissions keep it in the body.
- **Status codes are identical on both sides** (the 202/200 distribution and the shared `{error:{code,message,request_id}}` envelope from one `ApiExceptionHandler`). The only behavior difference: idempotent create replay after the session was deleted answers Public 404 vs WebShell 202 tombstone (see §9).
- **requestId has no Public counterpart**: drop the `requestId` trace echo from requests; error responses still carry `request_id` (toHttpError is unaffected).

### 3.3 SSE (the server loop is shared; only the payload differs)

- `ManagedEventStreamService.stream()` is shared by both surfaces: frames `id:<sequence>`, `event:<type>`, heartbeat `:keepalive`, the resync trigger (cursor below the replay floor → one id-less `agent.session.resync_required` frame then complete), `session.deleted` termination, and the read-grant recheck — all identical.
- Deltas: the data payload is `PublicEvent` (snake, created_at seconds) vs `WebShellEvent` (camel, millis); the resync data is `SessionResyncRequired{type,session_id,replay_floor_sequence,snapshot_through_sequence,action}` vs camel. Event names are unchanged → the client's corrupt-frame skip policy (only `item.output_text.delta`/`item.reasoning.delta` may be skipped, 3 consecutive corrupt frames max, skip logs rate-limited 1/50) is preserved as-is.
- Cursor: WebShell uses the POST body `afterSequence`; Public uses the GET `after` query or the `Last-Event-ID` header (header wins; an invalid header answers 400 `invalid_event_cursor`). **The client never sends Last-Event-ID today**; reconnection is driven by `use-managed-session.ts:636-820` (bootstrap transcript.coveredSequence → lastEventId, advanced per frame, stream_gap re-reads the transcript, stall after 3 non-advancing resyncs). Migration: pass the same number as `after=` (D-4b-5).
- Side-query stream: a shared 1s-poll emitter, `event:snapshot`, `id:<resultRevision>`, **no cursor parameter on either side** (afterRevision is client-local dedup only); the data changes from camel `Query` to snake `SideQuery` (timestamps stay millis). The client's identity guard (sessionId/queryId/resultRevision) runs on the adapted camel shape → zero changes.
- Client-files downlink: `event:request`, `id:<requestId>` (a string), data `{requestId,payloadJson}` → `{request_id,payload_json}`; no cursor, a new stream replaces the previous emitter, 500ms server poll + 300s idle, bridge 250ms retry + ownsConnection probe — all identical, only verb/query/snake change.

## 9. Risks and open items
