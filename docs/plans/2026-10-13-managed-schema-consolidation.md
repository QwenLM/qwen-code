## Scope and artifacts

The new service initializes exactly 32 business tables from `runtime-broker/src/main/resources/db/managed-schema/V1__managed_schema.sql`. Server Flyway and Broker initialization share that source. Legacy SQL/Java migrations remain documentation archives, outside the runtime classpath. No existing data is copied or upgraded; an existing legacy/foreign/malformed catalog is rejected before mutation. DataAgent tables are excluded.

The corresponding design records the complete 63 responsibility mapping. Closed Java operation/receipt/owner kinds and SQL CHECK/unique/FK/index definitions are versioned with the baseline. Domain adapters preserve existing HTTP identities and fields; snapshot pagination now returns a signed, scope-bound cursor for an immutable version with a 30-minute expiry.

Validation includes journal boundary rollback/replay; stale writer/claim generations; exact identities and creation-mode conflicts; snapshot consistent views, signed cursors, old-body protection and event-floor survival; original-object UNKNOWN reconciliation without another PUT; inherited child ACL and close debt; physical storage aliases/CSI per-execution ACK; schedule definition/scanner concurrency; and 10x historical-data query plans. ## Linux maintenance reboot acceptance

For LOCAL tool and child Git execution, enable `QWEN_MANAGED_AGENT_RUNTIME_VERIFIED_WORKSPACE_RECOVERY_ENABLED=true` on Linux and register every logical storage alias against its native mount before admission. Aliases of one mount share a physical owner; an unmapped alias cannot acquire execution authority. Preserve the registration marker and the native device/inode/birth-time identity across restart.

Use a persistent, task-owned directory and a fresh 32-table database. Run the native Linux suites, including invalid-byte Git paths and actual process-tree termination. Before reboot, persist the original maintenance generation, executionId, physical holder/mount identity and native machine/boot identity. Prove same-boot reconciliation and a missing/stale execution proof fail closed; lease expiry alone must preserve the holder.

Keep the SQL database durable across the execution-host reboot. An external MySQL 8.4 endpoint is valid; a temporary SSH tunnel must be re-established after reboot. Do not substitute a container or JVM restart for a changed native boot identity. After an actual reboot, reconnect, inspect the original record, verify the same machine with a different boot identity and unchanged registered mount, then run the offline maintenance-recovery CLI for that exact generation/execution. Read back STOPPED proof, original holder release and subsequent legal placement. A duplicate reconciliation must be idempotent; other aliases must remain unable to hold the same physical storage concurrently.

## Independent environment activation

1. Build immutable Server/Broker artifacts from the verified tree and create a new empty MySQL 8.4/InnoDB database. Configure both components to use this database and their shared canonical baseline. Bind acceptance endpoints to loopback or a controlled test gateway.
2. Start the new environment without formal traffic. Verify Flyway version 1, exactly 32 business tables, catalog constraints and a create/commit/read/replay/delete functional loop. Restart processes and prove original identities and terminal records persist. Validate worker due/claim/GC/recovery plans under the fixed 10x workload.
3. Quiesce new admissions at the old environment's gateway; settle its in-flight work under the old binary/schema. Preserve its database and historical read endpoint. Existing sessions retain their old endpoint; new sessions use the new endpoint. Never attach the new binary to the old schema.
4. Enable new requests only after every acceptance gate is recorded as passing. Record artifact revision, configuration identity and the database/environment association for new sessions.
5. Once the new environment has data, preserve it during rollback. Disable new admissions there if needed; keep a compatible service available for its sessions. Restore the old environment only for its own existing data or explicitly new old-environment sessions. Do not route new-environment IDs into the old database.
