# 本地工具可见性对比

[English](README.md) | [简体中文](README.zh-CN.md)

本文记录 [#12333](https://github.com/QwenLM/qwen-code/issues/12333) 的一次有限本地 CLI 对比。默认工具可见性下，这组任务的总 token 更少，但尚未证明质量不变。本文是实验记录和手动验证步骤，不是自动验收门禁。

## 已有实测

最终修正 fixture 的运行发生于 2026-10-09，生产源码为 `4360b003a087fe9e57f6ffbe7ba48795980b59c3`，模型为 `kimi-k3`，环境为 macOS、Node 22。九项任务，每组各重复两次，共 36 个 CLI 会话。A 让已注册工具启动时可见；B 不设置 `tools.visible`。两组均不设置 `tools.eager`，使用直接工具模式与 `tools.toolSearch.threshold: 0`，启用 Workflow，并同样禁用 memory、hooks、MCP 和自动标题。提示词、输入文件和能力相同，会话配置相互隔离。普通首轮请求分别包含 29 和 11 个工具声明。这测量的是同一提交上的可见性配置差异，不是某个 PR 的独立前后收益。

| 指标                         | A：启动可见 | B：默认可见性 |
| ---------------------------- | ----------: | ------------: |
| 满足全部请求条件的任务结果   |       18/18 |         16/18 |
| 供应商请求，包含子任务及失败 |          63 |            65 |

输入加输出下降 **30.03%**。B 的未缓存输入增加，供应商缓存未受控，不能据此证明账单节省。前台 Agent 单项消耗基本持平：123,215 → 123,126 token。

两次 B Agent 会话都实际执行了子任务并计算出 `TOTAL=63`，但父回答增加了文字说明，没有满足只返回结果的格式要求。一次 B Goal 在加载 schema 前尝试调用，被以 `invalid_tool_params` 拒绝，之后恢复。这是两项任务格式失败和一项独立的调用质量失败，仍按失败保留；格式差异尚未定位到具体的生产代码原因。

八次安全会话、四次 Goal 结果和四次已保存 Workflow 执行通过。Workflow 在两组中均启动可见，因此不能证明按需 Workflow 召回。安全用例在 yolo 审批下禁用工具注册，不是权限拒绝策略测试。

首轮单独保留：原始结果 A 14/18、B 12/18，总 token 为 969,739 → 783,840。它包含路径和 schema 检查的误判，以及两次通过仍启用的 `monitor` 实际修改 fixture 的失败。第二轮对两组同时修正了该 fixture。不能将不同配置混合取平均，也不能丢弃失败请求。

[已发布报告](https://github.com/QwenLM/qwen-code/pull/13767#issuecomment-6079794031) 保留分任务结果及来源。历史实验使用临时转发代理，将全部 128 次请求与原生日志核对。之后离线修正分类器，计入此前漏判的参数错误，未改变 token 或任务结果；该修正之后没有重新调用供应商。原始日志和失败运行保留在本地，不随本文提交。实验 runner 保留在 PR 历史提交 `82f1f057cfe17e573ae465958b95c14d0d95d196` 中，不再作为仓库命令维护。

## 使用现有能力做小规模复测

1. 固定一个 CLI 版本或源码提交和一个模型，准备同一小型工作区的两份临时副本及隔离配置。供应商、权限、hooks、memory 和启用能力保持一致，只改变被评估的可见性配置。记录确切配置，不修改日常使用的配置。
2. 选择几个正常任务：对话、读取并汇总文件、Shell 操作、多步编辑。只有评估对应能力时才加入 Agent 或 Goal。运行前固定提示词、输入和预期文件／结果检查，不在提示词中指定发现工具的调用方式。
3. 每个任务在两组中分别开启新会话，重复时交替 A/B 顺序。对于 OpenAI 兼容供应商，使用已有 headless CLI 和 API 日志选项，例如：

   ```bash
   qwen --model <model> --output-format json --chat-recording=true \
     --openai-logging --openai-logging-dir <private-log-directory> \
     -p '<same task prompt>'
   ```

4. 从会话记录核对实际回答、文件和工具执行。保留格式错误、拒绝调用和恢复过程。检查首轮请求声明，确认预期 A/B 差异确实生效。
5. 记录整个任务的供应商输入、输出和缓存 token，包含子任务、额外轮次及失败请求。父会话汇总本身不能证明计量完整。如果现有日志缺少某次请求或其用量，应标为覆盖不完整，不能补零，也不能把部分总数称为整个任务的节省。原始日志保密，仅发布脱敏结果。

示例命令只展示已有采集选项，不会自动配置 A/B 隔离或验证结果，也不能单独复现历史九任务实验。发现具体缺陷后，复用现有[集成测试 helper](../../../integration-tests/test-helper.ts) 编写可重复的回归，用现有[遥测](../../developers/development/telemetry.md) 查看用量和工具事件。最初收缩为纯文档时没有重跑供应商；之后的定向补测记录如下。

## 2026-10-13 有限补测

在 `c2f5ce45b156` 的源码 CLI 上运行两个会话，使用历史 B 配置以及相同模型和提示词。原始请求确认首轮 11 个声明，包含 `tool_search`／`tool_call`，Agent 和 Goal 工具仍隐藏。Agent 精确返回 `TOTAL=63`，这一个样本未再次出现格式失败。Goal 再次提前执行 `tool_call(get_goal)`，被拒绝后才搜索 schema，随后运行校验并完成。启动提醒和 Goal 续轮提示都已明确要求先审阅 schema。这是可复现的模型调用顺序错误；现有观察没有定位到缺失指引或可据此修复的生产代码。即使任务恢复，拒绝调用仍保留为调用质量失败。

此前四次隔离全局 `qwen` 运行使用的是基础安装 0.24.0，而非普通配置中的自动更新版本 0.25.0。它们完成了任务，但直接暴露 Agent／Goal，不能验证按需桥接，因此不纳入该结论。本轮未重新进行 A/B 成本对比，也未根据这些观察改动生产代码。

## 剩余验收

现有证据支持这组固定样本的总 token 降低，不能证明通用召回质量不变、账单节省或标准套件通过。#12333 继续保留：通过现有评测路径对比代表性任务及另行选定的配置覆盖。若发现可复现的产品缺陷，再做小范围回归和修复；本地验证不以扩建自定义评测框架为前提。
