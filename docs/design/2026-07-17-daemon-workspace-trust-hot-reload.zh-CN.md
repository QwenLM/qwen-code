# 守护进程工作区信任热重载

[English](2026-07-17-daemon-workspace-trust-hot-reload.md) | [简体中文](2026-07-17-daemon-workspace-trust-hot-reload.zh-CN.md)

## 状态

已为 QwenLM/qwen-code#6378 实现。为 QwenLM/qwen-code#13130 更新，该 issue 增加了
由操作者授权的信任授权端点，详见
[Web Shell 工作区信任授权](2026-10-01-web-shell-workspace-trust-grant.zh-CN.md)。

## 问题

守护进程目前在构造 `WorkspaceRuntime` 时评估工作区信任。`GET /workspace/trust`
报告该快照，而 `POST /workspace/trust/request` 只发布
`trust_change_requested`。修改 `trustedFolders.json`、IDE 信任或用户/系统级
文件夹信任设置都不会重建运行时，因此设置、环境变量、文件系统、ACP 会话、
MCP、扩展、渠道工作进程（channel worker）以及定时任务都会一直停留在旧的信任
边界上，直到守护进程重启。

信任无法就地更新。文件系统工厂、bridge、设置、环境变量、ACP 挂载以及若干个
工作区级管理器都会在构造时捕获其运行时输入。

## 安全不变量

1. 信任降级会在第一个异步排空步骤之前关闭受影响运行时的世代守卫。此后不得
   开始任何新的特权副作用。
2. 已关闭的世代守卫永不重新打开。替换运行时获得新的守卫与单调递增的世代 id。
3. 撤销失败绝不恢复此前受信任的运行时。
4. 格式错误或不可读的系统/用户设置按失败关闭处理。格式错误或不可读的
   trusted-folders 文件在需要文件信任时按失败关闭处理，但当文件夹信任已关闭、
   或 IDE 信任已裁决主工作区时则无关紧要。
5. 处于 transitioning、blocked 与 stale 状态的会话所有者绝不回退到主运行时。
6. 每一条运行时激活路径都会在发布前立即校验策略修订号。

## 信任策略

守护进程使用一个无副作用的策略加载器，只读取系统覆盖项、用户设置、系统默认
值、IDE 信任与 `trustedFolders.json`。工作区设置与项目环境变量文件不参与策略
评估。既有的信任规则优先级与路径比较行为保持不变。

该加载器产出一个不可变的语义快照。工作区把该快照物化为一个可操作的信任布尔
值和一个允许根（allowed-root）列表。只有物化结果变化才会重建运行时。仅来源
变化只推进已应用的策略修订号，不触发重建。

主文件系统保留既有的可信 IDE 多根行为。当某个次级根从主允许根列表中移除时，
次级与主世代都会在任一被排空之前关闭。

监控器每秒重新读取一次策略输入，仅当其语义哈希变化时才发布。IDE 与同进程的
受信任文件夹写入也会触发立即读取。`/workspace/reload` 与动态工作区注册会显式
请求一次协调。

受信任文件夹写入会获取 `proper-lockfile`、在锁内重新读取、保留注释，并以原子
方式替换一个普通 0600 文件、且不跟随符号链接。格式错误的文件不会被静默重写。

## 运行时归属

注册表持有稳定的 `WorkspaceEntry` 对象。一个激活条目引用一个不可变的
`RuntimeGeneration`，后者拥有运行时及其世代守卫。工作区身份、持久化注册元数据
与已应用的策略状态存在于条目上，而不是世代上。运行时构造与清理仍由守护进程宿主
统一协调。

工作区限定（workspace-qualified）的数据面路由在请求时解析其运行时。保留进程级
路径的主路由使用指向当前运行时的实时委托。特权 REST 变更会捕获世代守卫，并在其
提交边界重新校验。ACP、Voice、渠道工作进程与会话准入使用其既有的排空机制。信任
状态与守护进程清单读取稳定条目，不获取运行时。

会话所有者索引是世代感知的。会话创建与恢复会显式注册归属，运行时替换会使旧的
归属失效。既有的活动 bridge 扫描作为兼容性修复路径保留，用于早于索引机制的
会话。

运行时清理会关闭 bridge 与子渠道、Voice 状态、子会话、ACP 挂载、渠道工作进程、
定时保活以及 git 状态。由替换运行时拥有的管理器会以全新的设置、环境变量、文件
系统、信任、策略与缓存输入重建。共享的路径锁与进程遥测会跨替换存活，因为它们
不携带工作区能力。

## 协调

信任协调与运行时发布共用同一个守护进程拓扑闸门；工作区添加与重载会在其自身操作
之后通过该闸门请求协调。信任快照会被合并（coalesce），以便在调用方被释放之前
应用最新观察到的修订号。关闭流程会停止监控器，并在取得清理快照之前等待拓扑
闸门。

对于信任降级，控制器会在第一个异步排空之前同步关闭每个受影响的世代、关闭准入
路径、销毁旧运行时、构造全新运行时、重新校验策略修订号，并安装新的条目世代与
ACP 挂载。既有的 bridge 与 ACP 关闭路径提供有界或强制清理。过期的候选运行时会被
销毁并重建。

授权（grant）使用同样的有损替换。如果失败，控制器会尝试构造新的不可信运行时，
并将所配置的修订号报告为 failed，直到后续某次协调成功。如果无法确认运行时已被
收容，该条目保持 blocked 且深度健康检查降级；其他工作区仍可用。

## 协议

`POST /workspace/trust/request` 保持仅请求语义：它发布该请求，仍然需要本地操作者
裁决。直接记录裁决是另一条独立路由 `POST /workspace/trust/grant`，它要求操作者
权限，详见
[Web Shell 工作区信任授权](2026-10-01-web-shell-workspace-trust-grant.zh-CN.md)。
信任状态 v1 仍是默认的兼容视图。客户端通过 `statusVersion=2` 请求 v2；旧服务端
可能返回 v1。V2 将已配置策略与实际生效的运行时状态分离，并报告 `stable`、
`applying` 或 `failed`、一个不透明修订号以及稳定的错误码。只有当主、次级路由都
使用世代感知解析之后，守护进程才会通告 `workspace_trust_hot_reload`。

不引入可靠的应用事件总线。GET 状态是唯一事实来源。信任变更请求需要有一个激活的
世代才能发布既有事件；否则返回可重试的 503。

## 非目标

- 无需操作者权限的直接远程信任批准。
- 零停机双运行时或会话迁移。
- 对外公开的世代标识符。
- 并行运行时重建。
- 重建完整的 Express 应用。
- 改变独立 CLI 的信任语义。
