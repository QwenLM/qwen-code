# 原生 LSP 文件路由修复

[English](lsp-file-routing.md) | [简体中文](lsp-file-routing.zh-CN.md)

> 状态：已在本地实现；验证结果单独记录。

## 问题与范围

[PR #13568](https://github.com/QwenLM/qwen-code/pull/13568) 引入了文件适用性与
工作区 root 筛选。最初实现中的显式服务选择、预热和已跟踪文档重放没有遵守
同一工作区边界，不完整的语言推导也拒绝了此前可用的配置。本次修复统一这些
路径，不改变启动或传输。工作区编辑使用与读取相同的新鲜包含性检查。

## 路由决策

1. 路由前新鲜解析 file URI，包括显式 `serverName`。先检查当前已注册工作区
   目录，再检查服务 root。解析失败和工作区越界使用不同错误与调试日志。
2. 显式服务选择只绕过语言和服务 root 筛选，绝不绕过工作区边界。未知或未就绪
   名称使文档查询失败；工作区查询和调用层级续查也报告服务不可用。内部无 URI
   调用仍返回按名称筛选的 handle，供重载记账使用。文档查询拒绝非 file URI，
   包括显式服务 override。
3. 非空 `extensionToLanguage` 是完整的扩展名路由集合。否则，由一份 LSP 语言
   扩展名表判断已知适用性；TypeScript 包含 JavaScript 和模块扩展名，带数字版本
   的 clangd 名称允许 C。不再反向推导展示语言名称，也不保留 `.mm` 特例。
4. 只有 `extensionToLanguage` 缺失或为空时，未知配置语言和无法识别的无扩展名
   文件才保留经过范围校验的旧式投递。非空映射按扩展名匹配，前导点可选，不按
   文件名匹配；`Gemfile`、`Makefile` 不能表达为键。如果映射扩展名没有匹配任何
   文件，该服务的路由被禁用。已知语言
   仍拒绝未知的非空扩展名与确定不匹配的文件，包括 Python/Cython，以及未声明
   C 支持的 C++ wrapper。JSONC、zsh 等标准别名加入同一张表。这不是对所有未知
   扩展名无条件回退。
5. 主 root 服务接收所有已注册目录；非主 root 只接收自身 root 与已注册目录的
   交集。文件路由和两种预热候选发现共用该决策。错误服务 root 记录日志，只排除
   对应 handle。路由包含判定与主 root 每次只计算一次，不持久缓存文档解析结果。
   root 拒绝消息说明显式 `serverName` override，而不是在输出格式化中复制服务
   root 路由逻辑。
6. TypeScript 预热对每个 root 只执行一个 glob，按 TypeScript 扩展名优先级选择，
   不依赖映射键顺序或文件名大小写，并逐个跳过不可用候选。只使用路由扩展名
   与内建 TypeScript 集合的交集；交集为空时跳过发现，不打开被排除的文件。
   无匹配结果仍可重试，使新增文件和新注册目录能在同一连接上完成预热。

## 投递与导航

共享同步入口在读取或发送通知之前重新检查当前范围。撤销或无法解析的 URI
会丢弃已投递文本快照，但保留重放义务、现有连接的版本及待关闭元数据。仅有
持久记录的已撤销 URI 在连接替换后仍保持停放，范围恢复后以版本 1 投递。
配置重载有意丢弃已撤销的重放义务。范围
无效期间不发送文档通知、不读取文件内容。范围恢复后，文件查询和工作区扫描
先完成旧文档关闭，再重新投递；版本不重置，关闭失败也不影响健康文件。连接
替换会丢弃旧连接的关闭义务。调用层级的磁盘观察也将已撤销目标判为过期，不
读取当前范围外文件。有效范围内缺失文件的读取错误继续保留。

外部定义、实现和引用位置仍可见，但会标注继续文件查询前需要 `/directory add`。
不引入自动白名单，也不自动扩大可信目录。工作区诊断与符号结果过滤当前工作区
范围外的位置，避免把已撤销缓冲区呈现为当前结果。输出格式化只为单次响应记录
目录与范围判定，安全标注畸形和非 file URI，并在协议 JSON 后追加范围提示，
不修改其中的数据。用户文档说明显式映射、root 例外、
override 限制与不同错误。手工 E2E harness 使用真实 `WorkspaceContext` 规范化 root。

## 验证与验收

- 先补 Critical 回归测试：显式 override 的边界与不可用情况、Terraform/Gemfile
  等未支持类型、带数字版本的 clangd。
- 覆盖原生与 TypeScript 的范围内预热、跟踪目录撤销、重启/重载的健康文件、
  重新添加目录及错误 root 隔离。
- 使用严格 peer 覆盖两种同步模式下的范围撤销/解析失败，以及经文件查询或工作区
  扫描恢复的生命周期。要求关闭/打开配对、返回当前内容、关闭失败不阻断健康文件、
  连接替换丢弃旧关闭义务，并且同文本恢复不使旧调用层级 token 重新有效。
- 为只有 `.cxx`、`.hpp`、`.py` 的工作区补候选发现测试；删除未使用的 mock
  边界实现，并让 harness 返回解析后的 root。
- 保留显式映射排除、不相关服务拒绝、主 root 的附加目录路由、符号链接重定向
  新鲜性、缺失文件错误及无 URI 调用层级语义。测量每次路由 filter 只读一次目录。
- 不可用的工作区查询不能报告无诊断。仅有持久记录的已撤销文档在范围恢复后
  必须重放；不返回已撤销的工作区结果。有效与畸形 URI 混合时保留有效诊断。
- 回归测试在基线或定向 mutant 上必须变红；验证报告区分定向测试、构建检查及
  被阻断的 E2E 或平台覆盖。

## 约束与风险

未知语言的投递有意不声称能证明服务适用性；严格路由需配置显式映射。realpath
检查观察文件系统状态，不能提供面对并发外部写入的原子事务。macOS 符号链接
测试在本地运行；Windows junction 行为仍需 Windows runner。不新增 watcher、
持久缓存、依赖、公开配置字段或导航白名单。仅供展示的范围判定只缓存单次
响应，绝不复用于授权。
