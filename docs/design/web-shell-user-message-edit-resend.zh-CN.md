# Web Shell 用户消息编辑与重发

[English](web-shell-user-message-edit-resend.md) | [简体中文](web-shell-user-message-edit-resend.zh-CN.md)

## 问题与范围

支持在消息行内编辑最后一条普通用户消息。打开或取消编辑不能改变历史，确认编辑替换该轮对话，但不回退工作区文件。后台通知不算用户轮次。

初始实现可能把旧编辑发送到新切换的会话，在宿主拒绝发送前就回退，丢失附件，或在迟到的回退事件到达时删除新消息。输入法确认也可能误触发送。

## 设计

复用现有发送准备流程和会话归属检查。私有的 `beforeAdmission` 回调在 `prepareSubmit`、`onSubmitBefore` 和会话解析之后，乐观渲染和提交之前执行。编辑流程用它读取附件内容、确认原消息仍是最后一条、查找对应回退快照、执行回退并等待转录事件。现有准备状态在此期间阻止其它本地提交。每次异步操作之后重新检查会话归属；切换会话、工作区或重新加载都会使旧操作失效。

只有 `onAdmitted` 才表示成功。前置检查拒绝时保留原消息和行内草稿。回退后，明确的提交拒绝或附件上传失败会把已准备的内容接入现有失败消息重试入口。重试复用该用户消息，不再追加一条；普通输入框的独立草稿和附件保持不变。发送结束后再读取失败消息，因为附件失败可能异步创建该消息。提交结果不明确时使用现有恢复界面，不自动重试。

等待回退同步超过两秒后停止发送，并阻止写入，直到事件到达或重新加载会话。回退响应丢失时采用相同阻断。替换内容与待同步的回退一起暂存，与普通输入框分开；同步后创建一条可恢复的替换消息，提供重试入口，不自动发送。会话所有权变化时取消待恢复操作。发送失败留下的本地用户消息不能再次触发回退同步阻断。

回退前读取引用式附件，已有行内图片字节和本地文件内容可以直接复用。图片和文件通过正常上传路径重发。附件不可用时在回退前失败。引用注解复用输入框现有的文本变更映射，保留未受编辑影响的绑定。行内编辑器也支持纯附件消息。`isComposing` 或 `keyCode === 229` 表示输入法占用时，忽略 Enter 和 Escape。

保留现有宿主接管约定：`onUserMessageEditRequest` 返回 `true` 时由宿主负责编辑。历史转录视图只读。不引入新的 daemon 路由、持久化格式、依赖或文件回退行为。仅回退对话时清除已丢弃的快照位置，使后续编辑仍能找到正确轮次。

## 约束与风险

回退和提交是两次独立 daemon 操作，不具备原子性。回退后的网络或提交失败可能导致旧轮次已从当前分支移除；此时保留替换草稿并报告失败。切换会话有意取消旧操作，不把旧文字恢复到新会话。编辑覆盖的引用注解会失去原绑定，这与现有输入框映射一致。

## 验证与验收

使用上一轮审查中可控的失败场景和定向回归测试：

- 快照或回退延迟期间切换会话，绝不向新会话发送。
- 宿主前置检查拒绝时不回退，也不报告提交成功。
- 确认回退同步后才提交，保留普通输入框草稿。
- 超时独立暂存编辑内容并阻止写入；迟到同步后提供重试，不自动发送。
- 替换失败后在原位置重试，普通输入框草稿不变，成功后仍能继续编辑。
- 编辑后续轮次时，保留此前后台通知及其回复。
- 保留行内和引用式附件，支持纯附件消息；附件不可用时不改变历史。
- 输入法确认与取消按键不会发送或丢弃草稿。

执行包级测试、构建、类型检查、打包、lint 和格式检查。自动化组件及 reducer 验证使用隔离数据，不为测试失败路径覆盖用户的真实会话。详细计划和结果保存在 `.qwen/e2e-tests/`。
