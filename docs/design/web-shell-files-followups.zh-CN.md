# Web Shell 文件浏览器后续修复

[English](web-shell-files-followups.md) | [简体中文](web-shell-files-followups.zh-CN.md)

## 问题

本设计细化[文件浏览器设计](web-shell-file-browser.zh-CN.md)。

已合并的文件浏览器仍在 Pierre 树行中显示控制字符，携带完整高亮语法和主题资源图，
内联布局依赖未纳入许可证清单生成范围，且没有仅关闭内联预览的操作。

## 决策

- 通过固定版本的 `patch-package` 补丁为 Pierre Trees 增加仅用于渲染的
  `formatItemName` 接口。文件名专用格式化移除 ANSI、控制字符、Unicode 格式字符及组合字素连接符，
  保留合法空格，包括连续空格、首尾空格和不换行空格。筛选同时匹配按段格式化的显示路径和原始路径。
  普通行、折叠行、固定行及其
  可访问名称均使用该接口；不改变模型路径。读取、下载、引用和复制路径继续使用真实路径。
  清洗后显示相同的两个名称仍表示不同文件。上游提供等价的受支持接口后移除补丁。
  修改文件带有声明，补丁中的包 NOTICE 自动进入生成的发行声明。修改补丁并重新应用后，
  从 `packages/web-shell` 执行 `npm run dev -- --force` 重启开发环境，清除 Vite 预构建缓存。
- 为 Pierre 提供独立的 Shiki 4 构建入口，仅显式延迟加载常用语言和
  `github-light` / `github-dark` 两套主题。解析范围仅限 Pierre，现有 Shiki 1
  使用方保持原有行为。不支持的语言在渲染前回退为可读原文，保留已有大文件限制。
  开发环境、应用及库的生产构建均使用同一资源选择。将 Pierre 排除在 Vite 依赖预构建之外，
  确保开发环境使用相同适配层。`pierre-resources.ts` 定义 33 个允许的语言键，
  将 `yml` 归一化为 `yaml`、`kts` 归一化为 `kotlin`。对该资源图实际保留的模块代码
  设置 4 MiB 预算，包含重定向的 Shiki 子路径，不计入共享 chunk 中的其他代码。若构建包含
  Pierre 但缺少裁剪适配层则失败；transcript 构建不包含 Pierre 是合法情况。Vitest 同样应用适配层，
  并内联 Pierre 依赖。内部适配层声明不是公共包接口；发布的声明只能依赖已声明的运行时、peer
  或对应类型包。验证冷启动、常用语法、主题切换和回退行为。
- 库发布时将 `react-resizable-panels` 设为 external，与现有 UI 依赖保持一致。
  npm 依赖自行携带许可证，库产物不再包含未署名的内联副本。
- 在文件工具栏增加“关闭文件预览”。清除选中文件并恢复全宽文件树，包括树已隐藏的情况。
  保留已加载目录、展开态、筛选及树状态，再次选择同一文件可以重新打开。
  等待树变为可见后再将键盘焦点移回筛选框。

## 范围

不接入 Git，不编辑文件或修改文件系统，不做剪贴板 shell 转义，不改变通用 Markdown
或源码渲染器。原始路径仍是操作契约，复制的路径不是 shell 命令。UI E2E 使用模拟 daemon，
不能证明真实文件系统或 Git 后端操作。

## 验证

使用实际浏览器树行检查可见及可访问名称清洗、原始读取和复制值、清洗后重名、目录展开和
虚拟滚动。分别在树可见和隐藏时关闭预览，然后重新打开同一文件。冷启动验证常用语法和
未支持语言回退，切换浅深主题。将发布库的 JavaScript 体积与合并基线比较，执行高亮预算检查，
重新生成许可证清单，运行构建、类型检查及相关单元和浏览器测试。完整检查两轮 diff。
