# Managed Session history queries and authority residency

[English](2026-10-27-managed-session-authority-window.md) | [简体中文](2026-10-27-managed-session-authority-window.zh-CN.md)

## Status and baseline

PR5 of #13184 was researched against `0539160f35f983ba4a6d4d369c0ae18941b2fdb2`, including PR1 #15566, PR2/PR3 #15569/#15599 and PR4 #15626, and integrated with main `7a9a88938e65a528311973a552189f7dea1aa04d`. Bounded residency is the new implementation's normal path; it has no opt-in switch or synchronous whole-history fallback. Validation is in progress: implementation, focused acceptance and final CI qualification are separate states. The execution report records exact source hashes, failures and pending gates.

## Problem and goal

The authority retains all events, commands, identifiers, receipts, checkpoints, Actions, extension revisions and uniqueness evidence. Its synchronous history readers also reconstruct complete arrays. Local and HTTP restore concatenate the complete logical journal, and activation/inbox snapshots retain all terminal identities in resident maps. Removing one array would move the growth elsewhere or lose replay safety.

Bound authority, scheduler-store and restore memory to `O(active state + fixed caches + bounded I/O)`, independent of completed history. Preserve complete history and exact old-key replay/conflict answers. Cold restore may scan history; fixed restore latency and bounded disk usage are not goals.

## Storage and authority boundaries

The canonical native journal remains authoritative. Hosted uses existing MySQL through Java/JDBC; managed-local uses existing H2 through the same service contract. Standalone JSONL uses a file query adapter under its existing `SessionWriterLease`; it needs neither Java nor a database. Do not introduce SQLite or raise the standalone Node requirement.

Do not delete canonical transactions/resources, advance a native or public replay floor, automatically publish snapshots, replace local ownership semantics, or close the whole #13184 tracker. Public message projections cannot restore authority state.

## Read views and interfaces

A read view binds the tenant/Workspace/Session and committed sequence/digest; native HTTP also binds journal revision, and files bind the physical generation. Capture the view once before asynchronous reads. Query mutable facts as of that prefix, including an older requested sequence; preserve original immutable facts. Only a complete view can answer absence. Unavailable, rebuilding and corrupt views are errors, never empty results.

Historical point lookups and lists become asynchronous. Event reads use pages or asynchronous iteration, default 100 events, maximum 256 and 8 MiB per page. Reject non-safe-integer, NaN, fractional and invalid sequence inputs. Preserve contiguous pagination and existing HTTP/SSE envelopes. Remove synchronous whole-history production readers, including hidden arrays and Sets in their consumers. Bounded current summaries and active-only scheduler reads may remain synchronous.

## SQL query view

Reuse the native journal command index and source transaction bytes. Add versioned history facts containing a closed fact family, identity, source revision/sequence, locator and digest, plus contiguous index coverage. Update new facts in the canonical commit transaction. Backfill older transactions in bounded batches without holding the head lock across the complete scan. Refuse absence until coverage reaches the requested prefix. Verify derived facts against source transactions during restore and rebuild missing/inconsistent indexes from the canonical journal; canonical corruption blocks recovery.

History routes are persisted-Workspace/Session scoped and preserve existing tenant credentials and read grants. Core does not acquire SQL credentials. Historical version queries must not substitute the latest-only `ma_session_record` projection. Update the shared V1 schema baseline, initialization/validation registries and H2/MySQL coverage together; there is no V2 migration or automatic deletion of an existing catalog.

The implementation uses generation-qualified `ma_session_history_state` and `ma_session_history_fact`. Each generation records counts for 256 identity-hash buckets; a missing row cannot turn a populated bucket into an absence proof. A query verifies each selected locator, ordinal, digest and metadata against its one canonical source transaction. Core also compares query results with the independently rebuilt canonical facts. Backfill advances only a continuous prefix, with at most 100 transactions per request. Repair uses `expectedGeneration` as a compare-and-swap: an old concurrent repair joins the new generation rather than resetting it again; a future generation conflicts. Old derived generations are removed in batches of at most 256 rows, outside the all-history head-lock scope. Canonical resource/transaction corruption is never repaired as an index problem.

Core consumes native point and event-range queries. Domain identity enumeration currently uses its independently rebuilt canonical file catalog; the SQL `extension-domain` family is available to service callers but is not a Core directory reader. Source validation recomputes canonical event/marker digests, sequence/count and scope, including the physical parent across transaction boundaries; a refreshed raw checksum alone cannot validate changed canonical content.

CSI application inventory includes both complete typed history tables, yielding 40 managed tables and 827 columns. Derived metadata cannot discover authority associations or participate in global JSON-carrier scans; scoped and captured-key reads still verify exact rows. Covered facts must match their canonical transaction, counts and bucket manifest. Terminal cut derives its exact five history facts through the normal append extractor and advances coverage only across a continuous prefix. Missing state starts a new generation with zero coverage. Freeze reserves nine additional rows, including the optional state row, within the existing qualification limits.

## File query view

Use a content-addressed paged hash-trie with 64 KiB leaf pages; split by successive key-digest nibbles. Keys include the closed fact family and complete identity; verify identity on a digest match. Values contain bounded metadata and source locators, not all historical bodies. Mutable facts retain small version chains. A validated empty branch/leaf proves absence; a referenced missing or corrupt page does not.

Build a new owner/open generation from this open's streamed, validated canonical prefix. Never trust an old sidecar watermark as proof of negative answers. Publish one root per transaction and bind it to the prefix proof. Enumerate first-committed identities through append catalogs protected by byte length, count and digest, not directory listings. Freeze roots/catalog boundaries for readers. Scope cleanup to task-owned sidecars after readers finish, retaining canonical data and format barriers. Batch shared-path changes and measure write amplification; do not build a generic storage engine.

Leaf entries contain the key digest and an authenticated value locator. Large legacy identities are out of line, including in the 100-entry identity catalog pages. File event facts point into one verified transaction block; first execution receipts store its sequence rather than duplicating event bodies. Extension versions retain refs and metadata, loading parsed bodies on demand. Independent query roots share their authority owner's single 2,048-entry/4 MiB byte cache. Content blobs publish through private pending files and atomic links so concurrent roots cannot observe a partial blob.

A referenced missing or corrupt page triggers one serialized rebuild for that view from its captured canonical prefix. Rebuilding uses the same bounded owner cache and publishes an equivalent logical root only after complete source validation; it does not assume that replay reproduces old blob hashes. Frozen readers retain one root alias, and late retries use the verified repaired root rather than a later head. The writer retains its bounded pending overlay. A changed or unavailable source prefix/generation is an explicit error, not absence; derived repair never settles an uncertain append or modifies canonical history.

Close rejects new queries, drains reads/writes, clears the cache, and enumerates at most 32 directory entries at a time with at most 32 pending removals. Recursive directory deletion collected millions of filenames and failed under the fixed heap during scale validation; that failed run and its independent reproduction remain recorded. Cleanup never removes the transcript, snapshot pages or original resources. Immutable index pages and historical versions still consume growing scratch space during an open generation; close latency and write amplification are explicit costs.

## Commit and failure ordering

Only a known canonical commit may advance visible state and the query view. Evict resident facts after their view is available. If a file-view write fails after canonical commit, retain at most one transaction in a bounded overlay, return its committed receipt, and stop subsequent new writes until rebuilding succeeds. Retry returns the original result. A failed cache must not turn a committed ACK into rejection. Unknown append outcomes remain exclusively governed by `settleAppend()`; view absence cannot settle them.

## Resident facts and consumers

Retain at most 1,024 recent events and 8 MiB, and at most 2,048 historical/parsed-cache entries and 4 MiB. An oversized body is read for the current operation without entering the cache. Keep current activation/checkpoint, finite latest-kind summaries, unsettled inputs/Actions and active work or cleanup references. Do not retain every completed identity as active state.

Move command/event-ID deduplication, original execution receipts, checkpoint lookup, domain/extension versions, opening operations, Hook activation/once/occurrence/ordinal/definition pins, child continuations and team uniqueness to historical queries. Old retries retain transaction IDs, refs and results while reporting the current committed high water. The first execution receipt still wins. Domain lifecycle determines residency: a settled Hook registration, schedule or team can remain effective.

Migrate approval/model/Plan selection, wake/cancel recovery, tool results, original CSI, cleanup, Hook/automation/channel/child/team readers, transcript projections, exports and SSE. Replace full-history settled/delta-ID Sets with scoped queries. Build only the selected model branch, current compaction summary and required context without silently truncating history. Historical tasks keep their existing ordering with bounded pagination.

Current context contains model material after the effective compaction and along the selected branch. Non-model UI/attribution/attempt metadata remains in canonical history and is streamed when requested. Repeated memory catalogs and local command pairs use the existing API-history semantics. Recovery facts such as cancellation, tool-result identity and original CSI adjacency query the fixed canonical prefix, rather than inferring absence from the context projection. Team task pages default to 100 and cap at 256; their cursor binds the team and prefix so task dependencies and roster/plan answers do not mix later revisions. Hook installations, live schedule/team definitions, active input/task cleanup and pending Actions remain resident only as needed by their lifecycle.

Message-parent and CSI-adjacency consumers use `iterateMessageRecords()`, preserving the existing message/branch projection channel; `iterateRecords()` additionally includes terminal and domain records. A terminal UUID must never become a message parent merely because it is the last complete-history record. The explicit active-transcript-chain API includes its metadata records, independently of the bounded model-context projection. An external canonical owner parent ends a selected chain normally; an actual repeated in-chain identity is corruption.

Committed-model-output recovery inspects the complete fixed-prefix tail: a later terminal record must prevent resuming an already settled output. Terminal identity comes from its payload prompt ID, even when the record has no daemon prompt ID; another prompt's terminal must not block this recovery. This decision is separate from choosing a conversation parent and cannot use the message-only stream.

Single-event and batch event producers run only after the command's historical replay, scope, content-conflict and expected-prefix checks. A retry returns the original transaction with the current committed high water without invoking its producer again, including after cold open. This closes an existing producer-ordering gap exposed by the new real HTTP recovery acceptance; it does not change append settlement or actor fences.

Hook pending-work decisions read persisted execution/occurrence facts and therefore await `hasPendingOperations()`. The model boundary, recovery-status check and Hook admission callers use that required method together. Test doubles must supply it; silently treating an absent method as false could admit model work while Hook work is unresolved. A synchronous answer would require retaining another lifetime pending/history projection.

The Managed recorder retains a tail, record ordinal, user-turn count, pending tool identities and one compression summary. It does not retain all branch records or per-turn rewind arrays. Completed-turn checkpoints stream a fixed canonical active chain and verify the cursor-to-tail count before publication. Cancellation and Goal evidence also read this chain across compaction; Goal candidates and proof lookup spill to an owner-shared disk view. Legacy recorder/rewind behavior retains its existing contract. CSI turn maps contain only in-flight work; completed retries query the canonical prefix and return the original result without another model call.

Restore projections carry parallel parent, internal prompt and daemon prompt identities for the selected model context only. These temporary arrays are bounded by that context, rather than the complete canonical history. A Managed recorder discards all three arrays on activation and rebuild and does not append to them while recording. Its existing rewind refusal remains in place; Legacy live, cold and selective branch restoration preserve the daemon identity associated with each retained rewind anchor.

The current Harness checkpoint contains active tools, including settled tools whose results are not yet consumed, plus its existing fixed inline tail. Completed and consumed tool/binding pages stay in canonical resources. Authorization carries a required immutable history view with lazy tool/binding iteration, execution-ID point lookup and verified scalar counts, maximum ordinal and settlement/consumption summaries. An execution ID is not a function-call-ID alias. The view fixes the state ref, Session/Turn/prompt and archive counts; a later head cannot change an older view. Cold validation writes page locators, identity/ordinal uniqueness and first-commit order to disk. Warm commits reuse authenticated page proofs and index only new pages. Publish prepared forks only after the canonical commit is known. Missing/corrupt derived pages rebuild from that captured root; canonical corruption refuses recovery. Cache the compact current view, not hydrated historical arrays or an additional raw-root cache.

Keep the existing `managed-checkpoint-paged/1` bytes, 48 KiB/32-item pages, 4,096-page/64 MiB qualification limits and format floor. A new Turn's `before_model` drops the current archive reference while canonical history remains intact. CLI runtime ownership and definition-pin checks stream the whole fixed view, including pins outside the inline tail; pending-message and original-receipt lookup use historical identities. No production consumer reconstructs the full tool/binding arrays as a compatibility path.

Java checkpoint proof uses the same compact-root/pagewise model. Validate duplicate execution/function IDs, ordinals and binding-to-tool references with request-private disk facts; chronological iteration uses a verified reverse-page spool. Normal JDBC CSI proof also spills historical IDs, batches, intents, receipts, frozen batches, inventory metadata and execution snapshots. Each proof owner has a fixed 640 KiB bucket directory; record hashes link each lookup to its trusted bucket head, so an absent key requires a complete authenticated chain. Numeric prefix cursors freeze old reads without copying the directory. Private scratch values cap at 32 MiB: normalizing the numeric spelling of an already valid 8 MiB message can use up to three times its bytes, plus less than 512 KiB of bounded batch/refusal metadata. This follows the configured Jackson writer and [Java 21 decimal formatting](<https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Double.html#toString(double)>). The private codec preserves numeric node types, including overflow values pending semantic rejection. Its read depth of 72 covers fixed DTO wrappers around resources validated at depth 64. Execution snapshots retain raw SQL reference/result JSON and restore it with the original ledger parser, preserving decimal precision and its source depth. Public parsers and canonical message/general resource limits stay unchanged. Bodies are read one at a time, and manual JDBC transaction scopes, Spring completion or explicit offline proof close release the scratch owners. These changes do not remove existing CSI qualification limits or establish final Java/platform acceptance by themselves.

Frozen CSI batches normalize an absent optional prepared reference back to Java null after typed scratch decoding. Jackson's JSON null node must not look like a completed preparation to the unchanged admission checks. Prepared object references and old frozen prefixes retain their original values; this normalization changes no canonical wire bytes.

## Core API migration

This changes the internal Managed Core contract and all workspace consumers in the same PR. It does not change public event types or the native journal format.

| Previous use                                                           | New use and ownership                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Synchronous event arrays and cold identity getters                     | `readEvents()` returns a bounded Promise page; `iterateEvents()` is a reopenable fixed-prefix asynchronous query. Cold command, receipt, checkpoint, Action and extension queries return Promises. Await query predicates and terminal operators.                                                      |
| All extension records in a resident array                              | `extensionRecordsInDomain(domain, { throughSequence })` lazily reads a frozen version view; old versions and long-lived uniqueness facts stay on disk.                                                                                                                                                 |
| Journal `read()` to open an authority                                  | Every journal reader implements `scan(consume)` and delivers complete validated transactions with exact source offsets/bytes. Authority open never calls the bulk reader.                                                                                                                              |
| Full projected transcript for runtime decisions                        | `iterateMessageRecords(prefix)` preserves message/branch semantics; `iterateRecords(prefix)` also includes terminal/domain records. `projectModelRecords()`/`projectContextRecords()` contain current model context, with branch checkpoints in the latter. Use identity queries for historical facts. |
| Recorder branch arrays and cancellation/Goal scans                     | `readActiveTranscriptHistory()` returns a reopenable fixed active chain, including pre-compaction facts. `createTranscriptQueryHistory()` shares the authority cache. Restore supplies bounded pending-call/compression summaries and a scalar user-turn count.                                        |
| Hydrated checkpoint tool/binding arrays                                | Authorization supplies a compact checkpoint and `ManagedHarnessCheckpointView`: lazy `tools`/`bindings`, asynchronous `tool(executionCallId)`/`binding(executionCallId)` and verified counts/ordinal/settlement summaries. Historical pins and receipts must use this fixed view.                      |
| Managed restore `replay.records`, telemetry and notification-ID arrays | Managed all-history replay supplies reopenable `recordHistory`; telemetry supplies `uiTelemetryHistory`; `hasBackgroundNotification` performs a fresh canonical lookup when the bounded positive cache misses. Finite recent pages and legacy formats retain their array shape.                        |
| Unbounded ACP bulk response                                            | Consume asynchronous replay incrementally. Existing bulk update/byte limits reject with `HistoryReplayLimitError` (`-32012`); use paged history for a larger session. No short success response masquerades as complete history.                                                                       |
| Long-lived read-only authority                                         | `openReadOnly()` does not acquire, create, append or seal a writer. `disposeHistory()` releases its private query generation. A writer's `close()` seals first and drains/releases the history owner once.                                                                                             |

The CSI qualification snapshot retains its existing aggregate 128 MiB/4,096-reference limits; it validates and delivers one transaction at a time. The internal CSI bulk-history response preserves its array envelope and explicitly refuses a response above 64 MiB instead of truncating it. These explicit bounds are separate from normal unbounded-history recovery. No generic resource limit is raised to accommodate an export.

## Streaming restore and local conversion

Incrementally validate complete journal transactions, retaining exact marker chains, record/byte positions and torn-tail semantics. Consume selected native snapshots and continuous tails without whole-journal concatenation. Spill resource census/frontiers and checkpoint facts to the file view rather than growing alternate Maps.

Stream local header discovery, sealed conversion, ordinary restore and replacement verification. Keep the 16 MiB page and existing 64 MiB local resource/manifest limits. Preflight conversion capacity before publishing pages, spilling its page/ref census. Only manifest capacity exhaustion permits source-preserving resume, after the original prefix, sealed proof and every declared/nested resource validate. That branch publishes nothing, renames nothing and preserves the schema-3/format-2 barrier. It does not apply to an existing snapshot base, corruption, I/O failures or ownership uncertainty.

Stream activation/inbox v2 snapshot decode and replacement encode while retaining every canonical identity, order, payload, outcome and fence. The digest still hashes `JSON.stringify(parsed state)`, not raw input bytes. Use a pure-JavaScript streaming JSON parser without retaining consumed containers. Keep only pending/assigned/processing state resident; persist cold per-Session `nextEpoch` as well as released/finished identities. PR1's helper remains derived: supply its validated terminal from the new view, not from a full resident Map.

The parser is [`@streamparser/json`](https://github.com/juanjoDiaz/streamparser-json), pinned to `0.0.26`; it supports incremental JavaScript parsing without a native module or new Node requirement. Consumed state containers are released immediately. Encoding streams the same semantic JSON representation and preserves the existing v2 checksum contract.

The dependency is isolated behind the terminal-snapshot codec and pinned in the lockfile. Upstream inactivity does not change that version or permit a bulk-parse fallback. A replacement or upgrade must preserve semantic checksum, chunk-boundary, malformed-input and consumed-container tests on the supported Node versions; decoder failure refuses the snapshot rather than dropping identities.

## Compatibility and acceptance

New clients can stream existing transactions into a file view when a server does not advertise history-query support. A selected corrupt snapshot never falls back to different history. Managed Core asynchronous interface changes must migrate all workspace consumers and exported documentation together; do not provide a whole-history synchronous compatibility layer.

Compare streamed 10,000/100,000 completed histories with identical active state, payload size and model context in isolated fixed-heap processes. Assert cache/queue limits, record steady and restore peak heap/external/RSS, and prove that completed facts do not form new resident collections. Cover cold/reopened replay/conflicts, once/ordinal/pin/continuation/team/epoch/FIFO/fence semantics, frozen-prefix queries, backfill gaps, sidecar corruption, post-commit view failure, crashes, lost ACK, and uncertain append.

Run actual Core→Java→MySQL snapshot restore and H2/file paths; TCP fixtures and generic daemon smoke do not substitute for the final integrated path. Preserve resource-corruption refusal, including over-capacity conversion plus a missing old resource. The previous PR4 full CI has unresolved Automation/Monitor fault-gate failures; re-evaluate on the final revision without claiming that a merge proves qualification. Local Java setup/build/tests/retries share one 600-second budget; CI owns full profiles and database/platform/fault matrices. Build/typecheck/bundle and affected TypeScript tests remain required. Record exact tested revisions, failures, skips and pending gates.

The full SDK Java workflow includes a separate `managed-history-scale` qualification job for each of H2 and MySQL. Its opt-in Maven profile runs one scale Gate at 10,000 and 100,000 events with a separate fixed-heap Node process for each size, using the actual Core HTTP client and Spring service. This long-running lane does not enter the ordinary 600-second unit fork, replace the normal profiles or narrow their report guards. Require both sizes, compare retained memory, preserve phase metrics and reports on success or failure, and reject filtered/skipped qualification reports. H2 uses file storage; MySQL uses a task-private database. This CI entry is an acceptance mechanism, not evidence that the final-source tests have already passed.

The first two-engine run at `3c92f28d` failed before memory comparison: its fixture submitted different canonical sources for one execution-result identity, which the existing tool-publication contract rejects. The fixture now uses distinct executions and still verifies the window-external original receipt and old-command replay after recovery. The original failures remain recorded. Repaired-source qualification is pending CI; neither this fixture correction nor the earlier file-only measurement proves native scale acceptance.
