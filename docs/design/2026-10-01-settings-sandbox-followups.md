# Settings and sandbox follow-ups (#12417)

[English](2026-10-01-settings-sandbox-followups.md) | [简体中文](2026-10-01-settings-sandbox-followups.zh-CN.md)

## Problem and current state

PR #13119 made settings replacement atomic. Remaining startup paths report malformed operator settings inconsistently, boolean argument parsing loses named sandbox selections, and recovery metadata still refers to User settings although only Workspace recovery remains possible. The sandbox command waits for backpressure but can exit before a final buffered write completes. Both backend relays read ahead on shared regular-file stdin and can remain blocked on an idle named FIFO after the payload exits.

## Goals and scope

Preserve operator policy, make refusals actionable, report the effective boundary, and preserve ordinary command input/output semantics. Keep the existing sandbox policy and atomic publication algorithm. Add regression coverage for BOM reload, private save-directory events and failures, and native Windows replacement. This is a bugfix, not a new sandbox configuration surface.

## Design

Operator read and parse failures use the existing fatal configuration error contract (exit 52). The entrypoint reports the error once without a stack or argument help. Repair instructions name the original file; User preservation copies never authorize resetting operator settings. Workspace recovery remains separate, with exact-path Workspace metadata propagated through relaunch and the existing dialog. A failed reset after a successful preservation copy warns and continues with empty in-memory Workspace settings; inability to preserve a copy still refuses without resetting the original. Replace an existing corruption copy before copying again so read-only originals recover on repeated startups. Refuse before removing a copy that resolves to the original file, preserving the only bytes when the original links to that copy. Malformed recovery requires a single-link regular file at the canonical Workspace settings path; symbolic links, hard links and linked settings directories are refused before changing the original or an existing copy. Valid linked JSON still loads. Preserve raw bytes through a non-following source descriptor and create the copy exclusively with the original mode. Reset opens without truncation, verifies the same inode, then truncates and writes; replacement files are never reset. Startup warnings report the preserved copy without claiming that a reset succeeded. If Exit/restore cannot copy over the original, exact byte equality with the preservation copy satisfies restoration without changing permissions; different or unreadable files retain the copy and report the original failure. Snapshot and preserve-invalid callers retain their refusal semantics.

Let yargs own sandbox option values and subcommand aliases, coercing an empty value or true/1 to true and false/0 to false; repeated selections keep the last value. The default command and sandbox inspector share the same coercion, including case normalization. Session sandbox options do not silently turn subcommands into prompts. Named-option semantics apply everywhere before `--`. This changes the old bare `--sandbox <query>` convenience: use `--sandbox=true <query>` or `--sandbox -p <query>` for automatic selection, and `-p "..."` for literal option text inside a prompt. Both SDKs serialize their boolean sandbox option as `--sandbox=true` so appended text arguments remain separate. `--` stops option parsing, but its trailing tokens are not forwarded as the default-command prompt. The sandbox inspector reports inherited whole-CLI markers separately from tool confinement. Migration checks normalize both environment markers. Report npm as not probed and include the admitted command network policy in the model prompt.

Wait for stdout and stderr write completion, including a final write below the backpressure threshold. Execution cancellation does not cancel output completion: SIGINT/SIGTERM still fence accepted bytes before exit 130/143. Each output stream has its own error cancellation, so EPIPE exits 141 while the other valid stream still drains. Keep downstream error handlers until both flushes settle.

For regular files and named FIFOs, relay bytes through a private Unix stream socket with its payload write half shut, rather than exposing host-backed descriptors. A native helper supervises the backend: positional regular-file reads leave the shared offset unchanged while running; after child exit, nonblocking reads of the retained socket count the actual queued remainder, then advance the shared offset by bytes written minus that remainder. Do not use `FIONREAD` for this count: native partial reads exposed inaccurate remaining-byte accounting. The payload cannot reopen this socket via `/dev/stdin` or `/proc/self/fd/0` or write into its own receive queue. Read fd 0 directly; tools that reopen these paths, or require FIFO identity, may need adaptation. Poll nonblocking FIFO input and child completion together, so an idle writer cannot prolong exit. Directly inherited anonymous pipes, sockets and character devices remain explicit caller capabilities. Closed networking prevents new ordinary IP connections; it does not revoke existing standard-stream capabilities.

## Constraints and risks

Resolve the optional input helper only for inherited stdin. Missing or non-executable bundled helpers do not block bwrap probes or directly inherited pipe/TTY launches; host-backed input is refused before execution when no bridge is available. Landlock pins apply to both helper roles; custom helpers receiving host-backed input must implement the new internal relay mode. Explicit `stdio-setup-failed` records attest failure before backend exec, while `stdio-failed` after execution remains unknown unless payload exit was observed; empty bwrap status is never inferred from exit 125 alone. When needed, both backend relays consume the input helper; other Linux architectures retain directly inherited pipe/TTY execution but reject host-backed stdin without a supported helper; their status transport, payload attestation and cancellation behavior must remain intact. Bundled Linux x64 and arm64 helpers must rebuild reproducibly with the pinned compiler. Regular-file offset accounting concerns bytes consumed from the OS descriptor, not application-level parser consumption. Concurrent readers sharing stdin are outside this accounting contract. Do not grant a linked worktree's external Git metadata implicitly. A successful backend probe establishes admission, not full-session viability under every TMPDIR or environment setting.

## Validation and acceptance

Use isolated global-CLI baseline cases and repeat against the built CLI for interactive, headless, MCP, serve and ACP startup. Require one actionable refusal, a nonzero exit and unchanged malformed operator files. Cover named flags, aliases, boolean flags, the option-parsing stop at `--` and literal text in explicit prompts; BOM reload and three consecutive startups with read-only Workspace files, including preservation-copy aliases, external original/parent links and replacement-before-reset; final stdout/stderr bytes through slow real pipes after normal exit and SIGINT/SIGTERM; downstream close while the other output remains valid; zero-read and partial-read regular files; FIFO private-socket identity and exit with a live idle writer; Linux write-reopen refusal with exit and offset preservation; inherited connected descriptors; and preservation of original files on native Windows sharing violations. Run Linux kernel boundary checks separately from fake-backend transport tests. Build, typecheck, focused unit tests, independent verification and review are required. Platform cases are not considered verified until exercised on that platform.

Native CI also runs the public CLI verification matrix and ordinary shell tool calls under the runner's own UID. The native CLI harness is a permanent regression asset; its manual POSIX smoke mode provides an unsandboxed fake-provider control. A local fake model endpoint drives the real agent/tool loop; it does not establish authenticated provider or full-session viability. Run native Windows publication tests independently so unrelated full-suite failures cannot hide their result.

Create the host verification fixture before probing the backend, so an unusable TMPDIR reports the original host path and repair action without implying that the sandbox boundary was tested. Clean up that fixture after admission or verification failures. Inspection and explicit command execution do not create a verification fixture.

## Release communication

Document that malformed SystemDefaults, User and System settings block startup rather than silently resetting. Also call out named sandbox option semantics and the Linux x64/arm64 helper requirement for host-backed stdin. The generated changelog is not edited by hand; include this behavior in the fix's release description and user documentation. Keep #12417 open until the tracking acceptance matrix, including native platform evidence, is complete.
