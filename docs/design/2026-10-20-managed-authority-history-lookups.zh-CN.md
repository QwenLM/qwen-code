# Managed authority 历史索引读取

[English](2026-10-20-managed-authority-history-lookups.md) | [简体中文](2026-10-20-managed-authority-history-lookups.zh-CN.md)

## 问题与范围

这是 #13184 的独立分片，用于减少重复历史扫描。Authority 当前对序列范围过滤
全部保留事件，每次读取后续页都重新访问历史前缀，并从尾部反向扫描指定类型的
最新事件。因此，连续投影分页会重新访问已经消费的历史；查询不存在或较少出现
的类型时，每次同样可能遍历全部保留历史。

本次保持全部事件、命令身份、receipt、恢复事实和读取结果不变。它不代表
完成 authority 内存限制、原生 journal snapshot/压缩、终态身份保留或独立的
activation/inbox 快照分片。不引入保留下界或 TTL。

## 当前不变量与消费者

Journal scanner 要求已提交事件从 sequence 1 开始并严格连续。每个运行中事务
追加前都验证它继续当前已提交序列；只有已提交事务会进入 authority 事件数组。
结果未知的追加在结果得到证明前保持不可见。

分页投影与 Hosted transcript/event 读取使用 `readEvents`；recorder 上下文摘要、
Hosted 执行与恢复使用 `eventsInSequenceRange`；Hook activation 与原始 receipt
checkpoint 观测还使用 `lastEventOfKind`。这些同步 API 和返回的事件对象保持不变。
现有按 execution call 索引的 receipt 继续保留首次 receipt。

`context.compacted` 描述模型历史摘要覆盖范围，独立于原生 journal 重放下界；
本次不会使用它跳过任何保留事件。

## 变更方案

- 对每种已验证事件类型保留最新已提交事件。打开已提交 journal 时建立有限 Map，
  后续在普通追加和结果未知追加结算共享的已提交事件索引路径中更新。Map 对封闭
  事件类型 schema 的每个成员最多持有一个事件引用。
- 把两端均包含的序列范围转换为事件数组偏移，只复制请求范围。端点限制在保留
  数组内，保持小数端点行为；对乱序或 NaN 端点返回空范围。
- 分页读取从序列对应的数组偏移开始，不再访问已经消费的前缀。保持现有限额
  计算、正数限额拒绝、迭代和停止条件，包括既有数值边界行为，避免为了性能
  改变调用者契约。

既有的 `limit: 1.5` 和 `limit: NaN` 仍然读取剩余尾部，
`afterSequence: NaN` 仍然从第一个事件开始。这些兼容场景均有明确测试，
不改变上层的游标校验。

最新类型读取变为 O(1)，范围或分页变为 O(返回数量)，无需访问之前的前缀。
历史数组与已有历史索引仍会增长，新增 Map 自身由 schema 类型数量限制。
返回数组中的事件引用不克隆、不替换。

## 决策与边界

直接偏移依赖当前已验证、从 1 开始的连续历史不变量。以后启用物理事件淘汰前，
必须有持久历史读取器与新的偏移基准；不能删除前缀后静默沿用当前寻址。
本次既不增加该读取器，也不声称已启用压缩。

只有事务已提交或被证明落盘后才能更新索引。失败、拒绝或尚未确定结果的尝试
不能成为最新事件。已有幂等命令重放也不能推进索引。

不需要新选项、公共字段、端点、生成契约或消费者迁移。新的历史读取契约应是
单独变更，并完成自身的持久性与恢复验证。

## 验证

1. 通过真实内存 journal 与 authority 已验证的打开/提交路径复现前缀访问。
   统计事件数组的数字下标读取，不依赖耗时阈值。读取有界尾部页或范围时只应
   访问返回的事件，查询不存在的类型不应访问历史。
2. 验证空、两端包含、反向、截取、小数和非有限数值的范围与分页，以及默认/
   最大限额和现有限额错误。
3. 比较新提交、命令重试、重新打开、追加被拒绝和结果未知追加结算前后的
   最新类型读取结果。
4. 执行 authority、recorder、projection、Hook 和原始 receipt 消费者测试，
   然后 build、typecheck、bundle、格式/引用检查、两轮自查和独立验证/审查。

## 验收与剩余工作

返回序列、事件身份、首次 receipt 语义、命令重放、恢复和全部既有测试保持不变。
有界分页/范围的实测访问次数独立于前缀长度。全部 journal 字节和保留历史仍可读取。
#13184 中剩余的 authority 内存与原生 snapshot/压缩要求仍明确保持开放。
