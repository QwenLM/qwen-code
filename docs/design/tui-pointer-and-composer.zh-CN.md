# TUI 滚动、选择和权限位置

[English](tui-pointer-and-composer.md) | [简体中文](tui-pointer-and-composer.zh-CN.md)

## 问题和证据

虚拟聊天区对每个上报的滚轮事件移动三行，然后等待尾部 16 ms 输入定时器
和 Ink 输出节流。高频输入因此呈现 6–9 行的台阶。此外，Ink 补丁会先对
5000 行消息中的不可见行做横向裁剪，再做纵向裁剪：实测渲染 p50 为
68.50 ms，将纵向裁剪提前后为 5.42 ms。

主聊天区在标准 SGR 输入下可以选择文字，但会话预览弹窗缺少选择控制器。
原生 Warp 拖选验证仍待完成，因为原生自动化鼠标接口报告
noWindowsAvailable。当前权限模式占据左侧页脚，离输入框较远。

## 改动和理由

保留现有虚拟列表和 Ink 渲染器。调整 Ink 裁剪顺序，使横向处理只覆盖
纵向可见行，同时保持输出、语义边界和选择单元格。不给元数据增加缓存。

每个上报的滚轮事件按一行处理，对齐 Grok 在 Warp 的归一化方式。第一步
立即交付，后续更新合并到 16 ms 节奏。每次最多移动半个视口（至少一行），
剩余输入在后续帧交付。停止输入后，最多再追赶半个视口，丢弃异常突发的
剩余积压。反向操作丢弃旧方向积压；键盘导航、指针按下、
失去焦点及卸载取消待处理位移。滚动条按下仍立即定位，拖动使用最新位置。
只有当前位置到达当前底部时才重新跟随尾部，防止测量时把向上一行的操作弹回。
聊天增长时，之前的位置也必须到达之前的底部；一行容差会让新消息撤销明确的向上滚动。
这改善终端行的连续移动，不引入像素坐标，也不复制 Grok 的完整加速和
输入分类系统。

给会话预览弹窗接入已有的文字选择和内容鼠标控制器。上下文菜单打开时
暂停滚动和选择事件，保留已选文字。菜单中的 Escape/Enter 不得退出或
恢复会话预览。鼠标坐标继续采用物理终端尺寸。
复制和高亮都限制在选区所属视口，装饰边框不参与选择。渲染器的可选选区
边界随范围传递，并参与去重。叠加选择背景时替换单元格原有背景样式，
使 ANSI 序列在选区结束后立即恢复弹窗底色。

用户已确认主聊天区在 Warp 的拖选恢复正常。给输入文字区域接入相同的
可见区域选择，每个输出流只允许一个选区拥有者。拖动高亮并复制，不移动
输入光标；普通单击仍定位光标。编辑输入文字会清除用于复制的可视选区。
本轮不给文字缓冲区增加可替换的编辑选区。思考、工具和过程摘要在存在
文字选区时忽略松手展开，包括拖动后又回到起点的操作。

主视图和 agent 视图都在输入框右下边框显示本地化权限模式。保留语音和
会话顶部标签、光标坐标及输入框高度。标签按终端单元格宽度截断。
保留模式切换提示，并在没有可视输入边框时保留权限显示。
权限策略和模式切换处理仍使用现有实现。

## 范围和文件

改动涉及现有 Ink 补丁及回归测试、ScrollableList 和帧调度器、VirtualizedList
的尾部跟随规则、
SessionPreview、BaseTextInput、InputPrompt/Footer、
AgentComposer/AgentFooter、TextInputMouseController、选区归属、思考/工具/过程
点击保护及定点测试。保留已有弹窗和聊天层级改动。
OpenTUI 和终端原生回滚继续使用现有滚动实现。

## 验证和验收

在全局和本地 PTY 使用相同合成聊天、事件、时间戳及可见帧进行比较。
验证稀疏输入、高频输入、突发排空、反向、PageUp/Home/End、滚动条接管、
焦点和缩放。比较长消息改动前后的渲染，保持输出和语义单元格一致，
覆盖 CJK、ANSI 样式及横纵同时裁剪。

在聊天区和预览选择 ASCII、CJK 和多行文字，验证高亮、松手复制、
上下文菜单归属及返回原聊天。验证主输入和 agent 输入中的权限标签、
全部模式、窄终端、多行输入、顶部标签以及读屏和原生回滚兼容路径。
运行定点测试、lint、格式检查、build、typecheck 和 bundle。
如果原生 Warp 指针自动化仍不可用，如实记录覆盖缺口。

## 待解决问题

原生自动化仍无法向 Warp 交付指针操作。用户已确认主聊天区拖选正常；
使用真实 PTY 测试环境和定点测试验证输入框选择及松手误展开的缺口。
