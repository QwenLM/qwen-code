# Remote serve quickstart

## Problem

A non-loopback `qwen serve` currently refuses to start without an operator-created bearer token. The built-in Web Shell also requires an origin allowlist for same-origin mutations, and offers no recovery when a tab lacks a valid token.

## Design

- Resolve explicit `--token` before `QWEN_SERVER_TOKEN`, preserving trimming and explicit-empty shadowing. Only when neither source is present and BOTH the requested `--hostname` and its resolved bind are non-loopback, generate 32 random bytes as a hex bearer; a `localhost` request that resolves outside loopback keeps the existing fail-closed refusal and never generates. Explicit empty sources still fail the existing remote-bind check. Loopback and `--require-auth` defaults are unchanged.
- Keep generated credentials ephemeral and process-local. After successful listen, print the generated bearer once as intentional stdout credential output, separate from diagnostics. Never add it to ordinary URLs, logs or discovery metadata. Show token-free local/network URLs for wildcard listeners, advertised from the same private-LAN population Local Control uses (RFC 1918 / RFC 3927 IPv4 plus fc00::/7 ULA on physical interfaces; software/VPN/container-bridge interfaces, scoped and link-local IPv6 addresses, and routable public addresses are excluded); no public-IP lookup. Wildcard detection is canonicalised (trimmed/lowercased, including the IPv4-mapped `::ffff:0.0.0.0`); a zone-scoped explicit bind prints no quickstart entries. The whole block writes through the non-throwing stdout helper so a vanished pipe reader cannot take the listening daemon down. Warn that HTTP is unencrypted.
- Preserve existing loopback origin handling. Add a narrowly scoped remote same-origin middleware immediately before the origin policy: only on the primary non-loopback listener with a configured token, compare a canonical HTTP(S) Origin to the direct socket scheme and exact Host authority, ignoring forwarded headers. Authenticate matching requests before stripping their Origin. Cross-origin requests still use existing CORS policy; null origins remain rejected. This does not reorder static routes, health exposure, Host gating, Local Control, or body parsing. Both bootstrap and fully mounted apps use this guard. Its pre-auth predicate comes from the dependency-light `web-shell-preauth` module so the serve fast-path static closure keeps deferring the express-static/CSP machinery.
- In standalone Web Shell bootstrap, probe authenticated `/capabilities` before mounting the workspace. A 401 opens a token password form; a successful retry stores the token in the existing per-tab cache/sessionStorage and mounts the app. A 403 explains origin/Host policy separately rather than requesting another password. Transient outcomes auto-recover instead of dead-ending: a response carrying `Retry-After` (the bootstrap app's cold-runtime 503) re-probes on that interval, other network/5xx failures re-probe on a fixed interval, and a 503 WITHOUT `Retry-After` is the permanent runtime-failure envelope — its error text is surfaced with manual retry only. Every probe is bounded by a 10s abort (below the SDK's 30s fetch timeout) and cancellable on unmount; the retry button is never permanently disabled. Copy is bilingual (en / zh-CN) following the pre-app `RootErrorFallback` convention. Existing fragment handoff and extension postMessage remain supported; token-bearing URLs are still scrubbed in every build mode.

## Security decisions

The same-origin exception requires a verified bearer, not merely a matching attacker-controlled Host. Loopback exemptions remain unchanged. Local Control uses its existing listener-scoped credentials and origin allowlist, and is excluded from the remote exception. No proxy trust, cookie auth, persistent secrets, new flags, account management, certificate provisioning or TLS changes are introduced. Generated credentials rotate on restart; old tabs can enter the replacement token. Explicit credentials are never printed as plain text. The startup QR deliberately contains the resolved credential in a URL fragment, with an explicit secret warning; normal address lines remain token-free. The QR prints when the credential is the process-generated ephemeral one (its only delivery channel) or when stdout is an interactive terminal — a stable operator token is never re-published into captured stdout (container/systemd logs) on every restart. Reuse `qrcode-terminal`, choose the first deterministically enumerated private-LAN address, print an explicit fallback line when no candidate exists, and omit QR when Web Shell assets are disabled/unavailable. Existing public shell requests must bypass remote same-origin authentication because browser module-script fetches carry Origin without Authorization; API requests still authenticate.

## Files and verification

CLI token resolution, startup output, shared self-origin middleware, the extracted pre-auth predicate module, and both server mounts; standalone token configuration/bootstrap/auth gate and focused regression tests; serving, developer-daemon and help-text documentation. Regression coverage includes option/environment precedence and empty values, entropy/rotation, env-token end-to-end authentication, remote authenticated same-origin success at the real app mount, invalid/missing bearer, cross-origin/null/forwarded header rejection, LAN-population filtering, QR credential gating, startup-block EPIPE resilience, token UI retry/storage/auto-recovery, DEV-mode URL scrubbing, and unchanged loopback/local-control behavior. Baseline and bundle checks are recorded in `.qwen/e2e-tests/serve-remote-quickstart.md`.

## Boundaries and open questions

No changes to session/runtime ownership or API routes. `/capabilities` is the existing process-global bootstrap endpoint and is read only; normal selected-runtime and workspace routes remain unchanged. NIC addresses are suggestions, not a promise of firewall/NAT reachability. HTTP remains explicitly unencrypted. Three deliberate deferrals, all documented in the user guide and (for the first two) named by a startup warning: the WebSocket upgrade gate (terminal, voice) keeps its loopback/allowlist-only CSWSH policy, so remote same-origin WS still needs `--allow-origin` — extending the exception to upgrades requires its own bearer-verified design; the bootstrap probe's `/capabilities` response is discarded rather than seeded into the workspace provider, costing one extra same-endpoint round trip per standalone load; and — observed end-to-end, pre-existing and not introduced here — during a MULTI-workspace cold start the bootstrap app answers uncredentialed shell document/asset requests with its bearer 401 for ~150-200 ms (longer on slower hosts) until the runtime mounts, so a browser navigating inside that window renders raw JSON and needs one manual reload; the single-workspace default has no such window, human QR-scan latency effectively never lands inside it, and serving the pre-auth shell during the bootstrap phase is its own design decision tracked as a follow-up. No open product decisions remain for this change.
