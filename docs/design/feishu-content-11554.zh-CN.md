# 飞书富文本和引用内容（#11554）

[English](feishu-content-11554.md) | [简体中文](feishu-content-11554.zh-CN.md)

## 问题与范围

当前飞书 post 解析丢失图片、链接地址、代码和视频描述。引用查询重复解析逻辑，且忽略文件和图片引用。[Issue #11554](https://github.com/QwenLM/qwen-code/issues/11554) 是验收依据。本次有界修复沿用现有 Channel 附件契约，不增加路由或修改共享接口。

## 设计

包内内容解析器返回可读文本、提及名称、文本是否由用户编写，以及有序去重的资源描述列表。优先渲染非空 content_v2，回退到 content。保留 Markdown、代码块和链接。通过字段名识别直接接收结构，再处理语言包装。纯媒体 post 生成合成占位文本，避免被当作空消息丢弃或被无法满足的消息前缀要求阻止。

直接消息和引用消息共用解析。每个可下载资源保留原消息 ID。在现有预检授权通过后，沿用大小限制和下载工具，将图片作为 base64 附件、文件作为临时路径传递。引用内容继续作为不可信上下文包装；父消息中的文件和图片通过现有附件传递。元数据保留原文件名，文件系统路径进行安全处理。下载失败时明确保留资源不可用上下文。卡片引用文本提取保持原行为，不下载卡片和合并转发资源。

## 边界与风险

不增加出站上传、任意递归引用、云文档读取、新凭据或大小上限。保留结构化媒体顺序，同一消息重复资源 key 仅下载一次。不抓取 Markdown URL。共享 collect 缓冲和临时文件生命周期留待后续：当前 collect 消费会清除图片附件，适配器仍使用固定 60 秒清理定时器。定时清理风险需要完整队列生命周期验证及共享所有权设计。合并转发展开和不支持类型的明确提示也保留在 #11554 中跟进，本 PR 不关闭该 Issue。音视频可以本地文件形式传递，不保证所有模型均能解码。

## 验证与验收

先补官方 post 结构、content_v2、代码、链接、多图、文件和图片引用的失败测试。适配器测试使用模拟平台 HTTP，观察 bridge 输入和资源请求的原消息 ID。验证被阻止消息不会下载资源、部分失败有明确上下文、既有提及/前缀/卡片行为不回归。执行 build、typecheck、bundle、定向测试和两轮无发现自审。真实飞书 E2E 与模拟集成证据分开，明确记录平台访问限制。
