# 飞书富文本和引用内容（#11554）

[English](feishu-content-11554.md) | [简体中文](feishu-content-11554.zh-CN.md)

## 问题与范围

当前飞书 post 解析丢失图片、链接地址、代码和视频描述。引用查询重复解析逻辑，且忽略文件和图片引用。[Issue #11554](https://github.com/QwenLM/qwen-code/issues/11554) 是验收依据。本次有界修复沿用现有 Channel 附件契约，不增加路由或修改共享接口。

## 设计

包内内容解析器返回可读文本、同一消息不含媒体占位符的另一份渲染（用于命令分类）、文本是否由用户编写，以及有序去重的资源描述列表。优先渲染非空 content_v2，回退到 content。保留 Markdown、代码块和链接。Markdown 节点的块级与行内结构来自 CommonMark 解析器（markdown-it），不再用表达式从渲染后的文本反推：平台图片 key 只有在解析器读出图片的位置才是资源，因此代码围栏、行内代码、缩进、容器、引用式定义和 HTML 块都不需要各自的语法，两个作者身份判定也出自同一次解析。当解析器无法为全部文本作答时——抛出异常、节点超过分析上限、或嵌套达到解析器上限而不再下探——该节点按「用户撰写」处理，失败绝不损失整条消息：抛出异常时该节点不产出 key，超过上限时只损失上限之后的 key；由此漏掉的图片只要 legacy 镜像提到它，仍会送达。legacy content 镜像中的类型化 img/media 节点是平台自己对「这条 post 携带了什么」的陈述；只有镜像提到的 key 排在 content_v2 给出的所有 key 之后，按镜像顺序。命令渲染把媒体节点渲染为空、把链接渲染为其标签，因此媒体节点不会夹在命令与参数之间，也不会从成员可能亲手输入的文本里反推占位符。只要消息带有 legacy 行，就再按「本解析器出现之前分类器读到的样子」渲染一份——只含文本、链接标签和提及名，其余节点一律为空——并优先尝试：legacy 行拼出的命令会原样按一直以来的方式派发，Markdown 图片、代码块或分隔线既不会出现在命令里，也不会挡在它前面。命令渲染只在 legacy 行无法表达时兜底——Markdown 提及标签之后的命令，legacy 行把该提及写成任何提及 key 都解析不掉的显示名。因此命令的参数就是 legacy 行的文本，与一直以来相同：命令旁边的代码块或链接地址会保留在普通轮次给模型看的文本里，但不会带进命令参数（`/btw` 的问题也是如此——作为 #11554 的后续项）。通过字段名识别直接接收结构，再处理语言包装。纯媒体 post 生成合成占位文本，避免被当作空消息丢弃，且占位文本不会作为成员发言记入群聊历史。

直接消息和引用消息共用解析。每个可下载资源保留原消息 ID。在现有预检授权通过后，沿用大小限制和下载工具，将图片作为 base64 附件、文件作为临时路径传递。每条消息最多采集 8 个不同的资源（按文档顺序，超出丢弃并追加一行汇总说明，按不同 key 计数）；单张图片不超过 8 MiB 原始字节（即 bridge 的单图上传准入上限 CHANNEL_IMAGE_MAX_UPLOAD_BYTES，按解码后字节比较），文件下载总量不超过 100 MiB；适配器不再设图片总量预算——默认启用的 daemon 通路逐张上传、无总量上限，inline 兜底通路的 base64 总量上限由 bridge 自己执行。下载失败时明确保留资源不可用上下文，失败标记超过 4 条后折叠为一行汇总，并按原因区分「无法取得 / 超出预算 / 鉴权失败」。引用内容继续作为不可信上下文包装。适配器以自身口吻说出的每一行——包裹的开闭标签、来源行、缺失标记——都以本轮铸造的同一个 nonce 结尾（`[/引用内容 #1a2b3c4d]`），而 nonce 在发送者和被引用作者的文本都已存在之后才生成，因此两者都无法提前闭合包裹或冒充适配器声明来源；nonce 为十六进制，群聊路径消毒器的折叠与方括号剥离都不会改动它；包裹里有一行会告诉模型：引用内容到带相同编号的结束标签为止（独立成行，这样横幅、规则行和结束标签都落在消毒器 64 字符的标签窗口内，剥括号的结果一致）。`(image)` 这类媒体占位符只是内容的替身，不作任何声明，因此不带 nonce。包裹内部，被引用文本放在一个比其中任何反引号串都长一个反引号的代码围栏里，因此其中未闭合的围栏或 HTML 块在围栏之外没有任何结构。反引号串在去掉方括号后计数，因为群聊路径的剥离会删除成对方括号并把两侧的反引号串连成一串；在该路径上折叠会把围栏变成同样长度的行内代码段，同一计数意味着被引用文本里没有任何东西能闭合它；同一行上位于包裹之外的内容——发送者自己的名字标签和问题——属于发送者，而不是被引用作者。长度上限在码点边界处截断。不再从发送者文本中剥离任何内容；对被引用内容只删除形如完整提及标签的文本（标签及其包住的、至多 200 字符的名字）。父消息中的文件和图片通过现有附件传递，并附带 `[引用附件 message_id=… #nonce]` 来源行，其中内插的 id 与名称被约减到各自的字段文法；父消息查询失败时前置 `[Quoted message unavailable: …]` 标记，查询成功但类型无法渲染时前置一行如实说明其类型的文本。纯媒体父消息在两种表示下返回的都是适配器占位符而非用户原文，不套用引用包裹；机器人自己发送的父消息使用机器人专属横幅。带本地命令（/approve、/clear 等）的回复按命令轮处理：以不含占位符的渲染派发，不附加引用包裹、不下载任何资源；只有 /btw 会把被引用上下文放进它的问题文本内：取引用内容中「连同围栏在内的包裹形式仍放得进问题输入上限」的最长前缀。`!` 轮次的文本会被宿主 shell 执行，因此不会被改写，也不会在其前面放置任何内容。元数据保留原文件名，文件系统路径进行安全处理并限制长度。卡片引用文本提取保持原行为，不下载卡片和合并转发资源。

私聊引用保留父消息用于上下文和资源查询，但不创建 Channel 线程，因此普通授权回复与引用请求属于同一私聊范围。群消息继续使用 root_id 保留线程隔离。

## 边界与风险

不增加出站上传、任意递归引用、云文档读取、新凭据或大小上限。保留结构化媒体顺序，同一消息重复资源 key 仅下载一次。不抓取 Markdown URL。共享 collect 缓冲和临时文件生命周期留待后续：当前 collect 消费会清除图片附件，适配器仍使用固定 60 秒清理定时器。定时清理风险需要完整队列生命周期验证及共享所有权设计。合并转发展开和不支持类型的明确提示也保留在 #11554 中跟进，本 PR 不关闭该 Issue。音视频可以本地文件形式传递，不保证所有模型均能解码。

## 验证与验收

先补官方 post 结构、content_v2、代码、链接、多图、文件和图片引用的失败测试。适配器测试使用模拟平台 HTTP，观察 bridge 输入和资源请求的原消息 ID。验证被阻止消息不会下载资源、部分失败有明确上下文、既有提及与卡片行为不回归。执行 build、typecheck、bundle、定向测试和两轮无发现自审。真实飞书 E2E 与模拟集成证据分开，明确记录平台访问限制。
