# 模型上下文中的附件路径

[English](attachment-path-context.md) | [简体中文](attachment-path-context.zh-CN.md)

## 问题与范围

上传文件已保存在磁盘上，但分发时只提供内容和 `attachment:///` 标识
（图片仅携带字节和 MIME 类型）。模型需要通过脚本处理原文件时，必须自行
寻找位置，有时依赖记忆。本修复直接提供位置，不依赖记忆；不增加 Excel
解析、不修改浏览器预览，也不新增工具。

## 设计

会话附件存储在原内容块的 `_meta[DAEMON_ATTACHMENT_CONTEXT_META_KEY]` 中
添加模型上下文字符串，包含以 JSON 编码的存储名称、附件 URI、MIME 类型和
绝对路径，并说明使用该路径调用 daemon 主机上的工具。名称和路径使用 JSON
编码；附件内容仍属于用户数据。图片保留内联字节，文本文件保留原有内容。

`Session` 将该上下文加入模型的引用内容，包括仅有图片的消息，不合并到用户
正文中。每个附件引用仍对应一个内容块，用户展示文本、标题输入以及回合中
附件引用的持久化行为保持不变。

Vision Bridge 从解析后的文本生成解读提示时，排除附件路径元数据，避免其
占用 2,000 字符预算而挤掉用户问题、展开后的命令或语音转录。主模型仍然
接收路径上下文。普通发送、自定义命令和回合中投递共用这一过滤逻辑。

路径取自提供文件字节的同一次成功读取。不推算默认目录：自定义根目录可能
回退到旧存储。对外附件下载响应保持不变。存储引用分发时生成元数据，包括
恢复会话后分发的引用，不单独持久化一份路径映射。

正常提示分发和回合中消息队列消费已经共用解析器，降级时两者都保留有效
附件内容块中的元数据。重复引用继续共用一次读取和编码，读取失败后仍从
分发缓存中移除。

## 约束

路径属于 daemon/ACP 执行文件系统，不属于浏览器所在机器。受支持的 daemon
在本地启动 ACP 子进程，但 SSH 或 Managed 会话可能把工具委派到另一个文件
系统。元数据明确标注 daemon 主机，不声称远程工具可以访问该文件。ACP 当前
拒绝独立的工具执行沙箱。本修改不增加远程文件系统传输或沙箱挂载。现有
工具权限继续生效。附件缺失时保留现有失败或降级行为，不能到其他会话寻找
替代文件。没有存储附件引用的原始内联内容不
添加路径元数据。

绝对路径会作为提示内容发送给配置的模型服务商。默认路径可能暴露 daemon
用户的主目录名称，自定义根目录可能暴露其目录层级；当前方案不做路径匿名化。
若要使用由工具解析的私有附件别名，需要另行设计。

提供路径不会增加对不支持的二进制格式的解析器。模型可以通过 shell 工具
调用可用的解析器。分发后删除文件仍可能使此前提供的路径失效。

## 验证与验收

- 在禁用记忆的新会话中，图片、文本和二进制附件的绝对路径出现在最终模型
  请求中；通过这些路径读取到的字节与原文件一致；视觉模型仍可接收图片内容。
- 自定义根目录、备用根目录、恢复后的存储、重名文件以及包含空格或 Unicode
  的名称都指向正确的存储文件。
- 不可用附件继续按原有语义报错或降级；回合中投递时，有效附件同时保留
  元数据和内容。
- 现有内容、读取缓存、下载和会话隔离测试通过。
- 正常消息和回合中仅含图片的消息保留原展示文本及附件引用；路径仅进入模型
  上下文。
- 较长的附件元数据不会占用 Vision Bridge 的解读提示预算或挤掉用户问题；
  主模型仍然保留路径。
- 构建、类型检查、定向单元测试以及隔离的 Store → Session → OpenAI 请求
  转换探针通过。探针不调用模型、不加载个人记忆，验证请求构造和文件访问。
