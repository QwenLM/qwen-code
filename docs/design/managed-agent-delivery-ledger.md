# Managed Agent delivery ledger

[English](managed-agent-delivery-ledger.md) | [简体中文](managed-agent-delivery-ledger.zh-CN.md)

This ledger holds the merged history of the Managed Agent dual-path delivery proposed in [#12380](https://github.com/QwenLM/qwen-code/issues/12380). The proposal's issue body keeps the delivery snapshot and the open implementation PRs; the merged rows moved here on 2026-10-07 because the body had come within 10 KB of GitHub's 256 KiB issue-body limit. This revision covers PRs merged up to main `d0ddd020c8` (2026-10-07 09:08 UTC); later merges are added at the next reconcile. Rows describe the merged final PR body, not a review-time draft, and keep the evidence scope each PR claimed. This is an implementation inventory, not production acceptance.

## How to maintain this ledger

- One row per merged PR: ``| [#PR](https://github.com/QwenLM/qwen-code/pull/PR) | merged (`merge commit`) | Proposal coverage | Remaining boundary |``, with the merge commit abbreviated to ten characters.
- Write every PR or issue reference as an explicit link, `[#N](https://github.com/QwenLM/qwen-code/pull/N)` for a pull request and `[#N](https://github.com/QwenLM/qwen-code/issues/N)` for an issue: repository Markdown does not auto-link a bare `#N` the way an issue body does.
- When a PR listed in the [#12380](https://github.com/QwenLM/qwen-code/issues/12380) open table merges, remove its row from the issue and add it here, rewritten to the merged final state: scope, migration number and contract version as landed, remaining boundaries, and verification evidence attributed to its exact head.
- Keep this file and its Chinese twin in the same row order with the same rows; `README.md` in this directory describes the pairing rules.
- Rows through [#12998](https://github.com/QwenLM/qwen-code/pull/12998) keep the stage-grouped order of the issue table as it stood on 2026-10-07; rows from [#13277](https://github.com/QwenLM/qwen-code/pull/13277) on are in merge order, and new rows are appended in merge order.
- A PR belongs here when its scope is the Managed Agent delivery (the sdk-java services, the Hosted and managed runtime code, their tests, docs and CI lanes); a PR that merely touches a managed test among unrelated work gets no row.
- A PR closed without merging keeps a row in the "Closed without merging" table so its scope and replacement stay findable.
