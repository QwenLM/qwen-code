## 问题与当前状态

交互运行时迁移至 Bun 与替换 Ink 是两个独立变化。成功标准必须同时保住
npm 和 standalone 的安装、更新、进程生命周期，以及用户当前从 Ink 获得的
行为。PR 合并、mock 测试成功或成功回退到 Ink 都不足以证明迁移完成。

OpenTUI 基础、大量对话框、长记录窗口化及稳定光标已经进入 main。
#14044 的 Hooks 与 sandbox Diff 工作合并到了旧功能分支，没有进入 main。
PTY #14046 与 standalone 更新栈 #14134/#14139/#14142/#14187/#14210
仍未合并。当前 npm 安装不提供完整的 Bun/OpenTUI 运行时。
全局 `qwen` 0.23.0 只能作为历史基线：strict OpenTUI 因缺少原生包无法启动。

## 目标与边界

- TUI 使用 Bun，保留 npm、npx 和 standalone 入口。
- 盘点当前 Ink 的每个命令、对话框、输入操作、记录状态、状态提示及用户
  设置，逐项追踪到 OpenTUI 的生产接线。
- 分别比较运行时和渲染器变化，并回归最终安装产物。
- 提交完整且便于审查的 PR，通常包含测试和文档共 2,000–3,000 行变化。
  不为凑行数填充改动，也不为凑行数删除测试。
- 复用 React、现有桥接层、node-pty、Vitest、交互 PTY 测试框架、
  xterm、假模型服务和现有 parity 脚本。

本方案不引入 Solid、不重设计 agent 协议、不替换包管理器，也不合并默认
运行时切换、默认渲染器切换与删除 Ink 三个决策。

## 运行时与分发契约

每个子进程入口必须分类为宿主运行时、需要 Node 的 JavaScript、随包 Bun
JavaScript、原生程序或用户命令，不能机械替换 `process.execPath`。
Shell、MCP、hooks、skills、sandbox、daemon/WebSocket、restart 和
updater 消费方需要相应生命周期测试。

Node standalone 保留原有 npm 传输和配置行为。Bun standalone 必须在没有
外部 Node/npm 时工作，保持运行时类型，验证归档与 manifest 来源，在空的
隔离目录 smoke test，原子激活，并保留可用回滚。无效 manifest 必须安全拒绝，
同时给出准确恢复说明。空 HOME 不能把项目 `.npmrc` 当作可信用户配置。

发布证据覆盖支持分发中的 darwin arm64/x64、Linux arm64/x64 和 Windows
x64。明确注明不支持的变体，例如适用时的 musl。测试 npm 全局安装、npx、
相关安装脚本及 optional dependency 模式，以及干净 PATH、没有全局 Bun
时的 standalone。

## Ink 对齐契约

维护能力清单：当前 Ink 源码、OpenTUI 生产调用点、输入序列、可见状态、
副作用、自动化用例、必要人工用例、结果及精确候选版本。可选回调没有生产
调用方，就不算完成实现。

覆盖 slash 命令和对话框；编辑及快捷键；历史和 Vim；Unicode、CJK（中日韩）、
emoji 与 IME；多行和 bracketed paste；图片所有权；工具批准与取消；
流式输出及打断；记录选择/滚动/resize；会话恢复；状态/footer/loading/
错误；语言、主题和屏幕阅读器设置。

Ink 是预期行为的参考。已经证明的旧 Ink 缺陷应登记为明确例外，不能复制
不可达或错误的交互。短终端里的必要内容以及退出/返回操作，必须能够通过
滚动和键盘导航访问。

## 对比与回归策略

同一组确定性场景、假模型响应、配置、终端尺寸及候选源码分别运行：

| 组  | 运行时 | 渲染器         | 隔离的变化          |
| --- | ------ | -------------- | ------------------- |
| A   | Node   | Ink            | 现有行为契约        |
| B   | Bun    | Ink            | 与 A 比较运行时行为 |
| C   | Bun    | strict OpenTUI | 与 B 比较渲染与交互 |

Strict 表示回退渲染器算失败。记录命令、Node/Bun 版本、源码 SHA、
bundle/原生资产标识、seed/配置、原始 ANSI、解析后画面、请求、退出状态
和失败断言。缺少运行时、资产或平台执行记为 `NOT_RUN`/`BLOCKED`，
不能隐含算通过。

单测覆盖状态转移和失败边界，原生组件测试覆盖布局/滚动/光标，现有
node-pty/xterm 产品会话测试真实按键及副作用。除了画面，还比较语义状态和
模型/工具请求。只归一化明确声明的不稳定 ID 和时间戳，不抹除空白、颜色、
光标、换行或重复内容问题。
xterm 测试终端使用 Unicode 11 addon，避免默认 Unicode 6 宽度表误读
用显式光标位置绘制的双格 emoji。这是测试依赖，不改变产品渲染器，也不证明
全部字素簇或 IME 行为正确。清理会话时等待 PTY 退出再删除 fixture 目录；
清理失败也必须使验收失败。

产品场景包括长 Hooks/Diff、小终端与 resize、多轮文本/工具流式、打断、
粘贴所有权及恢复。各次发送之间等待测试框架 idle 边界。零重复消息和恰好
一次提交是硬门槛，不采用宽松计数。适用时检查同步标记、协议边界和可见帧；
零个标记的“平衡”不能证明同步输出。

PR 回归在精确 head 上运行所改能力用例及共享 smoke 集。
集成/发布回归运行全部三组及安装/更新产物矩阵。真实终端的 IME、选择、
无障碍和长时间生命周期测试，在自动化无法模拟终端协议时保留明确人工证据。

## OpenTUI 与 OpenCode 上游评估

Main 使用 OpenTUI 0.5.10。上游 OpenTUI 0.6.6 与当前 OpenCode 提供了
有用的修复和实现参考，但 0.6 引入原生所有权及生命周期变化。仅升版本
不能作为已经通过的解决方案。

隔离评估 React API/类型兼容、SyntaxStyle 显式所有权与 renderer 关闭、
原生包/parser/worker 资产匹配、最低 Bun 版本、Unicode/控制字符宽度、
resize/scroll/diff，以及三组产品/产物测试。保持版本与原生 ABI 一致。
除非证据证明上游替代了相同契约，否则保留 Qwen 的 IME、图片、光标和
长记录应用层保护。只有收益明确且门槛通过才升级；独立对齐修复不等待升版。

## 完成与切换门槛

1. 运行时门槛：所有必要消费方及安装产物在支持平台通过，包括 PTY 生命周期、
   更新和回滚。
2. 渲染器门槛：能力清单没有未解释缺口，自动化对比通过，人工终端检查留存，
   strict OpenTUI 运行真实产品且没有回退。
3. 默认切换门槛：前两个门槛在发布候选上成立，恢复/回退已实测。
   屏幕阅读器的等价路径取得证据之前保留可访问的 Ink。
4. 删除门槛：没有剩余 Ink 独占契约或分发回退依赖。删除 Ink 单独审查。

每 30 分钟跟进所管理 PR 的 head、实质评论、CI 失败及冲突。根据日志区分
产品缺陷和 runner/基础设施失败。记录旧 head 后才能 rebase 依赖 draft，
并保护其他工作区。修复后发布新精确 head 的证据。不自动合并、发布，
也不把跳过的检查算作验收。

## 风险与待定决策

当前机器能够验证 macOS arm64，不能代表完整平台矩阵。原生生命周期与 IME
限制需要明确的外部证据。Stack 审查期间独立变化可能合并；每个后继转 ready
之前，都要重新核对当前 Ink 清单和实际合并基线。默认切换以及可能的 OpenTUI
升版，在各自证据门槛通过之前保持为条件性决策。
