# 确定性的审查并行调度

[English](review-parallel-dispatch.md) | [简体中文](review-parallel-dispatch.zh-CN.md)

## 问题与当前行为

PR #11495 的自动审查串行运行了十五个前台 agent，耗尽了六小时预算。
调度器支持并发 agent 调用，但审查流程要求模型在同一个响应中发出全部调用。
模型或接口每次只返回一个调用时，这条指令就退化成串行执行。普通 agent 的
默认后台行为不适用，因为审查 agent 明确要求内联返回结果，并使用调用者管理的
worktree。

仓库已有 `review emit-workflow` 和固定的 `parallel()` 脚本，但技能尚未使用。
生成器排除了按区域分片的审查，而通用 workflow 默认每个 agent 最长十分钟、
每次运行最长三十分钟，低于日志中实际观测到的审查耗时。

## 目标与范围

- 通过固定 workflow 调度独立的审查 agent，覆盖首轮名单和验证、反向审计批次。
- 保留必需角色、精确提示词、worktree 所有权、执行记录、覆盖率检查和现有的
  审计收敛规则。
- 保留准备、调度、汇总、清理之间的顺序依赖。并发有上限，十五个 agent 不必
  同一时刻启动。
- 不改变模型选择、接口请求参数、问题判定策略、通用 workflow 默认值或 daemon
  路由。

## 设计

### 构建器与批次选择

首轮名单使用现有生成器。为后续批次的 `agent-prompt` 增加可选的清单输出模式。
成功构建返回计划身份以及本次实际构建的精确提示词记录键；预算或收敛拒绝不生成
清单。生成器可以合并这些清单，校验计划身份，拒绝重复或缺失的记录，然后读取
精确的已记录提示词。不得通过扫描历史记录猜测当前批次。

为尚未采用清单的调用者保留现有文本输出。生成脚本使用由内容派生的身份，避免
后续批次覆盖已有运行的恢复句柄所指向的脚本。

### 工具可用性

调用可信的内置审查技能时，在技能正文到达模型之前，为当前顶层会话启用 workflow
调度。共享技能加载路径同时覆盖斜杠命令和模型调用。注册过程保留已有工具权限、
bare/provisional 限制以及显式 workflow 禁用开关。其他会话仍需主动启用；工具
被禁用时，不会静默退回串行 agent 调用。

### 运行时限制

根据脚本在生成 workflow 的 review 目录下的规范路径识别审查脚本，不依据模型
编写的元数据。复用已有 workflow 调度器、队列、沙箱、执行记录和失败处理。
审查配置提供有限默认值：每个 agent 最多 500 轮、100 分钟，每个 workflow 最长
六小时，并发十个 agent。遵守操作者显式设置的 workflow 限制：workflow 并发
设置优先于工具并发设置，显式设为一会按操作者要求串行排队。存在有效审查
截止时间时，将启动时允许运行的时间限定为剩余时间减去汇总预留下限。
这不会替代外层 CI 超时，也不保证交互暂停后的绝对截止时间。

通用 workflow 保留现有默认值。通过已有宿主接口将选定限制传给两条调度路径和
沙箱。接入审查配置后，移除生成器对按区域分片审查的专门排除。

### 技能接入与结果

技能先构建完整批次，再请求生成器输出一个脚本，最后发起一次前台 workflow
调用。首轮审查 agent 一起运行；验证分片与独立的下一轮审计按现有规定合并为
一个批次。有依赖的后续轮次仍须等待汇总。

沿用现有交付检查和覆盖率检查。失败或空返回的 agent 必须报告为缺失，不能当作
成功完成且没有问题。重试缺失工作前，先从已有 workflow 日志和执行记录恢复
已完成工作。调用者在前台 workflow 结束前保留 worktree。

## 受影响组件

- CLI 审查提示词构建器、生成器、生成脚本及其测试。
- Workflow runner、orchestrator 的限制传递及其测试。
- 共享技能加载、workflow 注册及其调用方与测试。
- 内置 review 技能；如需匹配实际运行窗口，同时更新审查截止时间的并发估算。

## 风险与验证

清单选择错误可能遗漏角色或重跑旧问题。测试跨计划清单、过期或缺失记录、重复键、
被拒绝的构建和脚本身份不可覆盖性。验证普通 workflow 保持原有限制。沿用现有
执行记录发现机制，不增加另一种证据格式。

使用无凭据的 localhost mock。让两个独立 agent 等待同一测试屏障，要求它们在
任一结束前都已启动；串行循环必须使此测试失败。让生成脚本遇到缺失结果，确认
审查不能静默成功。运行构建、类型检查、相关单测和 E2E 计划，然后反复执行反向
审计，连续两轮没有新的可操作问题后才提交代码。

## 验收标准与待定问题

模型只需发出一次 workflow 调用，运行时就会在配置的并发窗口内调度完整的选定
批次。提示词和覆盖率证据与现有构建器输出保持一致。验证和审计清单只选择目标
批次。失败保持可见，脚本仍可恢复运行。目前没有待定的产品决策；实现中的发现
可以调整内部接入方式，但必须同步维护两个语言版本。
