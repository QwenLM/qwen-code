# 持久化取消请求耗时

[English](web-shell-cancel-duration.md) | [简体中文](web-shell-cancel-duration.zh-CN.md)

## 问题与范围

Web Shell 会显示实时取消事件，但加载持久化历史时会丢失该提示。提示应在刷新后
保留，并显示“你在 X 秒后取消了请求”（英文：“You cancelled this request after
X seconds”）。保留现有右对齐样式，不增加路由、存储系统或设置。

## 设计

复用现有 `system/turn_result` 记录。回合控制器首次因用户显式取消而中止时，
记录可选的 `cancelledAt`，与 `startedAt` 使用同一代理时钟。`endedAt` 仍表示
收尾结束时间。显示秒数为取消时间减去执行开始时间，向上取整且不小于零；
不包含排队等待和取消清理耗时。取消终态返回前等待绑定的 recorder 写入完成，
避免立即刷新抢在写入之前；记录失败沿用现有的持久化降级行为。

通过 prompt 响应及 bridge 终止事件传递权威取消时间。将实时完成事件与持久化
回放统一转换为现有 `prompt.cancelled` 事件。按 `promptId` 匹配，更新临时的
实时提示而不重复新增。回放保留记录标识和时间戳。重叠历史分页将持久化提示合并到
现有位置，同时处理临时提示及重放修复检查点，不重新取消当前正在运行的工具。Web Shell 适配器把耗时传给
现有系统消息组件，按语言格式化文案。“已处理”统计使用同一个取消耗时，
并采用相同的向上取整规则，包括明确显示 0s。SDK 直接更新省略时间戳时，保留原有时间戳。

没有显式取消时间的旧记录保持现有行为；不为会话销毁、新请求替换旧请求、
权限拒绝或转发失败虚构用户归因或耗时。保留现有临时取消提示以兼容旧服务端。
分支会话的历史继承语义不在本次范围内。

被中断的模型流也必须保留已输出的思考和正文。共享流处理器在取消清理时，
将部分输出同时保存到内存历史和现有的 assistant 延迟记录队列；消费者直接关闭
生成器也要执行此步骤。普通传输错误继续沿用重试及丢弃失败尝试的行为。
MAX_TOKENS 升级和续写重试在请求取消时跳过回滚；恢复流程直接重抛取消，不合成正常完成。
外层生成器收尾时合并保留的续写并删除内部恢复提示，覆盖在 yield 处取消和续写尚无内容的情况。
合成工具调用先记录再输出，确保此时关闭生成器仍保留恢复后的调用，而非原始 XML。网络断流续写在退避等待或建流期间，由外层生成器暂存累计正文前缀，
取消时负责保存；新流处理器接管或普通重试丢弃前缀时清除暂存，避免重复记录。
恢复 assistant 内容后，现有“已处理”统计栏也随之恢复，无需修改统计栏显示条件。

## 影响范围

CLI 会话回合记录；core 流式输出收尾及回合结果载荷校验；ACP bridge 终止事件转发及共享历史
回放；SDK 事件归一化及消息归约；Web Shell 消息适配器、组件和翻译。
所有数据仍位于现有所属会话及持久化工作区内。

## 验证与验收

先使用全局 `qwen` 尝试基线验证，再验证本地 bundle。取消执行中的请求，等待
收尾后从持久化历史重载，确认只有一条提示且秒数不变。在思考和正文都已输出后
取消，确认两类内容和“已处理”统计在重载后保留。另测一秒内取消、缓慢
清理、重复取消、连续两轮取消，以及普通完成、错误、直接销毁和请求替换不误显示。
覆盖畸形元数据和旧记录。测试升级、首次及后续恢复、空输出、消费者关闭生成器和合成工具
调用处的取消，验证未取消的 signal 仍正常丢弃失败尝试，且不留下内部恢复用户提示。运行相关包定向测试、构建、类型检查、打包、两轮
自查及独立审查。

还需在网络断流续写的 RETRY yield、退避等待和建流期间取消，覆盖含重叠正文的后续
续写；确认 history 与记录只各保存一份，新流处理器接管后取消也不会重复记录。

## 待决问题

旧历史缺少可靠的显式取消时间，不进行回填。
现有协议也会将 bridge 超时及部分关闭路径映射为用户取消信号。本次保留该
分类方式；增加取消原因协议不在范围内。
