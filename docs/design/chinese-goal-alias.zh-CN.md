# 中文 Goal 命令别名

[English](chinese-goal-alias.md) | [简体中文](chinese-goal-alias.zh-CN.md)

## 问题与范围

Issue #13317 要求将 `/目标` 作为 `/goal` 的另一种拼写。命令注册表已经支持别名，但 Goal 参数解析和队列优先级还只识别英文前缀。别名必须在交互、非交互和 ACP 模式中共享分发、发现、参数、信任检查与 Goal 状态转换。本次不翻译子命令，也不翻译其他命令名。

## 设计

在 Goal 命令现有且始终生效的 `altNames` 中加入 `目标`。解析完整命令行和判断排队消息是否为 Goal 控制时识别两个名称。流式消费方继续使用现有队列判定。浏览器的两个输入入口识别同一别名，并调用既有 Goal 控制路由；浏览器参数解析和清除命令判定共享一个前缀判定。注册表、限制规则、补全、ACP 元数据和 channel 的既有消费方读取已注册别名，无需新增语言表或运行时设置。

两个名称都接受现有英文参数 `pause`、`resume`、`clear`、`set` 和 `edit`。前缀匹配要求后接空白或命令结束，因此 `/目标x` 仍是不同命令。排队的 `/目标 clear` 必须和 `/goal clear` 一样绕过 Goal 对输入的暂缓。既有信任与禁用命令检查适用于两种拼写。

## 验证与验收

实现前验证全局 CLI 基线，再运行命令分发／补全、完整命令解析、命令限制和暂缓队列测试。通过已构建 CLI 的用户界面验证 `/目标`、`/目标 pause`、`/目标 resume` 和 `/目标 clear`，并以无关命令及普通排队消息作为对照。验证浏览器两个输入入口：Goal 活跃时，`/目标 clear` 必须进入 Goal 控制路由，而普通斜杠命令仍暂缓。Build、typecheck、格式与相关 lint 必须通过。这是别名提案，不声称已重新测试历史下游部署。

## 风险与决策

和其他内置别名一样，该别名对所有语言可见。本次明确实现 #13317 要求的一个名称，不决定通用命令名称本地化策略。协议字段和配置格式均不变。在上述范围内没有未决的实现问题。
