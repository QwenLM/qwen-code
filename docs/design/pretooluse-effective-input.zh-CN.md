# PreToolUse 的有效输入

[English](pretooluse-effective-input.md) | [简体中文](pretooluse-effective-input.zh-CN.md)

## 问题

文档中的 `hookSpecificOutput.updatedInput` 被忽略了。在执行阶段应用它会继续使用原请求的权限决定、确认结果和已准备资源。ACP 工具可能在默认权限检查时缓存远程调用；交互工具则把用户答案和批准状态保存在调用对象上。

## 生命周期

先解析最终工具并校验原请求，再运行一次 PreToolUse，然后才进行依赖参数的权限检查和准备。对象形式的替换值整体替换输入，经过媒体策略检查和工具自身的构建校验，并释放被替换的调用对象。保留调用标识和调用上下文。权限规则、计划模式的 shell 快照、受保护写入检查、worktree 限制、子代理跟踪、确认和执行都使用有效请求。执行后的 hook 也收到该请求。

明确的 deny 或 stop 阻止执行。allow 继续现有权限流程。核心调度器把 hook 的 ask 与普通审批合并为一次确认；必须交互的工具仍在有效调用对象上获得用户输入。ACP 保留把 ask 视为拒绝的现有行为。在 hook 或权限检查期间取消会阻止执行并丢弃附加上下文。成功和失败调用保留现有上下文传递行为。

串行 hook 把前一个替换对象传给后一个 hook，不合并已删除字段。并行聚合仍采用配置顺序中最后一个替换对象。未文档化的串行输出字段 `tool_input` 改为使用 `updatedInput`。

存储的请求参数在确认和行内编辑重建期间保持原始形式。hook 收到独立的路径规范化视图；重建前将保留的路径恢复为原始写法，执行阶段继续沿用执行后 hook 的规范化行为。ACP hook 输入只包含调用方参数，不包含操作员通过策略注入的字段，避免原样返回输入时将受保护配置误当成调用方输入再次提交。无头执行在启用 PreToolUse hook 时串行处理依赖参数判断并发安全性的 shell 调用，最终结构化输出使用已完成调用的有效请求。合并后的确认使用现有可见字段保留 hook 的原因。

## 边界

不能改写工具标识。托管调用在 preflight hook 之前已经完成准备并绑定参数摘要；固定策略调用的授权也对应特定请求。这些路径拒绝改变输入的替换值；相同输入仍然有效。通用 hook 传输失败行为保持不变。

## 验证

保留的测试覆盖有效执行和执行后 hook 输入、schema 拒绝、拒绝规则、计划模式写入、准备缓存、审批状态、一次确认、取消和固定输入拒绝。集成测试在 CLI 与 ACP 路径使用命令 hook 子进程和 echo MCP 服务。平台与运行中应用的证据单独报告；仅有单元测试不能证明桌面 UI 的实际结果。
