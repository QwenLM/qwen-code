# External memory import

[English](external-memory-import.md) | [简体中文](external-memory-import.zh-CN.md)

## Status and goal

2026-10-22: the first incremental PR implements in-memory Codex source validation, contextual preview, grouping, references and conservative usage estimates. CLI commands, filesystem collection, models, persistence and HTTP are subsequent work. PR #14281 remains open as the parallel full implementation; neither path automatically closes the other. Each incremental PR must contain at most 1,000 added plus deleted code and test lines; documentation is counted separately and excluded from that limit.

Clients need to migrate selected Codex knowledge into native Qwen memory without exposing a laptop filesystem to a cloud runtime. Plain per-bullet conversion loses context and cannot reconcile historical knowledge with existing memory. Qwen owns the parser and eventual import service; external product UI, standalone collectors, continuous/cross-instance sync and production deployment are outside this design.

## Source and preview contract

The input is `{version:1,source:"codex",files:[{path,content}]}` with relative paths and UTF-8 Markdown content. Allow only `MEMORY.md`, `memory_summary.md` and referenced `rollout_summaries/[A-Za-z0-9_.-]+.md`. Require at least one root memory file; reject absolute paths, traversal, backslashes, control characters, NUL content and case-insensitive duplicate paths. Raw sessions, credentials, configuration and skills are excluded. Paths record provenance and never authorize a destination. A later local reader must reject symlink files/directories; this parser receives contents and performs no filesystem access.

`previewSource` returns `{version:1,kind:"preview",digest,groups,sections,warnings,estimate}`. Each section includes stable `id`, `groupId`, `title`, `path`, one-based `line`, contextual `content`, `references`, `suggestedScope`, optional `sourceProject`, `reason` and `selectable`. Groups contain `id`, `scope`, optional `sourceProject`, `sectionIds` and `estimate`. IDs hash path and contextual content; the source digest hashes the validated, path-sorted envelope. Reordered source files preserve the digest and IDs; reordered sections preserve IDs but may change the envelope digest. No timestamps or generated random identifiers enter preview.

Preserve whole task sections and ancestor headings/prefaces, without including sibling projects. A single absolute project heading or `cwd` hint suggests `project`; explicit User profile/User preferences summary sections suggest `user`; missing, conflicting or unsupported hints stay `unassigned`. Suggestions never authorize destination scope. Discover supporting Markdown references from root resources, warn about missing references, and exclude unreferenced support files. Supporting sections require their own explicit selection later; references do not grant transitive selection. Preview performs no model call, authentication, native-memory read or task/memory write. Server preview will transmit the supplied contents; it is not a browser-local privacy guarantee.

Admit at most 256 files, 512 KiB/file and 8 MiB aggregate source. Bound Markdown parsing to 4,096 headings, 16,384 line breaks and 4,096 inline markers, conservatively including code blocks; reject pathological input before parsing where possible. Bound expanded contextual content to 8 MiB. Sections above 64 KiB remain visible but unselectable, with a split-source warning. Reject invalid input with `MemoryImportRequestError`; never silently truncate. Preserve LF/CRLF/CR-only source content and identify lines correctly.

## Estimates and eventual model execution

The shared budget is eight sections / 64 KiB source per batch, 32 KiB existing context, 32 KiB prompt/schema allowance, 8,192 output tokens/request, 32 logical calls/task and 512,000 reserved token units/task. Deterministically sort source IDs and pack within source-project groups. The eventual execution groups by confirmed scope as well; preview counts twice the unsplit batch count to bound a group's possible user/project split. `estimate` exposes `basis:"source-only-with-context-reserve"`, `modelCalls`, `sourceTokens`, `maxOutputTokens`, `reservedTokens`, `exceedsBudget` and `limits`, both per group and in aggregate, for selectable sections only. Empty selections estimate zero usage.

Use the existing text-token estimator for source tokens; conservatively reserve serialized source bytes, maximum existing-context and prompt allowances, output allowance and envelope overhead. Estimates neither read native memory nor invoke a provider and are not billing quotes. Actual selection/context/deduplication may reduce use. Future execution must reject oversized metadata/relevant evidence before a call, durably reserve request/prompt/schema/output usage before dispatch, and cap output and unattended retries. Failure, cancellation, restart and explicit retry never refund or reset the allowance; missing historical usage grants no new budget.

The eventual model uses the destination workspace's Config/authentication through a tool-free structured side query. Historical source and existing memories are untrusted data. Supply only selected source sections, a bounded same-scope metadata index and complete relevant evidence; do not silently demote oversized relevant bodies. Validate exact response IDs, decisions `new|duplicate|conflict|skip`, native document format and requested scope. Existing memories take precedence; uncertain overlap is a conflict, never permission to overwrite. Only validated new records may be published.

## Durable import and native memory contract

Submit requires explicit `{id,scope:"project"|"user"}` selections and a 1–128 character `[A-Za-z0-9_-]` idempotency key. The server derives paths from the trusted destination workspace; no destination path is accepted. Retain only selected immutable contextual snapshots, at most 16 MiB serialized, in private runtime state outside Git and native scanning. Repeating a key/request returns its task; changing its selection is rejected. A new key cannot duplicate prior source/output identities or restore edited/forgotten results. Do not migrate #14149 experimental state.

Tasks use `version:1,kind:"task"` and expose `id,status,createdAt,updatedAt,items,result,usage,budget`. `usage` contains `modelCalls,reservedTokens`; `budget` contains `maxCalls,maxReservedTokens`; `result` contains `sourceSections,newDocuments,duplicateSections,conflictSections,failedSections`. Task states are `queued|running|completed|partial|cancelled`; item states are `pending|added|duplicate|conflict|skipped|failed`, with reasons and native refs where applicable. Result counts distinguish source sections from newly published documents. Retry processes pending/failed items, not successful/conflicting items. Model failures require explicit retry. Cancellation stops new dispatch/publication; already-started requests may finish without publishing. A short per-task lifecycle gate orders durable cancellation, reservation/dispatch and final cancellation-check/rename, separately from worker leases and scope locks; it never spans model waiting. A worker cancelled while waiting for a scope lock must consume zero model budget after that lock is released.

Journal complete validated batch proposals and baseline hashes before publishing any member. Serialize publication per destination scope and recheck complete native snapshots. Publish through stage → intent → rename → committed ledger. Recovery waits out a dead worker's 120-second lease, reuses saved proposals and validates same-scope committed outputs, including other batches, without accepting external edits. A truly unpublished intent may be reconsidered; an already-renamed document remains protected even without its committed receipt. Never restore edited/forgotten output or publish twice. Lost locks fence dependent writes; unrelated tasks continue.

Project imports use a separate private root keyed by the real Git common directory: main and registered linked worktrees share it, independent clones do not. Ordinary project isolation and `QWEN_CODE_MEMORY_PROJECT_SCOPE` remain unchanged; imported repository scope is explicit. Cache identity with filesystem-dependent invalidation, refresh it for writes, and skip Git discovery when no imported layer exists. Integrate native search/fetch/recall/forget and metadata migration. Native user entries retain catalogue priority and existing limits; imported entries fill remaining capacity and remain searchable outside that bounded index. Source snapshots never become native documents or grant native writers source access. Published documents use native format, without an additional provenance marker.

## Future CLI and HTTP contract

CLI preview is `memory import codex --source <folder> --dry-run --json`, defaulting to `$CODEX_HOME/memories` or `~/.codex/memories`. It remains offline, including bare/safe mode. Confirmed local import adds `--apply --selection <json> --idempotency-key <key>` and optional `--retry`; apply/dry-run are mutually exclusive. Reject unavailable managed memory/bare/safe before confirmed admission. Use the current trusted local workspace's model, await durable results, flush complete JSON and tolerate EPIPE. Partial/conflicting/cancelled outcomes exit nonzero.

Advertise `memory_import_v1` only with the complete route set under `/workspaces/{workspaceId}/memory/import`: POST `/preview`, POST/GET `/batches`, GET `/batches/{id}`, GET `/batches/{id}/sources/{sectionId}`, POST `/batches/{id}/cancel` and POST `/batches/{id}/retry`. Preview accepts the source envelope; submit accepts `{source,selection,idempotencyKey}`; submit/retry return durable 202 receipts. All routes have selected-runtime ownership, existing authentication/trust checks and `no-store`; mutations use strict authorization. Keep the existing 10 MiB JSON-body limit. Unknown/untrusted/removed/draining/SSH runtimes and legacy `QWEN_CODE_MEMORY_BASE_DIR` / `QWEN_CODE_MEMORY_LOCAL` overrides fail closed without primary fallback.

Use the selected runtime's environment, storage, memory scope and bridge, including cold sessionless ACP dispatch. Check managed-memory availability before submit/retry admission and charging usage. Runtime services coordinate one recovery attempt, retry failures on subsequent task requests and recover registered runtimes on activation; preview does not recover tasks. Reads recheck runtime access before returning private content. Preserve successful 202 receipts if a generation closes after durable admission. Classify invalid request as 400 `memory_import_rejected`, missing task as 404 `memory_import_not_found`, unexpected service/storage failure as 500 `memory_import_failed`, and generation/recovery unavailability as 503 `workspace_runtime_unavailable` / `memory_import_recovery_unavailable` with `Retry-After: 1`. Keep source text and storage paths out of HTTP error responses.
