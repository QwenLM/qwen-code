# 减少 Computer Use 不必要的模型往返

[English](cua-skill-round-trips.md) | [简体中文](cua-skill-round-trips.zh-CN.md)

## 问题与范围

现有按平台分流的 skill 将初始化、平台查询、资源读取和清理分别展示为独立调用。
一条成功的 macOS 任务轨迹为这些步骤分别发起了模型响应，还将已知的编辑与保存拆开。
原生工具调用仅占总耗时的一小部分。本修改改进通用 skill 流程与 MCP 工具说明，
不加入特定应用指令，不改变 SDK 运行时、原生 API、任务提示或授权策略。

## 预期行为

在同一次 REPL 调用中初始化连接、查询连接的平台并读取唯一对应的本地 skill 资源。
skill 的实际目录由加载器或刚读取的文件提供。文件系统导入不可用时，保留已有的
`read_file` 后备方式。返回的平台为 macOS，且任务已明确指定唯一应用时，在同一调用中
打印对应资源后附加该应用的初始观察。共享 skill 说明这部分观察 API，并明确 getState
可能启动未运行的应用。平台流程复用返回的 app 与状态。未知应用仍按资源指引发现，
未知平台仍应失败。读取返回的资源和初始状态后，才能执行编辑与输入。

macOS 将目标不变的已知动作合并，包括保存，直到需要新的决策。新弹窗、菜单、目标变化
和不确定结果仍须先观察。AX 文本足够时优先用文本；缺失上下文、坐标定位或视觉属性
需要截图。任务完成时在最终验证的同一次调用中关闭连接。

共享 MCP server instructions 保持简短，将完整执行规则放在 `node_repl` 工具说明中。
这样，给每个工具添加 server instructions 的客户端便不会为五个工具重复同一套规则。
主工具说明逐字保留原有的导入、绑定、取消、状态检查点和外部副作用规则。
工具 schema 与运行时行为保持不变；辅助工具说明仍各自定义其操作。

## 风险与验证

合并动作不能猜测后续弹窗的控件，也不能重复未确认的动作。即使连接到远程桌面，
资源路径也应属于 skill 所在机器。保留平台、观察和文本操作的既有测试；构建、
类型检查打包的 SDK，并验证分发的 skill 资源一致。
验证 MCP 初始化和工具发现将全部执行规则保留在主工具中，再运行既有的 MCP schema
和生命周期测试。
用同一模型、初始输入和任务提示，从全新 VM 副本重跑任务。只有保存结果正确，且轨迹
确实减少了不必要的响应边界，才能接受修改；时间和 token 的退步也须记录。
通过更多应用检查指引能否泛化。实际结果保存在实验报告中；单次运行不能证明稳定的平均加速。
