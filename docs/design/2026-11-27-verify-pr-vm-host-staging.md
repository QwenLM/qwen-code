# Host Capability Probing and Per-Round VMM Staging for `/verify-pr` MicroVMs

[中文版本](2026-11-27-verify-pr-vm-host-staging.zh-CN.md)

**Status: implemented and verified on macOS arm64 and Linux aarch64 KVM; PR review and remote CI remain separate gates. Date: 2026-11-27.**

## 1. Context and Goal

The prior `/verify-pr` microVM milestones landed trust classification (`scripts/verify-pr-prepare.mjs`), host-record checking (`scripts/verify-pr-check.mjs`), ownership reaping and finalization (`scripts/verify-pr-vm-lifecycle.mjs`), bounded artifact collection (`scripts/verify-pr-vm-collector.mjs`), 3-port guest vsock transport (`scripts/verify-pr-vm-channel.mjs`, `scripts/verify-pr-vm-guest-vsock.py`), and launch-plan orchestration (`scripts/verify-pr-vm-runner.mjs`).

Two operational gaps prevented `verify-pr-vm-runner.mjs` from driving a real local microVM without hand-written PoC glue:

1. `select` accepted only manual capability flags (`--kvm`, `--vfkit --seatbelt-enforcing`) with no live host capability or macOS Seatbelt enforcement probe.
2. `runHardwareRound` required callers to manually create Firecracker's `jailRoot`, copy golden kernel/rootfs images to independent per-round files, write and chown `<jailRoot>/config.json`, or author a deny-default macOS Seatbelt `.sb` profile and stage `vfkit` assets, and did not verify an on-disk `<jailRoot>/config.json` against `plan.vmConfig`.

This change closes those Phase 2 host-side gaps in a single focused module (`scripts/verify-pr-vm-host.mjs`) plus minimal, backward-compatible wiring in `scripts/verify-pr-vm-runner.mjs`.

## 2. Scope and Hard Constraints

- **Allowed scope:** `scripts/verify-pr-vm-host.mjs`, `scripts/verify-pr-vm-runner.mjs`, `scripts/tests/verify-pr-vm-host.test.js`, this bilingual design document, and the five `#18400` R5 deferred test/doc follow-ups in `scripts/tests/verify-pr-vm-channel.test.js` and `docs/design/2026-11-25-verify-pr-round-input-hardening.{md,zh-CN.md}`.
- **Out of scope (untouched):** `packages/`, `.github/`, `.qwen/skills/`, `/review`, cloud resource provisioning, real model credentials, and guest workload packaging.
- **Backward compatibility:** existing manual `select` flags, `run --config`, and legacy `container`, manual `vm`, and `waived` `/verify-pr` flows remain supported. For `runHardwareRound({ stageAssets: false })` on default Firecracker launches, an absent `<jailRoot>/config.json` remains accepted for compatibility with fake-jailer harnesses, while any present on-disk `<jailRoot>/config.json` must now deep-equal the validated `plan.vmConfig` (extra sections such as `logger`/`metrics` or injected `network-interfaces` are refused before launch).

## 3. Design Decisions

### 3.1 Fail-Closed Live Host Capability Probing (`probeHostCapabilities`)

- **Linux KVM + Firecracker/jailer:** verifies `/dev/kvm` via `lstatSync` (non-symlink character device) and real `openSync(O_RDWR | O_NOFOLLOW)`, confirms readable cgroup v2 controllers (`/sys/fs/cgroup/cgroup.controllers`), requires positive non-root `vmmUid`/`vmmGid`, and validates `firecracker` and `jailer` (whether passed via explicit flags or discovered on `PATH`) as non-symlink regular executables whose `--version` exits 0 with non-empty output.
- **macOS ARM64 `vfkit` + Seatbelt (D7):** requires `darwin`/`arm64`, verifies `/usr/bin/sandbox-exec`, checks `vfkit` (explicit or `PATH`-discovered) as a non-symlink regular executable whose `--version` succeeds AND whose `/usr/bin/codesign -d --entitlements :-` output contains `com.apple.security.virtualization` (refusing hollow/unsigned binaries), and executes `probeSeatbeltEnforcement`.
- **Live Seatbelt enforcement probe (`probeSeatbeltEnforcement`):** runs a clean-environment `/usr/bin/env -i ... /usr/bin/sandbox-exec` subprocess with canonicalized (`realpathSync`) `POC_DIR` and `POC_SOCKET_DIR` parameters. It passes only when **both** positive controls succeed (read and write inside `POC_DIR`) **and** both negative controls are denied (reading a host canary outside `POC_DIR` and creating a file outside `POC_DIR` fail with no leak). External profiles are opened with `O_NOFOLLOW | O_NONBLOCK` (refusing symlinks, multi-hardlinks, and FIFOs), and invalid `vfkitBin` literals fail closed (`enforcing: false`) instead of throwing uncaught exceptions.

### 3.2 Minimal Deny-Default macOS Seatbelt Profile (`renderVfkitSeatbeltProfile`)

- Starts with `(version 1)`, `(deny default)`, `(import "system.sb")` (Apple's minimal dyld/system-library base, with no `/Users`, `$HOME`, `/tmp`, or IP network allowances), followed by explicit `(deny network-inbound)` and `(deny network-outbound (remote ip))`.
- Explicitly grants:
  - Process self-management: `process-fork`, `signal (target self)`, `process-info* (target self)`.
  - Executable and read access needed by `/bin/sh` live probing and `vfkit`: `process-exec`, `file-read*`, and `file-map-executable` on `/bin`, `/usr/bin`, and the validated absolute `vfkitBin` literal (rejecting quotes, backslashes, newlines, or NUL bytes).
  - Per-round storage and vsock UDS: `file-read*` and `file-write*` strictly under `POC_DIR` and `POC_SOCKET_DIR`, plus `network-bind` / `network-outbound` strictly for Unix sockets under `POC_SOCKET_DIR`.
  - Apple Virtualization services: `mach-lookup` (`com.apple.Virtualization.VirtualMachine`, `com.apple.SecurityServer`, `com.apple.CoreServices.coreservicesd`) and `iokit-open` (`AppleHVClient`, `RootDomainUserClient`).

### 3.3 Per-Round Independent Asset Staging and Disk Config Verification

- **`copyIsolatedAsset`:** opens the source with `O_RDONLY | O_NOFOLLOW`, asserts single-link regular file outside the canonicalized `vaultDir` (resolving symlinked `vaultDir` targets via `realpathSync`), normalizes `approvedRoots` entries (resolving not-yet-created roots via their deepest existing ancestor so symlinked prefixes such as macOS `/tmp/qc-vm` match canonical destinations), canonicalizes destination prefixes preserving the leaf before checks (and re-checks `safeDest` after creating parents), refuses to overwrite any existing destination, copies via streaming into an `O_CREAT | O_EXCL | O_NOFOLLOW` temp file inside `realParent`, computes SHA-256 while streaming, asserts `(dev, ino)` differs from the source and `nlink === 1`, applies mode and optional `fchown`, and atomically renames into `realParent`.
- **`stageLocalVmRound`:**
  - **Firecracker:** creates `plan.jailRoot`, copies `sourceKernelPath` and `sourceRootfsPath`, atomically writes `<jailRoot>/config.json` matching `plan.vmConfig` and `<jailRoot>/console.log`, and applies `vmmUid:vmmGid` ownership when running as root (or when `applyChown: true`).
  - **`vfkit`:** creates private `0o700` `pocDir`/`socketDir`/`homeDir`/`tmpDir` inside `approvedRoots` (refusing any pre-existing target directory that allows group/other access), derives independent copies of `kernel`, `initramfs`, and `rootfs`, and atomically renders `seatbeltProfile` at read-only `0o400` if absent. Any pre-existing profile at the plan's `-f` path must reside inside `approvedRoots` (outside `vaultDir`), pass non-blocking single-link validation, match `renderVfkitSeatbeltProfile({ vfkitBin })` byte-for-byte, and pass live `probeSeatbeltEnforcement` on `darwin`.
  - Records every directory actually created (including parents created by asset/file writers); rollback deletes created files, recursively clears only per-round runtime directories created by this call (newly created Firecracker `jailRoot` and newly created `vfkit` `pocDir`/`socketDir`/`homeDir`/`tmpDir`), and prunes all other created directories deepest-first via non-recursive `rmdirSync` without ever deleting pre-existing caller-owned directories.
- **`verifyFirecrackerDiskConfig` & `verifyVfkitSeatbeltProfile`:** open `<jailRoot>/config.json` and the `vfkit` `-f` Seatbelt profile with `O_RDONLY | O_NOFOLLOW | O_NONBLOCK` (refusing symlinks, FIFOs, and hardlinks) and verify exact parity with `plan.vmConfig` (`util.isDeepStrictEqual`) and `renderVfkitSeatbeltProfile({ vfkitBin })` (byte-for-byte, inside `approvedRoots` and outside `vaultDir`). Both checks run before token/collector setup and again immediately before `spawn()` on default launches (enforced unconditionally when `stageAssets: true` and whenever the on-disk file exists when `stageAssets: false`).

### 3.4 Runner CLI and Orchestrator Integration

- `node scripts/verify-pr-vm-runner.mjs probe [...]` emits JSON capability reports and exits 0 iff at least one hardware backend is genuinely ready.
- `node scripts/verify-pr-vm-runner.mjs select --context <snapshot> --probe [...]` feeds real probe results into `selectBackend`; mixing `--probe` with manual `--kvm`/`--vfkit`/`--seatbelt-enforcing`, passing probe-only flags without `--probe`, omitting option values (including flag-shaped next tokens starting with `--`), or passing invalid uid/gid values exits 2.
- `runHardwareRound` and `run --config` accept optional `stageAssets: true`, `sourceInitramfsPath`, and `applyChown`, cleaning up pre-launch staged assets on early failure and cleaning remaining staged files in `finally` only after `reapOwnership` proves worker absence.

## 4. Acceptance Criteria

1. `renderVfkitSeatbeltProfile` rejects unsafe `vfkitBin` literals and produces a deny-default profile that passes live macOS `sandbox-exec` positive/negative filesystem controls and blocks real outbound TCP to a local canary listener (while an unsandboxed positive control reaches that listener).
2. `probeSeatbeltEnforcement` returns `enforcing: false` for permissive `(allow default)`, symlinked, and hardlinked profiles, and on non-darwin platforms.
3. `probeHostCapabilities` refuses hollow `vfkit` binaries missing `com.apple.security.virtualization` via real `codesign`, refuses non-char/symlink `/dev/kvm`, symlinked or failing `firecracker`/`jailer` binaries, missing cgroup v2, and root `vmmUid`, and reports `kvmAvailable: true` on real Linux KVM with Firecracker/jailer.
4. `copyIsolatedAsset` and `stageLocalVmRound` enforce `approvedRoots`, `vaultDir` exclusion, single-link sources, independent destination inodes, no overwrites, broken-symlink rejection, and complete rollback on failure.
5. `verifyFirecrackerDiskConfig` accepts key-reordered matching configs and blocks tampered on-disk `config.json` (e.g. injected NIC) before spawning Firecracker.
6. `runHardwareRound({ stageAssets: true })` completes a zero-manual-staging real Linux Firecracker/KVM round with `outputStatus=complete`, `teardownStatus=destroyed`, `boundary.json (mode:"microvm")`, zero residual `jailRoot`/working disk, and unchanged golden kernel/rootfs SHA-256 digests.
