# 合并扩展状态的并发读取

[English](extension-status-coalescing.md) | [简体中文](extension-status-coalescing.zh-CN.md)

## 问题

legacy-primary `GET /workspace/extensions` 的 controller 将已完成响应缓存两秒，
但并发缓存未命中时，各请求都会创建 manager 并完整加载扩展。Store 锁让这些重复
扫描串行执行。

## 设计

每个 controller 保存一个进行中的状态加载，以解析后的 locale 和工作区信任状态
作为身份。相同身份的请求共享 Promise。保留完整响应以及从成功完成开始计算的两秒 TTL。

三个现有失效点同时清除响应缓存和进行中引用：手动刷新、写操作完成、写操作已提交但
后续工作失败。只有当前进行中条目能发布缓存或清除引用，通过对象身份判断失效，
不增加版本计数。旧调用方可以得到原有快照，但新请求不会加入已失效的加载。
当前等待者共享失败，后续请求重新尝试。

先解析信任状态，再解析 locale，确保缓存身份和 manager 使用的设置一致。
不同 controller、语言和信任状态不共享加载。保留各 HTTP 请求在 await 前后的生命周期校验。

## 范围

只修改状态 controller 及其测试。不引入长期 manager、新 API、后台旧值刷新、延长 TTL、
全局缓存、加载器优化或更强的读写排序。文档及隔离基准记录行为和实测收益。

## 验证

单元测试覆盖冷缓存及过期后合并、命中、失败重试、locale/信任及 controller 隔离，
以及各失效路径的旧加载完成竞态。运行构建、类型检查、controller 和工作区扩展路由测试。
基线与候选使用真实文件 fixture 及同一加载器；测量 1/2/5/10 并发、缓存命中和过期。
校验每份响应并统计完整刷新次数。耗时不含准备及启动，注明文件系统缓存已热。
不预期单请求有明显加速。

## 验收

相同缓存身份的一批并发请求只执行一次完整刷新。旧请求完成不能覆盖新缓存或清除
新进行中读取。结果必须记录基线 SHA、fixture 规模、样本数、耗时及限制。
