目标接口与适配实现统一按以下规则解释，不为每个方法新增类或 RPC：

- **读服务**＝`SessionRepository` / `LocalSessionRepository`，复用原 Core SessionService 与 reader。**生命周期命令**＝authority 内部的原维护编排，再调用 Repository 的本地方法；路径/lease/文件身份/回调标记为“留内部”。兼容接口保留旧 DTO；新远端 DTO 如需去掉 filePath，只在传输边界转换，不能删掉现有本地调用者依赖的字段。
- **sink**＝`SessionRecordSink`，以原 ChatRecordingService 保留编码、返回与失败契约；**Journal 增强**＝待实现 `DurableSessionJournal`。旧 void 返回、内存 cursor、best-effort 写入都不是强提交证明。Managed 的增强写入必须与旧 sink 共用该 Session 的唯一 writer，并成对迁移实际生产者。
- **S**＝Session 事实/投影；**H**＝实际 owner 的完整 Harness/coordinator 控制。Bridge 的 S/H 方法先由 `SessionExecutor` 适配，持久读取委托 Repository，强提交委托 Journal；`RecoverableSessionExecutor` 的 activation/checkpoint/detach 另行增强，不能用旧 close/dispose 替代。
- **C**＝原 workspace、目录、client 或 process 控制域；**R**＝原 Runtime/工具域。它们保留现有适配实现和作用域，只将必要引用/事实写入 Session，不迁入通用 Session 存储。Standalone 与 ManagedPromptService 保持入口/调度编排，通过上述接口串联。

返回签名中 Promise 不证明持久提交，也不能据此把非 async 实现改成 async。同步 throw、异步 rejection、boolean、undefined/null、部分成功分别保留。可选方法继续可选，外部注入的旧 Bridge 不能被补成假能力。验收栏均为后续实施要求，可结合主方案 T01～T12 执行；只读查询的宽松结果不能借作严格准入证明。
