# 自动记忆提取失败后的写入恢复

[English](auto-memory-failed-extraction.md) | [简体中文](auto-memory-failed-extraction.zh-CN.md)

状态：#13158 R1-3 的正确性修复已实现；失败成本和积压历史验收仍未完成。

## 问题与范围

fork 可能先写入有效记忆文件，再失败或被取消。结果保留了成功的 `filesWritten`，但提取 planner 在映射记忆主题和作用域之前就抛错。文件仍在磁盘上，索引却没有重建，manager 也没有记录用户记忆变更。成功 fork 后发生索引或游标写入错误，同样会丢失已知的写入作用域。

恢复已报告的写入，同时不推进失败提取的游标。默认路径和实验窗口路径使用相同的持久性规则。保留现有窗口选择、预算、冷却、队列和 drain 行为。

## 决策

用携带现有映射执行结果的类型化 Error，复用当前记忆根目录分类和成功写入统计；读取及被拒绝的写入不算变更。extract 在拒绝失败 fork 之前，重建受影响的索引并刷新当前记忆指令。此次失败不记录成功提取元数据，也不写入游标。

复用项目索引错误向上传播、用户索引尽力执行的现有策略。在 fork 之后的失败中保留执行结果。如果恢复本身失败，用 `AggregateError` 同时保留 fork 失败和恢复失败。manager 记录实际用户记忆变更和主题，同时保持任务及遥测状态为失败。用户变更记录沿用现有尽力执行策略。

## 约束与风险

只有报告成功的写入才能归属于 fork。没有返回结果就抛错的 fork 不携带写入证据。索引沿用现有文档验证；部分文件格式无效时，不会因为 fork 报告写入而变得有效。用户索引重建失败仍采用尽力执行策略，不能证明用户记忆可检索。当前记忆指令刷新也沿用尽力执行策略：现有 helper 捕获底层刷新错误并记录警告，这些错误不会进入类型化失败上下文。索引恢复不能证明实时提示刷新成功。原失败游标保留，因此同一历史仍可能重试。

这项修复不限制重复失败次数、不越过失败窗口、不调度剩余历史、不跨会话回放已丢弃历史，也不证明模型质量或 token 节省。这些要求仍未完成。假设失败没有写入文件而跳过窗口是不安全的。

## 验证与验收

验证失败 fork 的项目及用户写入映射、排除纯读取、重建受影响索引和刷新指令、保持游标及成功提取元数据不变、恢复失败时保留两个失败原因与作用域，以及 manager 在失败状态下记录用户变更。保留成功路径、默认及实验路径、用户索引隔离、游标保留和队列及 drain 回归测试。

执行 build、bundle、typecheck 和相关测试。受控编译运行时用例必须在自有隔离的项目及用户根目录实际写入有效文件后失败，证明索引重建和用户变更记录发生，同时游标未推进。这只证明写入恢复；提供方执行、代表性记忆质量、重试成本上界及后续历史可达性需要分别验收。
