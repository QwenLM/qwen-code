# 自动记忆提取失败后的写入恢复与窗口暂停

[English](auto-memory-failed-extraction.md) | [简体中文](auto-memory-failed-extraction.zh-CN.md)

状态：#13158 R1-3 的写入恢复和默认关闭的失败窗口尝试次数限制已实现；完整成本和积压历史验收仍未完成。

## 问题与范围

fork 可能先写入有效记忆文件，再失败或被取消。结果保留了成功的 `filesWritten`，但提取 planner 在映射记忆主题和作用域之前就抛错。文件仍在磁盘上，索引却没有重建，manager 也没有记录用户记忆变更。成功 fork 后发生索引或游标写入错误，同样会丢失已知的写入作用域。

恢复已报告的写入，同时不推进失败提取的游标。默认路径和实验窗口路径使用相同的持久性规则。保留现有窗口选择、每次 fork 的预算、冷却、队列和 drain 行为。开启现有冷却实验时，同一选中窗口连续失败三次后暂停，包括后续排队请求。

已建立的游标在失败后仍选择最早的待处理窗口，因此历史增长可能反复为同一失败选择付费。没有有效历史身份的初始游标则可能选择更新的真实用户轮；整个会话的失败上限会阻断这种已有恢复路径。

## 决策

用携带现有映射执行结果的类型化 Error，复用当前记忆根目录分类和成功写入统计；读取及被拒绝的写入不算变更。extract 在拒绝失败 fork 之前，重建受影响的索引并刷新当前记忆指令。此次失败不记录成功提取元数据，也不写入游标。

复用项目索引错误向上传播、用户索引尽力执行的现有策略。在 fork 之后的失败中保留执行结果。如果恢复本身失败，用 `AggregateError` 同时保留 fork 失败和恢复失败。manager 记录实际用户记忆变更和主题，同时保持任务及遥测状态为失败。用户变更记录沿用现有尽力执行策略。

复用选择器在 await 前计算的起点和终点历史哈希作为窗口身份。manager 通过共同提取入口提供一个窗口可运行回调，并捕获该身份用于失败记数。按项目及会话保存的进程内计数器允许同一选择连续失败三次。第四次请求返回 `failure_limit` 和持久化游标，不调用 planner、不写游标，也不标记提取成功。跳过保留失败次数，实际选择改变后仍可运行，未跳过的成功操作或关闭实验后的操作清除该元组。其他项目或会话的结果不能清除它。现有 Error 和写入结果契约不变，包括没有写入证据的抛错。

## 约束与风险

只有报告成功的写入才能归属于 fork。没有返回结果就抛错的 fork 不携带写入证据。索引沿用现有文档验证；部分文件格式无效时，不会因为 fork 报告写入而变得有效。用户索引重建失败仍采用尽力执行策略，不能证明用户记忆可检索。当前记忆指令刷新也沿用尽力执行策略：现有 helper 捕获底层刷新错误并记录警告，这些错误不会进入类型化失败上下文。索引恢复不能证明实时提示刷新成功。原失败游标保留，因此同一历史仍可能重试。

尝试次数限制仅适用于开启实验期间、一个 manager 内保持不变的选择。重启或关闭实验允许重试；选择改变后开始自己的连续失败计数。它不限制整个会话的调用次数、token 或提供方账单。现有可配置的每次 fork 预算仍然生效。暂停最早窗口仍可能让后续事实等待处理：次数限制和写入恢复都不越过该窗口、不调度剩余历史、不跨会话回放已丢弃历史，也不证明模型质量或 token 节省。这些要求仍未完成。假设失败没有写入文件而跳过窗口是不安全的。

## 验证与验收

验证失败 fork 的项目及用户写入映射、排除纯读取、重建受影响索引和刷新指令、保持游标及成功提取元数据不变、恢复失败时保留两个失败原因与作用域，以及 manager 在失败状态下记录用户变更。保留成功路径、默认及实验路径、用户索引隔离、游标保留和队列及 drain 回归测试。

验证同一窗口三次失败后第四次跳过，包括第三次失败前真实进入队列的请求。检查游标字节不变、明确的跳过任务和遥测、新用户窗口的初始游标恢复、成功后重置、项目及会话隔离，以及关闭实验时继续重试。匹配的受控编译用例先实际读取自有索引以建立原生游标，再复现修复前四次失败 fork、修复后三次失败 fork。保留窗口后的原始用户事实，不宣称该事实已被提取。此处观测尝试次数，不测真实模型成本。

执行 build、bundle、typecheck 和相关测试。已经完成的受控写入恢复用例在自有隔离的项目及用户根目录实际写入有效文件后失败，证明索引重建和用户变更记录发生，同时游标未推进。不要为了换源码标签而重跑它。提供方执行、代表性记忆质量、总重试成本及后续历史可达性需要分别验收。
