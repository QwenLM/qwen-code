# 第一轮 system prompt 精简

[English](2026-09-20-system-prompt-first-pass.md) | [简体中文](2026-09-20-system-prompt-first-pass.zh-CN.md)

## 问题与范围

默认主会话 prompt 重复描述项目规范、沟通要求和交互模式规则。五种示例变体均包含算术、素数判断、未执行的删除操作，以及重复的文件查找对话。重构示例还主动询问是否提交，与 headless 禁止提问的规则冲突。

本轮仅修改内置 prompt 文本及其测试。保留公共 API、模型分支选择、已声明工具过滤、普通模式和 CodeModeOnly 的调用约定、权限、sandbox 和 Git 保护、输出风格选择、自定义覆盖，以及外层上下文组装。不改变不同 provider 的指令角色，也不新增配置项。

## 修改内容

- 合并重叠的项目规范与沟通表述，保留检查相关代码、遵循现有依赖和规范、按任务调整回答深度的要求。
- 只在最终提醒中完整描述一次交互模式的提问策略；保留任务完成要求，删除其他段落已覆盖的通用安全和文件读取重复表述。
- 每种变体保留三个示例：受管理的后台服务、范围明确的重构、确认目标不存在后创建测试文件。保留模型对应的工具调用格式和先读后写示例。
- 缩短示例旁白，删除主动询问是否提交，以及算术、素数判断、删除操作和重复文件查找示例。保留的示例须在编辑前读取源码，并只在检查成功后报告验证通过。
- 精简工具规则中的重复表述，保留工具选择策略、独立调用并行、依赖调用串行、绝对路径，以及 CodeModeOnly 的输出和中止语义。

## 理由与调用方

入口仍为 `getCoreSystemPrompt`。生产调用方包括主会话客户端和 Arena worker，该函数也向包使用者导出。主会话自定义 prompt 继续绕过默认构建器。`Using Your Tools` 的行前缀和示例包装保持与已声明工具过滤兼容。输出风格仍只能选择省略软件工程工作流段。

本轮保留有代表性的工具格式，不在缺少模型效果证据时删除所有示例。验证策略和安全规则措辞也保持不变；调整何时需要测试或审批不属于本轮保守精简。

## 验证与验收

- 修改前通过全局 CLI 复现 headless 冲突，修改后验证本地 bundle。捕获请求可以证明 prompt 内容，不能证明真实模型的任务质量。
- 覆盖 general、qwen-coder、qwen-vl、gemma4 和 CodeModeOnly，以及 interactive、headless、ACP 三种模式。保留的示例不得主动追问，interactive/ACP 的澄清规则和 headless 无法接收回复的规则须保留。
- 使用实际文件工具 schema 校验示例参数，并保留先读后创建的顺序、部分工具过滤、声明全部工具时结果一致、无可用示例时移除标题的覆盖。
- 运行针对 prompt 和输出风格的测试、构建、打包、类型检查，以及改动文件的格式和 lint 检查。审阅更新后的 snapshot 和完整 diff。
- 在相同输入下比较修改前后的渲染文本，以 `o200k_base` 作为统一体积标尺。这不等于 provider 原生计费，也不证明任务成功率提高。

## 风险与后续

删减示例对不同模型的影响可能不同。在宣称质量提升前，仍需真实模型成对评估任务完成、工具错误、无必要提问、验证准确性、token 和耗时。过滤段落之外仍可能引用不可用工具或技能，这是单独的后续工作；本轮不宣称实现完整的能力感知组装。
