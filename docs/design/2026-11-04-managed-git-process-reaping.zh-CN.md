# Managed Git 进程树回收

[English](2026-11-04-managed-git-process-reaping.md) | [简体中文](2026-11-04-managed-git-process-reaping.zh-CN.md)

## 问题与范围

Git 执行器先停止父进程，再停止后代。Linux CI 记录了父进程消失、原有子进程变为 PID 1 下僵尸的现象。该子进程仍被视为存活，因此停止证明失败，Workspace 维护占用会按预期保留。中断检出的测试也采用相同的父进程优先终止顺序。此外，原生 CSI 测试生成器在强制关闭活动连接之前等待 HTTP 收集器的关闭回调，可能导致回调无法执行。

本次修复只调整进程回收及这些测试夹具，不修改 SQL、Workspace 所有权协议、公共 API 或原生夹具字节。停止未确认时仍须阻止资源释放。

## 回收设计

保留一次两秒的回收期限。前 1.5 秒持续观察后代，强制停止当前叶子进程，让其父进程仍有机会回收它们。所有已观察到的句柄都纳入最终停止证明，包括随后脱离原进程树的句柄。除了原根进程，还扫描已观察且仍存活的父进程，以发现新后代。

最后 500 毫秒用于向所有已知后代和根进程发出停止信号，并确认退出。即使某次发信号失败，也尝试其余最终信号。观察或发信号失败，或者期限到达时任何原已观察句柄仍存活，都继续返回 `STOP_UNVERIFIED`。这是有界、尽力而为的进程树发现，并非操作系统级别的“未观察进程不能逃逸”保证。

回收时临时清除并记录中断，结束后恢复中断标志，即使回收失败也如此。记录是否已经尝试回收，避免失败后由执行器的 `finally` 再启动一次回收期限。回收成功后，保持原有超时、失去 claim、输出超限或命令中断的错误语义。

## 测试夹具调整

中断检出夹具先通过 `worktree add --no-checkout` 注册，再直接持有并中断 `reset --hard` 进程。这样可以保留部分写入的文件，避免失败的父级 `worktree add` 删除它们。若存在后代，则先停止后代再停止父进程。保留部分文件数量、拒绝重入接管和文件保留断言。

CSI 收集器先启动 `server.close`，立即调用 `closeAllConnections`，再等待关闭 promise。在强制关闭现有连接之前先拒绝新连接。保留生成器既有的 30 秒退出期限和夹具、投影校验。独立的真实 HTTP 关闭探针可以验证顺序，但不能代表完整原生 CSI 验收，也不能解释所有历史生成器超时。

## 验证与验收

通过真实进程覆盖超时、失去 claim、输出超限，以及嵌套父、子、叶子进程的中断。断言原 PID 消失且中断标志恢复。覆盖部分检出重试和受影响的 Workspace 服务，保留停止未确认时继续维护隔离的行为。使用 JDK 21 和与源码匹配的兄弟 SDK 检查 Java 风格，遵守模块共享的十分钟本地验证预算。

使用活动 HTTP 请求对比旧、新收集器关闭行为。完整 Linux/容器进程回收、Hosted/fault、原生 CSI 和 SpotBugs 门禁由 CI 承担；仅 macOS 结果不足以证明不回收子进程的 PID 1 场景。提交版本的必要门禁通过前，验收仍待完成。不需要迁移。
