# OpenTUI 手动创建 Agent 与详情

[English](2026-11-13-opentui-manual-agent-creation.md) | [简体中文](2026-11-13-opentui-manual-agent-creation.zh-CN.md)

## 问题与当前状态

基础候选 `e6d36a90` 的 `/agents create` 只打开带 Escape 操作的 OpenTUI 占位面板，挂载处没有传入实际配置。Ink 则挂载已有创建向导，通过公开 subagent manager 保存。OpenTUI `/agents manage` 只列出名称和描述，没有选择或详情。新的全局0.23 Ink 基线已完成位置和手动方式导航、取消无存储改动、HTTP0 与自然退出。单独的当前 U 严格 OpenTUI 基线在实际占位位置画面失败，存储不变且 HTTP0；其失败清理不是自然退出成功。手动实现已通过受影响单测与三种公开运行组合验证。后续引导增量及合并验证见[引导创建设计](2026-11-13-opentui-guided-agent-creation.zh-CN.md)。

## 预期行为

恢复手动路径：项目或用户位置、Manual Creation、名称、系统提示词、描述、工具类别、颜色和确认。复用已有向导 reducer、验证、工具注册表分类、颜色选项、原生行编辑器和对话框选择组件。手动路径不发送模型请求。本手动阶段不包含引导生成；后续引导增量在保留手动路径的基础上加入该能力。

把实际对话框配置传给原生组件。仅通过 `getSubagentManager().createSubagent` 保存，传入所选 level、`overwrite: true` 和已有 `assertCanCommit` 回调。manager 负责验证、目标路径、序列化、写入和缓存刷新，无需直接写文件或修改 Core。仅允许一个保存请求，保留错误，拒绝重复提交。关闭、卸载或配置变化时，在 manager 已有提交检查前撤销待完成的 owner；这不能撤回已经开始的写入。

用 generation 计数器保证 owner 撤销不可复活：配置清理、关闭和卸载都会使已捕获的保存 generation 失效。即使返回同一个配置对象，也不能重新激活旧提交回调。提交授权以及成功、错误、finally 后续处理使用同一检查。被撤销的待保存状态一直保持锁定，直到关闭对话框，不自动转移或重启。最初仅比较引用身份的实现漏掉了 A → B → A 情况；Root 已在应用此修正前真实复现 guard 断言失败。原失败保留。修正后的保存守卫已在合并候选通过单测与公开流程验证。

保存前必须完成名称冲突检查，显示已有的同层覆盖或跨层优先级警告。检查失败时禁止保存，直到用户返回上一步。Escape 返回时保留草稿，在首步取消时不创建 Agent 目录。字段沿用已有编辑、粘贴和 Ctrl+C 清空语义；同一输入批次中的旧事件不能推进后续字段。持久化 `blue` 等规范颜色 id，而不是翻译后的显示名称。

已有 Ink 颜色选择器也必须在选择和高亮时输出相同的规范 id。它原先输出显示名称（`Blue`），违背已有 manager/parser 的小写合同；聚焦回归已在此修正前真实复现该输出。预览兼容 id 或旧的内存显示名称 prop，不意味着 Core 会接受无效的 `color: Blue` 文件。已有 Ink 创建与颜色编辑消费者接收修正后的 id，不新增任何原生编辑操作。先前失败的 Node/Ink 完整用例没有保留实际 Markdown，因此其精确差异仍未知，不能改称已留存的 Blue 文件失败。另一个原生完整用例在此仅针对 Ink 的修正前，已通过规范蓝色持久化和热冷详情；合并候选现已通过六个引导及手动公开运行组合用例，均验证规范蓝色的精确持久化。

manager 只新增列表 → 操作 → 只读详情导航。通过实际 manager 读取当前 Agent，显示明确错误，并展示所选 Agent 的名称、描述、系统提示词和颜色。Escape 按页面所有权逐层返回。显示文本经过终端清理，详情正文在已有有界对话框布局中滚动。列表或查看不能改变项目与用户 Agent 存储。

## 复用与涉及文件

将 `8a98af44`/`66ca2f5d` 中已有本地手动向导与只读 manager 作为经过检查的实现材料，而非自动重放补丁。仅带入后续规范颜色修正。共享行编辑器、对话框组件、reducer、类型和 generator API 与当前基础已一致。保留当前 Core hook trust 语义；旧工作树的 trust 实现较旧，绝不能复制回来。

生产代码涉及两个原生对话框组件、`dialogs-misc.tsx` 中的重新导出、创建挂载处、已有 Ink 颜色选择器，以及支持规范 id 的已有颜色显示 helper。添加同目录组件测试，并把聚焦公开手动创建用例加入交互测试。两种语言的设计同步维护。

## 验证与验收

先在隔离环境中用全局 `qwen` + Ink 经过位置和手动方式页面，取消返回输入区，确认项目与用户 Agent 均无写入，并自然退出。再以相同公开输入运行冻结的严格 Bun/OpenTUI 候选，记录占位缺口。两者都由 Root 持单 heavy 租约执行，使用 owned HOME、工作区和临时目录，不产生外部模型流量。

实现后运行受影响 CLI 整文件测试、正常 build、typecheck、lint、格式检查和 bundle。完整复用 `manually-creates-project-subagent-without-model` 公开用例且不修改断言：取消不改变任何存储；明确保存前不存在文件；项目范围只创建一个规范蓝色的精确 Markdown 文件；用户 Agent 不变；热、冷详情一致；两次会话都以零信号自然退出；模型 HTTP 为零。用同一候选 bundle 对照 Node/Ink、Bun/Ink 和严格 Bun/OpenTUI。单测还应覆盖用户级 payload、空字段、返回导航、重复 Enter、待保存时取消或配置替换、冲突检查和保存错误。单测 mock 不证明原生行为或磁盘持久化。

## 范围、风险与后续工作

引导生成由后续链接的设计覆盖。外部保存并编辑、manager 编辑和删除、Agent 执行、工具权限执行、其他平台、安装分发包和最终 merged-main 迁移验收均独立推进。已有计时、退出合同与运行时版本不变。聚焦项目用例不证明用户级磁盘创建或真实覆盖，这些缺口必须明确保留。原生布局可能不同于单测 mock，须复用已有布局规则并检查实际终端画面。当前没有阻止这一有限实现的未决产品问题；基线观察可能要求在实现前仅纠正测试准备。
