# 权限规则中的 Shell 重定向解析

[English](shell-redirect-permission-parsing.md) | [简体中文](shell-redirect-permission-parsing.zh-CN.md)

## 状态

已实现。这是 #10196 三项改动中的第一项；另外两项分别负责解析检查时就能确定的变量，以及处理只有运行时才能知道的路径。

## 问题

`Read`、`Edit`、`Write` 和 `WebFetch` 规则通过从命令文本中提取出的文件操作作用于 shell 命令，因此 `Bash(...)` 的允许规则不能压过文件的拒绝规则。原来的提取器在分词时丢掉了引号信息，重定向解析也只认识固定几种运算符写法，导致：

- 写成 `3>file`、`>|file`、`<>file`、`>&file`、`exec 3>file`，或者运算符紧贴前一个词（`printf X>file`）的写入没有被识别，于是 `Bash(...)` 的允许规则能绕过 `Edit(...)` 或 `Write(...)` 的拒绝规则执行它们。
- 被引号包住或被转义的 `>` 也被当成重定向。`grep ">" .env` 被识别成写入 `.env`，而不是读取，所以 `Read(.env)` 的拒绝规则不生效，而单独的 `Write` 拒绝规则却拦下了这条命令。
- 文件描述符操作被当成文件：`2>&1` 变成写入一个叫 `&1` 的文件，`> /dev/null` 变成写入 `/dev/null`。
- 复合命令的切分把 `>|` 当成管道，把 `printf X >| p.txt` 切成了 `printf X >` 和 `p.txt`。
- 前缀命令（`sudo`、`env`、`timeout` 等）用空格把后面的词重新拼起来，于是 `sudo cat "my notes.txt"` 被当成读取两个文件，`sudo bash -c '…'` 也没有被展开分析。它们的选项按整个词匹配，所以组合在一起的选项（`sudo -Eu root cat .env`）或 `env` 选项的值（`env -u FOO cat .env`、`env -C dir …`）会被当成命令。

## 目标

- bash 的每一种重定向写法都产生它实际执行的读或写。
- 只有未加引号的 `<` 和 `>` 才是重定向。
- 文件描述符的复制和关闭，以及 `/dev/null` 这类设备目标，不算文件操作。
- 原来的提取器报告过的文件访问一个都不丢，上面列出的误报除外。

## 非目标

- 改变哪些重定向目标算作文件。目标仍然沿用命令参数的路径判断规则，所以 `> "$OUT"` 在这里仍然不做分析。
- 解析变量（`$PWD`、命令里前面赋过的值）、花括号展开和 `$'…'` 字符串。
- 把 `$(…)` 当成一个词并分析其内容。单独做这件事，会让 `cat $(echo .env)` 失去原来按空格拆分时碰巧得到的拦截，所以它和“只有运行时才知道的路径”的处理一起提交。
- 对 `[[ … ]]` 测试、`(( … ))` 和 `$(( … ))` 算术、`${…}` 展开以及 `#` 注释建模。它们里面的 `<` 和 `>` 仍然按重定向读取。要在这些地方分清比较和重定向，就得看到它们可能包含的命令替换和进程替换，否则其中真实的重定向会和比较一起被丢掉：`[[ -n $(printf X > p.txt) ]]` 会写入 `p.txt`。这需要一个解析器，所以属于把提取迁移到 `shellAstParser.ts` 已经构建的 tree-sitter AST 上的那项工作。

## 设计

### 分词

一个词里的每个字符都记录它的书写方式：未加引号、在双引号里，或者是字面量（单引号或反斜杠转义）。去掉引号后的文本和以前一样，所以每个命令处理器看到的词都不变。词只在未加引号的空格和制表符处切开：`#`、`${…}`、`$((…))` 和 `[[` 没有特殊处理（见“非目标”）。

### 重定向

一个词在它未加引号的 `<` 和 `>` 处切开。第一个运算符前面紧挨着的一串数字或 `&` 是它的文件描述符。每一段都用同一个模式匹配，覆盖 `>`、`>>`、`>|`、`>&`、`<`、`<&`、`<>`、`<<`、`<<-` 和 `<<<`。目标没有紧贴运算符时，目标是下一个词，而这个词也按同样的规则切开：第一个运算符前面的部分是目标，后面的是更多的重定向，所以 `printf X > a>p.txt` 先写 `a`，再写 `p.txt`。切开后，前面那个词末尾粘着的 shell 语法会像其他词一样去掉，所以 `cat .env&>f` 和 `(cat .env)>f` 读的是 `.env`。

- `<` 和 `<&` 是读，`<>` 既读又写，其余都是写。
- `>&N`、`>&-` 和 `N<&M-` 复制或关闭文件描述符，不涉及文件。
- Heredoc 和 here-string 传递的是数据，不是文件名。
- `/dev/null`、`/dev/stdin`、`/dev/stdout`、`/dev/stderr`、`/dev/tty`、`/dev/fd/N` 以及 `/dev/tcp`、`/dev/udp` 套接字都不是文件。

进程替换（`<(cmd)`、`>(cmd)`）和 main 一样，被读作一个目标是词中剩余部分的重定向；它的内容不做分析。

### 前缀命令

前缀命令后面的词在第二次解析前会重新加上引号，内部命令像任何复合命令一样逐段分析。含有命令替换的词原样传过去，所以替换里的重定向仍然算数。被包装的 `bash -c SCRIPT`（或 `sh`、`zsh`）直接从这些词里展开：SCRIPT 就是 bash 收到的那个词，而重新加引号会丢掉它里面的引号，因为展开时只剥掉最外面一层。选项按 getopt 的规则读取：短选项可以组合，值可以紧贴选项或者是下一个词，长选项用 `--name=value`，`--` 或单独一个 `-` 结束选项。sudo 的 `-h` 只有紧贴时才带值（`-hhost`）。`env -C DIR` 在 DIR 里运行命令。`env -S STRING` 会把 STRING 拆成更多交给 env 的词，所以按 env 实际运行的方式分析；否则重新加引号后，`env -S 'cat .env'` 会保持为一个词，不对应任何命令。

### 复合命令切分

`>|` 是重定向，切分时不再在它的 `|` 处断开。这里的 `>` 必须是 shell 语法：在被引号包住或被转义的 `>` 后面，比如 `echo \>| cat .env`，`|` 仍然是管道。

## 风险

- 报告出的读写变多，设置了文件规则的用户可能会在以前没有弹窗或拒绝的地方看到它们。除了下一条列出的区域，每一处都是命令真实执行的访问。
- 测试、算术、展开和注释没有建模，所以那里带空格的比较仍然和 main 一样被读作重定向（`[[ a > b ]]` 写入 `b`）。紧贴在两个词之间的比较（`$((a>b))`、`(( n>max ))`）现在也会被读作重定向，就像其他地方紧贴的运算符一样，而 main 把整个词当成文本。两者都可能多出一次询问，或者在无界面模式下（写入除非允许否则一律拒绝）被拒绝；但都不会藏掉任何访问。
- 分词器仍然没有覆盖 bash 的所有结构（替换的内容、here-doc 的正文），这些保持原来的行为。

## 验证

- 单元测试覆盖每种重定向写法、非文件目标、引号、前缀命令和 `>|` 的切分，以及测试、算术、展开和注释里的重定向，包括它们所含的替换。
- 权限层测试：通过这些写法，`Bash(*)` 允许规则不能压过 `Edit(p.txt)` 或 `Read(.env)` 拒绝规则；在单独的 `Write` 拒绝规则下，文件描述符操作不算写入。
- 用 1,260 组命令和规则的组合与原来的提取器对比。除了“问题”一节列出的误报，没有任何结论变得更宽松。
- `.qwen/e2e-tests/2026-10-13-shell-redirect-permissions.md` 中的流程，用无界面模式分别在已发布的 `qwen` 0.24.6 和本改动上运行。八个用例全部按预期翻转：以前能读取 `.env` 或写入 `protected.txt` 的六种重定向现在都被拒绝；以前被单独的 `Write` 拒绝规则拦下的两条文件描述符命令现在可以执行。
