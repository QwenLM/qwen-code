# Review 过滤器来源

[English](review-filter-provenance.md) | [简体中文](review-filter-provenance.zh-CN.md)

## 问题

Review checkout 与用户仓库共享 Git 配置。全局 include 可以指向仓库提供的过滤器命令，Git 继承的配置作用域并不能证明文件归属。从 `core.worktree` 推测索引根目录并不安全：该配置和用于佐证的 gitfile 均可修改，工作树专属配置还可以再次重定向根目录。

## 决策

通过 Git 带作用域、以 NUL 分隔的配置查询，一次读取过滤器和 include 键。同一份结果同时提供命令键和来源文件；不读取无关值以限制输出量。查询失败或格式损坏时始终拒绝 checkout，包括所有带作用域的查询都失败的情况。

scratch-tree 和 base-tree 在创建工作树、由 Git 检出文件之前，都必须调用该门禁。关联的 base、scratch 和 probe 工作树先通过 `--no-checkout` 注册，再在目标的配置上下文中检查，通过后才显式检出文件。用户配置里的条件 include 可能只对新 gitdir 生效，因此仅检查来源工作树不能授权目标检出。base-tree 复用时仍为受控测量禁用已知驱动，但这不代表允许首次创建时执行这些驱动。

区分 Git 原生 global/system 配置入口与其包含的文件。原生入口即使被另一个工作树跟踪，也可能属于用户；但被检查的 checkout 或仓库管理目录能够改写入口或目标时，不授予该例外。保留精确的来源路径写法，不让别名继承信任。

对其他来源，拒绝发现为同一仓库体系内的文件。此外，将打开时的路径、规范化入口和真实目标及其祖先路径，与索引中的相对路径进行路径段后缀匹配，因为被索引的符号链接也可以重定向路径前缀。匹配只作为拒绝依据，不用于推测根目录。枚举公共目录、关联工作树和所属子模块的索引，包括嵌套子模块及其工作树。不再根据推测根目录下的索引未命中、`core.worktree` 或新写入的 gitfile 授予信任。目录发现或索引读取不完整时，不能豁免被包含的来源。

本地 include 遍历仍检查当前未激活的条件 include，因为未来 scratch checkout 的 Git 上下文可能不同。到达可信入口后，由 Git 计算实际激活的传递引用，每条命令的来源仍单独分类。当本地配置引用的用户过滤器可能转换过 checkout 内容时，共享工作树残留检查仍报告无法测量。

## 约束

有意收紧存在歧义的外部 include：真正位于仓库之外的文件，如果自身或祖先路径以某个索引路径结尾（不区分大小写并规范化 Unicode），也会被拒绝。同一仓库体系工作树中的未跟踪 include 也会被拒绝。没有此类歧义的普通外部 include 和原生用户配置入口仍受支持。

base 首次创建现在拒绝仓库本地过滤器命令，与 scratch 创建保持一致。需要 checkout 内容转换的用户，应通过仓库控制范围之外的 global/system 来源配置可信驱动。

管理目录遍历最多覆盖 64 个目录，索引输出累计最多 64 MiB。超限后不授予豁免，而不是静默截断证据。配置查询保留现有的 64 MiB 上限。

这是一次性检查，不是进程隔离。它不能消除同一用户并发修改的竞态，也不能在索引成员关系和目录发现证据全部被擦除后恢复历史归属。不引入新的持久化信任存储、根目录快照或通用 Git 解析器。

## 验收

先复现当前三类问题，再修改生产代码。验证工作树作用域的根目录、独立或裸管理目录、缺失标记、子模块、符号链接、嵌套 include、读取失败和无害的真实过滤器标记。保留原生及外部 include 用户过滤器的正向对照。执行 review helper 测试集、构建、打包、类型检查、lint，以及独立的最新打包 CLI 检查。报告实际执行的平台及未能执行的检查。
