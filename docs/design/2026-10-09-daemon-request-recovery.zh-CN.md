# Daemon 请求与自动恢复

[English](2026-10-09-daemon-request-recovery.md) | [简体中文](2026-10-09-daemon-request-recovery.zh-CN.md)

## 状态与范围

本分支已实现两个阶段，分开描述以便评审。第一阶段将 daemon HTTP 请求收口到 SDK，不改变连接策略。第二阶段在 daemon 不可用时暂停业务流量，通过每个 Provider 共享的恢复探测循环自动恢复。原生 WebSocket 共用第二阶段的连接门禁。不改变服务端路由及其归属规则。门禁由 Web Shell 启用，其他 SDK 使用方保留现有连接策略。

## 问题与当前行为

Web Shell 混用 SDK 调用与直接 HTTP 调用。会话重连和心跳依赖已有会话，因此等待首条 prompt 的页面可能在 daemon 退出后继续保留已连接状态。独立轮询与重连循环随后产生重复失败。Capabilities 描述支持的功能，不能证明当前可用性。

## 第一阶段：SDK 请求入口

为 DaemonClient 增加原生 REST 请求入口。使用客户端的 fetch 实现与凭证，保留请求 headers、body、取消、keepalive 和响应处理，并支持连接阶段超时覆盖。返回 Response，让现有 JSON 校验、HTTP 错误文案和 SSE 解析继续留在原调用点。REST 专用路由不能转换为 ACP 请求。现有 SDK 类型化方法保持原来的 transport 选择。普通原生 REST 调用保留 SDK 的连接阶段期限；传入 signal 时，由其负责取消与调用方的专用期限，保留长时间预热请求和 SSE body。旧 peer SDK 的兼容路径在未传 signal 时使用 30 秒连接期限。

迁移 workspace 文件系统、goals 和定时任务；Agent 名录、会话 Agent 请求及事件流；Local Control；会话 detach；启动和候选凭证探测；配对交换；远程 workspace 代理；以及 desktop-relay 的 daemon 端准备请求。如果 Provider 已持有对应连接，优先复用其 SDK 客户端。必要时通过一个兼容适配器支持已声明兼容的旧 SDK，不在各调用点分散添加特性检查。

请求保持现有归属：health 和 capabilities 属于进程全局；限定 workspace 的路由保留选定或持久化 workspace 的选择器；会话路由保留 live-session-owner 归属；旧路由仍归属 legacy-primary。远程 workspace 代理使用提供代理服务的 daemon 凭证，目标 token 单独传递。候选认证与配对必须独立于当前连接凭证。

排除 CDN 资源、Service Worker 的导航和资源缓存，以及独立的 desktop-relay 服务。带进度上传已经通过 XMLHttpRequest 进入 SDK；Web Shell 在上传发送点检查可用性并报告传输失败，不改变 SDK 的上传协议。

## 第二阶段：可用性与恢复

共享 daemon 连接状态独立于会话状态控制业务请求。发生传输失败后暂停后续业务流量，并合并连接检查。确认不可用后，各业务轮询、心跳和重连循环不得继续发送网络请求。保留列表缓存、聊天记录和未发送草稿，在主要视图展示持续的连接提示，并提供手动重试；全屏或模态 artifact 面板占据当前视图时，提示和重试位于该可见面板内。终端和本地文件桥等待共享恢复，离线时首次打开的终端显示一次本地化等待提示；显式终端释放独立于面板生命周期等待恢复，只使用释放专用路径，不创建 PTY。二维码配对刷新在断线后停止，恢复后须手动重试。语音和 Live Host 采集在断线后停止，须由用户重新开启，恢复过程不重放音频。

每个 DaemonWorkspaceProvider 为其活动连接维护一个带认证的轻量原生 REST 健康探测循环，下属所有面板共用该循环。指向同一 URL 和凭证的不同 Provider 仍各自维护控制器与探测循环，当前未实现 endpoint 级去重。REST 适配器和会话 Agent 事件流优先使用其 SDK client 绑定的控制器；仅在 client 未绑定归属时才按 endpoint 查找。独立应用使用一个聚焦的 Provider。重试间隔为 5 秒、15 秒，随后 30 秒；每次结束后再安排下一次，且有超时上限。普通检查遵守待执行的退避和认证暂停；页面回到前台或用户手动重试时可触发一次合并的立即探测。探测成功后重新验证 capabilities 与认证，再开放业务流量。恢复读取和会话附着，绝不重放 prompt 或其他写操作。

业务校验错误、会话或 workspace 不存在、主动取消都不能证明 daemon 故障。原始 TypeError 只有在 fetch 边界观察到时才作为传输故障处理；消费方上报的未分类 TypeError 仅请求诊断，不暂停健康连接。认证拒绝进入独立状态并暂停自动探测，等待凭证更新或用户手动重试。请求超时、HTTP 网关错误和事件流结束触发合并检查，不能仅因业务路由失败就暂停健康连接。旧请求与探测不得修改替换后的连接，也不能恢复过期状态。请求代次还能防止故障前的迟到失败重新关闭已经恢复的连接。销毁时取消探测与恢复等待，覆盖多个 Provider 与 StrictMode 重挂载。

暂停连接不能让缓存的实时活动状态永久有效。持续离线 90 秒（三个实时状态重试窗口）后，在本地使实时会话状态失效，不发送业务请求；短暂断线恢复会取消该过期任务。会话目录本身继续保留缓存。未加载过的会话列表和状态面板显示不可用提示，不能误报为空结果或持续显示首次加载，连接修复入口仍可使用。Managed 视图没有挂载 artifact 面板时仍保留连接提示。

恢复连接时，独立使在途状态读取失效，不影响已发出的设置写操作；保留其结果，绝不重放写入。宿主处理的本地斜杠命令和本地模型策略提示仍在网络提交门禁前执行。语音采集保留原始错误词汇，只由界面格式化器对服务不可用原因做一次本地化。

## 指标与限制

导出的聊天记录包含 Web Shell 共享翻译表和可用性消费代码。在相同依赖下，渲染器从合入主线 `65051590d9` 的 2,048,235 字节增长至本分支的 2,050,022 字节（增加 1,787 字节）。两次构建均有相同的 2,174 个输入，第三方源码未变。JavaScript 预算从 2,050,000 调整至 2,052,000 字节，保留 1,978 字节余量；禁止依赖的检查保持不变。

实际发出的失败请求仍如实记录为失败。本地阻止的操作不属于 HTTP 请求。恢复探测使用 `/health`，健康检查成功后再请求 `/capabilities`，必须按 endpoint 统计，使宿主能与业务 API 成功率分开统计。仓库调查未找到通用的宿主 HTTP 成功率上报入口，因此没有集成证据时不能声称已完成宿主指标过滤。用于发现故障的首批失败和已在途请求无法消除。宿主提供的 transport 可能在返回错误之前自行重试；门禁无法拦截该 transport 内部隐藏的网络活动。

## 验证与验收

第一阶段验证自定义 ACP transport 下的原生 REST 选择、显式 fetch 注入、认证与 headers 合并、编码后的 workspace 路径、空及带前缀 base URL、取消、keepalive、响应错误以及长时间 SSE body。运行相关包的定向测试、构建和类型检查。浏览器检查按需使用真实 daemon 与确定性模拟后端，并标明各证据来源。

第二阶段验证无会话页面、活动会话和多面板的停止与重启。在途请求结束后，不可用期间业务流量必须保持为零，仅该 Provider 共享的恢复循环可以发出探测。重启后恢复读取和会话附着，不能丢失草稿或重放写操作。检查误判分类、过期响应、卸载清理和自定义 transport。

## 待确认的集成问题

确认部署控制器如何计算空闲活动，以及宿主如何采集健康探测。确认旧会话已不存在时的重启语义；复用现有会话恢复行为，不隐式创建或发送任务。
