# 在 WebShell 创建空托管工作区

[English](2026-10-15-managed-workspace-creation.md)

## 问题与现状

托管模式已复用 WebShell 的输入框和侧边栏，但工作区选择器只能列出管理员登记的工作区。Java 服务目前提供发现与会话创建接口；运行时解析、存储校验、首个 Turn 准入均在启动时保存静态挂载映射。仅增加页面按钮无法得到可以执行任务的工作区。

## 范围

已认证的租户用户输入名称即可创建空工作区，选中后立即发起托管任务。管理员通过 `qwen.managed-agent.runtime-broker.workspace-creation-root` 开启能力，该配置指向已存在的规范目录，位于支持存储验证的 Linux local-process 主机。必须启用持久化、Session 隔离的 Broker、工作区恢复验证、Harness 文件工具及 Session Store。默认关闭。

本次不包含导入已有服务器路径、Git 克隆、上传、配额管理、删除工作区、共享权限管理或修复既有会话的 Writer 恢复流程。浏览器不能指定文件路径、storage ID、策略或身份。本地模式保留现有工作区行为。

## 创建协议与权限

新增 WebShell 接口 `POST /api/agent/web-shell/v1/workspaces/create`，请求包含 `displayName` 与 `idempotencyKey`。仅在已启用时，查询接口返回 `workspaceCreation` 能力。成功响应沿用工作区摘要结构。名称去除首尾空格后限制为 1–128 个字符，不允许控制字符。租户和用户来自认证请求上下文。

创建复用现有请求回执表，增加 `WORKSPACE_CREATE` 命名空间，按用户划定幂等范围。请求摘要覆盖规范化后的名称；相同键提交不同内容返回冲突。文件系统变化前，回执固定生成的工作区 ID、storage ID、存储注册操作 UUID 和名称。回执从 PENDING 变为 COMPLETED，不占用或改变工作区生命周期状态的含义。

服务端根据经过验证的回执身份生成独立目录 `creationRoot / hash(tenant) / receiptKey`，只创建受控目录并检查规范路径及祖先。在任何外围 SQL 事务之外调用现有原生存储 Guard 注册物理目录。最终 SQL 事务原子写入 ACTIVE 的 ROOT 工作区、generation 1、现有工作区执行 config/policy、创建者 OWNER 授权，并完成回执。新工作区不修改租户默认工作区。

重试沿用同一个 PENDING 回执、目录及注册操作。COMPLETED 重放读取当前工作区和权限，不重建已删除记录、不恢复已撤销授权、不重新激活已停止接收任务的工作区，也不重复注册存储。并发注册中若另一个请求先完成，则读回完成回执并核对当前授权后返回成功。失败准备保留可恢复状态，本次不增加自动删除目录的操作。

Schema V4 在已发布的 V3 会话列表索引迁移之后扩展回执命名空间。V1、V2、V3 资源与已应用历史保持不变；初始化和 Flyway 准入先识别各个规范的已发布版本，再应用后续迁移。

## 运行时接线

共用的创建目录解析器检查配置根目录与静态挂载及运行时私密状态目录的隔离，并核对回执命名空间、租户、storage ID、工作区 ID、结果结构和状态。PENDING 目录只对创建过程的存储注册开放；运行时解析、存储校验和首个 Turn 准入必须看到 COMPLETED 回执。原生物理身份和 marker 验证继续生效，storage ID 前缀本身不提供任何权限。

存储 Guard、运行时解析器和托管会话存储通过该解析器识别新增存储，同时保留静态挂载。底层路径解析不要求工作区仍为 ACTIVE，以保证工作区进入 DRAINING 或 REMOVED 后旧会话仍能关闭。新工作继续由 registry 校验 ACTIVE 与当前权限。服务重启后根据 SQL 与配置根目录恢复映射，不能依赖内存登记。

## 页面接线

Provider 宣告创建能力后，共用工作区选择器显示创建操作。使用已有作用域 Dialog 输入名称，显示进行中和错误状态；成功后选中新工作区并保留输入草稿和模型。客户端发送前固定并持久化待创建的名称和幂等键；响应不确定时重试同一操作。关闭弹窗不会重复创建，刷新后可恢复待确认操作。不支持或未开启的 Provider 保留列表发现功能。

## 验收标准

1. 默认关闭的部署不宣告也不接受创建；启用后生成独立、已注册且向创建者授权的目录。
2. 同键重试和并发只生成一个工作区；不同内容冲突；物理注册后恢复继续使用相同存储身份。
3. 保持用户与租户隔离、规范路径包含关系、marker/身份校验以及运行时私密状态隔离。
4. 页面创建并选中工作区，保留草稿，真实文件工具在该目录执行；刷新及 Java 重启后仍可找到，新会话能够继续使用原文件。
5. 已有静态工作区、本地模式、会话创建、取消和关闭继续可用；响应不暴露凭证或宿主路径。
6. 全新 schema 与已有 V1/V2/V3 数据库可升级，不改变历史迁移校验和，不删除数据。

## 已观察到的恢复限制

在与当前 main 集成之前，基于 `4b6b4270` 加这些本地功能的演示验收发现，控制面优雅停机时间超过 Writer 租约时，已有的空闲 Harness 会话会保留已过期的 Writer。该物理重启场景尚未在集成后的 PR head 重跑，当前 head 是否仍存在这一现象尚未验证。当时下一条消息停在 ACCEPTED，授权持续重试；该演示版本的驻留会话加载和 Writer 续期路径没有重新取得权限。工作区目录、marker 及 SQL 身份均保留。旧会话接续应单独记录为失败，不能与工作区持久化和新会话复用混为一谈；本功能不放松租约隔离，也不修复该既有恢复路径。

## 待定问题

已选择的空工作区范围没有待定问题。配额和存储回收需要单独的产品决策。
