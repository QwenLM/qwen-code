# Untrusted persisted transcript reader

[English](untrusted-persisted-transcript.md) | [简体中文](untrusted-persisted-transcript.zh-CN.md)

## Context

The daemon already exposes persisted-only session and group catalogs for registered untrusted secondary workspaces. This design adds a separate workspace-qualified REST contract that reads only an active persisted transcript, without starting ACP, loading workspace settings or project-defined capabilities, or creating a route-specific cursor signing key.

The default `GET /session/:id/transcript` route (and its `GET /session/:id/turn-index` sibling) now shares the same daemon-local read path, so its index cache survives ACP child exit instead of rebuilding in a fresh child on every cold reopen. It keeps its existing ownership resolution through live bridge state and its file-backed per-workspace cursor key, and it still flushes an already-live recorder through the bridge before a cursor-less backward first page (without starting a child). Because the daemon-local replay passes no full `Config`, replayed tool calls fall back to the persisted tool name with `kind: "other"` and empty `locations` — the same fallback the workspace-qualified route has always used. This is an accepted trade: the default conversation pane loses resolved tool icons and file links until a replay `Config` is threaded daemon-side; a dedicated test pins the fallback shape.

## Contract

The daemon advertises the unconditional `workspace_persisted_transcript` capability and serves:

`GET /workspaces/:workspace/session/:id/transcript?cursor=<opaque>&limit=<1..500>`

The workspace selector resolves an exact registered workspace id first, then a URL-decoded portable absolute cwd. Unknown or unregistered selectors fail closed with `workspace_mismatch`. Trusted primary and secondary workspaces and untrusted secondary workspaces may read. An untrusted primary remains rejected to preserve the existing plural-route safe-mode boundary.

Only active persisted JSONL is read. Archived sessions return `session_archived`; active/archive conflicts return `session_conflict`; missing sessions return 404. The response reuses `DaemonSessionTranscriptPage` and contains id-less `session_update` frames produced by the existing visible history projection. Raw JSONL and hidden system records are never returned.

## Security boundary

The workspace-qualified route must not start or preheat ACP, load settings, parse agents or skills, discover tools, run external commands, create a persisted cursor key, or write a route-specific daemon/debug log. It reads persisted JSONL daemon-local. It may synchronously read the bridge's in-memory session summary to check liveness on any page, without contacting the child. The only child RPC it may issue is flushing an already-live session's recorder before the first backward page (the live-flush barrier), which drains pending writes without starting a child. Existing daemon-wide HTTP access logging and telemetry remain outside this route-specific no-write guarantee. The singular route shares the same daemon-local read, replay (no settings load, no project tool registry) and live-flush barrier, and additionally resolves ownership through live bridge state.

Direct persisted transcript reads run with debug session logging suppressed. The archive coordinator holds a shared session lock across location checks, index construction, record reads, session-id validation and replay. Every returned record must carry the requested session id; a mismatch fails closed as a snapshot conflict.

The direct replay context contains only a session id, an update sink, optional message rewriting, and optional cumulative usage. Tool display metadata falls back to persisted tool name and description when no full `Config` is present. No project-controlled tool registry is consulted.

## Cursor lifecycle

The core reader accepts an explicit cursor codec. Existing callers continue to use the file-backed codec. The daemon creates one random master key per process, derives a separate 32-byte HMAC key from workspace id and canonical cwd, and caches an in-memory codec per registered runtime. Cursors from the new route therefore expire on daemon restart and cannot be replayed across workspaces.

The cursor freezes file identity, byte size, active leaf, replay position and replay state. Pure appends after page one do not change the snapshot. Delete, archive, truncate, replacement, an equal-size in-place rewrite (the frozen size still matches but mtime moved), leaf change, or session-id mismatch returns `transcript_snapshot_unavailable`. A uuid-preserving in-place rewrite followed by an append is not detected: the size grew, so the equal-size mtime guard does not run, and page bodies are read from the live file at the frozen offsets (see Compatibility and limits).

## Failure and race handling

For the first page, the route checks active/archive location but still attempts the active reader when location is unknown so malformed active storage is not silently reported as missing. For cursor pages it validates only the frozen active snapshot. On `ENOENT`, a cursor page returns snapshot unavailable; a first page rechecks location to detect an archive race before returning missing.

Concurrent requests for the same uncached snapshot share one build whose completion includes the snapshot re-verification and cache admission: if the file was rewritten or replaced under the build (equal-size mtime move, identity change, or truncation), every sharer receives `transcript_snapshot_unavailable` instead of the torn build result. A transient stat error during the re-verification (`EMFILE`, `EIO`, `EACCES`) serves the built snapshot uncached rather than failing a ready page; a missing file still fails closed. Admission reuses the length that re-verification stat returned: the ownership check, the class budget math, the reclaim and the cache write run synchronously against that one verified file state.

Replay is page-transactional at the protocol boundary: updates emitted before a replay conversion failure are returned with `partial: true`, a generic replay error and no next cursor. Pending tool calls and cumulative usage are carried in the signed cursor only after successful replay.

## Compatibility and limits

The singular route keeps its file-backed persisted cursor key, its ownership resolution and its ACP error mapping; only its read moved daemon-local (see Context), so cursors it minted before the change remain consumable. The workspace-qualified route keeps the existing default requested window of 100, maximum requested window of 500, 256 MiB snapshot cap, 32-entry index cache with a 64 MiB shared byte budget plus a separate 256 MiB oversized-index budget (worst-case byte retention is the sum, 320 MiB) and five-minute cache lifetime. The workspace-qualified route additionally caps each page at 4 MiB of persisted source records, 32 MiB of serialized response JSON and 64 KiB of cursor state. `limit` is a record-count ceiling for forward pages; backward pages may expand to at most `3 * limit` records to preserve turn and tool-call/result boundaries. A single aggregate record over the source budget returns `transcript_page_too_large`; an oversized replay cursor terminates the otherwise successful page as partial without issuing a continuation cursor. The first index scan remains linear in the frozen snapshot size.

When a class budget is full, admitting a newer snapshot evicts superseded or unreachable snapshots of the same file — but only when the new snapshot fits after the reclaim. Unreachable entries are reclaimable regardless of temporal order: a changed identity (the identity guard rejects their cursors, even when a backup restored an older mtime), a length beyond the current file (the size guard rejects them, even when a same-millisecond truncation kept the mtime), or an equal size at a different mtime (the mtime guard rejects them). Supersession is decided by length, never by mtime order: an in-place sync can append and then restore an older source timestamp, so a newer mtime does not make a shorter prefix live, and an older mtime does not make a longer index dead. A same-identity strictly shorter prefix is contained in the incoming snapshot and reclaimable fit-before-evict; a longer same-identity index still serves the frozen offsets and is protected. A refused admission never evicts: reclaim happens only when it enables an admission, which protects the still-readable append-left prefixes; a frozen-prefix read never reclaims the live newer index. Frozen cursors to an evicted prefix rebuild on demand. Eviction itself costs latency only: page bodies are read from the live file at the frozen offsets whether or not the index is cached, so eviction never changes what a page serves. That read model assumes append-only writes. A uuid-preserving in-place rewrite followed by an append serves rewritten prefix bytes under a frozen cursor, with or without a cached index: the size grew, so the equal-size mtime guard does not run, and the rebuilt or cached hints point at the rewritten bytes. Detecting it requires validating the frozen prefix bytes themselves (a digest carried in the cursor and checked against the current prefix), which re-reads the prefix and is deferred work. Byte-budget eviction stays within the entry's budget class: freeing shared bytes does not admit an oversized index, and a class-full refusal keeps resident indexes instead of thrashing between them. The 32-entry count cap is a separate, global LRU: an oversized entry can still occupy a slot a warm small index held, and the restore-offer door reclaims superseded same-file entries to free a slot when the count is full. These rules supersede the cache constraints of the older [selective-session-restore design](2026-08-08-selective-session-restore.md): its "skip the offer when admission would require evicting an existing value", its "byte-budget admission of a completed value must not evict an already-cached value", and its "an index whose own estimate exceeds the whole cache byte budget must not be retained" no longer hold — admission and the offer reclaim superseded same-file snapshots fit-before-evict (byte arm class-scoped, count arm class-agnostic), and the oversized class retains indexes above the shared budget. Its non-clobbering ownership rule (a completion updates or deletes the entry only while it still identifies that build) still holds. Managed message projections and hook aggregates retained alongside a cached index are accounted against the budget class the entry belongs to after the addition — an entry whose retained bodies cross the shared budget moves into the oversized class — and are not retained when the combined entry does not fit. The same fit-before-evict reclaim applies to that addition: when superseded snapshots of the same file block the target class, they are reclaimed only if the combined entry fits after the reclaim. The unreachable clauses require a verified current file state, which only the admission and offer doors have; growth accounted under a frozen prefix (a hook aggregate, or a projection decoded under a frozen cursor) reclaims only entries strictly shorter than a fresh stat of the live file (the live index always equals that length, whatever its identity): an in-place truncation under the frozen read can leave the current full index shorter than the frozen snapshot at the same identity, and that entry is the live index, not a historical prefix. A failed stat skips reclaim (only additions that already fit without reclaim are retained) instead of reclaiming blind, and the entry being grown is excluded from its own reclaim scan. Projections attach only after the shared build's verified admission and are accounted by the retention branch, so concurrent pages cannot leave retained bodies off-budget.

For append-only growth on an already-cached physical snapshot (`fileIdentity.ino !== 0`, same `(dev, ino)`, `base.snapshotSize < snapshotSize`), `getCachedIndex` extends the largest valid cached prefix incrementally rather than reparsing from byte 0. Each cached index may retain a compact `IncrementalIndexState` (sanitized branch-point hints carrying only the three `branch_checkpoint` payload fields, the 4-field execution-engine accumulator snapshot, raw start timestamps, loop estimate, and a 64-byte suffix fingerprint ending in `\n`) inside a `WeakMap`, accounted atomically inside the entry's cache-class admission byte size (dropped when adding it alone would cross the shared-to-oversized boundary or exceed the entry's class cap, so no state lives off-budget). Before scanning `[base.snapshotSize .. snapshotSize)`, the builder verifies the 64-byte tail fingerprint at `base.snapshotSize` in one pread; any mismatch (such as an in-place truncate-and-rewrite longer on the same inode) falls back to a full rebuild from byte 0. Incremental extension uses copy-on-write over `byUuid`, `branchPointRecords`, and `navigationOrdinal` (clearing stale ordinals for rewound turns) so frozen cursors and turn snapshots referencing the base index remain immutable. Cold full builds, incremental extensions, and cold prompt-time scans share a process-wide build concurrency semaphore (default 2), and `readPage` / `readTurnIndexPage` (including the daemon's singular and workspace-qualified HTTP transcript and turn-index routes) propagate `AbortSignal` through refcounted shared in-flight builds, semaphore queues, and `forEachLineInSnapshot` streams so cancelled requests detach immediately without aborting live sharers.

The TypeScript SDK exposes the method on `WorkspaceDaemonClient`. It forces native REST transport and has no ACP route mapping. Older daemons can be detected through the new capability and continue returning 404 for the route.

## Deferred work

Archived transcript reading, reverse/tail pagination, live follow, automatic full-history loading, worker-thread indexing, cross-restart cursors, frozen-prefix digest validation on rebuild (closing the rewrite-then-append residual), and the Web Shell viewer are separate follow-ups.
