## Existing policy and ownership

The existing public Core prepareFileWatchersForProcessExit marks final process exit on Darwin. Its closeFileWatcher detaches change/all listeners in that state and leaves resource reclamation to process exit; otherwise it closes normally. Core implementation, thresholds and APIs are unchanged. The marker is process-global and sticky until successful exec or process exit. These callers intend final exit, but an error may prevent termination; the selected failed-exec terminal 42 path now has controlled regression coverage; other errors outside that catch do not gain a new termination guarantee. Worktree watcher ownership remains selected Config/session and its existing sidecar directory; no alternate runtime/filesystem fallback is added.

## Changes and consumers

The shared interactive signal beginExit calls prepare once after its cleanupStarted latch and before runExitCleanup. Raw-mode restoration, duplicate-signal handling and cleanup order remain unchanged. The handler is installed on interactive startup; existing ACP final-exit preparation stays untouched.

Preparation, cleanup and original re-exec arguments remain unchanged; cleanup failures are outside this catch.
