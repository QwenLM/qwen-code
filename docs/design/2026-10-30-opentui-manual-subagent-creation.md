# OpenTUI manual subagent creation

[English](2026-10-30-opentui-manual-subagent-creation.md) | [简体中文](2026-10-30-opentui-manual-subagent-creation.zh-CN.md)

## Problem and evidence

The public `/agents create` command opens a real eight-step manual wizard in Ink, but OpenTUI previously displayed only a description and Escape. An isolated global Ink run completed cancellation, manual creation, exact Markdown verification, hot and cold detail views, two natural exits and zero model requests. An earlier baseline observer failed because it expected the description in the list rather than opening details; that failure remains recorded. The candidate's strict OpenTUI run then failed at the first location screen, showing the placeholder rather than the wizard. These are separate observations; the global binary's source identity is unknown.

## Scope and design

Add a native manual wizard without changing Core, the manager-details UI, default renderer or the Ctrl+C owner. The existing mount passes its actual config into the new component. Reuse the renderer-independent Ink wizard reducer, eight-step mapping, color options and tool registry categories. Location supports project/user, followed by an explicit Manual Creation choice, name, system prompt, description, tools, color and confirmation. The only offered generation method is implemented: manual creation performs no model request. Guided generation and external save-and-edit are not presented as working actions and remain separate work.

Text fields reuse the shared line editor, including caret movement, paste, word editing, kill/undo/redo and accepted-value history. Empty input cannot advance. Back preserves draft values; Escape at the first step cancels without saving. A step transition settles its field owner, and handlers reject events belonging to an earlier step in the same input read. Display strings are terminal-sanitized; empty native text segments around the caret are omitted.

Tools are actual registry display names grouped by existing tool kinds. All Tools remains an empty array, so the existing serializer omits the tools field. Explicit colors such as Blue are preserved, and automatic color remains `auto`. The confirmation checks the existing manager for name collisions before accepting save and displays the existing same-level overwrite or cross-level precedence warning. A failed conflict check prevents saving until the user goes back and retries the check.

Save uses only the existing public manager with `{level, overwrite: true, assertCanCommit}` and a full subagent config. No custom filesystem path or direct agent-file write is introduced. The manager validates, selects project `.qwen/agents` or the configured user agent directory, serializes, writes and refreshes its cache. A synchronous pending ref refuses duplicate commits. Errors retain the form. Success is visible before closing, with the close timer cleared on unmount.

Escape may close a pending save. Closing/unmount revokes the owner checked by the existing `assertCanCommit` callbacks before directory creation and file write. This cannot roll back a write that already started or committed. Late promise completion cannot reopen or update a closed wizard. No new Core API or cancellation guarantee is invented.

## Validation and acceptance

The new behavioral unit tests exercise eight-step payloads, real registry category values, user scope, empty-field validation, text history, backward navigation, same-read Enter bursts, save errors, single-flight submission, pending-owner revocation, name-conflict ordering and missing config. Their React host is a test double; they do not qualify native terminal rendering or disk persistence.

The existing interactive case must run against the built candidate: cancel without project/user store changes; manually create one unique project agent; verify complete summary and no pre-save file; save exact Markdown; verify the user store unchanged; read the created agent in the same process and after a real restart, including details on both Ink and OpenTUI; retain two natural exits and zero model requests. Candidate/runtime identity is recorded with the actual results. The earlier list-only OpenTUI observation was superseded by the separately reproduced and fixed read-only manager path.

Run affected CLI unit files, full build/typecheck/lint, formatting and the focused interactive case through Node Ink, Bun Ink and strict Bun OpenTUI. Review the full change twice after fixes and obtain an independent review. Existing baseline failures stay unchanged. User-level disk E2E, real overwrite, guided generation, external editor, agent execution/tool permissions and other platforms are outside the focused project-creation proof. A local candidate on an earlier base is not final merged-main acceptance.

## Actual validation during implementation

The first new wizard unit run recorded 2P/10F: newly allocated empty item lists triggered render-phase updates in the shared selection hook, before the Ctrl+C assertions were reached. Memoizing the caller's list by kind/toolCategories produced an actual second run of 11P/1F. Its only failure was the manual name retaining its text after Ctrl+C. Both failures and the earlier static-review omissions remain recorded; neither is retrospectively a pass.

Ink's real TextEntryStep uses the shared TextInput CLEAR_INPUT contract. The native field now routes the existing `keyMatchers[Command.CLEAR_INPUT]` to the line editor's `clear()`: clearing is one undoable edit, and an already empty field adds no unnecessary history. It calls neither preventDefault nor stopPropagation, leaves the global Ctrl+C owner unchanged, preserves Ctrl+Shift+C and keeps ordinary Shift+C printable. The post-fix four-file unit run actually passed 94 cases (12 wizard, 40 mount, 13 history and 29 line edit), with formatting successful. These do not qualify native behavior.

The first post-fix strict Bun OpenTUI run still failed at create-location-cancel. Its actual frame now showed Step 1: Choose Location, but the rows displayed project and user rather than Ink's meaningful location descriptions. Shared DialogSelect renders value unless the caller supplies renderLabel; this caller populated label but omitted that renderer. Preserve both the earlier 94P and this native failure, with later phases not reached. The minimal caller fix explicitly paints sanitized labels: Project/User Level and paths, Manual Creation, real tool-category names, and display colors such as Blue. Submitted values are unchanged. The original E2E oracle, single inputs and budget remain unchanged; that first post-fix native result remained pending at the time.

The label fix subsequently passed the four whole unit files with 95 cases, normal build, typecheck, lint and bundle. The actual Node+Ink, Bun+Ink and strict Bun+OpenTUI manual-creation cases all passed, including exact Markdown, hot/cold observations, zero model requests and natural exits. This is evidence for that local manual-creation candidate, before the later manager-details changes; it is not merged-main or complete migration acceptance.

The final local combined candidate, still uncommitted on the current dependency foundation, passed six whole CLI files with 111 tests after the PascalCase correction, then normal build, typecheck, lint and bundle. Node+Ink, Bun+Ink and strict Bun+OpenTUI each passed two Permissions cases, Source acquisition and the manual-creation case with hot/cold manager details: 12 executions, four unique cases, 18 observed natural session exits and zero model requests. The manual case proves cancellation without a write, the eight-step project creation, exact Markdown, user-store preservation and hot/cold read-only navigation. It does not exercise manual Ctrl+C natively, user-level disk creation, optional viewer fields or long scrolling. Unit coverage includes manual Ctrl+C, user-level payload selection, optional viewer fields and basic scroll dispatch; it does not qualify user-level disk creation or long-scroll E2E. ## Canonical persisted colors

Color choices display their existing labels but now submit the lowercase option id to the public manager. `blue`/`green` survive the existing Core parser; `auto` remains implicit during serialization. The selector reads canonical ids as well as historical display names without silently rewriting files. Earlier exact `color: Blue` creation evidence did not establish a retained color after Core reload. The corrected whole public creation scenario requires `color: blue` and the hot/cold detail color. The current canonical-color batch passed eight whole CLI files with 146 tests, normal full build, typecheck, native layout/resize and bundle generation. Node+Ink, Bun+Ink and strict Bun+OpenTUI each passed the full five-case public set, including this creation scenario and the new editing/deletion case, against one local source bundle: 15 executions, five unique cases, 24 observed natural session exits and zero model requests. Independent saved-result review confirmed the three profiles and 58 finite input pins; final typecheck and lint both passed. Earlier capitalized-color results retain their historical scope. This does not qualify installed mutation behavior, other platforms or final merged-main acceptance.
