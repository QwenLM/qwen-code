# 已取消轮次的恢复

[English](cancelled-turn-recovery.md) | [简体中文](cancelled-turn-recovery.zh-CN.md)

## 问题与范围

在工具结果之后主动取消 daemon 轮次，恢复的 API 历史与崩溃轮次相似。历史启发式忽略已持久化的 cancelled `turn_result`，继续提供恢复。此变更区分有权威记录的 daemon 取消与未知中断，不新增持久化账本，不从文本猜测取消，不改变工具结果修复。

## 标识与恢复

最后一条真实 API 用户输入携带客户端 `promptId`。活动分支中唯一对应的用户记录提供 `daemonPromptId`，它必须匹配之后唯一且有效的 `turn_result.promptId`，状态为 `cancelled`，且同时带有有效的 `cancelledAt` 时间戳和明确的 `cancelReason: 'user'` 来源。会话销毁和其他 abort 也会结算为 `cancelled`，因此仅凭状态无法判断用户意图。重复、缺失、无效或不匹配的标识不能确认主动取消。有效的旧取消终态带时间戳、没有明确来源，且之后没有新的输入、尝试或终态取代它时，视为意图未知，包括归属缺失或不明确的情况：历史确实中断时仍可以继续，但绝不自动继续。较新的无标识用户输入阻止重用旧取消。通过共享历史边界，同时结合通知形状和投影提供的权威尾部通知数量排除未投递通知。带 reminder 的旧通知条件样例仍可恢复；当前 ACP recorder 持久化的是裸通知信封。

完整会话恢复与选择性恢复使用同一判定。转录索引保留活动链的少量有效结算提示，包括压缩之前的记录。选择性恢复独立于回放窗口使用这些提示，不重读历史输入的大内容，也不向模型历史注入终态记录。压缩保留既有客户端输入标识。ACP 线协议恢复只从当前服务端历史的未修改前缀恢复身份，不确认来源不明确的标识。重试准备成功后，将身份移到新的实时用户条目；准备回滚时保留原归属。快速规则压缩保留主动取消与旧记录的确认身份。父链接缺失时保留 degraded-history 防护。

Retry、Continue 和恢复工具交互会重用原用户记录。写入权限获准后、异步准备及可能的提前中断结算前，recorder 必须持久化一条 `turn_attempt`，包含原客户端标识及新的 daemon 标识。最新尝试取代原 daemon 归属，包括尚未产生响应或终态就崩溃的情况。只有该最新绑定之后唯一且明确的用户取消终态才抑制恢复。归属标识未知时继续保留恢复。此记录不包含用户文本，不重复可见输入，且普通转录和 Managed 转录投影都保留它。实际重新提交用户内容时，通过既有 send 选项保留原历史输入标识，包括压缩路径；工具结果不复用该输入标识。

取消来源通过桥接取消元数据传递。远端 Host 的心跳与拒绝响应显式传递取消来源；用户 Stop 将来源随租约持久化，重启隔离及没有来源的旧响应仍作为中断处理。Channel abort 保留来源；SDK 将同一轮同步取消合并为一次请求，已发送的中断允许后来显式用户取消单向升级。工作区 agent 区分人工取消与 token 预算中断。ACP 路由同时保留取消来源和客户端身份。主动 Cancel 和删除排队输入携带用户意图；HTTP 响应连接关闭、超时、频道 steering、会话退出和 SDK 普通 signal abort 携带中断来源。所有受控取消均发送取消通知并等待终态 flush；只有用户取消在终态写入 `cancelledAt` 和 `cancelReason: 'user'`。ACP 中止 admission 和 pending send 时保留此原因。用户取消单向升级已经在途的中断；Broker 等待两次取消握手完成后才推进 FIFO。子进程对每个实际 admission signal 保存用户意图和时间，因为已经 abort 的 signal.reason 无法修改。REST 或 ACP-over-HTTP 显式关闭会话时，用户意图会通过子进程的关闭门控传递，对执行中及等待准入的输入保留主动取消来源。自动清理与 runtime 退出仍保留 dispose 来源；已经 disposed 的会话仍把后续取消按释放处理。只有用户意图才能写入 `cancelledAt` 或绑定实时取消标记。没有元数据的标准 ACP 取消仍保持主动取消行为。在结算提示进入索引字节统计前，丢弃无效输入标识。

## 运行时生命周期

初始化后的 chat 在调用方克隆历史前，将已验证的取消绑定到当前历史数组、长度、最后条目和用户推入计数。替换、截断、追加历史及新输入获准进入历史后使绑定失效。仅刷新启动上下文前缀，或在空闲内存压力清理中清除旧工具结果时，将已验证的结算状态绑定到更新后的历史；这些操作保留被取消的轮次。新 chat 不继承它。发送前准备失败并回滚新输入时，原始取消绑定保持有效；成功的新输入仍通过结构变化使旧绑定失效。ACP、daemon 状态和继续接口，以及 headless 继续入口都查询当前 chat。

实时 daemon 取消要求用户取消的 abort 原因，且只绑定一次到最新归属轮次的 chat，要求原会话仍然有效且该轮实际推入过用户内容。压缩创建新 chat 时检查新实例的输入推入计数；发送前取消后直接追加的本轮输入也会被标记。迟到的旧结算或未进入历史便取消的输入不能标记另一轮。既有持久化终态仍写入轮次开始时绑定的 recorder。

## 验证与验收

使用受控本地 provider 和真实构建的 daemon：执行一次 read_file，挂起下一次 provider 响应，主动 Cancel，重启后请求继续。必须拒绝继续且不请求 provider。配对 SIGKILL 对照不持久化终态，仍必须允许继续并正常执行。另检查实时状态、之后相同但未回答的输入、废弃分支、压缩、replay:none/recent/all、相同长度替换、未知或重复标识、历史缺口。

另验证连接关闭和 prompt 超时仍可恢复，直接 ACP 取消仍属主动取消。重试被取消的输入，中断新的尝试，确认旧取消不能抑制恢复；主动取消新的尝试时应抑制恢复，分别覆盖有无压缩。数字类型的异常输入标识不能使索引缓存字节统计变成非有限值。持久化尝试记录写入失败时，恢复执行必须在调用 provider 前停止。

## 风险与剩余工作

缺少权威 daemon 标识的旧转录不能确认主动取消，但最后一条有效且只有时间戳的取消仍需确认未知意图，使用其持久化终态身份；后续输入、尝试或终态会移除此保守门控。此变更覆盖有记录的 daemon 取消，不为旧路径或独立 TUI 取消凭空生成终态来源。模型响应与工具修复语义保持不变。

旧构建既会在用户取消时写入 `cancelledAt`，也会在受控 admission abort 时写入。因此，新记录只由能判定取消来源的 Session 结算写入点添加 `cancelReason: 'user'`。校验器要求该标记同时带有取消状态和有效时间戳；完整恢复和选择性恢复均将它复制到结算提示。只有时间戳、没有标记的旧记录仍可读取。完整恢复和选择性恢复独立于回放窗口及压缩保留其未知意图，既有的历史绑定取消标记携带终态 daemon 输入身份。恢复禁用自动继续，并提供该身份供用户确认。WebShell 恢复提示解释来源不明并在继续前询问；REST、ACP、SDK 与 stream-json Continue 携带已确认的身份，准入和最终执行均与当前恢复边界比较。缺失、过期或不匹配的确认不会请求模型。较新的轮次会使标记失效。缺失或不明确归属不用于认定用户意图，只有最新的有效旧终态可以保守地要求确认；无效载荷不产生终态提示。通用记录器和回放不会根据旧时间戳补造该标记。

上述规则仍有两处已知限制，均在本变更之外跟踪；将其视为可接受的兼容行为之前，需要 maintainer 明确裁定。

精确匹配且未标记的 Todo Stop Guard，以及原始实时历史中的 task-notification 自动尾部，不会遮住原始输入身份；有身份标记的真实输入即使文本匹配模板也保留权威性。冷恢复遵循记录器的权威通知计数，包括零，不套用实时通知启发式；因此未完成的已投递或带 reminder 的通知仍可以阻挡复用旧取消。其余「较新的无标识用户输入」规则在构造上是 fail-open 的。仍会产生未知用户形状边界的来源包括 cron 或 loop 回显（既不打标识也不裁剪）、被推入的轮次中途插话，以及在丢弃 code-mode 工具结果之后被推入的插话条目。当其中一条落在已取消轮次之后时，查找解析不出输入标识，恢复仍然可用，重启后可能重新提供用户已停止的工作。改为回溯到上一条带标识的条目，则会重新抑制该规则本来要保护的合法新输入，因此方向选择属于产品裁决而非修复。

客户端显式关闭现在会对执行中或等待准入的轮次记录用户取消。若先前中断已经结束、会话已空闲，之后关闭仍没有持久化的「已关闭」标记，重启后仍可能提供该中断任务。本变更不为已空闲会话合成轮次终态，也不修改持久化的会话生命周期契约。
