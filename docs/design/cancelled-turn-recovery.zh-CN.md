# 已取消轮次的恢复

[English](cancelled-turn-recovery.md) | [简体中文](cancelled-turn-recovery.zh-CN.md)

## 问题与范围

用户明确取消的 daemon 轮次，重启后可能看起来像未完成任务。恢复必须拒绝用户停止的工作，同时允许真正中断的轮次继续。本改动在现有终态记录中写入取消意图，复用现有执行身份。旧取消记录的确认流程和 UI 文案放入后续改动。

## 身份与终态

客户端 prompt ID 标识输入，daemon prompt ID 标识执行。用户记录和现有 turn attempt 在当前转录分支上绑定两者。完整与选择性恢复共享归属判定，不依赖重放窗口，包含压缩前记录。明确用户取消要求合法取消终态、有限取消时间、显式用户来源及唯一执行归属。只有时间戳的旧取消和归属不明的取消均视为未知，拒绝自动与直接 Continue。更新的模型输入、attempt 和终态取代旧边界；不进入模型历史的已完成本地命令不会取代它。

LlmClient 持有当前执行 ID 和归一化取消终态。实时结算和冷恢复使用同一归一化规则。输入准备成功后接受现有 invocation 或模型 prompt ID；准备失败不会替换归属。结算只更新所属执行。保留的发送前输入显式接受身份；仅准入阶段取消和迟到结算不能取消其他任务。持久化 Retry/Continue attempt 更新归属，并保留取消边界直至准备输入。压缩、启动提醒和空闲清理保留终态；显式替换历史、回退和清空使归属失效。消息数组不需要额外取消快照。

## 取消意图

用户 Cancel、删除排队输入和关闭活跃客户端，通过现有取消元数据传递用户意图。传输失败、超时、自动清理、dispose 和普通 SDK abort 属于中断。后到的用户取消可以升级进行中的中断；FIFO 取消握手完成后才能开始下一输入。只有用户意图写入持久化用户标记。恢复准入和实际执行均检查当前终态边界。非法终态不证明来源；历史缺口仍使用 degraded-history 防护。

## 验证与验收

使用真实构建的 daemon 和隔离的本地 provider。执行 read_file，挂起下一响应，Cancel、杀进程重启、重新关联并 Continue：必须拒绝且没有新增 provider 请求。对照组不 Cancel，在挂起响应时杀进程：必须可以继续并写入完成终态。仅删除第一组转录的用户来源字段：未知旧取消也必须拒绝继续。单元验证覆盖归属、选择性恢复、压缩、回滚、新输入、迟到终态和用户取消升级。

## 剩余工作

后续改动增加未知旧取消的显式确认，以及取消和中断的展示文案。未标记 cron/steering 的归属留在 #13502。先前中断后的空闲 Close 缺少持久化关闭标记。独立 TUI 路径不在本次已记录 daemon 范围内。不包含转录迁移或发布。
