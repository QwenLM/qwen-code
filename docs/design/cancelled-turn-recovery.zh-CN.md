# 已取消轮次的恢复

[English](cancelled-turn-recovery.md) | [简体中文](cancelled-turn-recovery.zh-CN.md)

## 问题与范围

在工具结果之后主动取消 daemon 轮次，恢复的 API 历史与崩溃轮次相似。历史启发式忽略已持久化的 cancelled `turn_result`，继续提供恢复。此变更区分有权威记录的 daemon 取消与未知中断，不新增持久化账本，不从文本猜测取消，不改变工具结果修复。

## 标识与恢复

最后一条真实 API 用户输入携带客户端 `promptId`。活动分支中唯一对应的用户记录提供 `daemonPromptId`，它必须匹配之后唯一且有效的 `turn_result.promptId`，状态为 `cancelled`，且带有既有的用户取消时间戳 `cancelledAt`。会话销毁和其他 abort 也会结算为 `cancelled`，因此仅凭状态无法判断用户意图。重复、缺失、无效或不匹配的标识，以及缺少时间戳的旧取消记录，都保留既有恢复行为。较新的无标识用户输入阻止重用旧取消。通过共享历史边界，同时结合通知形状和投影提供的权威尾部通知数量排除未投递通知。带 reminder 的旧通知条件样例仍可恢复；当前 ACP recorder 持久化的是裸通知信封。

完整会话恢复与选择性恢复使用同一判定。转录索引保留活动链的少量有效结算提示，包括压缩之前的记录。选择性恢复独立于回放窗口使用这些提示，不重读历史输入的大内容，也不向模型历史注入终态记录。压缩保留既有客户端输入标识。父链接缺失时保留 degraded-history 防护。

Retry、Continue 和恢复工具交互会重用原用户记录。恢复后的模型执行开始前，recorder 必须持久化一条 `turn_attempt`，包含原客户端标识及新的 daemon 标识。最新尝试取代原 daemon 归属，包括尚未产生响应或终态就崩溃的情况。只有该最新绑定之后唯一且明确的用户取消终态才抑制恢复。归属标识未知时继续保留恢复。此记录不包含用户文本，不重复可见输入，且普通转录和 Managed 转录投影都保留它。实际重新提交用户内容时，通过既有 send 选项保留原历史输入标识，包括压缩路径；工具结果不复用该输入标识。

取消来源通过桥接取消元数据传递。主动 Cancel 和删除排队输入携带用户意图；HTTP 响应连接关闭、超时、频道 steering、会话退出和 SDK 普通 signal abort 携带中断来源。所有受控取消均发送取消通知并等待终态 flush；只有用户取消在终态写入 `cancelledAt`。ACP 中止 admission 和 pending send 时保留此原因。只有用户意图才能写入 `cancelledAt` 或绑定实时取消标记。没有元数据的标准 ACP 取消仍保持主动取消行为。在结算提示进入索引字节统计前，丢弃无效输入标识。

## 运行时生命周期

初始化后的 chat 在调用方克隆历史前，将已验证的取消绑定到当前历史数组、长度、最后条目和用户推入计数。替换、截断、追加历史及新输入获准进入历史后使绑定失效。仅刷新启动上下文前缀，或在空闲内存压力清理中清除旧工具结果时，将已验证的结算状态绑定到更新后的历史；这些操作保留被取消的轮次。新 chat 不继承它。初始化回滚不能重新激活已经清除的标记。ACP、daemon 状态和继续接口，以及 headless 继续入口都查询当前 chat。

实时 daemon 取消要求用户取消的 abort 原因，且只绑定一次到最新归属轮次的 chat，要求原会话仍然有效且该轮实际推入过用户内容。压缩创建新 chat 时检查新实例的输入推入计数；发送前取消后直接追加的本轮输入也会被标记。迟到的旧结算或未进入历史便取消的输入不能标记另一轮。既有持久化终态仍写入轮次开始时绑定的 recorder。

## 验证与验收

使用受控本地 provider 和真实构建的 daemon：执行一次 read_file，挂起下一次 provider 响应，主动 Cancel，重启后请求继续。必须拒绝继续且不请求 provider。配对 SIGKILL 对照不持久化终态，仍必须允许继续并正常执行。另检查实时状态、之后相同但未回答的输入、废弃分支、压缩、replay:none/recent/all、相同长度替换、未知或重复标识、历史缺口。

另验证连接关闭和 prompt 超时仍可恢复，直接 ACP 取消仍属主动取消。重试被取消的输入，中断新的尝试，确认旧取消不能抑制恢复；主动取消新的尝试时应抑制恢复，分别覆盖有无压缩。数字类型的异常输入标识不能使索引缓存字节统计变成非有限值。持久化尝试记录写入失败时，恢复执行必须在调用 provider 前停止。

## 风险与剩余工作

缺少权威 daemon 标识的旧转录继续使用既有启发式。此变更覆盖有记录的 daemon 取消，不为旧路径或独立 TUI 取消凭空生成终态来源。模型响应与工具修复语义保持不变。

上述规则带来两处已接受的损失。本变更都不修复，且都在本变更之外跟踪。

`cancelledAt` 被读作用户意图的证明，但本变更之前的构建对每个受控 admission abort 都会写入该字段，因此旧转录中因超时、响应连接关闭或被后续输入取代而结束的轮次，现在会被读成主动取消，其恢复被永久拒绝。区分两者需要在持久化的 `turn_result` 上新增来源字段——这是跨 CLI 与 core 两个包的记录契约变更。

「较新的无标识用户输入」规则在构造上是 fail-open 的。已知四类会产生无标识用户形状条目的来源：带 reminder 的通知（只有裸 task-notification 信封会被裁剪）、cron 或 loop 回显（既不打标识也不裁剪）、被推入的轮次中途插话，以及在丢弃 code-mode 工具结果之后被推入的插话条目。当其中一条落在已取消轮次之后时，查找解析不出输入标识，恢复仍然可用，重启后可能重新提供用户已停止的工作。改为回溯到上一条带标识的条目，则会重新抑制该规则本来要保护的合法新输入，因此方向选择属于产品裁决而非修复。
