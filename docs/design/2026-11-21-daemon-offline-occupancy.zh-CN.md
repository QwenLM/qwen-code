# 离线读取 daemon 连接槽占用

[English](2026-11-21-daemon-offline-occupancy.md) | [简体中文](2026-11-21-daemon-offline-occupancy.zh-CN.md)

## 问题

`qwen daemon status` 读取本地发现记录后，会通过 HTTP 探测 daemon。详情命令还会请求 daemon 状态接口。排查监听器压力时，即使 HTTP 请求无法接通，运维人员也需要知道有多少长连接占用了连接槽。[Issue #18004](https://github.com/QwenLM/qwen-code/issues/18004)

## 命令与输出

`qwen daemon status --offline` 读取发现记录和对应的本地占用快照。命令跳过健康探测。状态显示为 `unchecked`。若进程在读取端可寻址的 PID 命名空间内已退出，则显示为 `stale`。命令拒绝 `--detail` 和 `--prune`，因为这两个选项会发起实时请求或修改文件。

文本输出显示总占用、按连接来源和监听器划分的计数，以及采样时间 `asOf`。`--offline --json` 将相同数据写入 `streamOccupancy`，并包含 `stale` 标记。采样距现在满 15 秒、时间晚于现在，或已知对应的本地进程退出时，快照标记为过期。快照缺失、读不到或格式无效时显示不可用，JSON 中为 `null`。健康状态和采样新鲜度分别判断。

## 发布与生命周期

daemon 写入发现记录后，在同一个私有目录发布带版本号的伴生文件。文件名将快照绑定到发现记录的端口、PID、启动时间及 PID 命名空间。文件包含时间戳和现有进程级占用计数，其中包括占用监听连接槽的 WebSocket。

发布器立即采样，随后每五秒刷新一次。写入使用同目录下权限为 `0600` 的临时文件和原子重命名，异步完成。定时器不会阻止进程退出，前一次写入仍未完成时跳过这次刷新。写入失败时保留上一份可读快照。daemon 的关闭流程会停止定时器，等正在进行的写入结束，再移除文件。这涵盖直接关闭监听器和为更新而重启的情况。异常退出时，发现记录及最后一份快照可能仍留在磁盘上。清除匹配的发现记录或通过它停止 daemon 时，也清除它的伴生文件。复用端口的 daemon 只读写与自身发现记录相符的快照。

## 范围与验证

改动涵盖本地 daemon 发现及命令路径。占用计数与现有 HTTP 状态接口使用同一数据来源。准入和连接恢复由 [#17479](https://github.com/QwenLM/qwen-code/issues/17479) 跟踪。

- 通过打包后的 CLI 观察真实本地流打开和关闭时计数上升和下降，检查文本及 JSON 输出中的计数和采样时间。
- 用回环地址上的服务器统计 TCP 连接和 HTTP 请求。离线 status 的两项计数均为零，普通 status 会请求 `/health`。
- 覆盖过期及缺失的快照、端口复用、记录清理和正常停机。刷新期间读取端得到完整的旧快照或新快照。
- 检查互斥选项在探测和清理前报错以及快照写入失败时 daemon 仍可用。
