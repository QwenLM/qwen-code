# Web Shell navigation rail

[English](web-shell-navigation-rail.md) | [简体中文](web-shell-navigation-rail.zh-CN.md)

## Problem and scope

The current sidebar mixes global navigation with project conversations and turns into a hover-operated session popover when collapsed. Introduce a persistent desktop icon rail and a collapsible Home column, retaining explicit embedded-host controls and backend behavior, with the requested Home-only default for unconfigured hosts. No user avatar, global recent catalog, new navigation framework, or daemon API changes.

## Rail layout and behavior

Home opens the existing brand, New task, pinned sessions and project sections. Hosts without a dedicated Live entry retain their enabled Live group here. Enabled primary navigation entries remain directly accessible in the rail. Its bottom contains only More and the collapse/expand control. In Home-only mode the collapse/expand control stays at the secondary column’s bottom right. When the primary rail exists, it alone owns this control; all secondary columns omit it. More groups settings, theme and other enabled footer actions; version text also lives in More; host custom content retains a wide area in Home. Rail icons use a consistent 17px size and 1.8px outline stroke, with Home using House. Selection preserves the same icon shape and changes only foreground and background colors. Idle icons use neutral gray; hover and selection use the stronger foreground and a subtle rounded background without a hard button border. Home, primary navigation, More and collapse/expand use a shared black, white-text, arrowless Popover without entrance or exit animations on hover and keyboard focus instead of native titles, preserving accessible labels and the scoped portal root. The Home-only fallback Live group uses the Project heading color and an adjacent chevron. Channel and Live column titles share Home’s brand typography: 18px, weight 500, line height 20px. Their bottom borders share Home’s 12px horizontal inset instead of spanning the column. The Project heading chevron and actions appear on hover or keyboard focus, staying visible on touch devices. Workspace and Live session groups retain indentation without vertical tree guides. Live retains its existing capability and showLive gates; this change does not add a new voice-start policy.

With a primary rail, collapse hides the secondary column completely and leaves only the 56px rail. Its expand button or Home click restores the column; hovering does not reopen it. Home-only mode retains main’s existing 56px folded sidebar with brand, New task, hover-session surface and bottom expand control. Clicking Home expands it and returns to the existing chat without creating a session. Except for Channels and Live described below, clicking another navigation icon opens its existing full-width functional page immediately to the right of the rail, replacing the Home column and chat presentation. Forms are not squeezed into a project-width column. In-place MCP, Skills, Agents and Extensions command panels keep Home visible and selected. Browser history returning to chat restores Home (or Live for a Live session URL). Scheduled Tasks and Goals omit their Back buttons when the rail is available; embedded single-column, compact drawer, or hidden-sidebar hosts keep them. Their page headers use the same 46px minimum height, 10px vertical padding and 14px title as Channel settings. Keyboard collapse first moves focus from the secondary column being hidden to the rail expand control. Collapse/expand and Cmd/Ctrl+B change only sidebar visibility, preserving the active page, URL, form drafts and active calls. Explicit page navigation may still unmount page forms, as it already does. Theme and local-file controls remain actions rather than pages.

## Unified Channels section

In rail mode, when source metadata and the existing source switch are enabled and the Channels entry is allowed, Channels opens a 300px session column and the full settings page together. Its header shows only Channels above a bottom border; search remains in the Project toolbar. Clicking the primary Channels icon always reopens the existing full main-area management page while retaining the channel list. The main-page title is Settings. This dedicated rail settings page has no Back button while the rail is visible; compact drawers, single-column and legacy entry points retain it. Opening a channel session returns to chat and retains the Channels selection. Home selects ordinary tasks. Hide the old Tasks/Channels tabs only when their replacement is reachable; single-column hosts and older daemons retain their existing behavior.

Reuse the existing source-filtered session catalogs, WorkspaceSection session rendering and shared row actions. Retain workspace folders and expansion state as Home, together with workspace-qualified loading, search, channel-type grouping, rename, export, pin where supported, delete, archive/restore, errors and capability/permission checks. The channel archive also groups sessions by workspace. Channel settings omits its introductory sentence and repeated workspace summary. Its toolbar places the workspace selector on the left without a visible label (the accessible name remains), followed immediately by a badge labeled “N configured channels” (using the actual count) for the selected workspace; refresh stays on the right. The unconfigured empty state has a border. No configuration counts are added to sidebar folders. Channel settings keeps its existing workspace selection behavior; matching channel names in different workspaces remain separate. Workspace management stays on Home: hide manage/add-workspace controls, workspace row actions and actionable workspace hover details in Channels. Search and session actions remain available. No daemon, Channel-route or generic navigation configuration change. A local Home/Channels/Live section choice survives returning from settings or opening a conversation; the public Channels route continues to mean channel management.

## Dedicated Live section

In rail layout, `showLive` and the existing primary-nav whitelist control the new `live` entry. Live opens its 300px session column and the existing Qwen Live settings card in the main area, with the same 46px header and Back rules as Channels. Both right-side page titles are Settings. The existing Live card uses a single column capped at 768px; labels and inputs align, with one Save button below the form and a red asterisk immediately after the API key label when required (with aria-required), instead of a Required badge. The enabled switch, endpoint, key replacement/removal, model, voice and native shortcut are staged locally. Save submits only changed, supported fields in one existing POST /live/setup request. Native enable confirmation appears at Save; cancellation and request failure retain drafts. Editing a field back to its saved value removes that draft field. If a refresh changes a field underneath an unsaved edit, saving is blocked with an explicit conflict notice; the user can discard the draft and load the latest observed settings before editing again. This client-side check covers observed changes, not atomic concurrent writes or secret replacements with unchanged metadata. Staged key removal remains visible and undoable even after re-enabling. Background status refresh does not disable an already loaded form or its Save button when there is no conflict; initial loading and mutations still block controls. Provider-route models do not submit inactive endpoint/key replacement drafts. Switching to a custom model submits endpoint only if explicitly edited; an untouched endpoint preserves the stored independent configuration, with a preservation hint instead of implying a reset to defaults. Host install/retry and launch remain immediate actions. Selecting a Live conversation opens its existing detail; clicking Live again returns to settings. The column directly lists daemon-owned Live workspace sessions and their existing actions without a collapsible Conversations heading, without ordinary project management or a new archive feature. A settled empty Live list shows a muted inbox icon above the existing no-sessions label, horizontally centered; loading and error behavior stays unchanged. Channels uses MessagesSquare; Live uses AudioLines, both at 17px with a 1.8px stroke.

Reuse the settings card, setup hook, and voice dialog without adding a welcome page or new voice capabilities. Move the existing composer voice trigger into the Live column through a portal; the controller stays mounted so navigation neither starts capture nor interrupts a call. When the secondary column is hidden or the narrow drawer closes, the trigger returns to the composer. Only explicitly activating the voice action uses the current start/connect flow. Existing support and composer action restrictions still apply. When this dedicated entry is available, global Settings omits the duplicate card; single-column, hidden-sidebar, `showLive: false`, and whitelist-excluded hosts keep the original Settings → Experimental card and conversation placement. Unsupported older daemons retain their session list and show an unavailable-settings notice. Add `/live` to the existing route parser, history handling and daemon public-document path list rather than creating a new navigation system. Only exact page GET/HEAD document requests serve public HTML; Live API requests retain authentication in both cold and warm daemons.

Validate route/reload/history, settings relocation and fallback, session selection, collapse/expand, narrow-host Back, no navigation-triggered Live mutation or media capture, and retained voice controls across trigger relocation. Existing voice/settings unit tests cover the unchanged capabilities; mock-browser screenshots show layout only.

## Compatibility and implementation

**Breaking change:** omitting `sidebar` now displays Home instead of hiding the sidebar; omitted item lists now expose only New task/collapse instead of all built-ins. Existing hosts must pass `sidebar: false` to stay hidden, or explicitly populate `primaryNav.items` and `footer.items` to retain their menus. Compact branding is now visible by default; pass `branding.hideWhenCompact: true` to hide it.

Use one automatic layout instead of a public `sidebar.layout` option. Home always exists. When another configured and available primary entry or footer action exists, show the rail; otherwise show only the 300px secondary column. Availability checks include project capabilities, Live opt-in, managed-provider availability and workflow support. Split availability and automatic folding use the shell container width (1024px); room for the split sidebar uses a 1200px container threshold. Unconfigured hosts, `sidebar: true`, and empty options default to Home/New task with only the collapse footer control. `sidebar: false` or `enabled: false` still hides the sidebar. Standalone explicitly configures its existing full primary and footer entries. Hosts opt into other entries through the existing `primaryNav.items` and `footer.items`; omitting their item lists no longer enables every built-in feature. A Home-only sidebar collapses to the existing 56px strip and hover-session popover; with multiple entries collapse leaves only the primary rail, whose expand button or Home click restores Home. All secondary columns omit their own collapse button in this layout.

Keep sidebar.enabled/defaultCollapsed, primaryNav.items/render, footer.items/render, branding, showLive, lockWorkspaceCwd, and host drawer APIs. sidebar:false hides both navigation columns. Host render callbacks retain wide slots in Home. Functional-page selection comes from App's existing activePanel/mainView. A local Home/Channels/Live selection controls the session source without adding a router. Browser history and page callbacks remain authoritative. With URL navigation, only explicit host item lists restrict existing page routes; Home-only menu defaults do not reject Settings, Plugins or Goals URLs. The new Live route still requires an available Live entry.

The stored sidebar width describes the combined rail and Home column; default Home to 300px plus a 56px rail (356px combined), and Home-only presentation to 300px. Previously saved total widths remain authoritative, clamped to an expanded minimum of 220px Home-only or 276px including the 56px rail. Do not unconditionally add 56px to historical values. Resizing and responsive behavior must respect the embedded container, not just window width. When the timeline is hidden in a desktop chat viewport of at least 760px, a separate conversation-search trigger remains available at the top right; compact mobile views retain their existing behavior. On narrow containers Home keeps its logo and brand name by default, including when a desktop collapse preference is stored; explicit branding:false or branding.hideWhenCompact:true still hides it. Use the existing drawer interaction, with both columns inside the drawer; Escape, focus, portals and host containment remain intact. Short rails scroll when primary entries need more room. The More popover reuses existing footer actions and host filters; update polling, the local-files bridge and the desktop relay remain mounted when it closes. The upstream desktop relay remains available in More with its existing authorization and connection lifecycle. Preserve scoped CSS, semantic colors, public variables, React 18/19 and portal-root integration.

Affected areas: WebShellSidebar and its CSS, App layout/wiring, translations, README, focused unit and browser tests. Reuse the existing hover-session surface only in Home-only mode; rail layout hides the secondary column and expands only on click.

## Risks and validation

Main risks are custom host content, constrained widths, page-route selection, collapse persistence, split view, keyboard focus, and Live capability gating. Test default/disabled/custom/locked sidebars, mouse hover versus click, draft retention, browser history, mobile and embedded narrow containers, short-height overflow, dark/light themes, and session operations. Browser screenshots using a mock daemon establish UI behavior only, not real Git/backend operations. Run build, typecheck, focused tests, bundle, browser tests and two clean self-audit passes.

## Acceptance and open questions

Home-only collapse retains its existing 56px folded sidebar and bottom expand control. Rail mode has one collapse/expand control at the primary rail’s bottom and leaves only that 56px rail after collapse. Home or Expand restores the conversation tree; function icons open their corresponding pages. All enabled entries remain reachable directly or through More, and Home never creates a session. Existing host configuration remains valid, and Live remains opt-in for embedded hosts. No open product questions; no PR or publishing is included in this implementation request.
