# Unified cross-platform ComputerUse App workflow

[English](cua-unified-app.md) | [简体中文](cua-unified-app.zh-CN.md)

## Status and scope

Implementation, deterministic native GUI acceptance and all three selected standard AP runs complete, 2026-09-22. Windows raw VLM results have the inherited calibration limitation described below. The user approved a shared App API with short numeric element IDs, automatic window/dialog tracking, internally managed focus switching/restoration, stable observation identities, and one complete skill entrypoint. Verification uses bounded AP jobs on macOS, Linux and Windows. The user subsequently approved this feature PR, including preparation of SDK 0.20.11. Production publication is a separate step. The base includes the separately reviewed SDK 0.20.10 no-Metal capture fix.

## Current gap

Before this change, the shared JavaScript App layer depends on macOS-only native window markers and app projection. Linux/Windows expose exact-window workflows instead. Windows discards revision identity even for budget-only truncation. The skill routes to platform-specific workflows, and deployment documentation omits the Windows UIAccess companion.

## Proposed implementation

Reuse ComputerUseApp for every platform. Normalize application discovery into compact identities, retaining detailed discovery internally. Native adapters resolve the app's active/last-active window and owned modal from OS metadata; they never borrow another application's window. Ambiguous or unsupported targeting fails before input. Re-resolve before every action and invalidate observed IDs/coordinates when the target or runtime generation changes.

Extend the existing app_context input and app-tree-v1 revision projection to Linux/Windows. Native numeric IDs remain bound to retained identities and are not remapped from text rows in JavaScript. Budget-only omissions retain identities and return no_change only for identical captured views; changed bounded views return full, never deletion diffs. Read failures and untrusted fallback backends still invalidate retained identity. Linux transient observations expose snapshot-scoped IDs/tokens; bounded, read-complete Windows UIA observations transfer the native bindings backing their retained IDs.

App input permits foreground preparation internally. Reuse native exact-target dispatch and focus restoration; never replay an action after an uncertain result. Restoration must respect a user's intervening foreground change and report failure without claiming that the action had no effect. App observations continue to capture a current coordinate frame internally and expose images only when requested. A sole minimized window remains selectable; screenshot observation restores it and checks readiness while preserving prior focus. An unowned same-process window taking focus is an uncertain result, rather than evidence that focus was restored.

One canonical computer-use/SKILL.md describes the complete common API and workflow. Its packaged copy must match. Remove the old platform workflow resources and update the stager/tests. Platform-specific unavailable text operations report unsupported_platform and remain documented honestly; no new clipboard implementation or platform worker is introduced merely to match names.

## Architecture and boundaries

The host loads the same native SDK runtime. Windows continues to use its existing signed UIAccess worker over named pipes; macOS uses its existing AX/capture/input backend; Linux uses its existing AT-SPI and X11/Wayland paths. App selection on Wayland uses existing Sway or trusted GNOME foreground metadata. The process-addressed compositor injection route cannot attest an exact App window and is refused before input; legacy exact-window callers retain their existing routing. No new service, protocol, credential store, permission grant or signing trust is introduced. OS focus/permission restrictions remain real failure conditions. The exact-window API remains available for existing programmatic callers; the model-facing skill uses App exclusively.

## Files and compatibility

Changes cover the shared App facade/types, Linux/Windows window resolvers and observation adapters, relevant native input/schema handling, skill staging and guidance, focused native/facade tests and deployment contract docs. Preserve macOS's existing behavior and the underlying closed action-result contract. Windows shortcut commands retain their exact arguments separately from executable aliases; conflicting launchers are not merged into a running PID based on shortcut timestamps. POSIX identity normalization is independent of the Node host and preserves case. Compact listApps becomes consistent across platforms; consumers of detailed Linux/Windows records should use the low-level driver API.

## Verification and acceptance

Record a baseline using the installed CLI/version and the facade reproducer, without claiming it is native GUI proof. Run focused SDK/native tests, builds and typechecks, then two complete self-audit passes. AP validation must prove the candidate native/JS/skill hashes in the actual worker, App numeric-ID actions, modal transitions, stable IDs, focus restoration and valid agent/evaluator completion. Keep job and attempt lineage, pin model/pipeline/judge/media settings, archive metrics and traces. Infrastructure-invalid attempts and reproduced SDK defects may be retried after a minimal repair with preserved lineage; valid low scores are not rerun. Each platform receives a bounded smoke case first; no full benchmark group is implied.

## Risks and remaining decisions

Native app identity is platform-specific, especially multi-process Windows applications and Linux compositor restrictions. Do not infer success from a shared schema or a mocked facade. API and native adapters must be verified together. The candidate artifacts and one standard AP case per platform are frozen and submitted. Deterministic native GUI checks passed on macOS, Windows and Linux X11. A standard Linux run then exposed ImageMagick hanging while capturing a destroyed window and holding the X server. The fallback now drains output concurrently, applies a five-second deadline, and kills/reaps its child before returning. A real X11 regression verifies server recovery and a subsequent successful screenshot; the final fixed Linux artifact completed validation as attempt4 of the same job. The same GTK menu object can also appear under both the main frame and a popup frame. Window-targeted pointer lookup now resolves native identity within the already-correlated frame; unscoped ambiguity refusal and application-wide legacy indices remain unchanged. A real GTK regression verifies numeric selection changes Alpha to Beta, unknown-window refusal, and within-frame ambiguity rejection. A popup grab can still prevent foreground restoration; that remains an explicit uncertain result requiring reobservation. All three agents/pipelines exited normally with code0: macOS57/57 AX and7/7 VLM; Linux48/51 programmatic and1/1 VLM; Windows68/79 programmatic and raw54/69 VLM. Linux failures are generated-application behaviors, with no new confirmed SDK defect or score retry. The fixed Windows worker replaced the legacy62-item VLM list with all69 schema-v2 assertions, reintroducing seven baseline-failed items (four passed and three failed here); retain raw54/69 with this calibration limitation and no retrospective denominator change. A separate review regression now verifies same-process App window selection on an isolated native Sway desktop. Broader Wayland input/observation coverage and the full benchmark remain unverified; these three cases do not establish full-score recovery. Full run identities and evidence are tracked in `.qwen/e2e-tests/cua-unified-app.md`.
