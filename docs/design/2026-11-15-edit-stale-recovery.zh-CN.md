# Edit 返回与自动过期恢复

[English](2026-11-15-edit-stale-recovery.md) | [简体中文](2026-11-15-edit-stale-recovery.zh-CN.md)

## 目标与范围

自动恢复保持默认开启，不增加真人确认。普通 Edit 成功返回省略模型已提供的文本。
用户修改的替换内容和恢复编辑通过有界片段返回新信息，UI 继续展示 diff。
确认编辑器提供的整文件替换不能在返回中被完整回显。

## 目标语义与授权

恢复操作替换 **当前文件** 中 `old_string` 唯一的字面精确匹配，并保留替换范围之外的内容。
它不证明当前匹配仍是先前 Read 所见的语义位置。若外部重写将唯一匹配移入另一个函数，
当前这个匹配就是替换目标。调用方应提供足以表达目标的上下文；两行阈值和固定偏移都不能
证明位置延续。这是保留默认自动恢复的明确取舍，适用于 AUTO_EDIT/YOLO 和非交互执行。
确认警告和返回片段用于说明事件，既不是授权边界，也不是旧语义位置的证明。

现有文件仍需会话内先前文本读取证据。恢复只用于非空、非 no-op 的单次文本替换，并要求
生产默认读取规则和权限管理器均允许自动读取。它遵循规范化后的工作区、受管记忆目录、
已授权运行目录、忽略规则、显式 ask/deny 规则，以及 scoped I/O 排除条件。显式 allow
规则不会扩大原本不能自动读取的默认目录范围。恢复不采用空白、引号或 Unicode 模糊匹配。
零匹配、多匹配、no-op 和不支持的情况均返回 `FILE_CHANGED_SINCE_READ`，不会通过不同的
内容派生错误泄露未读内容。

## 指纹、Read 基线与快照

`FileReadCache` 将两个事实分开记录：

- inode、mtime 和 size 指纹描述最新磁盘状态。
- `readBaselineNeedsRefresh` 表示恢复保留了尚未通过成功文本 Read 刷新的外部内容。

恢复写入记录写后指纹并显式传递基线标记，原子替换产生新 inode 时也不例外。同时关闭
完整读取的历史驻留资格。后续 Edit 即使磁盘指纹 fresh，仍执行恢复授权、精确匹配和
快照检查。WriteFile 必须等成功文本 Read 刷新基线后才能执行。部分或截断文本读取仍按
现有 prior-read 合同认可；要求完整 Read 会重新引入 #3945 / #4002 的大文件死锁。
Edit 准备期间内部读取磁盘不调用 `recordRead`，不能清除标记。ReadFile、附加文本和
注入的记忆保留既有 `recordRead` 语义。Grep 和 RipGrep 保留普通 prior-read 资格，
但搜索片段不清除恢复后的待刷新基线；仍需实际文本 Read。
部分 Read 清除基线标记，但不虚构整文件历史驻留；紧随其后的完整 Read 返回真实内容，
而不是占位符。普通写入保留原有读资格行为。用户手工修改的 Edit 关闭整文件历史驻留
资格，因为有界结果可能省略用户修改的内容。部分 Read 不重新开启该资格；完整 Read
必须先返回真实内容，后续 Read 才能使用占位符。

Shell 工具模拟执行的 `sed -i` 编辑同样等待一次成功文本 Read。它对当前文件执行正则
替换并写入完整结果，不使用 Edit 的唯一字面目标恢复合同。指纹 fresh 但基线待刷新时，
错误说明恢复后需要 Read，不再声称 mtime 或 size 已变化。实际漂移保留漂移提示；
冻结快照不匹配则明确指出准备时的快照，即使缓存 fresh 也仍返回
`FILE_CHANGED_SINCE_READ`。

恢复决定捕获 dev/inode/mtime/size 快照。读后、确认及写前检查必须匹配该快照。
传入 `expectedStaleSnapshot` 本身会允许匹配的恢复继续执行，即使未传 `allowStaleRecovery`；
调用方只能传递经过授权后捕获的快照。并发 Read 令缓存变为 fresh 也不会替换冻结快照。
文件随后变更或被删除仍须拒绝。快照只保护准备至写入区间，不保证旧 Read 的语义目标延续。
stat 至 write 的竞态，以及相同 mtime/size 的碰撞，仍是指纹检查的局限；本改动不引入锁或
内容哈希。

## 返回与诊断

普通编辑和新建文件只返回简短确认。用户修改保留修改说明，不再插入可能包含整文件的
`new_string`。用户修改和恢复结果在现有行数上限及 8,000 字符上限允许时展示编辑片段，
否则提示 Read。恢复结果说明 WriteFile 需要 Read，后续 Edit 仍执行恢复检查。
既有确认 UI 收到信息性警告，不增加确认对话框。仅在恢复写入成功后记录一次 debug 事件，
准备阶段不会记录成功事件。

## 验证与验收

- Read 后外改，再连续自动 Edit：每次成功且执行恢复检查，并保留目标之外的外部内容。
  基于旧内容的整文件覆盖被拒绝；实际完整或部分文本 Read 后允许 WriteFile。
- 以原子 inode 替换重复流程，基线标记必须保留。
- fresh 指纹的恢复仍拒绝 `replace_all`、no-op、模糊或多处目标，以及后来收紧的读取权限。
- 通过生产权限规则验证规范化工作区、运行目录、记忆目录、忽略或私有路径、权限 ask/deny
  和 scoped I/O。
- 在快照 S 确认，外部写入 F2，并在 F2 刷新缓存后执行：F2 不被覆盖。无漂移重读 S 则仍
  允许已捕获编辑。确认后删除仍返回文件过期错误。
- 用户修改产生的整文件参数及很长的单行替换均不能导致无界回显。普通 Edit 结果保持精简。
- hot restore 和 cold resume 保留原工具调用参数、唯一配对结果、实际磁盘内容和裁剪后的
  历史，不依赖成功片段。断言在 Node+Ink、Bun+Ink 和 Bun+OpenTUI 上运行。

回归测试定义当前行为；确定性回放结果不代表真实模型延迟、token 收益或生产恢复触发率。
