# Web Shell 侧栏按父子关系展示派生会话

[English](web-shell-sidebar-session-tree.md) | [简体中文](web-shell-sidebar-session-tree.zh-CN.md)

## 问题与现状

会话可以通过 `create_sub_session` 派生新会话（`agent` 工具的后台路径、side
task、隔离的定时任务派发）。每个派生会话都是一个完整的顶层会话：拥有自己的转录、
出现在 daemon 的会话列表中，并在 `parentSessionId` 中记录派生者。嵌套被限制为一级，
因此族谱始终是一棵两层树。

侧栏没有呈现这层关系，三个区域的现状各不相同：

| 区域                  | 派生会话 | 形态                                               |
| --------------------- | -------- | -------------------------------------------------- |
| 项目/工作区列表       | 显示     | 与父会话平铺混排                                   |
| 分组视图（organized） | 显示     | 平铺，`groupId: null` 归入「未分组」               |
| 最近会话              | 隐藏     | `sortRecentSessions` 跳过带 `parentSessionId` 的行 |

针对运行中的 daemon（`/Users/wenshao/git/qwen-code`，396 个持久化会话）实测：
一个父会话下有 8 个派生会话（`🧵 codex-tools`、`🧵 codex-ide-research` 等），
它们作为 8 个兄弟行渲染。父会话的标题无法提示这些行是它的子会话；而一旦派生会话
集中出现，还会把无关会话挤出五行预览（`SIDEBAR_SESSION_PREVIEW_LIMIT`）。

## 目标

- 在工作区列表中把派生会话挂在父会话之下，缩进一级，默认收起。
- 父行自身的操作（打开、重命名、固定、归档、删除）保持不变。
- 收起的子会话不再占用十行预览配额。

## 范围边界

范围内：侧栏渲染的全部会话列表——由 `WebShellSidebar` 自行渲染的主工作区列表及其分组视图，
以及由 `WorkspaceSection` 渲染的二级工作区列表，含其分组视图（「未分组」）与渠道会话分组。

范围外：最近会话区（它刻意排除派生会话）、固定区（固定行是独立引用，不是树节点）、
归档区、standalone 会话列表。本次改动不给它们加树，派生会话在这些区域维持现状。
不需要 daemon、SDK、存储或协议改动：列表响应已携带 `parentSessionId`，本设计也不使用
父过滤参数 `?parentSessionId=`。

## 方案

在渲染层、用侧栏已持有的分页数据建树。

新增纯函数模块 `sessionTree.ts`，输入一页会话数组与「已展开的父会话 id 集合」，
输出渲染序列：

- 不带 `parentSessionId` 的行是深度 0 的根。
- `parentSessionId` 命中同页某个根时，该行成为深度 1 的子行；仅在父展开时出现。
- 深度最大为 1；daemon 拒绝嵌套派生，因此不存在更深的父 id。
- 子行紧跟其父行，根之间保持原有的活动时间顺序。

父行增加展开箭头，其无障碍标签携带「当前页内已知的子会话数」。点击只切换该父会话；
状态按「工作区 + 父会话 id」持久化，重渲染与刷新后仍然有效。

截断与计数跟随树而非原始分页：预览上限与各分组标题的计数都按渲染行计算，因此收起的
父会话算一行，其隐藏的子会话算零行。

只有一种情况退回平铺行：父会话根本不在列表中——已归档而离开活动页、被固定到固定区、
被分到另一个分组，或不在已加载页内。此时子会话保留自己的行，因为侧栏其它列表不会显示它：
归档查询只返回已归档会话，最近会话区排除派生会话。隐藏它会让一个仍然存在的会话无法从
侧栏打开。

搜索会强制展开命中的父会话：子会话命中而父会话也在过滤结果中时，无论持久化的展开状态
如何都展示其子行，保证命中行不会藏在收起的父行后面。

## 设计决策与理由

**在渲染层建树，不改 daemon。** 分页数据已携带族谱字段，daemon 的列表契约在每条路径
上都暴露它。服务端增加聚合会为纯视觉分组重复实现分页、排序与 live 合并规则。

**按页建树，不做按需拉取。** 派生会话通常比其派生者更新，父会话因此多半就在已加载的
预览范围内。按父逐个请求会让一个每十秒轮询的列表多出每行一次请求。按页建树的代价即上文
的无锚点情形，已用回退规则显式说明。

**只做一层，因为 daemon 只允许一层。** `create-sub-session` 会拒绝「调用者本身已有父
会话」的派生请求（"nesting is capped at one level"），因此不需要递归渲染路径。

**默认收起。** 派生会话往往成批出现（实测一次 8 个）。默认展开等于用缩进的形式重现
今天的问题。

## 风险与约束

- 父行上的子会话数只反映已加载页。若父会话有更早的子会话落在页外，数字会小于转录中的
  实际数量。这是可接受的：计数标注的是「该行展开后能看到多少」。
- `SessionGroupSection` 通过 `Children.toArray` 做截断，因此收起的树不能把隐藏子行作为
  元素产出。本设计只产出实际渲染的行。
- `view=organized` 会拒绝 `parentSessionId`（HTTP 400），这也是本设计不做独立子会话
  拉取的原因之一。
- 归档父会话不会连带归档子会话。已归档的父会话离开活动页，其仍未归档的子会话在该列表
  退回平铺行，仍然可以打开；归档区只包含已归档会话，因此不会显示它。
- 未受信任的二级工作区保持只读平铺列表：这些行走独立渲染路径，没有悬停操作，也没有箭头。

## 验证计划

纯函数模块的定向单元测试覆盖：无族谱的平铺输入、父子归组、展开与收起、默认列表中的
无锚点子会话、搜索态下的无锚点子会话、分组归属分裂、行数对截断的影响。组件测试覆盖
箭头渲染、缩进、无障碍标签，以及父行自身操作仍然可用。

浏览器验证针对本地 `qwen serve` 使用实测工作区：改动前 8 个 `🧵 ...` 行与其父会话
并列；改动后父会话显示一个箭头、8 个子会话收起，展开后显示 8 个缩进行。E2E 计划与
结果存放在 `.qwen/e2e-tests/`。

## 验收标准

- 派生会话在工作区列表、分组视图、渠道分组中都不再与其父会话并列为兄弟行。
- 收起的父会话只占一个预览位；其后代不消耗预览上限。
- 展开父会话后，只显示已加载页内存在的子会话，缩进一级，按活动时间排序。
- 仅命中子会话的内容搜索仍能看到该子会话。
- 只归档父会话后，其仍未归档的子会话仍可从侧栏列表打开。
- 最近会话、固定区、归档区维持现有行为。
