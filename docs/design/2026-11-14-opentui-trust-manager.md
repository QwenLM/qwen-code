## Status and problem

Implementation in progress. Root global baseline63028 passed (42.131s, two natural exits, zero model HTTP); strictNative49702 failed at initial-options (32.933s), showing only the read-only placeholder. Its cleanup grace error/signal9 remain a failure, not a natural exit. Before this increment, `/trust` dispatch reached `OpenTuiTrustDialog`, which displays a yes/no value and Escape. Ink `TrustDialog` supports three persisted decisions and restart. The existing startup `OpenTuiFolderTrustGate` is a separate undecided-workspace gate; it does not close this command gap.

## Scope and behavior

Implement the complete command: display captured folder, current explicit level, inherited parent/IDE explanation; select Trust this folder, Trust parent folder or Don't trust using existing native list keys. Use the existing CLI trust evaluator and writer unchanged. Effective trust unchanged means persist immediately and close after success. Effective trust changed means retain only a pending choice, show the existing restart explanation and accept `r` to commit then invoke the real `relaunchApp`. Escape discards pending choice and closes without writing. A superseding choice clears the older pending choice before its write attempt. Failed reads/writes show a truthful error and do not close or restart. Parent/IDE trust that remains effective produces the existing warning. Folder-trust-disabled behavior follows the same policy evaluator.

This does not mutate Config trust in memory, grant approval, alter startup policy, delete inherited rules or make trust changes effective without restart. No Core API, new storage or generic ownership framework.

The native frame contains one real scroll region sized from the supplied popup height, leaving the existing four border/padding rows. All body text is constrained to the actual content width minus the scrollbar column, so the bar cannot cover folder or hint characters. Choice labels additionally reserve indicator/numeric columns and wrap without single-line clipping. Highlight changes and actual scrollbox size changes mark one pending focus reveal. A local public renderAfter hook consumes that marker after the native root has calculated layout and updated all descendant coordinates, then calls the existing scrollChildIntoView API; any resulting movement paints on the requested next frame. A label onSizeChange callback is not used: TextBufferRenderable overrides resize without calling that base callback. PageUp/PageDown and mouse scrolling expose the full folder, inherited notes and pending/error text. Ordinary rerenders and user scrolling do not force focus-follow again. This is a Trust-local layout change, not a shared dialog behavior change.

## Minimal reuse and ownership

Replace the placeholder with a collocated native component and tests; keep existing command and route. Reuse `TrustLevel`, `loadTrustedFolders`, `isWorkspaceTrusted(settings.merged, previewConfig, capturedWorkspace)` and `relaunchApp`; reuse native DialogSelect/frame primitives and existing host history for errors/warnings. Port only the small state transition from `useTrustModify`, not its ambient `useSettings`/`process.cwd` inputs. Keep Ink and startup gate production untouched. Current `isWorkspaceTrusted` accepts an explicit workspace and delegates to `getWorkspaceTrustStatus`, including scoped IDE trust; do not infer IDE trust from the primary cwd or bypass the policy evaluator.

The mount supplies explicit selected Config/settings/host. Capture Config identity, settings identity, session ID and canonical workspace from Config, plus the actual resolved `settings.workspace.path` and request generation. Capture that settings path unchanged; do not require a synthetic cwd-local settings file when the existing loader resolved a legitimate ancestor. Verify host.config/settings agree and current getters still match before preview, synchronous durable write, error publication, close and restart. Close/unmount or observed replacement permanently invalidates that generation; A→B→A cannot revive old callbacks. A genuinely new mount may act again. Do not fingerprint the whole trust file as owner identity: the authorized write itself changes it, and the existing writer merges fresh disk data under its own lock. No atomic external-FS replacement guarantee is claimed.

A process restart must relaunch the process actually owning this selected live runtime. Validate launch workspace/selected workspace agreement and ownership immediately before commit/relaunch; an unsupported or mismatched selected runtime reports an explicit error, never quits/restarts a primary runtime as fallback. The existing `onRestartRequest` callback is ordinary quit, not trust relaunch, so must not be substituted. The restart owner decision is checked immediately before entering this process-wide, irreversible cleanup; the existing function has no post-cleanup ownership callback, so do not claim one. Preserve existing error handling and await cleanup in `relaunchApp`; do not add flags or force a no-relaunch path.

The shared CLI relaunch entry now calls the existing public `prepareFileWatchersForProcessExit` before any `runExitCleanup`. This restores the process-exit preparation invariant already used by quit: every production caller of relaunchApp proceeds to process exit or re-exec. The five consumers are native FolderTrustGate/TrustDialog and Ink IdeTrustChangeDialog/FolderTrustDialog/TrustDialog. Their files, Core implementation, cleanup deadlines, r ownership, exec flags and restart mechanism are unchanged. relaunchForUpdate and client shutdown are outside this addition.

## Limits

Only the native CLI Trust route and the shared CLI relaunch preparation change. Existing CLI config policy functions are consumers, not modification targets; any required shared config change needs separate maintainer triage. Windows/relaunch platform qualification, native device/voice/IME gates, same-final-main packaging, default switch and Ink removal approvals remain independent. No prior Skills initialization failure is declared fixed by this work.
