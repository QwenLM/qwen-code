# 显式替换 Agent Host

[English](agent-host-replacement.md) | [简体中文](agent-host-replacement.zh-CN.md)

## 契约

普通注册继续追加独立身份。名称和工作目录由 Host 提供，不能证明两台机器具有相同身份。操作者选中已有 Host，生成有效期为 15 分钟、一次性的注册能力；`supersedesHostId` 只保存在该工作区的注册记录中。注册请求不能另选替换目标。

## 生命周期

替换成功后生成新的 Host ID 和凭证，将所有 managed-host Agent 的旧 Host 绑定迁移到新 ID，保留执行程序和其他 Host，并撤销旧凭证。旧的 running 和 cancelling 任务以 `agent_host_removed` 失败，之后可显式重试；已经 finishing 的任务保留完成结果。旧凭证和迟到结果被拒绝。排队任务继续绑定远程执行。

## 信任与持久化

注册能力通过选中且受信任的工作区的鉴权修改路由生成。注册和心跳只使用已解析的工作区，不回退到主运行时。不存在或已移除的目标、无效或过期令牌及重放均拒绝。独立的同名 Host 不受影响。

工作区锁串行化注册、绑定迁移和任务结算。现有存储文件分别提交，不具备回滚。迁移前，注册表暂存新 Host，并在能力记录中保存 `replacementHostId`。写入失败后，重试同一能力复用该身份，并采用重试的 Host 提出的凭证；旧版 Host 不提出凭证时由 coordinator 生成；只有迁移和结算完成才撤销旧凭证。暂存的替换可刷新自己的链接，但普通注册和移除 Host 不能覆盖它。磁盘故障可能在重试成功前暂时显示两条记录；未完整执行的替换不会返回成功。

暂存替换持久保留，有意超过注册链接的 15 分钟有效期。过期后拒绝该命令，但不会取消事务或回滚已迁移的绑定。恢复错误明确指出原 Host 的名称和 ID：在 Runtime 列表选中它，点击替换，生成新命令，再到替换主机上运行。刷新时轮换能力令牌并保留暂存 Host ID，旧命令仍然无效。对话框明确显示正在恢复替换，并在链接过期后提供刷新命令。恢复完成前不能移除原 Host 或暂存 Host；其他 Host 的移除不受影响。不提供自动过期清理或放弃/回滚操作。

## 注册凭证

Host 在注册之前先生成凭证，连同发送它时所用令牌的哈希，保存在凭证文件旁的 `key.enrolling.json` 里，再随令牌一起发送。coordinator 照旧只保存它的哈希；只有不发送凭证的旧版 Host，才由 coordinator 生成。令牌在同一步被用掉。所以 Host 如果收不到答复（超时、连接断开、守护进程停止、凭证保存失败），原本会留下一个已注册、却没有人持有凭证的身份。

重试时，Host 再次发送保存好的凭证，用同一个令牌或新令牌都可以。coordinator 按已完成的那次注册作答：同一个 Host ID，不会多出第二个 Host；新令牌不会被用掉，在过期之前一直有效。这个答复会把该 Host 的 ID 和公开记录交给持有它凭证的一方，而凭证加上这个 ID 本来就能以该 Host 身份认证。已持有凭证的 Host 在执行替换时如果收不到答复，用同一条命令就能完成：这条命令的令牌被拒、而凭证仍然有效时，它会发送曾随这个令牌发出的那份凭证。只随其他命令发出过的凭证，不会经这条路径使用。例外：

- 以该身份暂存的替换，只能通过它自己的注册能力作答，由此完成绑定迁移。
- 带着某个已注册 Host 所持凭证的替换（以它的注册能力令牌为准，过期与否都算）会被拒绝（409），它的注册能力不会被用掉。按那个 Host 作答会跳过替换，照常完成又会让两个 Host 持有同一份凭证。Host 随后生成新凭证、再次发送替换，用自己的身份完成替换。那份凭证注册出的 Host 仍留在列表里，处于离线状态；如果它正是被替换的 Host，则会被移除。如果这次重试被明确拒绝（注册能力已过期，或要替换的 Host 已不存在），说明替换什么也没做，Host 会把原来的凭证放回去，除非期间另一次注册已经存入了新的凭证。如果这次重试没有得到明确答复（忙、连接断开或被停止），原来的凭证不会保留，它注册出的 Host 留在列表里、处于离线状态，与替换已完成时一样。
- coordinator 已不再持有的替换令牌（已刷新、已被取代或已用过）不会被认作替换令牌。它带着已注册的凭证发来时，会按那个 Host 作答，替换不会执行；运行当前的替换命令才能完成。

如果一条命令第一次运行时拿到了凭证（完成了注册，或用已保存的凭证重新加入），但随后没能连上（例如首次心跳遇到存储繁忙），再次运行这条命令时会沿用这份凭证继续。凭证文件记录了注册时所用令牌的哈希，或最近一次重新加入所用令牌的哈希；只有 coordinator 对这次注册或重新加入的应答到达之后才会记录。重新加入的应答如果丢失（令牌在 Host 收到应答前已被用掉），就不会有记录，重跑照旧被拒。重跑时如果 coordinator 拒绝所记录的令牌，重跑得到的就是第一次运行得到的结果；这条记录先于任何已保存的注册凭证检查，因此旧版 coordinator 注册时留下的凭证不会让已用掉的令牌再被发送一次。第一次仍在进行时向同一个守护进程再次发起同一次加入，会等待它完成，而不是将它打断。其他被拒的令牌照旧报错，因此第一次运行什么都没得到的命令（例如被明确拒绝的替换）不会被报告为完成。重新加入时如果无法把这条记录写回已有的 `key.v2.json`，连接照样启动，只是之后重跑这条命令会像以前一样被拒；这期间被移除的凭证文件不会被写回。持有旧名凭证文件（`key.json`）的重新加入，会连同这条记录把它保存为 `key.v2.json`，这次保存必须成功，和以前一样。旧版本保存的凭证文件没有记录令牌，它对应的命令照旧被拒。

这个文件只在可能对应一次注册时保留：

- 凭证文件已持有它时，Host 会删掉这个文件。
- coordinator 明确拒绝注册时（令牌无效或已过期，或 store 拒绝了请求）也会删掉。这时它没有注册出任何东西；如果注册出了暂存的替换，那次替换会通过自己的注册能力，用新凭证完成。
- coordinator 无法完成注册时（忙或出错，返回 503），无法判断此前的尝试有没有成功，所以文件保留。
- 凭证被撤销时也会删掉，而且先于凭证文件删除，除非文件里是另一份凭证；读不出来的文件也一并删掉。撤销后再拿它注册，被撤销的凭证就会复活。文件删不掉时保留凭证文件，留给下一次尝试。如果某个 Host 在本机保存凭证之前就被 coordinator 移除，本机察觉不到这次撤销，它的凭证可能被再次注册。这样注册出的是一个新 Host，而不是被移除的那个：coordinator 只保存凭证的哈希，也没有其他 Host 持有它。
- 文件读不出来，或者不是本版本写下的，就在用掉令牌之前停止注册，不会把它覆盖掉。
- 已保存的凭证所持有的那份不会被再次使用。

## 客户端与 UI

相同工作目录中保存的旧凭证使用替换能力时，收到明确的 409 注册握手；普通心跳不能消费替换能力。新版客户端读取旧凭证以保留身份，并将凭证保存为 `key.v2.json`。旧版客户端只能删除原有的 `key.json`，因此混合版本替换不会删除新凭证。新版凭证写入和有条件的撤销清理还共用跨进程文件锁。写入在锁内比较原有身份，迟到的启动不能覆盖新凭证，未变更的 v2 凭证不会重写，只有为记录重新加入所用掉的令牌时例外。使用已保存身份完成替换需要新版 Host 客户端；普通注册和重新加入保持兼容。UI 在选中的外部运行时上提供替换入口，说明后果并复用现有加入命令。只有旧记录消失且新的在线身份出现，才显示替换成功。刷新恢复链接时返回暂存的 `replacementHostId`，使 UI 能够识别已显示为离线的该身份。远程连接快捷方式和其他协作架构不在本次范围内。

## 验收

验证普通独立注册、选中目标替换、凭证撤销、Agent 绑定迁移、running/finishing 结算、迟到结果拒绝、令牌一次性与工作区隔离、绑定写入失败后重试、同目录加入和凭证保护清理。在真实 coordinator 和 Host 上，通过 Web Shell 验证完整选中 Host 流程，提供无敏感信息截图和 tmux capture。受控 provider 证据与真实模型证据分别标注。全部实现完成后，集中执行构建、类型检查、针对性回归及一次完整审查。
