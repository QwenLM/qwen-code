# Managed runtime 0.26.3 测试修复

[English](managed-runtime-0263-test-repair.md) | [简体中文](managed-runtime-0263-test-repair.zh-CN.md)

## 问题与范围

CLI 0.26.3 已发布成功。独立的 Managed runtime 发布在
`Issue13180HardenedVerificationTest` 中失败：未指定 Bean 的 `JdbcTemplate`
将字符串标识绑定到 `VARBINARY` 列，H2 拒绝这种比较。生产存储层使用
`managedJdbcTemplate`，会将这些标识绑定为字节。

修复让测试使用同一个 Bean，保留匿名用户、越权用户和所有者的全部断言，不修改
生产代码或数据库结构。

## 恢复现有标签的发布

Managed runtime 工作流检出已发布的精确标签。因此，重跑旧工作流无法获取 main
上的修复。此变更合入后，从 main 手动触发工作流，传入 `tag=v0.26.3` 和
`dry_run=false`。

补丁随工作流锁定的工具版本入库，仅修改受影响的 Java 测试，仅用于 `v0.26.3`，
且要求源码提交为 `eeee1443a7e36ab22b2f1dcded8dec64b621a7ee`。该步骤要求受跟踪
的检出内容干净，验证补丁只包含指定文件，检查补丁可应用，并核对最终变更文件列表。
输入不符合预期时，在构建前终止。

完整 SDK 和服务端验证命令保持不变。发布仍校验不可变标签及已有产物的字节，只添加
缺失产物，并验证 GitHub 和 OSS 下载。原标签、生产源码、CLI 版本和已有产物都不
重写。其他版本不应用此补丁。这是单个版本的修复，不引入通用覆盖接口。

## 验证与验收

- CI 必须执行原有归属验证测试，保留原有断言。
- 工作流回归覆盖必须能对原测试应用补丁，得到修复后的测试，并保持生产文件样本不变。
- 错误的源码提交及指向生产文件的补丁必须被拒绝。
- 合入后的手动发布必须通过完整 Maven 检查，将缺失的 0.26.3 runtime JAR 和校验和
  发布到两个现有渠道。

本任务不运行本地测试或构建。静态审查不代表运行验收，证据由 PR 和后续发布 CI
提供。在此之前，Managed runtime 补发仍未完成。应保留该恢复步骤，以便重复执行
0.26.3 发布；后续修改该步骤仍需审查。
