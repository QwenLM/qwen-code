# 输入区添加菜单展示

[English](composer-add-menu-icons.md) | [简体中文](composer-add-menu-icons.zh-CN.md)

## 问题与范围

Issue [#16155](https://github.com/QwenLM/qwen-code/issues/16155) 指出输入区添加菜单的
展示不一致。用户提供了视觉参考，要求带底框的图标、更清晰的文字层级和紧凑的排版。
保留现有菜单背景和边框。计划模式与其他操作保持相同的视觉权重。操作顺序、可用性、焦点
行为和以确认状态为准的模式切换保持不变。

## 设计

在 `packages/web-shell/client/components/composer/AddMenu.tsx` 中复用
`lucide-react` 和现有下拉菜单及按钮原语。添加文件使用 Paperclip，引用文件使用
FileText，扩展使用 Blocks，MCP 使用 Plug，技能使用 Sparkles。后三项与工作区菜单的
现有图标保持一致。移动端抽屉的对应入口使用相同图标；独立的照片、相机和上传操作分别
使用 Image、Camera 和 Upload。

为五个桌面入口及移动端对应的引用入口添加简短的中英文说明。扩展和 MCP 的说明必须描述
为引用操作，不能表述为管理或连接操作。保持无障碍标签稳定，并提供无障碍辅助说明。
操作标题和辅助说明均使用常规字重。

扩展和 MCP 子菜单中的条目描述只显示一行，超出宽度时显示省略号。原生 title 保留完整文本。

保留现有下拉菜单、抽屉和按钮原语。新增小型私有 CSS Module，负责图标底框、文字层级、
条目间距和响应式菜单宽度。采用 32px 图标底框、52px 最小行高和不超过视口宽度的 320px
菜单，保持紧凑。移除技能上方的分隔线，剩余分隔线向内缩进，与图标底框对齐。菜单背景、
边框、阴影和 portal 集成继续由现有原语提供。使用现有语义颜色 token，不新增主题、依赖或
公共 API。删除共享样式表中过时的计划模式图标
容器规则，不对共享样式作其他视觉重做。

使用装饰性的开关形状指示计划模式的已确认状态。整行仍是唯一交互控件：桌面保留菜单
复选项语义，移动端保留按下态按钮语义。不嵌套新的按钮或开关，不引入乐观状态，也不对
该行设置特别的强调色或背景。
强制颜色模式下使用 Canvas/CanvasText 系统颜色和可见的轮廓线，保证圆点可见，并通过圆点
位置区分开启和关闭状态。

## 使用方与约束

共享输入区服务于桌面浏览器、移动端，以及 VS Code 伴生扩展等嵌入宿主。下拉菜单与抽屉
两条路径都必须保留现有操作及键盘或触摸行为。窄浏览器窗口的覆盖不能证明 VS Code
宿主本身正常，验证结果需明确区分。

## 验证与验收

- 运行 AddMenu 和 ChatEditor 单元测试及有针对性的输入区浏览器测试，确认文案、文件
  选择、引用、技能和计划模式仍正常。检查计划模式的开启、关闭、忙碌状态及通过指示器触发操作。
- 使用现有模拟 daemon 捕获并检查深色、浅色菜单和移动端抽屉的实际截图。证据须标注
  为模拟后端的 UI 验证，不代表真实 daemon 或 Git 操作验证。
- 检查桌面与窄窗口下的前置图标、文字对齐及菜单无溢出。运行仓库构建与类型检查。
- 同步更新组件、私有样式、两种语言文案、受影响测试和两份设计文档。本地验证产物保存到
  `.qwen/e2e-tests/`。

当前版本没有待定问题。本次参考附图的内部组织方式，保留现有菜单背景和边框，不突出计划模式。
