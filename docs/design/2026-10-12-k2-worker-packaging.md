# K2 private worker artifact packaging

[English](2026-10-12-k2-worker-packaging.md) | [简体中文](2026-10-12-k2-worker-packaging.zh-CN.md)

Status: implementation candidate. The original ACK worker's complete image digest, command and loader manifest are unavailable. Its narrative acceptance does not qualify a replacement. This design supplies new reviewable build inputs; it does not publish or install them, qualify confinement or enable physical release.

The private provisioner accepts a pinned image and base command, then appends `managed-runtime-worker --container-boot /var/run/qwen-runtime/boot.json`. Build one ESM bundle from the existing production attestation worker. Its entry accepts exactly those arguments and delegates boot validation to the production worker. It adds no routes or tools. The existing boot capability still selects the file-only composition. The bundle embeds its actual WASM dependencies, supplies the Node ESM/CommonJS bridge and rejects unsupported asset loaders or build warnings. Every file's actual supplied bytes and final readback are pinned. The compiler output and complete metadata are retained; a successful build is not startup acceptance.

Use the official Node 22 bookworm-slim image only after reading and pinning its actual selected Linux architecture manifest, configuration and full layers. The tag is a discovery input. Verify each descriptor's bytes/digest and every uncompressed layer diff ID before composing the candidate. An anonymous registry pull must not persist or print its token. Do not execute or extract downloaded archives as part of packaging. The new worker layer contains only `/opt/qwen-k2/worker.mjs`, owned by root and read-only. Clear inherited launch/environment configuration and set the fixed Node command, non-root image user and private worker arguments. The production Pod additionally enforces its existing UID/GID, capability drop, read-only root, boot volume and file-only contract. Image defaults do not replace admitted-spec or kernel checks.

`deploy/k2-evidence/build-worker.mjs` builds the exact bundle and input manifest. `package-worker.py` composes it with a separately verified base OCI layout into a new directory. Both refuse overwrite; incomplete attempts remain explicit. Package outputs include the complete manifest/configuration/layers and provenance digests, with no credentials or boot payload. The base includes ordinary binaries, but the reviewed worker policy must allow only the actual Node/loader/library/module chain. A file inventory or image hash alone does not prohibit executing other files.

Verify the bundler against actual production imports, independently test bounded invalid invocation/boot refusal, and compare repeated output bytes from unchanged inputs. Verify the image composer against actual pinned base descriptors and diff IDs, read-only layer metadata, output digest readback and refusal of corrupt or mismatched inputs. Native worker startup under the complete AppArmor bundle still requires the actual image, command, syscall/loader/mount permissions and target runtime. No prior Mac, fixture, parser or historical ACK result transfers to it. Registry publication and installation require a concrete separate approval. Full application, stop/unpublish, atomic release, reuse and public selection remain separate K2 acceptance requirements.
