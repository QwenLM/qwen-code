# Web Shell 会话回放时的布局

[English](2026-11-19-web-shell-replay-layout.md) | [简体中文](2026-11-19-web-shell-replay-layout.zh-CN.md)

## 问题

全量回放可能在一次提交里挂载大量含 Markdown 表格的虚拟行。行的 ref 会同步测量没有缓存的高度，新挂载的增强表格也会设置滚动位置。浏览器可能在每次 DOM 变更后重复布局，即使输入框已经恢复焦点，输入仍会排队。对一份真实会话进行本地生产构建回放时，一个按键用时 1.71 秒才写入编辑器 DOM。

## 改动

- 将消息列表的虚拟滚动预渲染范围设为 15 行。保留增强表格渲染器和现有的虚拟滚动启用阈值。
- 跟随最新消息时，虚拟行的 ref 首次挂载先使用缓存或估算高度，通过 ResizeObserver 获取真实尺寸。阅读历史、恢复前插历史页、定位消息或环境缺少 ResizeObserver 时沿用常规测量。
- 当全屏切换保存了滚动位置时，在挂载增强表格时恢复该位置。新表格已有默认滚动位置。

## 验证

用生产构建回放同一份录制会话。在编辑器聚焦且可编辑时，把按键投到最长帧内。验证这些按键全部写入 DOM，最慢用时低于 700 ms。检查快速滚动、加载更早的一页且保持阅读位置、搜索定位，以及增强表格全屏切换后的滚动和焦点恢复。
