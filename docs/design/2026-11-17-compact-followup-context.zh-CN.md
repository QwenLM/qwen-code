# 精简后续建议上下文

[English](2026-11-17-compact-followup-context.md) | [简体中文](2026-11-17-compact-followup-context.zh-CN.md)

## 问题与范围

Ink、OpenTUI 和 ACP 向共享建议生成器传入最多 40 条经过整理的 `Content`。
条数无法限制工具正文的体积。缓存共享默认开启，但建议 fork 可能选择不同的
fast model，同时继续携带父会话的系统提示和历史，无法依赖父模型的缓存。

本次限制普通建议上下文，并通过现有 side-query 客户端发送异模型建议。
保留同模型缓存 fork、建议提示词、输出过滤、取消、重试策略和调用接口。
Preview 的架构只作参考，不引入其服务、对话协议和灰度开关。

## 设计

共享生成器按原有优先级确定目标模型：显式覆盖、配置的 fast model、配置的主模型。
只有会话归属正确且模型与目标一致的缓存快照才使用原有 fork。
模型不同或标识无法确定相同时走精简 side query，不继承父会话系统提示或
工具声明。会话归属检查继续生效。本次不新增缓存 API，也不通过改变 provider
路由来解析别名。

side-query 路径在本地将传入的 `Content[]` 投影为纯文本，不增加模型调用。
对话总预算为 4,000 个 UTF-16 代码单元，包含标签、截断标记和分隔符。
这是字符预算，不是 tokenizer 的 token 保证；固定建议提示词另计。

| 证据               | 预算与优先级                                                          |
| ------------------ | --------------------------------------------------------------------- |
| 最新可见用户请求   | 最多 1,000 字符，最高优先级                                           |
| 最终可见助手文本   | 最多 1,800 字符，保留头尾                                             |
| 当前轮工具结果     | 合计最多 400 字符，最近优先；保留工具名、完成或错误状态及少量文本尾部 |
| 更早的可见用户请求 | 每条最多 600 字符，最近优先，使用剩余预算                             |

排除思考内容、内联或文件数据、函数调用参数和系统提醒。工具响应不作为用户请求。
工具摘要转成纯文本，裁剪后不会出现孤立的协议工具结果。没有显式 error 的 Shell
结果标为完成，不推断为执行成功。不修改传入历史或父缓存快照，选择完成后按时间
顺序排列。没有可用上下文时跳过这次可选请求。

原始用户目标只在传入的历史尾部仍包含它时保留；不为重建目标读取或复制整个会话。
同模型 fork 保持原样，包括其已有的 40 条历史尾部限制。

## 文件与消费者

实现和同目录测试位于 `packages/core/src/followup/suggestionGenerator.ts` 和
`packages/core/src/followup/suggestionGenerator.test.ts`。消费者为 Ink 的
`AppContainer`、OpenTUI 后续建议 hook 和 ACP `Session`，后者也负责 daemon/Web Shell
建议推送。它们的调用接口保持一致。

## 验证与验收

定向测试覆盖超长中英文、最新用户约束、最终回答头尾、当前轮工具错误、大正文排除、
思考与图片及提醒过滤、时间顺序、不修改历史、显式模型覆盖、关闭缓存、缺失或跨会话
快照，以及保持原样的同模型 fork。已取消请求不得生成建议。

运行 build、typecheck、bundle、定向 Core 测试和受影响调用方测试。实现前先尝试全局
CLI 基线；交互建议路径无法到达时记录直接调用生成器的脚本验证替代方案。

对完整的真实线上输入用相同模型成对回放基线与修改后请求，记录来源和输入完整性、
实际 token 用量、延迟，以及建议相关性和用户约束保留的人工检查。原始样本保留在
Git 之外。不将字符缩减等同于 token 用量，不将缓存输入节省等同于总费用，也不将
后台延迟等同于用户任务延迟。小样本用于验证可行性，不代表生产整体质量。

基于 main `10f05043c2` 的验证已通过 build、typecheck、bundle、42 个 Core 测试和
32 个调用方回归测试。构建后 CLI 的 ACP 检查确认异模型请求被精简，同模型父上下文
保持原样，每次运行均推送一次建议通知。

六个完整线上回合在 `qwen3.8-flash` 上成对回放，投影前输入为 168,701 token，
投影后为 8,843 token，减少 94.8%，两组均无缓存命中。这比较的是普通 side-query
路径，不包含原异模型 fork 的父系统提示开销。部分建议仍有冗余或猜测无依据细节的
问题；该样本不能证明质量无退化，也不能证明生产整体延迟改善。

## 风险与待确认事项

裁剪可能遗漏较早约束或有用工具证据。保留头尾并优先保留用户请求能降低风险，仍需
回放核对。模型标识的字面比较是保守判断，无法证明同模型缓存必定命中。同模型缓存
收益、输出上限和超时调优留待单独评估。本次没有阻塞实现的设计问题。
