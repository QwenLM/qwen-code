# Android 连接恢复

[English](./mobile-connection-recovery.md)

## 问题与当前状态

Android 连接配置基础功能（#12121）在系统重建 Activity 后总是显示连接列表。渲染进程退出时已有“重试”，但重新连接会丢失所选会话和工作区。旋转屏幕通常由 `configChanges` 处理，因此仅测试旋转不能覆盖这个问题。

## 预期行为

使用一个小型连接快照，只包含配置 ID、浏览器代际 ID 和白名单内的 Web Shell 导航信息。有活动连接时，将快照写入 Android 实例状态。Activity 重建后重新读取加密存储，匹配两个 ID，通过现有浏览器初始化检查，然后创建新的 WebView。重命名保留代际；删除配置或更改地址、令牌会阻止恢复。没有 Android 保存状态的普通冷启动仍显示连接列表。

通过 WebView 历史回调跟踪导航，包括 H5 的 `history.replaceState`。仅恢复 `/` 或 `/session/<id>`、可选 `workspace` 标识符，以及 `context=standalone|live`。标识符只允许有长度上限的 ASCII 字母、数字、`_` 和 `-`。外部来源、用户信息、错误路由、重复或未知查询参数、非法标识符都会回退到配置根路径。片段会被丢弃。保存状态不包含服务地址、凭据、原始 URL、WebView 历史、表单值或页面内容。凭据始终来自当前加密存储，并按现有连接流程附加到首次加载。

渲染进程存活时缓存经过验证的路由。渲染进程退出后，在销毁旧 WebView 前保留快照，并要求用户明确点击“重试”。在错误界面重建 Activity 后仍保留此选择。选择“连接”会清除恢复状态。普通连接错误也提供返回已验证路由的明确重试，不引入自动重试循环。

## 组件与决策

- `ConnectionNavigation.kt`：纯路由验证与规范化构造，使用独立单元测试。
- `ConnectionRecovery.kt`：有界 Bundle 序列化及配置代际匹配，不序列化凭据。
- `MainActivity.kt`：重新读取加密存储、跟踪历史、明确恢复操作及实例状态接入。
- 原生设备测试：使用内嵌回环服务，真正重建 Activity 和终止渲染进程；恢复、清理测试配置，不清除应用数据。

不使用 `WebView.saveState`/`restoreState`，因为它们保存的浏览状态超出需求。不把导航写入偏好设置，也不增加 JavaScript 桥。与其他功能集成时，现有文件选择和权限控制器仍负责取消旧回调并保留延迟结果的归属。

## 验收

重建后，新的独立配置 WebView 返回同一配置、会话和工作区。同源的多个配置仍保持隔离。重命名后可以恢复；删除或地址、令牌轮换后不能恢复。保存的 Bundle 仅包含约定标识符及重试标记。渲染进程被终止后显示“重试”，使用当前存储的凭据重新连接到同一路由。不支持的 WebView 仍拒绝连接。取消或退出连接后不会自动重新打开。

## 范围与待完成事项

仅恢复 Android 保存的实例状态，不恢复强制停止、移除任务或任意冷启动。不恢复未发送草稿、滚动位置、浏览历史、录音、权限和待处理文件操作。这不代表已通过真机、TalkBack、真实语音服务或服务端逐设备撤销凭据的验收。独立麦克风功能会在后台关闭已授权麦克风的连接，包括全屏文件选择器；此处不放宽该策略。生产凭据、通知、正式发布与签名仍属后续 Phase 2 工作。无需新增服务端协议。
