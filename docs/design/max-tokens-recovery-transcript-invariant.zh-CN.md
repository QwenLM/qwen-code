# MAX_TOKENS 恢复的对话记录不变量

[English](max-tokens-recovery-transcript-invariant.md) | [简体中文](max-tokens-recovery-transcript-invariant.zh-CN.md)

## 问题

当助手响应以 `MAX_TOKENS` 结束时，Qwen Code 会请求模型继续生成，并在内存中将续写内容合并到原始模型轮次中。如果每次尝试都立即记录，就会向仅追加（append-only）的对话记录写入相邻的多条助手记录，导致恢复会话时重建的历史与实时会话不一致。

## 设计

仅对由输出 token 恢复所拥有的轮次延迟助手记录。恢复续写在流式输出时仍然可见，但其终止块会被保留，直到模型轮次提交。恢复完成或被放弃后，从保留下来的合并历史轮次派生出一条持久记录。

每个对话在等待上一次发送之前，先串行化发送准入。这样可以将恢复所有权及其延迟记录隔离在单次发送内，而无需引入第二套按发送划分的状态模型。

Goal 用量按每次成功的模型尝试累计，与持久的助手记录相互独立。最终记录会将这些 token 标记为已累计，因此持久化时不会重复计费。

恢复的终止块最多排空一秒，以便纳入尾随的提供方用量元数据，同时避免一个从不关闭流的提供方卡住对话。在该有界截止时间之后到达的元数据不可用；Goal 记账会记录流被中止之前观察到的用量。

## 不变量

- 一个已恢复的实时模型轮次只产生一条助手对话记录。
- 该记录的消息 parts 等于经过结构化输出脱敏后保留下来的合并历史轮次。
- 普通流不会被缓冲到提供方 EOF。
- 同时被准入的发送按顺序执行，且不能共享恢复状态。
- 消费方放弃时，只持久化已经可见的模型输出。

## 非目标

此变更防止产生新的格式错误的对话记录。它不会重写在此修复之前创建的仅追加对话记录。
