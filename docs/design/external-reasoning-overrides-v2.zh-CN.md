# 外部思考配置覆盖：限定范围的重新设计

[English](external-reasoning-overrides-v2.md) | [简体中文](external-reasoning-overrides-v2.zh-CN.md)

状态：已实现，本地验证通过。替代 PR #11521 的实现方案。新 PR 的总变更
不得超过 3500 行，按生产代码、测试、生成文件和文档的新增行与删除行之和计算。

## 1. 目标与边界

允许使用方通过 settings 覆盖模型的思考格式、支持档位及默认档位。默认值必须
同时作用于实际请求和界面。支持复用现有 provider 协议的新模型名与网关别名。
思考配置在下一次用户发送前生效；当前轮及其工具续跑、重试、派生代理保持原配置。

复用 `modelProviders[].capabilities.reasoning`，不再引入平行的
`generationConfig.reasoningConfig`、分档预算映射、请求模板语言或新鉴权协议。
不重做模型注册表、图片模型生命周期、凭证刷新、调度、运行时快照恢复或通用
provider 错误处理。端点和凭证变更不属于本功能“下一次发送生效”的保证，
继续沿用它们已有的生命周期。

主分支已经把思考能力提供给模型发现与控件，部分适配器也读取这些能力。
真正需要补齐的是默认值一致生效、别名显式选择格式，以及当前轮稳定的思考视图。
填补这些缺口，不建立第二套配置系统。

## 2. 公开配置

已知模型只修改默认档位：

```json
{
  "id": "qwen3.8-max",
  "capabilities": {
    "reasoning": { "defaultEffort": "medium" }
  }
}
```

在已有 OpenAI 兼容 provider 上声明新模型：

```json
{
  "id": "company-model-v2",
  "baseUrl": "https://gateway.example.com/v1",
  "envKey": "COMPANY_MODEL_API_KEY",
  "capabilities": {
    "reasoning": {
      "profile": "openai-effort",
      "efforts": ["low", "medium", "high"],
      "defaultEffort": "medium"
    }
  }
}
```

继续使用已有的 `efforts` 和 `defaultEffort`，只新增可选 `profile`。
允许部分声明，先补齐再交给已有严格能力解析器。部分输入类型与完整解析结果
`ModelReasoningCapabilities` 分开，下游消费方不接收半成品。已有完整声明及其中的
`thinking`、`toggleOnly`、`canDisable`、`disableField` 无须迁移。
本 PR 不新增思考开关策略字段。

| 字段            | 职责                                                     |
| --------------- | -------------------------------------------------------- |
| `profile`       | 选择已有思考请求策略，不选择 SDK、端点或凭证。           |
| `efforts`       | 替换 `low/medium/high/xhigh/max` 中受支持的档位子集。    |
| `defaultEffort` | 在没有显式选择或优先级更高的已有原始覆盖时提供默认档位。 |

省略字段根据实际端点从已有 provider 列表继承能力，精确模型 ID 优先于归一后的别名。
未知网关路由需要显式声明。`efforts` 整体替换，不合并数组。继承的默认值用已有
函数归一到有效集合；显式指定的默认值必须属于有效集合。未知分档模型必须声明
`profile`、`efforts` 和 `defaultEffort`，不替使用方猜默认值，也不增加新模型名表。
仅开关 profile 不需要档位字段，并拒绝这些字段。保留现有规范档位词表。

Profile 是已有格式的封闭集合：

| 协议                  | Profile 与已有请求格式                                                                                                                             |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| OpenAI Chat           | `openai-effort`：扁平 effort；`openai-reasoning`：嵌套 reasoning；`deepseek-openai`：DeepSeek 思考及推理历史格式。                                 |
| OpenAI Chat 上的 Qwen | `dashscope-effort`：分档 effort；`dashscope-thinking`：顶层开关；`qwen-chat-template`：嵌套模板开关。                                              |
| OpenAI Responses      | `openai-reasoning`：已有 Responses reasoning 格式。                                                                                                |
| Anthropic             | `anthropic-manual`：enabled thinking 与固定或派生预算；`anthropic-adaptive`：adaptive thinking 与输出 effort；`deepseek-anthropic`：已有兼容格式。 |
| Gemini/Vertex         | `gemini`：已有 thinking-level 映射，只支持 low/medium/high。                                                                                       |

显式 adaptive profile 始终选择 adaptive thinking。需要手动预算的使用方选择
manual profile，不增加 adaptive-only 同义配置。省略 profile 保留已有推断。
显式 profile 替代思考格式推断，不覆盖端点专属的非思考限制。
显式 profile 决定请求控制字段；只有省略 profile 时，才把 `disableField` 作为
旧格式提示，不能让两种格式选择器同时进入适配器竞争。

## 3. 解析与请求链路

一个纯函数根据精确路由、外部声明和已有内置规则，得到有效能力、默认值与请求
策略，供界面和适配器共同使用。依照实际选中路由解析，不能使用注册表占位端点
做最终判断。显式 profile 不再依赖主机名推断思考格式。不能仅凭模型 ID 取用
另一个端点的声明。
未声明 `baseUrl` 的条目保留已有注册表选择身份，以选中的运行时端点完成格式推断。
显式覆盖端点并选择不同路由时，必须解析目标路由自己的声明。

区分模型默认值与用户选择。先使用已有会话或请求显式选择，再使用解析后的模型
默认值。只执行一次已有档位归一；声明已确定有效档位后，不能再按模型名二次截断。

`generationConfig.reasoning`、`samplingParams`、`extra_body` 保持各 provider
已有优先级与直接配置行为。Profile 替代已有的思考推断环节，不做最终整份请求体
重写。默认值低于已有原始覆盖；保留请求级关闭和已有强制思考处理。复用适配器对
可识别原始覆盖的已有状态映射。无法由原始输入确定实际档位时，使用已有的未指定
或不可调整控件状态，不能声称实际发送了模型默认档位。不调和任意互相矛盾的原始
字段，不扩展其接受形态，不新增覆盖状态界面。

各 provider 只增加小范围策略选择，同时选择已有序列化及必要的思考历史处理。
工具选择、采样、鉴权、缓存和非思考历史规则保留在原来的归属位置。未来不受支持
的协议通过适配器开发支持，不增加另一套可配置语言。

## 4. 下一次用户发送生效

每次用户发送进入执行时，持有一份不可变的思考配置表。表项使用现有精确路由身份，
只包含思考元数据。捕获全部已配置思考路由，确保磁盘重载后才创建的旁路请求或
子代理仍能使用父轮次版本。复用路由身份辅助函数。

配置观察链路准备最近一次有效思考配置表。在已有用户发送入口一次性替换当前表。
更新配置表不替换当前 generator、不调用 `refreshAuth`、不切模型、不刷新工具，
也不替换注册表。采用更新时清除旁路模型缓存，已经持有的视图仍保留原表。正常鉴权刷新继续携带当前思考配置表，不能提前采用待更新内容。

适配器读取捕获的表，不读取实时注册表中的思考配置。派生代理继承表，但解析自身
路由。未知路由使用自身已有内置规则，不继承父模型能力。已有切换模型流程保留
路由与偏好规则，从当前表解析思考配置；下一次用户发送再采用最近一次配置表。

自动重试、工具续跑及 Goal/后台续跑不采用待更新配置。新建会话使用最新配置。
冷启动模型预览可以读取最新有效表；已有会话控件展示当前表，在该会话采用更新
时同步变化。

运行时遇到无效声明时返回无覆盖，新建会话也能继续沿用原有行为。严格的暂存校验
拒绝无效更新，保留上一份有效思考表，并通过已有错误渠道报告模型及字段。不能阻断
无关设置更新或清空健康模型行。静态字段校验与端点推断分离，不允许占位 URL
造成全局启动失败。

## 6. 验证与验收

1. 已知 Qwen 3.8 Max 只配置默认 medium：控件选中中，真实请求发送 medium，
   不出现“使用模型默认值”菜单项。
2. 每种列出的格式使用未知别名：声明档位和默认值生效，最终请求符合已有策略。
   覆盖仅开关、manual/adaptive thinking、档位归一和显式关闭。
3. 无声明时请求内容和已有控件不变；已有完整能力声明仍可用，原始参数覆盖行为
   保持兼容。
4. 同名不同端点及模型切换：能力不泄漏，默认值不保存成用户偏好，显式选择沿用
   已有归一规则。包含 Qwen、DeepSeek、Kimi 切换。
5. 当前轮调用工具期间重载两次：请求、重试和新建子代理保留原表，下一次用户发送
   使用最近一次有效表。加入后续图片或端点更新，证明没有新增图片/凭证暂存事务。
6. 无效 profile、档位、默认值及依赖端点的推断：保留原思考配置及健康模型发现，
   给出有效错误信息，不发送编造的兜底格式。
