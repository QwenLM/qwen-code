# 始终可见的问答记录

[English](2026-09-09-web-shell-question-message.md) | [简体中文](2026-09-09-web-shell-question-message.zh-CN.md)

## 问题与范围

已完成的 AskUserQuestion 结果目前会合并到工具摘要，并隐藏在整轮对话的
“已处理”折叠区域。问答记录应像用户消息一样始终可见，在右侧气泡内先显示
问题，再换行显示答案。“已处理”的工具次数排除 AskUserQuestion。保留模型生成的问题原文，包括前缀。待回答控件的交互不变；折叠按钮增加明确的“展开／收起”文案，分别配合向下／向上的操作箭头。子代理内部工具保持现有行为。

## 设计

MessageList 从混合工具组中分离已完成的问答工具，阻止其参与紧凑摘要合并，
并将其保留在整轮折叠之外。保留 tool_group 角色、时间顺序和工具调用标识，
避免将答案误判为新的用户轮次。MessageItem 使用 UserMessage 的现有布局类
显示问答气泡，不调用用户输入解析器。

生产端返回结构化显示结果：
`{ type: 'ask_user_question_answers', text, answers: [{ question, answer }] }`。
给模型的原有文本保持不变。PostToolUse hook 的 `tool_response.returnDisplay`
继续为原字符串；PostToolBatch hook 的 `tool_calls[].tool_response.result_display`
也继续使用可读文本。共享 hook 转换复制问答响应，不修改界面及历史使用的结构化结果。
历史显示和录制对每个显示文本、问题和答案字段复用现有 32,000 字符压缩上限，
保留问答结构及截断标记。短字段和原始模型内容不变。
CLI 渲染器显示 `text`；Web Shell 校验类型标识及字符串
字段后，直接渲染问答数组。部分提交只包含实际提供的答案。不匹配前缀、不使用正则
拆分，也不按时间迁移展示。

仅结构化结果使用右侧问答气泡。历史字符串结果（包括单题）继续使用左侧 ToolGroup
及其原有展开控件。本次改动将两种格式都排除在“已处理”整轮折叠和工具计数之外。
空结果不渲染气泡或时间戳。

ACP 和持久化记录已支持传递结构化显示结果。SDK 将新结果投影为有长度限制、
仅包含白名单字段的 `question_answers` 预览；文档导出安全处理并保留这些字段。
Web Shell 从安全预览恢复相同显示结构，使实时、回放和导出一致。未知或格式错误
的结果使用现有工具展示。在上述预览限额内，多行答案和代码原文保持不变。

实时工具准备事件可能先创建参数为空的占位记录，完整问题随后才由提问请求提供。
因此在所有消息块转换完成后，再将提问参数关联到工具调用；判断问题参数是否缺失，
不把空对象当作完整参数。这让刚提交后的展示与历史回放一致，无需修改存储消息。

## 验收标准与风险

展开或折叠“已处理”前后，新结构化问答始终可见，并按原始答案顺序逐项显示。
问题在答案上方，无内部折叠。旧记录保留在左侧。实时完成与刷新后使用相同的问答布局；
超长的已存预览保留明确截断标记。长文本在气泡内换行。问答边界来自数组，答案中的标题形状文本不能生成额外答案。
未知字段不能进入安全预览或导出。不重写历史数据；由结果的类型标识决定展示方式。
