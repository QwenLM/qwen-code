# 精简常驻自动记忆策略

[English](compact-inline-memory-prompt.md) | [简体中文](compact-inline-memory-prompt.zh-CN.md)

## 问题与思路

文件式记忆模式下，前台读写策略随每次请求发送。目录全空时，旧实现也会附带一个快照，为每个已启用的记忆根目录写一段空索引。通过工具加载写入策略可以缩短首个请求，但也可能增加保存或遗忘记忆所需的模型请求次数。精简常驻策略可以让这些操作从首个请求就可用。

## 实现

- 精简主会话的文件式记忆策略。保留根目录及类型路由、完整的 frontmatter 要求、查重、私有索引维护、团队作用域和凭据限制，以及对过期记忆的核验。直接模型请求使用同一套指令执行保存、纠正和遗忘。
- 所有已启用根目录均为空时，新请求省去目录。在已发送非空快照后，发送带标记的空快照以替代早期条目。任一根目录有条目时保留完整快照、顺序、转义和截断。结构化召回和后台提取器沿用各自的提示词。
- 压缩共享的风险操作说明，省去通用模型默认示例。保留显式工具调用风格覆盖、模型专属说明、授权和拒绝规则，以及对用户已有改动的保护。

## 验证

使用同一模型、provider、工具和初始记忆，在两个构建中重放固定的普通问题，以及独立的保存、更新、遗忘和召回样本。记录首个请求和整轮所有请求的 provider 输入。普通问题首个请求的 provider 输入 token 必须下降。每个场景的整轮 provider 输入中位数须在基线的 130% 以内。检查正文、索引和召回，并验证删除最后一条记忆、恢复会话和补回同一条目后，模型收到当前目录。
