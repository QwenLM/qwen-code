## 1. 目标与决策

降低获取有用长期记忆的成本，同时不增加漏记、虚构事实、前台延迟或跨会话泄漏。提取启动次数和原始输入 token 数只是中间指标，不是目标本身。

按以下顺序推进：

1. 用固定题面和请求归因测量当前实现。
2. 保持现有调度频率，验证增量提取输入。
3. 只有实测剩余成本值得优化时，才考虑内容门控或批处理。

一次已完成且零产出的提取，只能描述过去的输入，不能证明下一轮没有有用信息。不交付基于这个推断的冷却策略。#13004 保持打开，作为成本与质量验收主线；#13612 保持打开，跟踪输入与生命周期正确性。它们都不是已完成的替代 PR。

## 2. 当前行为与证据边界

| 位置         | 源码基线上的当前行为                                                                                                                                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 普通模型循环 | 开启托管记忆时，`LlmClient.runManagedAutoMemoryBackgroundTasks()` 为符合条件的已完成用户请求调度提取；排除内部 session-agent 对话。                                                                                                             |
| ACP          | `Session.#recordPromptCompletionEffects()` 在新的、成功的逻辑用户轮次后调度；重试、取消和循环保护停止不触发。                                                                                                                                   |
| Manager      | `MemoryManager.scheduleExtract()` 检查主 agent 直接写记忆并串行化、排队提取；`runExtract()` 检查内存压力。                                                                                                                                      |
| 游标         | 每个项目只有一份游标，保存 `{ sessionId, processedOffset, updatedAt }`。切换到其他会话时偏移清零；历史缩短时，只有旧偏移超过新长度才清零。`runAutoMemoryExtract()` 用这个原始历史偏移检测新的非空用户文本，但没有把这段未处理输入交给 planner。 |
| 提取输入     | `captureCacheSafeParams()` 捕获最近 40 条 curated 历史并做精简。`runAutoMemoryExtractionByAgent()` 再清洗捕获的历史，作为 `extraHistory` 传入。因此原始历史、curated/精简历史和清洗后的提取输入，位置互不相同。                                 |
| 实际执行     | planner 调用 `runForkedAgent()` 时没有传 `cacheSafeParams`，因此走 headless-agent 分支的 `initialMessages`。另一处 `createForkedChat()` 的 40 条上限属于 cache 分支，不是本提取路径的第二次截断。                                               |
| 成功与失败   | 写入或带路径的工具活动可以推进游标；零次带路径工具调用会保留游标，错误保留重试行为。工具活动不等于成功读过记忆。                                                                                                                                |

同目录的 [memory-system.md](memory-system.md) 记录同一子系统，但其「提取游标」一节仍把 `processedOffset` 记为每次提取后都推进到 `params.history.length`。这只在未处理切片中没有新的非空用户文本、因而提前返回时成立；完成提取的路径只有在本次运行确实有进展时才推进该偏移——本文的验收标准与必须失败的回归用例都以此为准。

已配置快速模型时，提取器默认使用它，并有自己的系统提示，因此不能假设与主对话共享前缀缓存。历史超过 40 条后，提取窗口也会逐轮滑动。重复读取上下文仍可能命中 provider 缓存；换成移动的增量片段，可能减少原始输入，也会改变缓存复用。headless 结果只汇总输入、输出和总 token，没有缓存读写字段，缓存统计必须来自 provider 响应或请求捕获。仅靠源码分析，不能推导出降本或安全默认开启的结论。

在 #13004 中，历史测量发现了明显的后台请求量，包括零写入运行，但不是本文基线或增量输入改动的验收结果。同一提取器的工具循环可能产生多次提供商请求；必须分别统计提取任务与 API 请求。

Claude Code 2.1.301 的静态分析发现直接写记忆、prose 门控和可配置的每 N 轮频率，没有发现成功零产出后的冷却。没有观察到服务端实际开关值或真实用户默认配置。该对比只是背景，不是采纳理由。特别是 `用中文`、`别用 npm` 这类短句也可能是长期指令。

## 3. 第一个 PR：可复跑的基线测量

这个 PR 不修改提取频率、游标语义、提示词、模型选择或生命周期等待。先复用已有测试、provider 捕获设施及提取/API 遥测，再考虑增加观测。只补缺失的任务到请求关联或数值计数；共享遥测不得记录提示词、记忆正文、物理记忆路径、凭据或内部账号身份。

### 环境准备

- 固定源码 SHA、CLI 入口、provider、解析后的主模型与提取模型、生成参数和记忆协议。
- 使用合成题面，并隔离配置、项目/用户记忆、会话存储和工作目录。不读取或覆盖操作者的真实记忆和设置。
- 单独核对已安装 CLI。本机 `qwen --version` 预检返回 `0.25.0`；不能把该发布版本与固定源码基线混用。本文设计阶段没有运行对话模型。
- Dream、recall、migration、权限分类器和前台请求分别归因。若隔离需要修改设置，只改测试配置，并在不同组使用相同配置。
- harness 根据实际观测等待提取结束后评分。积压和超时明确记录，不能算成零成本或正常零产出。

### 指标

每个任务保留合成会话身份、触发点、有界历史范围、结果、请求 ID、模型、provider 返回的 usage，以及观测到的最终记忆状态。记录：

- 提取启动次数与每次启动的 API 请求数；
- provider 输入、输出、缓存读取、缓存写入 token，保持各 provider 的字段语义；
- 出站 payload 大小，分成提取指令、已有记忆 manifest、历史上下文和新增内容；
- 使用已核实费率计算提取及整个进程的估算费用；缺少费率或 usage 时标为 `unavailable`；
- 前台完成时间、提取结束时间，以及各生命周期边界的积压情况；
- 预期长期事实的保存、漏记、晚记、矛盾和虚构情况；延迟同时按轮次和耗时测量。

payload 字符数不是精确的组件 token 数。可用时采用与 provider 兼容的 tokenizer，并把组件 token 数标为估计值。不能把原始输入等同于未缓存或计费输入，也不能重复累加有重叠的缓存字段。P50/P95 仅从足够且公开说明规模的样本计算，不用少量运行编造分位数。

### 固定题面集

基线与后续候选使用相同的初始记忆快照和字面输入。工具密集场景复用已有受控 provider 和合成仓库数据，必须在一个逻辑轮次内产生超过 40 条 curated 历史。

| 场景             | 字面输入或步骤                                                                                                      | 质量判据                                                                                            |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 临时任务         | `17 * 23 等于多少？这只是一次计算，不要保存为记忆。`                                                                | 正确回答，不虚构长期偏好。                                                                          |
| 短偏好           | `以后用中文回答。`                                                                                                  | 持久保存语言偏好。                                                                                  |
| 纠正             | `不要用 npm 安装依赖，这个项目统一用 pnpm。`                                                                        | 保存协作约束。                                                                                      |
| 依赖上下文的确认 | Agent 提议一个合成项目约定，用户回答 `好，就按这个来。`                                                             | 连同前文保存被确认的决定，不带入无关旧提议。                                                        |
| 重复事实         | 重复初始记忆快照中已有的偏好。                                                                                      | 不产生矛盾或重复长期事实。                                                                          |
| 长工具轮次       | 先提出偏好，在提取尚未结束前，于单个逻辑轮次内产生超过 40 条 curated 条目。                                         | 候选目标：偏好出现在实际提取输入和落盘记忆中。基线若漏掉，记为实测损失，不算 harness 失败。         |
| 最后一轮事实     | 提出长期偏好，随即关闭 ACP 或结束一次性运行。                                                                       | 分别记录返回前保存、稍后保存或仍积压；不假定已有 drain。                                            |
| 历史替换         | 提出事实后，通过受支持生命周期调用执行压缩及 clear/resume/branch/rewind；包含压缩后新历史长度仍不小于旧偏移的情况。 | 报告基线保留情况与身份边界，不假定这些路径属于同一历史 generation；压缩后被静默跳过的内容记为损失。 |
| 并发会话         | 两个会话/工作目录交错提出不同合成事实，包括提取排队。                                                               | 不串用会话输入或记忆，不静默覆盖积压范围。                                                          |
| 失败重试         | 注入 provider/读取失败；另测成功写入后再发生失败。                                                                  | 未处理工作保留；重试不抹掉已保存事实，不推进到未覆盖的输入。                                        |

受控 provider 执行只能证明 payload、游标和生命周期契约，不能证明真实模型的记忆质量或降本。真实模型评测使用同一题面集，按事实盲评。每个成本/质量题面与模型先做五次重复，交替平衡基线/候选顺序，重置记忆和会话状态，记录冷/暖缓存条件并报告逐对结果；若不稳定再增加样本。本地重置缓存不能证明 provider 缓存是冷的。

### 完成门

交付可复跑 harness、保留的断言、私有原始证据和脱敏报告。报告标明归因缺口；没有候选的成对运行时，不作因果降本结论。已有 invariant 复用 `extract.test.ts`、`memoryLifecycle.integration.test.ts`；它们 mock planner 的测试，不能证明真实出站模型请求收到哪些消息。

## 4. 第二个 PR：增量输入，保持原频率

基于 `main` 新开聚焦 PR，不叠在 #13571 上。实现经核实的输入契约，并与第一个 PR 的基线对比。不加入冷却、字数过滤、新用户设置或持久重放子系统。

### 归属与输入

- 在所属完整轮次边界捕获已接纳的内容，并绑定项目/工作目录、会话及历史 generation 身份；不在稍后从另一个会话的最新缓存槽恢复输入。
- 在该 generation 内维护已覆盖偏移与不可变的任务结束偏移。区分原始历史坐标、curated/精简历史位置和清洗后的输入位置，不能互相当成下标。
- 从未处理范围构建显式提取输入。涉及指代或确认时，把紧邻的上一完整用户轮次作为只读上下文；重叠上下文不算新覆盖输入。
- 保留已有清洗、记忆根目录约束、模型/provider 选择及 metadata writer。保全工具调用/结果配对；继续排除隐藏推理和运行时提醒。
- 输入受解析后模型的上下文预算限制。过长范围按完整逻辑轮次分段；若单轮也过长，则携带来源范围与最小前文分块，保持工具协议有效。不能把被尾部上限删掉的内容算作已处理。

当前每个项目单份的游标，无法为交错会话或压缩 generation 表达独立积压范围。实现 PR 必须定义最小的、按归属/generation 区分的游标变更及迁移，不能静默把旧偏移当成持久消息 ID。

### 完成与重试

成功提取只推进到该任务实际覆盖的输入终点，即使期间到来新一轮也不能越过。重叠上下文不推进覆盖偏移。失败、取消、零工具幻觉保护或索引提交失败不能把未见输入标成已处理。保留现有用户/项目索引的非对称失败语义，除非独立核实的缺陷要求局部变更。

重试提取是至少一次，不是事务性的恰好一次写入。复用记忆协调避免重复/矛盾事实，不引入事务框架。主 agent 直接写过记忆不等于更早积压范围的所有事实都已保存；保留积压范围，并串行化写入和提取。拒绝归属或 generation 已变化后的旧结果。

排队请求保留实际覆盖范围与归属，不只保留最新历史长度。不能通过回退到其他会话缓存解决多会话排队。

### 生命周期边界

已接纳的输入快照保留到确认覆盖或显式取消。压缩或切会话不能静默销毁它。只接入输入契约必需的最小 generation/失效处理，不用“所有命令都等模型完成”代替归属管理。

若某个边界无法安全保留快照，则必须有有界 flush，或报告明确的积压/取消结果，不能宣称成功。进程退出和崩溃恢复不在该 PR 范围；报告必须披露未持久保存的积压工作。基于持久 transcript 位置实现重启恢复是独立设计，不能当成原始游标的既有能力。

### 验收

1. 真实出站请求包含单个逻辑轮次内超过 40 条 curated 条目中的早期事实，并保留依赖前文的短确认。
2. 已覆盖内容只作为有界前文出现，不重复成为待提取输入。
3. 提取期间到来的新工作，在旧任务完成后仍然积压。
4. 失败与成功写入后再失败保留重试能力，不破坏已保存事实。
5. 压缩、历史替换、rewind 和交错会话不推进其他归属/generation 的游标，也不把丢失内容误记为覆盖。
6. 固定题面和真实模型成对运行的事实质量不退化。分别报告原始 token 与估算计费成本；输入 token 更少不等于验收通过。

受控 provider 驱动真实 CLI/ACP 进程，同时检查 payload、记忆和游标落盘。以下合理回归必须使测试失败：恢复 40 条尾部输入、把原始偏移用于 curated 输入、推进到最新历史长度、取用其他会话捕获的历史。相同契约优先增强已有测试，不增加平行的 mock case。

## 5. 暂缓实验与上线

只有增量输入验收通过、剩余成本实测显著时，才考虑内容门控或确定性批处理。长度阈值不是长期价值分类器，每 N 轮批处理也不天然比零产出冷却更安全。

任何暂缓都必须保留输入、定义最大新鲜度延迟、覆盖所有生命周期边界，并把 flush/重试纳入费用。本文不承诺默认开启。收益很小、质量退化或缓存退化，都可以成为保留现有频率的理由。
