# 根据已保存的条目生成自动记忆索引

[English](runtime-owned-extraction-index.md) | [简体中文](runtime-owned-extraction-index.zh-CN.md)

## 问题

后台提取器收到的指令要求先写主题文件，再编辑对应的 `MEMORY.md` 索引。运行时已能根据保存的主题生成索引。模型编辑索引会消耗工具轮次，编辑失败后重试时尤其明显。

## 设计

提取器先使用主题清单，必要时打开已有文件查重。它在已有的用户和项目记忆根目录里写主题，将根索引交给运行时处理。提取权限允许读取两个根索引，并拒绝写入，包括通过符号链接写入。规则只针对这两个索引的确切路径。其他记忆操作沿用现有权限。

运行时根据成功写入的回执重建受影响的索引，包括提取因取消或达到轮次上限而结束的情况。如果提取器抛错且无法返回回执，运行时会尝试修复两个根索引，然后报告原始错误。项目索引重建失败时，记录待处理状态并保留历史偏移。下次提取先修复索引再发起模型调用，即使重试时没有新的主题写入也能修复。用户索引尽力修复。调度器、历史窗口和模型选择沿用现有设置。

## 验证

用受控 provider 覆盖新增、更新、只读查重、索引写入被拒绝，以及正文写入成功后发生故障的场景。检查主题文件和生成的索引。确认索引重建失败后历史偏移仍停留在原位，而且下次运行即使没有新写入也能修复索引。

每个固定场景用真实模型在相同初始记忆和对话输入下，对基线和候选版本做五组配对。覆盖新增事实、修改已有事实和无持久信息的回合。记录每批模型请求数、索引写入及失败次数、provider 输入和缓存 token、耗时及新会话召回情况。更新样本须在基线上复现模型维护索引。验收目标为模型索引写入零次、更新样本的配对差中位数至少少一次模型请求，以及必记事实全部能从正确范围召回。
