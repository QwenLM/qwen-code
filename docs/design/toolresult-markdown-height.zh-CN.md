# 工具结果 Markdown 高度预算

[English](toolresult-markdown-height.md) | [简体中文](toolresult-markdown-height.zh-CN.md)

## 问题与范围

ToolMessage 以前只要收到终端高度预算就禁用 Markdown，导致简短的问题回答也
显示字面的粗体标记。本次恢复格式，同时保留高度限制，不改变工具执行行为。
这是仅涉及 CLI 的缺陷修复；不修改 core、配置、依赖或协议。

## 设计

- Shell 输出默认保持纯文本，包括强制显示、获得焦点或取消上限的情况。
  只有 shell 行数上限未生效时才遵循明确指定的 Markdown 请求。明确指定的
  纯文本以及经过安全过滤的原始文件详情仍按纯文本显示。
- 字符串结果仅在完整渲染高度可放入预算时使用 Markdown，否则回退到现有
  保留尾部的纯文本预览，包括首行或首个表格过大的情况。展开后恢复完整
  Markdown。可视化 Mermaid 与 display-math 工具结果在有预算时也使用纯文本
  预览，因为源文本行数不能限制图形或复制命令标题的换行高度。纯文本预览注册
  溢出，展开或卸载时清理；仅由 shell 行数上限产生的截断不提示可展开。
- 放得下的实时结果传递 pending 标志。完整适配探测与 MarkdownDisplay 的流式
  预留行数及末端布局一致，但会拒绝过大的首个表格：实时工具整体替换输出，
  不会将隐藏的前缀提交到滚动历史。因此超预算的实时结果保留最新尾部和隐藏
  行数，而不是使用助手式的头部切片。
  仅在探测 pending 文本时去掉尾部空白，与渲染器保持一致；已完成结果保持
  源文本不变。两种状态都忽略前导空行，并将每段普通连续空行按一个间隔计费，
  与 MarkdownDisplay 一致；不合并代码块或数学块内部的空行。仅根据渲染高度
  判断能否完整放下，不再以原始源码行数作为门槛。
- 带实际高度预算的已完成 enforceHeightBudget 调用方将 Mermaid 按代码、
  display-math 按字面源码显示，不把数学块内部重新解析成 Markdown，也不将
  不可见的 `$$` 分隔行计入完成态高度预算。这样放得下的后续计划步骤仍可见，
  且无需猜测图形高度；无预算的调用方保留可视化。计划确认将扣除边距和内边距
  后的实际正文宽度传给共享渲染器，使换行与高度计算使用同一宽度。
- 高度计算使用与 Ink 相同的 wrap-ansi 按词换行选项。计入列表缩进与标记、
  渲染模式的任务复选框、引用前缀、代码块内边距、行号栏以及 Tab 展开。行号
  按代码块自身行数计算，不使用整个缓冲区行数；每个 fitPendingSlice 调用方——
  共享 Markdown 渲染器、流式提交循环和工具结果完整适配探测——都遵循实时
  渲染模式与 showLineNumbers。
  非代码文本的 Tab 跳过可打印宽度快捷判断，使用 wrap-ansi 的制表位计算。
  流式 Mermaid 预览计入标题换行后的高度，每条源码按一行截断文本计费，不使用
  代码行号、源码换行或可见的结束围栏。受限的已完成 Mermaid 源码仍使用普通代码块计费。
- 复用表格渲染器的纯布局函数 renderTableText，删除独立的近似列宽算法。
  预算与渲染共享横向/纵向布局选择。布局前先检查最小高度（每条数据至少一行，
  结合截断上限，再加外边距）；若已超过剩余预算，则直接拒绝，避免对超大工具
  结果进行完整布局。流式切片可能将已关闭表格变为末端表格，
  如果只有流式布局放得下，就保留表格为末端并延后后续文本；否则在保留后续
  文本时按较高的布局计费。第一种布局已足以判定切断时跳过第二次布局。逐条
  已渲染行统计高度；受限表格只换行到可以判定溢出为止，不处理不可见尾部。
  分别预留外边距与提示；极小上限只显示并计入提示，
  不保留孤立的边框。
- 不将完整结果伪装成流式内容来获得截断能力。没有预算的调用方保持完整渲染。
  只有纯文本工具预览注册可展开溢出；计划和助手表格提示保持纯文本。保留
  既有的完整计划编辑器入口，不新增 Ctrl+S 行为。

## 约束与风险

共享高度计算也用于实时助手输出，因此已有流式渲染和源文本切分测试必须保持
通过。精确表格布局比近似计算需要更多工作，但消除了分叉的布局规则，且仅使用
已安装的辅助能力。已完成的超限工具结果在受限预览中有意失去 Markdown 格式，
但保留可见的尾部内容与现有按渲染行计算的隐藏行数。其他非流式 enforceHeightBudget
调用方（例如计划确认）仍显示头部预览：首个块过大时可能只剩提示，其计数是
源文本行数，而非渲染行数。不引入通用 Markdown 尾部切片器或布局缓存。

## 验证与验收

- 使用全局 qwen 在交互终端复现字面的 **Color**，再用本地打包 CLI 验证实际
  终端单元格为粗体且不含分隔标记。
- 使用真实 Markdown 渲染器，并实际限制 Ink 容器宽度。对段落、按词换行、中文、
  列表、代码行号与 Tab、窄表格/长单元格/不均匀列宽表格以及展开行为，断言实际
  帧高度与溢出状态生命周期。固定尾部可见性、最小预算下的首块内容、恰好适配、
  助手表格提示、raw 模式、受限可视化源码、任务列表、禁用行号、运行时模式
  切换、显式 shell 上限，以及工具预览展开、转为空文本或卸载时的溢出清理。
  前导、内部和尾部的普通连续空行不能导致放得下的 Markdown 被拒绝；执行态
  转为完成态时应保持格式化，并保留完成态的尾部间隔。超大的执行态和完成态
  工具表格应回退而不发生布局崩溃，并保留可见尾部及溢出提示。
- 通过回归测试保留 shell 行数上限、明确的纯文本与原始文件详情。运行相关工具、
  Markdown、表格、高度计算、MaxSizedBox 和流式测试，以及 build、bundle、
  typecheck、lint 与格式检查。
- 区分组件测试覆盖和交互 E2E 证据；对简短结果按 Ctrl+S 不代表验证了长结果展开。
