# Daemon token persistence

[English](2026-10-21-daemon-token.md) | [简体中文](2026-10-21-daemon-token.zh-CN.md)

Status: implemented.

## Scope

Adds an opt-in, owner-only bearer-token sidecar for a daemon started by `qwen daemon start --save-token`, plus `qwen daemon token` to read or remove it. The discovery record and daemon log never contain the token.

## Command

```bash
qwen daemon start --token <token> --save-token
qwen daemon token [--port <port>] [--json]
qwen daemon token --remove [--port <port>]
```

## Storage

- Path: `daemon-<port>-<pid>.token` beside `daemon-<port>.json` in the runtime discovery directory; the pid scopes the sidecar to one daemon instance.
- Directory `0700`, file `0600` on POSIX.
- The file is written only when `--save-token` is explicit and a bearer token was supplied.
- `daemon stop` removes the sidecar together with the discovery record; `daemon token --remove` removes it explicitly.

## Behavior

- `start --save-token` refuses before spawning when no `--token` or `QWEN_SERVER_TOKEN` is available.
- The token is persisted after the discovery record is published; a write failure is reported and exits non-zero while the daemon remains running.
- `daemon token` selects exactly one record, reads the sidecar, and prints it only on explicit invocation. `--json` returns `{ port, token }`; `--remove` returns `{ port, removed: true }`.
- `daemon stop` removes the sidecar on stale, graceful, and forced stops.

## Security

- Persistence is opt-in; the default remains environment/CLI supplied tokens.
- The sidecar is not referenced by the record or written to logs.
- Possession of the file is equivalent to possession of the bearer token. Removing the file does not rotate the running daemon's token; stop and start with a new token to rotate.

## Limitations and follow-up

- This covers explicit `--token` / `QWEN_SERVER_TOKEN`. A token generated by `--open-with-auth` is not persisted by `daemon start`, which has no generated-token path; that remains a follow-up.
- There is no token rotation command; rotation is stop + start with the new token.

## Verification

- Unit: command registration, sidecar write/read/remove, 0600 mode, stop cleanup.
- E2E: `start --save-token`, `daemon token`, `stop`, and confirm the sidecar is gone.
