### 2.2 当前模型，不代表实测安全容量

`resolveDaemonMemoryBudget` 和 `createChildHeapPolicy` 在 daemon
启动时解析一个分区。默认预算下的算术结果如下：

| 可用内存，MiB | 有效预算 | 根进程预留 | 子进程池 | 子进程名额 | 每个子进程上限，MiB |
| ------------- | -------- | ---------- | -------- | ---------- | ------------------- |
| 2048          | 1024     | 256        | 768      | 1          | 768                 |
| 4096          | 2048     | 256        | 1792     | 3          | 597                 |
| 6144          | 3072     | 307        | 2765     | 5          | 553                 |
| 7265          | 3632     | 363        | 3269     | 6          | 544                 |
| 8192          | 4096     | 409        | 3687     | 7          | 526                 |
| 32768         | 16384    | 1024       | 15360    | 25         | 614                 |

容量报告建议的 16 个并发 workspace 因而不是当前模型的限制。直接强制应用原分区，会在
7265 MiB 主机上拒绝第七个已承诺的子进程，尽管报告中的负载在 16
并发下成功。这是必须评估的兼容性取舍，不能据此由 RSS 推导堆大小，也不能悄悄用常量
16 替换现有模型。

`MIN_CHILD_HEAP_MB = 512` 是策略下限，不是实测需求。模型可以返回零名额和
null 上限，绝不能下发表示采用 V8 默认值的 `--max-old-space-size=0`。

### 2.4 证据质量规则

- 采集时保持 daemon 事件流连接，并在子进程退出前等到新的资源读数。子进程探针独立累计生命周期峰值，但 daemon
  采集受订阅者门控，缓存可能缺失或过期。
- 每份样本保留 `activeAcpChildren`、`children.sampled`、
  `children.oldestReadingAgeMs`、`children.heap.reported` 和
  `unclassifiedSpaceNames`。缺少上报者、读数过期或空间分类未知，都表示覆盖未知，不能当成零消耗。
- 公共堆汇总取当前存活子进程各字段独立的最大值。GC 次数和暂停时间不是总和，最大值也可能来自不同子进程。
  不能在进程集合变化时相减汇总最大值来计算每个子进程的 GC
  代价。应使用单子进程成对实验，或在实验脚本中采集每个代次的快照。替换前保存样本，已退出子进程会从当前汇总中消失。
- 没有观测到 major GC 时，`peakLiveSetBytes = 0` 不代表存活集为空。汇总 GC
  次数大于零，也不代表所有子进程都有 major GC 后样本。必须明确记录每个子进程缺失的证据。
- 已提交老生代峰值依赖堆上限。在较大上限下超过候选值，本身不能判定候选失败。由于 GC
  回调异步执行，存活集观测也是上界。结论必须由真实候选运行、覆盖质量和 GC 成本共同支持。

只有所有必需负载都有完整证据、在候选上限下完成、实测保留了低于上限的余量，并量化了 GC
和延迟变化，校准才通过。目前尚未校准通用余量比例或可接受的延迟退化；报告必须给出观测余量和明确选定的验收阈值。
证据不全时结果为待完成，负载失败时应先重新评估分区，再将其实现为受支持的策略。

### 2.8 新版配对协议与已完成的限定范围结果

v1 超时记录保持不变。新的 v2 协议保留原来的轻负载检查与重负载三文件比较目标，但使用一次固定的只读 Shell 命令完成计数。计数范围明确为 `packages/cli/src/serve/` 下 Git 跟踪的非二进制文件，按大小写敏感的字面量出现次数计数。独立 Python 字节计数器校验辅助脚本；成功命令的输出和模型最终 JSON 都必须与该基准一致。执行协议已经改变，因此 v2 结果不能与 v1 合并统计。

v5 的实验专用回环代理仅保留请求时间、模型、正文大小、顶层字段、工具名称，以及参数 schema 的大小与 SHA-256；不保留授权头、消息正文、schema 正文或响应正文。每个对照臂记录 36 个 provider 请求；24 个带工具定义的请求都只包含 `read_file`，没有 `tool_search`，且没有解析失败。这验证了 v5 重跑的请求表面，并补齐这次重试缺少的 schema 观测，但不能解释已保留的 v4c 尝试为何表现不同。

所有有效 Node 24 候选运行中的最大老生代峰值为 109.97 MiB，距离实验性 544 MiB 参数仍有 434.03 MiB。v5 候选并发的最大值为 93.71 MiB，余量为 450.29 MiB。这些是有界输入下的观测余量，不是生产安全余量。精确送达和用量计数不能证明语义理解或所有历史持续驻留；本地重复性 MCP 负载也不代表任意外部服务。tap 与诊断开销包含在测量中但未单独做基准，且没有引入强制 GC。

pilot 快照、失败尝试和原始哈希均保留。候选 pilot 在启动基线前通过 3,957 项独立检查；完整配对通过 6,318 项独立检查。最终验证确认 1,072 个冻结 bundle 文件、运行时与实验哈希、四个干净仓库、OOM 计数不变、无残留校准进程，并删除临时 provider 文件。对于该负载，Node 24 并发缺口已经关闭。证据支持保留 544 MiB 作为限定范围的候选；更广泛的负载、更大上下文、多小时稳定性、其他宿主分区及明确的 GC/延迟发布阈值仍待完成。生产堆强制模式仍未实现。

## 3. 已核实的实现边界

| 组件                                                      | 当前行为与设计影响                                                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `packages/acp-bridge/src/daemon-memory-budget.ts`         | 解析宿主/cgroup 分母、根进程预留和子进程池。                                                                       |
| `packages/acp-bridge/src/child-heap-policy.ts`            | 计算固定的建模上限与名额。`off` 关闭建模，`observe` 记录假设拒绝，`admit` 只强制子进程数量；尚无强制堆上限的模式。 |
| `packages/acp-bridge/src/spawnChannel.ts`                 | 先预留再决策；`admit` 下拒绝超容量启动，并可先请求一次空闲回收再重试。新子进程仍使用旧的宿主派生堆参数。           |
| `packages/acp-bridge/src/process-registry.ts`             | 统计预留与已连接子进程。正在终止的自有进程组会持续占用名额，直到进程清理证明释放。                                 |
| `packages/cli/src/serve/idle-acp-reclamation.ts`          | 容量用尽时，从受信任既有 runtime 中选择最近最少使用且完全空闲的 channel；排除请求方及有活跃或依赖工作的 runtime。  |

| `packages/cli/src/serve/run-qwen-serve.ts`                | primary、internal 和 secondary runtime 工厂共享同一个进程注册表、堆策略和空闲回收器。                              |
| `packages/cli/src/serve/server.ts`                        | direct-embed 默认启动及外部注入 bridge/factory 是独立路径，不能自动继承未来的堆强制声明。                          |

多个会话共享一个子进程。注册数量、会话数量、活跃 prompt 数和 `bridge.isChannelLive()` 都不能替代真实进程预留。channel 可能已在逻辑上不可用，但子进程或其自有后代仍处于终止过程中。因此 #12008 会在已跟踪清理完成前继续保留隔离状态与容量计数。

workspace 注册仍与子进程容量独立，即使建模名额全部占用也可注册。已交付的空闲回收器只处理完全空闲且符合条件的 runtime；没有可自动回收对象时，由用户主动停止接口展示剩余 workspace 选择。固定堆提案不新增注册上限或环境变量。

## 4. 拟议策略与生命周期

### 4.1 显式且不可变的策略

校准完成后，在现有 fast-path parser、完整 CLI parser、`ServeOptions`、策略类型和
SDK 镜像中一起增加 `enforce`，保持 `off` 与 `observe`
行为不变。在启动构造任何子进程工厂之前，一次性解析模式与预算。变更策略需要重启，不能缩小运行中的子进程，也不能随
workspace 注册重新计算授权。

强制模式要求使用内建 daemon 启动路径、同一个共享注册表和同一个共享策略。
对不支持的注入 bridge/factory 配置，应在监听前拒绝，不能接受一个不生效的模式。
零名额或 null 上限的强制配置应在预热前拒绝。Standalone ACP、IDE 和 direct-embed
调用者保留现有行为，除非明确进入另行记录的受支持路径。

具体而言，`runQwenServe` 必须拒绝 `enforce` 与 `deps.bridge`
同时使用，因为后者当前会关闭策略构造。公开启动工厂启用强制时必须显式传入共享
`processRegistry`，否则每个隐式私有注册表都会允许自己的完整分区。
直接调用 `createServeApp` 而没有 daemon 自有强制接线时，也必须拒绝该模式。
调用方提供的状态快照不能证明实际接线完成。

### 4.2 预留、判断、启动与释放

复用 `ProcessRegistry.reserve()` 与 `committedProcessCount`。
在现有同步顺序中先预留，再将本次预留纳入数量进行判断。强制策略拒绝时，取消该预留并在
`spawn()` 前抛出有类型的容量错误。策略判断或 spawn 抛异常时，现有
try/catch 也必须释放预留。

获准后，即使固定上限低于父进程的堆上限，也必须显式下发
`--max-old-space-size=<ceiling>`，同时保留 `--expose-gc`。
验证它优先于继承的 `process.execArgv` 和 `NODE_OPTIONS`，包括当前 Node
版本支持的等价或冲突堆参数；只在强制路径中移除或拒绝冲突输入。旧版参数缓存或另一个工厂不能为后续子进程提供不同的上限。

已经确认一种冲突参数：
[`--max-old-space-size-percentage` 的优先级高于固定值参数](https://nodejs.org/api/cli.html#--max-old-space-size-percentagepercentage)。
本地 Node 22.22.3 探针在固定 512 MiB 时报告总堆上限 560 MiB；同时加入百分比
20 后，无论参数前后顺序，还是经 `NODE_OPTIONS` 传入，都变成 9878 MiB。
这些是启动参数观测，不是内存分配量或负载结果。强制路径必须拒绝冲突的百分比选项，归一化继承的固定
old-space 选项后再添加唯一的固定授权，保留无关的 loader 参数。不能断言 V8 的总
`heap_size_limit` 等于 old-space 授权，因为它包含其他堆容量。

附加成功后由进程注册表负责释放，保留取消、启动失败、退出和进程树清理语义。
发送信号或关闭 ACP 流不能证明根进程已退出。当前注册表在清理中保留已知自有进程组，但可能先释放根进程/已知范围，再报告清理证明错误；
Windows 上也可能在根进程退出后释放名额，即使杀死整棵树失败。因此不能将其升级为所有可能后代都已观测或终止的承诺。
已知仍存活的被跟踪进程继续计数，保留既有清理失败报告，并将后代进程/RSS 保证排除在本策略之外。替换时新旧子进程各占一个名额，直到旧进程真正释放。
满容量时可以拒绝替换；首版不提供预算外的替换余量，也不创建无界等待队列。现有 drain/rollback
行为继续由对应 workspace 代次负责。

承诺仅为 `committed child count × fixed old-space ceiling <= childPoolMb`。
它不约束进程 RSS、年轻代、外部缓冲、MCP 服务、channel worker、终端或整个 daemon 进程树。

## 5. 失败与状态契约

复用现有的子进程容量耗尽共享类型错误 `acp_child_capacity_exhausted`。REST 返回 503；ACP 使用既有错误信封，带等价的机器可读错误码及 HTTP 状态元数据。不自动重试，也不回退到 primary workspace。

逐一检查可能启动子进程的操作：会话创建、恢复、resume、fork、prompt 恢复、runtime
ensure/restart、启动预热、channel 管理和定时执行。跨 await
保留已解析的 workspace/session owner。会话的 worktree/branch/fork 路径可能在获取 channel
之前已经修改持久状态，因此工厂拒绝不能统一承诺 `sideEffectPossible: false`
或整个请求可以安全重试。保留各路由既有 outcome 与回滚元数据。后台启动和定时任务应通过各自既有的
owner 报告路径记录失败。

Conversations 需要明确保留原始原因的路径：`StandaloneSessionSpawnError`
会包装工厂错误，而 `standalone-session-service.ts` 当前会将未派发失败转换为
`standalone_creation_rolled_back`。执行既有回滚并保留其结果后，还要保留容量原因，不能把普通容量压力转换为终止隔离状态。
只修改全局 REST 和 ACP 错误映射会漏掉这条路径。

Runtime coordinator 也有一层包装：预热和 MCP 准备会将失败包装为
`WorkspaceRuntimeInitializationError`，REST 随后映射为
`runtime_initialization_failed`。这层也要保留容量原因，同时优先保留
代次关闭/draining 错误及既有 outcome。满容量 runtime-ensure
测试必须检查返回的容量原因，不能仅断言 HTTP 503。

当前源码将 `limits.memory.enforced` 定义为子进程堆标记。只在行为 PR
中扩展其类型，且仅对完整接入的内建强制路径设为 true，明确覆盖范围是 daemon ACP
子进程堆。同步更新 `mode`、拒绝次数语义和 SDK 类型：观察模式拒绝仍是假设判断，强制模式拒绝表示确实没有启动新子进程。
检查所有读取方，不能把新枚举值仅当作文档修改。

Workspace 注册保持独立，子进程名额全部占用时仍可成功。现有的可回收空闲对象 LRU 与用户主动停止行为保持不变；本提案不新增注册上限、会话驱逐或环境变量。
