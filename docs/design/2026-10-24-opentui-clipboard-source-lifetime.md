## Minimal proposed changes

1. Move existing CLIPBOARD_PASTE_FRAMING, wrapClipboardPaste, framePasteExpansion and unframeClipboardPastes verbatim into the existing pure paste utility (or one adjacent pure module if house size requires). Export the currently local frame function; keep existing Ink call classification and exports. Preserve exact matching, whitespace, escaping and no-match behavior. Existing expandPendingPastePlaceholders/restorePasteDraft retain their raw semantics. This is shared code used by both actual submitters, not a new abstraction layer.
2. OpenTUI submitDraft claims raw text, source snapshot and the existing draft before waiting. After its pending operations settle, choose model text from actual shell mode and final attachment set: shell raw; attachment-free slash raw using the same shared isSlashCommand classifier as Ink; otherwise frame matched collapsed pastes once. humanInput is always raw expanded text and only populated under existing known-input rules. displayText stays editable placeholders, submittedPrompt retains the actual user form, and imagePaths remain separate. Image-bearing slash remains a model prompt. Do not append attribution at paste, queue dequeue, @file expansion or Retry.
3. Keep source maps under the existing draft owner across an async clipboard completion. Prefer a captured existing map reference; if a map must be attached to Draft, it aliases the same existing pending map rather than introducing a second store. Actual writers are newDraft/restorePasteMap and admission; readers are late paste completion, submit snapshot, rejection restore and Vim capture. A claimed draft owns its map while the active successor owns a different map. The claim keeps its submit-time mode; a rejected admission restoring the current successor reads the successor's current mode, including a shell toggle while admission was pending. Never read the successor's current map/mode for the old operation. Late text fallback uses the same collapse/placeholder logic under that captured owner, including when submit has already claimed it. Identifier allocation derives from the captured map; collision restore continues through restorePasteDraft. No new persistent source or provenance schema.
4. Ctrl+V image absence or save failure calls existing readClipboardText, then the same ordinary pasted-text admission path; only supported Linux offers are in scope. Empty/null reads add nothing. The whole operation checks captured draft.valid/session owner after every async boundary before notices/insertion/attachments/submit. No resend, no paste broadcast duplication, no global clipboard mechanism. Bracketed image-path promotion is gated by !shellModeActive; shell paths remain literal command arguments. Preserve documented OpenTUI all-or-nothing invalid-image-path handling and shell+actual-attachment rejection/retention, rather than silently broadening this batch into Ink's known image-in-shell defect.
5. Preserve structured queue/steering and cancellation APIs. An unchanged popped single entry keeps its captured modelText, human subset and image paths; never recompute it from files or clipboard. If multiple already-framed entries merge into one editable submission, remove only each source-backed exact framing suffix before joining and append one suffix for the merged actual framed blocks; preserve escaped wrappers and all nonframing model payload fields. Never infer human origin by recognizing a marker. Edited restores use existing maps/collision logic and keep unknown members unknown; add a real joined consumer regression before choosing the final few-line normalization location. No dead optional switch and no second queue. App-shell deferred prompts must forward existing metadata intact; live-turn's unchanged modelText override is part of the review, not bypassed by a component-only green test.
6. Apply existing unframe at the composer history refill boundary (ordinary history and accepted reverse search), not inside the history store. userMessages often already use recallText, so this is idempotent compatibility for framed saved history. Search Esc restores exact original text/map/unknown snapshot; Up/Down shell history stays raw. Recall never grants known humanInput to imported/unknown history. External editor sees raw expanded text, keeps unchanged maps/undo semantics, and uses the same final submit; Vim Enter, normal Enter, completion submit and Ctrl+Q all reach that one finalizer.

A claimed submission retains its submit-time mode. When a rejected admission restores the current successor, classification reads the successor's current mode, including shell changes while that admission was pending. The two directions have a real composer regression; this does not claim terminal-level mode-switch coverage.

## Required invariants

- Two genuine collapsed pastes produce two escaped blocks and one exact suffix. Deleted/no matched placeholder produces no suffix. Literal tags, preescaped tags, backslashes, Unicode, CRLF normalization and placeholder collision preserve raw human bytes according to the existing helper's rules; do not invent byte-perfect whitespace semantics beyond Ink's current trim behavior.
- raw humanInput, user submitted/display/recall text and model framing stay distinct through queue, steering, rejection, cancel settlement and resubmit. Unknown/mixed restore retains only previously known human members; recognizing framed text is not evidence of provenance.
- Submission waits only its own pending operations. A late old read/copy cannot enter successor draft, a replaced session, cleared/unmounted editor or cancelled claim. Rejected acceptance restores matching images/text/maps exactly once, merging with successor through existing collision helper.
- Shell and attachment-free slash receive raw text; shell path-only paste does not become an image chip. Existing explicit shell-image rejection is retained. Model image bytes/MIME and image-only Enter no-op remain unchanged. No extra @file expansion or image transformation on Retry.
- Framing occurs once per newly admitted model submission. Prepared Retry is untouched; accepted steering is not appended twice. This fixes source interpretation, not a new permission or a promise to prevent all prompt injection.

## Regression and actual acceptance plan

Preserve full existing files; add collocated cases, not only snapshots or helper-only selftests.

The permanent clipboard product case keeps its original exact first-paste assertion for Node+Ink, Bun+Ink and strict OpenTUI. Only the native branch additionally recalls the original raw text, performs a source-defined edit at the unwrapped second-line end, explicitly resubmits, and verifies two closed HTTPs plus the two real model-facing JSONL user records (UUID, session, promptId, parent linkage and ancestry). Its oracle comes from original typed bytes, not model output. Raw journal files are retained from finally even on assertion failure. Ordinary TUI humanInput persistence is not established by these model records.

Current Ink history records the compact display placeholder, so the additional native raw-recall contract is not claimed as three-renderer parity. Preserve the failed Ink reference and its explicit follow-up [#15397](https://github.com/QwenLM/qwen-code/issues/15397) to recover original paste contents; do not turn that placeholder behavior into an accepted green expectation or skip the first-paste case. The native-only continuation is a declared behavior boundary, not a skipped test. Independent strict proof already exists; the newly integrated permanent version still requires fresh whole-file three-leg verification.
