# Web Shell 上下文概览与手动压缩

[English](2026-09-12-web-shell-context-compaction.md) | [简体中文](2026-09-12-web-shell-context-compaction.zh-CN.md)

## 问题与现有行为

输入框提示、对话中的上下文卡片和右侧上下文面板已经展示 token 用量。分类汇总
与具体明细分开排列，读者需要再次寻找同一个分类。剩余容量不够突出，面板也
没有直接执行已有 `/compress` 命令的入口。

## 目标与范围

在同一轮改动中完成上下文展示优化与手动压缩。复用现有用量数据和压缩行为。
不增加 daemon 路由、不改变压缩算法、不虚构系统提示词的子分类，也不改变
点击输入框圆环后在对话中查看上下文的行为。

## 展示方案

悬浮提示从已有本地计数展示精确的已用、总量和剩余 token，Hover 不发起请求。
剩余容量是上下文窗口减去已用量后的非负值，包含压缩缓冲区，不能标成空闲。

两个完整上下文入口共用概览、已用/空闲/缓冲区图例和高级分类折叠区。明细
直接放在所属分类汇总下面，保留内置工具与 MCP 工具的区分、完整名称、已加载
技能正文和 token 排序。继续使用连续的比例条与现有警告/错误阈值。数字使用
可读的主题颜色和等宽数字。侧栏分类默认收起，对话明细默认展开；折叠状态只
在本次挂载期间保留。

对话读数明确标注为快照。有操作能力时，完整快照提供已有的当前上下文读取
入口。刷新与压缩不会改写旧快照。尚无首次用量读数时，保留预估开销视图，
避免让人误以为已经测得零用量。

## 手动压缩与会话归属

当前上下文面板在刷新旁提供手动压缩。通过所属实时会话现有的 prompt 生命周期
执行规范命令 `/compress`，等待完成，展示进行中和失败反馈，防止重复提交，
并在完成后刷新当前上下文。取消反馈只确认请求已发出；现有后端仍可能在
取消后完成压缩，因此不能宣称压缩已经停止或成功。取消后的手动刷新同步
当前读数和输入框计数。

操作能力由所属主视图或分屏提供，包括实时忙碌、连接和写入阻塞状态。在调用时
和异步完成后重新检查归属与可用性。分屏中的会话必须使用自身面板的控制能力，
注册和清理期间也不借用主会话能力；主会话不在分屏集合中时保留自身的操作能力。
恢复出的其他会话标签页保持只读，直到
对应实时视图提供操作能力。恢复标签的读取适配器可能继承无关会话的动作，
因此不能将它当作修改权限的来源。切换会话、关闭分屏或卸载面板不能让旧结果
应用到新会话。提交前，由来源视图清除上一条请求的重试状态和过期后续建议。
保留普通输入框中的草稿与附件。

已结束的压缩结果随会话在主视图和分屏之间保留。应用保存最后一次结果，但不向
已卸载的分屏授予操作权限。仅在捕获的连接归属仍有效时对计数读取去重。
切换会话或回放恢复可能在同一读取函数上重置旧计数，因此新的有效归属需要
重新同步。同步失败后仍可使用刷新恢复。自动同步跳过命令失败结果；任何已
结束结果后的面板打开或显式刷新，仍会同步新读取的快照。新的实时结果优先于保留的
结果，避免第二次压缩失败时恢复更旧读数。同一会话更换读取方时保留面板当前
读数。重新打开面板时可以使用已完成的压缩读数；如果新读取瞬时失败，明确
提示当前显示先前读数，不宣称已刷新。刷新成功后清除该提示。分屏压缩主会话
时，也在提交前清除主视图中普通请求的重试状态，不清除其他会话的重试。

仅已公布的内置 `compress` 命令允许启用操作，同名自定义命令不代表压缩能力。
复用现有 Goal gate 和来源视图的忙碌/写入检查。压缩输出不包含普通用量元数据，
因此完成后的读取通过 `getContextUsage({ syncCounters: true })` 显式同步输入框
计数。此选项不修改计费用量或历史，仅在会话和模型仍相同、读取期间没有更新
用量到达时生效。代表未知计数的零值保留已有读数，压缩后的正数估算值仍然
有效。压缩成功后的刷新失败独立提示，不能自动重复压缩。

## 实现区域

- `ChatEditor` 及测试：轻量悬浮提示中的剩余容量。
- `ContextUsageMessage`、样式与测试：共享概览和分类内明细。
- `ContextUsagePanel`、样式与测试：压缩操作与反馈。
- `App`、`ChatPane`、`ArtifactPanel`：实时归属操作及其生命周期。
- 会话动作：显式同步所属输入框计数。
- 中英文文案与浏览器上下文场景。

## 风险与验证

主要风险是过期操作或跨会话修改。验证活动与空闲会话、快速重复点击、任务
执行中、断线、取消、切换会话和恢复的其他会话标签。验证压缩后的计数并保留
旧快照。检查零用量、估算值、超限、长名称、键盘折叠、浅色/深色主题以及窄
输入框和面板。

先用全局 CLI 确认基线，再验证本地构建应用，执行根目录 build/typecheck/bundle
及受影响包测试。对完整改动执行无方向与反向审计，直到连续两轮没有问题。
在 PR 中使用 fork 的 assets 分支托管真实的修改前后截图。

## 验收标准与未决问题

三个入口对已用和剩余容量的口径一致。分类明细只在所属汇总下展示一次。
仅所属会话空闲、可写且实时连接时允许压缩，进行中、失败和完成状态可见。
当前用量刷新，历史读数保持不变。后续压缩失败不能用旧结果替换面板较新的
读数。瞬时刷新失败后的回退读数必须明确标记为先前读数，并可通过刷新恢复。
没有未决产品问题。
