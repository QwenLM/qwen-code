# Standard Guest Entrypoint and Offline Golden Image Derivation for `/verify-pr` MicroVMs

[中文版本](2026-11-28-verify-pr-vm-guest-init-and-image.zh-CN.md)

**Status: implemented and verified on macOS arm64 and Linux aarch64 KVM; PR review and remote CI remain separate gates. Date: 2026-11-28.**

## 1. Context and Goal

With PR #18552 merged, the host-side `/verify-pr` microVM pipeline (`probe` → `select --probe` → `stageLocalVmRound` → `runHardwareRound` → `reapOwnership` → `verify-pr-check`) lives completely in-repo. However, two remaining Phase 2 pieces still lived in ad-hoc out-of-tree PoC scripts:

1. A standard PID-1 guest init entrypoint and zero-dependency guest lifecycle runner that orchestrates the 3-port guest vsock channel (`fetch-inputs`, `model-bridge`, `upload-artifacts`), entropy mixing, isolation checks, bundle materialization, credential-stripped workload execution, and clean poweroff.
2. An offline, read-only golden ext4 rootfs derivation tool that injects those audited guest scripts into a derived image without loop mounts or mutating the golden source.

This change brings both pieces formally into `scripts/`, completing Phase 2 with zero out-of-tree PoC glue, and also folds in the two non-blocking follow-ups recorded during PR #18552 review (`ensureApprovedDirHierarchy` accepting directory equality with a normalized `approvedRoot`, and recording `createdDirs.push(nextDir)` immediately after `mkdirSync` before `chmodSync`).

## 2. Scope and Hard Constraints

- **Allowed scope:** `scripts/verify-pr-vm-guest-init.sh`, `scripts/verify-pr-vm-guest-runner.py`, `scripts/verify-pr-vm-image.mjs`, `scripts/verify-pr-vm-host.mjs`, collocated unit tests (`scripts/tests/verify-pr-vm-{guest-runner,image,host}.test.js`), and this bilingual design document.
- **Out of scope (untouched):** `packages/`, `.github/`, `.qwen/skills/`, `/review`, cloud resource allocation, external model calls, and real credentials.
- **Backward compatibility:** existing default launch `bootArgs` (`init=/opt/poc/init`), manual `stageAssets: false` flows, and legacy `container`, manual `vm`, and `waived` `/verify-pr` flows remain unchanged.

## 3. Design Decisions

### 3.1 Minimal PID-1 Guest Init (`scripts/verify-pr-vm-guest-init.sh`)

- Pure POSIX `#!/bin/sh` (zero `shellcheck -s sh` warnings), compatible with BusyBox and Debian rootfs layouts.
- Mounts `/dev` (`devtmpfs`), `/dev/pts` (`devpts`), `/dev/shm` (`tmpfs -o mode=1777,nosuid,nodev`), `/proc`, `/sys`, `/run` (`tmpfs`), prepares a disk-backed `/work` (`0700`) for `HOME`/`TMPDIR` (avoiding RAM-only `/run` tmpfs exhaustion on large bundles/checkouts), optionally loads `virtio_vsock`, brings up loopback `lo` only (zero external NICs), exports a clean credential-free environment, invokes `guest-runner.py --from-cmdline`, syncs, and powers off cleanly when running as PID 1 so the guest exits without a kernel panic.

### 3.2 Zero-Dependency Guest Lifecycle Runner (`scripts/verify-pr-vm-guest-runner.py`)

- Pure Python 3 standard library; loads sibling `verify-pr-vm-guest-vsock.py` (or `/opt/qwen/guest-vsock.py` inside the derived image).
- Executes a 7-step fail-closed lifecycle:
  1. Fetches `manifest.json` (shape-validated) and `round.bundle` (verified against manifest `bundleBytes` and `bundleSha256`) via port 53 (`--unix-input` supported for host-side testing), and writes `entropy.hex` from `manifest.entropyHex`.
  2. Decodes 64-hex `entropyHex` and mixes the 32 bytes into `/dev/urandom` (configurable `--urandom-path` for testing); failed writes fail closed (`written: false`).
  3. Inspects `/sys/class/net` and `/proc/mounts` to verify loopback-only interfaces (`noNic`) and absence of shared host mounts (`virtiofs`/`9p`/`vboxsf`/`vmhgfs`/`fuse.sshfs`); missing or unreadable sysfs/procfs paths fail closed (`netInspected: false` → `noNic: false`; `mountsInspected: false` → `hasDirectoryShare: true`).
  4. Materializes a clean Git workspace under `work_root/repo` from `round.bundle` and verifies exact `baseRefOid` and `headRefOid` commits, or — only when explicitly opted in via `--skip-materialize` / `qwen.skip_materialize=1` for git-less minimal BusyBox images — creates `work_root/repo` and verifies the Git v2/v3 bundle header in pure Python (`verify_bundle_header`), requiring `headRefOid` as an advertised ref (never prerequisite-only) and `baseRefOid` as either an advertised ref or `-<oid>` prerequisite.
  5. When `manifest.modelProxy` is non-null, launches `model-bridge` on `127.0.0.1:0` over the negotiated `manifest.modelProxy.port` (falling back to `--model-port` / 54; `--unix-model` for tests) and verifies exact `GET /__health` raw nonce equality (`res.end(nonce)`) before starting any workload; mismatches fail closed and stop the bridge immediately.
  6. In workload mode (`--workload` or `/opt/qwen/workload.sh`), refuses to launch the workload if entropy injection or isolation checks failed, otherwise records `logs/guest-runtime.json` and runs the workload in a stripped environment in its own process group (`start_new_session=True`) under a bounded timeout (`DEFAULT_WORKLOAD_TIMEOUT = 30`s, fitting inside the collector's 45s default accept window with 15s headroom; killing the entire process group on timeout and raising on any non-zero exit code). In built-in self-test mode (no workload), emits `verify-pr-check`-compliant `report.md`, `verdict.txt = inconclusive` (recording `workload-completed: false` with `attribution: "harness"` so a plumbing-only round never certifies `merge-ready`), `assertions.json`, `comment.md` (rendering the attribution footer only when a valid 12-hex `qwen.skill=<12-hex>` / `--skill-digest` is supplied), and `logs/guest-runtime.json`.
  7. Wraps steps 4–6 in `try`/`except`/`finally`: unhandled exceptions (including timeouts and non-zero workload exits) write demoted `inconclusive` artifacts (`workload-completed` + `guest-lifecycle-error`) into a fresh private directory created after teardown (`qc-demoted-*`, outside `artifacts_dir` and `work_root`) so neither pre-written `merge-ready` files, sabotaged `logs/guest-runtime.json` directories, nor a detached `setsid` descendant rewriting `artifacts_dir` can override the uploaded verdict; `finally` stops `model-bridge`, uploads from `upload_dir` over port 52, and cleans up `demoted_dir`.
- Parses `qwen.*` tokens from `/proc/cmdline`, rejecting non-positive integer values for `cid` and `workload_timeout`, out-of-range (`1..65535`) ports, and non-12-hex values for `qwen.skill`. On the host side, `deriveCollectorAcceptDeadlineMs` in `scripts/verify-pr-vm-runner.mjs` scales `collectorOptions.acceptDeadlineMs` to `min(24h, max(45_000, workload_timeout * 1000 + 30_000))` whenever `qwen.workload_timeout=<N>` is present in the launch plan's cmdline and the caller did not specify an explicit `acceptDeadlineMs`.

### 3.3 Offline Read-Only Golden ext4 Image Derivation (`scripts/verify-pr-vm-image.mjs`)

- Validates the source ext4 superblock at byte offset `1024` (`s_magic = 0xef53`, `s_log_block_size`, 32/64-bit `s_blocks_count`) **before** any copy or resize, failing closed if the declared filesystem size exceeds the physical file length so truncated transfers can never be zero-filled by `truncateSync` + `resize2fs -f`.
- Copies the read-only golden ext4 image into an exclusive private temp file (`O_CREAT | O_EXCL | O_NOFOLLOW`, `0o600`, zero loop mounts, never opens the golden source for writing), optionally grows the offline filesystem copy via `truncateSync` + `resize2fs -f` when a larger `--size-mib` is requested, and injects the audited guest scripts plus optional workload and `--bundle-host-python` directly into the copy via a single batched `debugfs -w -f` script with explicit `0:0` ownership and POSIX modes (plus `tune2fs -U random` when available so `e2fsck -fn` stays 0-error clean).
- Because the base image is never unpacked through the host filesystem, every existing inode in the golden source — including arbitrary UID/GID ownership on regular files and symlinks (even when all regular files match the builder UID), named pipes (FIFOs), sockets, device nodes, shared hard links (`nlink > 1`), extended attributes (`xattrs`), and permissions — is preserved bit-for-bit even when running as non-root.
- Rejects quotes (`"`), backslashes (`\`), newlines, and NUL bytes in both `normalizeImageTargetPath` and `escapeDebugfsArg` so real `debugfs` never silently writes a target under a mangled name. Before writing anything into `tmpOut`, inspects `/` and every ancestor directory and target leaf via read-only `debugfs -f` (`stat`): fails closed on corrupt/non-ext4 images (`/` not a directory), refuses any ancestor directory that is a symlink or non-directory inside the untrusted base image (covering `/opt`, `/opt/qwen`, `/opt/python`), unlinks existing file/symlink leaves before `write`, and refuses to overwrite non-file leaves.
- Reuses `normalizeApprovedRoots`, `canonicalizeVaultDir`, `canonicalizePreservingLeaf`, and `isPathWithinApprovedRoots` to enforce `approvedRoots`, `vaultDir` exclusion (including `baseImagePath`, injected sources, `pythonBin`/`pythonLibDir`, and outputs), single-link non-symlink inputs, optional `expectedBaseSha256` pinning, no output overwrites, and in-image target path normalization (`normalizeImageTargetPath`). Stages each injected file into a private `0700` scratch directory and re-hashes it post-copy against its pre-copy SHA-256 before passing it to `debugfs write`.
- Re-hashes `baseImagePath` and hashes/verifies `tmpOut` **before** publishing via atomic `linkSync` (treating `unlinkSync(tmpOut)` as best-effort cleanup with unconditional `finally` removal so a transient `EBUSY` on the temp name never fails publication or strands an unretryable target).
- Provides optional `--bundle-host-python` using native `cpSync` and `readdirSync` (no hardcoded `/bin/cp` or `/usr/bin/find`) plus `ldd` to stage host Python 3 and its shared libraries and write them under `/opt/python` (cleanly replacing any pre-existing `/opt/python` subtree when re-deriving).

### 3.4 PR #18552 Non-Blocking Follow-Ups and Staging Guard (`scripts/verify-pr-vm-host.mjs`)

- `ensureApprovedDirHierarchy` accepts directories equal to a normalized `approvedRoot` (e.g. `copyIsolatedAsset(src, join(root, 'kernel'), { approvedRoots: [root] })`), while keeping strict child containment for file destinations.
- Moves `createdDirs.push(nextDir)` immediately after `mkdirSync(nextDir, { mode })` and before `chmodSync(nextDir, mode)` — while skipping any `nextDir` equal to a normalized `approvedRoot` — so a concurrent `chmodSync` failure rolls back newly created child directories without ever attempting to delete an `approvedRoot` itself during rollback.
- In `stageLocalVmRound` for Firecracker, fails closed and rolls back if the staged rootfs byte size exceeds the `fsize=<bytes>` limit declared in `plan.argv` (`--resource-limit fsize=<bytes>`). Because `guest-init.sh` places `/work` on the rootfs disk, launching a 512 MiB derived image under jailer's 256 MiB default `RLIMIT_FSIZE` would otherwise kill Firecracker mid-write with `SIGXFSZ` (signal 25).

## 4. Acceptance Criteria

1. `verify-pr-vm-guest-init.sh` passes `sh -n` and `shellcheck -s sh` with zero warnings, uses `/work` for `HOME`/`TMPDIR`, and mounts `/dev/pts` and `/dev/shm`.
2. `verify-pr-vm-guest-runner.py` completes the full 7-step lifecycle through `runHardwareRound` over real 3-port Unix sockets (input 53 + model proxy 54 + collector 52 + `verify-pr-check` exit 0), writes 32 decoded entropy bytes, strips host secrets from workload environments, emits `verify-pr-check`-passing `inconclusive` reports with `attribution: "harness"` when entropy/NIC/mount checks fail, refuses workload launch on isolation/entropy breach, supports `--skip-materialize` + `--workload`, honors negotiated `manifest.modelProxy.port`, rejects wrong `/__health` nonces before workload execution while still uploading diagnostics in `finally`, rejects invalid `qwen.*` cmdline integers, fails closed when sysfs/procfs paths are unreadable, and rejects prerequisite-only `headRefOid` bundle headers.
3. `deriveExt4GuestImage` and its `derive` CLI enforce `expectedBaseSha256`, `approvedRoots`, `vaultDir` (including symlinked vaults), single-link non-symlink inputs, no overwrites, in-image path traversal refusal, pre-`mkdirSync`/pre-`rmSync` hostile extract-tree symlink escape refusal (ancestor `/opt`, leaf `/opt/qwen`, `/opt/python`), `debugfs` stderr/empty-tree failure detection, spaced `tempParentDir` and symlinked `mkfs.ext4 -> mke2fs` support, temp cleanup + size hint on `mkfs` failure, and post-build golden SHA parity.
4. On real Linux aarch64 KVM, a 100% repo-only round (`verify-pr-vm-image.mjs derive` → `runHardwareRound({ stageAssets: true, runChecker: true })` → PID-1 `verify-pr-vm-guest-init.sh` → `verify-pr-vm-guest-runner.py`) completes with `ok: true`, `checkExitCode: 0`, `boundary.json (mode: "microvm")`, `entropy.written: true`, `isolation.noNic: true`, `isolation.hasDirectoryShare: false`, `modelProbeStatus: 200`, zero residual `jailRoot`, and unchanged golden kernel/rootfs hashes.
5. `copyIsolatedAsset(src, join(root, 'kernel'), { approvedRoots: [root] })` succeeds while `copyIsolatedAsset(src, root, { approvedRoots: [root] })` remains refused, and `stageLocalVmRound` rolls back newly created child directories on `chmodSync` failure without attempting to remove an `approvedRoot`.
