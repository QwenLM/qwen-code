# Code Mode 的 Goal 证据

[English](goal-code-mode-evidence.md) | [简体中文](goal-code-mode-evidence.zh-CN.md)

## 问题

Goal 验证器原先把每个外层 `exec` 结果都作为 `external_fact`。JavaScript 可以输出任意文字、复制 Goal 元数据或改写嵌套工具的结果。Headless 和 TUI 聚合宿主又会延后外层记录，使嵌套调度器没有记录器。因此，改写后的包装输出可能成为实际工具工作的唯一记录。

本修复处理审查 #13033 时发现的既有证据机制问题。默认工具按需加载仍是独立改动。

## 契约

脚本输出以 `execution_output` 保留，供检查和计算使用；它不能证明用户授权、Goal 状态、测试、文件、工具执行或远端状态。这些声明需要独立记录的原始工具结果，用户行为仍需要 `user_input`。Goal 元数据继续排除在工作证据之外。

## 记录

共享 Goal 来源分类函数根据调用身份，把直接或 bridge 包装的 `exec` 结果标记为 `execution_output`，不分析输出文字。Headless、TUI 和 ACP 等现有记录消费者都使用这条共享路径。

核心调度器保留已完成统一处理的内部结果。聚合宿主未提供记录器时，只有携带父调用 Goal permit 的 `code_mode` 请求，才可以使用同一 Config 的记录器；不会选择其他 Config 或主运行时。显式记录器的现有归属保持一致。该 Config 关闭记录时，不会生成回退记录。

内部结果使用 `code_mode_tool_result` 子类型。实际读取和错误仍是 `tool_result`，`get_goal` 和 `update_goal` 仍是 `goal_runtime`。外层聚合宿主只记录一次自己的结果。

## 证据与恢复

证据窗口包含原始内部工作结果，并单独分类外层脚本输出。旧的直接 `exec` 记录根据结构化响应名称识别；旧的包装记录根据同一 Goal turn 中对应的函数调用身份识别，支持 bridge 目标名称的大小写变体。其他 Goal 版本或 turn 的调用 ID 不会改变分类。

API 历史与共享 ACP 回放投影跳过 `code_mode_tool_result`，因为内部调用没有模型发出的函数调用与之配对。文档导出复用共享回放投影；导出归一化与文件统计在匹配外层调用之前排除内部结果。已完成回合的分支检查点在跟踪待完成调用、校验外层工具循环时忽略内部结果。完整会话仍保留它们供 Goal 验证，恢复给模型的历史只保留外层调用与结果。会话校验器和受管理会话的记录入口识别新子类型。当前读取器仍接受既有会话类型和旧证据类型，无需修改 Goal 状态版本。旧二进制不认识新子类型，恢复新会话需要更新读取器。

## 约束与风险

权限、hooks、取消、终止提案屏障、证据字节限制和进度计数保持现有行为。不新增执行层或依赖。证据分类是确定的，但最终语义判断仍由模型验证器完成；这不是对所有提示注入的防护保证。有限窗口仍可能省略较早的事实，此时必须拒绝证据不足的提案。

## 验证与验收

- 使用真实 Exec、Goal 运行时、记录器和文件工具的回归检查在修复前失败：聚合路径没有原始内部结果。直接记录和延后外层记录都必须保留原始结果，且外层结果不会重复。
- 脚本静默读取文件、回显 Goal 元数据、吞掉文件不存在错误、编造文件与测试声明，并计算 `42`。只有原始读取与错误是 `external_fact`，计算仍以 `execution_output` 保留，Goal 元数据不进入证据窗口。
- 旧的直接与包装脚本记录仍分类为脚本输出，其他 turn 的事实保持有效。
- API 历史、ACP 回放和导出只包含外层调用与结果，不会虚构内部调用。保留原始内部证据的同时，文档完整性、直接调用的文件统计与已完成回合的分支检查点仍然有效。
- 聚焦 Goal、Code Mode、记录与历史测试，以及构建和类型检查通过。独立测试代理验证打包 CLI 的实际 headless 记录和验证器请求，并检查权限拒绝与终止屏障。

先尝试全局 CLI 基线。若已安装版本不支持 Code Mode，明确记录此限制；历史原生输入回放与新的本地 CLI 验证分别报告。
