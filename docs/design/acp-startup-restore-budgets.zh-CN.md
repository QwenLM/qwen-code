# ACP 启动与会话恢复预算

[English](acp-startup-restore-budgets.md) | [简体中文](acp-startup-restore-budgets.zh-CN.md)

## 问题

PR #14985 为子进程创建与 ACP initialize 握手分别提供预算。每阶段获得 `initializeTimeoutMs`（`T`），两个阶段共用 `2T` 的绝对截止时间。失败清理还可能额外等待最多 `T`；必须保留优雅终止和强制结束的升级流程。

目前会话恢复在取得通道后才启动超时计时。因此，9 秒进程创建、9 秒握手与 53 秒恢复会在第 71 秒完成，超过 SDK 默认的 70 秒请求截止时间。真实 bridge 配合确定性 ACP 传输已在 load 和 resume 两条路径中复现这一行为。

## 范围与决策

保持 initialize 配置、默认值、协议 limits 和客户端超时公式不变。准确说明两个启动阶段与独立的失败清理预算。

新恢复使用一个基于单调时钟的 `sessionRestoreTimeoutMs` 截止时间，覆盖从恢复所有者开始准备到 ACP load/resume 请求的过程。引擎选择、取得通道和传递已记住的用户语言均消耗此预算。每个准备阶段的等待均受限，ACP 请求只使用剩余预算。即使事件循环卡顿使定时器回调延迟执行，准备过期后也不得发出迟到的 load/resume 请求。系统时钟校正不得改变剩余预算。

这样将通道就绪纳入通告的恢复预算，无需新增启动 limit 或调整 SDK/Web Shell 余量。默认恢复预算为 60 秒；SDK 请求仍保留 10 秒余量，Web Shell 看门狗仍保留 15 秒余量。慢恢复可能比此前额外享有未通告启动时间的行为更早超时；运维可以增大恢复超时配置。

隐式恢复预算仍为 `max(initializeTimeoutMs, 60000)`，不是 initialize 超时的两倍。initialize 超时为 30 秒时，两个启动阶段可以消耗全部 60 秒恢复预算；超过 30 秒时，两个阶段的总上界超过隐式恢复预算。慢速冷启动应显式设置 `--session-restore-timeout-ms`，使其大于 `--initialize-timeout-ms` 的两倍，并为引擎选择、已记住语言的传递以及 ACP 恢复请求预留额外时间。例如 initialize 超时为 40 秒时，推导的恢复预算仍为 60 秒，而启动本身可能需要 80 秒。显式恢复值始终优先，即使该值更短。

## 归属与清理

Bridge 继续属于已解析的工作区 runtime，引擎选择仍是权威结果。不改变 daemon 路由或 runtime 回退规则。

通道取得过程是共享的。恢复截止时间只终止该调用方的等待，不取消其他调用方的通道启动。延迟完成的就绪过程可以预热通道，但不得发出已过期调用方的 ACP 恢复请求。准备失败时，既有所有者 finalizer 会释放准入名额、关闭事件缓冲并完成合并等待方。

ACP 恢复开始后，保留现有超时隔离、延迟结果清理以及空通道与共享通道处理。准备阶段超过截止时间时，返回带有 `dispatched: false` 的 `SessionRestoreTimeoutError`，公共结果记为 timeout。REST 返回可重试的 `504 session_restore_timeout`，包含 `dispatched: false`，不带 `Retry-After`；此时没有已放弃恢复的隔离锁，同一 ID 可以立即重试。已派发请求的超时保留现有隔离锁以及按预算计算的 `Retry-After`（钳制为 5–120 秒）。暖会话挂接和恢复后的状态应用继续使用既有行为。

## 验证与验收标准

- `T=50 ms` 时，45 ms factory 加 30 ms 握手成功，暖 preheat 复用该通道。
- 时钟跳变使绝对启动截止时间剩余 25 ms 或已经耗尽时，握手预算分别被钳制为 25 ms 或 1 ms。移除钳制或扩大截止时间必须使这些断言失败；恢复共享预算必须使冷启动成功用例失败。
- 冷 load 和 resume 都在通告的恢复截止时间完成，早于 SDK/Web Shell 的余量；落在剩余预算内的恢复应成功。
- 引擎选择、通道取得或用户语言传递挂起时，准备阶段仍能超时。延迟的准备结果不得发出恢复请求、保留准入名额或损害共享通道。
- 系统时钟向前或向后校正均不改变恢复截止时间。即使定时器回调尚未执行，单调截止时间过期后也必须阻止引擎选择完成后的迟到通道取得，以及语言传递完成后的迟到 ACP 派发。
- 准备超时后允许同一 ID 重试，不泄漏准入名额，REST 不携带按预算计算的重试提示；已派发请求超时保留隔离锁和重试提示。
- 包测试继续覆盖恢复放弃、清理、合并等待、引擎归属、启动取消和暖通道复用。
- 构建、bundle、类型检查、格式、lint 和独立验证必须通过。无法取得原始慢速 Windows 工作区；确定性传输测试验证时序行为，构建版 CLI 冒烟结果单独报告。
