## 基线与范围

上一轮实验通过 417 个提交，将 core 测试从 `ab61e04161` 压缩至
`e15058c26b`。计入 fixtures 和测试工具后，受版本控制的测试代码从
659,618 行降至 477,908 行，字节数从 23,108,022 降至 17,375,101。
改动仅涉及 core 测试和一个共享 model fixture 模块。

本轮在基于 main `9e60263fde` 的分支上整合最终成果，保留上游测试改动，归档
原始测量证据，并在 core 中探索进一步减量。生产行为、CLI 和 Web Shell
压缩、PR 增长约束均在本阶段范围之外。

用户明确授权超出机械压缩的实验，包括合并雷同用例。因此，新实验中的
用例数量、原始名称和断言次数用于描述变化，不再作为不可改变的条件。
普通压缩仍保留这些严格检查。仅凭行数下降无法证明检出能力得到保留。

## 可复现测量

在 `scripts/test-loc` 保存冻结的历史故障语料、补充故障、样本定义、
依赖版本和精简后的原始结果。记录来源修订与哈希，区分找回的证据和新
运行结果。大型原始报告可保存在有明确名称的实验工件中，同时记录位置
和哈希。禁止通过在另一 main 修订上重建语料来悄悄替换历史样本。

可执行检查必须拒绝失败或空测试运行、缺失报告、断言采集不完整和没有
解释的名称变化，输出机器可读结果，并通过失败退出码表示未通过。
实验模式允许显式的多对一用例映射和删除理由，并报告用例、断言变化。
每个临时文件和覆盖率目录属于单次运行，分别清理。

历史故障回放和 mutation 会修改实现文件，因此在可丢弃的检出目录运行。
压缩前后测试必须使用相同的实现修订。固定 worker 数量和工具版本；发现
疑似能力损失时重复运行，并先比较同版本运行的差异，再归因于实验。

## 整合

通过三方合并将最终压缩结果应用到 `9e60263fde`。审查两个分支都修改的
17 个文件，包括自动合并结果，保留上游新增场景及修正后的预期。在新
实验开始前保存独立的整合检查点，分别记录整合与进一步减量的体积和
能力变化。

在同一 Linux 主机上构建、类型检查工作区，运行带覆盖率的完整 core
测试，并与 main 比较。重新检查冻结故障在两侧的适用性，对称记录排除项。
main 已有失败须单独记录并复现。人工审查 helper 的输入形状、可选字段、
mock 严格程度和异步顺序，这些性质无法仅通过计数和覆盖率确认。

## 后续实验

每个实验记录具体假设、目标文件、基线、行为由哪些测试负责、预期减量
以及保留或拒绝实验所用的检查。优先选择边界明确、已有历史故障或 mutation
证据的独立模块。候选手段包括：

- 合并等价输入分区，同时保留区分条件、负向边界和回归专属预期。
- 将相关状态转换表达为一个场景，在各状态检查结果，减少重复准备和清理。
- 在同一可观察契约能检出相关故障时，用它替代重复的内部交互检查。
- 整合相邻测试文件中重叠的检查，明确各行为的归属，并将 fixtures 纳入统计。

每个接受的实验单独提交，被拒绝的尝试及其测量也要记录。旧 mutation
引导删除试验曾因排除静态 mutant 而丢失历史故障检出；因此，此类删除
须启用覆盖被删行为的算子和静态 mutation，并人工检查负向案例及未来
错误扩大匹配范围的风险。

## 验收与报告

每个接受的实验必须同时减少测试行数和字节数。基线能检出的历史故障仍
能检出；在排除已确认的不稳定因素后，固定相关样本中原来被检出的 mutant
仍须被检出。报告覆盖行和分支集合的差异，记录噪声及可解释变化。
合并用例时检查故障定位能力和检查的独立性：场景前段失败可能掩盖后续检查。

构建、类型检查、受影响单测和格式检查必须通过。完整套件结果与局部实验
结果分别报告。对新改动和冲突整合完成两轮连续无新问题的独立审查。
报告实际测得结果与剩余不确定性；实验没有预设的 50% 成功结论，也不承诺
完整语义等价。

## 阶段结论与验证边界

- **整合：**已测得的体积下降保留了全部已观察到的 C1 检出和 2,809 个
  mutation 状态。已有 Git prune 套件失败、14 个 mutation Timeout 和旧
  Config 表格标题的可读性问题继续明确记录。严格的全样本 C2 门禁仍为
  `ok:false`。
- **进一步实验：**三项保留改动在所选模块共减少 232 行、6,441 字节，已记录
  定向 C1 和局部覆盖率证据。822 个 mutant 的样本没有丢失检出，新增检出
  两项，18 个两侧相同的 Timeout 继续显式记录，其中一项原因尚未定位。
  减量与整合检查点分别统计，不能据此预测整个 core 的收益。

比较器 v4（`bb78d117f4`）拒绝缺少健康运行失败记录的现代故障报告，13 项
报告回归检查通过。基于原始 C1 报告字节重新比较，两对结果均为 `ok:true`：
整合维持 103 个有效故障、三个排除项，实验维持两个有效故障、一个排除项，
两对均没有丢失检出，无须重跑注入故障。

本轮整合与实验阶段已完成，三个减量方向在上述样本边界内均予以保留。
T1 观测在本次波动范围内相近，没有提速结论；严格 mutation 与计时验证的
限制继续明确记录。Round-5 证据清单记录报告、中断排除决定、被排除的原始
运行、调查和耗时数据。结果已在 `codex/core-test-size-next` 准备好供审阅，
main 仍保持 `9e60263fde`。
