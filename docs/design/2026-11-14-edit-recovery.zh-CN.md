# 减少 edit 恢复时的重读和旧文本重复生成

[English](2026-11-14-edit-recovery.md) | [简体中文](2026-11-14-edit-recovery.zh-CN.md)

状态：本次变更已实现，2026-11-14，基于 `114694062b8`。下文调查使用 Qwen Code `7fab512f79d9ed24e9bc30b5d04b1f5f1267c295`；dsh-better-edit 核查固定于 v1.2.1，`009b922d591d93dd7d311fc5412717678d24ed3f`。第 10 节记录实际实现范围及回归证据；方案中的灰度收益目标仍未实测。

## 1. 问题与证据

[Issue #14979](https://github.com/QwenLM/qwen-code/issues/14979) 描述了编辑失败后的高成本恢复：重读内容、重新转录 `old_string`，有时还要重新生成替换内容。对 DataAgent 的只读调查确认了这一模式，时间范围为 2026-11-07 00:00 至 2026-11-14 10:35，Asia/Shanghai。统计按 session/call ID 去重，筛选 production 环境标签，排除自动记忆任务、其他记忆文件及路径缺失记录。覆盖范围是可访问的 DataAgent 部署，不是全部 Qwen Code 用户；部署标签不能独立证明环境标记准确。

| 观察                                                                                                                           | 对方案的含义                                                                                                                                                               |
| ------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 26,389 次非记忆文件编辑中有 263 次 no-match，约 1.00%                                                                          | 优先改善恢复，不必立即让全部编辑迁移协议。                                                                                                                                 |
| 同一范围有 1,395 次读取状态过期失败                                                                                            | no-match 和 stale 两条恢复路径都需要覆盖，且应保留原因区分。                                                                                                               |
| SQL 案例：失败的 old/new 分别为 5,063 / 7,226 字符；old 漏了此前读取已提供的 `d.`                                              | 属于转录错误，不能据此认为匹配器拒绝了正确输入。                                                                                                                           |
| SQL 重试前重读 60 行、返回 5,113 字符；下一轮模型请求耗时 43.003 秒、输出 3,781 tokens；失败到成功为 46.730 秒                 | 成本主要在模型和工具循环恢复；失败工具本身仅耗时 47 ms。                                                                                                                   |
| 成功重试的 old/new 为 5,065 / 7,141 字符                                                                                       | 引用可以省去再次输出的 5,065 字符 old，约占这两个文本字段的 41.5%。这是按字符计算的反事实估算，不是实测 token 或延迟收益。new 也发生变化，不能断言复用原替换内容即可成功。 |
| 报告案例：4,013 字符的 no-match 后绕到 grep、shell 提取和改写；之后一次 stale edit 在重读后重复了完全相同的 350 / 966 字符参数 | 恢复应尽量留在 edit 内，并允许明确复用未变化的替换内容。后续 stale 与同 session 的 shell 写入一致。                                                                        |

报告案例首次失配的内容差异来自历史写入重建，不是失败时的磁盘快照。两个案例都没有证明 issue 所述 800 行/20k tokens 的具体规模，也没有证明 edit 导致压缩。原始会话以及租户、session 标识不进入这份受版本管理的方案。

目标是减少恢复调用和模型重复输出，同时保留明确的目标选择、当前内容校验、权限和可审阅 diff。通过接受不确定写入来降低拒绝率，不属于成功指标。

## 2. dsh-better-edit 值得借鉴什么

核查的[工具 schema](https://github.com/Rianico/dsh-better-edit/blob/009b922d591d93dd7d311fc5412717678d24ed3f/src/tool-edit.ts) 使用 `{file, edits: [{anchor_from, anchor_to, replace_with}]}`，契约归一化层兼容旧字段和元组。部分 README 示例和 benchmark 仍描述旧接口。

| 机制                                             | 对 Qwen Code 的判断                                                                                                                    |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 三字符行锚点代替旧文本转录                       | 借鉴由宿主解析引用的原则。新替换内容仍需要输出 tokens。                                                                                |
| session 范围的已提供内容状态、快照、租约和行身份 | 短哈希本身不够。引用需要明确归属、准确内容证据和失效规则。                                                                             |
| 能定位目标时，拒绝编辑的同时返回当前目标行       | 借鉴有界恢复内容。目标丢失、窗口截断或身份不明确时仍可能需要读取。                                                                     |
| 成功 diff 提供新锚点                             | 后续让完整送达的成功片段也能提供新引用。Qwen 已有成功片段，但尚无这种寻址契约。                                                        |
| 区域外变化后通过身份重定位                       | 暂缓。需要处理重复行和“原行删除、相同副本仍在”等情况，不等于搜索相同文本。                                                             |
| 忽略 ASCII 空白的归一化                          | 不用它授权写入。实现会去掉字符串内部空格和缩进中的空格、制表符；其 ADR 明确假设外部修改仅来自格式化器，而 issue 还涉及人和其他 agent。 |

[归一化实现](https://github.com/Rianico/dsh-better-edit/blob/009b922d591d93dd7d311fc5412717678d24ed3f/src/hashline/hash-assign.ts#L105-L115)和[空白处理 ADR](https://github.com/Rianico/dsh-better-edit/blob/009b922d591d93dd7d311fc5412717678d24ed3f/docs/adr/0002-whitespace-insensitive-anchors.md)明确体现了最后一项限制：`"x y"` 和 `"xy"` 归一化后相同，不能认为语义相同。[已提供范围的校验实现](https://github.com/Rianico/dsh-better-edit/blob/009b922d591d93dd7d311fc5412717678d24ed3f/src/hashline/anchor-pipeline.ts)还允许租约路径中两个已校验边界之间存在未读取的内部行。Qwen 本方案第一版则要求整个替换目标已完整送达模型。

项目的 [benchmark](https://github.com/Rianico/dsh-better-edit/blob/009b922d591d93dd7d311fc5412717678d24ed3f/benchmark/README.md)报告：103 行固定样本、12 次脚本化替换，请求载荷为 702 对 1,015 tokens，约减少 31%。它不计读取和转录失败，使用 `cl100k_base`；[脚本](https://github.com/Rianico/dsh-better-edit/blob/009b922d591d93dd7d311fc5412717678d24ed3f/benchmark/run.mjs#L279-L296)构造的还是旧单次编辑接口，而非当前命名对象接口。README 的 40–60% 及单次实验 55.8% 数字不是 Qwen 线上对照结果。本次没有独立复现这些 benchmark。

## 3. 交付顺序

| 阶段             | 改动                                            | 预期收益                                       | 边界                                                 |
| ---------------- | ----------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------- |
| P0：改善失败反馈 | 返回有界当前候选、差异定位和准确的下一步        | 内容足够时省去单独定位、读取的往返             | 仍需普通 old/new 参数，单独做不能解决重复转录        |
| P1：恢复引用     | 在现有 edit 上增加明确的 `recovery_id` 调用方式 | 重试免传 old；可选复用失败调用的 new           | 绑定快照、单目标、同 session/runtime，不自动模糊写入 |
| P2：读取引用     | 用读取引用和行范围选择完整送达的内容            | 首次编辑也无需生成 old，包括本来就会成功的编辑 | P1 验证后再灰度，不整体迁移 hashline                 |

建议先交付 P0，再紧接 P1。如果只停在 P0，用户关心的 old_string 输出成本仍然存在。批量编辑、持久化行身份、自动重定位和通用撤销应单独评估，不作为前置条件。

## 4. P0：失败时提供可用的当前内容

增强 `EDIT_NO_OCCURRENCE_FOUND` 和 `file_changed_since_read`。权限拒绝、未读取文件、文件不存在和格式不支持仍需区分，不能偷偷转成已授权读取。两条失败路径向模型提供当前内容前，都需要通过等价 Read 权限检查，即使 edit 内部已经读到了这些内容。未获允许时只保留诊断，不返回内容或引用。

no-match 优先使用已经允许访问的当前内容。增加有界候选定位逻辑，通过仍匹配的上下文行及逐行对齐提供建议。它只负责建议。已有 `findLineBasedMatchOffsets` 定位的是已经匹配的子串，不是最近候选搜索器；单独复用 `extractEditSnippet` 也不能完成定位。

stale 只有在等价 Read 权限检查通过后才能获取新的文件观察结果。如果提交的 old 在当前内容中存在唯一精确匹配，可以据此确定当前候选；否则使用同一诊断定位逻辑，或返回准确的读取指引。`FileReadCache` 只存元数据，不存此前正文；没有保留快照时，不能承诺直接展示外部修改的真实前后 diff。

结果包含错误类型、路径、候选行范围、首个有帮助的失配点，以及清晰分隔的当前内容，不重复回显整份失败 old/new。候选相似度只作指引，不构成写入许可。最多列出三个简洁候选位置；第一版仅在保守识别出单个目标、且完整返回目标内容时提供可执行恢复引用。

初始建议上限为 120 行及 16 KiB UTF-8 恢复内容，包含附带上下文，两个限制同时生效。不能用省略号代替未展示目标，再发覆盖这些内容的引用。完整目标放不下时，返回更窄的 `read_file(offset, limit)` 指引，不发可写引用。这是待结合模型预算验证的初始实现参数，不是已测得的最优值。

当前内容转移到失败响应中，其输入 token 成本没有消失；节省的是额外模型/工具往返以及可以避免的反复读取。P0 不能因为生成了片段就调用 `recordRead`，否则会把 Edit/WriteFile 的整文件读取许可刷新到超出模型实际看到的范围。P0 本身也不能绕过 stale 检查。

## 5. P1：通过引用明确重试

保留原有 `{file_path, old_string, new_string, replace_all?}`，新增互斥形式：

```json
{
  "file_path": "/workspace/report.md",
  "recovery_id": "er_7Kq"
}
```

模型明确选中与 `er_7Kq` 一起返回的完整当前候选。省略 `new_string` 表示复用失败调用的替换内容；传入 `new_string` 则覆盖保存的提案。无需传入 `old_string`，显式空替换字符串仍表示删除。示例 ID 仅用于说明，实际 ID 应是不透明且有作用域的引用，不是三字符内容哈希。

模型应查看返回的候选及差异，再选择这一形式。SQL 案例中成功的 new 与失败版本不同，所以必须保留覆盖 `new_string` 的能力。机制不能推断“目标差得很少，所以原替换内容一定正确”。

### 状态与有效性

由实际执行文件操作的 session/runtime 管理一个小型内存存储。每项绑定 workspace、规范路径与文件身份、当前整文件精确内容摘要、候选准确范围及原始 old、失败调用的 new，以及原始 call。保留既有编码、BOM 和换行行为。不引入持久化快照数据库，也不把租户内容放入遥测。

第一版限制每个 session 最多八个引用、合计保留 1 MiB 文本；淘汰旧项，或在请求超出预算时不提供引用，普通 edit 仍可使用。P1 不支持 `replace_all`、歧义目标选择、跨 session 传递引用或自动 rebase。要求非空的原始目标文本在当前文件中只有一个字面匹配，即使诊断定位器更偏好多个相似位置中的某一个，也不能放宽这一条件。引用路径不回退到模糊匹配。

引用在写入成功后消费。快照变化、session/runtime/workspace 切换、重启、resume，或模型历史移除相应证据后，引用不可再用。第一版在 full/micro compaction 时清空存储。取消或抑制结果不能留下可操作引用。内容再次变化时拒绝，并在权限允许时返回新恢复信息；不静默重定位，也不自动批准原提案。

### 权限与确认

在 PreToolUse、权限处理和 AUTO 分类**之前**，把引用展开为等价的真实 file/old/new 参数。只在 `execute` 解析太晚，仅在 tool build 解析也不够，因为现有 hook 先于 build 执行。原始 wire 参数应单独保留用于计量，不能把展开文本重新注入模型会话。

人工确认继续展示真实的当前到拟修改 diff；AUTO 分类获得与普通 edit 相同的内容投影。引用不继承原审批。hook 参数替换、PermissionRequest 更新、IDE modify-and-confirm 都需重新校验；目标或 old 变化破坏绑定时，丢弃恢复权限，走普通读取/编辑路径。new 变化必须成为最终审核及写入的真实提案，不能被缓存的旧 new 覆盖。

使用仅属于本次 invocation、准确目标和快照的读取证据，不通过刷新全局 `FileReadCache` 让重试通过。绑定贯穿 confirmation、execute 和最后的 pre-write 检查，不能让另一次读取刷新共享 cache 后，使旧引用重新合法。核对精确内容和文件身份，不能只看 mtime、size。保留现有备份和写入语义。这些检查并不意味着对任意外部写入提供文件系统级原子 compare-and-swap 保证。

### 送达与裁剪

复用 `ToolResult.recoveryText`，把完整有界目标、差异说明和引用作为不可拆分的一块保留。这个约束要在结果 hook、批次预算处理之后、最终发送给模型的边界成立：不能只保留 ID，却丢掉部分目标。无法保证的路径不发引用，只返回诊断信息。如果需要 compaction 腾空间，应使旧证据失效，只为最终保留在待发送结果中的内容发新引用。

生成结果时先准备未激活的恢复状态，仅在完整恢复块进入下一次模型请求时激活。如果此前发生 compaction，丢弃旧项，并为最终保留的待发送恢复块发新引用。某条路径无法完成这个最终送达交接时，该路径只启用 P0。

同时覆盖执行失败和 confirmation 阶段的 `StructuredToolError`，两者都可能是模型唯一收到的失败响应。当前远程结果转发会遗漏 `recoveryText`，confirmation error 也没有携带它。在这些路径启用引用前必须补齐。生产者构造了结果，不等于模型已经收到。

## 6. P2：首次编辑也不转录 old_string

P1 验证后，让 `read_file` 为完整送达的原始文本范围返回不透明 `read_id`。edit 使用引用快照中的行范围：

```json
{
  "file_path": "/workspace/query.sql",
  "read_id": "rd_9M",
  "start_line": 140,
  "end_line": 190,
  "new_string": "replacement text"
}
```

行范围包含首尾，属于引用快照，并且必须完全位于已完整送达的覆盖范围内；它不是没有版本约束的当前文件行号。明确整行替换及文件末行/EOL 语义，第一版部分行编辑继续使用普通字符串形式。文件发生任何变化，第一版引用均失效，不自动在其他位置搜索字节相同的范围。P2 与 P1 的唯一字面目标不同，必须在快照校验后准确修改选中范围；为审核展开 old/new，不能在存在相同内容块时把范围编辑转成全文件子串搜索。

引用绑定原始源内容范围，不从渲染文本反推。当前 read 展示会 trim 行尾空白，还可能在行中截断。携带引用的输出必须保留底层行文本，不能复用这种有损渲染；截断行不能获得可写引用。P1 的最终送达规则同样适用于读取和成功片段。成功编辑只为实际完整返回的区域提供新引用，旧快照引用仍保持失效。

P2 消除首次编辑时的 old 输出，但 new 仍必须生成。在改变所有 provider 的默认 schema 或读取展示前，应与 P1、普通工具开展对比。只有剩余的区域外变化恢复成本足以证明投入合理时，才考虑身份重定位以及对应的状态和重复行语义。

## 7. 集成与灰度

首批启用引用的流量应使用已核实的标准 Node 文件系统执行路径；DataAgent daemon session 只有确认执行归属后才纳入。production 标签或 daemon UI 不能证明底层文件执行路径。一次 session 内保持 schema/能力选择稳定；不支持的路径不能声明或发出可用引用。

| 组件 / 消费者                                                                                                                                         | 所需工作                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `packages/core/src/tools/edit.ts`、`utils/editHelper.ts`                                                                                              | 候选诊断、兼容的参数形式、引用绑定、确认和执行校验                   |
| `tools/priorReadEnforcement.ts`、`services/fileReadCache.ts`、`config/config.ts`                                                                      | 保留整文件策略；在正确 session/runtime 管理限定范围的恢复状态        |
| `core/coreToolScheduler.ts`、`packages/cli/src/acp-integration/session/Session.ts`                                                                    | 在 hook/权限之前展开等价参数；重新校验 hook 和确认修改               |
| `tools/tool-error.ts`、`tools/tools.ts`、`tools/tool-response-finalizer.ts`、`tools/execution-tool.ts`                                                | 在 confirmation、execute、远程转发及最终送达中完整保留恢复块         |
| `tools/read-file.ts`、`utils/fileUtils.ts`、`core/llm-chat.ts`、`core/client.ts`                                                                      | P2 原文覆盖范围，以及送达和 compaction 失效规则                      |
| `services/ssh-execution-environment.ts`、`packages/cli/src/serve/hosted-workspace-tool-turn.ts`、`packages/cli/src/serve/hosted-csi-tool-evidence.ts` | 独立编辑实现/严格 schema；完成一致性验证前保留普通行为               |
| `mods/tool-dialect.ts`、`packages/web-shell/client/components/messages/ToolGroup.tsx`                                                                 | 字段白名单和基于 old/new 的 diff 回退需获得受支持参数或真实展开 diff |

表中没有 package 前缀的路径均位于 `packages/core/src/`。这是消费者清单，不代表第一份补丁必须修改全部文件；也不能把方案描述成只改 `edit.ts`。ACP、远程 worker、SSH、Hosted/CSI、方言适配器纳入前都需要明确验证。现有 notebook 工具、新文件创建、`replace_all` 和成功路径保持已有契约。

交付拆成 P0 诊断、P1 状态归属/输入展开/结果保留与恢复，以及单独评估的 P2。普通参数调用始终作为回退。回滚关闭引用发放，普通编辑继续可用，没有持久化状态迁移。

## 8. 验证与验收

重放两个真实工作流的脱敏复现：遗漏字符、数值转录差异、内部对齐空格，以及同 session shell 写入后的 stale。同时覆盖 new 不变和修改 new 的情况。现有 trace 是基线，不能当作尚未实现方案的运行结果。

正确性用例需包含重复块、删除后重建的相同内容、目标内容变化、区域外变化、size/mtime 相同的内容变化、路径替换、跨 session ID、读取权限拒绝、等待审批时变化、修改输入的 hook、IDE 修改、取消、结果 hook、输出裁剪、compaction 和 runtime 重启。验证编码/BOM/CRLF 保留及普通编辑无回归，分别测试需确认和自动模式。不能满足归属和最终送达约束的路径，应验证其不发可用引用。

对于稳定、完整送达且无歧义的目标，P1 的验收行为是失败后一次明确重试即可完成，中间不再 read，也不再输出 old；new 不变时也无需重复 new。歧义、超大或再次变化的目标必须拒绝，不能为了达到指标强行通过。回归样本必须零非预期写入，但样本通过不代表普遍的“零误写”保证。

指标按完整恢复过程统计，而不只看单个工具 span：

- 从失败到完成预期编辑之间的模型轮数及 read/grep/shell 次数。
- 所有相关轮次的输入/输出 tokens，cached input 单列，并记录 old/new 字符数；不把所有输出都叫浪费，也不以字符估算代替 provider 用量。
- 失败到成功耗时、最终编辑成功率、放弃及绕到 shell 的比例。
- 候选覆盖率、引用使用率、失效原因、输出预算压力及 prompt cache 影响。

按 no-match/stale、目标长度、模型、runtime 和自动/交互审批分层；匹配 session/实验组口径，始终排除后台记忆活动。建议灰度目标是适用样本的额外读取减少至少 50%、恢复输出 tokens 减少至少 30%，且不出现正确性或任务完成回归。这些是待验证的验收目标，不是预测或实测收益；同时报告全量结果，避免用适用范围掩盖低覆盖率。

实现验收前，执行定向单测、build/typecheck，以及覆盖真实内容送达和审批路径的 CLI E2E，再开展配对模型实验和小流量线上灰度。不能根据 SQL 案例直接推断节省 43 秒，也不能在仍需生成大段 new 时承诺整个 edit 只要 50 tokens。

## 9. 实现阶段待定事项

使用脱敏语料调整候选置信条件和输出上限，核验目标 provider 的 schema 兼容性。启用 ID 前，确认首批线上流量的执行归属和最终送达路径；完成 provider 检查后确定最终字段名，本文规定的语义是当前提案。

不把扩大空白容错或复制 dsh 的持久化锚点基础设施当作捷径。建议投入的是可直接用于恢复的失败内容，以及明确绑定快照的引用。它直接覆盖已观察到的两种恢复循环，同时为减少首次 old_string 转录提供可衡量的后续路径。

## 10. 实际实现范围及回归语料

本次变更在标准本地 Node 文件系统 session 上实现 P0、P1、P2。受支持 session 的 Edit 声明提供引用形式，有界 Read、可恢复失败及完整成功片段返回引用。完整源快照上限为 1 MiB，单个引用块上限为 120 行及 16 KiB，每 session 最多八个引用、合计保留 1 MiB 文本。更大或不支持的读取继续使用普通编辑。执行 facade/worker、managed 或 sandbox 执行、自定义或委托文件系统，以及关闭 read cache 的 session 不发引用。CLI scheduler 和普通本地 ACP/daemon 路径都会在 hook、权限检查前展开引用参数。本 PR 不向 DataAgent 线上部署。

整行替换中，如果原范围以换行结束、非空 new 未带最后换行，则补回该换行；空 new 删除选中范围。hook 修改该约束时也须提供有效的整行替换内容。用户通过编辑器将目标改为全文编辑时，回到普通 prior-read 检查。不增加重定位，也不用忽略空白的方式授权写入。

[回归语料](../../packages/core/src/tools/fixtures/README.md)包含 50 个 session 的 50 个独立真实失败：39 个 no-match、11 个 stale。它是选取的诊断数据，不是代表性发生率样本。所有业务文本替换为逐例中性 token，原始出处及映射保持私有。全部 50 例使用真实临时文件 I/O 复现原拒绝，并断言没有修改。七例具有独立交叉验证的同目标恢复依据和准确结果；另外 43 例证明拒写安全，不证明恢复正确性。

七例中四例验证 P1 恢复，三例经过有界 P2 read 后按范围修改。替换内容不变的案例省略 `new_string`，改变提案的案例使用真实成功编辑的替换内容。测试区分“发出了候选引用”和“证实引用指向预期目标”。额外的单元、流程及 compiled CLI 测试覆盖 hook、权限、人工确认、过期快照、重复块、编码、结果送达和历史失效。mock provider 的 CLI 测试证明实际客户端/工具循环及紧凑 wire 参数，不证明自然模型效率或全部 provider 都接受。另一个有界 smoke 使用已配置的 `DeepSeek/deepseek-v4-flash` 服务，完成五次真实 API 请求、四次工具调用：有界读取、读取引用编辑、故意 no-match、仅恢复引用重试，无 old/new 字段或中间重读。最终文件及捕获的 wire 参数均符合预期。这只验证了一个已配置的 provider/model 组合，延迟/token 对照收益及生产灰度仍待后续验证。
