# Selective Codex memory import

[English](codex-memory-import.md) | [简体中文](codex-memory-import.zh-CN.md)

## Problem and current state

Codex stores a cross-project handbook and a short summary, while Qwen manages typed topic documents and generated indexes. Copying a handbook into Qwen's index loses scope and consumes the context budget. Users need an offline, reviewable import without starting a model session or modifying the source.

The interactive preview supports reviewing large collections. Remaining ownership failures come from natural-language scope annotations and genuinely shared or unavailable project scopes. Recognize explicit ownership more accurately, then offer the remaining entries as clearly marked global candidates so every safe candidate has an import destination.

## Proposed behavior

`qwen memory import codex --dry-run` previews candidates from `memory_summary.md` and `MEMORY.md`. `--source` chooses the source directory. `--project-map` reads a JSON object mapping source working directories to local project directories. `--select` accepts candidate IDs. Without selected IDs, a TTY opens interactive review with an import confirmation; scripts only preview. Writing requires confirmation or explicit IDs, and omission of `--dry-run`. `--json` emits the complete preview for local inspection.

The importer extracts user profile and preference bullets from the summary, and preference, reusable-knowledge, and lessons bullets from recognized handbook sections. Every entry is a candidate for explicit review, not an assertion that historical observations remain true. Raw transcripts, rollout summaries, and skills are not imported. Supplemental edit/delete notes are reported as review material: they are not interpreted as commands or silently imported. The preview must make unresolved source amendments visible before any selection is applied. When supplemental notes exist, scripted application requires `--review-source <sourceDigest>` from the preview; interactive confirmation acknowledges their review and supplies the displayed digest; a changed source requires renewed review.

## Interactive preview

Use a standalone Ink interface only when the computed `preview.dryRun` is `true`, both stdin and stdout are TTYs, and `--json` is absent. This includes the default preview without `--select` and an explicit `--dry-run`. Load the interface only after this check; JSON and non-TTY output keep the existing format and do not load the UI. An explicit `--select` apply command continues directly through the existing import path. Opening the preview does not initialize an agent, model, or session, or make a network request.

The interface has three views: groups, entries, and detail. Group resolved project entries by native destination, using the resolved main project as the readable label; user memory has its own group. Global fallback entries have a separate `User memory (global fallback)` group. Their list labels and details explicitly identify the fallback, retain any original project path, and show the ownership failure in `scopeReason`. All eligible candidates, including global fallbacks, are preselected for review. Blocked entries remain ineligible. Show counts and status totals before opening a group. Preserve selected candidate IDs while navigating between groups. Supplemental source notes and parser/planner warnings share one readable `Source notes & warnings` review group, not importable candidates.

| Key                  | Behavior                                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| `↑` / `↓`, `j` / `k` | Move through the visible list.                                                                            |
| `Enter`              | Open the focused group, entry, note, or warning.                                                          |
| `Space`              | Toggle eligible `ready`/`duplicate` entries in the focused group or the focused candidate.                |
| `Esc`                | Return from detail to entries, then to groups; from groups, cancel.                                       |
| `d`                  | Close a dry-run preview; otherwise open the import confirmation (same as `i`).                            |
| `i`                  | Open the import confirmation, unless `--dry-run` was supplied.                                            |
| `a` / `n`            | Select all eligible candidates / clear all selections.                                                    |
| `o`                  | Open the focused entry, source note, or warning in the default editor from the entry list or detail view. |

Reuse the existing `RadioButtonSelect` with checkbox labels and parent-owned selection state, plus terminal sizing and keypress utilities. Render sanitized source text with `MarkdownDisplay` inside a bounded detail viewport. Show a visible truncation notice and the `o` action when the detail exceeds that viewport. Fenced content, including Mermaid, stays inert text; preview rendering must not invoke diagram, terminal visual, or code execution. Narrow terminals and resize events must keep navigation and the active selection usable without printing the entire collection.

The `o` action creates a review-only snapshot on demand in a private temporary directory outside repositories, the source directory, and native memory roots. On that explicit action, the host rejects a temporary root inside the source, a native memory root, or any Git checkout before creating the artifact. Use directory mode `0700` and file mode `0600`; include full sanitized review text and provenance, preserving any credential redaction already applied by the planner. Reuse the existing editor interaction with a read-only `SettingsContext` stub; do not call `loadSettings`. The standalone interface uses the existing hook's platform-default editor rather than the saved `preferredEditor` setting. Never open the source for editing, read editor changes back into the selection, or apply those changes. Keep review artifacts until the preview exits normally or is cancelled, so asynchronous GUI editor launch can finish; then remove them and report cleanup failures without printing their contents. Failure to create or open a review artifact, including under Node read-only filesystem permissions, leaves the preview usable and reports the failure. Before the user presses `o`, the interactive preview creates no directories or files.

## Ownership and destinations

Summary profile/preferences are user-scoped. Handbook records with a reliable project remain project-scoped, including feedback. Resolve explicit `cwd` metadata and apply exact `--project-map` entries before normalizing Git worktrees and subdirectories to the main checkout. Non-Git directories retain their explicit scope. Preserve submodule and separate-clone boundaries, and never guess repositories from directory names or remotes. Git normalization uses validated filesystem metadata only; it does not invoke Git or access the network. Load runtime settings and native memory destinations after ownership is resolved. Qwen's usual per-worktree recall is unchanged: imports belong to the displayed main checkout's scope and are not automatically recalled inside linked worktrees. The preview explicitly states this limitation.

Recognize quoted and unquoted branch annotations, descriptive worktree annotations, and local operating-system installation references following an explicit cwd. A primary cwd followed by `(rollout metadata cwd=...)` keeps primary ownership; the parenthesized cwd is provenance. A named alternative such as `cwd=/work/atlas or atlas worktree on release/example` stays with the explicit project only when the worktree's project name exactly matches the path basename. Unrelated absolute paths, mismatched names, extra cwd assignments, and unsupported suffixes must not be silently discarded. Preserve quoted path contents and candidate IDs, bodies, and dates.

When ownership cannot be established, offer the entry in native user memory as a **global fallback candidate**. This covers multiple projects, wildcard or missing scopes, unsupported/invalid metadata, nonlocal paths, missing/non-directory targets, and unverifiable Git main checkouts. This policy does not claim that the source was originally global: `scope: "user"` reports the effective destination, while `scopeReason` retains the original ownership failure independently of duplicate/conflict `reason`. Preserve `sourceProject` when available and expose `resolvedProject` only for a resolved project destination. `scope: "project"` identifies normal project entries. JSON, plaintext, group/list/detail, and full-text review all use the effective scope and explicitly mark global fallback. Eligible global candidates are selected by default, explicitly counted in the confirmation, and written only after import confirmation or explicit scripted selection. An exact project mapping can keep a known moved project project-scoped instead of falling back globally.

Credential detection precedes fallback: blocked content never becomes importable. Missing/unreadable source files, invalid mappings, unsafe native destinations, and corrupt ledgers remain command errors rather than being masked by global fallback. Use private native user/project roots; reject repository-local memory and destinations inside source/project checkouts. No settings writes, model initialization, agent hooks, or network requests occur during planning.

## Duplicates, conflicts, and persistence

Use normalized exact content comparison across all native documents in the destination, including entries beyond the normal index cap. Do not claim semantic equivalence or contradiction detection. Different content for an existing imported identity or matching native title is a conflict; never overwrite it. A separate JSON ledger keeps source identity, content fingerprint, and target filename after native maintenance modifies or removes documents. Previously imported but missing records remain skipped, preventing resurrection after forget. Source IDs and content fingerprints are separate. Applying an import also records fingerprints and IDs of eligible source candidates in that destination, including unselected candidates; dry-run never stores this snapshot. Subsequent previews match unchanged content to that history before considering positional IDs, so deleting or reordering neighbouring entries does not assign an imported identity to an unchanged, unselected entry. Text edits retain positional conflict and forget protection. Unknown changed content whose slot is claimed by a moved entry remains a conservative conflict with a distinct ID; review it in a separate source section. Older ledgers without candidate history remain supported but cannot identify never-imported entries retroactively. The history contains hashes and IDs only, not source text. Only explicitly selected `ready` entries create new topic documents; selected `duplicate` entries record handling in the ledger without creating another topic. A selected conflict aborts writes. Preserve source update timestamps when known and label unknown dates honestly.

An exclusive import lock prevents concurrent imports. Recompute under the lock, create topic files exclusively, persist ledger records conservatively before making entries eligible for reimport, and rebuild native indexes. Failures are reported without blindly retrying or overwriting user content. Source files and all existing topic documents remain untouched. Preview never creates memory directories, indexes, ledgers, or locks. Its only optional write is the private review artifact explicitly requested with `o`; selecting entries or closing without import confirmation does not write anything.

## Files and scope

CLI command and bootstrap registration; a Codex parser and import planner/writer under `packages/cli/src/commands/memory/`; a standalone interactive preview using existing terminal components; collocated synthetic tests; user documentation. Reuse native path resolution, scanning, secret detection, index generation, and editor interaction. Project normalization is specific to this importer. No core recall changes, external provider, automatic synchronization, semantic model calls, or skill migration.

## Privacy and limitations

Never commit real source memories, preview output, user-specific paths, or generated ledgers. Test writes only use temporary synthetic data. Real-data validation is dry-run only and reports aggregate counts. Known credential patterns block candidates without echoing secret content. Shared-scope fallback broadens availability to user memory and is therefore explicitly visible during review. Deterministic conflict detection is conservative, not semantic; users must review selected text and source amendments. Markdown layouts outside supported sections are reported rather than guessed.

The editor snapshot contains private review text and must remain outside Git, just like preview output. It is created only by the explicit `o` action. Closing the preview does not acknowledge source amendments. Import confirmation explicitly acknowledges reviewing any notes and passes the displayed source digest to the writer.

## Default selection and interactive import

All eligible ready/duplicate candidates, including clearly marked global fallbacks, are selected by default. Explicit initial IDs select only those entries; an explicit empty list selects none. Blocked, conflicting, and previously imported entries remain unselected. Reuse the existing list: `a` selects all eligible candidates, `n` clears all, and Space on a group toggles its eligible entries; Space on an entry toggles only that entry.

Running `memory import codex` without explicit IDs in a TTY opens review and allows `i` to open an import confirmation. The confirmation summarizes selected candidates, project/user destinations, and global fallbacks, with Import and Back actions. When source amendments exist, the import action explicitly acknowledges reviewing them. This acknowledgement must not be inferred from closing the preview. Confirmation returns a typed import action; only the CLI controller invokes the existing writer. The writer rechecks the source digest from the displayed preview before creating destination directories or locks, including when notes are absent or have been added/removed. A changed source requires a new review. Reuse the existing planner, duplicate/conflict checks, and writer; display a concise result rather than dumping every imported memory.

An explicit `--dry-run` disables importing regardless of selection or returned UI action. Its footer explains how to restart without `--dry-run`; finishing a dry-run remains preview-only. JSON and non-TTY invocations without explicit IDs still only preview. Explicit `--select` keeps the existing script apply behavior. The UI displays the number of selected candidates, not a promised new-file count, because deduplication is re-evaluated for that selection.

Verify default/all/none/group selection, explicit IDs, visible primary action, confirmation/back/cancel, source-note acknowledgement, actual synthetic selected imports via PTY, concise results, stale source rejection, and a strict no-apply guard for dry-run. All write tests use isolated synthetic memories; real memories remain read-only and must never enter Git.
