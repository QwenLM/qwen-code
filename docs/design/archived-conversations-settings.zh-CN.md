# 设置中的归档会话管理

[English](archived-conversations-settings.md) | [简体中文](archived-conversations-settings.zh-CN.md)

## 问题与范围

Issue #15549 对比了低频“已归档”区域的三种入口。本次实现方案三：在设置中新增独立分类，内容区域直接展示归档管理。移除侧边栏常驻区块，保留现有工作区分组、会话来源筛选、无工作区会话和托管会话，以及现有操作和限制。归档内容只读查看及归档完成提示条留作独立工作。

## 设计

参照已有 Connections 分类，为 `SettingsMessage` 增加可选归档内容插槽。在宿主展示标识中增加 `builtin:archived-sessions`。分类命名为 Archived conversations / 归档会话，使用归档图标和独立标题，不展示配置作用域标签和虚构的设置项数量。归档为空时入口仍然保留，并遵循设置的包含与排除规则。

`App` 仅在选中此分类时提供 DOM 目标。`WebShellSidebar` 通过 portal 将现有归档列表渲染到该目标，保留已有工作区路由、操作处理、确认流程和共用会话行。列表在侧边栏导航表面之外渲染，确保折叠、隐藏、移动端和 Live 导航不会隐藏设置内容。列表不受侧边栏搜索文本影响，继续保留工作区分组。支持来源元数据时，归档页提供独立的任务／频道切换，不依赖当前侧边栏导航；两种布局都能访问频道归档，且不改变活跃会话的查询。

目标是否存在取代原来的展开状态，作为归档目录的激活信号。每次打开时，在目录订阅注册之前通过布局 effect 刷新受支持的主工作区和带工作区限定的次级归档查询，避免冷缓存或已失效缓存产生第二次串行读取，并惰性挂载无工作区和托管归档。关闭设置或切换分类时移除目标，停止相应归档订阅，并清除无工作区归档的临时状态。托管会话继续使用已有嵌套 portal，生命周期操作仍由 `ManagedSessionsPage` 持有。

可选插槽在原有侧边栏归档功能可用时提供。禁用侧边栏的嵌入宿主继续维持原先不提供归档管理的行为，本次不引入第二个传统会话生命周期所有者。即使没有普通工作区，只要归档管理可用，设置入口仍然可用，确保无工作区和托管归档具有可达的管理位置。嵌入宿主升级时，必须提供设置入口，并在设置白名单中加入 `builtin:archived-sessions`，才能保留归档管理。排除该分类会有意隐藏其界面，不通过侧边栏回退绕过宿主展示配置。仅有归档的配置不展示依赖项目的模型控件。不需要修改存储、daemon 路由、SDK 或生命周期语义。

## 涉及区域与理由

- `SettingsMessage.tsx`、设置展示别名及中英文文案：分类、标题与可见性。
- `App.tsx`：将选中分类的目标连接到现有归档所有者。
- `WebShellSidebar.tsx` 及 CSS：迁移列表，移除旧区块头部，保留操作行为和惰性刷新。
- 设置、侧边栏及浏览器测试：验证入口、惰性加载、生命周期操作和布局。

复用现有所有者，可以避免为了导航调整而复制工作区解析或重写稳定的会话管理行为。

## 验证与验收

1. 两种侧边栏布局均不再存在常驻“已归档”头部。归档管理可用且宿主展示策略允许时，设置中展示“归档会话”。
2. 选中分类后，现有工作区分组及无工作区/托管归档直接显示在设置中，不打开弹窗，不展示用户/工作区标签。其他设置分类仍可正常使用。
3. 打开前不主动加载归档目录，重新打开时刷新。侧边栏搜索不会隐藏归档内容。
4. 保留恢复、重命名、导出、删除的已有约束及所属工作区路由，继续提供空状态、加载和失败重试反馈。
5. 检查桌面/移动端布局、明暗主题和中英文文案。执行仓库构建、类型检查、打包、针对性单元测试、lint/格式检查及浏览器 E2E。实际验证结果单独记录，不与设计声明混淆。

## 风险与待定事项

传统归档仍由侧边栏组件持有，测试必须覆盖侧边栏视觉表面隐藏时的 portal。托管归档已有嵌套 portal，目标挂载与清理应避免提前加载和残留内容。作者已为本次实现选择方案三；社区最终产品方向仍需维护者批准。
