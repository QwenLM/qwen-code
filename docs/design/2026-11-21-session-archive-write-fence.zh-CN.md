# 阻止旧写入器在归档后重建会话记录

[English](2026-11-21-session-archive-write-fence.md) | [简体中文](2026-11-21-session-archive-write-fence.zh-CN.md)

## 问题与范围

[#17251](https://github.com/QwenLM/qwen-code/issues/17251) 和
[#9688](https://github.com/QwenLM/qwen-code/issues/9688) 中，一个 daemon 可以归档另一个进程仍在写入的记录。迟到的追加操作会以允许创建的方式打开已经不存在的活动路径，迟到的标题更新也可能重建活动标题 sidecar。新记录的父记录已经在归档文件中，导致活动副本显示历史缺口。

已启用写入器租约的进程仍持有写入权时，daemon 现有的会话级租约已能阻止归档。默认的传统写入器不持有该租约。本改动保留两种模式，以及现有的 HTTP 和记录格式。不修复已有断链、不停止其他进程，也不改变删除逻辑或同级会话的归属。

## 存储边界

- 传统写入器创建或追加记录、写入标题 sidecar、存储层回退重命名，以及归档和取消归档，都使用活动 `chats` 目录下按记录文件划分的短时文件系统锁。已经获准的追加操作和它的标题 sidecar 写入之间，归档不能移走记录文件。活动路径无争用时，首条提示和恢复时生成的列表标题仍会立即显示；有锁争用时则延迟投影，不会让后续提示抢先成为列表标题。
  锁争用期间，传统写入器的追加操作按顺序排队，并在约一个陈旧锁回收周期内重试取锁，之后才报告写入失败。
- 在真正移动文件或解决归档冲突之前，服务会原子更新同级的 `<id>.jsonl.archive-generation` 代际标记。写入器保留加载或首次记录该会话时看到的标记，不会为同一路径刷新标记。写入前持锁核对标记，并确认归档副本不存在。传统写入器此后因修改消息组而取得现有会话级租约时，也必须通过这项检查。
- 拒绝写入后，两个活动文件都不会重建，即使取消归档把同一 inode 移回活动目录，或者后续删除清除了归档副本。显式恢复后的新写入器可以正常写入。未改变状态的归档或取消归档请求不会更新标记。
- 删除后有意保留代际标记，它不会进入会话列表。仅凭标记存在不能判断归档状态。如果更新标记后移动失败，先前的写入器可能失效；记录仍处于活动状态时，重新加载即可写入。标题 sidecar 仍是尽力写入。

文件系统锁需要各进程共同遵守，持锁者失效后可在 60 秒后恢复。保证适用于使用相同本地存储的当前版本参与者。旧版本 daemon 仍可能忽略此边界；依赖该保证前请升级或停止所有旧版写入器。此锁不会在原本可写入活动会话的传统写入器之间新增独占归属。

## 验证

见[双 daemon 端到端测试计划](../../.qwen/e2e-tests/2026-11-21-session-archive-write-fence.md)。
自动化存储测试使用真实文件系统，覆盖迟到标题、恢复前从未重试写入的旧写入器、首次写入争用和归档期间排队的追加。独立子进程实验使用生产写入器，并在其他进程执行归档和取消归档，核对归档原始字节和恢复后的父记录链，也验证了归档后删除的情形。
