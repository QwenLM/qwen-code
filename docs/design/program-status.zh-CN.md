# 交互式程序状态（OSC 7501）

[English](program-status.md) | [简体中文](program-status.zh-CN.md)

## 问题与范围

Issue #13870 要求终端无需解析屏幕即可获取代理状态。现有 OSC 9;4 仅显示工具活动。本改动为交互式 Ink UI 增加 OSC 7501，不新增依赖、终端白名单、能力查询、通知设置或焦点跟踪。OpenTUI 渲染器不在此次范围内。

## 状态映射

除 `clear` 外的每条状态报告包含 `app=qwen-code`。启动时报告 `idle`，响应时报告 `working`。工具审批和信任对话框报告 `blocked:kind=permission`；提问工具和其他可见对话框报告 `blocked:kind=question`；认证报告 `blocked:kind=auth`，优先于其他对话框。活动轮次进入空闲时锁存 `done`；若流报告终止性失败，包括认证过期或重试失败，则锁存 `error`。新模型轮次或 shell 轮次会重置该轮次失败信号，但不清除之前的错误提示。异步收尾期间报告的终止性失败会将锁存的 done 升级为 error。模型已恢复的单个工具错误不会将整个轮次标记为失败。并发侧查询及其独立工具续接的失败不会改变前台轮次结果。取消时报告 `idle`，并抑制该轮次的完成报告；取消期间可见的输入对话框仍报告对应 blocked 类型。下一轮开始时，以 working/blocked 替换锁存结果。打开对话框会暂时覆盖锁存结果，关闭后恢复。仅显示启动对话框不会产生完成轮次。

## 输出与生命周期

`use-program-status.ts` 使用 OSC 编码表及现有构造器和多路复用包装器生成报告。直接写入 stdout，绕过 Ink 拦截，并避免重复报告。仅 stdout 为 TTY 时启用 hook 及其清理监听器。hook 在 `AppContainer.tsx` 聚合对话框后挂载，不出现在 headless、JSON 或 ACP 入口中。

卸载和进程退出时清除未完成状态并移除监听器，保留 done/error 以便终端显示结果。对话框覆盖结果时仍会清除，避免标签页停留在 blocked。文件启动器和提示词缓冲区中已配置的终端编辑器及可识别的终端命令，以及工具确认中的终端差异编辑，发送终端释放/获取事件：交接前清除，返回后恢复当前报告，包括启动失败的情况。已配置的 GUI 编辑器不发送这两个事件。未带类型的环境变量或显式命令通过 core 编辑器命令表和有限的纯终端命令集合识别；未知或模式不确定的命令（如 emacsclient）不发送这两个事件。需要交接报告的未识别编辑器用户可选择受支持的终端编辑器。只有已发送释放事件才发送获取事件，包括临时文件准备失败时。SIGCONT 仅在 CLI 拥有终端时恢复报告。独立的状态和最后写入引用，使清除及 StrictMode effect 重新挂载后仍正确抑制重复报告。不安装 SIGTSTP 处理器，因为这会替换 Node 默认的挂起语义。挂起前清理推迟到 CLI 拥有明确的挂起生命周期之后；SIGSTOP 和操作系统睡眠无法拦截。嵌入式 PTY shell 保留 UI 所有权，不清除报告。

## 验证与验收

聚焦 hook 测试断言 idle、working、三种 blocked、锁存 done/error、下一轮重置、取消、重复抑制、退出/卸载清理、交接恢复及非 TTY 静默的精确协议字节。现有 OSC 测试覆盖帧格式和多路复用包装。执行完整构建和类型检查、聚焦测试及改动文件的 lint/格式检查。捕获交互式启动/退出的原始 PTY 字节，并在可行时用确定性模型服务器测试轮次；验证机器输出不包含 OSC 7501。支持终端的显示效果仍需手动检查。

## 风险与后续工作

终端决定如何显示或忽略该厂商起源协议。完成状态由现有 UI 状态和历史推断，不增加核心生命周期 API。不发送自由文本或凭据。焦点重置、挂起前清理和 OpenTUI 支持可在后续改动中完成。没有新增设置或迁移要求。
