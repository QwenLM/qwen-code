# 恢复会话时工具结果的放行规则

[English](2026-11-03-tool-result-admission.md)

## 行为约定

工具执行完成后，用户可以在本地会话记录里看到结果。新版写入的会话只有在记录了放行决定后，才会把结果加入模型历史。[#15595](https://github.com/QwenLM/qwen-code/issues/15595) 报告了恢复会话时把已被 `UserPromptSubmit` 拦截的工具输出发送给模型的问题。

## 写入和恢复

- 新写入的外层工具结果带有 `requiresToolResultAdmission` 标记。完成记录先于下一轮 hook 写入，工具结束后会话仍可动态安装 hook。
- 模型请求通过提示词 hook 后，会写入 `tool_result_admission` 系统记录，其中列出本轮获准结果的完成记录 UUID。发送方核对提交的工具响应及其附带内容。该记录证明输入已获准发送。模型服务端的应答情况由实际请求决定。宿主显式以工具结果结束当前回合时，例如 Goal 检查点，也在该处记录决定。
- 恢复时，工具输出在原来的位置等待对应决定。放行记录缺失或无效时，原文不会进入模型历史。只含工具结果的发送若在放行前取消，会保持历史原样，并在调用方读取流时返回取消错误。发送方在混入独立输入前标出准确的工具内容；取消时按对象身份移除这些内容，包括附带文字和图片。独立输入保留正常的历史写入和中断提示词续接行为，即使它的文字与工具附带文字相同。普通提示词和已准备请求的重放保留修改前的取消行为。若 ACP 明确拦截，或在工具完成后取消请求，模型可收到与实时会话相同的合成错误。如果进程在决定写盘前退出，沿用现有机制补齐未结束的工具调用。单独排队的用户输入保留原顺序。
- ACP 用户提示、定时任务及后台通知将已完成批次的结果传入共享模型轮次。工具结果轮次被拦截或取消时，统一记录扣留决定，并移除工具附带内容，保留单独排队的用户输入。每个完成结果保留首个有效决定。放行后若请求准备失败，包括压缩期间失败，实时历史与恢复历史都保留已放行的结果；此前已扣留的结果保留原有原因。最初的 Cron 和 Notification 请求沿用既有 hook 策略。
- 全量读取和索引读取使用同一套恢复逻辑。Code Mode 内部调用的结果仍不进入模型历史。压缩检查点已经保存模型历史，并取代之前的决定。

## 兼容性与验证

旧版工具完成记录没有放行信息，沿用原来的恢复行为，旧会话中曾被拦截的输出也受此限制。使用新版写入时，若工具完成后、放行前发生崩溃，完整结果可能只能在本地会话记录中查看。

用本地假模型检查首轮请求和恢复后的请求。分别执行拦截、放行、取消等待中的 hook，以及在完成记录落盘后强杀进程。核对每个工具调用 ID、整份请求正文和追加用户输入的位置。ACP 旧循环在工具结果轮不运行提示词 hook，可用它验证普通工具结果仍能正常放行。
