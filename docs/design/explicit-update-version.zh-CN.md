# 显式指定独立安装更新版本

Issue: #11484

[English](explicit-update-version.md) | [简体中文](explicit-update-version.zh-CN.md)

`qwen update` 目前会先通过 npm 发现版本，再下载对应的发布制品。如果运营者已经选定了某个确切版本，在无法访问 registry 的环境下就无法安装它，即使发布制品本身可以正常下载。

为 CLI 更新命令添加 `--target-version`。在本地校验并规范化所给的具体版本，跳过版本发现，并以该版本为目标复用独立安装更新器。不提供该选项时，保留现有的版本发现逻辑与安装指引。现有的 `--version` 选项保持仅展示版本的含义不变。

显式选择版本允许同版本重装与降级：它是“安装恰好那个版本”的请求，而不是“去寻找更新的版本”。接受稳定版与具体的 prerelease 版本，可选前导 `v`；可变标签（mutable tag）与格式非法的版本会被拒绝。不受支持的安装方式会返回错误，指引用户使用其安装方式手动安装该确切版本，既不进行 registry 发现，也不建议未固定版本的升级。所选版本不会被持久化：自动更新会在下一次会话中将独立安装再次向前推进，因此要保留某个确切的旧版本，需要设置 `general.enableAutoUpdate: false`。

制品路由继续遵循 `QWEN_UPDATE_BASE_URL`。归档、校验和与签名使用同一个解析出的发布根地址。请求的归档文件名带有已安装构建的 flavor（bun 运行时安装为 `qwen-code-<target>-opentui-preview`），因此 OpenTUI preview 安装保有可用的更新路径，校验中的 `runtime` 判定对这类安装也可满足。在替换安装之前，更新器会依据所请求的发布版本校验解包后归档的 `manifest.json`——`name` 必须为 `@qwen-code/qwen-code`，`target` 必须与安装的平台目标一致，`version` 必须等于所请求的版本，`runtime` 必须与已安装构建的 flavor 一致——并要求归档带有独立安装的可执行布局（`bin/qwen`、捆绑运行时，以及启动器所执行的 `lib/cli-entry.js` 入口）。这道产物身份校验在每一条独立安装更新路径上都会运行，包括后台、退出时与 daemon 驱动的更新，而不仅仅是显式指定版本。更新器在替换安装前，会将新可执行文件报告的版本与请求的版本进行核对。锁、解包防护、原子替换与回滚均保持不变。

变更仅限于 CLI 命令及其测试、独立安装产物校验与冒烟测试，以及用户文档。不引入 daemon/UI 端点、自动更新策略、registry 镜像或发布基础设施。其余产品层面的问题在对应 issue 上持续跟踪。
