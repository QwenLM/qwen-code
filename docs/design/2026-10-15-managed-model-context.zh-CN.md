# 托管模型显示与上下文占用

[English](2026-10-15-managed-model-context.md) | [中文](2026-10-15-managed-model-context.zh-CN.md)

## 问题与现状

托管新任务已经通过共享模型菜单选择宿主发布的 AgentDefinition 预设；已有会话却隐藏了模型菜单和上下文指示器。本地 WebShell 有可复用的模型与上下文控件，但修改模型和压缩操作属于 daemon，不能直接发送给托管会话。

Hosted 执行已持久化模型尝试的用量资源。服务商返回的 prompt token 数描述最近一次请求，累计计费用量不能表示当前上下文占用。现有资源尚未记录解析后的上下文窗口大小。

## 范围与行为

保留新任务选择 AgentDefinition 预设的机制。绑定工作区的公开托管会话空闲时可通过服务端发布的模型目录切换下一轮用户请求使用的模型，保留历史、指令、工具和审批策略。目录只包含已配置模型 ID 和标签，浏览器不提交凭证。当前选择与最近一次实际模型观测分开。尚无观测数据时显示 Agent 身份，不把当前宿主预设标签冒充旧定义修订的实际模型。浏览器请求不增加模型凭证或任意模型 ID。

复用上下文环形指示和浮层，显示已用 token、配置窗口及剩余容量。使用最新成功提交的主模型请求中服务商返回的 `promptTokenCount`，以及同一解析配置的 `contextWindowSize`。两者必须为安全整数，已用量非负，窗口为正。旧会话、不支持的服务商、无效元数据等缺失情况保持未知，不能估计容量或用累计消耗补缺。

本次范围是绑定工作区的 Java 托管会话。不包含手动压缩、提示词分类估算或服务商管理；不显示不支持的操作。本地模型、用量、推理与压缩行为保持原样。

## 持久化数据与投影

Hosted CLI 在现有成功用量元数据条目中附加来自解析配置的可选 `contextWindowSize`。既有用量资源、`model.attempt` 事件信封及恢复协议不变；资源的模型路由提供实际观测模型身份。已准备的请求只有在既有 Provider pin 与当前配置一致时才使用该配置的窗口；备用或恢复路由的窗口无法验证时保持未知。不需要修改核心 schema 或恢复格式。

在现有 Session Store 提交事务中，只投影状态为 `output_committed`、用量引用 kind 为 `managed-hosted-model-usage`、schema version 为 1 的 `model.attempt` 事件。Hook、started、abandoned 尝试不更新占用。核对引用资源的完整引用与已提交会话 scope，读取量不超过现有 64 KiB 资源限制。

在 `ma_session_record` 保存一条私有 SQL 投影：`record_kind=DOMAIN`、`domain=hosted_context_usage`、`record_id=latest`，指向已提交用量资源并维护既有 `SESSION_RECORD` 资源引用。不产生新的 `domain.committed` 事件，也不占用标题记录。源事件 sequence 作为投影 revision；`first_sequence` 保留首次源 sequence。会话 head 事务串行更新。每个更新的合格成功事件都推进指针，即使元数据缺失，也不能沿用更早的已知占用。

现有表约束允许该绑定会话投影，该上下文投影无需新增 DDL。快照、任务、relay 和元数据消费者保持既有域范围；通用会话退役及资源引用清理覆盖此行。不增加启动回填或日志扫描。

## 接口与页面接线

WebShell 会话摘要增加可选 `modelContext`：`modelId`、可选 `inputTokens`、可选 `contextWindowSize`、`observedAt`。只返回这些白名单字段，不返回原始资源、预算、路由、凭证或累计指标。单会话有界读取一组投影与资源；列表页完成现有授权过滤后一次批量读取观测。旧 Provider 和无观测会话继续兼容。

托管 Provider 校验并投影元数据。已有会话启用共享模型和上下文工具栏操作；可选模型禁用标志在运行、等待审批、切换中或不支持时锁定选择，同时保留本地默认行为。数据有效前，上下文控件保持可用并如实显示未知。共享浮层继续使用 WebShell portal root、作用域样式及屏幕边界限制。

## 同一会话切换模型

使用同步 WebShell `session-models/query` 和 `session-models/change` 操作。查询返回宿主目录、当前选择与能力；变更提交目录模型 ID、预期修订号及操作者范围的幂等键。重放前先核对访问权限；已完成的相同请求先于后续配置和空闲门禁重放。拒绝幂等键冲突、过期修订、不支持的 Harness、非公开或未绑定会话，以及存在运行回合、审批、生命周期或恢复工作的会话。

V5 接续已发布的 V3 会话列表迁移与本变更的 V4 工作区创建迁移，保留其资源字节和历史，为 `ma_session` 增加当前模型 ID/修订号，为 `ma_turn` 增加可空且不可变的模型 ID/修订快照。默认修订零保留原 AgentDefinition 模型行为。每轮用户请求在受理的同一会话锁内复制当前选择；派发只读该轮快照。模型变更在同一事务清除私有上下文最新投影及其投影引用，保留原始日志，避免 A 切 B 再切 A 时复活旧 A 用量；相同幂等键重放不得清除后续观测。

SDK 通过 `model-selection/1` 能力向私有 Harness prompt 接口传可选 `modelSelection: {modelId, revision}`。Harness 校验后将其写入既有 `managed-admission` 资源，驻留与冷重放都核对该选择，同时保留既有 prompt payload digest 含义。执行和恢复从该已受理输入读取选择，不能用可变的当前选择覆盖正在运行的回合。每轮新配置通过缓存凭证解析已配置的非运行时模型；模型不存在或不唯一时明确失败。不可变 AgentDefinition header、已准备请求 schema 与既有精确路由恢复保持不变。本阶段自主唤醒输入沿用既有 AgentDefinition 策略。

浏览器持久保存未确认变更的会话、模型、修订号和幂等键。成功响应经会话读回确认前锁住发送、目录修改及后续模型选择；不确定结果使用原意图重试。摘要修订门禁防止旧轮询回填旧选择和用量。切换保留消息历史，新成功请求提供用量前上下文显示未知。本地控件与新任务 AgentDefinition 预设保持独立。

## 验证与验收

1. 全局 CLI 和浏览器基线确认：已有托管会话缺少模型和上下文控件，新任务模型预设已存在。
2. CLI 测试证明元数据来自解析配置和最近 Finished 用量，不改变模型执行或恢复信封；容量缺失或无效时不猜测。
3. Java 测试覆盖仅主模型成功提交投影、scope 与引用核对、单调重放、未知替换旧值、批量读取、安全字段投影和旧资源兼容；上下文投影不增加 DDL；验证 V4 到 V5 保留既有会话及每轮选择快照，原清理流程保持有效。
4. 前端测试覆盖实际模型显示、空闲切模型、忙碌时禁用、未知与已知占用、刷新、会话隔离、本地默认行为和新任务预设。
5. 在演示中用新建真实模型任务生成快照，与原生已提交记录核对；刷新后百分比与剩余量计算一致。不能以工具效果或计费推测替代证据。检查桌面及 390px 浮层，保留此前会话和文件。
6. 交付前完成构建、类型检查、打包、针对性测试、双语文档、连续两轮干净自审和独立审查；只在验收任务静止时更新本任务所属演示进程。
