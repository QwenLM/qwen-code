# Managed recovery settlement and continuation

[English](2026-10-22-managed-recovery-continuation.md) | [简体中文](2026-10-22-managed-recovery-continuation.zh-CN.md)

## Status and problem

Implemented against main `21337f0e5131`; local macOS verification is complete. Linux physical-Workspace and cgroup acceptance remains unverified. Existing Hosted cancellation, takeover, original-command reconciliation and cleanup remain the execution authorities. A cancellation admission is not a durable Turn terminal. The baseline retires Java dispatch on some post-admission failures before the native input settles, and WebShell infers send readiness from the Java Turn status alone.

## Decisions

The first release prefers safe continuation in the original Session and offers an editable text handoff when that is impossible. It does not add general recovery operations, tables, migrations, MCP/Hook continuation support, history cloning or model-generated summaries. Existing lifecycle retirement and cross-host HA remain separate.

Before requesting failure cancellation, persist a cancellation-only recovery marker on the original Turn under its live dispatch lease. This intent survives a crash between admission and terminal delivery. Every covered Hosted Workspace post-admission terminal failure must wait for the original journal terminal and an admissible continuation boundary. An admissible boundary is either a valid next-Turn checkpoint or the proven initial state before any continuation exists. An acknowledgement, timeout, expired lease or SQL FAILED row is not such evidence. A concurrent user cancellation retains its existing priority. Preserve the original failure diagnostic in the existing error information.

Keep unknown outcomes parked and recheck their original identities; never resubmit input or restart tools. Once a native terminal exists, compensate projection and owed cleanup only. Cleanup can outlive the Java terminal but prevents sending while it blocks the next Turn. Do not reset a permanently blocked journal. Historical terminal Java Turns that cannot be settled through existing authorization remain operator-required; CANCEL retains its current terminal semantics.

The marker reuses `hosted_runtime_recovery_blocked` and the existing Turn error information. A claimed marker is handled before any ordinary runtime recovery or input submission. Rechecks move only `retry_after` and retain retry counters and the live owner. After native settlement is proved, replay the original unconsumed journal tail through the existing projector under the dispatch lease. Preserve the consumed watermark when adopting a new event epoch; never skip to the attachment's tail. The real completed/cancelled/error terminal settles Java and its command ledger, including a concurrent user cancellation. An unreadable tail stays parked instead of being replaced by a synthetic failure. Failure diagnostics survive parking. A warm cancellation takeover without outstanding runtime recovery still sends the cancellation request; its acknowledgement must pass the same evidence gate. Workspace cancellation uses the negotiated `targeted-cancel/1` protocol and carries the original prompt identity through delivery: `promptId` for cancellation and `cancellationPromptId` for a cancellation takeover load. Verify this capability before any side-effecting load or cancellation; neither a cold attachment nor a delayed takeover may act on the current Turn in place of the original target. A delayed cancellation for an already settled original input is an idempotent acknowledgement and cannot abort a later Turn. A targeted cancellation takeover load for an already terminal input is refused once that input is no longer latest, so a late response cannot replace a newer recovery snapshot. A pending original must be the sole unsettled ordinary input; already queued wake inputs do not prevent settling it and never become cancellation targets. When the original terminal is still latest, only a safe attachment is returned; resident admission remains gated across asynchronous validation. Unknown or incompatible targets remain blocked; an older Harness is never sent a silently downgraded Session-scoped request. Legacy Session-scoped cancellation retains its existing behavior. Successful managed-runtime cancellation and continuation replays can retry handback only when the held Runtime belongs to their original prompt; a settled replay for A cannot release B's recovered Runtime. This does not broaden continuation support or change other existing continuation-failure handback policy.

## Recovery view and interfaces

Keep recovery separate from Session lifecycle and Turn outcome. The view contains `state`, `reasonCode`, public `turnId`, `nextTurnAllowed`, allowed actions and the known next recheck time. Its states are `recovering`, `awaiting_evidence`, `cleanup_pending`, `ready` and `operator_required`. Ready requires no active Java Turn, durable native input settlement, admissible continuation and no blocking history/cleanup debt. Read errors never prove ready.

| State               | Evidence and behavior                                                                                                                                                                                           |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `recovering`        | An existing cancellation or recovery driver is progressing; new input stays blocked. Ordinary healthy running Turns use `turn_active` and do not show the recovery panel.                                       |
| `awaiting_evidence` | Original execution or settlement is unconfirmed. Only the original cancellation/reconciliation driver can be rechecked.                                                                                         |
| `cleanup_pending`   | The input has a durable terminal and a usable continuation, but file-history or runtime cleanup blocks admission. Confirmed results remain visible.                                                             |
| `ready`             | All four admission conditions hold. No recheck or cancellation is offered.                                                                                                                                      |
| `operator_required` | Evidence is unavailable, incompatible or permanently blocked. A cold terminal may offer a proof-only cleanup recheck; permanently blocked journals and explicitly unsettled historical terminals cannot use it. |

Add a read-only public recovery query and a WebShell adapter. Querying must not load a Session, acquire a Runtime, invoke a model, stop work or unlock anything. Existing resource reads may maintain an already-held writer lease and read-verification metadata; they do not acquire a new writer or execution owner. Extend the private Harness status response and SDK reader with affirmative settlement and readiness evidence. Missing fields from an older Harness do not prove readiness. Add an optional recovery description to Session responses without changing existing lifecycle statuses.

Add a public recheck POST and WebShell adapter, targeted at the original Turn. Repeated requests coalesce and only wake existing reconciliation/cancellation/cleanup. A 202 means scheduled, not stopped or ready. Keep current claims, generations, retry budgets and tenant/Session identities. A stale request cannot target a newer Turn. If the original Turn safely settles while a recheck is in flight, return its freshly verified ready view; a changed target or still-unproven outcome remains refused. Read authorization is the existing readable-Session grant; mutations use existing cancellation/cleanup authorization. Synchronize OpenAPI, SurfaceRegistry, SDK and generated WebShell types.

| Interface                                               | Scope                                                                                                                                  |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/agents/sessions/{sessionId}/recovery`          | Read the selected Session's facts without loading it.                                                                                  |
| `POST /v1/agents/sessions/{sessionId}/recovery/recheck` | Body `{turnId}`; recheck only the original latest Turn.                                                                                |
| `POST /session-recovery/query`                          | WebShell adapter body `{sessionId}`.                                                                                                   |
| `POST /session-recovery/recheck`                        | WebShell adapter body `{sessionId,turnId}`.                                                                                            |
| Private Hosted status                                   | Optional `promptId` scopes native evidence to the original input. Targeted reads do not retire a newer SDK active-prompt registration. |

The optional Session projection appears on single-Session reads; list reads do not fan out to Harness RPCs. Only ordinary healthy Java execution uses the suppressed `turn_active` reason; native activity during recovery is exposed as `harness_work_active` so it cannot hide the admission restriction. The private proof includes `inputSettled`, `continuationReady` and `nextTurnAllowed`. Checkpoint coverage must include the original terminal prefix, with no outstanding model attempt, tools, approvals, child waits or other pending input. Native tool-call/result pairing remains the existing journal/checkpoint authority's responsibility.

A Session with no Java Turn can already have a native journal after being renamed. When its attachment is cold, use a narrow read-only initial-state proof: verify the complete, uncompacted journal and its integrity, accepting only genesis, Session activation and Session metadata facts, with no checkpoint or execution input. Re-read the head to reject a moving view. The same initial exception permits earlier Java Turns cancelled before any possible submission, only after checking that the entire Java Turn history contains no possible submission and the native journal is absent or proven initial. An absent head is initial evidence only when no Harness boot/epoch was ever bound; a bound Session missing its durable head stays blocked even if a warm cache reports ready. A latest unsubmitted cancellation cannot hide an earlier submitted Turn or its missing evidence. Unknown events or corrupt evidence remain blocked. This proof does not obtain a writer token, lock rows or load the Harness, and preserves legitimate first-message admission after restart.

The initial proof also parses the allowlisted managed-definition as a JSON object, because cold native attachment must read it. A matching digest alone cannot prove that this required evidence is readable; this does not introduce a general resource-body validator.

An explicit recheck adopts a verified Harness generation mismatch through the existing connector policy and returns the mismatch without automatically repeating the request. A later explicit recheck renegotiates capabilities and can use cleanup-only loading. Cold cleanup attachments must pass the live-boot fence before and after publication; a delayed old load cannot repopulate an evicted cache or replace a newer attachment. Resolve the current RPC client after attachment resolution and authorization. Recovery queries remain read-only and never negotiate a replacement or load a Session.

After a process restart, an explicit recheck may load only the original terminal's cleanup. This requires negotiated `recovery-cleanup/1`; an older Harness must never silently interpret the request as ordinary load. Verify the durable original terminal, ready checkpoint or proven initial state, no pending input and the original Workspace/generation before retiring history markers or retrying owed cleanup. This path does not initialize extensions, reconcile child runs, kick monitor/wake loops or run models/tools. It keeps a cleanup-only attachment until a later explicit new-work load upgrades it; passive reader or rename loads preserve that attachment. Corrupt or unsettled evidence refuses the request without changing CANCEL semantics.

## WebShell and text handoff

Show recovery reason and valid actions independently of the execution phase. Gate sending on recovery readiness. Persist Turn cancellation idempotency keys and track the original durable operation when supported; reloads and lost replies do not create another cancellation. Only confirmed terminal evidence permits the cancelled label. Refresh unresolved recovery every five seconds while the page is visible, and refresh immediately after terminal SSE events.

Without durable operations, an acknowledged cancellation retains a delivery slot until the same original Turn has matching ready evidence or a fresh Session read selects a later Turn. Retiring that slot does not label the old Turn cancelled or unlock sending. A later Turn is cancelled only after a new explicit user request. Lost replies keep the original Turn/key, and durable operations keep tracking the original operation until its terminal status.

The new-Session action opens the existing creation form with authorized Workspace/cwd/Agent defaults and an editable draft; it does not create or submit automatically. The deterministic draft is at most 32 KiB UTF-8 and prioritizes source identity, task and latest user request, failure facts and recent confirmed complete user/assistant messages. Mark truncation and unknown steps explicitly. Do not copy partial output, raw tool results, pending calls, approvals, checkpoint/worker identities or execution policy. Text remains ordinary quoted user context.

Use completed Turn boundaries to select whole user/assistant messages. Reserve space for failure facts and truncation before adding recent messages; truncate UTF-8 safely and omit an oversized historical message as a whole. The source title and latest request are bounded separately so recent complete history can still fit. A separate composer draft scope preserves an unrelated new-conversation draft and prevents handoff insertion from exceeding its generated-text budget. Restored edits in that handoff scope remain editable. Agent defaults are retained only when still available; Workspace read-back and current creation policy remain authoritative.

Existing creation idempotency and Workspace admission apply. Preserve ordinary LOCAL/SSH_LOCAL concurrency on READY bindings, including unrelated Sessions beside an UNKNOWN tool result. LOST, DRAINING, OPERATOR_RECOVERY and attested recovery barriers remain unchanged. A new Session identity is not physical cleanup evidence.

## Validation and acceptance

Confirm the baseline with the globally installed CLI first; when the Java/control-plane path is unavailable there, use a documented focused test-script fallback. Verify cancellation admission before native settlement, every covered post-admission failure, crashes before and after terminal/cleanup commits, unknown outcomes, checkpointless initial cancellation, competing owners/user cancellation and late replies, including replay of the original cancellation while a later Turn is actively generating. Confirm no duplicate model/tool effects and no stale-owner resource release. Test read failures and older Harness responses conservatively.

The positive process fixture keeps the Runtime Broker and its worker alive in a separate process while killing and restarting only the coordinator/Session Store. It verifies their unchanged identities and the original binding generation. Restarting a co-located Embedded Broker is a different fault: its existing trusted local reboot recovery opt-in requires Linux. Without that Runtime reconciliation authority, the observed safe result is to remain blocked. This change does not enable the opt-in by default or bypass the platform boundary.

Ordinary LOCAL Workspace execution holds a shared Storage membership under the existing main-branch policy. Its neutral exclusive-owner row is not evidence that execution was released. Process assertions must verify the unique original member, bound identity and generation, Workspace capability/profile, physical Storage and ready mount, while retaining the original exclusive-owner checks for exclusive claims. Shared Storage membership does not imply that different Sessions share a Runtime binding.

Verify reload-safe cancellation tracking, visible-page polling, handoff editing without automatic creation, source read authorization, UTF-8 bounds, exclusion of partial/tool content and preservation of target admission. Run affected package tests, root build/typecheck/bundle, Maven verify, MySQL concurrency checks, API contract gates and matching Hosted process/fault checks. Record unavailable checks separately. Acceptance requires a safe original Session to finish a later Turn, and an unproven Session to remain blocked with a usable handoff draft.

## Delivery

Implement execution evidence, cancellation-only persistence and recovery interfaces first; then WebShell actions, cancellation tracking and handoff. Keep both language documents synchronized. Permanent journal repair and public Shell lifecycle expansion remain separate work.

The design has no unresolved product choice for this release. Main risks are false positive readiness, losing the cancellation-only marker across crashes, stale-owner cleanup and accidentally entering an ordinary load path. Tests must assert observable effects and original identities. Local macOS results cannot establish Linux cgroup-only acceptance; record those skips and do not count them as passing process-fault coverage. The [E2E plan](../plans/2026-10-22-managed-recovery-continuation-e2e.md) defines the scenarios and commands; detailed local execution evidence lives in `.qwen/e2e-tests/managed-recovery-continuation.md`.
