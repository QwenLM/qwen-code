## Status and problem

This document records bounded local current-schema acceptance and its plan; it adds no recovery permission. At revision `6717ce88820dc99982b14350ae777669a42b2907`, which incorporates main `46bf492d05f4520bfd918c62e104d45f433da493`, production code permits a successor to skip an expired writer claim that never installed an activation. The existing C6 process result predates the canonical schema and current module composition. The current RC/RR contention result keeps a producer parked inside a callback; it does not establish recovery after operating-system process death.

The accepted fresh C6 scenario uses the current canonical schema: kill the original text Main and Hosted processes after the final tool receipt commits, kill a second pair after its writer claim commits but before its response is delivered, and recover the original prompt with a third pair. The scenario reproduced the usage metadata defect below; its correction and the renewed process run are included.

The second fresh process invocation on `594032afdc42e0c5a3f130c05208187c0232a5ab` reached the real first model output and exposed such a defect before any tool execution: current Hosted includes `contextWindowSize` in its usage snapshot, but the native verifier closed the snapshot to five token counters and rejected the legitimate extra field. The correction accepts optional positive safe-integer context-window metadata, including the full JavaScript safe-integer upper bound, while preserving the legacy five-counter shape and rejecting invalid values or unrelated fields. It preserves original usage bytes and digest bindings, without changing ownership, activation, lease or recovery permissions. Merged verification now includes all 28 focused proof cases, the unfiltered same-worktree SDK/Server checks and the fresh complete C6 process chain. The original failed process artifacts remain failed.

The Kubernetes API, placement and mount provenance remain explicit local fixtures. A small fixture copy selects an existing reachable local non-loopback IPv4 before Pod creation, so production placement and handle generation retain the same address throughout. A strict one-shot worker listen facade changes only the original `43190/0.0.0.0` bind to that selected address and restores the method immediately. The unchanged ready envelope is a startup signal; the production placement-derived endpoint is the connection address. No alias, route, hosts, firewall, production IP validation or authentication changes are permitted.

The existing Darwin platform, mount observation and proc-FD mapping delegate actual file operations to owned real files. They do not establish a native CSI mount, Kubernetes admission, kernel confinement, actor closure, physical retirement or reuse. Broker-to-worker calls use the default production HTTP transport without destination remapping. The production Hosted writer and activation lease duration remains 60 seconds; both expirations use database time without SQL updates, injected clocks, seal or release operations.

The local API fixture exposes Pending until the independent worker has actually started listening, then lets the production provisioner poll and attest normally. The original component fixture gated its remapped transport; using its eager Ready status with an ungated default transport introduced a startup race and is not retained. Independent address probes observed that this macOS JDK selects the existing local HTTP proxy at `127.0.0.1:7897`; both selected-address Java and Node requests reached an already listening server successfully. Preserve that default network path and record it as an environment boundary; do not infer a direct socket path or native cluster networking from this scenario.

## Scenario and evidence

1. Freeze source, built products, helper inputs and the Java/Node dependency files before launch. Record real paths and hashes, then compare them after execution. A loaded module outside the frozen dependency set invalidates the qualification; pre/post hashes alone are not native immutability proof.
2. Create the original Session through the existing private producer, warm the actual provisioner and start the independent worker. The first real owner runs the original prompt and the two tools. Hold the last successful receipt response after SQL commit and before delivery. Verify both executions are settled, receipts complete and the repair message/resolve absent; SIGKILL both registered owner processes and confirm exit.
3. Retain the worker, database and files. Observe database time until both original writer and activation leases naturally expire. Compare the complete database and file image with the post-crash image.
4. Start the second real pair. Hold its committed writer-acquire 200 response before delivery and activation installation. Verify generation 2, unchanged activation epoch 1 and unchanged writer credential hash; only the head writer ID, generation, lease and modification time may change. SIGKILL the pair, confirm exit, and again wait for natural expiry without writes.
5. Start the third pair with the identical original prompt ID and text. It must acquire generation 3, install activation epoch 2, repair the original tool message and resolve, make the actual second model request, consume and settle the original turn, and return ready for the next turn. There must be no generation-2 journal entry, repeated native execution or third model call.
6. Capture original HTTP envelopes, database-clock samples, process identities and death readbacks, complete typed database images, file bytes/inodes, model requests, journal/resource bytes and final Main output. Resource verification timestamp changes must correspond to captured successful same-scope resource GETs; preserve every other cell and qualify any read-receipt additions explicitly.
7. Stop only owned processes, remove the owned database and worker scratch tree, and read back closed listeners, exited processes and removed database/storage. Preserve evidence and failed attempts.

Before/after checks cover 128,634 files and 187 symlinks without drift. Actual loaded files for the coordinator, worker and all three Hosted owners stay within that pinned closure. It does not relabel the earlier run as a pass.

## Acceptance and remaining work

A pass requires actual process death at both cuts, real committed generation-2 claim without activation installation, natural lease expiry, generation-3/epoch-2 recovery, exact original batch/result identity, exactly two model requests, settled original turn and verified cleanup. A parked promise, synthetic generation, manually appended journal, replayed model output or shortened lease cannot satisfy this plan.

The separate fresh C8 result after atomic complete-output commit is recorded in [canonical complete-output acceptance](2026-10-18-k2-canonical-complete-output.md). Full native actor confinement, cloud installation, physical cleanup and reuse remain unfinished and cannot be inferred from this local test. If no existing local address can bind and self-connect, record an unavailable default-transport baseline; a remapped-transport experiment has a narrower scope and cannot replace it. No other design question is open for this increment.
