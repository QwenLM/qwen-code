# Android Blob 下载

[English](android-blob-downloads.md) | [简体中文](android-blob-downloads.zh-CN.md)

## 问题与现状

Web Shell 通过 Blob URL 和下载链接导出会话、工作流历史和工作区产物。Android WebView 无法把这些仅存在于渲染器中的 URL 交给 DownloadManager。原生外壳目前没有下载目标选择或字节传输功能。本后续改动基于连接配置切片，不修改服务器认证或最初的移动外壳 PR。

## 拟议改动

添加 Web Shell 内部 Blob 保存辅助函数及原生控制器。现有导出调用方等待该函数，并通过已有错误界面显示失败；预览下载链接仅在原生能力存在时使用它。普通浏览器和桌面外壳保持下载链接行为：点击停止传播到宿主导航处理器，并在一秒宽限期后才撤销对象 URL，让浏览器有时间读取内容。仅用于预览的对象 URL 不变。原生传输仅处理已获取的字节，不执行带认证的网络请求或远程 URL 获取。

独立 transcript 构建保留浏览器保存及来源取消检查，但在编译时排除应用专用的原生传输。导出的 HTML transcript 是浏览器文档，不是已配置的交互式 Web Shell 源。其现有下载操作不会获得原生 16 MiB 限制，并继续执行不变的 transcript 包大小门槛。交互式构建和完整库构建保留原生保存。

产物链接直接传入原始 Blob；图片标签页在本地解码 data URL。测试中的 WebView 在守护进程的 `connect-src 'self'` 策略下阻止 `fetch(blob:...)` 和 `fetch(data:...)`，因此辅助函数不会获取这两种 URL。只有 Blob URL 而没有原始字节时，会显示重新打开或使用浏览器的提示，不放宽 CSP，也不静默失败。

Android 在加载配置的源之前通过 AndroidX WebMessageListener 注入 `qwenAndroidDownloadV1`。必须同时支持 `WEB_MESSAGE_LISTENER` 和 `WEB_MESSAGE_ARRAY_BUFFER`。监听器验证实际来源、主框架标志、当前挂载的 WebView 和文档生命周期。响应使用绑定到框架的 JavaScriptReplyProxy。不引入通配来源或无限制的 JavaScript 接口。

## 协议与限制

每个原生控制器最多有一个活动导出。版本 1 的 JSON `begin` 消息包含随机的 32 位十六进制 `id`、文件名、MIME 类型和精确字节数。元数据最多 2 KiB。发送端按 Unicode 码点限制文件名，避免拆分 UTF-16 代理对。Android 替换路径分隔符、Unicode 控制/格式字符和未配对代理字符，再将文件名限制为 255 个 UTF-8 字节且不拆分码点；通过缩短主文件名保留不超过 15 个 UTF-16 单元的末尾扩展名。移除开头的空白以及末尾的空白和点，但保留 `.gitignore` 和 `.env` 等名称开头的点。空白或仅含点的名称使用 `download`。它验证 MIME 类型，并接受零到 16 MiB 的大小。这是明确的原生专有限制；普通浏览器原有的 100 MiB 工作区下载限制不变。

收到 `ready` 后，发送方通过 ArrayBuffer 消息传输，每块最多 64 KiB。每个帧以 32 个 ASCII ID 字节和四字节无符号大端偏移量开始。Android 只接受当前 ID 和精确的下一个偏移量，逐块确认并拒绝溢出或不完整传输。同时最多等待一个块的确认。有界内存缓冲区避免明文暂存文件；即使取消，活动槽位也会保持占用，直到文档提供程序的写入线程退出。

完整长度的 `finish` 消息以建议文件名和 MIME 类型打开 `ACTION_CREATE_DOCUMENT`，由用户选择目标。`choosing` 确认结束传输超时；用户选择目标时不设置短超时。最终响应报告 saved、cancelled 或 error。原生保存开始后，出错不会回退到下载链接而产生重复下载。传输确认在 30 秒后超时。显式 cancel 消息释放未完成的传输。

## 所有权、权限及失败行为

仅接受具有返回写入授权且实际写权限有效的外部 `content:` URI。拒绝本应用提供程序、非 content URI 和缺失授权。不请求广泛存储权限或持久化 URI 授权。写入在 UI 线程之外运行，在打开目标前检查取消。一旦目标已打开，即使页面卸载或 Activity 重建，也会完成有界文件的写入；不会向已取消或过期的页面发送 saved 回调。提供程序错误会显示；开始写入后的 I/O 失败或进程终止可能留下部分目标文件。应用不会删除任意提供程序 URI 来掩盖失败。

导航、切换连接、连接错误、渲染器丢失和 Activity 销毁均使传输失效。迟到回调不能关联到新文档或新连接。系统选择器槽位保持占用直到结果返回；Activity 重建时仅保留该占用状态，不保留字节、URI 或页面回调。正常跳转到系统保存选择器不会使纯文本连接失效。麦克风授权已合入 main：其预检会在打开文档选择器或创建目标文件前取消已获麦克风授权连接的 Save，并提供明确的重新连接选项。麦克风后台关闭策略保持不变。

main 中的连接恢复可以在 Activity 重建后通过新的 WebView 恢复纯文本连接，但不会恢复导出：销毁时取消旧传输，尚未返回的选择器结果占用状态单独恢复。连接错误和渲染器丢失会先执行统一的连接清理，再显示 Retry，因此恢复流程不会保留下载字节，也不会把过期的 Save 结果关联到新页面。

## 受影响文件与范围

原生修改仅限移动外壳下载控制器、Activity 接线、设备测试和 README。Web Shell 修改仅限内部保存辅助函数、会话导出调用方、工作流历史导出、产物下载及链接和相关测试。不提议修改守护进程路由、SDK 认证契约、服务器端凭据签发、后台服务、公共宿主 API、依赖或工作区成员。

## 验证与验收

实现前用父版本 APK 和真实 HTML Blob 下载确认不会打开原生保存目标。全局 CLI 无法测试 Android WebView，因此改用父版本 APK 和本地合成夹具，并单独记录 CLI 是否可用。

APK 和 Web Shell 必须同时包含此协议。新版 Web Shell 配合旧版 APK 时没有原生桥，可能静默失败；请升级 APK 或使用浏览器。新版 APK 可在不支持的 H5/provider 下载到达 WebView 时显示浏览器/更新提示。

验证提供程序首次写入后取消仍保留目标的全部字节，即使来源页面仍为当前页面也不报告成功；打开目标前取消仍应不写入。成功写入后必须为匹配的传输恰好发送一次 `saved` 终态响应并释放槽位。验证普通浏览器回退、二进制和零字节导出的逐字节一致性、包括 `.gitignore` 和 `.env` 的文件名、原生大小上限、块顺序和 ID、忙碌状态、超时及取消。通过针对性测试覆盖所有修改的 H5 调用方。在 API 26 和 36 模拟器上验证真实 WebMessage 传输、系统保存选择器、目标字节、取消后重试、恶意框架或来源消息、导航、重建及迟到选择器结果。构建并类型检查仓库、打包 CLI，以及构建、静态检查和测试原生包。记录提供程序不支持的能力，不把它们计为通过。发布前完整审查最终差异两遍，并取得独立代码审查。

## 待确认事项

提高原生 16 MiB 上限需要另行审查存储和内存策略。任意服务器 HTTP 下载、断点续传及后台下载不在范围内。可独立审查的连接、文件选择器、麦克风和下载切片需在维护者明确方向后进行集成验证；仅此切片不代表完成 Android Phase 2。
