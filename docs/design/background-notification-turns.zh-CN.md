# Web Shell 中的后台通知执行

[English](background-notification-turns.md) | [简体中文](background-notification-turns.zh-CN.md)

## 问题

后台结果会进入 Session 队列，但处理结果的自动执行没有进入 bridge 的 prompt 生命周期。通知可能在前一个 RPC 的终态事件发布前继承其 prompt ID，后续输出又丢失外层 prompt ID，live-state 则在实际执行期间报告空闲。因此，用户插入的消息可能被提升为中断当前执行的新 prompt。原有用户输入和停止路径还会丢弃排队中的结果。

## 行为

后台子智能体保留发起它的执行 ID 和工具调用 ID。如果结果属于当前正在执行的 turn，就在模型的安全边界从同一个通知队列中消费，此后不会再触发重复的自动 turn。其他执行活跃时，来自更早 turn 的结果继续等待。任务完成的展示独立于结果消费。空闲时，每条结果启动一次使用共享会话历史的独立自动执行。

自动执行期间发送的用户输入使用现有 mid-turn 队列。在执行结束边界到达的输入，会在最终边界前消费，或通过现有用户 prompt 路径提升为后续执行。显式停止取消当前执行，并暂停通知消费，直到新的用户 prompt 开始执行；待处理结果会保留。

## 实现

| 层              | 改动                                                                                                                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core 任务注册表 | 注册任务时捕获来源 prompt 上下文，并在终态回调元数据中携带。                                                                                                                                    |
| ACP Session     | 在安全边界消费属于同一执行的结果；维护队列归属；取消时保留结果；为自动执行的每条更新携带生命周期标识；通过需要确认的启动准入，确保前一个 RPC 的终态先于自动输出发布。                           |
| ACP bridge      | 跟踪可选的后台执行描述符（turnId、taskId、toolUseId、sourceTurnId、label、startedAt）。处理启动准入和结束通知，关联输出及权限请求，处理剩余 mid-turn 输入，并将执行状态纳入快照及相关操作保护。 |
| SDK             | 在 live/load 快照和生命周期事件中携带后台执行元数据，包括回放。                                                                                                                                 |
| Web Shell       | 复用现有任务状态同步和 mid-turn 输入；按时间顺序追加轻量结果标记，提供来源和现有任务面板入口；折叠时保留最新主智能体回复，并在工具没有输出及页面刷新期间保持执行状态。                          |

Session 负责通知消费，bridge 负责传输层执行状态的可见性。只有前序 prompt 的终态发布后，才确认启动准入；不等待排队中的后续 prompt，以免与子进程的历史串行化形成死锁。已被停止或取代的启动请求不能重新激活执行状态。结束事件只清理匹配的执行 ID。现有 Goal 语义保持兼容。

## 文件与范围

生产改动涉及 core 后台任务元数据、ACP Session 及其事件发送和记录、bridge 客户端/类型/运行时、SDK daemon 类型与规范化，以及 Web Shell 会话状态、消息适配器和列表渲染。测试与对应源码放在一起。不计划新增依赖、通用调度器或公开 daemon 路由。现有厂商扩展方法可以增加后台来源。

## 验证

定向测试覆盖启动与终态顺序、过期结束事件、同 turn 结果消费、不重复自动执行、其他 turn 的结果排队、工具和最终边界的用户输入、停止时保留结果、live/load 一致性、权限归属及回放分组。使用确定性的本地模拟模型/daemon 场景验证实际传输和浏览器投影，排除模型输出变化。基线使用全局 qwen，修后验证使用本地 bundle。需要完成构建、类型检查、定向测试、完整 diff 自审和独立 review。

## 决策

用户消息与模型执行 ID 是不同概念：mid-turn 指导是当前执行中的真实用户消息。后台任务活动与主模型执行也是独立状态；仅有排队或仍在运行的任务不会使 hasActivePrompt 变为 true。Shell、monitor 和 workflow 通知共用自动执行生命周期；同执行注入仅适用于带来源元数据的子智能体。旧数据缺少来源元数据时，回退到排队自动投递，不猜测其是否属于当前 turn。bridge 重启后若子进程仍存活，可靠恢复必须使用现有 load/运行时快照路径，不能仅凭历史启动记录推断正在运行。

## 对话展示

自动执行 ID 仍是传输层生命周期标识，不产生额外用户轮次。每个后台结果有一个轻量标记，提供“来源”和“查看详情”操作。来源定位发起任务的工具，详情打开现有右侧任务视图。子智能体原始输出保留在该视图中。完成和消费的重复通知会被去重，原工具在等待结果处理时显示完成状态。

每个用户轮次折叠时，保留最后一段完整的主智能体回复，包括自动执行产生的回复。较早的主回复、思考和工具折叠进现有过程区。结果标记按时间顺序保持可见，不产生轮次导航项或独立轮次统计。后续用户消息仍开始新的可见轮次。缺少后台元数据时沿用旧展示方式。

## 后台任务活动

Live-state 还携带 `hasRunningBackgroundTasks`，与 `hasActivePrompt` 和 `backgroundTurn` 独立。至少有一个后台任务正在运行时为 true，没有任务仍在执行时为 false（暂停任务不执行；正在启动或暂停过程中的 workflow 仍计入）。主智能体空闲、子任务运行时，用户仍可输入，侧栏展示后台活动。兼容旧 daemon 缺少这些字段的情况。状态必须来自实时任务归属，不能从历史 transcript 推断。

侧栏优先显示 prompt 的 loading 图标。主智能体空闲且 hasRunningBackgroundTasks 为 true 时，前置状态位显示琥珀色呼吸灯及后台任务提示；false 或字段缺失时清除该标记。鼠标悬浮在后台灯上时隐藏操作按钮，悬浮在其他位置时保留原有操作。

Live-state 请求通过 catalog 和 provider 保留本地单调时钟的请求开始时间。后台 start/end 事件和 load 快照使用相同本地时钟记录观察时间。早于最新后台状态观察发起的响应，不能替换该状态或触发空闲收尾；后续空闲响应仍可收尾终态事件丢失的后台执行，即使此前没有轮询到活跃状态。这些时间戳仅保留在 Web Shell，无需修改 daemon 协议。

## 通知传输失败后的恢复

现有 active-work 心跳重复报告最后结束的后台执行 ID。bridge 只收尾匹配的执行，因此结束通知丢失后无需用户输入即可恢复，过期报告也不能停止较新的执行。后续成功的 RPC 同样能证明其前序自动执行已经结束；仅派发 RPC 不能作为证明。

准入失败时保留结果，并在 1、2、4 秒后重试；持续失败后明确提示用户发送消息，不无限循环。重试复用执行 ID，启动准入具备幂等性。显式停止取消重试定时器；新的用户 prompt 重新启用保留结果的处理。

SDK 将启动标记规范化为状态，而非 assistant 正文。Load 和 live-state 忽略格式错误的后台描述符。折叠逻辑将后台标记视为执行边界，因此只有工具输出或被取消的续跑不会隐藏此前完整的主智能体回复。

## 归属与交错结果

RPC 交接期间优先采用显式后台来源。即使旧后台描述符仍等待同步，活跃用户 RPC 的未打标权限和文本也保留该 RPC 的身份及发起客户端。状态标记分割 transcript 文本块，后续文本不会移到标记之前。SDK 回放根据经过验证的后台来源补齐缺少的 prompt ID。

后台标记在首次观察到执行时捕获对应任务结果。该执行的后续输出不能消费或改写同一任务 ID 的较新完成结果；显式消费通知仍可确认较新结果。回归覆盖准入等待被取消、其他后台执行的准入，以及完整 transcript 历史缺少发起工具时从任务列表恢复详情。

Review 修复确保折叠时保留仅被被动任务完成标记分隔的所有主回复片段。工具执行和自动执行标记仍作为回复边界。在真正开始执行前被取消的 pending prompt，不会解除停止操作造成的通知暂停。Mid-turn drain 携带实际消费它的 RPC/后台执行 ID；bridge 在移除排队输入前验证该 ID，并在附件 I/O 期间保留归属。缺少该字段的旧 drain 保留原有回退。过期后台描述符不能丢弃较新本地 prompt 的终态，包括 HTTP 准入返回前收到的终态；旧后台终态也不能收尾尚未绑定 ID 的本地 prompt。

同 turn 消费在保留结果之前加入待发送的队列溢出摘要，并进行记录；取消时保留组合后的输入。展示失败不会丢弃模型输入。Web Shell 只对带任务 ID 的通知去重，因此独立的队列丢弃诊断仍然可见。后台准入在等待前序终态之前和之后都检查 worktree 重置屏障；所有权转移后，存活的旧 session 不能启动自动执行。
