# Managed restart cancellation recovery

[English](managed-restart-cancellation-recovery.md) | [简体中文](managed-restart-cancellation-recovery.zh-CN.md)

## Problem and scope

Process acceptance found three connected gaps: exhausted transient HTTP renewal retries stopped the background cadence; an unacknowledged prompt after writer expiry could not cancel; and terminal recovery refusal used plain cancellation even when the parked Turn required takeover. Public failure did not settle the native input, so the existing close gate correctly remained shut.

This change repairs these paths without enabling Full Access, replaying Shell, resuming expired writers, bypassing idle-journal checks, or adding public API fields. Automatic continuation after a full writer-lease outage remains outside scope.

## Decisions

1. Keep the healthy renewal cadence. After transport or retryable 5xx failures exhaust their request budget, reschedule at one second only while the original grant remains live. Stop on expiry, refusal or seal start, including in-flight close races. Never acquire a replacement grant implicitly. An activation heartbeat transaction may continue unchanged after three attempts only within the original writer lease captured at submission; ordinary transactions retain their three-attempt limit. Tenant-guard contention retains its shared request budget and cannot restart it through activation retries. Preserve transaction identity, bytes and digests, and retain any later lease obtained by concurrent writer renewal when applying the receipt. Stop background writer renewal after an unrecoverable journal append, except a known rollbackable non-commit refusal. Never clear the authority write-failure latch.
2. A missing admission epoch is not proof of non-admission. Only a dispatch owner with a live claim may cancel an ambiguous prompt after locking its Session and original head, proving the writer sealed or expired and the scoped, uncompacted journal completely idle. Check prior admission using that same head-verified scan, with the Session's protocol and confirmed cleanup; never issue a second snapshot read for that decision. Withdraw the submission mark and cancel in the same transaction. Missing, foreign or incomplete evidence stays blocked; an accepted native input cannot use this shortcut.
3. For Workspace executions, use cancellation takeover and the original checkpoint/activation/prompt before terminal recovery failure. Workspace failure cleanup has a separate internal authorization: the exact admitted RUNNING Turn, its live dispatch owner and its recorded admission epoch must match before checking the original Session structure. It does not require a public cancel command or grant new execution access. Ordinary cancellation still requires durable CANCELLING intent. Workspace cleanup failure remains retryable. Legacy Sessions without a Workspace retain best-effort cancellation and terminal failure for unsupported takeover; this does not certify native cleanup or safe close. Terminal recovery failure is atomic and refuses a concurrent user cancellation instead of overwriting it.
4. An `await_runtime` snapshot with an unknown outcome may attempt cancellation of its original execution identity. This does not permit continuation or execution retry. Runtime cancellation must still observe a terminal result or preserve the existing abandoned/unobserved distinction before journaling settlement. Unknown agent/command waits remain ineligible.
5. A Harness-local Shell publisher can disappear while its original Worker survives. Only a definite publisher connection refusal provides loss evidence; an HTTP refusal, timeout or malformed response remains indeterminate. If publication then fails, only an explicitly cancelled foreground capture with its own real aborted process result, a valid original started PID and positive POSIX process-group disappearance may retain a cancelled result. The child-process API reports its PID on the original handle rather than its completed result; other methods and explicit result PIDs must match. Promoted processes, missing results, live/denied groups and Windows remain uncertain. Loss during finalize reports capture unavailable, producer lost, no manifest and delivery blocked; loss during accept preserves the original valid manifest with delivery blocked. Only the same sink's original result object and the same physical-stop evidence may receive a local four-field ACK; a cloned or forged envelope cannot bypass the original publisher. This ACK claims no durable native outcome and fabricates no outcomeRef. Successful execution or arbitrary publication failure never becomes a witnessed cancellation.
6. Where the original Broker exposes a native blocked-cancellation result, record its receipt under the current fenced writer before resolving the recovered foreground Shell wait. Read the original Broker's settled result without starting work, verify the original checkpoint, intent, arguments and runtime call mapping, and reuse the Shell admission's manifest, sealed-stream and digest checks. The Broker scopes the read by the original Harness Session, Runtime Session and execution; its returned binding generation is authoritative, without acquiring or comparing a replacement Runtime lease. Definitive not-found, valid legacy results without capture, and native results outside the blocked-cancellation family use the existing generic history outcome without creating a native receipt. The old intent belongs to the checkpoint's activation; it need not belong to the replacement writer. Recovery verifies durable seals rather than a dead producer's in-memory prefix. Existing receipts and manifests retain their original outcome references. A lost capture produces a blocked receipt with no result reference or artifact resources; a complete capture is admitted only after full validation. The real journal transaction creates the result projection and its sequence/revision. Keep the close verifier unchanged: a physical stop and a generic history result alone do not replace that receipt.

## Constraints and risks

Keep tenant, actor, Workspace, dispatch ownership, writer generation and Runtime identity guards. Do not weaken `requireIdleJournal` or certify a stop from HTTP202, timeout or lease expiry. A permanently unreachable Runtime may still block cleanup; retries must preserve uncertainty. Cross-package SDK, Harness and Java consumers must be tested together.

## Validation and acceptance

- Preserve failing baseline tests and prior real Linux evidence separately.
- Cover exhausted writer and activation renewal budgets, identical retries, concurrent lease preservation, stopped renewal after unrecoverable append, rollbackable refusal, expiry/refusal, seal races and unchanged healthy cadence.
- Test live/expired/sealed writers, accepted native inputs, compacted/missing heads and lost dispatch claims.
- Test parked cancellation takeover, transient cleanup refusal, unknown Runtime cancellation with positive stop versus still unknown, no execute replay and one terminal public outcome.
- Verify unsupported legacy takeover reaches terminal failure with or without an admission acknowledgement, while unsettled Workspace cancellation retains its owned retry and never logs a terminal failure.
- Exercise real original publisher loss with a foreground parent/child process; verify cancelled execution and unavailable capture only after its process group stops. Test exact dispatch-claim authorization, rejection of foreign/stale/unadmitted claims and a user cancellation winning the terminal race.
- Verify a recovered cancellation commits one native receipt and reuses it after a write/resolve crash; retain complete manifests, verify empty-stream seals and reject foreign identity, damaged resources or a fenced writer. Confirm the resulting journal projection allows the existing physical-close checks to finish.
- Build, typecheck and test affected TypeScript consumers; run SDK/server verification, disposable MySQL and matching Hosted recovery profiles.
- Independently repeat real Linux/MySQL Java/Harness replacement with original Worker identities, exact file/marker bytes, successful cancel/close and physical release. Keep the original demo untouched and restore test resources.
