# 生效权限上下文

[English](2026-11-24-effective-permission-context.md) | [简体中文](2026-11-24-effective-permission-context.zh-CN.md)

## 问题与范围

会话实际处于 `default` 时，配置文件仍可能写着 `auto`。读取该文件或观察一次成功的工具调用，都不能确定当前审批模式，也不能证明用户是否批准过该调用。主会话需要在模型决定调用工具前，提供运行时生效上下文。

本次覆盖 CLI、TUI、stream-json、ACP 主会话请求，以及继承这份上下文的分叉会话。不改变权限执行、审批 UI、命令执行、重试或工具调用次数限制。提供上下文不能保证模型遵守“先询问”或“只执行一次”的指令。

## Codex 参考与缓存行为

Codex 比较从执行步骤生成的生效权限快照：状态不变时不生成更新，状态变化时向对话历史追加上下文。它通过 developer 消息更新权限。参考[权限状态比较](https://github.com/openai/codex/blob/9b2ef38f548f120a092a2870da2883e0c8300116/codex-rs/core/src/context/world_state/permissions.rs)和[执行步骤状态记录](https://github.com/openai/codex/blob/9b2ef38f548f120a092a2870da2883e0c8300116/codex-rs/core/src/session/mod.rs)。

Qwen Code 沿用快照比较、增量追加的方式，并使用已有的 user 消息 system-reminder 约定。权限更新不重写系统提示词或旧权限快照。在其它请求构造条件不变时，模式切换前的完整 provider 消息仍是后一次请求的精确前缀。同一模式的后续请求不重复追加权限文本。

该方式保留可缓存前缀，不保证 provider 实际命中缓存。首次快照及之后的状态变化会增加 token。压缩、历史替换、工具变化、provider 路由及 provider 缓存策略仍可能影响缓存。

## 运行时快照生命周期

主会话创建时启用此能力，包括恢复、清空及压缩重建。每次新构造模型请求前，读取 `Config.getApprovalMode()`，与当前保留历史中最近一份带内部标记的快照比较，仅在快照缺失或变化时追加。文本相等判断还能识别被截断或过期的快照。用户引用但没有内部元数据的文本不能抑制运行时上下文。

快照准确说明五种模式及其边界。例如，`default` 可能直接放行只读或显式允许的操作；`auto` 可以使用自动审查，同时仍可能拒绝操作或要求人工审批。文本要求模型依据运行时状态，不从配置文件或成功的调用推断模式。不包含配置内容、凭据或权限规则列表。

向当前 user / 工具结果消息追加，不修改父子会话共享的历史对象。保留前导工具响应、连续快照的发生顺序，以及末尾 UserPromptSubmit 收据。权限和记忆快照的插入顺序与记录顺序一致，保证恢复后的请求前缀一致。已有请求投影统一将提醒放在用户正文之前。

继承带标记快照的会话也启用同样的生命周期。子会话保留父会话前缀，并在实际模式不同时追加自己的状态。没有主动启用且没有继承快照的其它会话保持原有行为。

## 持久化与计量

每次持久更新记录为 `permission_context_snapshot` 系统 transcript 记录。普通回放、选择性恢复、托管会话迁移及轮次删除与其它上下文记录一同处理。恢复状态未变的快照可避免重复注入。如果压缩或历史替换移除了快照，下一次新构造请求时追加当前状态。

提示词估算预览待追加快照，将其纳入请求大小计算，但不写记录。provider 不返回 usage 时，新追加上下文只计入一次。临时恢复投影不修改历史，也不写记录。

已持久化的 prepared-request 重试保留原请求，不在回放期间重写权限上下文；下一次新构造请求时再次比较生效模式。即使保存的请求带有较早的快照，工具执行仍由运行时权限检查裁决。

## 验证与验收

- 捕获五种模式的请求，覆盖配置持久值 `auto` 被实际 `default` 覆盖的场景。
- 两种 ACP agent loop 均执行 `default → default → auto → auto-edit → yolo → plan → default`。
- 断言系统提示词完全相同、前一次完整请求消息数组是后一次请求的精确前缀，并且重复模式不新增快照。
- 验证父子会话模式不同时，保留父会话前缀并追加子会话实际模式。
- 覆盖历史替换、压缩、transcript 往返、选择性恢复、托管迁移、轮次删除、临时恢复请求及提示词计量。
- 执行定向测试、构建、类型检查及确定性 provider 请求捕获。上下文投递与前缀保留验证不依赖真实模型推理；实际缓存命中率和模型遵从性不在此次验证范围。
