# Node REPL 取消截止时间

[English](node-repl-cancellation-deadline.md) | [简体中文](node-repl-cancellation-deadline.zh-CN.md)

## 问题

当前执行超时只发送取消请求，没有限制等待终态的时间。通过
`nodeRepl.signal.waitUntil` 注册的原生操作可能永远保持 pending。
内核事件循环阻塞也可能导致取消请求无法被处理。这两种情况下，活动 cell
都会阻止后续执行和 reset。

AP 任务 `ap-osworld-v2-61451340fa4a463c-s1` 在执行包含四个 CUA 操作的 cell
后停止推进。归档缺少最后一次工具调用的返回体和内核诊断信息，因此不能证明
具体哪个操作或层级挂起。本次修改针对可独立复现的取消流程无限等待问题。

## 行为

保留正常取消及其绑定保留语义。执行超时或显式取消后，宿主允许内核在五秒内
返回终态。如果内核仍无响应，撤销该内核代次，并使用现有的有界终止机制结束
其进程树。返回原始的 `timeout` 或 `cancelled` 状态，明确说明绑定已丢失，
并提示调用方在重试操作前验证外部状态。

每条执行退出路径都清除取消定时器。定时器回调只能撤销对应执行所使用的内核。
后续调用可以启动新内核；已注册的模块根目录继续保留。

## 决策与约束

截止时间由宿主负责，因为宿主事件循环独立于被执行的代码。仅对内核内的 promise
设置超时无法恢复已阻塞的事件循环。五秒允许原生操作正常收尾，同时避免执行
超时被无限延长。不新增配置项或公开工具。

终止进程会丢弃绑定和模块状态，但无法回滚已经发给应用或远程服务的操作。
返回结果必须说明这种不确定性，不能暗示取消已经撤销了操作。

## 验证与验收

- 永不结束的取消屏障能返回超时终态；显式取消能返回取消终态。排队工作可以继续。
- 在异步边界之后阻塞的内核能由宿主终止。
- 正常取消仍等待原生操作终态，并保留内核和此前绑定。已过期的定时器不能杀掉后续 cell。
- MCP 调用方能收到状态丢失提示，并能执行新 cell。
- 包测试、构建、类型检查和独立复现验证通过。
