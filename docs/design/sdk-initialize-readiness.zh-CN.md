# SDK 初始化回复与就绪状态

[English](sdk-initialize-readiness.md) | [简体中文](sdk-initialize-readiness.zh-CN.md)

## 回复与就绪

通常，流式 JSON CLI 会在配置和 MCP 发现均已就绪后回复 `initialize`。
如果初始化超过回复截止时间，CLI 会发送控制器生成的成功回复，同时继续初始化。
SDK 客户端会把错误回复视为握手失败。队列中的提示始终等待就绪，后续初始化失败时，
CLI 会向这些提示报告错误。

## 截止时间与关闭流程

本地 SDK 通过 `timeout.controlRequest` 发送客户端实际使用的时间预算，并通过
`timeout.controlRequestDeadlineUnixMs` 发送绝对截止时间。CLI 因此可以扣除启动进程和
分派请求用掉的时间。CLI 会预留最多 5 秒用于传递回复，且预留时间不超过剩余预算的一半。
此计算假定 SDK 和 CLI 使用同一时钟。只发送预算的客户端继续使用相对截止时间，
两项均未发送时使用默认的 55 秒。

读取到 EOF 后，CLI 会等待初始化回复发出。若仍未就绪，CLI 会额外等待 5 秒，
随后将就绪状态设为失败，使队列中的提示能够报告错误，CLI 也能完成关闭。

## 验收标准

- 初始化及时完成时，CLI 在 MCP 发现后回复，再处理提示。
- 客户端提供绝对截止时间时，CLI 根据剩余时间安排回复。
- EOF 不影响初始化回复。若初始化始终未就绪，队列中的提示收到终止错误，CLI 能完成关闭。
- 提前发出成功回复后，若初始化失败，队列中的提示会收到错误，原始初始化请求只收到一次回复。
