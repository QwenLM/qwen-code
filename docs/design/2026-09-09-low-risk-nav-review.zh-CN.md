# 静态文档导航的自动专项审查

[English](2026-09-09-low-risk-nav-review.md) | [简体中文](2026-09-09-low-risk-nav-review.zh-CN.md)

## 问题

PR #11426 只修改了一项导航（+1/-3），但自动审查启动了 16 个初审 agent、
2 个反向审计 agent 和 2 个验证 agent。它花了 90 分钟追查已有示例文档中的
问题，最终超时且未发布结果。现有微小 diff 门槛只缩短超时，不减少审查工作量。

## 设计

自动 workflow 通过 `QWEN_REVIEW_AUTOMATIC=true` 标识自身。抓取 PR 后，CLI
可以在捕获的计划中记录 `reviewProfile: docs-nav`。显式审查请求、本地审查、
续跑审查、有效的增量审查，以及缺少新抓取合并基点的情况，均保留原有行为。

分类使用完整的捕获 diff 和不可变的 base/head 文件内容。初始仅接受一个已有的
普通 `docs/**/_meta.ts` 文件，新增与删除行数之和少于 25，且前后版本均为只含
字面量字符串与对象的 `export default` 对象。顶层导航键的集合和顺序必须保持
不变：键顺序就是侧边栏顺序，`type: 'separator'` 会对其后条目分组，因此单纯
重排也属于结构变化，而非展示变化。仅允许标签、`title` 和 `display`（`hidden`
或 `normal`）变化，其他元数据必须完全相同。导入、调用、展开、计算键、转义、
重命名、文件模式变化及不支持的语法，均保留完整审查。分类器从不执行文件，
也不影响 CI 共用的 docs-only 分类器。

共用的 docs-only 分类器控制 CI 路由，不控制审查角色列表或发现的因果范围。
只扩展它，仍会保留导致 #11426 超时的审查工作。本方案单独限定这些工作。

专项模式保留现有 high-effort 调用及发布授权。计划中的 profile 改变必需的工作：
一个导航 reviewer 阅读完整 diff、相关 PR context 和直接导航消费者，再返回
候选问题或明确的无问题回执。候选问题必须先说明本 PR 导致的行为差异，才能进入
一轮独立验证。因果范围以外的已有缺陷不会触发验证或进一步探索，不启动反向审计
或专家分发。reviewer 会收到两个捕获版本的明确读取指令，无需从分支最后一次提交
推断 base。仓库声明的额外 reviewer，仅在现有 effort、topology 和 mode 策略
允许这些角色时，才使审查保留正常角色列表。

覆盖检查要求专项 reviewer 的证据；发布发现时，还要求现有的独立 verifier
证据。结果组合会披露专项范围和省略的反向审计，将无问题的结果限制为 COMMENT，
同时保留已验证的阻断问题。该披露也会阻止发布的 ledger 认证增量锚点。skill
不得从此模式提升完整审查缓存。发布继续使用现有 submit 命令，保留相同的授权、
提交版本、锚点和 presubmit 检查。

## 实现范围

- Workflow：标识自动调用，保留显式请求和预算行为。
- 捕获与分类：从 base/head 推导 profile，不使用用户开关。
- 角色列表与 brief：一个专项角色，finder 和 verifier 共用因果范围。
- 覆盖：与角色列表共用 profile 选择，并披露缩小的范围。
- 内置审查指令：分发、单轮验证、发布和缓存规则。
- 测试：保守分类、完整审查回退、覆盖及发布契约。

## 范围与验证

此变更不调整 deadline 准入、通用 medium/minimal 行为、可执行变更的安全审查
策略或 CI 测试分类器。不支持的导航语法继续使用现有审查。

基线 CLI 探针和使用本地 bundle 对 #11426 的重放，将验证角色列表与完成行为。
发布验证不进行公开写入。一行权限变化、可执行元数据和混合 diff 仍必须要求完整
审查。缺少 reviewer/verifier 证据时，必须限制结果；无问题的专项结果不得批准，
也不得为后续完整审查提供锚点。性能目标是 10–15 分钟内完成并产出结果，以实测
为准，不从 agent 数量推算。

## 待定问题

这个刻意收窄范围的初始版本没有待定问题。其他低风险文件形式需要独立证据，
可以后续添加。
