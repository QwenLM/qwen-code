# 专注模式

[English](focus-mode.md) | [简体中文](focus-mode.zh-CN.md)

## 问题与现状

紧凑工具视图仍会在主对话中显示工具组和推理。专注模式提供可持久保存的可选阅读视图，隐藏推理并概括已完成的工具组，同时保留完整历史，供详细视图和导出使用。

## 设计

Ink 和 OpenTUI 交互界面均提供 `/focus` 和布尔设置 `ui.focusMode`，默认关闭。Provider 向历史行提供当前状态，向命令处理器提供切换动作。命令在 User 作用域保存设置，除非生效的 workspace 或 system 设置覆盖该值。发生覆盖时，`/focus` 提示用户，不修改 User 偏好。不受信任的 workspace 设置不能覆盖 User 偏好。设置对话框和命令必须保持运行时状态一致，以合并后的有效设置为准。命令写入失败时保留原内存状态和显示视图。恢复默认值与普通切换一样更新视图。`/config` 修改有效设置时也同步 Provider。

专注模式隐藏推理标题和后续推理行。只有当非空工具组已提交、所有工具均成功、失败或取消、不是用户主动发起，并且没有子代理执行结果、内联图片或省略图片元数据时，才压缩为一行本地化摘要。单个工具保留显示名称以及可用时长度受限的文件标识。工具组保留数量，并标识失败工具，不显示原始命令或输出。内存读写计数保留在同一行。运行中和等待确认的工具保持可见。用户消息和助手回答不变。

Ctrl+O 使用 `fullDetail` 显示原始推理和工具组。完整详情优先于专注模式：详情展开时启用专注模式会修改偏好，再次按 Ctrl+O 才重新应用专注过滤。会话预览仅绕过专注过滤，保留原有分组方式和高度限制。

切换阅读视图必须重绘既有历史，包括旧版 Ink 静态历史渲染器。虚拟视口保留屏幕控制权，并使用现有刷新机制。

## 受影响区域

- CLI 设置 schema 和界面翻译。
- 交互 Provider 组合、命令注册及命令上下文。
- 历史行渲染和对话刷新。
- daemon workspace 设置路由对 TUI 专属偏好的过滤。
- 命令、Provider、渲染器的同目录测试，以及交互测试。

## 范围边界

本功能仅改变呈现，不修改提示词、模型输出、工具执行、已存历史或导出。更丰富的轮次摘要、新快捷键以及减少模型叙述的指令留待后续工作。Web 渲染器不在本次范围内，在实现呈现支持前不得提供可用的专注切换。

现有 TUI 专属设置过滤器仍从旧版 primary 和 selected-runtime workspace 设置路由中排除专注设置。这些路由的信任关系、运行时归属和失败行为不变。

## 验证

本地 E2E 计划覆盖既有历史切换、重启持久性、设置变更、完整详情切换以及特殊工具状态的可见性。单元测试直接验证这些约束。发布检查包括 build、typecheck、本地化、lint、bundle 和仓库 preflight。

## OpenTUI 对齐及维护者评审

两种终端渲染器复用 React Focus Provider，统一持久化及作用域优先级。OpenTUI 将命令上下文和设置对话框接到相同动作。Ctrl+O 状态是临时的，仅影响显示，包括已提交的历史行和展开的推理、工具结果。

与渲染器无关的辅助函数负责紧凑工具标识与压缩资格。Ink 适配工具组，OpenTUI 适配工具卡片，不必共享布局代码。OpenTUI 的事件生产者和历史归并保留呈现元数据，以豁免用户主动命令、子代理结果及图片。恢复会话时保留标识文件所需的工具参数。过滤不得删除已保存的条目。

涉及 HistoryItemDisplay、SessionPreview、Focus 命令及翻译，以及 OpenTUI 启动、命令连接、设置挂载、对话渲染、事件适配和历史归并。daemon workspace 设置路由将专注设置加入 TUI 专属过滤器，同时适用于 legacy-primary 和 selected-runtime 请求。各边界均有同目录测试。认证、模型选择、工具执行及 daemon 路由归属保持不变。

接受五项维护者建议：保留身份信息的摘要、原生 OpenTUI 支持、准确的 Ctrl+O 提示、紧凑的终态取消显示，以及预览专属的 Focus 绕过。支持 OpenTUI 不会移除 Ink，也不会更改用户选择的渲染器。
