## 修订后的架构方向

当前方案为[统一工具执行沙箱设计](2026-09-16-tool-execution-sandbox.zh-CN.md)，同时覆盖 bwrap 迁移和 Landlock 接入。其决策、能力 profile、配置、调用入口清单和验收标准优先于本文历史内容；不代表已经实现。

- 模型通信、认证刷新、会话持久化和审批处理留在可信宿主进程。该进程只获得履行职责所需的权限；位于命令沙箱外不代表可以执行模型要求的任意写入。
- 每次调用依据可信配置、工作区状态和适用审批，解析不可变的有效权限策略。启动不可信命令代码及其后代时施加内核约束。
- 盘点全部由模型驱动的文件变更与执行入口，包括内置文件工具、子代理、MCP、hooks 和后台进程。内置变更必须在可信实现边界或受限 worker 中执行同一策略。仅包装 shell 不能实现完整覆盖。远程服务需要独立的控制边界。
- 区分普通工具失败、策略拒绝与沙箱启动失败。支持扩大权限时，先把审批绑定到具体操作和允许范围，再开始新调用；拒绝或审批不可用不能触发自动无约束重放。
- 避免向工具子进程传递宿主凭据、任意可写描述符或宽泛 Qwen 状态授权。CLI 在宿主认证，同时显式定义个别工具确实需要的凭据。
- 先用 bwrap 实现并验证策略/执行器接口，在同一交付中替换旧 CLI hop，再按同一必需能力接入 Landlock。不保留整 CLI bwrap 选项，也不把它作为执行回退。

原先的最低 ABI 5、`partial` 标签、全局状态子目录列表、私有临时目录生命周期，以及整 CLI 标记协议，均是**需要重新评估的暂定选择**，不是修订后边界的既定要求。一些约束仍然成立：显式请求不能因设置失败就无约束执行；子目录只读规则不能撤销宽泛父目录授权；网络承诺必须匹配真实执行能力。不能暗示仅移动边界就解决了这些问题。

中英文统一设计现已覆盖调用入口清单、可信与模型控制的输入、权限传递、内置文件操作、审批、网络、进程生命周期和向后兼容。实施规划应从该文档继续。选择依据是分离可信运行时职责与不可信执行，而不只是模仿其他产品。

## 历史整 CLI 提案——不作为实施计划

后续章节记录已撤回的提案。下文“首版”“建议”“发布门槛”等表述仅针对历史提案，不能覆盖上面的修订方向。

### 改变早期提案的发现

| 发现                                                                       | 设计结果                                                                |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| bwrap 失败不意味着 Landlock 可用；外层容器也可能阻止 Landlock 系统调用。   | 探测实际 helper，要求成功安装约束。                                     |
| 当前 bwrap 在可写父目录上叠加只读挂载，保护操作者控制的 `QWEN_HOME/.env`。 | 不能照搬 `--rw QWEN_HOME` 加 `--ro .env`，需要重新划分状态写授权。      |
| 当前网络 `closed` 模式创建网络 namespace。                                 | 首版纯 Landlock 后端拒绝 `closed`。                                     |
| 现有提示词描述只读挂载、合成 `/dev` 和 `EROFS`。                           | 为 Landlock 提供准确的独立报告与提示词。                                |
| 启动器是安全敏感二进制，现有后端发现却假定可执行文件位于 PATH。            | 通过绝对路径定位打包的 helper，不搜索用户提供的 `landlock` 可执行文件。 |
| 现有运行时状态和 writer lease 依赖宿主进程身份。                           | 保留 PID namespace、`/proc`、运行时位置和归属记录。                     |

Landlock 的 handled rights 决定规则默认拒绝哪些操作；未列入的权限不会自动受到限制。ABI 查询报告能力是否存在，但实际安装规则仍可能失败。这是两个独立检查。[规则集 API](https://man7.org/linux/man-pages/man2/landlock_create_ruleset.2.html)

### 首版产品契约

通过 `QWEN_SANDBOX=landlock qwen …`，或现有字符串类型的 `tools.sandbox` 设置启用。除非单独修改布尔类型 CLI 选项，否则不创造 `--sandbox=landlock` 用法。Bare 模式、环境变量与设置优先级保留现有语义。显式 `bwrap` 仍只选择 bwrap；`QWEN_SANDBOX=true` 保留当前候选顺序。失败后绝不在约束外重试任务，也不静默切换后端。

支持平台为 Linux x64 和 arm64，要求 **Landlock ABI 5 或更高**，且功能探测成功。ABI 3 增加截断控制，ABI 5 增加设备 ioctl 控制；建议的最低要求避免设备策略随 ABI 降级。上游 Linux 6.10 引入 ABI 5，但必须探测运行时 ABI，不能依据版本字符串，因为内核可能回移功能或禁用该 LSM。ABI 1–4 直接拒绝，不能仅提示后继续运行。[ABI 参考](https://man7.org/linux/man-pages/man7/landlock.7.html)

这个最低要求有意排除了部分 6.1/6.6 系统。若后续目标用户数据表明这类系统占主导，应重新讨论一个独立命名、保护较弱的 profile，不能悄悄降低当前 profile 的要求。新 ABI 不自动启用新的权限或限制：首版 helper 使用固定、经过审查的 ABI-5 文件系统策略。

对用户的承诺是**文件系统操作限制**，不是宿主文件系统只读，也不是完整宿主隔离。为兼容 CLI/工具，读取范围保持宽泛。本 profile 不提供秘密文件保密、handled rights 之外的元数据操作限制、网络隔离、资源限额，或对宿主服务代办权限的限制。

### 文件系统策略

#### 固定权限与授权

处理 ABI 1 的文件系统权限，以及 `REFER`、`TRUNCATE` 和 `IOCTL_DEV`。网络和 scope 字段设为零。helper 定义有名称的固定掩码，不从配置接受任意掩码。

| 授权                                   | 允许的操作                                                                                                                                                                                                                                                                                            |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 全局 `/`                               | 仅 `READ_FILE`、`READ_DIR`、`EXECUTE`。不提供全局写入、截断、目录变更或设备 ioctl 授权。                                                                                                                                                                                                              |
| 获准可写目录                           | 读取/执行；普通文件写入/截断；创建/删除普通文件和目录；创建符号链接、FIFO 和 socket；`REFER`。绝不包含 `MAKE_CHAR`、`MAKE_BLOCK` 或 `IOCTL_DEV`。                                                                                                                                                     |
| 经调用方审查确有需要的显式普通可写文件 | 仅文件读取/写入/截断，不包含目录权限，也不推导父目录授权。首版 CLI 策略使用目录授权。                                                                                                                                                                                                                 |
| 终端/设备兼容例外                      | 精确授权 `/dev/null`、`/dev/zero`、`/dev/random`、`/dev/urandom` 写入，以及真实 shell 执行需要的 PTY 路径（`/dev/ptmx`、`/dev/pts`、`/dev/tty`）。设备 ioctl 权限仅限终端路径。不能整体授权 `/dev` 写入/ioctl。必需设备缺失时启动失败；可选终端设备仅可在已验证不依赖它们的 headless profile 中省略。 |

设备列表是实现验收目标，不是已验证的兼容性结论。发布前必须通过真实 Linux 的 PTY、重定向 stdio 和普通 shell 工具测试。全局读取意味着设备节点不像 bwrap 中那样被隐藏；不能声称提供 GPU/设备隔离。

使用规范化路径与 `O_PATH | O_CLOEXEC` 规则描述符，在安装允许掩码之前检查描述符的对象类型。必需路径缺失和任何规则添加失败均为致命错误。helper 只支持普通文件/目录授权及明确列举的设备例外。执行子程序前关闭规则描述符。[规则 API](https://man7.org/linux/man-pages/man2/landlock_add_rule.2.html)

#### 工作区、临时文件与 Git

保留现有 HOME/祖先目录禁止规则、对设置提供的额外目录的更严格处理，以及经过验证的 linked worktree/common Git 目录发现逻辑。仅抽取并复用这些校验逻辑，不能复用 bwrap 最终授权数组。

授权工作区、获准额外目录、经过验证的 Git 元数据及获准缓存位置。宿主临时目录不整体可写，改为在宿主创建本次启动专用的私有目录，并将子进程 `TMPDIR` 指向它。硬编码其他临时路径的程序可能被拒绝，应报告而不是扩大授权。受监管启动结束后清理该私有目录。缓存根必须通过与工作区根相同的重叠检查。

启动前规范化并检查全部授权。打开描述符后，规则指向相应对象；若路径被独立修改，无法再按预期解析，启动可能失败或后续操作被拒绝。不能承诺对恶意同用户宿主进程提供原子保护。测试符号链接、既有硬链接、跨目录重命名和 common-directory 布局。获准的 Git 配置/hooks 仍可能影响后续宿主 Git 命令。

#### 保护操作者配置

同一层内的 Landlock 规则累加权限，子规则不能撤销父规则授权。附加层会取权限交集，但不能简单表达“除这个文件名之外全部可写”。[策略组合](https://docs.kernel.org/6.12/userspace-api/landlock.html#layers-of-file-path-access-rights)

因此首版**绝不授予全局 Qwen 目录本身写权限**。其中 `.env`、根级设置、凭据和安装元数据保持可读，但位于写授权之外。即使 `.env` 不存在也要保护该目录，子进程不能创建替代 `.env`。

进入约束前，通过可信初始化创建并检查仅有的必要数据目录：运行时 `tmp` 和 `debug`，以及启用功能需要的全局 `ide`、`plans`、`audits`。授权这些子目录，不授权父目录。这是从 `Storage` 推导的首版封闭列表，任何新增状态使用方都必须显式审查。不能授权所有既有子项，也不能通过枚举配置文件构造宽松策略。要求状态子目录是真实目录并拒绝符号链接重定向。保留现有会话/运行时路径，使宿主进程能够查看和回收同一个 writer lease。

若独立配置的运行时目录与全局 Qwen 目录在规范化后互不包含，可在相同检查后授予目录权限。若它等于全局 Qwen 目录，则拆成获准运行时数据子目录。若工作区、临时、缓存、Git 或运行时授权会覆盖全局 Qwen 目录或任何祖先，则拒绝该布局。例如从 `QWEN_HOME` 本身启动，或把 `QWEN_HOME` 放到整体可写的工作区下。双向检查重叠：全局 Qwen 目录下的授权只有完全位于获准数据子树内才允许；拒绝 `workspace=~/.qwen/extensions`、`runtime=~/.qwen/commands`、`cache=~/.qwen/skills`。同时拒绝绕过受保护文件检查的路径别名；当 `.env` 存在时，保留当前普通文件/单硬链接要求。

因此，首版 profile 内不支持保存全局配置、需要替换根级文件的登录/token 刷新、扩展安装及自更新。认证和配置应在外部准备。不能将这些操作移入自动提权的宿主回调。预配置 API key 的 CLI 回合能够工作是发布门槛；若启动身份初始化确有需要，应审查后在 hop 前完成，且不能运行工作区控制的 hooks。OAuth 刷新和广泛的托管状态兼容作为明确的后续工作。

对于 `.env`，单硬链接/类型检查与目录策略共同保护 handled 文件系统操作涉及的内容和名称替换。对于其他配置，本提案保护命名路径与目录项，不保证覆盖所有可能已存在的硬链接别名；不能声称全部全局配置内容不可变。既有可写别名是残余风险，必须在可行性测试中记录。它不保证所有元数据操作只读，也不能阻止可达的宿主服务代为操作。说明 `.env` 保护时必须同时说明这些边界。

### 网络契约

| 请求模式           | 首版行为                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| `open`             | 支持，共享宿主网络，仍受外层限制。                                                                                |
| `proxied`          | 支持既有宿主代理生命周期与代理变量归一。明确说明路由仅是建议性配置，直接通信仍可能发生。                          |
| `closed`           | 启动代理或载荷前拒绝：`Landlock profile does not support closed network mode; select a backend that supports it.` |
| 非法值或代理不可用 | 拒绝；保留 closed 优先于代理的规则。                                                                              |

ABI-4 TCP 规则按端口授权操作，不按目标主机名/IP。它们不能实现当前完整网络 `closed` 承诺，也不能保证仅通过代理出网。首版不增加具有误导性的“只禁止 TCP 的 closed”模式。未来更严格的网络限制需要单独的策略设计，以及 UDP、DNS、IPv6、Unix socket、继承描述符测试。[网络规则 API](https://man7.org/linux/man-pages/man2/landlock_add_rule.2.html)

### Helper 与启动协议

分发 `packages/core/vendor/landlock-run/{x64,arm64}-linux/qwen-landlock-run`，相邻 `src/` 目录保存规模小、便于审查的 C11 源码。不预设缺乏依据的行数目标。TypeScript 宿主构建 argv；helper 不调用 shell，也不读取工作区配置。

拟定接口为 `qwen-landlock-run --probe` 和 `qwen-landlock-run --profile fs-v1 [--rw-dir <absolute-path>]... -- <argv>...`。读取、设备和必需权限掩码属于固定 profile。不开放任意 capability、syscall 或可写根逃逸选项。宿主组装策略时验证根的来源；helper 验证语法/类型并安装精确授权，不判断授权来源的可信性。

`--probe` 在独立短生命周期进程中执行：查询 ABI，要求 ABI >= 5，设置 `no_new_privs`，创建固定 handled-rights 规则集并安装，然后输出一条有长度上限的 JSON 记录：`{"protocol":1,"abi":5,"profile":"fs-v1"}`，ABI 字段为实际值。约束安装前不能输出成功记录。该检查验证宿主能力，不验证每一个工作区授权或保护属性。真实启动始终针对实际授权重新安装约束。

启动时，在执行载荷前拒绝格式错误的 argv/未知 profile；打开并检查授权；设置 `no_new_privs`；安装规则集；关闭全部 helper/授权描述符；然后 `execvp` 目标程序。任何前置条件或系统调用失败都不能运行载荷。失败使用退出码 125，并输出带 `qwen-landlock-run:` 前缀、已净化的阶段与 errno 诊断。成功 exec 后保留载荷退出码，包括 125；不能单凭该退出码认定是设置失败。[约束安装 API](https://man7.org/linux/man-pages/man2/landlock_restrict_self.2.html)

仅有 stdin/stdout/stderr 是有意继承的启动描述符；获取 helper 描述符前关闭继承的 >= 3 描述符。测试必须包含调用方故意传入的可写 FD。Stdio 本身是明确例外：宿主重定向到约束前已打开的文件，仍保留相应能力。继承的环境秘密和可达宿主服务也在文件系统读写策略之外。Landlock 不追溯撤销已打开文件的权限。[描述符语义](https://docs.kernel.org/userspace-api/landlock.html#rights-associated-with-file-descriptors)

宿主按 helper 路径/profile 缓存本进程内严格解析的成功探测结果或失败。未知协议、格式错误/超长输出、非零退出、超时或信号终止均拒绝。沿用五秒超时。不跨启动持久化宿主能力，也不从环境标记推断能力。

### 生命周期与报告

保留宿主 PID namespace 和 `/proc` 视图。与当前非容器启动一样，helper 在受监管进程组中运行，继承 stdio。Helper exec 保持其进程身份。仅复用 bwrap 与 Landlock 确实需要的少量进程监管逻辑；分别保留 argv、能力和策略构建。

保留 SIGINT/SIGTERM/SIGWINCH 转发、130/143 退出码、终端恢复、readiness 取消和代理清理。Helper 配置父进程死亡信号，并在 exec 前检查父进程退出竞态。这保护直接载荷，不保证全部脱离进程组的后代随外层启动器退出。正常终止必须停止普通子进程组；主动脱离的后代仍受约束，但可能继续存活。外层被突然 SIGKILL 时的整树终止需要单独设计 supervisor/cgroup 机制。[父进程死亡语义](https://man7.org/linux/man-pages/man2/PR_SET_PDEATHSIG.2const.html)

仅在子进程环境设置 `SANDBOX=landlock`、`SANDBOX_ENFORCEMENT=partial`，保留现有标记词汇。此处 `partial` 表示 profile 范围有限，绝不表示缺少必需 ABI 权限。新增 `SANDBOX_LANDLOCK_ABI` 和 `SANDBOX_LANDLOCK_PROFILE=fs-v1`，由 helper 按实际安装结果覆盖。它们是展示/重入元数据，不是认证或安全边界。在保留现有沙箱标记的地方同步注册并净化新字段的重载行为。

`qwen sandbox` 报告后端、ABI、profile、实际写授权、受保护配置目录和网络语义。状态文本为 `landlock (filesystem restrictions, ABI N)`，不显示绿色“完全隔离”。独立 Landlock 提示词说明 `EACCES`、宽泛读取、建议性代理，以及配置写入限制，不能描述挂载或隐藏设备节点。单独一个 `EACCES` 不能证明策略拒绝。

`qwen sandbox --verify` 使用有正向对照的、宿主可写的临时目标，不复用 bwrap 专用的固定宿主路径/网络 namespace 检查。成功标题为 `Declared Landlock profile checks passed`，并同时说明限制。会话内新增目录不能扩大已安装规则集：未覆盖目录直接拒绝并提示重新启动；允许在已有授权根内 `/cd`。被拒绝命令不能在约束外重放。

使用固定版本的 musl 工具链与固定构建镜像 digest，产生可复现的 x64/arm64 二进制。记录工具链/源码 hash、编译器/linker 参数、许可证声明和产物 hash。CI 重建并逐字节比较；仅使用浮动版本的 `apt install musl-tools` 不构成可复现契约。用户不需要编译，也不在启动时动态下载可执行文件。未经许可证审查不复制外部 helper 源码。

不支持的架构、资产缺失、不可执行/noexec 安装、不支持的 ABI、LSM 禁用、外层系统调用拒绝，都必须明确报告不可用。正确打包的二进制不能证明宿主可以执行约束。

### 验证与实现阶段

| 阶段                      | 交付与门槛                                                                                                                                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. 生产集成前的可行性验证 | 在临时 Linux 环境制作原生 helper 原型，证明固定权限、设备/PTY 行为、配置保护和 ABI 失败路径。审计普通 API-key 启动与状态写入方。暂不自动后备，也不分发二进制。 |
| 2. Helper 与分发          | 经过审查的源码、固定工具链可复现二进制、探测协议测试，以及 x64/arm64 的实际 npm/standalone 资产检查。                                                          |
| 3. 显式 CLI 集成          | `open`/`proxied` 普通回合、独立检查/verify、准确提示词/UI 和失败行为；既有 bwrap 测试保持通过。                                                                |
| 4. 真实 Linux CI          | 独立无凭据套件及兼容性矩阵；矩阵通过且报告限制符合观测后才发布。                                                                                               |

必须提供的行为证据：

- 授权根内允许的写入/创建/删除/重命名/截断成功。宿主已证明可写的兄弟文件不能通过 open/write、`O_TRUNC`、truncate、rename replacement 或硬链接搬移而被修改；检查原内容和目录项。
- 全局 `.env` 的内容与路径能够抵抗直接写入、截断、unlink、符号链接/重命名替换及硬链接尝试。覆盖 `.env` 存在/缺失、根重叠、状态路径重定向；禁止布局必须在写出任何载荷标记前失败。
- 普通/linked Git worktree 提交成功；跨边界 writer 冲突/回收保留 transcript 与宿主 namespace 身份。这是服务级归属证据，不是完整 daemon handoff 认证。
- 真实 fake-model CLI 回合在 `open`、`proxied` 中运行真实 shell 工具；代理观察到流量并终止。`closed` 和非法模式不能启动代理/载荷。`proxied` 中仍可直连，报告必须如实说明。
- 覆盖设备/PTY、终端缩放、SIGINT/SIGTERM、代理失败/readiness 取消、额外继承 FD 和直接父进程死亡。主动脱离后代的观测与普通进程组清理分开报告。
- 探测/启动拒绝覆盖 ABI 1–4、无 Landlock、LSM 禁用、seccomp 拒绝、helper 缺失/架构错误/noexec、非法探测结果和规则集失败。模拟 syscall 失败验证控制流，真实内核矩阵建立约束证据。
- 包含一个隔离环境，在其中禁止创建 namespace 但允许 Landlock 调用，证明预期部署价值。不能修改共享宿主 sysctl 或禁用其安全策略。
- 在真实内核上测试 ABI 5 和更新 ABI，两种支持架构均验证打包/执行。新内核模拟 ABI 返回值不能替代最低内核的行为运行。CI 前置条件不支持时明确失败，不能跳过后显示绿色。
- 无约束的反向对照只运行临时文件用例，并必须触发断言失败。不能把秘密、宿主配置或固定系统路径作为破坏性测试目标。

### 取舍与发布决策

建议首版保持显式启用，范围小于 bwrap：ABI >= 5，仅文件系统策略，不支持 `closed`，保护全局配置且仅指定状态子目录可写。这样可以检查实际限制，避免静默后备改变用户策略。

接受实现之前，维护者必须通过阶段 1 验证两个实际假设：足够多的目标环境具备 ABI >= 5；禁止全局配置写入后，预配置 CLI 仍可使用。任一假设不成立，都应通过独立设计更新重新讨论产品 profile 或状态布局。不能用缺少必需权限、授权全局 Qwen 父目录、替任意拒绝写入提供宿主回调，或自动无约束重试来绕过交付门槛。

严格秘密读取隔离、OAuth 刷新/全局设置兼容、完整网络禁止、信号/Unix socket scope 控制、seccomp、脱离进程的约束、自动后端选择及逐工具审批均作为独立工作。本文可以进入可行性验证，但不表示可部署的 Landlock 后端已经存在。
