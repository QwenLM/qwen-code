# CUA 工具失败与效率修复

[English](cua-tool-efficiency-fixes.md) | [简体中文](cua-tool-efficiency-fixes.zh-CN.md)

## 范围

本文合并通过 Codex CLI app-server → 本地 Node REPL MCP → Qwen CUA SDK → 进程内 macOS 原生库执行 OSWorld 时发现的 bugfix，覆盖失败或无效的工具调用及可避免的执行开销。任务得分不是效率判据；4 个整任务回归不能证明全部 20 个任务已验收，也不能证明达到 baseline 耗时的 ≤1.5× 目标。

## 问题与修复

## 行为约束

### REPL 状态

绑定仍由声明它的 module 持有，不挂到 `globalThis`。旧 helper 的读写与后续赋值立即共享状态，同一语句内也有效。保留重复声明错误、重复 `var`、解构/循环目标、词法遮蔽、const/TDZ、裸调用 `this`、对象简写、函数/类的推断名称和严格模式下裸标识符 delete 错误。尚未声明名称的前向引用保留已有 module 行为，并非全局 Script REPL。

普通错误恢复到最后完成的语句/声明器检查点。超时/取消恢复 cell 进入时的绑定值，不发布新绑定。对象原位修改和外部副作用不回滚；异步续执行保护及 native 终态屏障保持有效。

### 输入与观察

Process Manager API 已废弃，但在验证主机上仍可用。修复保证进程成员/前台状态实时查询，不接管宿主主线程；不保证 activation policy 等全部 AppKit 属性都已实时更新。

保留精确 PID/窗口归属、焦点守卫、后台拒绝、Screen Sharing 物理投递、单键 flags 和 web 坐标聚焦回退。前台 Unicode 使用已有精确窗口 HID 守卫，准备焦点后重新验证目标。默认字符节奏、普通 Unicode/Tab 及原子 AX 插入保持不变。跨 Return 的读回不能构造单字段部分写入偏移，避免引导错误重放。

可编辑控件聚焦要求：无修饰键点击、未声明 `AXPress`、`AXValue`/`AXFocused` 可写、前后值可读且不变，以及新读取的精确焦点身份。仅组合框可以接受其直接文本编辑子节点。失败不触发第二种动作；确认聚焦不代表后续提交或应用联动已经发生。

AX 去重保留首次 DFS 出现并遍历未见后代；真实属性失败及剩余深度/数量限制仍产生不完整观察。占位节点例外要求角色严格为 NoValue、父节点是受支持的搜索框、尺寸类型正确且为零、子节点成功读取为空、无标题/描述/值/占位文字/help 或动作、值/焦点不可写且未聚焦。未知、瞬态、非空或可编辑节点不会被忽略。facade 不完整采集最多重试一次，不提供可用元素 token；原生 AX 错误保持可见。

### 窗口与截图

sheet 发现采用有界直接子节点读取及身份去重，不再遍历一次完整控件树。仅唯一匹配且同归属的 sheet 可以扩展原本无法解析的目标。顶层窗口调整、菜单/文档激活及同意流程保持原语义。

非零图层发现要求显式 PID、可见 CG 候选，以及 AX 对 `AXSheet`、`AXDialog`/`AXSystemDialog` 或 modal 状态的证明。在 blocking worker 中最多检查 64 个根，消息超时 100 ms，总截止时间 500 ms。worker 失败显式报错；缺少 AX 证明不补充结果，也不授权输入。最终由同一份 CG 快照重建排序。无 PID 发现保留 layer-0 过滤；未能发现或较晚出现的对话框仍可能缺少动作结果提示。

附属窗口组使用只包含选定窗口的 display filter，在一个显示器内按已验证边界裁剪。截图前后复查归属、边界、组分类及在屏状态。AX 分类明确读取失败时也选择此裁剪路径；截图仍需要屏幕录制权限。不仅裁父窗口图，也不回退到已知错误的组截图。屏幕外或跨显示器窗口组可以返回截图不可用。

普通截图通过已有 ScreenCaptureKit 依赖/特性设置 `includes_child_windows(false)`，保留权限检查、几何、缓存身份及失败语义。广泛验收前必须验证菜单、popover 和合法子窗口内容；若受支持的内容消失，应收窄或拒绝该调整。当前控制实验不能证明旧系统行为及全部坐标输入路径。

## 验证与剩余工作

2026-09-12 记录的实现检查：70 项 REPL、54 项 SDK（5 项集成测试跳过）、6 项 Skill、MCP 通道冒烟、357 项 macOS native 测试及 native release 构建通过。全仓构建/类型检查被未改动的 `qwen-live` 缺少本地 `@node-rs/jieba` 依赖阻塞。原生验证需同时设置 `DEVELOPER_DIR` 和 `SDKROOT` 来选择已安装的 Command Line Tools；此前旧 SDK 编译失败保留在报告中。Windows/Linux 未测试。

GUI 控制实验通过实际后置状态验证了应用实时变化、选区/替换、LF/CRLF 输入、附属面板观察/输入、可编辑控件聚焦、非零图层对话框生命周期及 AX 身份处理。case34 R5、case44 R2、case45 R1 和 case50 R4 使用冻结的 native `b47e0102`。候选 `cbeefff9` 单独修正了 GIMP Welcome/主窗口图像；之后重新构建的二进制通过构建/测试，但未进行 GUI 验证。这些证据不能互相替代。

剩余工作：

- 验证最新截图调整对亮度对话框、菜单/popover、附属面板及实际坐标输入的影响，再重跑相关任务。
- 修改前先量化正常的 1 秒无窗口变化等待：观察期间还持有焦点抑制 lease。首次立即采样并未消除该等待。
- AX 错误发生在真实 UI 变化之后时，保留并明确状态证据。sheet `setValue` 拒绝、颜色文本读回但实际颜色未联动仍是独立未解决问题。
- 使用原任务描述、原始输入、setup/getter/scoring 契约及修改后的 Skill 继续对齐回归。在独立且不可改写的运行中记录源码/runtime/Skill 哈希；历史主机/provider/CLI/scorer 差异及实际工作量差异仍限制归因。baseline 的相似症状在未证实同根因前仍标为疑似环境问题。

详细实验保留在本地调查记录和 Git 历史中。PR 包含[英文验证报告](https://github.com/QwenLM/qwen-code/pull/11683#issuecomment-5642894479)、[中文验证报告](https://github.com/QwenLM/qwen-code/pull/11683#issuecomment-5642915885)及任务对比评论。仅凭机制控制实验和更短的已记录运行，不能证明纯 SDK 提速或全部工具路径已覆盖。
