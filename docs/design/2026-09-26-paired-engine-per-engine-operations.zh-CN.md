# 双引擎按引擎的运维行为

[English](./2026-09-26-paired-engine-per-engine-operations.md) | [简体中文](./2026-09-26-paired-engine-per-engine-operations.zh-CN.md)

## 状态

#12737 的 B2c 切片，属于 #12380 的 Stage B 宿主接入，基于上游 `f5ad9cb9b1`。它承接
[双引擎 owner 选择](./2026-09-26-paired-engine-owner-selection.zh-CN.md)（B2a）与
[双引擎工作区 runtime 身份](./2026-09-26-paired-engine-workspace-runtime-identity.zh-CN.md)
（B2b 第一部分），并落实 #12737 中
[Q2/Q3 回复](https://github.com/QwenLM/qwen-code/issues/12737#issuecomment-5846370487)
确定的隔离恢复决策。带确认的工作区变更下发（B2b 第二部分）与宿主接线（B2d）仍是独立
切片。目前没有普通宿主构造双引擎 Bridge。

## 问题与当前行为

双引擎 Bridge 同时持有 Legacy 与 Managed 通道，但仍有几项操作按单通道的方式运行。

- **隔离。**清理失败、或被放弃的恢复或会话创建迟迟未结算的通道，会停止接收新会话。它的
  已有会话可以无限期地继续发 prompt，通道只有在所有会话排空后才退出，因此被隔离的引擎可能
  无限期占着会话。
- **子进程资源。**资源采样只轮询一个通道，daemon 对每个工作区 runtime 最多统计一个 ACP
  子进程。
- **用户语言。**语言变更只送达一个存活通道。之后才启动的 Managed 通道从 Bridge 得不到任何
  语言信息。
- **预热与保活。**二者只作用于 Legacy 通道。这是有意为之，但没有在任何地方定义。

## 范围

范围内（针对双引擎 Bridge）：隔离恢复策略、按引擎汇总子进程资源、向每个引擎下发用户语言，
以及 Managed 的预热与保活语义。

不在范围内：带确认的工作区变更下发及其隔离原因（B2b）、宿主接线与选择器输入（B2d）、真实
的 Managed 引擎。单 factory 的 Bridge 在本切片的所有方面保持现有行为。

## 方案

### 隔离恢复

双引擎 Bridge 的某个通道第一次因任一现有原因不再接收新会话时，一个隔离周期开始：恢复清理
失败、新会话清理失败，或被放弃的恢复或会话创建迟迟未结算。Bridge 记录开始时间并设定排空
期限 `quarantineDrainTimeoutMs`，默认 300 000 毫秒。期限从开始时起只计一次，不因任何活动
延长。

隔离周期内：

- 该引擎与以前一样拒绝新会话。该通道还以同样的 503 `acp_channel_unavailable` 分类与原因
  拒绝其会话的任何新工作：prompt、mid-turn 消息、后台回合，以及会在子进程里启动工作的
  side 请求（内容生成、旁支提问、回顾摘要、fork agent，以及启动或恢复工作的 goal 与
  workflow 操作；暂停或清除仍然允许）。已经在运行的回合照常进行并结算。隔离开始前已排队的
  prompt 在轮到它时被拒绝；运行中的回合没有取走的 mid-turn 消息会从队列视图中移除，而不是
  启动新回合。goal 回合由子进程自己发起，无法拒绝；它们会自行结算，或在期限到达时被取消。
- Bridge 会在开始时、以及此后每当有会话结算、或其恢复、创建、worktree 重置完成时，关闭该
  通道上已结算的会话。已结算的会话没有排队或运行中的 prompt 或自动回合、没有在途的通知或
  side 请求、没有运行中的后台任务，子进程也没有报告为它持有的工作。这些关闭与任何被判定为
  condemned 的通道一样在本地授权并设有时限。通道不再承载任何工作后，提前退出。
- 目前没有任何原因能让隔离提前结束。#12737 的决策只允许"工作区变更缺少确认"在收到经过
  校验的确认后于期限前解除；B2b 会加入这一原因。因此，即使迟到的工作之后结算，迟迟未结算
  的原因也会让通道退出。

期限到达时，Bridge 请求取消正在运行的回合，然后按现有的升级流程终止通道。期限只是触发清理，
不是进程已退出的证据。

与任何退出一样，在观察到通道的根进程退出之前，会话条目、ID、准入名额与 owner 保持占用。
该引擎拒绝新会话的时间更长：要等进程登记表确认子进程的整个进程树都已消失（与 workspace
runtime stop 等待的释放相同；没有登记表的通道以退出为准）。提前排空的通道仍在终止时也是
如此，在此之前 workspace runtime stop 也会报告 `stopping`。如果期限触发的升级流程结束后、
或根进程退出后，一个初始化时限（至少 15 秒，即登记表自身的终止窗口）内仍不能确认子进程已
消失，拒绝原因变为 `channel_exit_unverified`，daemon 日志与遥测会报告可能需要运维介入。

此后，每个会话都可以按需恢复。owner 选择器把它送到同一引擎的新通道，由该引擎判断其持久
状态能否安全恢复；未决的工具副作用或不完整的恢复证据会在那里保持阻塞并等待对账。Bridge
从不重放回合，也从不转投另一个引擎。

单 factory 的 Bridge 保留现有的隔离行为：已有会话继续发 prompt，通道在它们排空后退出。
是否对其应用排空期限是另一项决定。

### 子进程资源

资源刷新会轮询每个存活通道，每个通道同一时间最多一个请求。Bridge 快照随后合并各通道的新鲜
读数：RSS 与 CPU 相加（CPU 已经是占整机的比例，相加后仍截断到 100），读数年龄取最旧的
一个，heap 高水位取最大值，未分类的 heap 空间名称取并集。快照还说明它覆盖了多少个子进程、
其中多少个报告了 heap 高水位。daemon 按 Bridge 的存活通道数统计每个 runtime 的存活 ACP
子进程，并把每个快照的子进程数（不超过该存活数）加入 `sampled`，因此在两个引擎下
`sampled <= activeAcpChildren` 依然成立。对于双引擎的主工作区，资源图表显示其子进程之和。

Legacy 仍像以前一样按工作区控制读取。读取 Managed 子进程只是观察：既不会重置该通道的空闲
计时，也不会因回应缓慢而让通道退出，因此打开的仪表盘不会决定 Managed 子进程的存活时间。

### 用户语言

`setUserLanguage` 把变更发送到 Bridge 的每个存活通道，并累加它们刷新成功与失败的会话数。
调用失败的通道计为一次失败；只有没有存活通道、或所有通道都失败时，调用才会拒绝。Bridge
还会记住最后一次请求的语言，并在新启动的 Managed 通道发出第一个会话请求之前把它发送过去。
这一步失败只记录日志，不会阻塞会话。Legacy 通道仍在启动时读取持久化设置。

### 预热与保活

预热只启动负责工作区控制的 Legacy 通道，保活也只延长它的空闲期限。Managed 通道从不预热：
它随第一个 Managed 会话或恢复启动，在有会话或在途工作时保持运行，之后由普通的空闲超时
回收。Managed 的工作从不延长 Legacy 的保活，Legacy 的保活和资源采样也都不会让 Managed
通道保持运行。

## 验证与验收标准

每项行为都在双引擎 Bridge 上覆盖，而不只在 Legacy 上。

1. 被隔离的通道拒绝新 prompt、mid-turn 消息、后台回合与 side 请求，正在运行的回合照常
   结算；另一个引擎继续接收工作。
2. 被隔离的通道上，已结算的会话被关闭，有在途 side 请求或通知的会话保留到它们回应为止；
   通道排空后在期限前退出。
3. 期限不因活动延长。期限到达时正在运行的回合被取消、通道被终止；准入与 ID 只在观察到退出
   后释放，引擎只在进程树被释放后重新开放，不能确认子进程已消失时该引擎以
   `channel_exit_unverified` 继续拒绝。
4. 此后，被关闭的会话可以按需恢复到同一引擎的新通道。
5. 迟迟未结算的原因与清理失败一样让通道退出；在隔离期间完成恢复、创建或 worktree 重置的
   会话同样会被排空。
6. 资源快照覆盖两个引擎，daemon 的子进程计数保持一致。
7. 语言变更送达两个引擎；之后启动的 Managed 通道在第一个会话之前收到记住的语言。
8. 预热与保活只影响 Legacy；Legacy 被保活时，Managed 通道仍按空闲超时回收。
9. 单 factory 的隔离行为不变。

## 风险与待定项

- 在被隔离的通道上阻止新 prompt 是对 #12698 双引擎行为的有意改变；对仍可能自行解除的
  迟迟未结算原因也让通道退出同样如此：#12737 的决策只允许经过确认的工作区变更提前解除。
- 关闭已结算的会话会打断已连接但空闲的客户端；它们会在同一引擎的新通道上恢复会话。
- 在进程树被释放之前保持引擎关闭，会在已排空的通道终止期间推迟该引擎的新会话，通常不超过
  一个初始化时限。一个始终无法消失的子进程会让该引擎保持关闭，直到运维介入；在此期间客户端
  收到可重试的 503。
- 与任何通道退出一样，会话条目、ID 与准入在根进程退出时释放；只有引擎闸门等待登记表释放
  进程树。如果 #12737 决策所说的"物理清理"是指这一更严格的含义，也可以让准入一直保留到
  该释放。
- 记住的语言属于单个 Bridge 实例并只存在内存中。daemon 重启后才启动的 Managed 宿主依赖
  自己的设置加载。
- 选择器输入（Q1）与 Hosted 边界（Q4）仍待 B2d 决定。
