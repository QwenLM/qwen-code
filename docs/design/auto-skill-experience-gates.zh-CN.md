# AutoSkill 经验信号门控

[English](auto-skill-experience-gates.md) | [简体中文](auto-skill-experience-gates.zh-CN.md)

## 问题与范围

Issue #9062 仍未解决：AutoSkill 评审目前只依赖完成 20 次工具调用。
只读探索会消耗一次评审，而短调试会话和用户纠正可能没有评审机会。
AutoSkill 仍默认关闭；确认流程、managed skill 写入限制和内存压力检查保持不变。
本设计替换触发条件，不改变评审 agent 或 shell 进程生命周期。
本设计取代[最初 AutoSkill 提案](skill-nudge/skill-nudge.md)中的计数、触发和
`ScheduleSkillReviewParams` 章节。该提案只按次数触发的代码片段仅作为历史记录，
不再是当前调用方契约；评审 agent 和写入沙箱设计保持不变。本设计也取代
[ACP managed auto-memory](auto-memory/acp-managed-auto-memory.md) 第 7 节及
对应的完成工具验收条件：ACP 转发所有终态完成记录，携带调用 ID 与执行状态，
包括取消结果；由共享客户端决定保护与记账。

## 设计

评审有两条路径：至少 5 次已接受的完成调用，加上同工具失败后恢复或已接受的
中途 steer；或者至少 20 次已接受的完成调用，加上实质性工作。不新增设置。

客户端按调用 ID 暂存小型完成记录，直到对应工具结果被聊天历史接受。
接受判定使用请求所属的确认记录，只包含 setup 和 inline repair 后仍驻留在历史中的
已提交 parts。按对象身份而非仅调用 ID 跟踪：较早的 synthetic response 导致迟到真实
结果被丢弃时不计数，真实结果被提升到较早回合时仍计数。快照在输出预算改写后获取。
首个流事件、正常提交和 finally 路径消费此记录。setup 回滚时没有确认记录，其他发送
的推送不能为被拒绝的工具结果或 steer 提供经验信号。确认推送后的 provider 错误仍
保留接受状态。直接 `addHistory` 也消费匹配记录。重新提交的结果不能重复计数。
被拒绝的输入不会推进评审窗口。skill 文件修改保护仍在本地执行完成时更新，
即使 PostToolUse hook 随后拒绝该结果，或调用在开始执行后结算为取消，也保留保护。
被拒绝和取消的结果仍不计入经验，未开始的写入不设置保护。已取消的执行也保留
完成调用 ID，避免重放重新设置 skill 保护。
ACP 将 code-mode 嵌套调用和 MCP App 完成记录标为非面向模型的调用。
TUI 也将因历史去重而丢弃的迟到结果标为非面向模型的调用。这些完成记录
不创建待接受经验记录、最近工具提示或普通调用 ID 预留，因为没有模型提交
可以接受它们。本地 skill 写入仍设置保护并预留 ID，防止重放重新
设置保护；这些有意保留的 ID 直到会话重置才清除。

流内 ID normalization 除当前历史的 ID 外，也保留客户端在会话中已记录的
完成调用 ID。压缩或 rewind/restore 因此不会让新的执行复用一个会被完成记账
当作重放丢弃的 ID。重建的主聊天共享同一个只读保留视图；`/clear` 与会话切换
随既有评审状态一起清除该视图。不新增独立 ID 存储或持久化状态。

调度器记录的终态排除已取消的调用，即使执行此前已经成功结算。
执行状态排除未执行和已取消的调用；终态错误类型排除 hook 拒绝的结果。
Auto Memory 回忆提示不依赖经验门控：只有面向模型且未取消的终态完成记录
才会添加最近工具提示，不要求结果已被接受。非面向模型的完成记录不添加提示。
shell 成功恢复要求已有的结构化
`ShellResultDisplay` 为 completed 且退出码为 0，绝不解析输出文本。
shell 失败使用执行状态和错误类型；即使前端标为成功，结构化的 cancelled
结果也会被排除。不需要更改 shell 进程拆除逻辑。

同一批结果中，同工具同时失败和成功，不会因结果排序制造重试弧。
后续该工具有成功调用且没有失败的批次才能闭合待恢复失败。
不同工具之间不推断恢复关系。

实质工作包括内置 write/edit/notebook/shell/code-mode 工具、注册的 mutator
种类以及委托 agent 的工作。未标注只读的 MCP 工具也计入（`Kind.Other`
表示副作用未知）。这是保守兜底，并不证明文件改变：shell 读取和委托读取
仍可能调度评审。read/search/fetch 和纯控制流工具不会仅凭调用量获得资格。

信号与待接受完成记录不依赖历史索引，可跨压缩保留。派发时仅重置已消费的
计数与信号，尚待接受的完成记录仍供后续使用。会话切换和 `/clear` 清除全部
评审状态。已有评审运行时保留新窗口，因为其历史快照不包含派发后的工作。
评审仍在回合边界检查，不在每次工具结果后检查。AutoSkill 也在完成 Retry 时
检查：provider 失败前已经接受的结果，即使重试后不再调用工具，也可获得评审
机会；重放结果仍只计数一次。递归 Steer 和 Hook 回合继承原始交互的边界；
Auto Memory 的提取、dream 和迁移保留原有类型门控。已派发评审若后续失败，
保持既有行为：不重新尝试已消费窗口。

## 影响层次

- `packages/core/src/memory/experience-signals.ts`：结果分类、实质工作判定、批次累积。
- `packages/core/src/memory/manager.ts`：必填经验信号及门控。
- `packages/core/src/core/client.ts`：已接受结果计数、steer 和重置。
- `packages/core/src/core/llm-chat.ts`：在流内 normalization 时保留会话已记录 ID，
  覆盖历史移除与主聊天重建。
- headless CLI、TUI 和 ACP 完成路径：提供已有结构化响应，覆盖全部生产调用者。
  TUI 即使对已去重或属于次级交互的模型完成记录，也转发取消结果，由共享客户端
  统一处理保护与经验过滤；client-initiated 工具仍排除。ACP 也转发取消的完成
  记录，保留已结算的执行状态和取消的 span 结果。ACP 使用原始聊天流，
  因此也转发已接受的结果批次。基线 ACP 不调度 AutoSkill
  评审；本改动保留这一启用范围，不新增 ACP 功能。
- 同目录测试和既有 skill-review 集成测试：门控、结果、接线和生命周期回归。

## 验证与验收

运行定向单测、仓库 build/typecheck，并用构建后的真实 CLI 连接可控的
OpenAI-compatible provider，执行真实工具。以 provider 收到的 extractor
请求计数，不依赖日志推断。先以全局 `qwen` 建立基线，并使用已有认证尝试
真实模型 smoke。测试工件放在 `.qwen/e2e-tests/issue-9062.md`（git-ignored）。

验收：21 次只读调用不派发评审；同工具恢复在 4 次调用不派发、5 次派发一次；
不同工具成功不闭合重试；20 次 shell 执行保留兜底；禁用和手工 skill 保护
保持；新窗口不复用旧信号。单测覆盖拒绝、重复结果、混合并行批次、结构化
未知 shell 状态、接受/拒绝 steer、压缩及会话重置。终止式 steer 和 retry
不需要后续工具调用；retry 控制覆盖少于 5 次的恢复、20 次纯只读调用、禁用
AutoSkill 和重复重放。真实聊天流 normalization 测试覆盖截断、restore、
compact 形状的历史替换与聊天重建后复用 provider ID 或生成 ID：新完成调用
仍计数并保留 skill 写入保护，重放仍幂等。clear 与会话切换对照允许新会话
复用 ID。ACP iterator 在首个 chunk 前后失败时，结果仍恰好接受一次。
ACP 取消测试覆盖未开始、执行中及执行后取消的结果；执行后取消的 skill 写入
仍设置保护并保留调用 ID，但不计入经验或最近工具提示。
嵌套读取、普通写入和 MCP App 调用不留下待接受记录或普通 ID 预留；
只有面向模型的父调用结果才计数。嵌套 skill 写入仍保留保护和 ID，但没有
待接受记录，包括取消或被 hook 拒绝的写入。
TUI 去重测试验证：丢弃的普通结果不留下待接受记录、普通 ID 预留或最近工具
提示。已开始执行的 skill 写入仍保护并预留 ID，但不计入经验，包括执行开始后
取消的情况；未开始的写入不保护，重放不能重新设置保护。混合批次仍只接受
并计数其中的新结果。不引入新的 shell 进程取消语义。

## 风险与开放问题

确定性信号只是启发式，不是可复用经验的语义证明。未标注只读的 MCP 工具和
agent 委托有意优先避免漏掉实质工作。待接受结果占用内存直到接受或会话重置。

5 次调用的经验门槛是相对于 20 次调用实质工作兜底的有意成本取舍：重试或
steer 较多的会话中，若每个新窗口都满足条件，可能每约 5 次已接受调用就派发
一次评审。派发重置该窗口的计数与信号；评审运行期间保留下一个窗口，它可能
在该评审结束后的下一个符合条件的回合边界派发。每次评审处理完整且不断增长
的会话历史，默认限制为 8 轮 / 120 秒；已有的 `memory.agentMaxTurns` 和
`memory.agentTimeoutMinutes` 设置可以覆盖对应限制，0 表示禁用该项限制。
开启确认时，新建技能会暂存并提示用户确认。因此重复评审会增加 token、
执行时间及可能的确认操作成本。会话次数上限、冷却期与增量历史处理继续
作为延期的调度策略工作。

不加入持久化、分类器、可配置阈值、新 UI 或 Auto Memory 提取频率改动。
本实现没有待定产品决策；平台验证限制必须单独报告，不能用单测通过代替。
