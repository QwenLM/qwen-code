# 稳定托管记忆规则与请求末尾目录

[English](managed-memory-cache-prefix.md) | [简体中文](managed-memory-cache-prefix.zh-CN.md)

状态：在 #2653/#8277 的提示词与缓存架构轨道中，针对 #11550 的实现提案。整体提醒架构和原始后端缓存实测仍需分别验收。

## 问题与预期结果

旧版托管记忆将 MEMORY.md 目录放在 system instruction 中。因此每次记忆刷新都可能改变对话之前的请求前缀。首次保存记忆还会将精简规则切换为完整规则。只移动目录仍会留下第二处失效来源。

预期结果是：在作用域不变时，保存、更新或删除托管记忆不会改变 system instruction、工具或已保存的对话。下一次请求仍会收到最新目录。这验证的是客户端请求前缀稳定性，不能据此认定服务器保留了 KV 缓存、缩短了 prefill 延迟或降低了完整成本。

## 设计与取舍

将现有完整记忆规则留在 system instruction 中，使其与目录内容无关。会话调用方选择 `forceFullProtocol: true` 和 `includeIndexes: false`；维护代理继续使用默认的规则加目录提示词。完整规则保留访问、类型和作用域约束，包括 TEAM 隐私和凭据限制。规则明确指出，请求末尾的目录条目是数据和指针，而不是指令。

使用现有的分作用域标题、空目录提示和截断逻辑单独构建目录。在当前请求的对话和工具响应之后追加一个文本 part。复制末尾 Content 容器及其 parts 数组；不把该 part 保存进历史，不修改调用方输入，也不在刷新时追加永久历史事件。无变化的刷新生成相同目录文本。后续请求替换上一份仅用于请求的目录，不累积旧版本。

对于空语料，相比原精简路径，始终使用完整规则会增加启动输入。这是为避免首次保存切换规则、保留完整指导而做出的正确性取舍。其质量和完整成本需要在 #12333 中评估；本改动本身不证明计费 token 更少。

## 执行入口与状态归属

`Config` 分别保存规则和目录。旧版模式刷新在全部目录读取成功后构建两者，并同步安装。读取或分层上下文刷新抛错时，保留上一份成功的规则和目录。关闭记忆、安全模式及工作区迁移会清空两者。作用域或信任变化应当改变提示词；缓存稳定不能保留过期权限或其他工作区的数据。现有目录读取器返回 null 或空值的语义保持不变，本改动不调整文件系统失败处理。

主 LlmChat、普通 AgentCore、继承已渲染规则的 fork 和进程内 Arena 都通过 LlmChat 组装请求，在这个边界接收其运行时 Config 的最新目录。自定义及一次性生成在模态裁剪之后使用同一个追加函数。继承规则但不经过这两个入口的调用方自行投递目录：`/summary` 将其追加到 side query 的内容末尾，外部 codex/ACP 子代理执行器在首轮任务之后发送目录。ACP 续轮原本就只发送任务，因此对端保留首轮目录，与目录内联时相同。有一个继承方有意不发送目录：压缩的 side query（`chatCompressionService`）原样复用主 system instruction，以便共享会话的提示缓存，它只负责总结历史。因此它的规则文本提到了请求末尾的目录，而这一个请求并不携带；在那里追加目录只会改变总结的输入，没有收益。目录位于工具响应之后，保持已有工具顺序。

追加函数用现有客户端易变尾部元数据标记目录。Anthropic 和 DashScope 转换器将对话缓存断点放在该尾部之前。如果 Anthropic 的一条用户消息只有易变内容，断点回退到更早的用户消息；没有更早的用户消息时，不添加消息缓存断点。客户端元数据在发送前移除。这保留了可缓存的请求边界，但不证明后端复用了缓存。

结构化召回仍需显式开启，不发送旧版目录；其树和正文投递不变。目录 getter 同时检查 legacy 模式和非空的规则 getter，因此也遵守维护代理派生 Config 通过覆盖规则 getter 禁用会话记忆的约定。准备好的结构化转换提交时保留私有旧版目录，回滚即可恢复原目录，无需扩展转换载荷。工作区重置会清理这些保留的数据。

## 统计与展示

请求快照只将最后一个 user Content 中最后一个、与当前目录完全匹配的文本 part 归入记忆，并从消息估算中移除这一个 part；不会修改请求，也不会把更早的相同用户文本算作记忆。规则仍从 system 字符串归因。`/context`、记忆展示及记忆大小警告包含规则和目录。实际计费总量仍以 provider usage 为准。

## 验证与验收

自动回归覆盖首次保存、更新、无变化刷新、删除、刷新抛错、作用域抑制、结构化提交与回滚、工作区重置、请求末尾不持久化、工具配对及统计归因。真实流式发送边界应显示最新目录恰好一次、原历史保持稳定，后续历史不包含旧目录。自定义生成应保留调用方输入。

受控 CLI/provider 检查应在成功托管写入前后捕获请求，验证新记忆可见及前缀一致性。真实模型的选择和读取质量、原始 llama.cpp 热缓存计数、代表性完整成本与 P95，仍需在各自环境可用后验收。本实现不需要代理服务。

## 范围与后续工作

本提案修复 #11550 中旧版托管目录的位置。它不迁移 #2653 的所有动态 system-reminder 生产方，不完成 #8277 的整体动态内容架构，不默认开启结构化召回，也不替代当前无权限访问的外部评测 runner。维护者评审需要结合这些轨道判断规则与数据分离，以及完整规则的启动开销取舍。
