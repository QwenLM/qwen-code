# 输入框草稿附件

[English](composer-draft-attachments.md) | [简体中文](composer-draft-attachments.zh-CN.md)

## 问题与范围

未发送的图片和文件应随文字草稿在会话切换、页面刷新后恢复。文字使用 localStorage，其配额不适合存放 8 MiB 附件。保留现有文字格式和 daemon 协议，使用相同草稿 key 将附件载荷存入 IndexedDB。

## 存储与恢复

直接保存图片载荷以及文件的 Blob/文字载荷，不增加协议字段。输入框草稿、本地目录句柄和托管待处理请求复用 IndexedDB 请求工具，由它直接创建各自的单个 object store；写入在事务完成后才算成功。存储不可用或失败时，内存输入框仍可使用，恢复结果视为没有存档附件。

每个草稿 key 在当前页面中只有一份草稿会话，由该 key 的所有已挂载输入框共享。主聊天和展示同一 session 的分屏即时共享文字、行内及顶部引用标签、恢复的输入标注和附件载荷。不同 sessionId 使用独立记录。焦点、光标、菜单和历史浏览保持视图独立；临时历史预览不替换共享的未发送草稿。

共享记录只持有一次进行中的附件读取。读取只记录最新的待保存附件快照，以及显式清空是否已丢弃旧存档。在读取完成前返回草稿或挂载第二个视图时复用该读取；其他草稿读取完成时可以更新自己的存档，但不能更新无关输入框。汇总各订阅视图尚未完成的文件读取批次，避免另一视图仍在读取新附件时发送。视图离开时移除其待完成计数。最后一个视图退订后，等待读取完成即释放记录和载荷。文字沿用现有 localStorage 格式和保存防抖；即使尚未落盘，另一个已挂载视图也能读取实时文字。

附件编辑即时保存，包括恢复期间排队的编辑。每次编辑先连接共享会话并更新其订阅视图，包括宿主在被动初始化之前恢复的附件；提前连接时保留已存文字，并先读取附件存档再保存新增附件。因此分屏添加 Y 后在主聊天添加 Z 会保留两者。显式删除、清空和已接受的提交传播到所有同 key 视图，不合并旧快照来恢复已删除的内容。切换草稿时不保存离开的附件快照。会话创建时仍显式将待创建草稿的附件迁移到分配的会话 key。

草稿 key 不变时，工作区元数据更新不会重置附件或取消待读取。初始未知的工作区确定后，即使没有文字记录，也始终读取其附件存档。无作用域的内存附件先并入该读取，再保存。

附件能力变化同时记录所属草稿 key 和显式输入框上下文。目标草稿禁用附件不能清理离开草稿，即使目标上下文先于会话 ID 到达。同一 key 重新启用附件时，允许在工作区元数据补全或取消待切换上下文时恢复存档。

当前草稿恢复期间禁用发送，并在普通发送、历史重试和历史搜索发送入口检查读取状态。宿主通过 `composerInput.submit` 发起的一次性自动发送会等待该读取，不会丢弃；草稿切换、用户修改文字或输入 effect 清理后取消延迟发送。仍允许添加附件，读取结束后将新增附件与存档合并。图片按载荷去重；文件全部保留，重名时复用现有文件名后缀工具。文件名或 Blob 元数据相同不能证明内容相同。

显式清空会丢弃存档，即使读取尚未完成。之后新增的附件应保留，但不能带回已清空的存档。待读取期间删除刚新增的卡片只更新当前快照，不丢弃尚未读取的存档。卸载时解除当前读取与 UI 的关联。

## 发送接受确认

提交时记录草稿的编辑计数。同一页面中的输入框实例按草稿 key 共享计数，使已卸载实例的回调也能识别重新挂载后的编辑。同步记录文字、文件引用卡片及附件编辑和显式清空；后台保存不递增计数。文字仍使用现有的两秒防抖保存，不能仅靠持久化文字判断最近是否编辑。旧草稿或已卸载实例的发送确认晚到时，只有保存的文字和编辑计数都与提交时一致，才清理存储。纯图片消息没有保存的文字记录，也遵循该规则。清理一个 key 不会取消另一个 key 的读取。现有同会话编辑器身份检查继续保护新输入，包括已提交附件的删除语义。

待创建草稿变成 session 时，仅在提交所捕获的编辑器身份仍匹配时，将该提交的清理 key 和编辑快照迁移到分配的会话。之后切走或卸载才收到的接受确认，仍会清理迁移后的存档。通过比较当前草稿 key 和清理 key 来识别已离开的草稿，包括返回没有 sessionId 的待创建输入框。分配前的编辑阻止此次归属迁移，分配后的编辑改变目标 key 的计数，均应保留。该交接复用现有提交记录和身份检查。

## 约束与风险

IndexedDB 属于浏览器尽力保存的 origin 存储，配额不足或浏览器回收会导致无法恢复。本次不增加保留策略、跨标签页冲突处理或 daemon 端草稿存储。二进制文件与另一个同名附件并发恢复时，通过后缀保留两份，不按元数据猜测内容相同。

## 验证与验收

- 存档附件仍在加载时不能仅发送文字；读取成功或失败后恢复发送。
- 旧草稿发送被接受时，不删除提交后新增的附件，即使文字未变。
- 桌面端或移动端输入框重新挂载后，同样保护新草稿。
- 文字保存前仅修改文字或文件引用卡片，也能保护重新挂载草稿中的附件不被旧确认删除。
- 切到不支持附件的草稿时，保留离开草稿和目标草稿未读取的存档；同一草稿显式禁用附件仍会清空。
- 工作区元数据晚到时，保留已加载及加载中的会话附件，以及等待中的宿主发送。
- 待创建会话草稿的工作区确定后，恢复纯附件存档，并合并无作用域时新增的附件。
- B 加载期间接受 A，不影响 B 恢复。
- 同名文字文件和二进制文件保留两份载荷，名称互不冲突。
- 快速 A-B-A 切换复用待读取，不重复附件。
- 同一会话的主聊天与分屏在落盘前共享文字和附件，覆盖继续编辑、删除、清空及已接受的提交；旧视图不能覆盖或复活另一视图的附件。
- 不同 sessionId 保持隔离，包括同时显示在分屏中的情况。
- 分配会话后切走或卸载，迟到的接受确认仍清理迁移后的存档；分配前后的新编辑均保留。
- 待读取期间清空后再添加，不恢复已清空附件。
- 宿主在布局阶段恢复的附件在有无 IndexedDB 时均保留，并与已有存档合并而不覆盖。原有会话创建、卡片删除、重新挂载、能力禁用、本地句柄及托管待处理请求存储测试继续通过。

测试计划及复现证据位于 `.qwen/e2e-tests/` 和 `.qwen/issues/`。全局 CLI 尚未包含此未发布功能；延迟读取回归测试通过 IndexedDB 替身执行 worktree 中真实的输入框 hook。
