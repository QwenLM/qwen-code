# Worktree 恢复期间的自动任务

[English](2026-11-17-worktree-restore-automatic-work.md) | [简体中文](2026-11-17-worktree-restore-automatic-work.zh-CN.md)

状态：已在 macOS 本地实现并验证，未部署到运行中的 daemon。

## 问题

ACP 冷恢复会在 daemon 调和持久化 worktree 之前启动持久化 cron。到期的 cron 轮次可能等待用户回答，而目录迁移又等待该轮次完成。Web Shell 则等待加载完成后才展示问题。`hasActivePrompt` 不涵盖所有内部自动轮次，因此不能据此判断目录迁移能够完成排空。

## 范围

修复 Web Shell load/resume 和定时任务对记录了 `workspaceCwd`、由路由管理的 worktree 的冷恢复。保留现有会话 ID、聊天记录存储、worktree 归属锁、标记检查、目录包含关系、信任校验与清理行为。不重启共享 daemon，不修改其他会话，不自动回答问题，也不扩大文件系统访问范围。初始就是旧版 sidecar 的恢复与不包含 worktree 的恢复保留现有兼容行为；严格 sidecar 不得在恢复期间消失或降级。

## 设计

daemon 通过 sidecar 预读，已经知道严格 worktree 恢复必须在返回前调和 cwd。在这条路径上，将所有会话来源的恢复问题都延迟到调和之后，而不再仅限 Channel 会话，并通过私有恢复标志要求子进程在 cwd 恢复成功前保持自动任务暂停。这是 bridge 内部元数据，公开 REST 请求体不能选择该标志。

子进程仅接受已认证私有父进程的标志，并且仅在构造冷恢复 Session 时应用。在构造完成后、异步登记、回放生产者或 cron 启动之前立即设置暂停状态。暂停状态阻止 cron、Goal、通知队列和新的前台轮次进入执行，并作为 Session 工作持有项受到生命周期保护。它不是正在执行的轮次，不得加入排空谓词，否则目录迁移会等待自身的准入暂停状态。

成功的 `session/cd`（包括经过校验的同目录操作）仅在释放关闭锁后解除 cwd 暂停。自动队列和持久化 cron 随后可以在调和完成的目录中恢复，但仍有保存的问题等待重建时除外。自动准入同时遵守已有的问题恢复谓词，否则 cron 消息可能在恢复轮次重新检查历史之前挤走原问题。前台问题重建仍可进入执行，其活动轮次会在回答完成前保护自动队列。校验或迁移失败时保持 cwd 暂停，由现有恢复清理逻辑仅丢弃该 Session。热附着不得向已有任务追加 cwd 暂停状态。

daemon 在现有校验和迁移期间持续持有 worktree 归属锁，并仅在调和后触发延迟的问题。目录缺失、不明确、不可信、已移除或无效时均不得回退到主工作区。本次修改不改变手动切换目录时的排空语义。

绑定定时会话的启动恢复与 keepalive 唤醒使用和用户加载相同的恢复核心。每个回调都绑定所选工作区 runtime 和 generation guard，包括存储、bridge 和准入。generation 已移除或关闭时直接失败，不使用主 runtime。未提供 daemon 回调的已有嵌入方式保留 helper 直接调用 bridge 的兼容路径。

目录调和刷新 LLM 上下文时，将结构性目录消息插入到末尾可恢复的问题之前。保留问题的调用负载、provider 元数据与已完成调用 ID，使问题仍能被发现，后续回答仍与调用相邻。异步生成目录上下文后重新检查历史；如果问题已经获得回答，则将上下文追加在已完成的问答之后。

## 风险与限制

旧进程中已经卡住的 Session 仍需定向取消并重新加载。本次修改防止新进程中所覆盖 daemon 入口的冷启动顺序缺陷，不会热修补已安装的进程，也不负责建立跨 daemon 的写入归属。它不会为这些入口之外直接使用 bridge 的调用方增加 daemon worktree 调和流程，也不改变 Live conversation 目录迁移。不识别私有元数据的混合版本保留已有兼容行为。其他传输失败与前端错误展示不在本次范围内。

## 验证与验收

- 使用隔离运行环境和确定性的本地 provider，或聚焦的测试脚本降级方式，复现修复前的冷恢复顺序。不得将用户的运行中会话作为模型测试夹具。
- 到期自动任务在 cwd 调和前不能执行或提问；调和成功后在 worktree 中恢复，并且聊天记录和问题可以加载。
- Channel 与普通会话来源的持久化问题都必须延迟到严格 worktree 校验之后。
- 启动恢复与 keepalive 唤醒经过相同的 worktree 校验和暂停流程；已关闭的 runtime generation 必须被拒绝。
- 目录上下文刷新后，待回答问题仍保留完整调用负载；上下文生成期间到达的回答不得被移动或重新打开。
- 保存的问题与到期 cron 同时存在时，必须先重建原问题，再允许自动消息追加；回答完成后自动任务恢复执行。
- 暂停的 Session 继续受到条件生命周期清理保护，但没有执行中任务时，其轮次排空等待应能完成。
- cwd 切换失败不能解除自动任务暂停；成功与经过校验的同目录操作能够解除暂停。普通会话和热附着保留原有行为。
- 保留对目录包含关系、归属、缺少标记、会话被替代及清理失败的回归覆盖。
- 在将源码修复标记完成之前，运行受影响单测、构建、类型检查、隔离修复验证与两轮干净自审。现有现场恢复证据与源码修复证据分开记录。

本地验证使用 Node 24.12.0、loopback mock provider 和隔离的配置、runtime、workspace 目录。已安装的 0.27.4 在 30,458 ms 后复现 cron 恢复超时；最终 bundle 在 1,827 ms 内加载成功，返回精确 worktree cwd、`persisted-v1`，保留待答问题且聊天记录可读。实际冷启动 cron 请求包含 worktree 路径。持久化问题夹具在 2,100 ms 内加载成功，问题正确恢复、cwd 精确且没有额外模型请求。组合夹具在 1,769 ms 内加载成功，三秒内的 15 次探测均保留原问题。仅在夹具中回答后，到期 cron 在 307 ms 内于正确 worktree 继续执行；聊天记录从 6 增至 22 个事件，并出现有独立标记的 cron 问题。单测回归覆盖自动任务准入与排空、问题顺序及准入优先级、恢复回调接线、已关闭 generation，以及严格 sidecar 消失或降级。全量 build、bundle 和 typecheck 通过。这些结果不代表已发布，也不代表 Windows、Linux 或外部模型 provider 验收通过。
