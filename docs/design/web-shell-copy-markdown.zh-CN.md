# 在助手正文底部复制 Markdown

[English](web-shell-copy-markdown.md) | [简体中文](web-shell-copy-markdown.zh-CN.md)

## 问题与范围

助手正文底部已有通用复制按钮，实际复制的是原始 Markdown。用户需要在它
旁边增加明确的 Markdown 入口。保留现有复制行为、流式输出限制和导出的会话
文档行为。最后一轮已完成回复的底部操作栏保持显示。

## 方案与决策

在 `AssistantMessage.tsx` 的复制按钮后紧接增加 Markdown M↓ 图标，复用
`assistant.copyMarkdown` 作为本地化提示和无障碍名称。两个按钮都通过现有
剪贴板工具复制完整 `content`，保留 HTTP 降级和失败报告。每个按钮各用一份
`useCopiedFlash` 状态，仅被点击的按钮显示成功。复用现有底部样式，在已有底部图标
旁定义一个小型内联 SVG，不增加基础组件、依赖、公共选项或 daemon 路由。

## 验证与验收

更新 `AssistantMessage.test.tsx`，检查原始 Markdown 完整保留、独立成功反馈、
本地化、定时器清理、降级和显示条件。增加聚焦的浏览器测试，使用现有模拟
daemon 验证相邻按钮、真实剪贴板内容、键盘操作并截图。此验证覆盖 UI 和
剪贴板行为，不代表真实模型或 Git 后端验证。
执行构建、类型检查、相关单元测试和浏览器 E2E。剪贴板失败必须沿用现有
警告行为，不显示成功。无待决问题。

## 最后一轮的显示

最后一轮已完成的助手回复，其内置底部操作栏无需悬停即可完整显示。将已有的
最终回复轮次标识与最新轮次起始标识比较，通过 MessageItem 传递显示标志
（包括其 memo 比较），并应用局部 CSS 类。历史轮次保留悬停和焦点显示；
发送新的用户消息后，取消上一轮底部操作栏的常显。流式输出、后台任务和文档
模式已有的显示限制仍然生效。在浏览器和聚焦的 MessageList 测试中验证多个
轮次、历史轮次悬停和下一条用户消息的切换。
