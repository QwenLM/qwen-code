# Web Shell 新任务模型默认值

[English](web-shell-model-preferences.md) | [简体中文](web-shell-model-preferences.zh-CN.md)

## 交互

「模型」设置新增新任务默认值表格，列表使用 daemon 的实际对话模型。每行按
模型能力提供思考、强度和上下文窗口控件。上下文窗口可直接输入整数 token 数，范围为 1 至
该模型显示的上限。输入更新当前作用域的草稿，数值无效时禁用保存。
面板变窄时，控制项排列在每个模型名称下方。关闭思考时保留强度，再开启时可继续使用。
供应商编辑器保留自己的窗口上限操作。

现有「用户」和「工作区」页各自管理草稿、保存和取消。每个字段显示其来源，可以
恢复继承。工作区逐字段覆盖用户值，管理策略和模型默认值继续适用。保存会发布
设置变更事件，现有任务继续使用各自的配置。

## 设置与任务状态

工作区范围的 daemon API 通过 `GET /workspace/model-preferences` 返回模型目录、
限制、两级配置和来源。`PATCH` 接受一个作用域和有变化的字段，`null` 表示恢复
继承。daemon 在设置锁内读取最新目录和设置，校验整批数据后写入对应作用域的
`model.preferences`。模型键由 daemon 根据认证类型、模型 ID 和实际端点生成。
新增的 `reasoning.enabled` 与 `reasoning.effort`、`contextWindow` 一样可选。

新建的本地 daemon 任务在创建时保存有效偏好。任务在切换模型和恢复时继续使用
保存的快照。旧记录继续沿用原有回退逻辑。Web Shell 现有的思考控件把选择保存
到任务中，优先于任务创建时的默认值。任务级上下文窗口编辑器后续接入。

原生 Web Shell 在 daemon 声明支持时展示新表格。嵌入宿主在初始化和重置
配置都能保留两级 `model.preferences` 后，可开启 `modelManagement.allowPreferences`。宿主设置面板可以调用同一套
daemon API。

## 验证

创建使用 200K 窗口的 A，保存 128K，再创建 B。验证二者发消息、切换模型和
重启 daemon 后的实际上下文窗口。修改 A 的思考选项，再核对 B 和后来创建的 C
使用的默认值。覆盖按字段继承、同 ID 不同端点、强制开启、只支持开关，以及批量
校验失败后设置未发生变化。

在桌面和窄屏触控视口中检查 token 输入和显示的窗口上限。确认超出范围的数值留在输入框中，
保存有效值或恢复继承时使用当前作用域。
