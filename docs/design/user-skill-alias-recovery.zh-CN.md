# 用户级 Skill 别名恢复保护

[English](user-skill-alias-recovery.md) | [简体中文](user-skill-alias-recovery.zh-CN.md)

状态：PR #15466 的候选修正。新增共享拼写授权会在不写入的情况下被拒绝；这不是完整权限隔离验收。

## 问题与范围

User `skills.disabled: ["pdf"]` 条目可能同时限制 `rust:pdf` 与 `go:pdf`。
仅启用 `rust:pdf` 时删除该条目，会静默解除另一个限制。另一方面，将唯一的
历史硬禁用别名转换为 `default` 模式时，必须删除该硬禁用别名，否则请求的
模式不会生效。限制查询必须保留 registry 和 authored 两种拼写。

## 候选行为

取得 settings 写锁之前，枚举主工作区和其他受管工作区目录。只有身份已解析，
且目录完整、受信任并经新枚举时，才能删除 authored 别名。保留快照即便标记
`stale: false`，以及带错误的目录，都不能证明归属唯一。

将 registry 与 authored 两种拼写都按 registry 身份建立索引。该规则涵盖带
冒号的名称：`go:pdf` 既可能是一个 Skill 的 registry 名，也可能是
`rust:go:pdf` 的 authored 拼写。同一 registry 身份在不同工作区重复出现
不构成歧义。

启用或转换禁用模式时，从 User 硬禁用及默认禁用列表中移除已证明唯一的别名。
保留共享或未解析别名。查询阻止原因时使用完整身份，只豁免本次写入确实移除
的条目。System/SystemDefaults 硬锁继续生效。批量启用会重查此前显式请求项
已移除或抵消的限制。

精确 registry 拼写在解除全局限制前也必须证明归属。项目 `pdf` 与扩展
`rust:pdf` 同时存在时，启用 `pdf` 必须保留全局 `pdf` 限制并返回已有阻止
原因。默认授权和硬禁用转默认禁用也遵守此规则。缺少新鲜目录证据时保留现有
限制；目录完整且归属唯一时，普通精确恢复仍可执行。
已有授权可能已抵消共享默认限制。此时启用请求保留默认回退限制并报告无变更，
但必须在不假设任何条目会被删除的前提下检查完整身份。未解析名称的硬禁用转
默认禁用无法证明归属，因此保留已有硬限制；注册前写入硬禁用仍可执行。

## 已决定的边界：新增授权

新增授权有独立入口：没有 User 限制，但 Workspace 存在
`defaultDisabled: ["pdf"]` 时，新增 User `enabled: ["pdf"]` 会同时影响
项目 `pdf` 与扩展 `rust:pdf`。User 守卫按现有契约排除 Workspace 条目，
因此写入路径改为拒绝该授权：除非完整的新鲜受管目录证明写入拼写只对应一个
registry 身份，否则返回 `changed: false` 与
`reason: "ambiguous_skill_name"`，且不写入文件。已有授权不拒绝。已证明唯一
的普通授权仍可执行，共享名称需通过 settings 处理。另一选项是设计按身份的
权限表示，支持共享名称的选择性恢复，但需要单独的契约和迁移设计，本修正
不声称提供。目录检查仅覆盖受管工作区，不能证明并发安装或未注册工作区的
全局目录原子快照。

## 验证

回归测试必须拒绝会删除共享硬禁用或默认禁用的单项及完整名称批量启用，涵盖
项目/扩展、扩展/扩展、次工作区和含冒号名称碰撞。新枚举失败时必须保留限制，
缺少新鲜归属证据时拒绝精确名称恢复；遵守高层锁、保留未解析禁用、允许唯一别名
恢复、拒绝新增共享授权且不写入文件，以及硬禁用转默认禁用，并让两种请求顺序
达到相同批量结果。这些持久化测试使用真实临时 settings 和受控目录，不能作为
真实 ACP 竞态或其他操作系统的验收。
