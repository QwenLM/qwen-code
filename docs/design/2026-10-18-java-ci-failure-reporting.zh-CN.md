# Java CI 失败上报

[English](2026-10-18-java-ci-failure-reporting.md) | [简体中文](2026-10-18-java-ci-failure-reporting.zh-CN.md)

Java CI 失败后，作者应能直接收到摘要，或在 issue 队列看到跟踪单，而不必自行翻找 Actions job。main 手动全量 39042781121 失败，对应上报流程 39047669819 的所有 job 却被跳过。审批触发的 Managed Agent 全量也被上报流程的 main 分支过滤排除，即使它在 PR 合并后才结束。

扩展现有失败上报流程，复用其解析、去重与自动修复派单能力：

- 保留现有 main push 和定时失败上报，并接入 main 或 PR 分支上手动触发的 SDK Java 全量失败。
- 接入失败的 Managed Agent PR 和审批运行。按精确 head SHA 在仓库的 PR 列表中查找对应 PR：事件的 `pull_requests` 数组可能为空，且审批运行会把基仓库记录为 head 仓库，因此限定词是 SHA，而非从运行信息推导的源仓库过滤（无关 fork 上的同名分支携带不同的 SHA）。忽略已被新提交替代的运行以及已关闭未合并的 PR。
- 每个失败 run 在 PR 中发布或更新一条评论，列出失败 job 的直达链接、失败步骤和已识别的测试。PR 已合并时，同时进入既有 issue 去重和自动修复派单流程；但若本次失败是对其合并前工作流的重跑（第 2 次及以后），则只保留评论、不创建 issue，因为它描述的是 main 已经替换掉的 head。attempt 不可读时仍然创建 issue。重跑从早先 attempt 的评论中尽力恢复 tracking 链接；若该评论从未发布或已被删除，则评论不带链接。未合并时仅回贴 PR，不创建 main 回归单。
- 保留 main 和已合并 PR 的基础设施失败单次重试，以及按失败测试去重的行为；已合并 PR 的重跑例外——既不重试也不创建 issue，只回贴评论。开放 PR 的基础设施失败发布评论，不触发需要写权限的重跑；在基础设施路径上，只有成功派发重跑才抑制报告。
- 把超出 `timeout-minutes` 的 job 视为可上报的取消。GitHub 会把这类运行判定为 `cancelled`，在运行层与并发替代无法区分；区分它们的是 job 注释里的「The job has exceeded the maximum execution time」。注释已读取且不含该消息的 `cancelled` 运行属于替代，不承担任何结果。注释读取失败的 `cancelled` 运行照常上报——误判一次替代多一条评论，丢掉一次超时则丢掉整个回归记录。
- `cancelled` 只在既有允许清单已接纳的目的地上生效：main 的 push/schedule 运行，以及允许清单内工作流的 `workflow_dispatch`。这个限定保证被替代的 `Managed Agent gate` PR 运行不会被当作 job 超时报到贡献者的 PR 上。
- 超时运行整条重跑，而不是逐 job 重跑：没有任何 job 处于 `failure` 结论供 `rerun-failed-jobs` 选择。重跑自身的结束会重新进入本流程并上报结果，因此该次失败在重跑结束后归档。重跑上限为第 3 次 attempt——首次上报前共两次整矩阵重跑——使持续超出上限的 lane 最终归档而不是无限重跑。由不可读注释推断出的超时照常上报，但绝不购买整矩阵重跑；重放一条可能已被替代的矩阵代价更大。provisional 报告上的超时直接归档而不延后，因为它测的 head 已被替换、其重跑无法重新进入。
- 重跑继承归档，所以 `file_issue` 无法同时当作派发与归档的开关。目的地延后超时归档时改记 `rerun_pending`；若该次派发失败则归档，若重跑被跳过则不在此归档——provisional 与注释不可读的运行走各自的路径。
- 超时会连带取消同一次运行的兄弟 job；只上报注释中指明超时的那个 job，也只抓取它的日志。渲染器接收这份精选集合而非完整 job 列表，使五 shard 矩阵只列出真正出错的那条 lane，而不是全部五条。
- 在查询 issue 前生成 PR 摘要，避免 issue API 失败吞掉评论。评论查询和发布最多重试三次，每次写入前重新查询以避免重复。

只读分析 job 仅检出默认分支，不检出触发运行的 PR。评论和 issue 发布 job 不检出仓库，不执行仓库代码；摘要通过环境变量和正文文件传递。关联 PR 时必须匹配目标仓库、`main` 基分支、当前 head SHA，且 PR 处于开放或已合并状态。不可信 PR 代码不会获得 bot PAT，也不能在合并前创建已批准自动修复的 issue。

验证使用真实失败运行的元数据，重放事件过滤逻辑，通过替代 GitHub CLI 边界验证 PR 关联和评论更新，并覆盖原有日志解析、issue 去重及基础设施重试行为。本地验证与线上触发、发布分开记录。
