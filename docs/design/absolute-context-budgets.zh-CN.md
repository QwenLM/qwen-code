# 绝对上下文预算

[English](absolute-context-budgets.md) | [简体中文](absolute-context-budgets.zh-CN.md)

## 状态与问题

#12029 的 Draft 实现，属于 #12028。Core、CLI 测试及请求级验证已经通过；默认值须经核心维护者评审后才能合入。

ToolSearch 默认允许按模型窗口的 10% 预加载；常驻记忆告警使用 15%。窗口变大便允许更大的常驻前缀，而任务需求并未改变。窗口占用率不是成本预算。

## 拟议变更

保留 `tools.toolSearch.threshold` 的百分比含义。新增 `tools.toolSearch.maxPreloadTokens`，默认 8000，预算取百分比预算与绝对上限中的较小值。零表示关闭按预算预加载，不是禁用工具，也不改变显式 eager 声明。保留全有全无的预加载决策以及无 ToolSearch、CodeModeOnly 的行为。

为现有常驻上下文告警增加 10000 个估算 token 的上限；原有 15% 阈值较小时仍使用它。这只是告警，不截断或拒绝加载指令。告警显示实际生效阈值，不能在只超过绝对上限时误称超过窗口百分比。

复用现有设置校验与 Config 传递链路，在运行时边界处理有限、非负的上限。不引入预算管理器，也不在本次修改 schema 体积估算器。

## 层次与文件

修改 CLI 设置 schema 与 Config 构造、核心 Config 参数和 getter、client 预加载调用点以及记忆告警。使用仓库生成器重新生成设置 JSON schema。增加相邻测试并更新用户设置文档。审计派生 Config 和 SDK 调用，避免参数丢失或只有声明而没有生产调用方。

## 权衡与边界

8000/10000 是 issue 讨论中待评审的策略提案，不是实测最优值。较小预加载预算可能增加 ToolSearch 轮次，并在会话中途改变声明前缀。首轮输入减少不证明完整任务成本更低。宣称节省前应分别比较冷启动与缓存复用。不能承诺所有仅内置工具的配置都不变：启用的功能和工具描述会改变池大小。

PR #10410 的 deferred-call bridge 不是该默认值的前置依赖：`main` 上没有这个桥接面，#11321 处理的也是该新表面的后续契约。实测默认启动池约 6447 个估算 token，低于拟议的 8000 上限，因此默认值不会因此新增 ToolSearch reveal 或前缀变化。更低的自定义上限可能触发这些行为；在稳定桥接方案落地前，这是 operator 显式选择的取舍。

本次不迁移扩展内容，不修复分类统计，不改变权限、工具可见性规则或指令正文。

## 验收

验证大小窗口、百分比与上限取小、零和自定义上限、工具池边界、无效值，以及无 ToolSearch 和代码模式路径保持不变。验证告警阈值上下两侧与原有告警生命周期。检查 CLI 设置传递及直接构造 Config 时的默认值。

先以隔离配置和 localhost 请求捕获 dry-run 全局 CLI，再对构建后的 bundle 重跑。记录实际工具声明与告警文字，不能只有公式测试。运行构建、类型检查、针对性测试、独立验证和两轮无发现的 diff 自审。mock usage 不是 provider 成本证据。
