## Problem and first supported case

The original private file runtime can complete a turn, but cannot retire that completed application. Hosted denies activation release, the SQL live decoder refuses a terminal suffix, worker drain returns BLOCKED without a full inventory, and generic Runtime Session release refuses CSI. Original native continuations and binding control claims can still change a DRAINING original. A caught renewal failure or an empty pending Set does not prove completion.

The first positive path starts with one fully settled, still-live original Hosted owner, generation-1 binding/writer and epoch-1 activation, the original bare Pod, uncompacted inline native history and only Read/Write/Edit effects. A pending model/tool round, cancellation, UNKNOWN result, unresolved read/PUT, unsupported ledger, replacement owner or missing original authority blocks. No new model request, recovery activation, dispatch, file preparation or legacy publication/ACK is introduced to make a pending prefix appear settled. Ordinary deferred_v3 ACK evidence does not qualify this private file lane.

## One original retirement authority

Store typed nullable application progress on the canonical `ma_operation` CSI_RETIREMENT row in the fresh schema. Keep row.phase and identity_json byte-exact DRAINING and keep binding and holder DRAINING and retain the occupied slot with its original active binding. The application format is qwen-csi-application-retirement/1. Fields are progress_format, progress_version, progress_stage, settlement_deadline_ms, frozen_request_bytes/sha256, cut_bytes/sha256 and finalize_receipt_bytes/sha256. Every field has a real coordinator, writer gate, finalizer or retry consumer below; no second release ledger or caller-provided completion boolean is added.

Stages are SETTLING → FROZEN → CUT → DRAINED, with exact progress versions 1, 2, 3 and 4 checked by both the SQL authority and Hosted status reader. BLOCKED is a reported condition preserving the last durable stage. At original beginRetirement, persist SETTLING/version 1 and an overflow-checked DB startedAt + 300000 ms deadline in the same original Connection/commit as intent insertion, binding seal and holder DRAINING. This is a five-minute application-settlement budget for the new format, distinct from the ten-second SQL transaction and thirty-second RPC bounds. A shorter current writer/activation expiry remains binding. Legacy rows have NULL progress and are not backfilled; missing, partial, unknown or corrupt progress blocks this application path. Retry never initializes or moves a deadline.

Within each Hosted completion attempt, every later status response must preserve each already observed non-null frozen-request and cut digest, and must not move its progress version backwards. Refuse conflicting responses before another retirement command. A consistent already advanced response may skip completed stages; an initial DRAINED response remains a read-only retry with no writer acquisition. This client check supplements the server's immutable-row validation and does not qualify physical release.

The original holder revision comes from the saved reservation. DRAINING must equal its exact checked next revision, including reserved 4 → draining 5 in a later cycle. It is distinct from runtime generation 1, writer generation 1, activation epoch 1 and application progress versions. Current admission does not create a physical RELEASED outcome.

Each mutating consumer obtains fresh same-Connection DB time after blocking dependencies and immediately before its final write. Equality with the deadline is expired. New original writer/activation/dispatch extensions during SETTLING cannot exceed the deadline; an old expiry already beyond it is not silently shortened or accepted by max/min arithmetic. FROZEN prohibits all new renewal. A live deadline never revives an expired writer or activation. The cut uses the original writer and historical terminal predecessor, without treating a released activation as live. Postcut observations use immutable cut/receipt authority and need no live renewal.

## Existing-owner barrier and exact preparation

Add one authenticated primary-listener, live-session-owner route at /session/:id/internal-csi/retire. It selects an existing owner by full Session scope, original binding and retirement ID; it never attaches or acquires a new owner. It synchronously latches retirement before any await, closes attach/text/history and queued ordinary work at actual start, and returns the same pending operation for exact retry. A different retirement conflicts. The retirement operation is outside the Set it joins, avoiding self-join. Other owners continue operating.

Preserve task failures when tracked tasks leave the Set. Retain the original authority.renewActivation Promise<ActivationState | undefined> before both the existing then(() => undefined) mapping and catch handler; owner.renewing currently holds a mapped Promise<void> and cannot distinguish successful activation facts from a no-op. Freeze the activation timer, join the raw renewal promise and reject undefined/no-op outcomes or a rejection. Close HTTP writer-renewal admission and rescheduling before joining its original renewal promise; retain the grant and its actual outcome. Do not call stopLocal, seal, assertWritable or ensureWriter to prepare closure. stopLocal disables requireGrant before join and may turn an otherwise successful renewal into a swallowed error. The owner.managed.activation object is the install identity; current expiry comes from authority.currentActivation after the joins.

Only a renewal that actually exists is joined and checked. With no in-flight renewal, use the current original activation/grant after admitted tasks join; do not initiate a renewal or interpret the absence of a promise as an undefined renewal result. Closing the original writer also closes pending-append settlement admission. After joining any renewal, join an already issued acquisition before checking the original generation; a settlement waiting for renewal must recheck admission before issuing a new acquisition.

Close ordinary authority admission synchronously and prepare exactly one release in its original serial boundary after admitted work has joined. Reject an unresolved append before publishing a boundary or encoding a release, and check writeFailure/recoveryBlocked and the actual active activation. Construct the boundary body from the current committedSequence/lastRecordUuid, preserve current activation expiry, and use the existing record/marker encoders and local staged-resource store. The release is one activation.changed event, two records and one managed-activation-boundary resource. Preparation performs no HTTP, writer renewal or durable append. Cache the prepared result so even a failed persist attempt does not generate new UUIDs, references or timestamps. Existing generic release/close remains denied for CSI.

Extract the existing HTTP commit-body construction as a private shared routine genuinely consumed by ordinary append and this preparation. Ordinary append still ensures its writer first; retirement preparation uses the already joined grant and cannot call ensureWriter. Capture the exact UTF-8 JSON body, including all records, resource bytes, IDs, times, parent links, digests and original metadata. The request's latestCheckpointResourceId is null; the actual predecessor checkpoint is separately pinned and remains in the durable head.

## Private coordinator protocol

Use narrowly scoped retirement endpoints under the existing Managed Session operator authentication. POST freeze receives format, retirementId and frozen body bytes as canonical base64; POST cut consumes the same exact frozen digest; POST finalize consumes the persisted cut identity; GET status is read-only. The body and frozen envelope exclude naked bearer tokens. Authentication uses the original header and persisted token hash for original identity; retry authentication does not issue a new grant. Duplicate/unknown fields, trailing tokens, noncanonical base64 and out-of-bound bytes refuse. A complete but unsupported or inconsistent persisted inventory returns HTTP 409 with csi_application_inventory_blocked; it is not an invalid request body.

The Session Store prefix is /internal/managed-session-store/v1/sessions/{sessionId}, with POST /csi-retirement:freeze, /csi-retirement:cut and /csi-retirement:finalize and GET /csi-retirement. All requests include exact workspaceId and retirementId; the Hosted retire request also includes tenantId, workspaceId and bindingId and is authenticated by the existing primary listener. A private application store owns the fresh bounded transactions and uses the same configured DataSource, binding/session repositories and worker HTTP transport. Spring's controller and the existing private Main test composition must call this same store; no alternate test-only cut implementation qualifies it. The retire operator reads the reviewed original runtime request and current persisted retirement scope, then calls the selected Hosted route without RuntimeAccess.resolve/acquire. These names describe new APIs, not baseline commands.

Distinguish preparedCommitSha256 (SHA-256 of the unchanged existing commit-body UTF-8 bytes) from frozenRequestSha256 (SHA-256 of the persisted server envelope bytes). The envelope includes those exact body bytes as base64, their digest, independently derived original identity/pins/token hash and exact pre-cut observation bytes/hash. Do not add server facts to CommitTransactionRequest or leave them only in coordinator memory. frozen_request_bytes/sha256 store this entire envelope. Pre-cut observation binds preparedCommitSha256; after freeze returns the envelope hash, cut and finalization bind frozenRequestSha256. This avoids circular observation hashing and preserves both body and server facts exactly.

The server freezes the complete existing commit body plus independently derived original identity, writer hash, predecessor head/checkpoint/activation pins and worker candidate inventory before any terminal write. Before closing worker admission, a bounded planning transaction validates original authority, full settled prefix and the complete candidate suffix with terminal's pure proof and verified frozen resource overlay. It performs no terminal writes. Outside SQL, obtain the original pre-cut worker observation bound to retirement and this prepared request digest. A second fresh bounded transaction revalidates all current authority/membership, deadline, the exact candidate's two records/one resource and the original observation, then CAS persists FROZEN and exact request/observation bytes and hashes. RPC and filesystem work stay outside SQL. Same-semantic body with different UUID/ref/time is a conflict. A timeout preserves the original prepared request and requires observing the persisted result before repeating. Invalid suffix refuses before immutable freezing; cut still independently revalidates it before its only write.

cut is the real consumer of TerminalProof. It accepts only the saved request, validates the full active predecessor using the original decoder and validates the unique release suffix using terminal. Insert its exact resource/ref/transaction with the existing schema rules, update the head preserving its checkpoint, compute the full immutable cut from current locked membership, and atomically persist CUT and head SEALED in one Connection/commit. Combining the terminal write and cut avoids an extra durable ACTIVE-terminal interval while preserving the prior durable FROZEN request. No ordinary commit route or generic seal bypass gains terminal permission. Retain writer_id, token hash and lease fields; SEALED and CUT revoke authority.

The terminal delta's writtenAt uses the inventory's fixed UTC representation of SQL DATETIME cells. Before writing, bind the exact shared Timestamp through CAST(? AS DATETIME(6)) on the original connection and decode that result with the same UTC calendar as inventory. The same Timestamp is then bound to all five declared time cells. This accounts for JDBC's timezone conversion and SQL precision without reading current rows back to manufacture an expected delta. writtenAt is an image value, not an ordering or expiry authority. Terminal metadata retains strict value/type validation and compares canonical JSON, so equal integral values decoded as IntNode or LongNode remain equal.

The cut fixes the complete predecessor inventory and one declared terminal delta, rather than comparing later protocol outputs to pre-freeze values. Validate progress version/stage, frozen envelope, cut and receipt outputs through their explicit CAS transitions. The cut bytes never include their own bytes or hash. Completion compares head/resources/transactions against the predecessor plus the exact saved terminal delta and progress against the saved CUT authority; every other inventoried row remains stable and membership-complete in both directions. No broad field-ignore list permits undeclared changes.

Expose a separate terminal-history result only to this actual cut/finalization/retry consumer. It retains the full validated predecessor and one exact terminal suffix, enforces history/resource budgets and rejects every suffix after release. Live history, NativeHead, execution authorization, cold restore and ordinary replay remain active-only. A postcut retry reads the saved cut/sealed head before any live assertion, returns the exact existing evidence or conflicts, and never acquires, renews, appends or ACKs.

## Original Connection, lock order and writer closure

All freeze/cut/completion transactions reject ambient composition, use the original DataSource and target Connection and have a ten-second whole transaction deadline. Query timeout is bounded by remaining transaction time. Nonlocking discovery is a locator only. Candidate prefix is P → R → complete sorted slots/bindings → indexed private pin and full request/context → registration → physical holder → immutable intent/progress → head/history/resources/refs → Runtime Session/executions → publication/read/output/secondary inventory. Current membership, all field values and DB time are rechecked after waits. No RPC, independent transaction, snapshot authority or late parent acquisition belongs inside it. The order must be measured on actual MySQL RC/RR before acceptance.

Install an explicit same-Connection progress gate at the validated original prefix, never inside value-only Original.requireContinuation. Its production consumers are SessionStore renew/commit/blockRecovery/publishToolResult/native read completion; execution compareAndSet/claimDispatch/renewDispatch/requestCancel; RuntimeAccess snapshot before and after RPC; binding claim/renew/release/CAS; and owner/worker admission. READY with no intent retains current admission. DRAINING requires valid SETTLING progress for permitted original continuations and the immutable pre-seal authorization ceiling. FROZEN/CUT/DRAINED refuse all those mutations. The sole terminal write is cut's exact frozen consumer.

Binding-only control writers must discover identity first and enter P/R/original/progress before their old binding lock. Never add P after an already-held binding. Missing/untrusted/ambiguous private authority fails closed, and normal non-CSI control behavior remains supported. Keep immutable sealedBindingVersion distinct from current control record_version and progress_version. Close RuntimeAccess snapshot admission before RPC and have worker admission also latch, so a late request cannot enqueue an untracked history observation. Already admitted continuations either join before freeze or make it BLOCKED.

An admitted unfinished turn may need to read its current durable checkpoint after beginRetirement to consume a result that already returned. SETTLING therefore admits only that original current checkpoint resource, proved by the full live native prefix with a non-null original input and epoch-1 activation. Preserve the existing OPEN→RETURNED/UNKNOWN read and delivery-lease protocol, bind its authorization to the immutable sealed binding ceiling, and require its delivery expiry within the settlement deadline. Other resources, a settled turn, expired authority and FROZEN/CUT/DRAINED refuse new reads. This continuation grants neither another input nor another execution or model request.

Refuse private live Session Store access and application retirement before granting writer authority or changing journal/progress when this port is installed; preserve ordinary after-commit publication and replay behavior. The retained read-only historical credential check does not depend on this live port. Absence of the port is a deployment prerequisite, not evidence that older or in-flight broker records have disappeared. Do not qualify a scope previously exposed to that transport by merely switching the flag off.

Use a bounded explicit original-schema catalogue, not a reflected general database framework. For every table, define independent discovery predicates, sorted keys, supported values or any-row BLOCKED, the controlling producer and the empty-set insertion fence. MAX_ROWS is 4096 and MAX_BYTES is 32 MiB for the aggregate current evidence; overflow and unresolved association block. ## Atomic application completion and retry

After the original qualified receipt, completion reacquires the original current authority, exact CUT and full stable inventory. Verify the complete receipt and original worker association. On the same Connection, persist exact receipt, use a narrow Broker repository operation to CAS only that original logical Runtime Session READY→RELEASED, and CAS progress CUT→DRAINED. Each update count must be one; any failure rolls all three back. Generic Runtime Session CAS/release remains denied for CSI.

Keep immutable intent DRAINING, binding/physical holder/slot, original handle/lease and registration reserved. DRAINED only completes application obligations. Dispose only the selected Hosted owner's local handles after observing this committed completion, without another append or seal. Exact retry reads immutable cut/sealed head/receipt and original released logical Session before current/acquire/assertWritable. The deadline does not invalidate a committed result or permit a new mutation after expiry. Worker failure after cut leaves CUT/BLOCKED and retains ownership.

## Main large-result format compatibility

Native execution results are read in full up to 1 MiB, with another 16 KiB for the HTTP response envelope. An original tool outcome permits 64 KiB inline, or an explicit `managed-tool-outcome-chunks` manifest with `managed-tool-outcome-part` members reassembled into complete JSON larger than 64 KiB and no larger than 4 MiB. Existing message chunks use the same inventory owner checks; each format retains its original decoder's count, length, digest and UTF-8 checks.

Live inventory reassembles complete content after an actual table scan and feeds its typed references into the original discovery closure. Final validation permits raw parts only when covered by a successfully decoded complete manifest. Retained scans process manifests before parts; every member matches the original Tenant/Workspace/Session/scope, actual primary key and full descriptor. Missing, repeated, changed, foreign-owner, orphan and undeclared parts refuse progress. Reassembly supplies no execution, writer, installation or physical authority.
