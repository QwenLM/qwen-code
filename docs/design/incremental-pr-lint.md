# Incremental PR lint and static-check build reuse

[English](incremental-pr-lint.md) | [简体中文](incremental-pr-lint.zh-CN.md)

## Problem and scope

PR lint currently scans the entire repository. The static job also installs dependencies with a prepare hook that builds and bundles every workspace, then its bundle-closure check cleans and rebuilds the CLI dependency closure. In run 39977456043, dependency installation including lifecycle scripts took 563 seconds; this does not identify how much time belonged to downloads versus building.

This change targets file-local lint and duplicate build work. Cross-package dependency checks, generated-output checks, runtime dependency audit, and helper tests remain enabled. It does not change runner concurrency or required-check policy.

## Design

Only pull requests set `LINT_BASE_SHA`. A bounded fetch obtains 100 commits of base/head history and then deepens in capped steps while ancestry is missing or a shallow boundary remains above the unique merge base. Ambiguous merge bases stop deepening immediately because more history cannot make them unique. Each fallback from this loop announces its reason (cap reached, deepen fetch aborted, or ambiguous merge base), the number of successfully completed deepens and the base-history depth reached. A fixed window expires in about a day at this repository's merge rate, which silently sent longer-lived PRs through the full scan; it runs after the steps that refetch shallow history for the base ref or the merge base, because a depth-1 fetch of the base tip grafts the very commit the scope names, after which `merge-base` fails closed and each such PR pays for a full scan without saying so — and a history fallback is now announced as a workflow warning plus a step-summary line, unlike the routine configuration fallback. That fetch asks for no blobs (`--filter=blob:none`) because the scope reads only commits and trees, and a plain fetch can fail resolving deltas against blobs an earlier blobless step left out of the checkout. The lint scope helper uses a proven merge base and NUL-delimited Git file lists. Unavailable or ambiguous history falls back to full lint. Deleted paths participate in configuration invalidation but are not passed to file linters. Renamed files are checked at their new paths. Selection is per file, which is sound only while every enabled import rule evaluates one file at a time (`import/no-internal-modules`, `import/no-relative-packages`, `import/no-extraneous-dependencies`, `no-restricted-imports`); enabling a cross-file graph rule such as `import/no-cycle` would require revisiting this scoping.

ESLint, Prettier and YAML checks select changed complete files. Prettier runs from the nearest ancestor that carries a Prettier config or ignore file, so a diff without nested configuration costs one spawn instead of one per directory (spawn cost is bounded but real: a measured 0.24 s cold start against a 37 s whole-repo run breaks even near 154 touched directories, while recent diffs stay far below that — median 3, maximum 39 in #15524 — so the common saving is about half a second and wide sweeps stop paying a spawn per directory). Shell-related changes invoke the existing full ShellCheck lane to preserve sourced-script coverage; unrelated changes skip it. Its legacy output pipeline masks checker failures, so strict ShellCheck failure enforcement requires separate baseline cleanup. Workflow/action changes retain a full actionlint scan because reusable workflow contracts cross files. Changes to lint rules, configuration, ignore files, dependencies or the lint implementation restore full checking. Non-PR events retain full checking. An empty relevant file set is a documented skip; a failed diff is never treated as an empty successful check.

The lint install sets `QWEN_SKIP_PREPARE=1` and `QWEN_SKIP_NOTICE_GENERATION=1` only for that step. Dependency lifecycle scripts and patch-package remain active. The existing clean CLI build/bundle closure check runs after file lint and before i18n, schema and notice checks. Its outputs support later checks. The test job retains normal prepare behavior. Both primary hosted jobs reuse the existing pnpm store cache action; self-hosted stores remain on their existing paths.

## Validation and acceptance

Exercise real temporary Git repositories for ordinary changes, renames, deletions, unusual filenames, configuration invalidation and incomplete history. Check command failures propagate. Run the actual linters and static pipeline on an isolated checkout installed without prepare, so missing build prerequisites cannot hide behind old outputs. Verify generated schemas and notices remain unchanged and run the affected workflow/script suites.

Compare timings on the same runner class after deployment. Local timings and the 563-second historical install are not a promise of CI savings. Full repository checks on main remain the backstop for cross-file effects outside the incremental selection.
