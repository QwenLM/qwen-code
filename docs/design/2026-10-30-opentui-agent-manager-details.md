# OpenTUI agent manager read-only details

## Status and problem

The revised global Ink baseline actually passed with hot/cold details and unchanged complete agent-store maps. The unchanged OpenTUI manager then failed at `hot-created-agent-actions`: after Enter its actual frame still showed the passive Subagents name/description list. That original failure is retained. The native read-only implementation is now verified locally with the manual wizard as uncommitted feature changes on the current dependency foundation. After the PascalCase file-name correction, six whole CLI test files passed 111 tests, and normal build, typecheck, lint and bundle all passed. Node+Ink, Bun+Ink and strict Bun+OpenTUI each passed the four selected public cases: two Permissions cases, Source acquisition, and manual creation with hot/cold manager details. Across the three profiles this is 12 executions of four unique cases, with 18 observed natural session exits and zero model requests. This is pre-commit local candidate evidence, not merged-main or installation acceptance.

The public `/agents manage` command opens `subagent_list`. Ink lets the user select an agent, choose View Agent, read its configuration, and return through the action and list screens. Before this change OpenTUI reduced the manager result to name/description bullets and only handled Escape. The earlier manual-creation E2E deliberately checked details on Ink and only list descriptions on OpenTUI; its success did not establish detail parity. The revised case now requires details on both renderers.

## Proposed behavior

Preserve the full public `SubagentConfig` returned by `config.getSubagentManager().listSubagents({ force: true })`. Keep the manager's project/user/builtin/extension precedence rather than implement another lookup or load by a displayed name. Show a selectable agent list, a read-only action screen with View Agent and Back, and a scrollable detail screen. Do not advertise unimplemented Edit or Delete actions.

Details show the same existing values as Ink: File Path, Tools, optional Model and Color, Description, and System Prompt. Use existing translation keys, terminal-safe rendering, and shared native selection/scroll primitives. Display labels must explicitly consume item labels; selection values remain identities. A missing tools field displays `*`, matching Ink. Preserve actual empty-array behavior rather than invent serializer semantics.

Enter selects only within the active screen. Escape returns details → actions → list → composer, retaining the selected agent. Each screen owns its keys; stale callbacks must not act after a transition or unmount. Loading and error states must not manufacture an empty successful list. This is read-only: no save, editor launch, update, delete, model request, or reload mutation.

## Files and boundaries

The production change is CLI-only: one extracted manager component and its existing re-export. Collocated behavior tests use the real shared selection component, and the focused E2E delta preserves the original public setup. The panel budgets the title and the exact rendered footer with wrappedRows at the actual content width, plus five rows for border, padding and the body margin. When the chrome cannot fit, the existing compact mode hides the title/footer and keeps the body scrollable. Mount/config wiring already exists. No Core changes, edit/delete/generation work, manager-wide refactor, default switch, or Ink removal.

## Narrow-terminal regression

Official CI on the published feature candidate failed the unchanged native layout check: at 11 columns and a 12-row region the agent list frame measured 26 rows. The unchanged local native script reproduced the same result. Earlier normal-width public passes remain valid at their scope and do not cover this geometry. The new navigation footer wrapped across many rows but the old chrome budget charged only one. The minimal correction derives the same footer for rendering and measurement, preserving its text, read-only navigation, compact fallback and body cap. Three focused component cases cover narrow list, action and detail pages; the combined candidate passed all 114 tests across six whole component files, normal build, typecheck and lint. Its final native run passed all 132 short/narrow cases, scroll/resize checks and the real session-picker resize checks. Manager actions/detail have component coverage, not separate native geometry observations. New combined-candidate public runtime and installed acceptance remain separate. Original CI and local failures are retained.

The first native run after the footer correction passed all 132 short/narrow frame cases, then timed out at the old unlabelled generic readiness predicate requiring physical scrollHeight ≥ 40; that run did not establish which dialog failed first. The new selectable manager mounts only its visible item window, unlike the former all-rows bullet body, so that predicate and direct physical scrollTo no longer test its contract. The existing native script now keeps the Skills/Diff physical 40-row checks, but uses 39 real Arrow Down inputs to reach and visibly select the final manager item, then requires that selection to remain visible across every original resize. Readiness failures include the dialog, width, scrollHeight and frame without increasing the 100-pass bound. The owned Git diff fixture is checked for its actual added rows and end marker once. The revised script subsequently passed, including a final run on the combined current-main source tree. Original failures and React act warnings remain recorded; this narrow native proof does not establish every full-application viewport or final merged-main acceptance.
