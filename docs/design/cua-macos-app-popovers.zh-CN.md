# macOS App 弹板控件

[English](cua-macos-app-popovers.md) | [简体中文](cua-macos-app-popovers.zh-CN.md)

## 状态与问题

已验证的缺陷修复，2026-09-24。Freeform 的绘图颜色按钮出现在 App 无障碍文本中，但没有 AX 动作或可写值，因此没有动作 token，`app.click(id)` 失败。点击它的屏幕位置会打开另一个无标题的 270×300 调色板窗口。App 门面继续观察主画板，导致调色板不可见。调色板不在 AX 窗口列表中，常规后台指针安全检查会拒绝它；前台投递则等待该窗口无法报告的 AX 焦点。

## 范围与设计

在 macOS App 普通窗口观察中，即使有边界框、已启用的 `AXButton` 未声明 AX 动作，也为它分配动作索引。现有 App 点击执行器随后使用按钮边界框执行后台指针点击，让临时弹板保留到下一次观察。旧版和打开菜单的 AX 遍历保持原样。

在 macOS 上，如果同一进程有一个可见、无标题、零层级的小窗口，位于原生 App 目标窗口之上、包含在其范围内且尺寸更小，App 门面将其中最靠前的窗口视为当前界面。层叠顺序使用仅包含屏幕上窗口的列表判断：macOS 的全量窗口列表在包含屏幕外窗口时可能给出反转的 `z_index`。全量列表仍用于解析原生目标，包括最小化窗口。切换界面会使旧 ID 和截图坐标失效。App 对这个辅助窗口的点击采用后台指针投递。macOS 执行器只在进程级变更锁内再次验证当前 WindowServer 所有权、位置尺寸和层叠顺序后才接受这一特例；其它 AX 无法解析的窗口仍按原规则拒绝。指针事件仍指定精确窗口 ID。动作记录报告实际使用的投递模式。其它平台继续使用各自的原生 App 目标窗口。

## 约束与风险

调色板不暴露 AX 元素，因此选色使用其截图坐标。其它满足相同几何条件且位于最前方的无标题工具窗口也可能被选中；当它是当前可见 App 界面时，这符合预期，但自动选择后仍须验证下一状态。特殊输入路径绝不能接受其它 PID、隐藏或不在当前 Space 的窗口、被遮挡的同级窗口或失效窗口 ID。

## 验证与验收

运行有针对性的 App 与 macOS 原生测试、SDK 和仓库构建、仓库类型检查，然后在已授权的 ChatGPT 进程中完成真实 Freeform 操作：打开绘图工具、按 ID 点击颜色按钮、将调色板观察为当前 App 窗口、按新截图坐标点击红色格，并验证主窗颜色值从黑色改变。确认在刻意绘图之前，画板现有绘图数量不变。最后一次修改后完整检查两遍 diff。真实 Freeform 测试中，颜色值从 `black` 变为 `vermilion`；原有 43 条绘图没有变化。SDK 专用的 computer-use 类型检查被已有生成声明中缺少的 `UniffiGcObject` 和 `UniffiHandle` 导入挡住；对目标测试使用 `skipLibCheck` 后通过。
