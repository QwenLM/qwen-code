# Web Shell 图片 URL 粘贴

[English](web-shell-image-url-paste.md) | [简体中文](web-shell-image-url-paste.zh-CN.md)

## 问题

Issue [#16088](https://github.com/QwenLM/qwen-code/issues/16088) 描述了两条静默的
图片粘贴路径：非空纯文本绕过图片摄取，以及剪贴板声明 `Files` 却不提供文件对象时
不被接管。[#11334](https://github.com/QwenLM/qwen-code/pull/11334) 为支持可编辑的
PowerPoint 内容引入了文字优先，因此让所有混合剪贴板都改为图片优先会造成回归。

## 决策

仅当粘贴目标是编辑器、输入框和附件均启用、未处于 shell 模式、草稿去掉前导空白后
不以 `/` 或 `!` 开头，且剪贴板恰好包含
一个图片文件候选、没有其他文件候选或拒绝项、纯文本去除首尾空白后为单个
HTTP(S) URL 时优先图片。沿用现有附件队列并消费事件。其他文字和文件混合的
粘贴继续优先文字，包括多行 PPT 文字。桌面端、触屏折叠编辑器和触屏展开编辑器
使用相同规则。输入区域内其他文本控件保留各自的粘贴行为。

粘贴和拖放均用现有文件载荷判定函数确定事件归属。不含纯文本的粘贴声明了文件却没有候选或
拒绝项时，记录一个不可用项，由现有摄取提示说明文件被跳过。普通文字和仅含
HTML 的粘贴不会新增警告。拖放提示保持原有行为。

## 约束和风险

URL 规则是启发式判断：从办公文档复制的单个 URL 如果同时带有一张位图，也会
优先图片。仅凭剪贴板形态无法可靠识别用户意图。带说明文字、非 HTTP(S) URI、
多张图片或图片不可用时继续优先文字。不引入剪贴板权限、异步剪贴板 API、daemon
改动或新依赖。

## 验证和验收

- URL 加一张图片会添加图片附件，不把 URL 插入输入框。
- PPT 文字加位图仍为可编辑文字，不添加图片附件。
- 纯图片粘贴正常；没有图片的普通 URL 保留为文字。
- 附件禁用、shell 模式、命令草稿和其他文本控件保留文字行为，包括附带位图的 URL 参数。
- 已声明但不可用的文件粘贴触发现有警告一次。
- 工具函数及桌面、触屏 DOM 回归覆盖以上决策。浏览器 E2E 使用合成剪贴板事件和
  模拟 daemon，不代表已验证真实 Linux、浏览器或办公软件的系统剪贴板格式。
- 运行全量构建、bundle、仓库类型检查和相关测试。
