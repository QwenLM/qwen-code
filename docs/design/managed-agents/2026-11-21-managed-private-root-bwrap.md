# Private-root Bubblewrap execution for Managed Agent

[English](2026-11-21-managed-private-root-bwrap.md) | [简体中文](2026-11-21-managed-private-root-bwrap.zh-CN.md)

## Problem and current state

[#15081](https://github.com/QwenLM/qwen-code/issues/15081) asks for Workspace filesystem and process confinement, understandable denials and operator opt-in. The [#12380](https://github.com/QwenLM/qwen-code/issues/12380) tracker assigns Workspace side effects and uncertain-outcome handling to the selected Runtime and keeps untrusted deployment behind separate acceptance. [#15163](https://github.com/QwenLM/qwen-code/pull/15163) selects an opt-in Linux local-process profile with a private filesystem view and Broker-visible stop evidence.

At `0cfbdac07b`, Core's existing bwrap executor mounts `--ro-bind / /`. It restricts writes and still permits broad reads outside the Workspace where host permissions allow them, subject to its specific masks. Current Hosted file and foreground Shell paths use worker permissions, and serve rejects the public execution sandbox settings. The existing Linux cgroup stop receipt in the local provisioner is specific to the Managed extension profile and obtains proof from the live Runtime. The open [#14667](https://github.com/QwenLM/qwen-code/issues/14667) tracks durable containment and Broker verification after worker death.

## Delivery and prerequisites

This change delivers an internal private-root executor and a real Linux check that drives it through the compiled Core relay. Its caller in this change is the acceptance fixture. There is no settings or wire change, and CLI, ACP and Hosted keep their existing paths. The internal contract lets the project qualify the filesystem and launch boundary independently while the Runtime and Broker work proceeds.

The deployment controls the root image, bwrap binary, interpreter, relay, state directory and Workspace mount source. Provision source paths whose entire resolution chains remain stable, including their parents, and protect the pre-staged image from modification throughout the run. The host processes sharing the worker UID are trusted because they can access the host control and receipt files. Build the image independently of host credentials and other Workspace data. Throughout execution both mount trees must exclude nested mounts, devices, pathname sockets connected to outside services and inode aliases to files outside the source. Workspace import must copy outside files to independent inodes. The deployment must preserve these constraints for every host-side writer that can change the Workspace. The executor checks launch inputs. Provisioning and enforcing mount-source invariants remain the caller's responsibility.

## Execution contract

Add an internal `executePrivateRootBwrap` in Core next to the legacy bwrap adapter. Accept explicit absolute rootfs, Workspace, installation and state paths and the Workspace access mode. Reuse the packaged bwrap relay and the existing path, scratch, receipt and cleanup checks. Reject non-Linux and root workers, a relative or non-directory rootfs, and absent, symlinked or nonempty image mount points. Check canonical paths for equality and overlap in both parent directions. Reject overlap among the Workspace and the image, installation, state or launcher directories in both access modes. Apply the same check between the image and the protected host directories. Use the absolute, canonical non-setuid and non-setgid bwrap launcher owned by deployment.

The only mounts are the read-only image at `/`, the selected Workspace at `/workspace` in its admitted mode, a private tmpfs at `/tmp` and bwrap's minimal `/dev`. The image supplies empty directories for the three mount points. There is no procfs or host-home, installation or state mount. Use an explicit private user namespace with nested user namespaces disabled, separate PID, network, IPC and UTS namespaces, no capabilities, `--new-session` and `--die-with-parent`.

Launch a literal, absolute executable in the private filesystem view with its argument vector after `--`, with cwd fixed at `/workspace`. The adapter accepts piped stdin bytes. Descriptors 0–2 carry only controlled stdio. The dedicated bwrap status descriptor is closed before payload exec, and stdout and stderr are never treated as status. The adapter has no PTY, caller environment or Shell background-promotion inputs. Launch the relay from its host control directory with an adapter-owned environment. Use `--clearenv` before setting private `PATH`, `LANG`, `HOME`, `PWD` and temporary-directory variables, including clearing the shared relay's host scratch paths. Map all abort reasons to ordinary cancellation.

Invalid launch inputs reject before the relay starts. Namespace setup and image exec can fail after launch and return an unconfirmed result. All failures have no host fallback. A confirmed nonzero exit is a confirmed payload outcome. Preserve interrupted and unknown outcomes from the receipt protocol. Missing, unreadable or mismatched receipts cannot authorize retry. An empty process unit proves stopping only. Replay requires durable selected-Runtime execution state and the existing reconciliation policy, including positive pre-exec evidence for a decision that depends on no payload having run.

## Remaining Hosted delivery

1. Require #14667's durable cgroup identity and Broker-visible empty-proof contract before admitting the first payload. Bind the unit to the selected Runtime instance and epoch and the binding generation. On close, fence new execution on that Runtime before the Broker checks the original unit. Keep the holder if the unit is missing, replaced, unreadable or populated.
2. Admit a deployment-owned, disabled-by-default profile for Linux local-process. Bind qualification and the immutable policy to the selected Runtime and Workspace generation before payload execution. Route every admitted operation through equivalent confinement and derive its read/write mode from frozen admission. Include `Config.includeDirectories`, file history and undo, and tool preparation, checkpoint and recovery paths that touch disk in the admission and routing inventory. Refuse unsupported Hooks, MCP, extensions, LSP and other executable routes at admission, including their initialization paths. Map admitted Workspace-relative paths into the private view before running file workers and Shell. Select the trusted file worker and its interpreter from the immutable image. Qualify the real runtime image and its toolchain for each supported deployment.
3. Project typed `confinement_unavailable`, `confinement_denied` and `confinement_stop_unconfirmed` through the Broker and tool results. Give operators enough information to fix the deployment or move declared inputs into the Workspace without exposing host paths or treating arbitrary command exit codes as policy denials. Maintain the existing trusted deployment behavior when the profile is disabled.

## Acceptance

Run the focused Core tests and a strict Linux acceptance fixture against the built adapter and relay, as an unprivileged worker on Linux with non-setuid bwrap and static BusyBox. Prove both Workspace directions with readable positive controls and unobservable sibling and host markers, including symlinks. Check read-only image and Workspace behavior, private temporary files, fixed cwd and environment, piped input, and a confirmed nonzero exit. Reject direct and symlink-aliased source overlap for both Workspace access modes. Use a test-owned outer process that remains live before and after the sandbox check, a signal-zero probe and a listener first reached with the same client. Require a confirmed success for the payload's assertions and no inner connection at the outer listener. Prove a parent environment sentinel is absent, the payload cannot write the status descriptor and nested user namespace creation fails with a working outer positive control. Observe a payload-owned start marker before sending a background-promotion abort. Bound both the startup and settlement waits. Require an interrupted receipt and a canceled result with no promotion. This is local regression evidence for the cancellation path. Verify that a missing launcher rejects and that a missing image executable or unavailable namespace cannot produce either a confirmed exit or a payload marker. Use a working payload in the qualified environment and a host executable that can write the marker as positive controls. Run the namespace refusal separately and require the kernel or bwrap setup diagnostic. Recheck the public serve sandbox refusal with the same isolated settings before and after the change. Record distribution, kernel, architecture and bwrap version. Missing prerequisites cannot pass the fixture. The result qualifies the tested executor configuration. It does not qualify a Hosted deployment, dynamic toolchains, or Broker stop and recovery.
