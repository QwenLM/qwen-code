# Managed Agents Multi-Agent Public API

[English](2026-11-23-managed-multi-agent-public-api.md) | [简体中文](2026-11-23-managed-multi-agent-public-api.zh-CN.md)

## Status and goals

This is the design draft for [#13785](https://github.com/QwenLM/qwen-code/issues/13785), for maintainer discussion. A client should be able to identify which agent produced an output, reconstruct the task tree and team roster after reconnecting, and act on a specific task or approval within its permissions. The model and existing runtime continue to orchestrate execution and create teams. The public API projects execution facts and accepts authorized interventions.

This design defines the shared contract, dependencies and release criteria. The [Legacy Agent Team host gate](2026-11-21-agent-team-host-gate.zh-CN.md) pushed to the fork is the first M4 delivery slice and has its own detailed design and implementation.

## Current foundation

- **Managed public contract.** On upstream `main` at `1158b9bd5da2`, the OpenAPI version is `1.125.0`. It provides the `child_agents` capability, `PublicTask.child_session_id`, task listing, detail, events and cancellation, and Action responses. Events, items, task events and Action sources still lack a typed `agent`. Tasks lack `parent_task_id` and `depth`. Team and member queries, `multi_agent` and the task input route remain undeclared. ## Shared contract

- **Identity and navigation.** Project typed `agent` identity from committed runtime records. Use `id` to correlate an execution, `parent_id` for ownership, and `kind` and `depth` for type and level. The projector derives `path` for display. Concurrent namesakes, reloads and replays must preserve correct execution attribution. Keep `PublicTask.id` as the task address, `child_session_id` as the navigation link, and `PublicSession.agent_id` as a reference to the agent definition. M1a and M2 settle the `agent.id` namespace, identity across Session continuations, and historical semantics when ownership changes. The detailed M1 design can add optional `phase` when it has a reliable source.
- **Reads and replay.** Committed records determine terminal task state, current ownership, the team roster and durable message provenance. A cold Session supports queries, recovery and replay. Historical data with insufficient evidence omits the new attribution and preserves existing events and cursors. Model text, role labels and notification bodies cannot set contract identity.
- **Capabilities and authorization.** Tool registration depends on actual host support. Public capabilities describe the API available for the current Session. Route authorization still governs whether a caller may read or intervene. Actions retain D6 request IDs, ownership and response rules. State queries follow the existing Session visibility boundary.

## End-to-end acceptance

Launch two same-named child agents in one Managed Session. Let one wait for an approval and the other finish. Disconnect and reconnect the client, replay from the existing cursor, query the task tree, then confirm execution IDs, child Session links, approval ownership and terminal state. Use the available capabilities to respond, send input or cancel the targeted child and check that the other branch is unaffected. With team support, add a member departure and query the roster without waking the model. Check that historical references still resolve to the right member. Verify the contract, projection and actual host wiring at their respective layers.
