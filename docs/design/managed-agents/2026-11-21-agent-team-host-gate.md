# Gate Legacy Agent Team tools on host support

[English](2026-11-21-agent-team-host-gate.md) | [简体中文](2026-11-21-agent-team-host-gate.zh-CN.md)

## Problem

[#13785 M4](https://github.com/QwenLM/qwen-code/issues/13785) asks hosts to declare what they can handle before offering Agent Team tools. On main at `b62d4ab7`, `Config.isAgentTeamEnabled()` checks the shell execution sandbox, then the environment or experimental setting. ACP builds the same legacy registry, but main does not attach the Legacy team's leader message callback or approval listener there. The manager leaves reports unread and its inbox poll skips the terminal notification. A teammate tool approval in that host can wait until the stall timeout. [#14855](https://github.com/QwenLM/qwen-code/pull/14855) characterizes the report and terminal paths by constructing the manager below registration.

The Ink TUI attaches a leader message callback and uses the interactive teammate permission path. The noninteractive CLI attaches a leader message callback and handles approvals through stream-json control or its existing noninteractive fallback. Both paths intentionally support Legacy Agent Team. The Hosted Harness declares its own team tools through `teamsAdmitted()` and uses durable records and Session messages.

## Host declaration and registration

Add an internal `agentTeamHostSupported?: true` option to `ConfigInitializeOptions`. Capture a strict true from the first initialize call, after the abort check and before asynchronous initialization starts. Store the result on Config for the lifetime of this registry. A true value is the host's commitment to receive team reports and handle teammate approval requests, including the explicit noninteractive fallback. Application code declares the capability. Settings and the environment continue to express the existing user opt-in.

| Config initializer                                                                | Declaration                                                                                                                                                                                             |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ink `AppContainer` mount                                                          | True. Ink wires the leader callback and interactive permissions.                                                                                                                                        |
| Text/JSON headless in `llm.tsx` and stream-json `Session.ensureConfigInitialized` | True. Both use the noninteractive leader callback and corresponding approval handling. Stream-json preserves existing initialization options, including the SDK MCP callback, when it declares support. |
| OpenTUI, ACP bootstrap and individual ACP Sessions, other Config consumers        | Omitted. An ACP bridge session uses the same per-Session Config path.                                                                                                                                   |
| Hosted Harness                                                                    | Uses its separate `teamsAdmitted()` path.                                                                                                                                                               |

An OpenTUI startup failure before Config initialization falls back to Ink's normal declaration. Once OpenTUI has started initializing the shared Config, the first initializer owns its registry and declaration. A late fallback follows the existing single-initialization rules and keeps the first capability declaration. Configs derived in the same host inherit the declaration through their prototype. Ordinary environment variables, settings, and client metadata alone cannot declare this capability.

Add the host check to `Config.isAgentTeamEnabled()` before the existing sandbox and opt-in behavior can admit the tools. The existing registration block and `AgentTool` schema and description already use this predicate. Team tools and the team-only `name`, `plan_mode_required` and `read_only` arguments follow the same admission decision. Ordinary Agent, list, stop and follow-up tools keep their existing declarations. Team execution continues to require a live TeamManager. Hosted declaration and durable execution continue to use their existing admission path.

## Integration with #15658

At [`c752f6b1`](https://github.com/QwenLM/qwen-code/pull/15658/files), ACP Session installs a sink and approval routing when `isAgentTeamEnabled()` is true. The sink handles report delivery and manager replacement. Its approval relay uses session-scoped ACP requests and bridge retirement notifications. With this gate in place, the rebased PR must supply positive host support in the first ACP Session Config initialization call. Use the shared `newSessionConfig()` path for eligible live Sessions so creation, load, and resume apply the same rule. Follow the approval ownership checks in #15658. The handshake describes support and leaves permission authorization to those checks.

Use the existing `initialize.clientCapabilities._meta` negotiation when enabling ACP. A future change can use an explicit boolean `qwen.agentTeam`, advertised by a bridge or client that can deliver team reports and present session-scoped teammate approvals to its consumers. The future ACP producer should combine a strict `true` client declaration with available sink and permission wiring. Older and generic clients remain on the ordinary tool set. The current gate introduces only the internal initialization option. Wire negotiation and ACP opt-in will ship with the wiring they depend on. The public `multi_agent` capability, task input route, and team projection remain separate work.

Force Agent and the seven team tools visible in the test fixture to avoid mistaking tool deferral for a gate. Run the Ink teammate-report test with the renderer pinned to Ink. Verify stream-json direct and SDK startup forward the capability and preserve the SDK MCP callback; exercise the existing teammate-approval tests. Use a real Bun OpenTUI run for any claim of renderer-level OpenTUI coverage. Verify supported entry points pass the option and unsupported OpenTUI and ACP paths omit it. A second initialize call joining an unsupported host’s existing initialization cannot add the capability.
