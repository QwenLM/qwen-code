# Durable local Runtime cgroup identity and stop proof

[English](2026-11-21-managed-local-cgroup-stop-proof.md) | [简体中文](2026-11-21-managed-local-cgroup-stop-proof.zh-CN.md)

## Problem and scope

[#14667](https://github.com/QwenLM/qwen-code/issues/14667) requires process-tree containment and a stop proof that survives the loss of a Hosted Runtime worker. The stdio MCP supervisor reaps a process group. A descendant that creates a new session leaves that group. The durable local provisioner checks the original worker PID and start identity, but its ordinary stopped-worker receipt does not attest descendant exit. The extension-only stop protocol relies on a live worker and a separate cgroup hierarchy.

This stage of [#15081](https://github.com/QwenLM/qwen-code/issues/15081) adds stop evidence for session-exclusive, durable Linux `local-process` Managed Workspace bindings. It covers the worker and inherited descendants, including stdio MCP and descendants in a different process group. The output is a Broker-owned proof usable by the existing drain and recovery paths. Private filesystem activation, default promotion, shared Runtime bindings, subprocesses launched by external services, the MCP supervisor's memory cost and Windows support have separate scope.

## Activation and trust

An operator sets `qwen.managed-agent.runtime-broker.provider-options.cgroup-root` to a dedicated, canonical delegated directory on cgroup v2. The local provider accepts this option only in durable Linux mode. Newly created Managed bindings require storage, `WorkspaceExecutionProfile.admitsIsolationClass` and `admitsCapabilityDigest`, excluding the Managed extension execution profile. Non-Managed workers retain the existing path. Refuse unsupported Managed placements before allocating or launching a worker. Existing version-2 registrations retain their recorded profile. A version-3 binding keeps its original group even if the setting changes.

Broker and worker are trusted service processes. The deployment controls the state directory, cgroup hierarchy and mount namespace. It must prevent tools, same-UID untrusted host processes and competing managers from moving Runtime processes outside their assigned unit, importing other processes into it, or modifying recovery records. Keep the hierarchy path and parents stable. Only the Broker may create or remove its units under the resource lock. Operators keep other mounts off these paths. Strip `QWEN_MANAGED_HOOK_CGROUP_ROOT` from version-3 startup. Foreground tools and stdio MCP inherit the unit. Command Hooks, background Shell and Monitor operations that need their own delegated supervisor use their existing unsupported-isolation refusals in this profile. A future untrusted Hosted profile must isolate this cgroup control plane from payloads.

## Resource identity and launch ordering

The existing provision request lock serializes allocation, launch, recovery and stop. On a fresh eligible intent, create a leaf beneath the delegated root with a name derived from the provision request digest. Refuse an existing directory at that name. Check the cgroup v2 type, domain mode, readable `cgroup.procs` and `cgroup.events`, and writable `cgroup.procs` and `cgroup.kill`.

Use a version-3 local resource handle. Keep the existing host, boot, PID/time namespace and request identity, which binds the provision request, Runtime instance, lease epoch and Workspace generation. Add the canonical root, cgroup namespace and kernel filesystem object identities for both root and leaf. Store the same handle in the fsynced local registration before returning it for Broker persistence. A retry reuses the recorded handle. The new local registration encoding is version 2 and requires a version-3 handle. Continue using version-1 registration encoding for version-2 handles. Reject mixed encodings. A directory left before registration sync is an orphan for operator inspection. Do not adopt it by name. Missing or conflicting state keeps the original binding fenced.

The provisioner records `LAUNCHING`, validates the exact unit, then starts a fixed local shell trampoline with literal argv. It joins its own PID to the unit and waits on the Broker's stdin pipe for a launch line. Under the same resource lock the Broker reopens the original identity, observes that exact live PID inside it, persists `REGISTERED`, then sends the launch line followed by the existing boot envelope on stdin. The trampoline execs the configured worker only after that line. EOF, a failed migration or membership mismatch never authorizes that exec. A crash leaving `LAUNCHING` keeps recovery blocked because an unregistered trampoline could still be entering the unit. Ready adoption rechecks the group and live worker membership. No new worker launches for a registered or retired identity.

## Stop and recovery

The existing Broker drain fences new execution and reserves the binding before calling the provider. Whole-binding terminal drains for version 3, including resource drain and storage retirement, use the existing proof-first branch for any member still held when the Broker drains the binding. They require settled work and persist the stop receipt before Session or member release. The stopped-only route still requires matching worker absence when it has no receipt. Before kernel I/O, revalidate the live drain claim and any lifecycle authority. An expired claim cannot commit a receipt or clear a member. A late stop may leave a reusable local stop fact. For version 3, the provider holds the original registration lock and reopens the exact recorded unit. Use descriptor-bound directory identities and relative no-follow opens. Open the kill file for write without creation or truncation, so a same-name replacement cannot receive a kill or supply evidence. After checking the recorded identities, write `1` to `cgroup.kill` when the unit is populated and wait for a bounded period for the kernel's recursive `populated 0` result in `cgroup.events`. Confirm that the original worker has exited. A successful write or a missing PID alone cannot establish stop. An unreadable, replaced, missing or nonempty group before proof leaves the storage holder fenced and reports stop unconfirmed. Observation can establish journal loss separately. If the worker is gone and the original group is already empty, observation may persist the stop fact and return both evidence records without sending signals. A populated or unverifiable group supplies no writer-stop evidence.

Persist `RETIRED` under the registration lock only after verified emptiness and worker exit, or existing trusted whole-host reboot evidence. For version 3 this state is durable original stop evidence. After persisting it, remove the verified empty leaf when possible. A retry after removal uses the saved proof. On a verified trusted reboot do not open or touch a same-name group in the new boot. Without saved proof, maintenance attestation on the same boot checks the same original unit and requires it already empty. Observe, adopt and invalid ready-envelope cleanup never write version-3 `RETIRED` without verified evidence. Reopened retired state can supply stop evidence for the existing LOST reconciliation rules. An already LOST binding keeps that recovery path, including its execution settlement rules. With a populated group, isolated operator recovery must stop the original unit before attestation. A RELEASED version-3 binding reached through verified LOST recovery can satisfy later resource-drain retries with its exact stop and loss evidence. Maintenance uses the stored handle even if the current option is absent.

Use the existing Broker receipt and generation checks, durable receipt persistence and fenced Session/member release transaction. For version 3 the retired transport tail verifies that no member remains. Earlier Harness live-detach requests, ordinary turn handback and parking retain their trusted live-owner rules. Their successful acknowledgements are independent of this worker-retirement proof. The receipt carries the exact durable handle for the provision request. If SQL has no handle and the worker could never have started, use the original locked local intent. The launch and stop phases preserve the public API and TypeScript boot envelope. The canonical V1 catalog includes local version-3 bindings in its indexed recovery candidates. Initialize a fresh development catalog under the existing V1 policy. Kernel emptiness proves stopping. Journal loss, uncertain tool results and replay retain their existing gates.

## Acceptance

Exercise the real Linux provisioner and Broker drain with a dedicated test cgroup. Verify that the worker and a test-owned descendant that creates a separate session are enrolled before work, then forcibly stop the worker and positively observe its descendant and populated unit. Reopen the original registration in a fresh provisioner. Verify that PID absence supplies no stop proof, that a different live cgroup bind-mounted over the original unit produces no receipt or release and neither cgroup is killed, and that the original cgroup is killed and proven empty before recording the receipt and releasing the original holder. Verify a live terminal drain reaches the same proof gate before handback, idempotent retry after the unit is removed, a protected sibling process that remains alive, real join refusal and gate EOF before worker side effects, and legacy durable registration compatibility. Use the real Linux provisioner, Broker and Workspace transport. Check the original Session's execution storage key and the physical member count in an isolated MySQL catalog. Exercise the existing claim-fencing regression for delayed stop results. Record any environment limitations.
