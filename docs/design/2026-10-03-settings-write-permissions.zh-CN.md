# 设置替换时保留文件权限

[English](2026-10-03-settings-write-permissions.md) | [简体中文](2026-10-03-settings-write-permissions.zh-CN.md)

## 问题

替换已有设置文件时，新 inode 使用默认权限。在 umask 022 下，普通启动迁移或设置保存会将私有的 0600 或 0640 文件变成 0644。私有暂存目录保护中间字节，但若父目录允许访问，最终文件可能被更多本地用户读取。此问题早于 #13119 的原子保存修复。

## 决策与范围

暂存前读取已有普通文件的普通 POSIX 权限位（0777）。用不跟随链接的普通文件检查排除符号链接和其他文件类型的权限继承，同时保留跟随链接的目录检查，继续拒绝目录及指向目录的链接。用读取的权限创建暂存文件，并在写入后、备份与发布前设置精确 mode。仅指定创建权限并不足够：umask 077 会移除已有 0640 文件的组读权限。若 chmod 返回 ENOSYS、ENOTSUP 或 EPERM，仅在暂存文件报告的普通权限位不授予超出已读取 mode 的权限时发布。这允许在支持创建和替换、却拒绝 chmod 的 CIFS/SMB 挂载上保存，同时即使操作不受支持也拒绝发布更宽的暂存权限。其他设置 mode 失败仍通过现有清理路径中止，保留已提交目标。精确保留 POSIX mode 需要文件系统支持。保持单次替换 rename、私有备份、失败恢复和交错 writer 的行为。

新文件及在符号链接位置发布的文件保留现有策略：默认 0666 与调用者 umask 共同决定权限。若目标在不跟随链接的检查前消失，则按新文件发布，使用这些默认权限。替换仍替换链接本身，不修改其引用目标。不增加 mode 选项，不修改设置 schema。共享 writer 的调用方包括 JSONC 创建/更新（启动迁移和普通保存）、事务快照恢复，以及异步包装。无需改变沙箱授权。

## 约束

权限保留是对称的：已经具有组写或其他用户写权限的普通设置文件会以相同权限重新发布；此前写入器隐式收窄到 0666 & ~umask 的行为不再发生。

保留普通权限位，不携带 setuid、setgid 或 sticky 位。替换仍创建归属于 writer 的新 inode；owner/group 身份、单文件 ACL、扩展属性和 Windows ACL 的保留不在本次范围内。Node 在 Windows 上的 chmod 行为有限，POSIX mode 不代表 Windows 访问控制保证。检查与发布之间的外部并发权限修改及文件替换仍不属于既有的最后一次发布生效契约。本次不增加断电持久性保证。

## 验证

使用隔离 User/Workspace 文件和假 token，通过离线启动迁移复现并复验。原生 POSIX 测试覆盖 umask 022/077 下的 0600、0640、0644、0666，以及精确字节、暂存/最终 mode 和 setuid/setgid/sticky 位丢弃。在暂存目录创建后删除已有目标，要求仍成功发布新文件，不遗留工作文件且不调用 chmod。新文件及符号链接替换测试保持默认 umask 行为；覆盖指向 /dev/null 和普通 0644/0777 文件的链接、引用目标不变，以及指向目录的链接被拒绝。注入 ENOSYS/ENOTSUP/EPERM，在暂存权限相同或更窄时要求完整发布并清理；对这三种错误分别注入更宽的暂存权限，要求拒绝发布。注入 EACCES、I/O、只读或无分类 chmod 错误，要求原目标字节和 mode 不变且无暂存遗留。验证 EPERM 下的直接设置保存与启动版本规范化。错误注入不代表原生 CIFS/SMB 或 FAT/exFAT 验证。复跑既有策略读取、交错写入、发布拒绝、JSONC 和快照测试。提交前完成 build、bundle、typecheck、连续两轮干净自审和独立审查。原生 Windows 替换测试保留平台门禁，不把本地跳过算作验证。
