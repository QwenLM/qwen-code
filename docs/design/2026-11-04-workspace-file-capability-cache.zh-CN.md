# 复用本地 Workspace 文件能力

[English](2026-11-04-workspace-file-capability-cache.md) | [简体中文](2026-11-04-workspace-file-capability-cache.zh-CN.md)

## 问题与范围

每次本地 Workspace 文件查询、读取、上传及上传状态查询都会启动两次 CLI：
先读取带版本的能力文档，再执行实际操作。本地验收样本中，仅能力探测进程
就耗时约 221 ms。对于未变化的本地可执行文件，复用已经成功的握手。

本次仅改变本地能力发现。授权、上传标识、SQL 准入与结算、维护保护、进程
超时和响应校验保持现有行为。SSH 仍在每次交换时探测远端 CLI。不增加配置
或协议字段。

## 设计

`WorkspaceFileProcess` 保留一个不可变的 volatile 快照，包含成功的帮助响应
以及配置的 Node 和 CLI 文件身份。身份包括配置的绝对路径、解析后的路径、
文件键、大小、创建时间和修改时间。相对路径、非普通文件以及无法读取身份
的文件继续使用现有的逐次探测。

命中缓存后，仍从已保存的文档校验本次请求需要的能力。读取能力不代表上传
能力。未命中时执行原有的有界探测，仅在校验成功且再次读取的文件身份未变
时缓存。失败或格式错误的握手不会缓存。每次实际文件操作仍启动独立进程并
校验自己的响应。并发的首次请求可以分别探测，不增加串行化文件 I/O 的锁。
只保留最新快照即可限制缓存大小，无需缓存服务或淘汰策略。

正常的 CLI 构建和部署替换会改变入口文件身份，使快照失效。带内容哈希的
bundle 导入通过该入口更新。直接编辑导入模块但不重新构建入口，不属于身份
变化；这种开发修改之后应重启 Java 进程。缓存仅优化协议能力发现，不提供
文件完整性保证，也不参与授权决策。

## 验证与验收

- 重复读取和上传复用成功的探测，实际操作仍独立执行。
- 仅声明读取能力不能放行上传。
- 替换 CLI 或改变 Node 身份会重新探测；无效替换在实际操作前被拒绝。
- 相对路径仍逐次探测。失败探测可以在下一次请求中恢复。
- 现有上传未知结果、有界输入和超时检查通过。
- 按原样本方法复测 1、2、4 并发的真实 32 KiB 上传，记录延迟、成功率和锁等待。

沿用现有共享本地验证预算与未变化的 CLI bundle。完整 MySQL 和 Hosted/故障
验收仍由 CI 承担。分别记录已执行检查和限制；本文不声明验收已经完成。
