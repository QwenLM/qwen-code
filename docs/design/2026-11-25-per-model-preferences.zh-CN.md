# CLI 按模型保存偏好

[English](2026-11-25-per-model-preferences.md) | [简体中文](2026-11-25-per-model-preferences.zh-CN.md)

## 目标

目前 CLI 保存一项全局思考强度，切换模型时会沿用运行中的强度。上下文容量已由模型
配置提供，用于展示上下文用量和自动压缩。让本地 CLI 能为每个主对话模型保存思考强度
和上下文窗口，并在切换模型或重新启动时恢复这两项设置。

## 设计

- 沿用 Preview 的配置结构 `model.preferences[routeKey]`，包含两个可选字段
  `reasoning.effort` 和 `contextWindow`。使用 main 解析出的认证类型、模型 ID 和
  端点标识构造键，让不同端点上的同名模型各自保存偏好。
- 复用 CLI 配置写入器和模型选择的作用域规则。每次仅更新所选作用域中正在编辑的
  字段。清除字段后，按其余设置和模型默认配置解析有效值。
- 在启动、完整配置重建和 OAuth 热切换时，先解析目标路由，再应用模型偏好。以目标
  模型的配置为基础，避免上一模型的设置变成目标模型的默认值。缺少模型专属强度时
  回退到旧版 `model.reasoningEffort`。按现有规则应用思考能力和显式会话覆盖。
- 让 `/effort` 及两个终端强度选择器共用偏好写入入口。使用
  `/context-window <tokens|default>` 设置或清除当前模型的窗口偏好。应用保存的
  覆写前按目标模型容量校验 token 数。解析得到的 `contextWindowSize` 用于现有的
  用量展示和压缩路径。保存成功后同步更新当前运行配置。

## 验收

- 为 A、B 保存不同的强度和窗口。执行 A → B → A 后检查两项生效值，再启动新的
  CLI 进程检查两个模型的设置。
- 验证同名不同端点和 OAuth 热切换路径，确认生效的偏好取决于目标模型路由。
- 验证清除一个字段会保留另一项，拒绝不支持的值，缺少模型专属强度时回退到旧版
  强度。检查字段更新的配置作用域，确认仅会话生效的改动未写入配置文件。
