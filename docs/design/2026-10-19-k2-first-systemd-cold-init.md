# K2 first-systemd cold-init software slice

[English](2026-10-19-k2-first-systemd-cold-init.md) | [简体中文](2026-10-19-k2-first-systemd-cold-init.zh-CN.md)

## Status and scope

Software implementation draft for independent review, 2026-10-19. This design carries the reviewed first-systemd decision and the mandatory usermode-helper/module reduction into the implementation. It does not report an installation, policy load/lock, reboot or native acceptance. The actual code and all software outputs are prepared in an owned isolated source copy; this slice leaves the original worktree untouched.

The only first lane is Ubuntu 24.04.5 amd64, kernel 6.8.0-139-generic and the observed initramfs-tools entry. Its production call chain is hardened `/init` → original `run-init` root switch → `/opt/qwen-k2/bin/k2-cold-init` as PID1 → same-thread on-exec into `/usr/lib/systemd/systemd` → fixed empty `qwen-k2-cold.target`. It starts no bus, runtime, kubelet, CSI, source, gateway or business actor. This endpoint is not a usable ACK node or the complete K2 producer. Normal services, selected CSI/admission, durable physical authority, RELEASED, history and reuse are separate work.

## Candidate and acceptance are separate stages

Offline generation must produce a real deterministic candidate before native testing. It checks source/ELF/data pins, closed shapes and deterministic hardened outputs; it does not require an earlier successful cold boot, an accepted-node receipt, immutable flags on ordinary staging files or a policy already loaded into the build host. Thus a controlled native trial can use the candidate. No candidate or generator self-report grants installation authority.

A candidate contains the hardened initrd overlay/final image, rootfs payload, closed installation graph and an external byte inventory. The final image digest stays outside its own input graph. Native acceptance occurs only after the owned test environment has actually consumed the boot image, established the boot TCB/helper boundary, executed the confined systemd endpoint and independently checked cleanup. Unknown or unsupported native behavior remains refusal of the lane; no force/skip/qualified option makes it accepted. Source/7 and durable authority/release semantics are unchanged.

## Observed inputs and actual entry

Read-only node evidence pins the original kernel `/boot/vmlinuz-6.8.0-139-generic` (15059336 bytes, SHA `0066409132868538bc0c9076f60131025775d5bbd8617df074d059f91b584918`) and `/boot/initrd.img-6.8.0-139-generic` (62554950 bytes, SHA `898d873471a90fb4ce6cfb1c6161a9a67a44ba8a467a63ce651972910d58cf65`). The 15 known initrd entries are seven scripts (`/init`, `/scripts/functions`, init-top/init-bottom `ORDER` and `udev`, local-bottom `ORDER`), four `/usr/bin/{busybox,env,run-init,switch_root}` and four lexical loader/libc entries. The four tools are the same 330000-byte dynamic BusyBox ELF; the interpreter/libc closure and declared link chains must be checked, not described as static klibc. Actual systemd has 24 observed dependency mappings; ldd observations do not cover every future dynamic lookup.

The generator uses exact reviewed original bytes/anchors and fixed replacement templates, never a generic init framework. Remove alternative init, breakpoint, rescue/panic-hook/shell/reboot and arbitrary argv/env/cmdline selectors. Preserve required root mounting and virtual-filesystem moves. Fix `panic=0` and `systemd.import_credentials=no`; clear runtime/LD/debug environment before dynamic helpers and cold-init startup. `run_scripts` and every reachable ORDER invocation/parameter source must explicitly propagate failure to PID1, rather than rely on `set -e`. Fixed panic emits a bounded literal diagnostic and exits; native kernel fail-stop remains a test obligation.

Udev shutdown is an exit request followed by actual join/reap of its known trusted child. It is not the last init-bottom helper. Keep explicit ownership of that child from trusted creation; never kill unknown userspace to make the final process scan pass. The full base digest binds inherited helper bytes, but does not substitute for their semantic TCB/native review. Missing or ambiguous termination blocks the next step.

## Mandatory helper closure and module capability reduction

New read-only facts establish real efivarfs mounted at `/sys/firmware/efi/efivars` (type `de5e81e4`), both SystemdOptions paths ENOENT, unchanged kernel-config SHA `a5debe1362156decce8c37181c3bbed212fb6b976a7bce481bb22cadb1dee48d`, `/sbin/modprobe` resolving to `/usr/bin/kmod`, 78 loaded modules, module/kexec disable values 0, and full UMH capability masks. Current hotplug/uevent helper paths are empty; modprobe is enabled, core_pattern invokes apport, and suid_dumpable is 2. These are post-boot observations, not proof of a future boot interval. Modprobe configuration even contains install/remove directives; neither an empty target nor a fixed ordinary service unit closes this path.

After the last trusted initrd helper/module work and real-root handoff, before policy loading or systemd, cold-init validates the actual initial namespace/process boundary and directly closes exactly these kernel interfaces, with bounded no-symlink/type/ownership checks and complete-write/readback checks:

| Fixed interface                 | Required resulting bytes                                                                        |
| ------------------------------- | ----------------------------------------------------------------------------------------------- |
| `/proc/sys/kernel/modprobe`     | Write exactly one LF byte (`\n`); require readback exactly one LF, representing the empty path. |
| `/proc/sys/kernel/hotplug`      | Write exactly one LF byte (`\n`); require readback exactly one LF.                              |
| `/sys/kernel/uevent_helper`     | Write exactly one LF byte (`\n`); require readback exactly one LF.                              |
| `/proc/sys/kernel/core_pattern` | `core\n`, never a pipe or caller-selected command.                                              |
| `/proc/sys/fs/suid_dumpable`    | `0\n`.                                                                                          |

Never issue a zero-byte write or treat it as a successful disable. Every interface requires one complete nonempty write followed by an independent bounded read; short write, changed object or different readback stops the boot.

Set the exec caller's soft and hard RLIMIT_CORE to zero. Permanently remove only CAP_SYS_MODULE from permitted, effective, inheritable, ambient and bounding sets and independently read all five back immediately before exec. Use the already locked original PID1 thread. Bounding/inheritable removal prevents root exec from restoring that capability. The reviewed systemd v255 kmod_setup checks the actual effective capability and returns when it is absent; this is real privilege reduction, not a fake conditional, optional switch or a replacement for other guards. Go runtime threads remain the pre-policy TCB and do not become protected host actors; exec destroys those other threads, and systemd inherits the reduced caller. No goroutine, callback or child may issue module/exec operations on behalf of a different still-privileged thread.

Systemd v255 calls initialize_coredump(false) before manager configuration: it attempts RLIMIT_CORE=infinity and core_pattern=|/bin/false. DumpCore=no cannot control that earlier path. The renderer unconditionally appends literal deny-write rules for all five fixed helper/core interfaces and `deny capability sys_resource,` to the systemd profile. AppArmor deny wins over broad host-base allows. With inherited hard/soft CORE=0 and CAP_SYS_RESOURCE denied by the enforced profile, systemd cannot raise the hard limit; the reviewed upstream code logs failed attempts and continues. Actual Ubuntu behavior still requires native acceptance.

Before on-exec, independently enumerate bounded `/proc/thread-self/fd` entries. Inherit only the exact three console descriptors; every other retained/runtime descriptor must be explicitly classified and CLOEXEC. All kernel-interface descriptors are CLOEXEC and closed before this gate. Unknown, writable inherited, changed or non-CLOEXEC descriptors fail-stop, so an unconfined writable descriptor cannot bypass the later pathname denies. No test seam or configuration disables this gate.

Do not additionally set modules_disabled/kexec_load_disabled or alter global UMH capability masks without a separate design. Clearing helper entrypoints and dropping the caller's capability does not drain already queued kernel work. No known userspace snapshot/API is accepted as proof that pending UMH is empty. The trusted creation/termination discipline and actual native boot trace remain mandatory; missing proof refuses native acceptance. The new software has no option to waive this gate.

## Actual PID1, protected exec and kernel operations

The command accepts no arguments or alternate roots/paths. Before destructive operations require actual host PID1/original main thread and supported initial PID/user/mount namespaces, full uid_map, real proc/sysfs and correct kernel/rootfs. Lock the startup OS thread in command init and never unlock. Bound leader/task scans; allow the loader and positively classified kernel threads, reject other userspace/zombies/ambiguity. Two scans are not lifetime or pending-UMH proof. Mount only the fixed securityfs location when its real expected mountpoint/context permits; refuse foreign mounts or stacked AppArmor namespaces.

Reuse immutable regular-file/nlink1/root owner/no-write/ext4/mount/ancestor guards, retaining actual file and ancestor FDs and revalidating named/held identities. Use a role-specific retained executable holder with 128 MiB per ELF and 64 MiB aggregate systemd/dependencies; do not enlarge existing input bounds. Compare the actual running `/proc/1/exe` object with the retained loader before loading and again before exec. Pin actual no-symlink systemd path and all 24 dependencies, plus explicitly declared alias nodes/search inputs. Cache/preload/hwcaps or unknown lookup is refused by the supported runtime lane. `unix.Exec(path)` is pathname execution, not execution of a retained FD; absence of concurrent mutators and the boot TCB remain required. No unreviewed execveat fallback is added.

The real producer requires enforce/hash/export enabled and unlocked empty reviewed root policy namespace. Load the one complete packed bundle once, independently compare all profile modes, objects, same raw-data bytes/hash/length, ABI/context/revision, lock policy and read back with equivalent checks. No source-label-specific locked consumer is used as a fake producer. Complete kernel/helper/state/retained-input checks precede the original-thread exec attribute (the fixed `/proc/1/task/1/attr/exec`, after proving `/proc/thread-self` is `1/task/1`) and same-thread Exec. Failure before or after setting next-exec stops PID1 with no alternative exec/retry/reconnect. Candidate software tests may inject destructive operations only through narrow package-private test seams; production constructors always create real operations.

## Fixed systemd endpoint and pre-target inputs

Use immutable 0700 `/etc/qwen-k2/cold-systemd`, containing only immutable 0700 `units`. The two fixed names `generators` and `environment-generators` must be absent with retained-parent checks before loading and before exec. Existing empty directories are insufficient: v255 manager.c existence checks would still fork sd-gens. Units contains exactly the 85-byte target (`[Unit]\nDescription=Qwen K2 cold boot endpoint\nDefaultDependencies=no\nAllowIsolate=no\n`, SHA `37f7d64500e1fab843ab15d981f1550929e1d6ea69e93c8503f14d9f000c06b6`), default.target → that target, and apparmor.service → /dev/null. No normal service/drop-in is discoverable.

Cold-init entry environment is exactly LANG=C. Execute actual systemd with argv `["/sbin/init","noibrs"]` and exactly six environment entries: LANG=C, SYSTEMD_LOG_TARGET=console, SYSTEMD_LOG_LEVEL=info, SYSTEMD_UNIT_PATH=/etc/qwen-k2/cold-systemd/units, SYSTEMD_GENERATOR_PATH=/etc/qwen-k2/cold-systemd/generators, SYSTEMD_ENVIRONMENT_GENERATOR_PATH=/etc/qwen-k2/cold-systemd/environment-generators. No trailing colon is permitted. Upstream v255 commit `db11bab38ccf1ed257f310d29070843d4c58ea01` actually consumes these variables as replacement paths; an Ubuntu build still needs native verification.

Pin 51-byte `/etc/systemd/system.conf` (`[Manager]\nDumpCore=no\nCrashShell=no\nCrashReboot=no\n`, SHA `71d282b87f39bbe1d3a9b209df8f78f5d543883da3b43738721c5c4593523ad1`) and the four absent/empty system.conf.d roots in /etc, /run, /usr/local/lib, /usr/lib. Require `/etc/initrd-release` and `/etc/ima/ima-policy` absent. Require real visible efivarfs and ENOENT for `/sys/firmware/efi/efivars/SystemdOptions-8cf2644b-4b0b-428f-9387-6d876050dc67` and `/run/systemd/efivars/` same name; unknown/unmounted/EACCES is not absence. Initial observations now meet this sampling check; runtime still checks the new boot. Do not use SYSTEMD_EFI_OPTIONS test override. Exact cmdline/credential-env checks make the source-backed `systemd.import_credentials=no` return before payload imports. Module capability reduction applies before first systemd; remaining hostname/machine-id, IMA/other-LSM/kernel state, dynamic startup/helper behavior, boot-loader selection and prior TCB remain concrete native gates. An empty target alone certifies none of them.

## Files, verification and limits

Affected implementation areas are fixed Python boot generator/packager/templates; render-profiles/compile-profiles fixed sets and real LSM leaf reads; Go cold-init/coldboot plus retained birth/artifact readers; Java WorkspaceCsiInstalledBytes and independent fixtures/tests; complete paired design/deployment instructions and E2E/software-fallback plan. No durable SQL/release/source7 change is included.

Test safe generation/packaging through real subprocesses and independent fixture byte inspection; reject each missing/extra/version/pin/alias/input/bound/output-reuse case. Verify same graph across Python/Go/Java and unchanged original guards. Test destructive ordering and all failure exits using test-only operations; no fake success or CLI/env/root/PID/kernel bypass enters production. Compile static Linux amd64 and arm64 (only amd64 is the native lane). Run focused Python/Go/Java checks, required Maven verification, and isolated root build/typecheck/bundle with low parallelism/read-only dependency inputs. Keep every failed attempt and final hashes, then self-audit twice and obtain independent testing/review. Native E2E and physical acceptance remain explicitly not run under this task's privileged restrictions.

No local/remote policy load/lock, existing VM configuration/service/privileged-state mutation, cloud API/installation/reboot or worker/model action is part of this software work. An approved ordinary-UID Linux runner may use only its own temporary source/cache/output tree for package-private fake operations and explicit no-load/no-cache parser grammar checks; those are not native acceptance. Failure keeps bounded evidence and never creates authority or silently rolls back a locked boot. Out-of-band recovery needs separate authorization and fresh boot/custody. Immutable installed artifacts/cold tree remain protected; writable runtime OCI bundles/lifecycle directories are not made wholly immutable.
