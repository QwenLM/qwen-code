# 扩展列表与详情分开加载

[English](extension-list-details.md) | [简体中文](extension-list-details.zh-CN.md)

## 问题与范围

扩展管理页面在显示列表前，会读取全部已安装扩展的技能、命令、智能体、上下文和设置。
列表只需要清单元数据与激活状态，资源详情只需为选中的扩展加载。

此改动独立于工作区激活投影优化（#12541）与完整状态请求的进行中加载合并（#12638）。
它使用现有目录读取能力，不改变完整状态缓存。合并 #12638 时，共享文件可能需要常规冲突处理。

## API 与归属

新增 `extension_list_details` 能力标记，对应两个归属 legacy-primary 工作区的路由：

- `GET /workspace/extensions/summary`：沿用状态响应外层结构，包含扩展元数据和激活状态，
  完全省略 `capabilities` 与 `details`。
- `GET /workspace/extensions/:name/details`：返回单个扩展的完整条目；不存在时返回
  HTTP 404 和 `extension_not_found`。

原完整状态接口与指定工作区的激活投影保持原有契约。两个新路由都使用已解析控制器的
工作区、信任状态、语言与生命周期代次检查，不选择其他运行时，也不在解析失败后回退。

## 加载与一致性

列表读取一致的目录快照，不加载子资源。单扩展详情在同一个存储读取边界中读取全部清单
身份，但仅加载指定名称的子资源。这样保留身份校验与快照激活语义，同时避免遍历排在
目标扩展前面的资源。两种读取都不填充管理器缓存，也不创建插件数据目录。保留现有清单
和子资源错误行为。共享响应映射保证来源脱敏与元数据和完整状态响应一致。

## 客户端行为与兼容性

SDK 增加独立列表与详情方法。扩展管理页面仅在 daemon 声明新能力时使用它们，否则沿用
完整状态加载。选择扩展后单独请求详情，提供加载、错误和重试状态。切换选择或刷新列表
后，旧响应失效；只将资源字段与当前列表元数据组合，避免旧详情覆盖激活状态变化。
其他状态接口消费者保持不变。

## 验证与验收

- 列表省略资源字段，其元数据与完整状态一致。
- 所选扩展详情与完整状态一致；不存在的名称返回 404。
- 仅加载所选子资源；缓存状态与插件目录不受影响。
- 测试覆盖选择竞态、刷新、错误与旧 daemon 兼容。
- 构建、类型检查、相关测试与真实 HTTP 冒烟检查通过。
- 对 20 和 100 个扩展使用真实文件系统交替测量完整状态、列表、单个详情及列表加详情。
  单独报告热缓存下本地控制器耗时，不将其视为浏览器和网络性能。

## 风险与限制

详情请求仍读取全部清单以保留存储身份一致性。列表和详情来自不同快照，因此两次请求
之间卸载扩展会导致 404，并显示详情错误。本次不增加持久详情缓存或进行中请求合并。
浏览器端到端耗时与冷磁盘表现需要单独测量，不能由控制器基准推断。
