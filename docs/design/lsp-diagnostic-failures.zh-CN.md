# LSP 诊断能力协商与失败可见性

[English](lsp-diagnostic-failures.md) | [简体中文](lsp-diagnostic-failures.zh-CN.md)

> 状态：已在本地实现；验证结果单独记录。

## 问题

客户端请求 `textDocument/diagnostic`，却没有声明已经实现的拉取诊断能力。
真实测试使用的 JSON 服务因此选择推送，通过 `publishDiagnostics` 报告非法
JSON，并拒绝拉取请求。服务层忽略拒绝并返回空数组，工具却将其呈现为没有
诊断。工作区诊断请求失败和报告结构无效也会产生相同的“假干净”结果。

## 决策

声明 `textDocument.diagnostic`，禁用动态注册及关联文档支持。复用已有的拉取
请求、规范化与工具输出，不为修复能力协商而新增推送缓存。

成功的文档和工作区报告必须包含 `items` 数组。缺失或 `null` 响应不能证明
当前报告干净；整合 main 的失败记账后，这取代原先的 null 兼容策略。范围内的
逐文件报告必须包含自己的 `items` 数组，规范化不能丢失诊断。空字符串诊断消息
合法，缺失或非字符串消息仍无效。畸形 URI 字符串及越界位置仍被省略。物理解析
失败与 URI 语法畸形不同：必须拒绝，不能丢弃一个可能位于范围内的报告，也不能
仅因结果范围未知而清除其已投递状态。

请求未发送此前的结果标识，因此不含 items 的 unchanged 报告不能证明当前结果。
无效报告外层结构和范围内的畸形内容即使在此前已有诊断时也必须拒绝；范围、
同步及扫描预算失败也仍是硬错误。按 main 的策略，独立传输失败逐服务器记账：
健康服务器返回的实际非空诊断仍保留，但不能证明分析完整。空结果必须由可用
应答服务器背书，且不存在相关的失败或不可达服务器。不支持该方法、返回
`-32601` 的兄弟服务器不能否决真正受支持的答案；如果没有服务器应答，包括
仅有一个不支持工作区拉取的服务器时，查询必须拒绝。文档空答案的归属判断在
文件路由后进行；`serverName` 显式选择绕过语言/root 及基于声明的归属判断，
绝不绕过工作区边界。拒绝会指明服务器或无法解析的 URI，并保留原始原因。工具
以 `ToolErrorType.EXECUTION_FAILED` 暴露这些失败，不改变公开的诊断数组类型。
[磁盘同步设计](lsp-disk-document-sync.zh-CN.md) 记录整合后的失败／归属记账；
不相关的传输 catch 不属于本修复。

## 边界

保持现有工作区包含性、显式映射权威性、无扩展名兼容路由、文档同步及诊断
规范化。未实现关联文档报告、诊断动态注册、刷新请求或非请求式推送缓存。
仅支持推送、不能回答拉取请求的服务会报告失败，而非文件干净。工作区结果
数量限制与越界过滤不变。

## 验收

- 复现非法 JSON 已推送错误、但当前拉取请求失败的行为。
- 验证初始化只声明实际支持的诊断行为。
- 使用真实 JSON 后端，在打开／修改后，非法文件返回非空拉取诊断，合法文件
  返回成功的空报告。
- 新构建的 CLI 显示非法文件的实际后端错误，而非 `No diagnostics found`；
  明确区分 mock 模型与真实模型，披露模型认证缺失及不可用平台。
- RPC 拒绝、超时或连接关闭不能证明结果干净。有效空报告仍可用；仅有 null／
  缺失响应必须拒绝。健康服务器的实际诊断可在独立 RPC 失败时保留，但无效内容
  和范围／同步／扫描错误即使在此前已有结果时也必须拒绝。仅有一个不支持工作区
  拉取的服务器时应失败；受支持的兄弟服务器提供空报告时仍成功。两种查询均保留
  空消息诊断及其相邻的真实错误。
- 既有路由／范围／生命周期测试、构建、类型检查、打包及定向 lint／格式检查
  通过。在环境可用时，真实 macOS 和 Linux 运行印证协议行为，不声称未执行的
  Windows 测试已经通过。

## 风险

此前被隐藏的诊断失败现在会变得可见。main 的部分结果策略在独立传输失败时
保留实际诊断，但不证明分析完整。null 响应不再证明结果干净。无效内容及未知的
结果范围仍是硬错误。本修复不提供完整推送诊断支持，
也不保证每个 LSP 服务都支持拉取诊断。既有文件系统竞态限制不变。
