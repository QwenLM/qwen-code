# 将工作区新建分组迁移到更多菜单

[English](workspace-create-group-menu.md) | [简体中文](workspace-create-group-menu.zh-CN.md)

## 问题与范围

Issue [#15312](https://github.com/QwenLM/qwen-code/issues/15312) 反馈，用户容易将
工作区行内用于新建分组的「+」误认为新建会话。新建会话是高频操作，而新建分组
是偶尔使用的整理操作。本次只迁移分组创建入口，保留其名称和行为。

## 实现

为 `WorkspaceMenu` 增加可选的 `createGroup` 操作，放在会话创建相关菜单项之后，
复用现有 `sidebar.groupCreate` 翻译。侧栏仅在现有工作区信任和分组权限允许时
提供该操作，复用主工作区或指定工作区的现有分组编辑器处理函数。
移除行内新建分组按钮，保留行内新建会话操作。

设置 `lockedWorkspaceCwd` 的嵌入式侧栏目前隐藏工作区菜单，但允许新建分组。
为其提供仅包含获准的新建分组操作的菜单，保留创建能力，同时不开放工作区管理。
不允许分组时隐藏该菜单。

涉及组件为 `WorkspaceMenu`、`WebShellSidebar` 及其同目录测试。
无需修改 daemon、SDK、分组数据、翻译或会话创建行为。没有待定产品问题。

## 验证与验收

- 所有工作区标题行均不再包含行内新建分组按钮。
- 更多菜单复用现有本地化名称，并打开原有编辑器。
- 主工作区和其他工作区分别通过原有客户端创建分组。
- 不可信工作区、未启用分组能力、排除分组操作的配置均不获得新权限。
  锁定侧栏仅显示其获准的新建分组操作。
- 新建会话操作保持可用且行为不变。

运行针对性的组件测试、构建、类型检查及含前后对比证据的浏览器验证。
主要风险是丢失锁定侧栏入口，或将其他工作区的操作发送给主工作区客户端；
回归检查必须覆盖这两点。E2E 计划和结果放在 `.qwen/e2e-tests/`。
