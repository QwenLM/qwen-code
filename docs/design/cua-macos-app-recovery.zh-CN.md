# macOS App 观测与输入恢复

[English](cua-macos-app-recovery.md) | [简体中文](cua-macos-app-recovery.zh-CN.md)

## 问题

CUA SDK 0.20.6 可能返回已关闭的 Apple 菜单，而不是所选应用的窗口。
AppKit 还可能从 AXChildren 和 AXWindows 中遗漏仍存活的窗口，同时
AXFocusedWindow 和 AXMainWindow 依然有效。NSPasteboard 不可用时，
驱动创建会触发 panic，阻碍桌面失效后的恢复。

输入验证复现了可见 TextArea 的完整文档中心落在窗口外，以及 Preview
托管文件面板不响应向宿主 PID 投递的点击和快捷键。托管控件与应用根窗口
具有不同的原生窗口 ID，但真实 AX 父链能够将它们关联。

## 改动

只有子菜单可见时，才将菜单选为 App 观测根节点，保留的菜单通知也遵循
此规则。窗口枚举无法解析精确目标时，补充同 PID、原生窗口 ID 与请求
窗口一致的 focused/main 引用。保留现有所有权检查和读取不完整的报告。

每次操作按需获取 NSPasteboard，将 nil 作为可恢复错误处理。剪贴板的
可用性不应决定驱动是否能够创建。保留 Unicode 文本、PNG、文件 URL
和富文本粘贴事务。

在控件与精确窗口的矩形交集中选择点击点。App 指针点击和前台快捷键复用
现有前台 HID 实现。发送全局 App 点击前，提升精确 AX 根窗口，要求系统
命中元素的有界 AXParent 链通过 CFEqual 到达同一根节点，同时要求精确
焦点窗口和 WindowServer 前台进程一致。归属不明、坐标过期或窗口遮挡
必须在发送鼠标输入前拒绝。

公开 App API 继续隐藏投递模式，沿用现有原生 SDK 进程、权限、安装、
动作串行化以及焦点／光标恢复机制。本次准备 CUA SDK 和驱动 0.20.7，
Node REPL 保持 0.1.4。不增加依赖、服务、公开选项或自动重放。

## 验证与限制

在自有文档上对照发布版与候选版，使用独立 AX 和文件读回验证。覆盖菜单
选中状态残留、空窗口数组、剪贴板为空时创建／重连／恢复、长 TextArea
点击、托管面板字段和快捷键、被遮挡目标、滚动及生命周期复用。剪贴板
故障注入仅在临时子进程执行，恢复目标使用私有剪贴板。

动作回执成功不等于输入生效。必须用字段值、选区变化、可见滚动或精确
文件内容证明结果。提交前运行原生测试、SDK 测试／构建／类型检查、
仓库构建／类型检查／打包，以及包和版本校验。环境失败单独记录。

归档 benchmark 中最初的 WindowServer 重启缺少崩溃堆栈和可重复触发
条件。本次改动不宣称防止该重启，也不负责重新启动失效的桌面会话。
此前路径输入截断单独记录：文本投递代码未改，新建面板上输入成功不能
确定此前截断的原因。benchmark 分数恢复必须在新版本发布后测量。
