# `/verify-pr` MicroVM 标准 Guest 入口与离线 Golden 镜像派生设计

[English version](2026-11-28-verify-pr-vm-guest-init-and-image.md)

**状态：已在 macOS arm64 与 Linux aarch64 KVM 实现并实测；PR 评审与远端 CI 仍为独立门槛。日期：2026-11-28。**

## 1. 背景与目标

PR #18552 合入后，`/verify-pr` microVM 宿主侧整条流水线（`probe` → `select --probe` → `stageLocalVmRound` → `runHardwareRound` → `reapOwnership` → `verify-pr-check`）已完全在仓库内闭环。但阶段 2 仍有两块关键能力停留在仓外临时 PoC 脚本中：

1. 标准 PID-1 guest 启动入口与零第三方依赖的 guest 生命周期编排器，用于串联 3 端口 guest vsock 通道（`fetch-inputs`、`model-bridge`、`upload-artifacts`）、熵注入、隔离自检、bundle 物化、剥离凭据的工作负载执行与干净关机。
2. 离线、只读 golden ext4 rootfs 派生工具，在不挂载 loop 设备、不修改只读 golden 源镜像的前提下注入上述受审 guest 脚本。

本次改动将这两块正式入库至 `scripts/`，彻底脱离仓外 PoC 胶水脚本，同时一并落盘 PR #18552 评审中记录的 2 条非阻断 follow-up（`ensureApprovedDirHierarchy` 接受目录本身等于规范化 `approvedRoot`，以及将 `createdDirs.push(nextDir)` 紧接 `mkdirSync` 置于 `chmodSync` 之前）。

## 2. 范围与硬约束

- **允许改动范围：**`scripts/verify-pr-vm-guest-init.sh`、`scripts/verify-pr-vm-guest-runner.py`、`scripts/verify-pr-vm-image.mjs`、`scripts/verify-pr-vm-host.mjs`、`scripts/verify-pr-vm-runner.mjs`、同目录 collocated 单测（`scripts/tests/verify-pr-vm-{guest-runner,image,host}.test.js`）以及本双语设计文档。
- **范围之外（不得触碰）：**`packages/`、`.github/`、`.qwen/skills/`、`/review`、云资源分配、外部模型调用与真实凭据。
- **向后兼容：**保留既有默认启动 `bootArgs`（`init=/opt/poc/init`）、手工 `stageAssets: false` 流程以及 legacy `container`、手动 `vm` 与 `waived` `/verify-pr` 流程。

## 3. 设计决策

### 3.1 极简 PID-1 Guest Init（`scripts/verify-pr-vm-guest-init.sh`）

- 纯 POSIX `#!/bin/sh`（`shellcheck -s sh` 零警告），同时兼容 BusyBox 与 Debian rootfs。
- 挂载 `/dev`（`devtmpfs`）、`/dev/pts`（`devpts`）、`/dev/shm`（`tmpfs -o mode=1777,nosuid,nodev`）、`/proc`、`/sys`、`/run`（`tmpfs`），创建基于根盘的 `/work`（`0700`）作为 `HOME`/`TMPDIR`（避免纯内存 `/run` tmpfs 在大 bundle 与 checkout 下发生 OOM/ENOSPC），按需加载 `virtio_vsock`，仅拉起回环接口 `lo`（无外网 NIC），导出无宿主凭据的干净环境，调用 `guest-runner.py --from-cmdline`，完成后 `sync` 并在 PID 1 下干净关机以避免内核 panic。

### 3.2 零依赖 Guest 生命周期编排器（`scripts/verify-pr-vm-guest-runner.py`）

- 仅使用 Python 3 标准库，动态加载同目录 `verify-pr-vm-guest-vsock.py`（或镜像内的 `/opt/qwen/guest-vsock.py`）。
- 按 7 步 fail-closed 契约执行：
  1. 通过端口 53 拉取 `manifest.json`（结构校验）与 `round.bundle`（按 manifest `bundleBytes` / `bundleSha256` 校验，支持 `--unix-input` 用于宿主侧离线测试），并由 `manifest.entropyHex` 写出 `entropy.hex`。
  2. 解码 64 位十六进制 `entropyHex` 并将 32 字节写入 `/dev/urandom`（支持 `--urandom-path` 单测）；写入失败即 fail-closed（`written: false`）。
  3. 检查 `/sys/class/net` 与 `/proc/mounts`，核验仅含 `lo` 接口（`noNic`）且不存在宿主机共享目录挂载（`virtiofs`/`9p`/`vboxsf`/`vmhgfs`/`fuse.sshfs`）；sysfs/procfs 缺失或不可读时 fail-closed（`netInspected: false` → `noNic: false`；`mountsInspected: false` → `hasDirectoryShare: true`）。
  4. 从 `round.bundle` 物化纯净 Git 工作区至 `work_root/repo` 并验证 `baseRefOid` 与 `headRefOid` 提交；仅当针对无 `git` 的极简 BusyBox 镜像显式传入 `--skip-materialize` / `qwen.skip_materialize=1` 时，预先创建 `work_root/repo` 并以纯 Python 校验 Git v2/v3 bundle 头部（`verify_bundle_header`），要求 `headRefOid` 必须是 bundle 内实际通告的 ref（不可仅为 `-<oid>` 前置行），`baseRefOid` 可为通告 ref 或 `-<oid>` 前置行。
  5. 当 `manifest.modelProxy` 非空时，启动 `model-bridge` 监听 `127.0.0.1:0` 并转发至协商的 `manifest.modelProxy.port`（缺省回退 `--model-port` / 54；测试用 `--unix-model`），在启动任何 workload 前调用 `GET /__health` 校验返回的裸 `nonce` 逐字节匹配；不匹配立即 fail-closed 并停止 bridge。
  6. 在 workload 模式（`--workload` 或 `/opt/qwen/workload.sh`）下，若熵注入或隔离检查任一失败则拒绝启动 workload；通过后写入 `logs/guest-runtime.json` 并在剥离宿主凭据的环境与独立进程组（`start_new_session=True`）中限时运行（`DEFAULT_WORKLOAD_TIMEOUT = 30` 秒，与 collector 默认 45 秒接收窗口对齐并留出 15 秒引导/物化/上传余量；超时与非零退出均向整个进程组发 `SIGKILL`，仅在 `workload_rc == 0` 后才将 `artifacts_dir` 标记为待上传）。在内置自检模式（无 workload）下，直接在内存中构建符合 `verify-pr-check` 契约的 `report.md`、`verdict.txt = inconclusive`（记录 `workload-completed: false`、`attribution: "harness"`，确保未验证任何 PR 行为的管道自检绝不误报 `merge-ready`）、`assertions.json`、`comment.md`（仅在传入合法 12 位十六进制 `qwen.skill=<12-hex>` / `--skill-digest` 时渲染页脚）与 `logs/guest-runtime.json`。
  7. 将步骤 4–6 整体包入 `try`/`except`/`finally`，且默认 `upload_dir = None`、`upload_payload = None`：所有未捕获异常（含超时与非零 workload 退出码）均直接在进程内存中构建降级后的 `inconclusive` 诊断产物（`workload-completed` + `guest-lifecycle-error`）并写入 `upload_payload`，不在磁盘创建任何临时目录，使预写的 `merge-ready`、被破坏成目录的 `logs/guest-runtime.json`、`setsid` 脱离进程组持续覆写 `artifacts_dir` 的残留进程以及 `/work`/`/tmp` `ENOSPC` 均无法泄露未验证结论；即便构造降级产物本身失败，`finally` 也绝不回退上传旧 `artifacts_dir`。`finally` 始终停止 `model-bridge`，并经端口 52 流式上传 `upload_payload`（内存）或 `upload_dir`（仅 `workload_rc == 0` 后）。
- 按 last-wins 语义解析 `/proc/cmdline` 的 `qwen.*` 参数，对 `cid` 与 `workload_timeout` 拒绝非正整数，对端口限定 32 位 `AF_VSOCK` 合法范围 `1..4294967294`（排除 `0` 与 `VMADDR_PORT_ANY = 0xFFFFFFFF`，与宿主侧 `buildFirecrackerLaunchPlan` 对称），对 `qwen.skill` 拒绝非 12 位小写十六进制值。宿主侧 `scripts/verify-pr-vm-runner.mjs` 的 `deriveCollectorAcceptDeadlineMs` 会遍历启动计划命令行中的全部 `qwen.workload_timeout=<N>` 并取最后一次匹配（last-wins，与 guest 保持一致），在调用方未显式设置 `collectorOptions.acceptDeadlineMs` 时自动将接收窗口扩展为 `min(24h, max(45_000, workload_timeout * 1000 + 30_000))`。

### 3.3 离线只读 Golden ext4 镜像派生（`scripts/verify-pr-vm-image.mjs`）

- 在复制或扩容**之前**直接读取源 ext4 镜像偏移 `1024` 处的超级块（`s_magic = 0xef53`、`s_log_block_size`、32/64 位 `s_blocks_count`），若文件系统声明字节数大于源物理文件长度则立刻 fail-closed 拒绝派生，防止截短传输的损坏镜像被 `truncateSync` + `resize2fs -f` 静默补零发布；同时以超级块声明字节数（`baseFsBytes`）作为缩容拒绝与扩容触发判据，使填充容器内包含较小 ext4 文件系统时仍能准确扩容。
- 将只读 golden ext4 镜像复制到排他私有临时文件（`O_CREAT | O_EXCL | O_NOFOLLOW`、`0o600`，零 loop 挂载，绝不以写模式打开 golden 源镜像），若请求了更大的 `--size-mib` 则先通过 `truncateSync` + `resize2fs -f` 离线扩容，再通过单次批量 `debugfs -w -f` 将受审 guest 脚本与可选 workload、`--bundle-host-python` 直接写入独立副本并显式设置 `0:0` 所有权与精确 POSIX 权限（可用时调用 `tune2fs -U random` 生成新 UUID 并保持 `e2fsck -fn` 零错误）。
- 由于基础镜像从不经宿主文件系统解包，即便在非 root 环境下，源镜像中的所有既有 inode——包括普通文件与符号链接的任意 UID/GID（即使所有普通文件都与构建者同 UID）、命名管道（FIFO）、套接字、设备节点、共享 inode 的硬链接（`nlink > 1`）、扩展属性（`xattr`）与权限位——均 100% 逐比特零损保留。
- `normalizeImageTargetPath` 与 `escapeDebugfsArg` 均直接拒绝 `"`、`\`、换行符与 NUL 字节，防止真实 `debugfs` 不解析反斜杠转义而把路径错写成异名条目。在向 `tmpOut` 写入任何内容之前，先通过只读批量 `debugfs -f`（`stat`）检查 `/` 及所有目标祖先目录与叶节点：对坏镜像/非 ext4 文件（`/` 非目录）立即 fail-closed，阻断恶意基础镜像内的祖先符号链接或非目录（覆盖 `/opt`、`/opt/qwen`、`/opt/python`），对已有文件/符号链接叶节点先 `rm` 再 `write`，拒绝覆写非文件叶节点。
- 复用 `normalizeApprovedRoots`、`canonicalizeVaultDir`、`canonicalizePreservingLeaf` 与 `isPathWithinApprovedRoots`，强制校验 `approvedRoots`、`vaultDir` 排除（覆盖 `baseImagePath`、注入源文件、`pythonBin`/`pythonLibDir` 与输出路径）、单链接非符号链接输入、可选 `expectedBaseSha256` 锁定、禁止覆写输出以及镜像内目标路径规范化（`normalizeImageTargetPath`）；所有注入文件先复制到私有 `0700` 暂存目录并复核 SHA-256 与预哈希一致后再喂给 `debugfs write`。
- 在原子发布输出镜像**之前**完成 `baseImagePath` 不可变复核以及 `tmpOut` 哈希与单链接校验，随后以 `linkSync` 作为唯一发布点（`unlinkSync(tmpOut)` 改为 best-effort 并由 `finally` 无条件清理临时名，确保临时名首次 `EBUSY` 绝不导致误报失败或残留不可重试目标）。
- 提供可选 `--bundle-host-python`，使用 Node 原生 `cpSync` 与 `readdirSync`（不硬编码 `/bin/cp` 与 `/usr/bin/find`）配合 `ldd`（遇到 `=> not found` 或非预期 stderr 立即 fail-closed）打包宿主 Python 3 及其共享库并写入 `/opt/python`：位于暂存子树内且目标存在的相对符号链接保留为内部符号链接，绝对或越界符号链接按源 `pythonLibDir` 物化为常规文件（悬空则 fail-closed），二次派生时幂等清理重建已有 `/opt/python` 子树。

### 3.4 PR #18552 非阻断 Follow-Up 与 Staging 守卫（`scripts/verify-pr-vm-host.mjs`）

- `ensureApprovedDirHierarchy` 接受目录本身等于某个规范化 `approvedRoot`（例如 `copyIsolatedAsset(src, join(root, 'kernel'), { approvedRoots: [root] })`），同时对文件目标继续维持严格子路径约束。
- 将 `createdDirs.push(nextDir)` 移至 `mkdirSync(nextDir, { mode })` 之后、`chmodSync(nextDir, mode)` 之前，同时跳过等于规范化 `approvedRoot` 本身的路径，保证 `chmodSync` 异常时新建子目录仍被回滚清理且回滚绝不会尝试删除 `approvedRoot` 本身。
- 在 Firecracker 的 `stageLocalVmRound` 中增加 fail-closed 守卫：若暂存 rootfs 大小超过 `plan.argv` 中声明的 `--resource-limit fsize=<bytes>` 上限则立刻报错并回滚。由于 `guest-init.sh` 将 `/work` 放在 rootfs 根盘上，若在 jailer 默认 256 MiB `RLIMIT_FSIZE` 下启动 512 MiB 派生镜像，guest 写入越过 256 MiB 偏移时 Firecracker 会中途被内核 `SIGXFSZ`（signal 25）终止。

## 4. 验收标准

1. `verify-pr-vm-guest-init.sh` 通过 `sh -n` 与 `shellcheck -s sh` 且零警告，使用 `/work` 作为 `HOME`/`TMPDIR` 并挂载 `/dev/pts` 与 `/dev/shm`。
2. `verify-pr-vm-guest-runner.py` 经真实 3 端口 Unix socket 通过 `runHardwareRound` 完成 7 步闭环（input 53 + model proxy 54 + collector 52 + `verify-pr-check` 退出 0），精确写入 32 字节熵，从 workload 环境中剥离宿主秘密，在熵/NIC/挂载检查失败时产出可通过 `verify-pr-check` 的 `inconclusive` 报告（含 `attribution: "harness"`），在隔离或熵违背时拒绝启动 workload，支持 `--skip-materialize` + `--workload`，优先使用协商的 `manifest.modelProxy.port`，在 workload 启动前拦截错误 `/__health` nonce 并在 `finally` 上传诊断产物，拒绝非法 `qwen.*` 整数，对不可读 sysfs/procfs fail-closed，并拒绝仅以 `-<oid>` 前置行出现的 `headRefOid`。
3. `deriveExt4GuestImage` 及其 `derive` CLI 强制校验 `expectedBaseSha256`、`approvedRoots`、`vaultDir`（含符号链接金库与打包 Python 输入）、单链接非 symlink 输入、禁止覆写、镜像内路径穿越与双引号/反斜杠拒绝、ext4 超级块截短校验与基于声明大小的扩容/缩容判定、镜像内祖先符号链接拦截（`/opt`、`/opt/qwen`、`/opt/python`）、坏镜像与 `debugfs` stderr 失败检测、`ldd => not found` 与越界 Python 符号链接处理、含空格 `tempParentDir` 兼容、空间耗尽临时文件清理与 `--size-mib` 提示、发布前 `tmpOut` 哈希与原子 `linkSync` 发布，以及事后 golden SHA 一致性。
4. 在真实 Linux aarch64 KVM 上，100% 仓内脚本全链路（`verify-pr-vm-image.mjs derive` → `runHardwareRound({ stageAssets: true, runChecker: true })` → PID-1 `verify-pr-vm-guest-init.sh` → `verify-pr-vm-guest-runner.py`）以 `ok: true`、`checkExitCode: 0`、`boundary.json (mode: "microvm")`、`entropy.written: true`、`isolation.noNic: true`、`isolation.hasDirectoryShare: false`、`modelProbeStatus: 200`、零残留 `jailRoot` 与 golden kernel/rootfs 哈希不变完成。
5. `copyIsolatedAsset(src, join(root, 'kernel'), { approvedRoots: [root] })` 通过，而 `copyIsolatedAsset(src, root, { approvedRoots: [root] })` 仍被拒绝，且 `stageLocalVmRound` 在 `chmodSync` 失败时回滚新建子目录而不尝试删除 `approvedRoot`。
