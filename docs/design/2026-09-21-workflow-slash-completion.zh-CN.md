# 已保存工作流斜杠命令的完成通知

[English](2026-09-21-workflow-slash-completion.md) | [简体中文](2026-09-21-workflow-slash-completion.zh-CN.md)

状态：实现处于 [#12415](https://github.com/QwenLM/qwen-code/pull/12415) 的评审阶段，处理 [#12176](https://github.com/QwenLM/qwen-code/issues/12176)。

## 问题

已保存工作流的斜杠命令发起客户端工具调用。前台结果不触发模型续轮，注册表的完成通知服务于后台任务，因而结果可以存在磁盘中，却没有进入对话。

## 决策

保留斜杠工作流的前台执行。将结果投递与运行模式分开：`executionOrigin.kind` 为 `client` 时，调度器为支持通知的调用传入内部通知标记。来源缺失或来源为模型时不启用通知，其中包括结果应返回父调用的嵌套 code-mode 调用。具有多种含义的 `isClientInitiated` 标记不决定投递。Workflow 将投递标记传给运行器和注册表条目。该标记不属于模型可传入的工具参数，也不属于持久化运行模式设置。初次调度及 `PermissionRequest` hook 编辑参数后重新创建调用时均保留标记。

客户端发起的任务完成或失败后，复用现有完成回调和通知队列。模型发起的前台任务沿用工具结果返回；后台任务沿用后台通知。取消不产生完成通知。终态检查防止一个任务报告两次。

运行器在执行结束前将终态刷新到工具卡片。按 Esc 取消后，卡片保留运行 ID 和阶段记录，显示 `status: "cancelled"`，替换取消前的运行中进度。任务结束后移除查看实时进度的提示。这次显示刷新不向队列加入完成通知。

前台进度保留在工具卡片，包含运行 ID，并提示在卡片查看进度。`/workflows <runId>` 在任务结束后用于查看运行；前台执行期间输入该命令会进入队列。完成通知显示运行 ID、状态、每个文本块上限为 4,096 字符（含截断标记）的返回值预览或错误、运行器记录的子任务失败，以及结构化对象返回值顶层非空的 `failed`、`errors`、`error` 字段。从原始对象读取这些字段，其他字段无法序列化或 getter 抛错时也保留失败信息。共享失败格式化函数将每个报告字段及运行器记录的派发错误限制为 400 字符（含截断标记），截断不会切开 Unicode 码点。空对象、数组、Map、Set，以及只含空白或终端控制字符的文本不产生报告条目。原生 Error 值显示为 `Name: message`，省略运行时调用栈，覆盖沙箱创建的 Error 及结构化结果内嵌套的 Error。非空 Map 显示为键值对列表，Set 显示为值列表，在现有预览上限内保留集合内容和嵌套 Error 的原因。同一组报告行通过独立的 `<reported-failures>` 元素进入模型上下文，置于结果预览之外，不改变运行器的派发计数。普通字符串不作为 JSON 失败报告解析。这些字段作为脚本报告的数据展示，不把完成状态改判为运行失败；不解释任意业务结果结构。没有返回值的任务显示 `(workflow returned no value)`，不向模型发送结果元素。

前台和后台完成通知将模型结果预览限制为 25,000 个 XML 转义后字符，该上限不受工具输出配置影响。返回给模型的工具结果、终端工具卡片与完成通知共用 Error 及集合的序列化语义，保留各自的美化和紧凑格式。值无法序列化时，工具卡片保留运行元数据，将受影响的顶层字段替换为占位提示。结果文本、脚本报告的失败字段及运行器记录的派发错误共用 ANSI／控制字符清理，保留换行，并将制表符展开为空格。清理后的通知文本用于显示及模型上下文；工作流消息和审批脚本片段使用同一清理函数。XML 转义限于预览部分；截断不会切开 Unicode 码点或 XML 实体，与子会话通知共用有界 XML 函数。截断提示携带存储层提供的绝对快照目标路径，不依赖 journal。提示明确指出：通知发出后才写入快照，只有收尾阶段持久化成功后才能在该路径读取完整聚合结果。缺少目标路径时提示查看已结束的运行，不编造相对路径。现有诊断信息保留逐 agent 的 journal 路径。注册表结果和持久化快照不截短。后台摘要保留原有包围引号和经过转义的标签。

TUI 在收到前台完成回调时显示通知，无需等待模型准入或回复。同一通知随后经现有队列进入模型及聊天记录，后续追问可以获得结果。斜杠命令派发记录中的 `outputHistoryItems` 可以保持为空，完成结果有独立的通知记录。

## 替代方案与取舍

删除所有前台运行的过滤条件，会为已有工具结果返回的模型任务增加通知。将斜杠任务切到后台，会改变内联进度和前台取消行为。内部投递标记保留这些行为，并复用通知通道。

让客户端工具进入正常工具结果续轮，还需要处理缺少模型工具调用记录、轮次归属及取消的问题。把命令展开成模型提示，会在执行前增加一次模型调用，并把参数选择交给模型。这次修复无需采用这两种方案。

现有通知通道会触发模型回复并消耗 token，本方案保留原 issue 要求的结果回报行为。静默写入上下文或自动总结开关属于额外功能；保留前台执行不意味着增加这些选项。用户看到的结果不依赖模型总结成功。

## 范围

ink 渲染器中的交互式已保存工作流命令保留脚本路径／仅名称调用、参数、审批、前台进度及取消行为。Headless 和 ACP 保留提示展开。嵌套 code-mode 调用向父调用返回结果，普通模型调用不增加通知。不增加公共工具参数、配置选项或持久化结构迁移。快照序列化保持原状：其普通 JSON 序列化不保留原生 Error、Map 和 Set 的内部内容。本轮修复在通知、模型工具结果和工具结果显示中保留这些值，不增加其内部内容的快照持久化。

OpenTUI 独立且尚未接线的 `schedule_tool` 处理器，以及工作流历史中新增的持久化结果查看器，不属于本次修改。两份编写技能均将斜杠命令说明限定于 ink，并建议在 OpenTUI 中让模型调用 `Workflow({ name: '<name>' })`。

## 验证

使用隔离交互会话和记录请求的模拟模型端点，检查受控 agent 完成前的前台进度、完成结果和真实子任务失败的显示、一次结果通知、完整运行快照的持久化及追问上下文。覆盖包含大量 XML 特殊字符、失败字段位于预览范围之外的大结果：显示和模型上下文均保留显式失败行，有上限的模型预览、绝对快照目标路径及独立失败元素进入后续追问上下文。覆盖脚本抛错、取消和审批拒绝。模型发起的前台任务作为对照：一次工具结果返回，无额外完成通知。保留参数、仅名称模式、headless 和 ACP 的命令加载测试。与命令输出可见性测试共享现有的 90 秒只读 `/about` 就绪探测。
