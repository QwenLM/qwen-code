# 已保存工作流斜杠命令的完成回传

[English](2026-09-21-workflow-slash-completion.md) | [简体中文](2026-09-21-workflow-slash-completion.zh-CN.md)

状态：[#12176](https://github.com/QwenLM/qwen-code/issues/12176) 的修复提案。

## 问题

交互式已保存工作流命令发起的是客户端来源的前台工具调用。客户端发起的工具不会将结果发送给模型，而工作流完成回调服务于后台运行。因此，运行可以完成并持久化结果，却没有把结果送回会话。

## 决策

为交互式命令的工作流参数设置 `run_in_background: true`，复用现有启动回执、工作流注册表完成回调和 TUI 通知队列。保留按脚本路径或仅按名称调用的选择，以及用户传入的参数。

启动回执标识运行并指向 Background Tasks。`/workflows` 对话框提供阶段树、用量、暂停／恢复和取消控制。完成或失败通过现有通知通道进入会话，携带返回值和记录的 agent 失败信息。

## 其他方案与取舍

保留前台模式，需要在工作流注册表引入客户端来源标记，或在工具结果续轮路径增加例外。两种方案都会为现有后台模式能够处理的场景引入新的投递规则。删除前台通知守卫会让模型发起的前台运行收到两份结果。

本方案把内联实时进度移到 Background Tasks 和 `/workflows`，启动后释放输入框。这是需要维护者评估的可见行为变化。方案不改变协议或持久化 schema，也不改变模型发起、headless 或 ACP 执行。

## 范围

改动覆盖交互式已保存工作流命令，包括用户、项目和扩展来源。工具审批、信任检查、工作流运行器和通知准入继续由现有组件负责。Headless 和 ACP 命令继续展开为模型提示。

OpenTUI 的 `schedule_tool` 处理器尚未接线是另一问题；为工作流历史增加持久化结果查看器也不属于本修复。

## 验证

使用独立交互式会话和合成模型端点，证明斜杠命令运行写入结果后，模型无需用户补充提示即可收到一份结果。覆盖成功结果、描述部分失败的结果和工作流抛出的错误。在终端核对启动回执和模型的完成回复。

以模型发起的前台工具执行作为对照：结果经正常工具响应返回，不产生后台完成通知。保留现有取消、审批、参数、仅名称模式、headless 和 ACP 检查。

执行证据放在 PR 的前后对照报告中；本文定义验收标准，不声明测试完成。
