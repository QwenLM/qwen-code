# Auto 分类超时后的主模型审核

[English](auto-classifier-main-model-fallback.md) | [简体中文](auto-classifier-main-model-fallback.zh-CN.md)

## 问题与当前行为

Auto 模式使用已配置的 fast 模型进行权限分类；未配置 fast 模型时，使用会话模型。当前第一阶段到达截止时间后会返回不可用，并将待执行操作转人工确认，即使另一个会话模型可能完成审核也是如此。

## 目标与范围

fast 分类第一阶段超时后，让不同的会话模型获得一次审核机会，同时将待执行操作保留在现有权限流程中。保留策略拒绝、显式权限规则、上下文过滤、用户取消，以及审核无法完成时的既有人工回退行为。

仅第一阶段自身超时触发该回退。API 错误、无效响应、上下文超限、提示词构造失败和第二阶段失败保留原行为。不新增或修改用户配置、界面、权限传输协议或模型选择设置。

## 提议行为

| 结果                                      | 后续行为                                 |
| ----------------------------------------- | ---------------------------------------- |
| fast 第一阶段允许                         | 沿用现有允许结果。                       |
| fast 第一阶段标记风险                     | 进行既有第二阶段复核。                   |
| fast 第一阶段到达截止时间，且模型标识不同 | 请求会话模型进行一次完整的独立审核。     |
| 未配置 fast，或 fast 与会话模型标识相同   | 保留不可用及人工回退。                   |
| 会话模型审核允许                          | 通过既有调度流程继续原待执行操作。       |
| 会话模型审核拒绝                          | 沿用既有策略拒绝处理及脱敏后的理由。     |
| 会话模型审核失败或超时                    | 保留不可用及人工回退。                   |
| 用户在任意阶段取消                        | 传播取消，不再请求新审核，也不执行操作。 |

主模型审核是无状态的权限请求，不是新的 Agent 轮次。它接收与 fast 分类相同的投影后会话、可信用户回答、待执行操作和策略，不重新加入助手正文或工具结果。不会切换或改写会话模型和对话历史。

## 模型、提示词与时间预算

使用既有 side-query 模型覆盖参数指定会话模型。比较已配置的模型标识，不新增一套路由解析器。回退复用既有完整审核响应结构，包括布尔判决与简短拒绝理由，并使用新的中性提示词后缀。不得声称第一阶段已识别风险，因为超时并没有给出判决。

完整审核复用已配置的第二阶段超时，默认 30 秒。与默认第一阶段 10 秒预算合计，在需要回退时允许约 40 秒的分类请求时间。审核也沿用第二阶段的 thinking 设置与 4096 token 输出预算。仅发起一次 side-query，并将分类器层的尝试次数限制为一次，非交互托管会话也适用。既有服务商 SDK 的传输重试仍受本次审核截止时间约束，不保证只发送一个 HTTP 请求。

区分分类器自身超时、用户取消与其他请求失败。主模型审核使用新的截止时间并结合原始用户信号，不能复用已到期的 fast 信号。接受 fast 阶段与回退审核的结果前，分别检查对应信号，避免迟到响应允许已取消或已过期的操作。

## 集成与可观测性

在共享分类器内部实现。CLI 调度、ACP 会话和托管工具轮次已消费其允许、拒绝、不可用契约。增加 `main` 结果阶段，并报告实际选择的模型；通过 Auto 决策传递阶段，不改变审批协议载荷。

诊断记录阶段、模型、结果与耗时，不记录提示词、工具参数、用户或会话标识及模型推理。主模型审核成功时，不将暂时的 fast 超时记为一次拒绝。

## 影响文件

- `packages/core/src/permissions/classifier.ts` 及测试：仅超时回退、独立取消预算、判决元数据和有限尝试次数。
- `packages/core/src/permissions/classifier-prompts/system-prompt.ts` 及测试：中性的完整审核指令。
- `packages/core/src/permissions/autoMode.ts` 及测试：共享结果阶段类型及既有结果处理。
- `docs/users/features/auto-mode.md`：说明自动回退和仍需人工确认的情况。

## 风险与取舍

仅 fast 阶段超时后增加延迟与模型成本。两个模型可能共享故障中的服务商或额度，因此第二次审核不保证恢复。标识相等判断无法解析所有服务商别名。本改动不会重新评判已完成的策略拒绝，也不修复过于保守的分类策略。

## 验证与验收标准

使用合成提示词、模型标识、命令和本地 mock 地址。不提交生产日志、客户标识、凭据或会话正文。

定向测试覆盖：回退允许与拒绝、相同投影上下文、显式主模型覆盖、中性指令、单次有限尝试、全新且可配置的截止时间、相同或未配置的 fast 模型、非超时失败、主模型失败、用户取消和迟到结果。既有显式 ask/deny、受保护写入和正常两阶段行为必须保持。

先对全局 CLI 运行确定性基线，再对构建后的本地 bundle 运行相同受控场景：延迟 fast 分类，随后主模型允许，应在不要求人工确认的情况下仅执行一次无害本地操作；主模型拒绝或不可用时不得自动执行，适用时仍保留既有人工批准流程。提交前完成构建、类型检查、定向测试和两轮连续无问题的自审。

## 未决问题

本范围无未决问题。独立超时配置、服务商回退策略、并行抢跑请求与权限策略变更均不在此次改动内。
