# Web Shell 审批模式白名单

[English](web-shell-approval-mode-allowlist.md) | [简体中文](web-shell-approval-mode-allowlist.zh-CN.md)

## 问题与范围

Web Shell 始终提供 default、auto-edit、auto 和 yolo，宿主及 settings.json 都不能过滤单个选项。本次新增展示过滤，不改变 daemon 权限、CLI/TUI 行为、Plan 行为或当前会话模式。

## 设计

在设置 schema 注册可选字符串数组 `ui.allowedApprovalModes`，不同设置作用域之间使用替换合并。该键收窄 shell 提供的审批模式，因此仅在操作者作用域（User、System、SystemDefaults）生效：仓库工作区设置中的值会被剥离并警告，工作区作用域的写入会被拒绝——克隆下来的仓库不得移除操作者设定的限制。通过现有工作区作用域设置响应提供该值，不在设置编辑器展示。复用已有运行时、信任和重新加载行为，不新增路由。

在 WebShellProps 暴露 `allowedApprovalModes`（WebShellWithProviders 同样继承）。显式传入的 Prop 优先于设置，空数组也算显式配置。未配置时默认提供全部四种执行模式。过滤未知值、重复值和 Plan，保留内置顺序。非数组的错误设置回退到全部模式；没有受支持模式的数组不提供任何选项。

App 和 ChatPane 共用 `useApprovalModes` hook，通过限定设置接口读取明确选中的工作区。主视图使用 `activeWorkspaceCwd`，不得从 legacy-primary 的设置编辑器数据推导此列表。解析后的主列表传给输入框下拉菜单、审批弹窗和自定义页脚。通过现有定制上下文传递宿主 Prop，使分屏和侧边任务的 ChatPane 输入框继承它。未传宿主覆盖值时，每个面板读取自身工作区的限定设置，并在设置事件后刷新；独立会话或读取失败时，不回退到主工作区设置。仅当 daemon 声明支持工作区限定设置能力时才执行读取；不支持该能力的 daemon 保持默认列表，重连后会重试读取。对支持该能力的 daemon，首次读取失败时不提供任何模式，而不是回退到默认列表——把拒绝解析为默认值会悄悄丢弃操作者设定的限制；重新加载失败时保留上一次的有效列表，下一次设置事件会重试。切换工作区或 daemon 客户端后，忽略过期响应和缓存值。快捷键循环使用同一列表，支持回绕；当前模式被隐藏时从列表第一项开始。空列表使循环不执行操作，并禁用下拉入口。快捷键选择已处于的模式不执行操作。Web Shell 直接选择模式也拒绝隐藏选项；Plan 切换保持独立，当前执行模式被隐藏时也不受影响。

过滤不会自动改变恢复或外部修改的当前模式，入口仍显示真实模式。这是 UI 定制，不是安全边界，其他客户端和 daemon API 仍可切换模式。

## 影响文件

CLI 设置 schema、生成的编辑器 schema 和工作区设置路由；Web Shell App 和 ChatPane、定制上下文、共享 plan-mode 工具、输入框、审批弹窗、设置展示、公开导出和 README；定向单元测试和浏览器测试。

## 验证与验收

- 未配置时，下拉菜单和弹窗恰好提供全部四种模式。
- 设置和 Props 均可过滤，Props 优先于设置。
- 下拉菜单、弹窗、自定义页脚和快捷键循环使用同一列表。
- 验证回绕、当前模式被隐藏、空列表、单项、非法列表及 Prop 动态变化。
- 验证作用域设置传递、操作者作用域之间的替换合并，以及工作区作用域的值会被剥离。宿主通过 `allowedApprovalModes` Prop 为不同嵌入实例设置各自的白名单，不改变审批执行约束及 Plan 切换。
- 构建、类型检查、打包、定向单元测试、明确使用模拟 daemon 的浏览器检查，以及两次连续干净的自审。

## 风险与待定问题

没有待定设计问题。独立会话上下文可能不提供设置，Props 在此场景仍可使用。设置加载完成前，UI 使用默认列表。实际权限始终由已有后端规则决定。
