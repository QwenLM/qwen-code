# 子代理容器执行（Track A）

[English](2026-09-12-agent-container-execution.md) | [简体中文](2026-09-12-agent-container-execution.zh-CN.md)

状态：后端及操作者/定义策略已实现。独立 Linux rootful Docker 验证覆盖较早版本，Podman/rootless 验证仍待完成。关联：#11695、#11696、#9556。

## 问题与现状

Worktree 隔离改变工作目录，但命令仍以宿主用户身份执行。文件工具在校验、权限准备、
执行和缓存维护阶段也直接调用宿主文件系统 API。仅替换 `FileSystemService` 或静态
shell 入口，无法迁移整个执行面。

现有 review 命令执行器提供了有用的容器策略：显式环境白名单、临时 HOME、按名称清理，
以及离线 build/test 命令。它专用于 review 的挂载布局不是通用工作区策略。
目前 install 使用普通容器网络，并没有仅限 registry 的出口控制。

## 范围与启用

本变更为普通子代理实现容器执行后端。父级模型循环及工具仍在本地运行。
每个受支持的子代理拥有独立环境；操作者的容器要求适用于所有普通兄弟子代理。
这是子代理执行策略，不是整会话隔离。

可信 CLI 操作者使用 `QWEN_AGENT_EXECUTION_BACKEND=docker` 或 `podman` 要求容器执行。
来自仓库文件的环境值不能启用或配置运行时。Agent 不提供 `execution_backend` 参数。
定义可声明 `executionBackend: container`；省略时继承操作者策略，定义不能降低该要求。
两者均未要求容器时，继续本地执行。
镜像使用现有 sandbox image 覆盖机制；模型参数不能指定镜像、挂载、运行时端点或任意容器标志。

首版后端仅在 Unix 宿主上提供。Windows、整会话 sandbox 和 Daemon/Serve 交接不提供 factory。
要求容器但 factory 不可用时，在启动子代理之前失败；factory 缺失不表示回退本地。

使用独立安装、完整打包的 CLI，在目标项目中启动
`QWEN_AGENT_EXECUTION_BACKEND=docker qwen`，随后普通 Agent 调度均要求容器执行。
使用 Podman 时将 `docker` 换为 `podman`。
操作者可导出 `QWEN_CODE_CUSTOM_SANDBOX_IMAGE` 选择其他工具链镜像。
工作区不能与 CLI bundle 或依赖查找目录在任一方向重叠，包括规范化后的别名和当前尚不存在的查找目录。
启动容器前，CLI 检查安装目录及 Node 依赖查找目录中是否存在指向保护范围外的链接，
防止通过可写工作区别名修改宿主随后加载的代码。
支持上移的依赖和始终留在保护范围内、目标已经规范化的包链接（允许普通的前导 `../`）。
拒绝安装/查找根目录及其祖先路径中的符号链接、外部或悬空链接、安装文件的硬链接和不可读取的目录。
因此不支持通过硬链接共享包存储的安装方式。
保守检查也可能拒绝共享 Node 查找目录中无关的链接包。
此时应在共享全局包目录之外本地独立安装，并启动
`QWEN_AGENT_EXECUTION_BACKEND=docker node --no-global-search-paths /path/to/independent/cli.js`。
该标志禁用 Node 的全局回退查找，但不会排除祖先 `node_modules` 目录，因此仍须独立安装。
不支持源码和 tsc 启动。开发 CLI 时，先构建、打包并准备 npm 包，
再独立安装且不保留源码工作区链接；代理工作区可使用目标 checkout 或独立 worktree。
CLI 重启时保留环境变量值，供 Node TLS 证书、设置插值等启动早期消费者使用。
父子进程通过私有元数据在加载环境文件之前恢复文件来源；任何作用域的文件都不能设置该元数据。
元数据保留在进程环境中，以覆盖 Shell、review 等普通子 CLI 启动；重载时同步更新，
保留被冻结或因读取失败而保留的值的来源。容器运行时客户端丢弃该元数据和全部文件来源的环境变量。

该策略可与 `isolation: "worktree"` 和 `working_dir` 组合。
它不扩展面向模型的 isolation 枚举，也不改变 `isolation: "remote"`。
与 `tools.codeModeOnly` 的组合会在容器启动前被拒绝；首版容器注册表只支持直接工具调用。

## 后端策略与定义边界

最初由模型主动选择的方式允许已启用的操作者能力不被使用。修订后，Config 中不可变的
要求与 factory 生命周期分离。派生的授权、worktree、workflow 和恢复上下文继承该要求，
关闭之后也不例外。每次调度只解析一次定义后端，校验、环境归属、hooks 和持久化元数据
均使用该结果。未知模型参数不能覆盖它。

定义解析后只允许字符串值 `container`。项目声明须位于可信工作区，与外部 executor 一致。
null、`local`、其他值、重复键、损坏的 YAML 及无效必填字段均须按声明名称拒绝，
不得回退到较低优先级的本地代理。保存、无关字段编辑、扩展和 SDK 会话对象均保留该字段。
消费会话对象时校验；不得过滤无效声明后继续初始化并使用内置代理。显式删除仅移除定义
偏好，不能移除操作者的最低要求。Claude 插件转换保留有效声明，被拒绝的源文件保持原样，
供扩展加载器记录拒绝。Daemon REST 和 ACP HTTP 创建/更新在现有已解析工作区及信任
检查内拒绝该字段，不配置运行时。

CLI 变量同时设置能力和要求。Core API 宿主可只注入 factory 而不设置默认要求，允许定义
单独选择。定义不能创建缺失的能力。本轮不新增 CLI 的仅启用能力设置。

Team、Arena、workflow、外部 executor 和保留的普通/fork 恢复路径没有容器生命周期，
要求容器时拒绝。直接构造 Headless 和当前 in-process Team 后端须在本地工具循环开始前
检查。可调用工具的内部 fork（记忆提取、dream、remember 和 skill review）也拒绝；
明确丢弃工具调用的缓存查询 fork 仍可用。不得清除派生策略来绕过限制。
Daemon、managed runtime 和 SSH 支持仍不在范围内。没有未决策略：定义可增强，
不能降低操作者的最低要求。

影响范围包括 Config 和 CLI 启用、Agent 解析、定义类型/解析/序列化、插件转换、SDK 类型
同步、直接运行时构造和两种 Daemon 修改协议。本次修订不改变传输和 worker 生命周期。

验收必须检查实际调度：省略或伪造模型选择参数不能使要求容器的子代理本地执行；factory
不可用时明确失败；可信定义单独选择有效；损坏的高优先级声明被拒绝；保存/SDK/插件
路径保留策略；不支持的入口和 Daemon 修改协议拒绝它。未配置策略的本地调度作为对照。

## 架构

Harness、模型凭证、授权和代理 transcript 留在宿主。容器 worker 执行现有工作区工具。
宿主使用有类型的执行契约，携带结构化准备信息和 `ToolResult`，而非纯字符串工具协议。

契约覆盖准备、确认、执行、修改和释放。用户修改绑定调度器的调用 ID，调用结束时丢弃，
因此相同参数的其他调用无法消费这份修改。宿主的同步工具构建只验证 schema，不调用原工具
依赖文件系统的 build 方法。原始 build 和路径校验在 worker 内运行。宿主保留工具的
classifier 参数投影。批准回调与修改后的内容经过同一个 invocation 边界；
worker 内的回调函数不会被当成数据序列化。

Worker 随所属子代理持续存在，使读取、编辑、notebook 准备及后台工具状态共享同一个
工具会话。Harness 的缓存失效必须传播到该会话。Worker 只接收工具必需的显式配置，
不接收模型提供商凭证、MCP 凭证、父 Config 对象或模型客户端。
显式工具配置保留文件过滤、新文件编码、shell 超时和心跳设置、输出捕获上限以及
截断设置，包括未设置阈值和零表示不限制输出的语义。

容器子代理不提供文件历史检查点、基于宿主路径的 IDE diff 和按路径自动触发的
rules/skills 激活，避免依据容器返回的路径读取宿主文件。内联确认 diff 使用 worker
提供的原文和修改内容。ToolSearch 在宿主 harness 内仅查询私有工具注册表，
保留延迟发现与权限拒绝行为。容器代理在每轮模型请求前刷新自己的工具声明；
揭示工具不会刷新父代理的模型客户端。

显式选择环境后才惰性启动执行。Worker 随已安装的 CLI 一起打包，并以只读方式挂载，
避免使用镜像中独立版本的 worker。开发验证使用由同一源码构建并独立安装的包。

## 执行归属

| 执行面                                                                  | 容器子代理中的归属                    |
| ----------------------------------------------------------------------- | ------------------------------------- |
| Read、Write、Edit、NotebookEdit、Glob、Grep、目录列表                   | 容器 worker，包括准备与路径解析       |
| Shell、shell 任务输出与停止                                             | 容器执行会话；宿主 PID 不代表容器 PID |
| 授权决定、invocation guard、模型请求、transcript                        | 宿主 harness                          |
| Worktree 创建、变更检测、保留与移除                                     | 宿主，执行资源清理之后                |
| 父会话 `!` 命令和 `@` 文件展开                                          | 父会话环境；本变更不引入会话级后端    |
| Monitor、嵌套 Agent、外部 ACP agent、自定义命令工具、skills、LSP 和 MCP | 首版容器工具注册表不提供              |
| 用户或子代理的可执行 hooks                                              | 拒绝不兼容组合，不静默禁用            |

容器子代理不能静默继承父级中绑定宿主的 discovered tools。
不支持的组合在子代理启动前失败。任何容器失败都不得转到本地后端重试。

## 文件系统与 Git 边界

只将解析后的工作树绑定到其规范化绝对路径。不得为满足工作树外的依赖符号链接扩大挂载。
使用临时 HOME；不挂载宿主 HOME、凭证存储、运行时目录或容器 socket。
同路径映射减少转换，但不构成授权：真正的路径解析和文件操作发生在容器内。

另将独立的临时输出目录以相同路径挂载给主 worker 和安装 worker。
Harness 也将截断后的完整工具输出写入此处，使安装 worker 退出后，恢复路径仍可读取。
该目录仅包含工具输出，随所属代理清理，不暴露宿主运行时目录。
临时根目录在解析符号链接后也必须位于可写工作区外，防止 worker 替换输出目录的父目录。
宿主持久化（包括截断和回退写入）以独占方式创建共享文件，不重新打开条目或按路径修改权限。
宿主不覆盖已有条目；写入失败沿用现有恢复路径。Worker 仍可修改共享输出内容。

使用空的只读挂载遮盖工作树的 `.git` 条目。Linked worktree 引用包含父级、兄弟状态及
潜在凭证的共享 common directory。只遮盖选定工作区根目录的 `.git`。工作区内的嵌套仓库和 submodule 仍属于可读写的
工作区内容，其中保存的凭证也可访问；这不是仓库秘密过滤器。
宿主仍能看到实际变更，并执行现有 worktree 保留规则。
Git 提交传递或私有 Git 元数据视图需要单独设计。

## 网络与凭证

普通命令、文件操作、build 和 test 均无网络。
明确识别的独立依赖安装命令可以在共享工作文件的另一安装容器中运行。
命令分类必须拒绝将复合 shell 表达式视作安装请求。
该例外允许普通网络，包括执行包生命周期脚本并访问可写工作区；脚本可以传输工作区内容。
为兼容依赖及工具链，继续允许生命周期脚本。仅限 registry 的出口或强制 `--ignore-scripts`
属于另外的策略变更。

两条路径使用相同的显式环境白名单及临时 HOME，不转发模型、GitHub、云或 MCP 凭证。
镜像与容器运行时属于可信基础设施。Rootful 运行时使用调用者的宿主 UID/GID，
因此 root 操作者会在容器内以 UID 0 运行。移除 capabilities 和 `no-new-privileges`
仍然生效；UID 映射不保证使用非特权用户。
首版不在现有整会话 sandbox 或 daemon/内嵌 bridge 启动的 ACP 子进程内提供该后端，
因为这些启动交接不保留环境来源。
强制请求容器后端时返回明确的不可用错误，不得自动挂载 Docker socket。

## 生命周期与恢复

选定环境在启动前记录每个容器名称，并在启动失败、前台完成、后台完成、取消、错误及
会话拆除时幂等清理。必须等待清理结束，再由宿主检查或移除 worktree。
仅终止宿主上的容器客户端不够。
调度器在工具终态释放 invocation 资源，包括宿主权限拒绝的调用。
安装执行结束但清理失败时，返回原始输出并附清理告警，保留 worker 归属，
让会话清理失败而不是删除工作区。前台及后台代理完成时也保留结果和终止状态，
附上清理告警；根会话继续拥有清理失败的资源。不能因为清理失败就重放已经完成的命令。
自动压缩历史会跨派生 Config 层级直接清理 worker 缓存。
失效请求失败会记录日志，但仍完成已经压缩的历史对应的 token 统计；下一次工具调用
仍须成功同步缓存才能继续。仅回收内存时不会清理 worker 的已读记录。
权限准备接收调用者的取消信号，释放 invocation 会中止仍未完成的准备。
创建容器可能需要先下载镜像，因此不受固定 30 秒上限限制，但支持取消。
运行时元数据查询和删除命令仍保留 30 秒上限。

首版不恢复已释放的容器子代理。扫描发现和直接恢复两条路径都必须拒绝。
在 sidecar 中写入容器 isolation 标记，使旧版读取器将其视为不支持的值；
工作树选项单独持久化。该协议兼容标记不改变 Agent 工具的 isolation 枚举。
仅新增未知后端字段不够，因为旧版读取器会忽略未知属性。

容器丢失表现为工具错误。可能已发生写入而响应丢失时，报告结果未知；
harness 不自动重放操作。取消和损坏的协议响应会使整个 worker 会话失败；
当前产品取消操作也会停止所属代理。静默跳过协议损坏可能掩盖丢失的结果，因此恢复能力后续再做。

宿主因 `SIGKILL` 等原因硬退出时无法运行上述清理，可能留下已退出的容器和临时输出目录。
首版没有启动清扫器；操作者手动移除之前必须确认资源归属且执行已经停止。
跨会话回收器需要另外明确归属和竞态规则。

## 影响范围

- Core 执行契约、本地工具会话、容器传输与 worker。
- Agent 工具参数、Config 派生、注册表归属和清理。
- Agent 元数据和后台恢复的两条路径。
- 文件读取缓存失效；现有文件系统服务 API 保持不变。
- CLI 可信能力启用及共享的 review 容器策略。
- Bundle 入口、针对性契约测试及 E2E fixture。

## 验证与验收

对本地和容器工具会话运行同一组契约用例：读写、先读后改、notebook 编辑、搜索、错误、
流式输出、取消和释放。运行宿主集成测试，证明父级及兄弟隔离、不回退宿主文件系统、
授权与 classifier 投影保留，以及拒绝不兼容恢复。
断言容器 argv、环境、挂载与网络分类。

先用全局 CLI 记录不支持的基线，再用确定性模型 fixture 驱动构建后的 CLI。
有真实 Docker 或 Podman 时，验证宿主标记凭证不可读、工作树持久化、网络拒绝、安装、
进程清理和容器死亡。模拟运行时测试只证明协议行为，不证明内核隔离。
明确报告无法执行的真实运行时测试。

[独立 Linux 验证](https://github.com/QwenLM/qwen-code/pull/11711#issuecomment-5645312113)
报告在 `ebae028529` 上使用 rootful Docker 26.1.5 完成十组 harness 和十三条 CLI 验证。
因无法拉取 0.23.3，使用已发布的 0.23.0 镜像；因 bridge 无公网出口，使用本地 HTTP tarball 服务。
该报告仍未验证 Podman、真实 rootless daemon 和配置的 0.23.3 镜像。
这些是外部报告结果，与本机进程夹具检查分别记录。

完成 build、typecheck、bundle 和针对性测试，随后进行两次干净的自审以及仓库的
代码审查流程，再声明完成。

## 后续能力

远程执行和环境资源属于 Track C；凭证代理属于 Track B。
Git 元数据传递、嵌套容器代理、容器会话恢复、外部工具及需要提供商的 vision 处理不属于
首版后端。图片、音频和视频读取（包括原生内联媒体）也不支持，因为 worker 不接收模型的
modality 配置。不支持的媒体读取会报告该限制，不得静默回退到宿主执行。
