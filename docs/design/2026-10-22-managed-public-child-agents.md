# Public Managed child agents

[English](2026-10-22-managed-public-child-agents.md) | [简体中文](2026-10-22-managed-public-child-agents.zh-CN.md)

## Status and problem

Implemented with public child delegation enabled by default for qualified new Sessions, integrated with main `605fd5ee17`. The approved design used main `4515275b1727e8f9b509e2c2aefe97e976293acf`; implementation uses the newer isolated checkout. Hosted child Sessions, result relay, task queries and durable cancellation were already available. Public Shell previously suppressed the child orchestrator. Removing that suppression alone would also expose teams, workflows and messaging, and the original child creation copied the parent's initial approval mode rather than the effective launch policy. This change adds explicit public admission and immutable launch policy.

## Admission and compatibility

`QWEN_MANAGED_AGENT_WORKSPACE_CHILD_AGENTS_ENABLED` defaults to true; set it to false to disable new delegation. Unsupported deployment profiles continue to start normally without public child admission. Only new built-in qwen-code Sessions on LOCAL storage, session-isolated durable local-process execution and `hosted-workspace-shell/1` qualify. Require `public-child-agents/1`, approval selection and matching internal child-close support. Persist `public_child_agents_version=1` on eligible Sessions; existing Sessions remain version 0. Children retain that provenance. The additive V17 migration leaves old rows at zero. Public and WebShell advertise `child_agents` and `childAgents` respectively; absence means unsupported. A version-1 root keeps its orchestration capability after the deployment switch is disabled so accepted tasks remain visible; current launch admission is checked separately.

Carry the public surface through create, load and recovery. Public Sessions expose only the ordinary tools and `agent`, with no team, workflow, messaging, isolation, custom definition or nested launch. Keep orchestration available for existing work after the deployment switch turns off, while refusing new launches. Private internal paths retain their existing tools. SSH, CSI/resident, workspace isolation and mount-owning MCP/Hooks remain excluded.

Recovery cleanup and targeted-cancellation loads carry the same public version and model route; SDK request copies also preserve the original prompt identity. A delayed cancellation fences children of that source only and releases a recovered lease only when it belongs to the original prompt, preserving later Turns. After an asynchronous child stop fence, cancellation rechecks the original recovery identity and any concurrent admission before synchronously claiming the Turn; repeated requests retain the same receipt.

## Execution and ownership

Reuse the existing child lifecycle and three distinct facts: terminal result, parent acceptance and parent consumption. The immutable launch resource records the source prompt and effective approval mode/revision, model and Skill snapshot. The trusted Harness constructs these fields before launch commits; replay uses the committed resource. Java creates exactly one child under the same tenant, Workspace, directory, pinned definition and recorded owner, preserving execution grants. Do not expose independent input, model or policy mutation on public children.

The model snapshot records the actual prepared request's model ID, parent model revision, authentication type, endpoint digest and provider-configuration digest. It carries no credentials or parent conversation. A child uses its own model revision 1, retains a matching default runtime model or resolves the exact configured route, and verifies the provider digest after authentication and before every request. When a parent request uses a fallback runtime view, an optional `origin` records the source model ID and route digests. A child restores and verifies that base, resolves the same fallback view, verifies its full digest and initializes the model client within the isolated runtime frame. No sampling values or credentials enter the envelope. Configuration drift fails closed. Recoverable public Shell approval batches carry this small route pin independently of full model-request capture; their original tool IDs and revisions survive restart. A pure Agent batch resumes without acquiring the parent mount.

Approval mode is fixed at launch, matching CLI/daemon timing. Later parent changes affect new children only. Preserve Managed default/auto-edit/yolo semantics without implicit privilege elevation. Default execution is background with a durable completion notification; foreground waits retain their existing mount restrictions. Keep depth 1, four active children and 64 launches per scope.

Parent Turn cancellation durably fences further launches and wakes from that source prompt, then records stop requests for its active children. Recovery continues the same requests. Other Turns' children remain untouched. Late results remain readable without restarting the cancelled parent work. Accepted command, recorded stop and physical termination remain separate; uncertain outcomes never imply success or automatic replay.

## Public APIs and WebShell

Extend existing action queries with optional `include_children`/`includeChildren`, default false. Aggregate the parent and direct children with per-Session read authorization, preserve the actual action owner and bind pagination to tenant, parent and aggregation mode. Responses continue through the existing owner Session route with its action/input/policy revisions and idempotency key; aggregation does not grant approval permission.

Refresh aggregated approvals serially every three seconds while the page is visible, independently of the task panel. Abort and discard stale requests on Session, account or Provider changes. Reuse the task panel for active count, pending approval, stopping state and actual child approval mode. Optional task metadata includes the server-wide Session count `activeChildCount`, durable `stopRequested` and the child's actual `approvalMode`; the count is independent of pagination and a stop request never implies termination. Read results through `childSessionId` and the existing transcript reader, with a return link that preserves the parent's draft. Track cancelled children until their authoritative terminal states; a completed cancel command alone is insufficient.

The [Session lifecycle UI](2026-10-22-managed-session-lifecycle-ui.md) remains available alongside child delegation. WebShell lifecycle capabilities retain their actor ownership checks, while public children keep their delegated-input-only and immutable-policy restrictions. Archive-filtered Session pagination and history export remain independent of aggregated Actions and the child transcript dialog; opening a child keeps the parent Session and its draft mounted. Contract version 1.87 includes lifecycle/export, checkpoint recovery, and public-child surfaces.

## Verification and rollout

Cover disabled/old hosts and Sessions, unsupported profiles, direct forged calls, foreground/background runs, write/Shell allow/deny/expiry/lost responses, immutable policy after a mode change and restart, cancellation/launch/completion races, duplicate commands, tenant and owner boundaries, revocation, paging, hidden panels, stale responses and multiple tabs. Restart Java/Harness during creation, foreground wait with a pending notification and result delivery. Verify scoped resource release and no replay of uncertain effects.

Run focused package tests, build/typecheck/bundle, Java Maven verify, disposable MySQL 8.4 and Linux real-process Hosted/WebShell acceptance. Validate contract/admission, execution/stop, and UI/qualification independently. Default enablement applies only after the existing runtime and Harness eligibility checks pass. Maintain the shared additive schema and inventory together without modifying published migrations. Keep this design bilingual and synchronize the E2E plan under `.qwen/e2e-tests/`. No unresolved product decisions.

Qualification uses local deterministic model endpoints and disposable databases. Record individual passing scenarios and interrupted attempts in the E2E report; a unit test, an HTTP-route test or a generic process-recovery test does not prove the entire public-child failure matrix. Browser rendering and multi-tab acceptance require separate evidence before a deployment advertises those scenarios as qualified.
