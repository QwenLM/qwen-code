# Java CI failure reporting

[English](2026-10-18-java-ci-failure-reporting.md) | [简体中文](2026-10-18-java-ci-failure-reporting.zh-CN.md)

Java failures must reach their author or the issue queue without requiring a search through Actions jobs. A manual SDK Java run on main (39042781121) failed while its failure reporter (39047669819) skipped every job. Approval-triggered Managed Agent runs are also excluded by the reporter's main-only branch filter, even when they finish after the PR merged.

Extend the existing failure reporter rather than creating another reporting pipeline:

- Continue reporting the existing main push and scheduled failures, and also accept manual SDK Java failures on main or a PR branch.
- Accept failed Managed Agent PR and approval runs. Resolve their PR by the exact head SHA against the repository's pull requests; the run's `pull_requests` array can be empty, and an approval run records the base repository as its head repository, so the SHA — not a source-repository filter derived from the run — qualifies the PR (a same-named branch on an unrelated fork carries a different SHA). Ignore superseded heads and PRs closed without merging.
- Post or update one PR comment per failed run, listing failed jobs with direct links, failed steps, and identified tests. A merged PR also routes to the existing issue deduplication and autofix assignment, except for a rerun of its pre-merge workflow (attempt 2 or later): a rerun keeps the comment but opens no issue, because it would describe a head main has already replaced. An unreadable attempt still files. A rerun recovers its tracking link from the earlier attempt's comment on a best-effort basis; if that comment was never published or has been deleted, the comment ships without the link. An open PR gets the comment without opening a main-regression issue.
- Keep the existing one-time infrastructure retry for main and merged PRs, and failing-test issue deduplication. A merged PR's rerun gets neither a retry nor an issue — only the PR comment. Open PR infrastructure failures get a comment without dispatching a privileged rerun. On the infrastructure path, only a successfully dispatched retry suppresses a report.
- Treat a job that exceeds its `timeout-minutes` as a reportable cancellation. GitHub concludes such a run `cancelled`, which is indistinguishable at the run level from a concurrency supersede; the job annotation "The job has exceeded the maximum execution time" is what separates them. A cancelled run whose annotations were read and carry no such message is a supersede and owns nothing. A cancelled run whose annotations could not be read is reported rather than dropped — a misclassified supersede costs one comment, a dropped timeout costs the regression.
- Admit `cancelled` only for the destinations the existing allow-list already admits: main push/schedule runs and a `workflow_dispatch` of the admitted workflows. Scoping is what keeps a superseded `Managed Agent gate` PR run from being reported as a job timeout on the contributor's PR.
- Rerun a timed-out run whole, not one-for-one: no job has a `failure` conclusion for `rerun-failed-jobs` to select. The rerun's own completion re-enters the workflow and reports the result, so the occurrence is filed then. Bound the reruns at attempt 3 — two whole-matrix reruns before the first report — so a lane that keeps exceeding its cap eventually files instead of rerunning forever. A timeout inferred from an unreadable annotation list is reported but never buys a whole-matrix rerun; replaying what may be a superseded matrix is the expensive mistake. A timeout on a provisional report files rather than deferring, because the head it tested is already replaced and its rerun could not re-enter.
- The rerun inherits the filing, so `file_issue` alone cannot gate both the dispatch and the issue. When the destination defers a timeout's filing it records `rerun_pending` instead, and files if that dispatch later fails; a skipped rerun files nothing here, since a provisional or unreadable-annotation run files through its own path.
- A timeout cancels the run's siblings; only the job whose annotation named the timeout is reported and its log fetched. The renderer is fed that curated set rather than the full job list, so a five-shard matrix names the one lane that broke instead of all five.
- Prepare the PR summary before issue lookup so an issue API failure cannot swallow the comment. Retry comment lookup and publication up to three times, re-reading before each write to avoid duplicates.

The read-only analyzer checks out only the default branch, never the triggering PR. The comment and issue writers check out nothing and execute no repository code; report strings travel through environment variables and body files. PR matching requires the destination repository, the `main` base branch, the current head SHA, and an open or merged state before allowing a comment or an issue. Untrusted PR code cannot obtain the bot PAT or create an autofix-approved issue before merge.

Verification replays real failed-run metadata, exercises PR resolution and comment upsert through a fake GitHub CLI boundary, and checks the existing parser/deduplication and infrastructure-retry behavior. Live dispatch and publication are separate from local verification.
