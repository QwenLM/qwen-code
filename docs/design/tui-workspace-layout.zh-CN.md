# TUI 工作区布局与过程摘要

[English](tui-workspace-layout.md) | [简体中文](tui-workspace-layout.zh-CN.md)

## 问题与范围

当前虚拟对话列表会随短对话缩小，输入框紧跟消息。弹窗替换底部控制区，打开时会
挤动对话。工具摘要只合并同一调度批次的调用，连续的思考、过程说明和命令仍然形成
很长的执行日志。

基于当前主仓继续改进视觉层级，不查阅旧 UI worktree。保持原始历史、工具执行、
审批和终端协议不变。主要目标是默认的 Ink 虚拟视口。

## 设计

虚拟对话列表即使内容为空或很短，也填满分配给它的高度。输入区和 agent 标签栏
占用底部行。其他嵌入列表保持按内容收缩的现有行为。

普通弹窗在对话之上的绝对定位覆盖层中居中显示。宽高受终端限制，空间允许时保留
外边距。高终端中的设置与会话悬浮窗最多占 32 行；设置列表保留原有最多八项的限制，避免撑满
整个屏幕。保留现有键盘归属和内部列表导航。底部输入区显示为不可操作的预览，不挂载
第二个活动输入组件。弹窗绘制不透明背景，防止底层文字穿透。认证流程保留原有
不截断的行内布局，避免隐藏供应商表单所需输入。读屏与原生滚动历史布局保留线性
呈现方式。

弹窗专用尺寸上下文向布局组件提供这些边界，覆盖会话恢复与删除、回退与差异、hooks、
extensions 及其嵌套列表。用于鼠标坐标和终端协议的物理 `useTerminalSize` 保持不变。
悬浮窗内的会话预览使用可滚动视口，避免 `<Static>` 输出在打开或返回预览时打印到
覆盖层之外。独立选择器和线性布局中的预览保留原有终端历史呈现方式。

仅在展示层投影中，跨相邻历史条目合并成功完成的工具批次与已完成思考。只有同一
连续过程后续出现工具批次、确认其为中间说明时，才允许折叠 assistant 文本。末尾
回答保持可见。错误、取消、运行中工具、审批、图片、专用工具结果及其他状态记录
保持可见，并分隔过程段。原始条目、ID 和源码复制索引仍为权威数据。摘要是一行
灰色操作计数，思考耗时与唯一展开提示进一步弱化。全局详情模式恢复原始顺序；
鼠标展开保留可点击并带收起提示的摘要，展示紧凑的命令和文件路径目录。
完整思考与原始工具结果仍可通过 Ctrl+O 查看。两种交互都不修改存储历史。

手动展开过程组后，保留摘要，并让每个原始成员作为独立虚拟列表行。
安全工具调用采用紧凑语义行；已完成思考不再在聚合耗时下面重复折叠标题。
打开过程不会强制所有成员进入完整详情。明确展开的思考保持可见，Ctrl+O
恢复完整原始顺序与输出。成员保留原始引用、源码复制偏移和各自测量后的
可见状态：不能仅因摘要可见，就为视口外的已展开思考启动 Thinking Mod。

单独的工具批次打开后也保留摘要。成功完成且可安全汇总的读取、搜索、列表
和 Shell 调用展示逐条紧凑目录，并提示通过 Ctrl+O 查看原始输出；专用和交互
结果保留已有渲染器。再次点击摘要就能收起。由显式子成员展开而打开的过程
保留父摘要；关闭父摘要时清除子批次展开键和思考头。拖选后的松手不会切换
标题。原生滚动历史保留仅键盘的回退方式。

## 涉及区域与约束

改动限于 CLI UI：工作区布局、虚拟列表尺寸、弹窗边界、过程投影、摘要渲染和针对性
测试。共享工具分类仍与丢弃工具结果的规则分离；折叠命令不能丢失输出。先对已提交
和待提交的重复批次去重，再聚合。源码复制偏移在投影之前按原始记录计算。原生
`<Static>` 历史保持只追加，不回溯合并条目。实验性 OpenTUI 的表现单独报告，保持
现有渲染可用。

## 验证与验收

使用隔离的确定性 OpenAI fixture 和任务专属终端会话。记录全局 `qwen` 基线，验证
当前 bundle 在 100 × 32、40 × 16 和高终端的表现。检查启动及短回答后输入贴底、
多行输入、长历史滚动、窗口缩放、弹窗导航和 Esc，以及弹窗背后不能输入。检查连续
思考、过程说明、读取和命令被聚合，最终回答保留；详情模式应恢复顺序和输出。错误、
审批、取消和图片必须可见。验证深色、浅色、NO_COLOR 与读屏回退。截图使用 Chrome
Canary。运行构建、类型检查、bundle、针对性测试、格式与 lint 检查、两轮干净自审
及独立审查。

## 风险与待定事项

聚合改变虚拟条目几何，成员和展开状态变化时必须使缓存高度失效。覆盖层尺寸必须
与子弹窗使用的宽度一致。不能依靠推测模型阶段隐藏运行中记录或最终回答。通过
投影、布局回归测试及真实终端验证这些约束。无需新增配置或依赖。
