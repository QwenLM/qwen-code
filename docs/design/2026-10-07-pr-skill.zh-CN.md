# `/pr` 内置技能

[English](2026-10-07-pr-skill.md) | [简体中文](2026-10-07-pr-skill.zh-CN.md)

## 状态

已在本 PR 中实现（issue #13509）。`.qwen/e2e-tests/2026-10-07-pr-skill.md` 中的 E2E
计划已部分执行：`prepare`、非 GitHub 远端的预检停止以及 usage 路径已在一次性本地仓库上
通过；从默认分支和从特性分支运行 `create`，以及幂等的重复运行，已在真实 GitHub 仓库上
以交互方式通过。询问后更新、未提交改动的选择以及 AUTO 模式尚待执行。

## 问题

贡献流程中的 issue 一侧已由 `/create-issue` 覆盖了从起草到提交的全过程。而发布
PR 是最不可逆的一步，却没有交互式的负责方：用户要么手写标题和正文，要么由模型
即兴执行 `git push` 和 `gh pr create`，在模板、未提交改动、已有 PR、哪些命令需要
确认等方面没有一致的规则。现有的 `.qwen/skills/prepare-pr` 是非交互式的 CI 契约
（为 autofix 和 repo-hygiene 写出 `pr-title.txt` 和 `pr-body.md`），并且刻意不做
push。

## 目标 / 非目标

目标：

- 提供由用户触发的 `/pr` 技能，根据当前分支起草 PR 标题和正文，并可选地推送、
  创建或更新 PR。
- 适用于任意仓库：读取仓库自身的约定，而不是硬编码格式。
- 所有会产生变更的命令都保持在常规确认之后。
- 在收到 review 反馈后重新运行，既不会失败，也不会产生重复的 PR。

非目标：

- GitLab / `glab`，以及 `/mr` 别名（`SkillConfig` 不支持别名）。
- 无 `gh` 时的回退方案（push 加 `compare` / `pull/new` 链接）。
- `/pr edit` 和 `/pr view`。
- 权限规则中的参数级排除（属于单独的核心改动）。
- 修改 `.qwen/skills/prepare-pr`，其 CI 契约保持不变。
- 提交代码。`/pr` 从不 commit。

## 设计

### 命令

该技能位于 `packages/core/src/skills/bundled/pr/SKILL.md`，因此在每个仓库中都可用。

| 命令                                     | 行为                                                                  |
| ---------------------------------------- | --------------------------------------------------------------------- |
| `/pr`、`/pr prepare`                     | 起草并展示标题和正文，不发布任何内容。                                |
| `/pr create [--draft] [--base <branch>]` | 推送分支并创建 PR；若已有 PR，则在询问后更新。`--draft` 创建草稿 PR。 |

其他任何参数都会打印用法，并且不执行任何操作。

### 流程

`prepare`：

1. 在一个只读批次中收集分支状态、upstream、远端和仓库元数据，然后确定基础分支
   （见下文）。
2. 读取仓库约定（见下文），以及该分支相对基础分支的提交和 diff。
3. 按照 PR 模板和提交风格起草标题和正文，将正文写入 `.qwen/tmp/qwen-pr-body.md`，
   并打印草稿。不推送，也不创建任何内容。若 `gh` 不可用，`prepare` 会跳过 `gh`
   查询、说明这一点，并基于 `git` 数据继续。

`create`：

1. 预检，此时尚无任何变更：已安装 `gh`，`gh auth status` 成功，且推送远端是
   GitHub 远端。否则打印明确的提示并停止。
2. 工作区，在起草之前检查：处于 detached HEAD 或 merge、rebase 进行中时停止。若
   存在未提交的改动（CLI 自己的 `.qwen/tmp/` 临时文件除外），列出文件并询问。选择
   “先提交”则停止并打印一行可直接复制的 `/commit ...`；选择“不含这些文件继续”则
   继续，并在输出中列出被排除的文件。
3. 执行 `prepare` 的步骤以得到草稿。
4. 分支：若位于默认分支，提出分支名建议，确认后执行 `git switch -c`。
5. 推送分支（需确认）。
6. 用 `gh pr view` 查找该分支的 PR。查询出错与确证不存在是两种不同的结果；出错时
   停止。
7. 不存在 PR：将 `gh pr create --body-file ...` 作为独立的前台命令运行（需确认）。
8. 已有打开的 PR：展示其 URL，以及标题和正文与草稿的差异，询问用户，仅在回答
   “是”时运行 `gh pr edit`。
9. 已有已关闭或已合并的 PR：询问是否创建新的 PR。
10. 打印 URL、标题、基础分支，以及未纳入 PR 的文件。

基础分支的确定顺序：`--base`，否则取已有 PR 的 base，再否则取 `gh repo view` 返回的
仓库默认分支（fork 则取上游仓库），`gh` 不可用时取远端的 `HEAD`。从不硬编码
`origin/main`。

推送远端的解析顺序：`branch.<b>.pushRemote`，然后 `remote.pushDefault`，然后
upstream 所在的远端，然后唯一的远端，否则询问用户。从不使用 `--force`、
`--no-verify` 和 `--amend`，也从不绕过失败的 hook。

### 权限模型

`allowedTools` 只增不减（`packages/core/src/skills/types.ts`）：它只授予规则，从不
限制。匹配基于前缀，且没有排除语法（`packages/core/src/permissions/rule-parser.ts`
中的 `matchesCommandPattern`），因此 `Bash(git push)` 也会匹配 `git push --force`，
`Bash(gh pr create)` 会匹配任意参数。所以允许列表无法区分安全形式与危险参数，该
技能只授予只读规则：

- `gh auth status`、`gh repo view`、`gh pr view`、`git config --get`
- read、glob 和 grep 工具
- `Write(/.qwen/tmp/**)`：仅限 `write_file`，且仅限项目根目录下的 `.qwen/tmp/`
  临时目录（开头的 `/` 相对于项目根目录）

所有会产生变更的命令（`git switch -c`、`git push`、`gh pr create`、`gh pr edit`）
都走常规确认。只读的 git 命令（`status`、`diff`、`log`、`rev-parse`、`remote`、
`branch`）已由 `shellReadOnlyChecker.ts` 自动放行。不带限定的 `run_shell_command`
规则被归为危险规则（`dangerousRules.ts` 中的 `isDangerousBashRule`），在 AUTO 审批
模式下会被暂存，因此不使用。该技能设置了 `disable-model-invocation: true`，只有用户
可以触发。

### 与会话 PR 绑定的集成

该技能通过 shell 工具驱动 `gh`，而不是使用 `packages/core/src/utils/github-prs.ts`。
通过 shell 工具运行 `gh pr create` 是已有插桩的路径：
`commandRunsGhPrCreate`（`packages/core/src/services/session-pr-service.ts`）会在
运行前对分支做快照，`bindGhPrCreate`（`packages/core/src/tools/shell.ts`）会将创建
出的 PR 绑定到会话。因此技能会指示模型把 `gh pr create` 作为独立的前台命令运行，
不要放进子 shell、不要用 `&&` 串联、也不要放到后台。`gh pr edit` 不会被绑定；在
更新路径上，会话保留原有绑定，这是可以接受的。

`github-prs.ts` 仅作参考：`gh pr view --json` 的字段集，以及
`BranchPullRequestSnapshot` 中 `none` / `error` 的区分，其中 `none` 表示确证不存
在，`error` 则不是。

### 仓库约定的发现

技能在运行时读取当前仓库：PR 模板（`.github/pull_request_template.md` 及其变体）、
`CONTRIBUTING`、`AGENTS.md` / `CLAUDE.md`，以及 `git log` 中的提交信息风格。它从不
硬编码正文格式；若没有模板，则用简短的文字说明改了什么、为什么改。

## 决策与理由

- **内置技能，而非项目技能。** 适用于任意仓库，并随 CLI 一同发布。备选：放在
  `.qwen/skills` 中，则只存在于本仓库。
- **通过 shell 工具使用 `gh`，而非 `github-prs.ts`。** 技能是提示词，无法导入模块；
  要访问该模块需要新增核心工具。`createGitHubPullRequest` 只能创建，没有 edit 封装，
  因此更新部分无论如何都要调用 shell。进程内创建还会绕过 `commandRunsGhPrCreate` 和
  `bindGhPrCreate`，丢失会话 PR 归属。备选：新增面向 agent 的核心工具。
- **只读允许列表。** 无排除语法的前缀匹配无法表达“允许 push、禁止 force-push”。
  备选：看似精确的变更类规则（`Bash(git push)`），但仍会匹配 `--force`；不带限定的
  `run_shell_command`，属于危险规则且在 AUTO 模式下被暂存；权限系统中的参数级排除，
  属于单独的核心改动。
- **`--body-file .qwen/tmp/qwen-pr-body.md`。** 避免 markdown、`$(...)` 和引号带来的
  转义问题。该命令本来就会提示确认，所以文件不会增加审批面。备选：内联 `--body`。
- **`disable-model-invocation: true`。** 发布不可逆，应要求用户明确表达意图。备选：
  允许模型调用，已否决。
- **更新已有 PR 前先询问。** 其他人可能已在阅读该 PR。备选：静默更新，或直接失败；
  前者会让 reviewer 意外，后者会破坏 review 反馈循环。
- **`/pr` 从不提交，而是指向 `/commit`。** 内置的 `/commit`
  （`packages/cli/src/ui/commands/commit-command.ts`）已实现选择性暂存以及 hook 和
  密钥策略。打印另一个斜杠命令有先例：`/goal-draft` 打印 `/goal set`，`/batch` 建议
  `/batch-api`，`/review` 建议 `/review --fix`。备选：在 `/pr` 内部提交，会重复实现
  该策略。
- **仅支持 GitHub。** 在任何变更之前判定；非 GitHub 远端会得到明确提示。备选：支持
  `glab` 或无 `gh` 的链接回退，均推迟。
- **基础分支依次取 `--base`、已有 PR、`gh repo view`。** 可处理 fork 和非 `main` 的
  默认分支。备选：硬编码 `origin/main`。

## 风险

- 模型偏离文字规则。缓解：所有变更命令始终需要确认，且允许列表只含只读规则。
- 若模型包装了 `gh pr create`，会话绑定可能丢失。缓解：明确指示独立运行。
- 模板填写质量因仓库而异。
- 已知限制：设置了 `tools.executionSandbox` 时，技能命令会被拒绝
  （`packages/cli/src/services/BundledSkillLoader.ts`）。
- `gh pr edit` 不会绑定到会话；更新路径保留其原有绑定。
- PR 署名：shell 工具只会把 `gitCoAuthor.pr` 的署名行（"Generated with Qwen
  Code"）追加到内联的 `--body`/`-b` 中，而不会追加到 `--body-file`
  （`packages/core/src/tools/shell.ts` 中的 `addAttributionToPR`）。因此即使开启了该
  设置，`/pr` 创建的 PR 也不带署名行。这适合禁止在 PR 中提及 AI 的仓库，但与手动输入
  `gh pr create --body` 的行为不同。若要遵循该设置，需要 shell 工具支持
  `--body-file`，或由技能自行追加该行；留作后续工作。
- `cd <dir> &&` 前缀会让只读的 `git status` / `git diff` 需要确认，因为切换目录后，
  目标仓库的 git 配置（例如 `core.fsmonitor`）可能执行命令
  （`packages/core/src/utils/shellAstParser.ts`）。这在真实运行中被观察到；技能现在
  要求模型在当前目录下运行每条命令，不加 `cd` 前缀。
