# Web Shell 文件树上传

[English](web-shell-file-tree-upload.md) | [简体中文](web-shell-file-tree-upload.zh-CN.md)

## 问题与范围

文件面板已能浏览工作区目录，但无法接收本地文件。为文件树侧栏添加文件拖放上传，
在底部固定显示细进度条。复用已有工作区上传接口和队列；不修改后端、SDK、依赖或
输入框行为，不支持递归上传本地文件夹。

## 预期行为

- 拖到目录行时上传到该目录，包括折叠的目录；拖到文件行时上传到其父目录。
  侧栏空白处始终对应工作区根目录，不受选中项或筛选条件影响。
- 只处理文件拖放，忽略拖入的本地目录；拖动时显示目标位置。即使无法上传，也取消
  到达文件面板的文件拖放默认行为，包括预览容器和工具栏。根目录目标提示使用工作区名称，
  不显示协议中的根目录标记。
- 复用 `useFileUpload` 的顺序上传、进度、限制、取消、服务端安全编号和错误处理。
  遵守 `fileUploadEnabled` 和 daemon 公布的 `workspace_file_upload` 能力；
  文件树的明确目标不使用输入框的默认上传目录。
- 上传属于文件标签页对应的可信工作区，即使该标签页不同于当前会话。工作区有公布
  的 ID 时必须支持限定工作区的 REST，禁止回退到主运行时。
- 等待或上传时在侧栏底部固定显示进度条，队列结束后隐藏。收起树时进度条显示在
  文件面板底部。失败提示保留在分栏上方并可关闭，收起树不会隐藏。通过一个礼貌的
  状态区域播报最终结果，避免为每个失败文件创建强制播报。
- 将服务端确认的路径插入文件树，保留展开、选中、筛选和预览状态，清除父目录的
  空目录提示。切换工作区或撤销上传能力时中止并清空队列。

## 实现与决策

`useArtifactWorkspaceTarget.ts` 通过已有的所有者权限检查，在上传请求前后校验
所有者，提供可选的上传动作。上传要求明确可信且唯一公布的所有者，旧读取行为保持
不变。`WorkspaceFileBrowser.tsx` 使用该动作和已有上传 hook。通过原生拖放事件
的 composed path 识别 Pierre shadow DOM 中的树行，通过树自身的目录元数据判断
目录目标，包括刷新尚未完成时由上传路径恢复的祖先目录。CSS Module 提供目标提示和三像素底部进度条。复用已有上传翻译，新增
目标位置文案同时提供中英文。

汇总进度覆盖当前队列，成功通知消失后仍保留其字节统计。队列空闲时清空统计，
上一队列尚未消失的成功通知不会计入新队列。进度表示已传输字节。
进度条持续显示直到服务端确认完成。界面不会覆盖已有文件：已有接口会自动为同名
文件编号。

## 验证与验收标准

定向单测覆盖能力门控、可信工作区归属、过期所有者、宿主禁用覆盖、公布的大小限制、批次数量提示、礼貌错误播报及已有队列行为。浏览器 E2E
使用实际 Pierre 树和模拟 daemon，覆盖根目录、嵌套或折叠目录、文件行拖放、
二进制字节、进度可见性及吸底位置（包括收起文件树）、成功通知消失后进度稳定、
后续队列重新统计、可读目标提示及拖离清理、成功插入、错误、非文件拖放、目录拒绝和上传
不可用状态。如可用，真实 daemon 检查验证实际文件字节和同名编号。截图只说明
界面行为，并明确标注模拟 daemon。提交正式可评审 PR 前完成构建、类型检查、
定向测试、lint 和连续两次无问题的完整差异审查。

## 约束、风险与待定问题

本地文件夹上传及新的手动取消按钮不在范围内，保留切换目标和卸载时已有的中止行为；
取消无法撤回服务端已经发布的文件。拖放目标依赖
Pierre 既有的行路径属性和 composed 事件，因此必须有浏览器覆盖。嵌入预览 iframe
内部的事件属于其自身文档，不在容器级保护范围内。没有未决产品问题。
