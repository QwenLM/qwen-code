# Web Shell 可选传输能力

[English](web-shell-optional-transport-capabilities.md) | [简体中文](web-shell-optional-transport-capabilities.zh-CN.md)

## 问题与范围

嵌入式传输可以支持流式 Prompt，而不提供可选的 daemon 摘要和原生待处理 Prompt 路由。自动摘要和队列同步必须遵守能力声明。使用 `optimisticUserMessage=false` 时，权威用户回显还会晚于浏览器开始发送；以旧用户消息作为计时起点，会短暂显示上一轮的耗时。

本变更修正浏览器对现有传输契约的处理，不新增 daemon 路由、认证机制或持久化客户端队列。

## 决策与约束

- 仅在声明 `session_recap` 时注册自动摘要。
- 仅在声明 `session_prompt` 时查询原生待处理 Prompt。缺少该能力时，会话活跃期间将普通排队消息保留在本地，随后通过普通流式动作逐条发送并等待完成。发送前重新检查归属、取消和宿主策略。提交结果不明确时不自动重放。
- 中途注入与原生排队能力独立。显式宿主 hold 仍然阻止注入；仅缺少原生排队能力不能阻止已声明的中途注入能力。
- 紧急 Prompt 状态不能配对此前转录结构的延迟快照。纯流式尾部追加仍保留延迟路径。
- 浏览器发起的 send 在结束前记录其会话 ID 和本地开始时间。两种聊天布局在权威用户回显之前使用该起点。清理仅移除同一次操作的记录，避免旧请求完成后清掉新归属的状态。此状态不发给 daemon。远端恢复中的轮次仍保留权威起点。

本地队列条目仍只存在于浏览器，不能保证刷新后保留。缺少原生排队能力的传输不能展示其他客户端的原生待处理消息。具备原生能力的路径保留既有行为。

## 验证与验收

修改生产源码前，复现缺少能力时仍然调用接口、仅流式传输误走原生队列，以及用户回显前计时起点旧了一小时。验证具备能力的对照、逐条完成、发送失败处理、中途注入独立性和远端恢复计时。验证本地计时在完成、取消、拒绝及归属替换后的清理，保留 UI 结构一致性和流式节流覆盖。

组件及协议夹具测试必须与浏览器端到端验证区分。这些回归不依赖真实账号或特定服务商入口。合入前运行受影响测试、构建及 bundle、类型和格式/lint 检查。宿主集成的浏览器验证仍是独立验收。
