# 选择性导入 Codex 记忆

[English](codex-memory-import.md) | [简体中文](codex-memory-import.zh-CN.md)

## 问题与当前状态

Codex 使用跨项目经验手册和短摘要，Qwen 使用带类型的主题文档及生成索引。把整份手册复制到 Qwen 索引会丢失归属并占用上下文预算。用户需要离线、可预览的导入，且不能启动模型会话或修改源文件。

交互预览已支持审阅大量条目。剩余归属失败来自自然语言范围说明，以及真正共享或不可用的项目范围。本轮更准确地识别明确归属，再将其余条目作为明确标注的全局候选，使每条安全候选都有导入目标。

## 预期行为

`qwen memory import codex --dry-run` 预览 `memory_summary.md` 和 `MEMORY.md` 的候选条目。`--source` 指定来源目录，`--project-map` 读取将源工作目录映射为本地项目目录的 JSON 对象，`--select` 接受候选 ID。未指定 ID 时，TTY 打开带导入确认的交互审阅，脚本环境只预览。只有确认导入或显式指定 ID，且未指定 `--dry-run` 才写入。`--json` 输出完整预览供本地检查。

从摘要提取用户背景和偏好列表，从手册的已识别章节提取偏好、可复用知识和经验。每项都是待显式审阅的候选，不代表历史观察仍然成立。不导入原始会话、rollout 摘要和技能。补充修改／删除记录作为待审阅材料展示，不将其当作命令执行或静默导入。应用选择前，预览必须显示尚待核对的来源修订。有补充记录时，脚本应用要求传入预览的 `--review-source <sourceDigest>`；交互确认明确认可已审阅说明并传入所展示的摘要；来源变化则要求重新审阅。

## 交互预览

只有计算得到的 `preview.dryRun` 为 `true`、stdin 和 stdout 均为 TTY、且没有指定 `--json` 时，才使用独立的 Ink 界面。这包括未传 `--select` 的默认预览和显式 `--dry-run`。通过条件检查后才加载界面；JSON 和非 TTY 输出保持现有格式，且不加载 UI。显式 `--select` 的实际导入命令继续直接走现有导入流程。打开预览不初始化 Agent、模型或会话，也不发起网络请求。

界面分为分组、条目和详情三层。已解析目标的项目条目按原生目标目录分组，以解析后的主项目作为可读标签；用户级记忆独立成组。全局回退条目单独显示在 `User memory (global fallback)` 分组。列表和详情明确标注回退，保留已知来源项目，并通过 `scopeReason` 说明归属失败原因。所有可导入候选（含全局回退）默认勾选供审阅。被阻止的条目仍不可选择。进入分组前显示数量及状态汇总。在不同分组间切换时保留已选候选 ID。补充来源记录和解析／规划警告合并在一个可阅读的 `Source notes & warnings` 审阅分组中，不作为可导入候选。

| 按键                 | 行为                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| `↑` / `↓`、`j` / `k` | 移动可见列表中的焦点。                                                   |
| `Enter`              | 打开当前分组、条目、补充记录或警告。                                     |
| `Space`              | 切换当前分组中的可导入条目或当前 `ready`／`duplicate` 候选。             |
| `Esc`                | 从详情返回条目，再返回分组；在分组层取消。                               |
| `d`                  | 关闭 dry-run 预览；普通模式打开导入确认（与 `i` 相同）。                 |
| `i`                  | 打开导入确认；`--dry-run` 时禁止导入。                                   |
| `a` / `n`            | 全选可导入候选／清空全部选择。                                           |
| `o`                  | 在条目列表或详情中，用默认编辑器打开当前条目、来源记录或警告的完整文本。 |

复用现有 `RadioButtonSelect`，以复选标记展示由父组件管理的选择状态，并使用终端尺寸及按键工具。通过 `MarkdownDisplay` 在有边界的详情视口中渲染经过清理的来源文本。详情超出视口时，明确显示截断提示和 `o` 操作。代码围栏内容（包括 Mermaid）保持为普通文本；预览渲染不得触发图形、终端视觉内容或代码执行。窄终端和窗口尺寸变化后，导航及当前选择仍须可用，不得把整份记忆集合打印出来。

`o` 操作按需在仓库、来源目录和原生记忆目录之外的私有临时目录中创建仅供审阅的快照。在这次显式操作中，宿主会在创建产物前拒绝位于来源目录、原生记忆目录或任何 Git checkout 内的临时根目录。目录权限为 `0700`，文件权限为 `0600`；包含完整的已清理审阅文本和来源信息，并保留规划器已有的凭据脱敏。复用现有编辑器交互，提供只读 `SettingsContext` 占位上下文，不调用 `loadSettings`。独立界面使用现有 Hook 的平台默认编辑器，不读取已保存的 `preferredEditor` 设置。绝不打开源文件供编辑，不将编辑器修改读回选择结果，也不应用修改。审阅产物保留到预览正常结束或取消，以便异步 GUI 编辑器完成打开；之后删除产物，清理失败时报告错误，不打印产物内容。创建或打开审阅产物失败（包括 Node 只读文件系统权限下的失败）时，保留可用的预览界面并显示错误。在用户按下 `o` 之前，交互预览不创建任何目录或文件。

使用已有 CommonMark 解析器处理 Markdown。根层标题定义归属和支持的章节；章节内的下级标题保留其正文，遇到另一个支持的章节则开始独立条目。有序和无序列表逐项处理。忽略分隔线，跳过代码块及不支持的块并报告来源行范围或行号。合并检查同层全部 `applies_to` 和 `cwd` 元数据；尾部分隔符不影响比较，不解析 `..`，保留原始路径拼写。

## 归属与目标目录

摘要中的背景／偏好属于用户级。手册中有可靠项目归属的条目仍属于项目级，包括反馈。解析明确的 `cwd`，先应用精确 `--project-map`，再将 Git worktree 和子目录归一到主 checkout。非 Git 目录保留明确范围。保留 submodule 和独立 clone 的边界，不凭目录名称或 remote 猜测仓库。Git 归一只验证文件系统元数据，不执行 Git 或访问网络。确定归属后才加载运行时设置和原生记忆目标。Qwen 日常按 worktree 隔离的召回不变：导入内容属于界面显示的主 checkout 范围，不会自动在关联 worktree 中被召回。预览明确说明这一限制。

识别明确 cwd 后带或不带反引号的分支说明、描述性 worktree 说明，以及本机操作系统安装引用。主 cwd 后的 `(rollout metadata cwd=...)` 仅作为历史来源，不覆盖主归属。`cwd=/work/atlas or atlas worktree on release/example` 这类命名备选，仅在项目名与路径 basename 完全相同时保留明确项目。不得静默丢弃其它绝对路径、名称不匹配的项目、额外 cwd 或未知后缀。保留引用路径原文，以及候选 ID、正文和日期。

无法确定归属时，将条目作为原生用户记忆中的**全局回退候选**。适用于多项目、通配或缺失范围、不支持／无效元数据、其它平台路径、缺失／非目录目标，以及无法验证 Git 主 checkout 的情况。这不意味着来源本来就是全局：`scope: "user"` 表示实际导入范围，`scopeReason` 独立保留归属失败原因，不被去重／冲突的 `reason` 覆盖。保留已知 `sourceProject`，只有确定项目目标时才提供 `resolvedProject`。正常项目条目使用 `scope: "project"`。JSON、纯文本、分组／列表／详情和全文审阅均读取实际范围并明确标注全局回退。可导入的全局候选默认勾选，在确认页明确计数，只有确认导入或脚本显式选择后才写入。已知项目搬迁时，精确项目映射可以使其继续属于项目级。

先检测凭据，再进行范围回退；被阻止的内容不会因此变为可导入。来源文件缺失／无法读取、映射非法、原生目标不安全、台账损坏仍是命令错误，不被全局回退掩盖。使用私有原生用户／项目目录，拒绝仓库内本地记忆及来源／项目 checkout 内的目标。规划过程不写设置、不初始化模型、不调用 Agent Hook、不访问网络。

## 去重、冲突与持久化

对目标目录中的全部原生文档做规范化后的精确内容比较，包含超过常规索引上限的条目。不声称能够判断语义等价或矛盾。同一导入身份内容变化，或原生文档同标题但内容不同，均报告冲突，绝不覆盖。独立 JSON 台账保留来源身份、内容指纹和目标文件名，原生维护修改或删除文档后仍保留台账。已导入但目标缺失的记录继续跳过，防止遗忘后复活。来源 ID 与内容指纹分离。实际导入时，还会保存该目标下可导入来源候选的指纹和 ID，包括未选中的候选；dry-run 不保存此快照。后续预览先按历史指纹匹配未改变的内容，再考虑位置 ID，避免删除或重排相邻条目后，未导入条目继承已导入条目的身份。正文修改继续遵守原位置的冲突与遗忘保护。未知的新内容若占用了已移动条目的位置，仍以独立 ID 报告保守冲突，需要在单独的来源章节中审阅。旧台账仍受支持，但缺少候选历史时不能追溯识别从未导入的条目。历史只保存哈希和 ID，不保存来源正文。只有明确选中的 `ready` 项才创建新的主题文档；选中的 `duplicate` 项只在台账中记录处理结果，不再创建主题。选中冲突则停止写入。已知来源更新时间予以保留，未知时间明确标注。

独占导入锁防止并发导入。加锁后重新计算，通过排他创建写入主题文件，保守持久化台账防止失败重试重复导入，最后重建原生索引。失败明确报告，不盲目重试或覆盖用户内容。源文件和已有主题文档保持不变。预览不创建记忆目录、索引、台账或锁。唯一可选写入是用户通过 `o` 显式请求的私有审阅产物；选择条目或未确认导入即关闭均不写入任何内容。

新主题文档包含原生结构化元数据：由来源类型确定分类，由主题／类型生成两个不同的规范化关键词，并由主题生成一个有长度限制的使用场景。过程确定、离线，无需后台元数据迁移。显式选择已导入且主题完整的条目时，可以修复失败的索引，不改写主题或台账；缺失主题仍保持遗忘。进程中断留下的锁，需要确认没有导入进程运行后再手动删除；错误给出锁路径和恢复步骤。释放某个锁失败时，仍会尝试清理其它已获取的锁。

## 文件与范围

CLI 命令及启动路由注册；`packages/cli/src/commands/memory/` 下的 Codex 解析器及导入规划／写入逻辑；使用现有终端组件的独立交互预览；相邻合成测试；用户文档。复用原生路径解析、扫描、凭据检测、索引生成及编辑器交互。项目归一仅用于此导入器。不修改核心召回，不接外部 Provider，不自动同步，不调用模型做语义判断，不迁移技能。

## 隐私与限制

绝不提交真实来源记忆、预览输出、用户专属路径或生成台账。写入测试只使用临时合成数据；真实数据只进行 dry-run，只在 Git 外保存汇总证据。已知凭据特征会阻止候选且不回显凭据内容。共享范围回退会扩大到用户级可用，因此审阅时必须明确展示。确定性冲突检测采取保守策略，但不具备语义判断能力；用户必须检查选中文本和来源修订。支持范围外的 Markdown 结构明确报告，不猜测。

编辑器快照包含私有审阅文本，和预览输出一样必须保存在 Git 之外，且仅由显式 `o` 操作创建。关闭预览不代表认可来源修订。导入确认明确声明已审阅来源说明，并将所展示的来源摘要传入写入器。

## 验证与验收

先验证全局 CLI 帮助基线，再用构建后的命令测试合成来源／目标目录。验证预览无写入、精确项目映射、用户／项目隔离、去重和冲突、显式选择、重复导入、已修改和已遗忘目标、损坏台账、符号链接／不安全路径、凭据脱敏，以及原生索引／解析兼容性。完成构建、类型检查、定向测试、打包、连续两轮干净自审和独立审查。本地真实 dry-run 前后计算来源和目标文件哈希，只在 Git 外保留汇总证据。本次没有实际记忆写入授权。

本次预览调整保留全局 `qwen --help` 不包含记忆功能的基线，并用当前实现的 bundle 复现冗长的纯文本输出。随后在 PTY 中使用多项目合成数据运行重新构建的 bundle，验证三层界面、跨组选择保留、不可选行、来源记录和警告、有限详情及尺寸变化、编辑器查看全文、取消及产物清理。验证 `o` 之前不创建文件，审阅产物满足权限和位置要求，只读文件系统错误不会终止 UI。JSON 必须仍可解析，非 TTY 输出保持格式，显式应用命令绕过界面，所有预览路径均不得初始化模型、发起网络请求或写入原生记忆。只使用合成数据，在 `.qwen/e2e-tests/codex-memory-preview.md` 记录 UI 基线及结果。

主项目归属使用真实临时 Git 仓库验证，覆盖两个 linked worktree、嵌套目录、submodule 和独立 clone。检查目标目录相同、来源保留、跨 worktree 去重和主项目已有记忆冲突、映射优先级、损坏或不支持元数据的保守失败，以及项目分组。离线 dry-run 期间禁用 Node 文件系统写权限。

验证自然语言范围及尾随其它项目的反例、各类归属失败的全局回退、明确范围字段、可见的全局选择及确认数量、用户范围共享去重／冲突、凭据阻止，以及合成条目显式选中后写入用户记忆。对同一真实来源在禁写条件下复验，对比候选 ID／正文／日期与已解析项目，单独汇报回退数量及原生用户记忆数量。

## 默认选择与交互导入

默认选中全部可导入的 ready／duplicate 候选，包括明确标注的全局回退项。明确提供初始 ID 时只选择对应条目，明确的空列表则保持空选。被阻止、冲突和已导入条目不勾选。复用现有列表：`a` 全选可导入候选，`n` 全部清空，分组层的空格切换该组可导入条目，条目层的空格仅切换当前条目。

在 TTY 中不指定 ID 执行 `memory import codex` 后进入审阅，按 `i` 打开导入确认。摘要展示选中候选数量、项目／用户目标及全局回退数量，并提供导入和返回操作。存在来源修订说明时，导入操作明确声明已审阅说明，不能把关闭预览视为认可。确认返回带类型的导入动作，仅由 CLI 控制器调用现有写入器。写入器在创建目标目录和锁之前重新核对所展示预览的来源摘要，包括没有说明、说明新增或删除的情况；来源变化必须重新审阅。复用现有规划、去重／冲突检查及写入逻辑，完成后输出简短结果，不逐条打印全部记忆。

明确的 `--dry-run` 始终禁止导入，不因选择或 UI 返回动作而改变。页脚说明去掉 `--dry-run` 后重新启动的方式，结束 dry-run 仍只预览。JSON 和非 TTY 模式未指定 ID 时仍只预览；明确的 `--select` 保持原有脚本应用行为。UI 显示选中候选数量，不承诺新增文件数量，因为去重会按最终选择重新计算。

验证默认／全选／清空／整组选择、明确 ID、主要操作提示、确认／返回／取消、来源说明认可、PTY 中真实写入合成目标、简短结果、过期来源拒绝，以及 dry-run 永不应用。写入测试全部使用隔离合成记忆；真实记忆保持只读，绝不进入 Git。
