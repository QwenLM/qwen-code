# K2 private generic read, PUT and callback boundary

[English](2026-10-10-k2-private-generic-retention.md) | [简体中文](2026-10-10-k2-private-generic-retention.zh-CN.md)

Status: bounded generic implementation independently accepted for its exact fixed Java sources after baseline reproduction and two measured regression repairs. Refs #13395 and Draft PR #13526; complete K2 and maintainer architecture review remain open.

## Problem and current behavior

The generic resource reader creates a generic delivery lease, verifies bytes and updates last_verified_at without excluding a stored private Session. Generic publication streams and PUT admission have the same gap. Existing ReadLease.check relies on its in-memory identity and old SQL lease; close deletes by ID alone. PUT completion writes UNKNOWN or RETURNED without requalifying the current stored publication and attempt. Quarantine and abandon callbacks lock a publication but do not current-check its private parent or recheck the complete target tuple.

The native owner reader already uses its independent original authority and durable OPEN/RETURNED/UNKNOWN history. Generic paths cannot stand in for it. A private history is still private when only its profile changes while its original request pin remains.

## Goals and scope

Refuse unsupported generic private read/open/PUT admission before new leases, metadata writes or physical I/O. Independently refuse old private lease checks/cleanup, PUT completion, quarantine and abandon mutations, preserving every existing private value. Qualify the actual stored publication/object/attempt or exact persisted lease hashes instead of caller JSON or claim memory alone.

Keep ordinary missing-public-Session, resource validation, original non-private deferred_v3 publication and supported ambient transaction behavior. Retired ordinary Sessions still permit cleanup of old leases and settlement of an already started PUT. The background collector/quota increment is separate. No new schema, native reader, native publication permission, application cut, drain, finalization, physical release or public selector is introduced here.

## Qualification and transaction order

Use the original same-DataSource TransactionTemplate, joining supported ambient callers. Each independent admission/check/close/completion starts or joins a short transaction: discover stored target, lock retention tenant, current FOR UPDATE TRUE exclusion, then its necessary head/publication/lease/attempt child locks and exact tuple verification. Private semantic refusal throws and rolls back any tenant upsert. No late placement lock, REQUIRES_NEW connection or global change to lockSession/requireLive is added.

Generic resource metadata requires its own participating transaction: R→G before head/grant and a current locked resource read, complete resource scope/storage validation and last_verified_at UPDATE. Lease admission alone is insufficient when its standalone short transaction has already committed. Return only the verified resource snapshot for subsequent I/O; do not extend a standalone SQL transaction across that I/O. Its existing scope and credential validation remains necessary. Generic lease admission independently excludes private targets. The owner-native reader and its direct same-UUID lease completion do not instantiate generic ReadLease and keep their original continuation path.

Store.requireEvidence genuinely calls the generic resource reader inside apply's existing transaction after retention tenant, original placement/parent and head/publication locks. The exclusion reuses those held domains. It must not try to acquire a new placement parent after children. A standalone ReadLease.check cannot take TRUE parent first: a later failing check cleanup may take retention tenant in the same ambient transaction, introducing the inverse edge. Both check and close follow retention tenant then current TRUE exclusion.

The support claim is limited to the actual same-DataSource transaction wiring and known consumers. A caller that already holds unknown child locks, mismatched transaction manager, raw promotion or future same-ID reassociation is not qualified by these method names. Independent full-schema RC and warmed RR measurements must retain exact connection, isolation and held-lock observations; source inspection alone cannot prove the whole deployment lock graph.

## Admission and persisted identity

read(String/JsonNode) excludes the current target before its head lock and lease INSERT. readPublication discovers the actual stored tenant/workspace/Session tuple outside its admission TransactionTemplate, then rechecks that same publication under R→G→head in the admission transaction before issuing a lease. Standalone target discovery must not establish an early RR read view before waiting for R: an independent MySQL comparison reproduced a new post-retirement lease when discovery was moved inside the template. Restore the original snapshot placement while retaining the full locked target recheck. Do not add a new retention-state restriction to ordinary readPublication. Previously warmed arbitrary ambient snapshots remain outside the qualification claim.

Every existing-lease check current-qualifies its internal original tenant/Session, then verifies the persisted lease ID, tenant_key, session_key, retirement generation and expiry. Close locks the exact lease and refuses a mismatched persisted hash tuple; its DELETE includes all identity predicates. Private old leases stay unchanged. Ordinary expired/retired leases remain removable, and an absent ordinary lease may close idempotently. The in-memory close latch must follow transaction completion. Mark a successful delete pending only after SQL succeeds; register afterCompletion to reset it on rollback or an unknown outcome. A participating REQUIRED callback return is not an outer commit. Private or SQL refusal leaves the latch retryable. Verify close→outer rollback→close against the restored row. The latch is not native read completion evidence.

Check and close take R→current G→exact lease; they do not read or change the journal head and omit the new redundant head lock. Admission/publication/metadata retain their head locks. Check reads the database clock and the original non-locking retirement result together in one statement after acquiring the exact lease lock. This keeps the post-lock expiry time, adds no retirement-row lock, and retains every physical delivery guard. An actual 8 MiB HTTP download reproduced 442 checks and 3408 statements versus the original 750, exceeding the unchanged 2800 bound. The reduced query cost must satisfy that existing test for both full and 4096-byte adapter reads without caching checks or changing guard timing/thresholds.

PUT admission discovers the actual stored publication, qualifies it before head/child writes, then rechecks the complete tuple and caller key. Existing requireLive and PINNED conditions remain admission requirements. A standalone call commits one new IN_FLIGHT attempt before physical PUT. Existing supported ordinary ambient behavior may retain the caller transaction across I/O; this increment does not add fresh-boundary semantics to that ordinary path.

Each completion independently discovers the actual attempt's scope/publication/object key and the publication's current target; after qualification it locks and compares publication and attempt against the admitted identity. Only that IN_FLIGHT attempt can become UNKNOWN or RETURNED; a zero-row completion must refuse, not silently return success. Completion does not impose new requireLive/PINNED conditions: ordinary retirement during I/O must retain the original completion semantics. A new successful retry never resolves a different UNKNOWN attempt. Private refusal keeps the old attempt unresolved and propagates success-path failure before any later catalog installation.

These exclusions cannot undo an already admitted old physical I/O. A frozen IN_FLIGHT/UNKNOWN row remains a blocker and does not prove physical completion or stopped writers.

## Cleanup and primary errors

lockRetainedPublication current-qualifies the actual target and rechecks tenant/workspace/Session/scope/publication after locking; existing PINNED/RETIRING conditions remain. This protects only its actual quarantineResource, DataStore.abandonScan, quarantine and quarantineCandidate consumers. quarantineResource also locks and rechecks the actual object slot/resource/object key before publication/object writes.

Private callback refusal is visible to the caller. On an existing primary failure, cleanup refusal or SQL failure is attached as suppressed. Preserve the original exception object/type/message. PUT UNKNOWN completion, finish's candidate quarantine and publish's candidate quarantine currently lack that protection and must use the existing suppressed-error pattern. Successful completion refusal remains an error and must not silently allow DataStore.install to continue.

DataStore.verify currently probes bucket versioning before retention.open. Move this existing preflight after qualified readPublication lease admission and lease.check, preserving the versioning check and original guarded object open. Count bucket probes separately as physical calls; constructor startup probes are outside per-invocation admission. An old admitted invocation may already have physical I/O in flight and cannot be undone.
