# 从侧边栏将会话添加到分屏视图

[English](sidebar-session-split-view.md) | [简体中文](sidebar-session-split-view.zh-CN.md)

## 问题与当前行为

Issue #14775 希望在侧边栏会话菜单中增加“添加到分屏视图”。
目前用户必须先通过底部入口打开分屏，再使用会话选择器。
App 持有面板列表；SplitView 已支持添加会话、去重和六个面板的上限。

## 拟议改动

- Sidebar 默认动作列表新增仅在下拉菜单出现的 `split` 动作，
  提供英文和简体中文文案。沿用现有动作白名单、屏幕大小能力、
  忙碌状态与工作区资格检查。只允许普通工作区会话（包括缺少来源元数据
  的旧会话），与分屏会话目录一致。归档、渠道、独立、Live、未知工作区及
  不可信工作区的会话不提供此动作。
- App 在分屏打开时追加选中会话；分屏关闭时，菜单打开选中会话，
  并在当前会话属于工作区时将其一起加入，不恢复旧面板列表。
  底部入口仍保持恢复旧列表的既有行为。打开时复用现有分屏打开流程与会话分类。
  等待打开期间的添加操作合并到当前分类代次的选择中；导航离开会取消待处理选择。
  追加时沿用面板内选择器的同步面板更新：Sidebar 已将目标限制为符合资格
  的活跃工作区会话，因此可以保持现有面板及未发送附件。
  对于控制面板列表的嵌入宿主，通过现有变更回调提出请求，
  仍由宿主决定何时应用变更。等待分类期间只合并宿主已通过受控属性接受的会话 ID。
- 重复会话不会重复添加。已有六个面板时禁用添加新会话，
  并显示现有限制说明；保留已有面板。
- SplitView 收到外部新增面板时退出最大化并激活新面板，
  与现有会话选择器的行为一致。

## 设计决策与范围

保留 Sidebar → App → SplitView 的职责分工。菜单发送操作意图，
App 组合会话 ID，SplitView 渲染并管理面板焦点。
复用已有工作区分类、provider、Radix 菜单及 portal。
无需修改 daemon、SDK、桌面 Rust、CSS、快捷键、传输机制或归档生命周期。
桌面端加载同一个 Web Shell。已有分屏传输限制不属于本功能范围。

## 验证与验收标准

通过真实菜单验证当前与选中会话一起打开、追加时不替换已有面板、
重复添加无效以及六面板上限。验证另一面板最大化后新增面板仍可见。
离开已有六个面板的分屏后，菜单仍应打开当前与选中会话。
验证独立会话分类延迟、面板身份保持以及连续追加，包括首次打开期间的
连续添加、去重、容量限制及导航取消。
检查中英文文案、动作白名单、归档及不符合资格的会话、可信次工作区、
小屏幕、受控嵌入，以及原有底部入口和选择器行为。

运行定向单元测试和浏览器测试、构建、类型检查、打包，并在本地
Docker Linux 中重跑相关测试。基线与验证结果保存在
`.qwen/e2e-tests/14775/`。
