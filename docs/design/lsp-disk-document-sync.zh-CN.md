# 原生 LSP 的查询时文档同步（PR1）

[English](lsp-disk-document-sync.md) | [简体中文](lsp-disk-document-sync.zh-CN.md)

原生 LSP 查询此前只打开每个 URI 一次，之后不再刷新文本。现在服务按服务器和连接
保存已交付的磁盘文本及版本。在位置和文档查询之前，服务读取目标文件，只发送所需
通知。每个连接的版本从 1 开始，在交付变更时递增，也包括强制预热。新连接丢弃旧连接
的状态；配置重载为重启的服务器重放当前磁盘文本，同时保留未变更服务器的状态。

无论写入者是 edit/write 工具、钩子、shell 命令还是手动编辑器，下次查询目标时都会
覆盖已保存的变更。不覆盖未保存缓冲区和编辑时反馈。#3170 的编辑时 `didSave` 工作
与此互补；#3029/#3034 的诊断工作及 #11418 的文档更新仍独立进行。

初始化仅保留 `textDocumentSync`。数值 Full/Incremental 隐含打开/关闭支持；选项
对象分别遵守 `openClose` 和 `change`。Full 发送新文本。Incremental 替换整个旧文档
范围，使用 UTF-16 代码单元，并将 CRLF、LF 和 CR 视为换行。None 或缺失能力不授权
发送变更通知。只有不抛错的通知发送才记录快照（不代表服务端 ACK）。不支持 `openClose` 的服务器既不接收
`didOpen`，也不接收无对应打开的 `didChange`；它自行从磁盘加载，编辑后仍可查询。
如果客户端已打开的文件发生变更而服务器不支持变更通知，同步抛出不支持同步的错误
并跳过请求。读取或不支持变更的失败会关闭已打开文档、释放全文，并让当前调用失败。
不支持变更时会停放 URI，供后续使用当前磁盘文本重新打开。关闭失败保留待关闭错误、
版本和读取失败计数；后续同步（包括工作区诊断）在重开前重试关闭。关闭成功后
后续调用可以恢复。同连接关闭/重开即使文本相同，版本也保持递增；仅连接替换重置
版本。普通变更发送抛错保留旧快照和可重试版本。发送返回绝不代表服务端确认。

TypeScript 预热将交付委托给同一个服务辅助方法。强制预热即使文本未变，也发送能力
允许的 `didChange`，递增版本而不重复 `didOpen`。已同步且支持通知的预热仍等待稳定，不警告。能力确实不支持通知时（包括强制预热
未变文本但不支持 change），管理器记录包含
服务器和能力的警告，并记录已尝试预热，避免重复扫描。实际的回调、读取或发送失败
会被捕获，保持可重试，包括强制尝试失败后。延迟的预热不会将替换连接标记为
已预热。普通的未变更查询不发送通知。只有新打开才触发
文档查询的等待和重试，变更不会。工作区符号预热区分找到可用文件和发送打开通知：
存在文件时，自行读盘的服务器在每次调用中也会获得索引等待和空结果重试。没有预热
文件时，两者都跳过。重载重放仅在交付了通知时等待稳定。

调用层次项包含可选的客户端 `documentRevision` 字段，经工具 JSON 和原生客户端
原样回传。原生 incoming/outgoing 调用要求有效来源信息，不会将旧偏移应用于新文本。
一个小型 HMAC 使用实际规范化的 LSP 项参数、服务器名称、文本摘要及已交付版本，将项
绑定到具体连接。签名递归排序 JSON 对象键，但保留数组顺序，因此等值工具 JSON 的
键顺序变化不会被拒绝，实际值发生变化仍然无效。`WeakMap` 为每个连接保存一个随机
密钥，不维护已签发项的注册表。
客户端字段绝不转发给语言服务器。签发结果前，对请求前捕获的快照检查磁盘文本、
已交付版本、活动句柄和连接；对于这些请求前快照，其他查询的同步或连接替换不能将旧响应认证为新响应。
incoming/outgoing 调用在预热前后及请求后进行验证。陈旧、缺失、修改过或未知的来源
信息会拒绝操作，工具明确提示 “prepare call hierarchy again”，绝不显示“没有调用”。
跨文件 prepare 结果仅在其文件已有请求前快照且仍新鲜时认证。其他结果保持无签名，
即使响应后文件可读：响应后的读取无法证明服务器使用了哪份文本。遍历无签名项时，
错误指出该项自身的 URI，要求在该文件的当前位置重新 prepare。签名不发送通知，也不发起额外请求。
查询目标仍在其请求前捕获快照，并跨 await 绑定到原始句柄和连接。绝不使用返回的旧偏移自动 prepare，也不按名称猜测。嵌套的 incoming/outgoing 项仅在
请求前已观察其文件时获得来源信息；未观察文件的嵌套项仍可显示，但继续遍历之前必须
在当前位置显式 prepare。无关嵌套文件漂移或不可读也仅保持无签名，不丢弃健康兄弟项。根目标新鲜度或连接
变化仍拒绝整个请求，包括空响应和请求错误。非文件 URI 保持无签名，并提示
“cannot be traversed; prepare at a file location instead”，不提示可重试的陈旧错误。
普通非文件请求保持透传。

## 边界

- 工作区符号仍只进行预热。可选预热失败记录日志但不取消搜索。自行读盘服务器的
  成功发现结果按连接缓存；重新检查可读性而不保留交付文本，候选删除则重新发现，
  无候选时不负缓存。工作区诊断还会在带结果数量限制的循环内，为每个被查询
  的服务器同步已跟踪文档（默认限制 100）。不会发现更多文档，也不会同步达到限制
  后被跳过的服务器。已跟踪指在本连接上已交付、或由更早的连接变更或可恢复同步失败停放；重载快照与
  sweep 使用同一并集，重载的清空会消费该停放集。重连同步打开全部已跟踪 URI 后，
  仅为新打开统一等待一次；
  didChange 不等待。该 await 期间连接替换会拒绝，而非查询未同步的新连接。
  固定等待不证明服务器分析已完成。待关闭文档会重试关闭，不发现额外文档。工具可选的首个符号引用查询以文档为目标，同样会同步。
- 不增加文件监视器、编辑时反馈、IDE 缓冲区、安装、工作区级依赖新鲜度保证或诊断
  推送/拉取重构。读取观察的是磁盘快照，不是与并发外部写入者的原子事务。自行读盘
  的服务器在文本未变时没有客户端交付版本；两次观察之间先变更再恢复相同文本的
  外部编辑无法被检测。
- 文档和工作区诊断在同步失败时拒绝，即使此前已有服务器返回诊断。工作区同步失败
  （已跟踪文件不可读或被删除、发送抛错、不支持变更）不会被普通拉取请求的捕获逻辑
  吞掉，也不会返回空结果或部分成功。已跟踪 URI 首次读取失败后仍停放，包括 ENOENT；
  连续第二次读取失败仅将该 URI 从停放集移出，两次观察到失败的诊断调用均拒绝。
  共享同步辅助方法将此上限应用于普通查询、预热和 sweep，按实际读取次数
  而非调用次数计数。读取成功清零计数，新连接重置计数和版本。从未跟踪的文件首次
  查询不可读时，不创建重放义务。逐出后后续 sweep 可以继续；文件恢复后需通过成功的
  文档定向查询重新纳入跟踪。逐出保留同连接版本及待关闭状态。不支持变更和发送抛错
  不消耗读取重试次数。配置重载重放仍在交付前消费停放集；保留重载失败交付的义务
  继续延后。管理器捕获内部的
  TypeScript 预热错误；其他预热文件失败不会阻止查询已同步目标。传播的失败使用
  工具已有的失败提示，而不是声称结果干净或完整。成功的空诊断仍显示为干净。除
  调用层次来源处理外，已有请求/拉取及公共查询的捕获逻辑不变，可能返回空数组或
  null；这些**不能证明诊断干净**。更广泛的错误结果设计仍属于 PR2。
- 传输不确认通知交付。本变更不重构异步写入或已关闭连接的处理。

## 成本

可同步目标查询读取并比较完整磁盘文本，即使大小和 mtime 未变。不支持通知且
未跟踪的普通目标跳过读盘，但层次来源验证仍观察磁盘。保留的快照内存
与每个服务器连接已交付的文档成正比，直到清除跟踪。层次遍历仅捕获一次快照引用，并复用不可变快照的文本摘要。预热前、预热后、
响应后及错误路径的每个检查点都重新读盘；结果批次仅同步共享每 URI 的观察，
绝不跨 await 缓存。每项独立 HMAC 包含规范化参数、文本摘要及版本；连接密钥采用弱引用，不随签发项数量增长。普通未变更
查询不发送通知。Full 和 Incremental 都发送全部新文本；Incremental 还会扫描旧
文本以计算范围。只有大文件测量证明必要时才升级到最小差异。20 项同 URI 遍历测试要求目标读取三次（正常路径每个检查点一次），而非每项
一次；错误路径另加新观察。prepare 后，20 项遍历创建 23 个小 HMAC（3 次根验证
加 20 项），保留快照的全文哈希次数为零，未跟踪的自行读盘快照为一次。这些是
测试断言，不是真实服务器延迟保证。这是基于观察的保证，不是与外部写入者的原子事务。

## 验证与文件命名

聚焦测试覆盖全部十条文档查询路径、文本未变/变更、每 URI 版本（同一连接先编辑 B
再编辑 A）、数值/选项同步能力、UTF-16/CRLF 替换、连接替换、限定范围的配置重放、
重载后恢复的旧查询、预热交付与恢复、TSX 语言优先级、读取/发送失败（包括第二个
文档打开失败）、精确请求 URI/位置、恢复 mtime 的同大小编辑，以及独立进程保存
目标。调用层次测试覆盖工具 JSON 往返、嵌套项、移动行的编辑、其他查询、自行读盘
服务器及在途响应竞态。固定工作区诊断顺序、结果限制范围及符号重试行为。实际客户端
和工具测试验证：已跟踪文件被删除、发送抛错或工作区变更不受支持时拒绝操作，包括
此前已有服务器返回结果的情况，同时保留普通拉取请求的捕获逻辑。初始化测试通过启动路径
验证能力的产生。变异检查必须杀死下列每个具名变异体（除注明外均位于
`native-lsp-service.ts`），并使所列测试变红：R1-5，`ensureDocumentSynchronized`
返回恒为 `true` 而非打开标志（`does not delay or retry an empty query after
didChange`）；R1-6，`lsp-server-manager.ts` 的预热 catch 重抛而非返回
（`contains TypeScript warmup callback failures`）；R1-8，快照写入移到 `didOpen`
发送之前（`retries a failed second-document didOpen at version 1`）；R1-10，hover
发送结束位置而非起始位置（`sends the requested hover URI and start position`）；
R1-11，同步读取首个被跟踪文档而非请求的 URI（`keeps text and versions independent
for two documents`）；R1-12，委托的语言 ID 失去相对扩展名推导值的优先级
（`preserves the extension-derived language ID in a TSX-only warmup`）；R1-13，
重载同时清除未变更服务器的跟踪（`retains the unchanged server snapshot when only
its sibling reloads`）；R1-15，强制预热传入 `false` 而非强制标志（`forces
unchanged TypeScript warmup with a monotonic didChange before retry`）。R1-14 是
阴性对照：将 `constants.ts` 中的 `DEFAULT_LSP_WARMUP_DELAY_MS` 提高到 300 后，
`preserves replayed snapshots` 仍须通过。

按照 AGENTS.md，涉及的服务、管理器及其相邻单元测试此前已重命名为 kebab-case。
其聚合导出、原生客户端类型导入、集成测试和直接 E2E 测试框架导入已更新。公共类名
和根聚合导出名不变；仅涉及导入的旧文件未重命名。旧 PascalCase 子路径导入不再
解析。公共管理器预热方法现在要求返回交付状态（`boolean`）的同步回调，并返回
`Promise<void>`，而非 `Promise<string | undefined>`。可选 `documentRevision`
字段保留项结构的兼容性，但原生遍历缺少来源信息的旧项现在会明确失败，要求重新
prepare。仓库内调用方已迁移；外部兼容性策略仍需维护者确认。
