# 自定义命令的文件内容保持字面值

[English](./2026-10-15-custom-command-file-literals.md)

## 契约

命令定义是模板，`@{...}` 读取的文件是数据。文件中的 shell 表达式、参数占位符及未闭合的模板语法必须保持原样。模板自身的 shell 审批、拒绝和转义规则不变；读取失败仍显示现有占位符和错误提示。

TOML 与 Markdown 加载器均使用命令工厂，按 AtFile、Shell、DefaultArgument 顺序执行。不能倒置顺序，否则用户参数及 shell 输出中的路径可能被重新解释。审批重试从原始模板重新读取文件。

## 修改

用 CLI 内部 WeakSet 标记 reader 返回的每个 part，先将原始字符串转换为 text 对象。Shell 处理器在提取文本前检查对象身份，原样透传已标记的 part。保留顺序执行及目录标题、多媒体的排列，不增加协议字段、序列化元数据或解析器。模板片段继续使用现有解析器；默认参数追加位于最后，不再需要来源标记。

信任边界是文件 reader 的输出。当前工厂在两处理器之间没有克隆或序列化；未来新增文本解释阶段必须保留并检查该边界。本修复不声称保证任意未来流水线安全。

## 验证

真实 CLI 基线尝试审批文件中的 `!{echo FROM_FILE}`，在请求模型前失败。修复后通过本地模型 stub 重放：表达式及文件中的 `{{args}}` 原样传给模型，模板的参数正常替换。模板自身的 shell 表达式继续按原有权限规则执行。

工厂集成测试覆盖字符串和对象 part、文件内未闭合语法、多媒体、审批重试及 shell 输出和用户参数中的字面语法。运行既有处理器套件、构建、类型检查、lint 和格式检查。
