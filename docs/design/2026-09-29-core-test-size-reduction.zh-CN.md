# Core 测试代码减量

[English](2026-09-29-core-test-size-reduction.md) | [简体中文](2026-09-29-core-test-size-reduction.zh-CN.md)

## 问题

Core 每行生产代码约对应 1.7 行测试代码，而且差距仍在扩大：2026-09-26 至
2026-09-29 期间，Core 测试代码增加约 31,600 行，生产代码增加约 20,200 行。
其中大量是重复的 mock 准备和近乎相同的用例，增加审查与维护成本，却没有多发现问题。

## 目标

大幅缩减 Core 测试代码，生产代码保持不变，回归检出能力的损失控制在明确预算内。
其他包以及后续测试增长的约束另行处理。

## 方法

| 方法         | 改动                                  | 必须保留                           |
| ------------ | ------------------------------------- | ---------------------------------- |
| 共享夹具     | 用小型工厂复用配置、请求、响应和 mock | 每例独立状态、字段缺省、顺序、异步 |
| 参数化场景   | 用一张表替代结构相同的用例            | 每行的输入、预期结果和有用名称     |
| 完整结果预期 | 用一个手写的完整预期值替代零散断言    | 预期值独立于实现                   |
| 行为契约     | 一个生命周期测试检查多项相关结果      | 错误路径、选项传递、调用方接线     |

辅助函数、夹具和快照计入规模。合并后的用例失去独立的失败名称，一个断言失败可能
掩盖后续断言；这一诊断代价是可以接受的。不删除任何测试文件。

## 约束

只有同时满足以下条件，减量才会保留：

- 生产代码不变；构建、类型检查和 lint 通过；测试套件没有新增失败。
- **覆盖率：**原已覆盖的生产代码行损失不超过 0.5 个百分点，以主干的插桩行数为分母。
  新增覆盖不能抵消损失，单个文件的较大损失需要审查。
- **历史故障：**通过回退修复重新引入的历史生产缺陷，凡是主干测试能发现的，
  减量后仍须发现。
- **变异测试：**在抽样模块中，主干能杀死的变异体存活不超过 1%。

## 结果

两侧均在 Linux arm64 上以覆盖率模式运行完整 Core 测试套件，对照主干 `3a8fd11711`：

| Core               |    主干 | 本次改动 |               变化 |
| ------------------ | ------: | -------: | -----------------: |
| 测试与辅助代码行   | 716,440 |  538,171 | −178,269（−24.9%） |
| 测试与辅助代码字节 | 25.0 MB |  19.4 MB |             −22.5% |
| 测试文件           |     868 |      868 |                  0 |
| 测试用例           |  33,854 |   33,771 |                −83 |
| 生产代码行覆盖率   |  91.02% |   91.02% |                    |
| 生产代码分支覆盖率 |  88.65% |   88.66% |                    |

- **覆盖率：**只有 1 个原已覆盖的行失去覆盖。此前对照 `e767e223c5` 的一次运行损失 41 行，
  位于两处依赖时序、且没有测试断言的路径上；这次没有再出现。
- 故障与变异回放对照的是主干 `e767e223c5`，早 11 个提交。
- **历史故障：**106 个历史缺陷中有 91 个仍能在该主干上重新引入，两侧发现的都是同样的 80 个。
- **变异测试：**对十三个完整模块启用全部变异算子。4,583 个变异体中，主干测试杀死 3,286 个；
  本次改动没有丢失其中任何一个，并额外杀死 20 个。这些模块是：Anthropic 用量统计、workflow 预算、
  XML 工具调用回退、文件读取缓存、模型注册表、流式工具调用解析、重试错误分类、microcompaction、
  memory discovery、hook 系统、schema 校验、会话 hook 管理和 hook 规划。
- **用例：**24 个文件中的 203 个测试名称被合并为更少的测试或作为完全重复项删除，
  主要是 hook 和 schema 校验测试。
- 测试套件没有新增失败。

## 代价与局限

- 合并后的用例名称更少，部分失败更难定位。
- 早先一个阶段还在覆盖率显示重叠的地方删除或删减了 179 个测试文件。沙箱验证表明它丢失了
  真实的检查（抽样的 23 个变异体中有 7 个存活），因此已撤回：这些文件与主干一致。
- 测量在 Linux arm64 上进行；该平台跳过的测试不在测量范围内。

## 后续

- 恢复的 179 个文件可以用同样的方式压缩。
- 仅靠压缩的收益在 30% 左右趋于饱和。要让 Core 保持精简，还需要检查每次改动新增的测试代码量。
