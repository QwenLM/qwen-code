# 会话删除隔离

[English](2026-11-18-session-delete-isolation.md) | [简体中文](2026-11-18-session-delete-isolation.zh-CN.md)

## 行为约定

删除工作区会话 A 只影响 A。定时任务通过 `per_run` 创建的会话 B 拥有自己的历史，A 删除后仍可通过 B 原有的会话 ID 打开。如果 A 和 B 共用 ACP 通道，关闭 A 时 B 正在执行的轮次可以继续。

## 关闭与清理

删除会话要求持有 A 的 ACP 子进程先刷新记录器并返回关闭成功。随后 daemon 获取现有的维护租约并删除 A 的数据。如果持有者已经不存在，也通过同一租约检查后执行删除。

删除请求沿用初始化时限来等待关闭。超时后请求返回错误并保留 A 的文件。关闭仍在等待结果时，bridge 阻止 A 接收新的工作。如果迟到的回执确认关闭成功，bridge 完成关闭，后续重试可删除 A 的文件。明确拒绝时可重新尝试。RPC 结果不明时继续限制 A，并允许向原持有者重试删除。该删除路径会保留同通道上的其他会话。

Worktree 清理在现有的 worktree 锁内检查活跃和归档元数据。与其他所有者共用的 checkout 会保留。如果任一归档状态存在较早的 reset 前任，则指向该 checkout 的所有前任会话都必须离线才能清理。只有直接前任时仍适用单次 reset 的例外。

## 验证

- 通过真实 daemon 执行一次 `per_run`，使用确定的模型响应。关闭 B，删除 A，然后用 B 原有的 ID 重新打开它。检查完整历史仍按原顺序包含请求和回答。
- 在 B 的轮次正在运行时，延迟同一通道上 A 的 ACP 关闭回执。检查关闭超时、B 正常结束轮次，以及迟到的回执只关闭 A。验证关闭期间 A 上的新旁路请求和关闭前已排队的 fork 都不会执行。
- 验证关闭超时会保留 A 的历史和附件。检查清理时保留与归档会话共用的 checkout，以及只归档当前所有者后仍由较早的在线前任使用的 checkout。
