# 工具结果大小统计与超大结果的一致处理

[English](tool-result-size-accounting.md) | [简体中文](tool-result-size-accounting.zh-CN.md)

## 问题和当前行为

#11536：生产者、落盘门限、单工具/组合裁剪、聚合收尾和发送保护都可能缩短结果，而执行统计仅保留较晚的预览长度。网页抽取也有自己的输入上限。

随上下文压力调整预算（#2566）是另一项改动，不在本设计范围内。普通默认值保持 25,000 字符 / 1,000 行。

## 变更

MCP 保留独立的 500k 字符上限（全局默认值的 10 倍）；是否让 MCP 改用全局上限属于产品决策，不在本次改动范围内。shell、grep、agent 和自行分页的工具保留现有声明上限。200k 聚合预算仍独立生效。所有生产者（包括 MCP）现在都会上报缩减前的大小。

内部来源信息以可枚举 Symbol 附加在顶层响应 Part 上。它能经过实时浅拷贝、收尾和媒体处理路径，但不会进入 JSON、hook 响应或模型载荷。它包含数值形式的原始大小、调用关联、预算来源，以及仅在进程内使用、用于复用已有产物的本地落盘文件路径。遥测从不发送这些路径、结果内容、参数或哈希。会缩短输出的生产者在缩短前上报大小；普通生产者在执行后立即测量。深拷贝或恢复的结果无法从预览中还原原始大小，会被明确标记为未知。PostToolBatch 替换结果按现有调度器调用标识继承原调用的来源信息。

执行事件给出原始与处理后的字符数和 token 估算。另有一个按调用的注入事件，在真正调用内容生成器之前、基于经过聚合/发送预算和模态瘦身后的最终请求发出。每个聊天用 WeakSet 保证同一来源在重试和后续历史重放中只记一次；从未提交给生成器的调用不产生注入事件。字符数统计文本形式的结果载荷；token 估算复用压缩模块的 Part 估算器，包含包装与媒体估算。这些是对内部提交请求的估算，不是 provider 分词计费，也不是网络送达确认。

每个缩短层都会发出数值形式的输入/输出大小、实际预算及来源和所在层级。落盘还会通过一个不含本地输出路径的 logger 触发现有的落盘结果事件。RUM 镜像这些大小字段，字符/token 直方图按函数名、工具类型和截断状态区分原始/注入阶段。调用 ID 只出现在日志中；直方图的通用会话属性仍遵循现有的基数开关。遥测失败不会导致工具或模型请求失败。

## 恢复与生产者策略

完整输出存根保留现有标记和完整输出的 SHA-256 标签，循环保护逻辑保持兼容。两个落盘写入路径都会附上总字符/行数和明确的 read_file offset/limit 提示。合法且大小受限的 JSON 会得到由 JSON.parse 生成的结构/键/数组计数/样本预览；过大或非 JSON 文本沿用现有的方向性预览。这只是可恢复的样本，不能替代完整的结构化结果，也不是 schema 推断引擎。解析有大小限制，以免对超大结果再做一次大分配。

MCP 和 shell 在缩短模型输出之前先落盘。通用与聚合缩减器只在之前没有落盘决定时才落盘，会复用已有文件，并在 I/O 失败时仍保留现有硬上限。网页抓取的 100k 抽取上限作用于其摘要旁路查询之前，而不是结果预算；网页搜索会按段落保留引用。这些语义性的生产者缩减仍然有效，本设计只是把它们记录下来，而不是用统一的字符串截断替代。可测量时会单独携带缩减前的大小；这里的"原始"指结果预算缩减前的语义输出，不是网络字节，也不是整个旁路查询记录。

## 影响边界与兼容性

核心调度器的转换以及执行后/hook 后的收尾；共享的截断与收尾；shell/MCP/web 生产者；LlmChat 的发送边界；遥测类型、OTLP/RUM logger 和直方图定义。交互式、headless、ACP、agent 和 speculation 都汇聚到共享的转换器/收尾器和聊天发送边界。Code Mode 的嵌套调用保留执行测量，但当只有父调用的输出被提交时，不会单独声称自己被注入模型。

不新增公开配置、持久化记录格式、遥测内容采集、传输 schema、存储生命周期、精确分词器或依赖。现有的显式门限仍然有效。

## 决策与限制

当生产者只提供预先截断的预览、没有原始大小元数据时（包括恢复的结果），原始大小记为未知，绝不静默推断。网页抽取语义和结果中合法的字面内容保持不变。provider 调用统计只在生成器边界记一次；网络发送失败与 provider 成功响应是两回事。
