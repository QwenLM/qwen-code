# 工具结果大小统计与超大结果的一致处理

[English](tool-result-size-accounting.md) | [简体中文](tool-result-size-accounting.zh-CN.md)

## 问题和当前行为

#11536：生产者、落盘门限、单工具/组合裁剪、聚合收尾和发送保护都可能缩短结果，而执行统计仅保留较晚的预览长度。网页抽取也有自己的输入上限。

随上下文压力调整预算（#2566）是另一项改动，不在本设计范围内。普通默认值保持 25,000 字符 / 1,000 行。

## 变更

MCP 保留独立的 500k 字符上限（全局默认值的 20 倍）；是否让 MCP 改用全局上限属于产品决策，不在本次改动范围内。shell、grep、agent 和自行分页的工具保留现有声明上限。200k 聚合预算仍独立生效。所有生产者（包括 MCP）现在都会上报缩减前的大小。

内部来源信息以可枚举 Symbol 附加在顶层响应 Part 上。它能经过实时浅拷贝、收尾和媒体处理路径，但不会进入 JSON、hook 响应或模型载荷。它包含数值形式的原始大小、调用关联、预算来源和裁剪状态。遥测从不发送这些路径、结果内容、参数或哈希。会缩短输出的生产者在缩短前上报大小；普通生产者在执行后立即测量。深拷贝或恢复的结果无法从预览中还原原始大小，会被明确标记为未知。

执行事件给出原始与处理后的字符数和 token 估算。另有一个按调用的注入事件，在真正调用内容生成器之前、基于经过聚合/发送预算和模态瘦身后的最终请求发出。每个聊天用 WeakSet 保证同一来源在重试和后续历史重放中只记一次；构造、setHistory 及 addHistory 时把继承的来源标记为已报告，fork 新执行的结果仍会报告自己的注入事件；从未提交给生成器的调用不产生注入事件。字符数统计文本形式的结果载荷；token 估算复用压缩模块的 Part 估算器，包含包装与已配置的媒体估算。持久化层测量实际返回的完整内容，包含保留的媒体。这些是对内部提交请求的估算，不是 provider 分词计费，也不是网络送达确认。

每个缩短层都会发出数值形式的输入/输出大小、实际预算及来源和所在层级。落盘还会通过一个不含本地输出路径的 logger 触发现有的落盘结果事件。RUM 镜像这些大小字段，字符/token 直方图按函数名、工具类型和截断状态区分原始/注入阶段。调用 ID 只出现在日志中；直方图的通用会话属性仍遵循现有的基数开关。遥测失败不会导致工具或模型请求失败。

## 恢复与生产者策略

完整输出存根保留现有标记和完整输出的 SHA-256 标签，循环保护逻辑保持兼容。两个落盘写入路径都会附上总字符/行数和明确的 read_file offset/limit 提示。请求预览额度不超过 2k 时，合法且大小受限的 JSON 会得到由 JSON.parse 生成的结构/键/数组计数/样本预览；过大或非 JSON 文本沿用现有的方向性预览。这只是可恢复的样本，不能替代完整的结构化结果，也不是 schema 推断引擎。解析有大小限制，以免对超大结果再做一次大分配。对象计数放在样本对象之外，所选键名完整保留；样本超额时回退方向性预览。单行数据的中间部分需按字节读取或对完整文件查询恢复。

MCP 和 shell 在缩短模型输出之前先落盘。通用与聚合缩减器只在之前没有落盘决定时才落盘，会复用已有文件，并在 I/O 失败时仍保留现有硬上限。文本落盘沿用现有单文件及会话限额，异步写入前预留 UTF-8 字节，失败回滚。batch 只改变实际裁剪 part 所属的 provenance。网页抓取的 100k 抽取上限作用于其摘要旁路查询之前，而不是结果预算；外层超大 envelope 即使包含内层裁剪标记，仍走全局 persistence gate，可能保存指向原始页面文件的外层结果，而不放大默认结果预算；网页搜索会按段落保留引用。这些语义性的生产者缩减仍然有效，本设计只是把它们记录下来，而不是用统一的字符串截断替代。可测量时会单独携带缩减前的大小；这里的"原始"指结果预算缩减前的语义输出，不是网络字节，也不是整个旁路查询记录。

## 影响边界与兼容性

核心调度器的转换以及执行后/hook 后的收尾；共享的截断与收尾；shell/MCP/web 生产者；LlmChat 的发送边界；遥测类型、OTLP/RUM logger 和直方图定义。交互式、headless、ACP、agent 和 speculation 都汇聚到共享的转换器/收尾器和聊天发送边界。Code Mode 的嵌套调用保留执行测量，但当只有父调用的输出被提交时，不会单独声称自己被注入模型。

不新增公开配置、持久化记录格式、遥测内容采集、传输 schema、存储生命周期、精确分词器或依赖。现有的显式门限仍然有效。

## 决策与限制

当生产者只提供预先截断的预览、没有原始大小元数据时（包括恢复的结果），原始大小记为未知，绝不静默推断。网页抽取语义和结果中合法的字面内容保持不变。provider 调用统计只在生成器边界记一次；网络发送失败与 provider 成功响应是两回事。

## 本轮正确性修复

构造聊天、setHistory 及 addHistory 时，将继承历史的 provenance 标记为已报告，防止 fork 或推测接受路径重复记入父调用；fork 新执行的结果仍正常报告。batch 仅更新实际缩短的 part 所属 provenance，未裁剪的小结果保留自己的预算和标记。

估算使用压缩路径的已配置图片 token 值，持久化层计算真实返回内容时包含保留的媒体。文本落盘沿用单文件及会话磁盘限额，在异步写入前按 UTF-8 字节预留，失败时回滚。内部 provenance 不再携带无人读取的文件路径；既有 response/entry 文件路径继续负责恢复及复用。

web_fetch 保留约 100k 的内部提取/摘要输入，面向模型的超大 envelope 仍走全局 persistence gate，即使内层页面已带裁剪标记。不新增 102k 输出预算，默认仍为 25k 字符/1000 行。大型失败回退可能保存外层 envelope，再通过其中的原始页面指针恢复全文；这不代表第二次摘要，也不声称只落盘一个文件。

只有请求的预览额度不超过 2k 时采用结构化 JSON sample。对象计数位于样本对象之外，所选键名完整保留，避免覆盖真实 omittedKeys 字段或合并长前缀键。sample 超额则回退方向性预览。单行 JSON 的中间内容不能靠 read_file 行偏移恢复，提示明确要求按字节读取或对完整文件执行查询。

取消或 hook 停止等整体替换结果，不沿用被替换生产者的原始大小和预算。原始大小未知时裁剪状态也保持未知，直到实际缩减器明确标记。只有文件真正保存后才产生成功落盘事件；跳过或失败不冒充已落盘。包含标签与转义的完整 sample 仍需满足预览额度。
