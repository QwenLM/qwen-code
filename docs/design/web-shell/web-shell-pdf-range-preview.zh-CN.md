# Web Shell PDF 按需预览

[English](web-shell-pdf-range-preview.md) | [简体中文](web-shell-pdf-range-preview.zh-CN.md)

## 问题

在 `main` 提交 `ac4ae44c` 中，打开工作区 PDF 时，Web Shell 要读完整个文件并生成
Blob，才会把它交给浏览器的 PDF 预览器。一个 20 MiB 文件需要串行读取 80 个
256 KiB 分片，并请求两次文件元数据。因此要等最后一个字节到达才能看到第一页。

## 设计

- Web Shell 的产物面板对 4 MiB 至 100 MiB 的工作区 PDF 启用按需预览。较小的
  工作区 PDF 和 PDF 附件走浏览器原生预览。100 MiB 是工作区文件已有的预览上限。
- 打开按需预览时加载 PDF.js 的 legacy 构建及其 worker，以兼容 Web Shell 支持的
  浏览器版本。文档使用 JBIG2 或 JPEG 2000 图像时，按需加载对应的 JBIG2 和
  OpenJPEG 解码器。通过 `stat` 获取文件大小，由 PDF.js 请求所需字节范围，每次
  `readFileBytes` 最多读取 256 KiB。关闭后台预取。首屏的读取量取决于 PDF 的文件
  布局。
- 每次读取都经过现有的工作区鉴权和文件操作入口。预览器检查返回的偏移和字节数，并用
  文件大小及修改时间检测文件变化。切换文件或关闭预览时释放文档，忽略迟到的结果。
- 每次在画布上渲染一页，用户翻到需要更多数据的页面时继续读取。需要搜索、打印，或文档
  依赖外部 CMap 等资源时，可以主动打开完整的原生预览。也可以在完整预览中下载原文件。

产物面板和延迟加载的 PDF.js 预览器在 `packages/web-shell` 中实现。两种预览都
使用现有的 daemon 文件接口。

## 验收

- 在连接真实 daemon 的浏览器里，从「文件」打开同一份 20 MiB PDF。使用相同的
  浏览器、文件和网络条件，对比 `ac4ae44c` 的 Web Shell 生产构建及优化版。记录
  从点击到第一页可见的耗时，以及此时已收到的 PDF 字节和 HTTP 响应字节。
- 暂缓返回仅后续页使用的数据，确认第一页的实际内容已可见。切换到后续页时，应请求该页
  所需的范围，数据返回后显示该页。
- 检查小型工作区 PDF、PDF 附件、完整预览及下载。在读取尚未完成时，分别验证文件变化和
  关闭预览的行为。
