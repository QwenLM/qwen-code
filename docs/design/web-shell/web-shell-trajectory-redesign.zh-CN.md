# Web Shell 轨迹视图重设计

[English](web-shell-trajectory-redesign.md) | [简体中文](web-shell-trajectory-redesign.zh-CN.md)

状态：提案，本文内容均未实现。范围：仅 `packages/web-shell`，不涉及 daemon、
SDK、传输格式、持久化或设置项。关联：#12293（轨迹视图）、#14071（PR7A）、
#14723（PR7B）。

## 概要

轨迹面板回答“这个会话是怎么跑的”。自 2026-09-20 起，约二十个 PR 各自加了一项
能力，每项能力都带来一条常驻的控件带和说明文字。在默认的停靠面板里，记录列表
现在从 824 px 高面板顶部往下 572 px 处才开始，只能看到 7 行；打开检查器后只剩 2
行。

本次重设计保留全部数据保证和几乎全部行为，改变的是面板的布局与绘制：

- 顶部只留三条细栏：摘要栏（40 px）、时间条（56 px）、工具栏（46 px）。控件区
  （chrome）共 142 px，原来是 572 px，可见约 21 行。
- 真正的树形结构：轮次 → 步骤（一次模型请求及其文本）→ 工具 → 子代理步骤。工具
  的图标、本地化名称和描述与对话区及“工具调用”面板一致。
- 记录详情在停靠面板中以下钻视图打开，在全屏时以可调宽度的侧栏打开，取消底部
  分屏。
- 实时、暂停、历史只用一个状态控件；只有一个警告指示；所有范围说明收进“关于”
  浮层。
- 时间轴配色经过校验，失败不再依赖分辨红与橙。
- 运行中底栏只在有任务运行时出现，取代常驻的“近期执行”表格。

工作分五个 PR 交付，见[实施计划](#实施计划)。

## 背景

### 当前面板做什么

数据链路（本提案不改动）：

- 分页 transcript 重放时原地输出计时帧（`_meta.timing`）。
  `projectTrajectoryWindow` → `buildTrajectory` 把它们折叠成轮次和行；
  `buildTrajectoryLayout`、`buildTimeline`、`filterTrajectory` 和
  `summarizeTrajectory` 再把这些行投影给视图。
- `useTrajectoryWindow` 持有有界窗口：最多 4 页、每页 250 条记录，从新到旧读取，
  通过游标书签做“更早 / 较新”导航。
- 实时的请求与工具生命周期来自会话事件流，经由 `trajectory-live-store`、
  `project-trajectory-lifecycle` 和 `project-trajectory-executions`（最多 256 个
  请求、256 个工具）。

界面从上到下，全部在 `TrajectoryPanel.tsx`（2,153 行）中组合：

1. 近期执行：可折叠的虚拟列表，带自己的“跟随中”“暂停”“回到最新”控件。
2. 总计行（“已加载窗口 · 4 轮 · 18 请求 · 19 工具”）和刷新按钮。
3. 执行跨度、活跃覆盖、主模型请求累计，失败计数，以及“指标说明”折叠项。
4. 时间概览：三条带标签的泳道、坐标轴、“活跃时间 / 真实时间”、缩放按钮和图例。
5. “所选”栏，带“查看详情”和一行上下文提示。
6. 固定高度的错误槽位。
7. 窗口导航：状态文字、“更早一段”“较新一段”“回到最新”。
8. 筛选：搜索、类型、状态、上一条、下一条、清除筛选和覆盖率说明行。
9. 虚拟化表格，以及底部分屏的检查器。

## 问题

**P1. 控件优先，内容垫底。** 每项能力都加了一条常驻条带。固定高度的槽位（错误
槽位、提示行、更早记录栏）即使为空也占着空白，列表只能拿剩下的高度。

**P2. 说明文字被当成内容。** 范围与上限说明一直显示在屏幕上：“有界生命周期记录；
下方筛选仅作用于历史窗口”“指标与搜索仅覆盖当前窗口”“已到当前快照的最早记录”，
以及“生命周期详情可能不完整或超出保留上限”（显示了两次）。这些话都对，也关系到
能否正确解读数字，但它们是参考资料，不是状态。

**P3. 两份列表，三种移动窗口的方式。** “近期执行”和历史表格展示的数据有重叠，
排序和滚动规则却不同。“回到最新”（两处）、刷新图标、“更早一段 / 较新一段”按钮
都会改变窗口。

**P4. 行是平的，每行信息很少。**

- 轮次 → 请求 → 输出的层级只靠一个 18 px 缩进表达。
- 每轮的 prompt 出现两次：轮次标题里一次，“用户”行又一次。
- 每个请求行都写着模型名，18 行全是同一个；真正有用的数字反而被截断（“2.4s ·
  首 token 9…”）。
- 一列等宽字体的标记承担三种含义：行类型、请求序号、工具的线上名称
  （`run_shell_co…`）。
- 思考和回复各占一整行。

**P5. 详情和列表抢空间。** 底部检查器最高 320 px，会把列表压到两行。它的“摘要”
页签把每个字段画成带边框的卡片，连“未记录”占位也画；耗时却放在单独的“指标”
页签里。

**P6. 没有统一的视觉体系。**

- 10 px 文字占多数，标签使用等宽字体。
- 浅色主题的次级文字对比度不达标。
- 失败条是红色，叠在橙色的工具泳道上。
- 缩放按钮只有 14 px，图例和它解释的对象分开。
- 同一个工具在这里和在对话区、“工具调用”面板里画法不同。

**P7. 手势看不见。** 拖动框选区间、右键拖动平移、右键单击清除、滚轮缩放，屏幕上
没有任何提示。一个 60 px 高的图表还配了四行控件。

## 目标

- **G1 内容优先。** 停靠面板中列表上方的控件区不超过 150 px；1440×900 下关闭
  详情时至少可见 20 行。
- **G2 一件事只说一次。** 一份列表、一个状态控件、一个警告指示；说明按需查看。
- **G3 行的读法与 Web Shell 其他地方一致。** 共用工具图标、本地化工具名和描述；
  状态用图标加文字表达。
- **G4 看详情不丢列表。** 窄时下钻，宽时侧栏，两种形态都能用键盘在记录间切换。
- **G5 无障碍的视觉体系。** 没有小于 11 px 的文字；两种主题下次级文字对比度不低于
  4.5:1；时间轴配色通过校验；状态从不只靠颜色表达。
- **G6 保留现有全部保证。** 只显示记录到的值（“—”表示未记录，0 表示实测为零）；
  行不会在阅读时跳动；窗口保持有界并分页；PR7B 的跟随 / 暂停语义、单一 Tab 焦点的
  键盘模型和按会话隔离保持不变。

## 非目标

- 不改 daemon、SDK、传输格式、持久化或设置项。面板仍通过 `rightPanelItems`
  按需开启。
- 不做跟随时的历史自动同步，见[后续工作](#后续工作)。
- 不与“工具调用”面板合并，两者只共享组件。
- 不新增测量。新出现的数字只有 token 合计和每轮实际历时，都由窗口中已记录的值
  计算。
- 不改 TUI。

## 先例

**DeepSeek Harness**（`dsh-v0.2.1-rc.2`，`packages/client/ui-trajectory`），即
#12293 引用的参考：

- 32 px 工具栏、50 px 三泳道概览，下面是记录列表。
- 检查器是侧栏，宽 320–720 px，可调；宽度不超过 760 px 时变成覆盖式抽屉。
- 行高 30 px。每个模型步骤是一条记录，合并其文本和推理；工具调用和结果共用一行。
- 耗时和 token 只在检查器里显示，运行中的行没有任何标识。qwen-code 不应照搬这两点：
  耗时正是这个视图的意义所在。

**Trace 查看器**（官方文档与代码，2026-10-20 读取）：

- Jaeger 用可调宽度的侧栏取代行内展开的 span 详情，理由是行内展开会造成滚动位移
  和抖动
  （[ADR-0006](https://github.com/jaegertracing/jaeger-ui/blob/main/docs/adr/0006-side-panel-span-details.md)）。
- Langfuse 按面板宽度重排工具栏，从 320 px 预览到 4K 窗口用同一个渲染器，并把逐行
  截断标记换成一条提示
  （[响应式时间轴](https://langfuse.com/changelog/2026-08-28-responsive-timeline)、
  [截断提示](https://github.com/langfuse/langfuse/blob/main/web/src/features/traces/components/TraceTruncationNotice.tsx)）。
- Phoenix 用容器查询控制条形列：宽度低于 500 px 时隐藏，高于 800 px 时占三分之一
  （[traceTreeStyles.ts](https://github.com/Arize-ai/phoenix/blob/main/js/app/src/components/trace/traceTreeStyles.ts)）。
- LangSmith 加入了全高瀑布图和吸顶的轮次标题
  （[changelog](https://docs.langchain.com/langsmith/changelog)）。
- Sentry 默认压缩长时间的空闲间隔，Langfuse 借用了这一做法
  （[timeCompression.ts](https://github.com/langfuse/langfuse/blob/main/web/src/features/traces/fns/timeline/timeCompression.ts)）。
  Cursor 论坛的一个报告里，一段没有标注的 70.5 s 间隔被读成模型卡顿
  （[论坛](https://forum.cursor.com/t/170426)）。
- SigNoz 和 W&B Weave 把红色留给错误，并配图标
  （[SigNoz](https://signoz.io/blog/new-trace-detail-view/)）。OpenAI 把空计数视为
  “未知，而非零”
  （[tracing 指南](https://developers.openai.com/api/docs/guides/agents-api/tracing)）。
- Jaeger 用空心图标标记子孙节点中的错误
  （[PR #3302](https://github.com/jaegertracing/jaeger-ui/pull/3302)）。

本提案采纳：

- 一条概览条作为唯一的区间控件。
- 详情用下钻或侧栏，从不行内展开。
- 吸顶的轮次标题。
- 每个模型步骤一条记录。
- 红色只表示失败，且总是配图标。
- 用状态表达说明（一个标签、一个占位行、一个浮层），而不是文字。
- 标出空闲间隔。

## 设计原则

1. **列表就是产品。** 其他一切都是观察列表的镜头。
2. **一件事只在该说的地方说一次。** 状态只在一处；参考资料放在 ⓘ 后面。
3. **平时安静，失败醒目。** 成功什么都不显示；失败显示图标和文字。
4. **同一样东西，同一种样子。** 一次 Shell 调用在这里、在对话区、在“工具调用”
   面板里看起来一样。
5. **只呈现记录到的事实。** 缺失的耗时显示“—”。除了现有的实时已运行时长（继续
   标注为近似值），不做任何估算。

## 方案设计

### 布局

```
┌ 摘要栏 · 40 px ──── 统计 ……… [⚠] [⊗ 2 项失败] [● 实时] [⟳] [ⓘ]
├ 时间条 · 56 px ──── 三条泳道 · 空闲间隔标记 · 图例 · 时间模式菜单
├ 工具栏 · 46 px ──── [🔍 搜索 · 3 / 22 ˄ ˅ ×] [区间芯片] [筛选 ①]
├ 记录列表（弹性） ── 边界行 · 树形行 · 吸顶轮次标题
│                       暂停时浮动的“跳到最新”
└ 运行中底栏 · 40 px，只在有任务运行时出现
```

停靠面板中，记录详情覆盖在工具栏和列表上，摘要栏和时间条保持可见。全屏时，详情
在列表右侧的侧栏打开。

面板已声明 `container-type: inline-size`。下列分档用容器查询实现；面板上的
`ResizeObserver` 把同样的分档提供给决定下钻还是侧栏的代码：

| 面板宽度              | 行为                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 小于 420 px           | 摘要只显示总历时和芯片；“筛选”变成图标按钮。                                                                        |
| 420–959 px（停靠）    | 上述布局；详情为下钻视图。                                                                                          |
| 960 px 及以上（全屏） | 摘要增加模型耗时、请求数、工具数和 token；列表与详情左右并排。列表本身宽度不小于 760 px 时，增加瀑布列和 token 列。 |

### A. 摘要栏

单行，40 px，`white-space: nowrap`。

- **统计（左侧）。** 总历时是标题（14 px 半粗），后面是活跃时间。标签为 12 px，
  颜色用 `--traj-text-secondary`（见 [H](#h-视觉系统)）；数值使用
  `font-variant-numeric: tabular-nums`。全屏时增加主模型耗时、请求数和工具数，以及
  输入 → 输出 token。空间不够时先截断统计，芯片永不截断，完整数值始终在“关于”里。
  中文文案标签在前（“总历时 23m 38s · 活跃 6m 3s”）。
- **警告指示（⚠）。** 至少有一项生效时才出现。点击打开浮层，逐项列出并给出操作：

  | 项目                           | 操作            |
  | ------------------------------ | --------------- |
  | 刷新失败，正显示上次读取的数据 | 重试            |
  | 断线期间历史可能已变化         | 刷新            |
  | 切换到其他窗口失败             | 重试 / 回到最新 |
  | 部分 transcript 无法读取       | 重试            |
  | 生命周期详情不完整或被省略     | 无（仅提示）    |

  这一个控件取代上下文提示、错误槽位和窗口失败行，而且不会移动任何行。

- **失败芯片。** “N 项失败”，文字 `--error-color`、底色 `--error-bg`，仅在 N > 0 时
  显示。点击切换“状态 = 失败”筛选，`aria-pressed` 反映当前状态。
- **状态胶囊。** 由 PR7B 的跟随状态机驱动：

  | 状态                     | 胶囊                 | 点击     |
  | ------------------------ | -------------------- | -------- |
  | 生命周期不可用，最新窗口 | （不显示）           |          |
  | 跟随中且 `live`          | ● 实时               | 暂停     |
  | 跟随中且 `catching-up`   | 正在连接…            |          |
  | 已暂停，最新窗口         | ❚❚ 已暂停            | 回到最新 |
  | 正在返回                 | 正在更新…            | （禁用） |
  | 历史窗口                 | 更早的记录           | 回到最新 |
  | 生命周期 `stale`         | 正在重连…，并显示 ⚠ |          |

  暂停时，列表底部居中还会浮出“跳到最新”按钮；有新执行到达时（PR7B 的 “updated”

## 数据与状态改动

全部改动都在 `packages/web-shell/client` 内，所有投影保持纯函数并有单元测试。

- **`buildTrajectoryLayout`**
  - 把每轮开头的用户行并入轮次标题，把每个回复或思考行并入它所属的步骤。
  - 提供 `owner: Map<rowKey, visualKey>`，使搜索命中、选中和 `rowIndexByKey` 查找
    都落到一个可见行上。
  - `parentToolCallId` 能在窗口内解析时，把子代理的行嵌套到发起它的工具行下。子代理
    的行没有 `requestIndex`，因此按记录顺序分组：每个子代理请求开启一个子代理步骤，
    之后同一父调用下的行都归入该步骤，直到下一个子代理请求。无法归位的行作为智能体
    调用的直接子项。
  - 提供 `level`、`setSize`、`posInSet` 以及每个步骤的摘要文本。
  - 保留 `groupIdentities`，使折叠状态像现在一样在重新投影后保持。
- **`summarizeTrajectory`** 在 PR-R1 增加 token 合计（主会话：输入、输出、缓存），
  在 PR-R3 增加主要模型，以及由记录的起点和耗时计算的每轮实际历时。缺少起点时回退为主模型耗时，并加
  “模型”后缀。
- **`buildTimeline`** 同时返回它裁掉的空闲间隔（位置和长度）。
- **新增 `trajectory-status.ts`**（纯函数）。根据窗口、生命周期投影和跟随状态推导
  胶囊状态、警告列表和边界行状态。上文的决策表直接成为单元测试。
- **`filterTrajectory`** 保留索引不变。类型维度中“步骤”映射到 `request`，“提示”
  映射到 `user`。命中数和逐条跳转按不同的 owner 计数，而不是按原始行。
- **不改动：** `buildTrajectory`、`projectTrajectoryWindow`、`useTrajectoryWindow`、
  实时 store 与生命周期投影、transcript 分页加载器。
- **属性。** `TrajectoryPanel` 增加 `workspaceCwd`，使描述中的路径像“工具调用”面板
  一样显示为相对路径；可选增加 `onOpenFile` 和 `onOpenAgent`，仅当该页签的会话属于
  当前工作区时传入，遵循“工具调用”面板同样的归属规则。

## 备选方案

- **页签（概览 | 时间轴 | 记录）。** 否决：会割裂时间条与列表现在共享的时间—记录
  关联。
- **DeepSeek Harness 式：边界画在行上，不要标题行。** 暂不采用：qwen-code 需要每个步骤
  的耗时和 token，步骤行正是放它们的地方。
- **可调高度的底部检查器。** 否决：在停靠面板里它仍然和列表抢空间。
- **区间框选改为变暗而非筛选。** 考虑过。保留现有的筛选，因为它有测试且适合长会话；
  只去掉“上下文”标签。
- **搜索只做原地高亮、不筛选**，如 LangSmith 和 Perfetto。暂不采用，见已定问题 5。
- **两行式行**，如 Langfuse。否决：停靠尺寸下单行可容纳约 21 行，两行式只有约 13 行。

## 已定问题

2026-10-20 确定，均采用提案的选项。

1. **“近期执行”** 保留在运行中底栏的“全部”之后；等有了历史自动同步再考虑移除。
2. **停靠面板中单击即打开详情**（下钻）。Enter 也可打开；方向键只移动选中项。
3. **token 合计** 只统计主会话。
4. **微型条** 以同一轮内最长的计时行为比例尺。
5. **文本搜索** 保持现有的筛选方式，只显示命中项及其祖先，不改为原地高亮。

## 附录 B 配色校验

校验工具：数据可视化规范中的 `validate_palette.js`（OKLab，Machado 2009 色觉缺陷
模拟），全配对模式。背景：#ffffff（浅色）和 #0a0a0a（深色），即面板计算后的背景。
当前的失败色是 `--destructive`，浅色下计算为 oklch(0.577 0.245 27.325) = #e7000b，
深色下为 oklch(0.704 0.191 22.216) = #ff6467；工具泳道计算为 #eb6834 和 #d95926。

| 配色                                     | 主题 | 色觉缺陷最差值  | 正常视觉最差值 | 结果                                 |
| ---------------------------------------- | ---- | --------------- | -------------- | ------------------------------------ |
| 当前：#2a78d6、#eb6834、#1baf7a、#e7000b | 浅色 | 8.1（红对橙）   | 11.7（红对橙） | 不通过                               |
| 当前：#3987e5、#d95926、#199e70、#ff6467 | 深色 | 4.8（红对青绿） | 9.9（红对橙）  | 不通过                               |
| 提案：#2a78d6、#1baf7a、#d03b3b          | 浅色 | 9.9             | 24.0           | 通过                                 |
| 提案：#3987e5、#199e70、#d03b3b          | 深色 | 7.2（警示区间） | 20.9           | 通过，需二次编码（斜纹、图标、文字） |

对比度补偿：青绿色在白底上为 2.82:1，低于 3:1。由于每个工具 span 旁边都有带文字
标签的行，且图例始终可见，满足补偿规则。
