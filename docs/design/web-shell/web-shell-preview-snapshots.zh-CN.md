# Web Shell 历史网页版本

[English](web-shell-preview-snapshots.md) | [简体中文](web-shell-preview-snapshots.zh-CN.md)

## 问题

开发服务器的历史链接显示的是当前页面。用户需要当轮交付的页面在后续编辑、关闭预览、
刷新 Web Shell 和重启 daemon 后仍然可用。

## 设计

开启会话记录的受管 ACP 会话中，每次成功的 `Artifact` 发布都会尝试额外写入独立、
不可变的本地 HTML 快照。普通 CLI 发布和未开启记录的会话不创建历史文件。
现有发布器继续更新稳定的最新 URL。快照包含该次调用发布的完整包装后 HTML，包括
内联样式、脚本、数据和内嵌资源。每次调用生成新 ID，即使源路径或内容相同。

快照存储失败时，已发布 URL 仍然有效，工具会报告历史版本未能保存。如果取消操作在
发布完成后、快照保存期间到达，工具会释放该次新快照，并且不为已取消的请求返回产物
描述符。返回说明仍会如实承认发布成功，其他历史版本不受影响。

快照字节位于生产该快照的运行时存储目录下的 `artifacts/snapshots/<UUID>/index.html`。
排他创建防止覆盖。工具额外发出一个已发布 HTML 产物，包含唯一 managed ID、文件 URL、
`artifactType: web_preview_snapshot`、最新发布 URL 和现有受信任的
`qwen.published.sha256` 校验和。现有工具结果产物接收与持久化流程将描述符关联到工具
调用和原始轮次；HTML 字节不会进入模型上下文或 SSE 消息。会话恢复和同运行时分叉
保留这些描述符，包括原时间戳和删除标记。只有来自 Artifact、符合预期 UUID 路径及
校验和的快照描述符可以恢复本地文件 URL；普通本地文件链接仍不受信任。恢复不读取
HTML，因此字节缺失不会阻止恢复对话记录。

新快照还包含保存会话 ID 哈希的 `references/` 目录，由元数据
`qwen.snapshot.references: 1` 标识。发布时创建所属会话的引用。分叉在提交对话文件
之前取得自己的引用。快照存储缺失不会阻止分叉：保留历史描述符，并警告内容可能
不可用。其他引用错误仍会终止分叉；失败分叉只释放该次操作的引用。所属运行时会被显式捕获。
删除会话仅释放实际删除的对话文件中出现的快照 UUID，包括旧侧通道事件，不会按会话
ID 扫描其他工作区。删除记录、淘汰、成功回退历史和删除会话都会释放该会话的引用。
只有最后一个引用被释放后才删除文件。删除持久化失败时，保留持久化历史所需的字节。
没有引用元数据的旧快照会保守保留，因为无法确定它们的其他分叉所有者。描述符持久化
前进程崩溃或清理失败留下的文件也会保留；本次不增加孤立文件回收器。

产物批次回滚时，会释放被丢弃快照的本会话引用，包括淘汰过程中从活动变更列表移除的
候选。恢复后的活动记录及其他会话仍持有的快照会保留。删除未能持久化的快照即使已不在
活动列表中，也会继续受到保护。不完整恢复跳过的已有快照也会保留，不会被当作成功
回退历史而删除。该保护状态随回滚恢复，并在后续成功的持久化变更、完整
快照提交或完整恢复后清除。这既避免失败批次泄漏引用，也不会误删已记录历史所需的字节。

新增 `GET /session/:id/artifacts/:artifactId/content` 路由属于
**live-session-owner（活动会话所有者）作用域**，使用与产物列表相同的所有者解析、
客户端过滤、信任检查和 cwd 绑定读取行为。它在所属会话中查找已注册产物，只读取该
运行时存储目录下的固定快照路径，验证描述符、文件 URL、普通文件类型、路径包含关系、
16 MiB 大小限制和校验和。快照缺失或被修改时返回错误，不回退到源文件、最新 URL
或主运行时。响应使用 attachment disposition 和 nosniff。

浏览器通过已认证的 daemon SDK，以来源会话 ID 读取此路由。产物面板在具有不透明
来源、允许脚本的沙箱中渲染 HTML，并使用现有禁止联网的产物 CSP。历史与普通 HTML
预览都使用固定父文档，其 `frame-src 'none'` 阻止内容框架自身导航。内容框架具有
独立的不透明来源，因此其脚本不能修改父层策略。这使 Web Shell 允许实时开发 URL
时仍保留离线预览边界。面板显示历史版本标记及创建时间。关闭面板只移除查看状态；
从原消息重新打开会获取同一版本。同一次发布具有历史版本卡片时，会隐藏轮次中的本地
文件发布链接卡片。HTTP/HTTPS 发布卡片仍保留，用于打开最新托管页面。

刷新会从内存中的 HTML 重建已加载快照，因此导航造成空白框架后，可以不再次请求
daemon 就恢复。初次加载失败仍会重试内容路由。关闭后重新打开会再次获取该版本；
不会把快照字节持久化到浏览器存储。

## 边界与保留策略

本功能保存自包含的 Artifact 交付，不保存任意实时网站或用户浏览器的临时状态。
实时 URL 预览仍可使用，并明确标为实时页面。Artifact 工具已经要求内联依赖，现有
尽力验证器保持不变。离线查看器在运行时阻止网络资源，本功能不打包外部依赖。
重新打开历史版本时，交互状态从交付 HTML 的初始状态开始。

快照描述符沿用会话产物的保留策略和默认 200 条记录上限。本次不实现无限存档，也不
改变会话删除或保留策略。新发布不会覆盖旧快照；快照保留到最后一个保留记录被删除。
过去的实时链接记录不能追溯重建。快照字节缺失时显示不可用，包括移动对话文件却没有
携带运行时存储的情况。

## 受影响组件与验证

- Core Artifact 工具、快照存储与持久化辅助函数及定向测试。
- ACP 产物恢复和删除标记验证。
- CLI 所有者作用域内容路由及路由测试。
- Daemon SDK 已认证的内容读取方法及测试。
- Web Shell 轮次选择器、产物面板、翻译和浏览器测试。
- Web Shell README 和实时预览设计中的版本历史边界。

测试从同一源文件发布 v1 再发布 v2，在保持稳定最新 URL 的同时，两份快照保留各自的
字节。重启并读取持久化会话数据，打开各原始消息，操作内联交互，关闭再刷新，并使源
文件和最新页面不可用。覆盖所有者隔离、伪造描述符、符号链接、截断和校验和不匹配。
在快照字节或引用存储缺失时分叉，验证对话和描述符均保留；其他引用错误不得提交不完整
分叉。注入批次持久化失败、容量超限和引用同步失败，验证回滚释放新引用，同时保留已有
所有者及删除尚未持久化的所有者。在发布后和快照写入期间取消，验证新快照被回收、早先
版本保留且已发布 URL 仍可读。先运行全局 CLI 基线，再执行 build/typecheck/bundle、定向单元测试和本地 daemon
上的浏览器场景。命令及结果见 `.qwen/e2e-tests/web-shell-preview-snapshots.md`。

本次有限增量没有开放设计问题。
