# Web Shell Composer 添加菜单

[English](web-shell-composer-add-menu.md) | [简体中文](web-shell-composer-add-menu.zh-CN.md)

## 问题

Composer 已经能做很多「往这条消息里加点东西」的事，但几乎都没有可见的入口。文件只能拖进来或粘贴。引用 workspace 文件需要知道要输入 `@`。调用技能需要知道要输入 `/`。不知道某项能力存在的用户，没有任何途径发现它。

这背后还有一个相关的缺口：仓库里其实已经有一个汇总的「更多操作」界面，但它只在类触屏设备上渲染。桌面端根本没有，所以桌面用户看不到任何形式的能力清单。

## 目标

在 Composer 工具栏最前面加一个 `+` 按钮，把目前缺少可见入口的「添加到这条消息」类能力收拢到一起。

`+` 是**入口，不是能力**。它只呈现已经存在的东西。

## 设计

### 定位

- **纯前端。** 不新增后端能力，不改 daemon 路由，不改消息结构。
- **只增不改。** 现有工具栏控件（模型、审批模式、语音、workspace、git 分支、上下文用量、宽度）保持原有位置和行为。后来只有 Plan 一个例外：宿主同时列出 `plan` 时，它的入口放进这个菜单，常驻的 Plan 开关离开工具栏。见下文「计划模式」。
- **默认关闭，通过工具栏项列表开启。** Web Shell 本来就允许宿主声明渲染哪些内置工具栏控件。`addMenu` 作为一个需显式开启的标识加入该列表，且不在默认列表里，因此现有嵌入方看不到任何变化。
- 独立宿主把 `addMenu`（与它本来就列出的 `plan` 一起）追加到随上下文变化的默认值上，从而保留空状态下的 Git 控件。分屏通过自己的面板列表开启：该列表省略宽度控件，因为面板尺寸决定了它们的宽度；workspace 标记只在需要显示时才带上。
- **「添加到消息」，外加一行模式项。** 早期草案还带有一个「本任务上下文」分组（上下文用量、会话回顾、Goal、shell 模式）。它因为与 `+` 的含义无关而被移除，现在依然不恢复。Plan mode 是后来才接纳的，只占分隔线下方的一行，这把 `+` 的含义从「添加到这条消息」放宽为「添加到这条消息，或选择如何处理它」。理由只适用于 Plan：它很少被选用，但它的开关曾是工具栏上最重的控件，也是整行唯一的开关；它不能回到权限菜单里，因为规划与执行权限相互独立（见 [DAC Chat Plan 开关](../dac-plan-toggle.zh-CN.md)）；而 Codex 等聊天输入框已经把这类按任务使用的模式放在 `+` 后面，用户会去那里找。被否决分组里的每一项都另有去处（上下文环、斜杠命令）；Plan 此前没有一个安静的去处。管理类界面（MCP server、工具、agent、设置）有意不放进来——它们已经有侧边栏入口，重复一遍只会把一次可发现性修复变成导航冗余。

### 菜单内容

「添加到消息」分组有五项，全部展开为子菜单。

| 项         | 说明 | 行为                                                       |
| ---------- | ---- | ---------------------------------------------------------- |
| 添加文件 ▸ |      | 子菜单；选择「添加为附件」或「上传到工作区」，再选本地文件 |
| 引用文件 ▸ |      | 子菜单；按名称搜索 workspace 文件；插入一个引用            |
| 扩展 ▸     |      | 带说明的普通子菜单列表；插入一个已启用扩展的引用           |
| MCP ▸      |      | 普通子菜单列表；无过滤；插入一个 MCP server 引用           |
| 技能 ▸     |      | 子菜单；列出技能；把技能的调用文本插到输入最前面           |

**为什么文件入口只有一个而不是两个。** 两个相邻的顶层入口都以「选一个本地文件」开头，很难区分。一个「添加文件」子菜单既让主菜单保持紧凑，又在原生选择器打开之前把去向讲清楚。

「添加到消息」的五行都是单行。需要的细节由子菜单内容提供。
小屏断点以下，菜单变窄，次要说明隐藏，让相邻子菜单不被水平裁切。

### 计划模式

宿主同时列出 `plan` 和 `addMenu` 并提供 Plan 切换回调时，菜单末尾多出一条分隔线和一行。

| 项       | 说明                   | 行为                                                      |
| -------- | ---------------------- | --------------------------------------------------------- |
| 计划模式 | 先出计划，批准后再执行 | 勾选行，不是子菜单；Plan 开启时显示勾选；每次选择切换一次 |

- 它是最后一行，也是唯一不是子菜单、唯一带前置图标、唯一带第二行文字的一行。说明文字在小屏断点以下隐藏，与其它次要说明一致。
- 选中它会关闭菜单，恰好切换一次 Plan，并把焦点交还 Composer 输入，与插入类的行一致。
- 模式控件忙碌期间（模式切换或计划批准交接），该行被禁用，并在其它行显示「不可用」的位置写明原因「模式切换中」。
- 它不依赖 workspace，所以在没有任何添加动作可用时，它仍显示在空状态行下面。
- 触发按钮保留「添加到消息」这个无障碍名称，因此只看触发按钮发现不了这一行。Plan 仍可通过 `/plan` 使用，工具栏标签会报告它的状态；工具栏一侧的规格见 [DAC Chat Plan 开关](../dac-plan-toggle.zh-CN.md)。
- 宿主列出了 `addMenu` 但没有 `plan`，或者没有传切换回调时，没有 Plan 行，菜单就是上面那五项。

### 布局与交互

- 触发按钮是一个纯图标按钮，是工具栏行里第一个内置控件，位于宿主的 toolbar-start 插槽之后。
- **`+` 是否可见只由宿主的工具栏项列表决定。** 列表里有 `addMenu`，`+` 就在；没有，就不在。它不会因为当前 workspace 里五项内部能力都不可用而消失——那会让入口在切换 workspace 时闪烁，恰恰在最需要的时候破坏可发现性。如果宿主已开启但每一项内部能力都不可用，`+` 会打开一个空状态行，说明此处没有可用的添加操作。
- 「添加到消息」的各项都是单行。五项加一条分隔线，总共大约六行；宿主开启 Plan 入口时再多两行（一条分隔线和两行文字的 Plan 行）。
- 子菜单在悬停时作为**该行右侧的独立浮层**打开，而不是原地展开。原地展开会让面板变得很高，看不到全貌。
- 子菜单里的长列表滚动，而不是长到超出视口。
- **菜单绝不能说谎。** 一项要么点击后能用，要么不显示，要么以禁用状态显示并写明原因。静默的无操作是本设计首要防范的失败模式。
- 可搜索的子菜单区分加载中、空和失败三种状态。通过点击打开时，文件搜索输入框获得焦点；通过悬停打开时不抢 Composer 的焦点；输入框带有无障碍名称。
- 选择文件附件或引用之后，焦点回到 Composer 输入，而不是 `+` 触发按钮。同步的引用会追加到草稿里，并把光标留在标签之后，后续输入紧随其后。
- 切换任务或 workspace，或者禁用 Composer，会关闭菜单并丢弃任何待处理的原生文件选择，避免过期结果跨越 Composer 归属。
- **Skills 是前置插入，不是替换。** 选中一个技能会把它的调用文本插到输入的最前面；用户已经输入的内容，以及已经插入的引用标签，都会保留并跟在调用文本之后。草稿是否为空都一样，这也去掉了早期草案里「草稿非空时禁用 Skills」的分支。
- **本功能不支持键盘导航。** 实现没有添加键盘处理、导航规则或专门针对键盘的焦点恢复。

## 调研中确立的约束

这些是关于现有系统的事实，它们塑造了设计，每一条都排除了一种原本看似理所当然的实现。

1. **引用是文本加显示元数据，不同种类实际做的事不同。** 被引用的扩展确实会把它的上下文注入这一轮。被引用的 MCP server 会注入一条提示性说明。而指向具体 MCP **资源**的引用，在 Web Shell 路径上后端完全不处理——它以字面文本到达模型。
   → MCP 停在 server 这一层。这不是简化，而是唯一能工作的形式；提供资源下钻就等于发布一个什么都不做的菜单项。
2. **被引用的 workspace 文件同样不会被展开成内容**——模型仍然需要自己去读。文案不能暗示文件内容已经送达。
3. **技能调用必须位于输入的最前面才生效。** 这由插入策略负责：选中技能会把调用文本前置到输入最前面，已输入的文本和已插入的引用标签原样保留在它后面。正因如此，才不需要在草稿非空时禁用 Skills——约束是靠插入落点来满足的，而不是靠拒绝插入。
4. **附件和上传是两条已有的通道**，各有自己的前置条件（宿主开关、daemon 能力、workspace 信任）。菜单读取这些检查已经产出的结果，而不是重新推导条件，所以 `+` 菜单和 `@` 面板对同一个文件永远不会给出不同结论。
5. **文件引用既需要浏览，也需要全 workspace 搜索。** 子菜单打开时位于当前目录，允许用户进入文件夹，但在真实的文件数量下只靠目录浏览不可行。名称查询走现有的全局搜索路径，并按字面量处理，因为文件名可能包含模式元字符。
6. **插入绝不能冲掉已有输入。** 已输入的文本和已插入的标签在每次插入后都保留。这排除了其它功能所用的「整体替换输入」做法——那些功能之所以安全，只是因为它们的输入保证为空。
7. **共享 provider 不能改变现有的 `@` 面板。** 目录下钻只对 `+` 的文件子菜单开启；只要 workspace glob 搜索动作存在，`@` 就继续使用它。

## 触屏

移动端布局和新增操作现由[移动端输入框操作](mobile-composer-actions.zh-CN.md)定义。
横向子菜单改为带返回、关闭按钮的底部抽屉，增加明确的照片、拍照、命令、历史、
Shell 和实时语音入口。下方非目标继续描述桌面下拉菜单；触屏以链接设计为准。
附件和引用插入复用现有通道；技能、命令前置保留原生 textarea 草稿。

## 非目标

- 后端改动、新能力、消息结构改动。
- 「本任务上下文」分组（上下文用量、会话回顾、Goal、shell 模式）。Plan mode 是后来唯一的例外，理由见「定位」。
- 「全部命令」入口。输入 `/` 已经覆盖了它，去掉这一行也顺带消除了随之而来的草稿状态问题。
- 管理页面。
- MCP 资源级引用。
- **指定子代理。** 没有办法确定性地把一条消息路由到指定名称的子代理：可引用对象里没有 agent 这一类，选择 agent 是模型侧的工具参数，会话请求不携带相关字段，也没有任何后端路径把用户文本映射到 agent。唯一可用的形式是用自然语言请求模型照办，这什么都保证不了，还违反「绝不说谎」规则。
- 供宿主注册自定义 `+` 项的 API。固定五个添加项外加 Plan 行，由现有的工具栏项列表机制控制。
- 重构现有的仅触屏操作界面，或重构 `ChatEditor`。

## 风险

- 「添加文件」子菜单承载着真实的语义差异（消息范围的附件 vs 持久保存在 workspace 的文件）。它的措辞必须把两种结果都讲明白。
- 新增的前置控件加大了工具栏的最小宽度，会挤压窄分屏上的文字折叠预算。需要对小宽度下的折叠行为做回归检查。
- 最大的工作量不在菜单本身：内置引用源原本私有于一个 hook，必须提升为共享模块，让 `@` 面板和 `+` 使用同一个事实来源。
- 在已有文本前面前置技能调用，会产生一条用户并没有逐字输入的消息（草稿是「foo」，结果是「/review foo」）。可以接受——这正是先输入 `/` 会得到的结果——但这个过渡必须足够明显，让用户注意到消息的形状变了。

## 延后（在此发现，不在此修复）

另行提交；不要并入本次改动。

- `@` 面板已经提供 MCP **资源**下钻，而 Web Shell 后端会忽略它。用户以为自己引用了一个资源；其实没有。
- 像 Plan 行这样把状态改到 Composer 别处的行，不会播报给读屏软件：菜单关闭，焦点回到输入框，标签出现在工具栏。被它取代的开关之所以能报告状态，是因为它本身获得了焦点。要正确播报，需要区分「用户在这里请求的变化」和「随会话到来或由 `/plan` 触发的变化」，而 Composer 仅凭 props 分辨不出来；只靠 props 驱动的状态区会把一次会话切换当成用户操作播报出去。
- 「绝不说谎」规则在 Plan 上有一个缺口，继承自被 Plan 行取代的那个控件。分屏没有把「写入被阻塞」的状态并入 Composer 的 disabled 属性，所以在分屏加载会话记录、或连接处于错误状态时，选择「计划模式」是静默的空操作，而不是带原因的禁用行。主 Composer 并入了该状态，因此菜单的触发按钮被禁用，这一行受到保护——但工具栏标签不受保护：会话写入被阻塞期间它仍可点击，却什么都不做。要补上其中任何一半，都需要把「宿主会因为什么原因拒绝」这个信息告诉 Composer，而它今天拿不到。
- 名称里带空格或非 ASCII 字符的扩展，客户端写入时会转义，但后端匹配器从不反转义，所以这类引用可能静默失败。
- 文件上传的设计文档声称插入的 `@` 引用会被一个现有的 resolver 消费。那描述的是 TUI 路径；daemon 路径并不这样做。
- 存在两个语义不同的触屏检测辅助函数，其中一个是对另一个的重新实现加放宽。

## 验证

按行为层面描述，不绑定某种实现形态：

1. 宿主的工具栏项列表里没有 `addMenu` 时，`+` 永不出现。有的时候，`+` 位于工具栏最前面，其它控件都不移动；唯一的例外是同时列出 `plan` 时，Plan 开关让位给菜单行和工具栏标签。
2. 用户选择「添加为附件」时，添加文件以附件形式落在消息上；选择「上传到工作区」时，落到磁盘并插入一个引用。三个引用子菜单插入正确的引用形式。Skills 把调用文本前置到输入的最前面。
3. 文件引用能凭部分名称找到 workspace 里任意位置的目标。
4. MCP 子菜单为每个 server 插入 server 级引用，包括那些暴露了资源的 server，语法与 `@` 面板对没有资源的 server 所用的一致；它有意不进入资源下钻。
5. 草稿为空时选中技能，得到调用文本后跟一个空格。草稿非空时选中技能，得到调用文本、一个空格，然后是之前的草稿——引用标签全部保留。
6. 任何插入都不会丢失已输入的文本或已插入的引用。
7. 某项能力不可用时，对应的项被隐藏，或以禁用状态显示并写明原因；只要 `addMenu` 在宿主的工具栏项列表里，`+` 本身就保持可见。如果所有内部项都不可用，`+` 会打开一个空状态行，而不是悄悄消失。
8. 触屏和桌面显示同一组项，但要以真机上的子菜单检查为准。
9. 长子菜单滚动，而不是溢出视口。
10. 覆盖指针交互；键盘导航不受支持，也没有针对本功能的专门实现。
11. 列出 `plan` 并提供切换回调时，Plan mode 是最后一行，Plan 开启时显示勾选，每次选择切换一次，把焦点交还 Composer，并在模式控件忙碌时以「模式切换中」为原因被禁用。没有 `plan` 或没有切换回调时，该行不存在。它始终保留在空状态行下面。
