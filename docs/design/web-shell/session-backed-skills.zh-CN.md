# 基于会话的 Skills 菜单

[English](session-backed-skills.md) | [简体中文](session-backed-skills.zh-CN.md)

## 问题与范围

部分宿主仅在会话存在后提供 Skills。对于新输入框，读取工作区目录无法得到该会话的权威命令列表。为菜单准备会话时，还必须保留草稿，并在用户发送首条消息时复用同一会话。

本变更新增一个默认关闭的 WebShell 集成选项。不修改服务端权限、不安装资源、不提交消息，也不增加另一套会话创建生命周期。

## 设计

可选属性 `skillsRequireSession` 默认为 `false`。启用后，打开内置 Skills 菜单或帮助对话框会准备当前输入框的会话，并读取其支持的命令。自定义页脚不会仅因挂载就提前准备会话；宿主可以在自己的菜单打开时调用输入框可选 API `ensureSession()`。

会话准备复用现有消息准备 Promise。并发发送可以共享该准备过程，并保留分离的客户端用于提交准入。如果导航已切换输入框，仅由菜单触发的准备会分离其客户端。挂载状态、来源版本、当前会话、请求代次和响应会话检查共同防止过期结果写入另一个输入框的菜单。

输入框复用既有草稿分配机制，在分配会话时迁移当前文本和附件。分配仅限于相同的输入框历史与草稿存储身份。并发发送可以接管该分配。

## 兼容性与风险

现有宿主保持默认目录行为。启用此选项的宿主需要支持会话命令查询，并容忍首次打开菜单时的会话创建延迟。打开菜单可以分配会话，但不会创建 turn。此客户端变更无法替代后端会话生命周期中缺失的资源初始化。

主要风险是导航期间的过期异步结果，以及准备与发送重叠时的草稿迁移。保留现有归属检查，不回退借用无关会话。

## 验收与验证

1. 在启用会话 Skills 的新输入框中打开菜单，应显示所分配会话的命令，且不提交消息。
2. 选择 Skill 并发送，应复用已准备会话，且准备期间保留当前草稿与附件。
3. 准备未结束时导航，旧结果不得写入新输入框；并发发送应保留既有准入行为。
4. 不设置此选项时，应保留现有工作区目录路径与自定义页脚行为。

首次菜单的会话准备、菜单展示及草稿保留，已在此次基于 main 提取之前的集成环境中确认。新基线上未运行测试、构建、lint 或类型检查。导航竞态与默认路径仍需评审者验证。本草案仅覆盖必须依赖会话的目录。首次初始化仍可能让菜单等待会话准备完成。会话创建前准备目录，以及让 Worker 就绪代表目录就绪，均不在本变更范围内；不宣称已改善首开性能。
