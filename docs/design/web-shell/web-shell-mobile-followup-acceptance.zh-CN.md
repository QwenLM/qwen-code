# 移动端 follow-up suggestion 接受

[English](web-shell-mobile-followup-acceptance.md) | [简体中文](web-shell-mobile-followup-acceptance.zh-CN.md)

状态:已实现于 `feat/web-shell-mobile-followup-acceptance`(PR #17918),2026-11-20–21 经多轮评审修订(Tab 键 → 动作词键 → 单 chip 建议条 → 光标/斜杠键排 → 240px 换行修复 → 字素/视觉行光标、列保持与滚动揭示 → 有界镜像测量、折行行尾字素钳制、仅垂直写列、展开对话框 surface、忽略不聚焦)。

## 问题

触摸输入框(原生 `<textarea>` 后端,`(hover: none) and (pointer: coarse)`)只把 follow-up suggestion 渲染成 placeholder 灰字。桌面 CodeMirror 用 Tab / Enter / → 接受,语义是「填入输入框但不发送」;触摸后端没有对应手势。空输入点发送会整条直发,输入前缀再发送会补全直发,但两者都不允许用户先编辑再发。

两个历史决策约束本变更:mobile-composer-actions 重设计移除了旧模拟 Tab/Esc/左右键,因为当时 Tab 在 textarea 后端上是死键;#14220 移除了编辑行的 ↑/↓ 历史步进,因为历史召回统一走搜索面板,且 plain textarea 恢复无法重建 inline tag chips。因此本变更不复活历史步进。

## 设计

一个触点,一条接受路径:

- **建议 chip 条**:输入行上方,覆盖所有 composer 变体;chip 样式的可点按按钮,标签即建议文本本身,前带插入图标,旁带忽略按钮。编辑行不带 follow-up 专用控件;其 → 光标键兼作同一接受(对齐桌面 ArrowRight)。

单 chip 出自三轮评审;后续轮次加入下文的光标/斜杠键排与窄屏换行。第一版加建议条与编辑行 `Tab` 键;评审指出触摸用户没有 Tab 键与相应肌肉记忆。第二版把该键改本地化动作词(`Fill in` / 填入 / Вставить);评审指出光秃及物动词仍缺宾语,且与建议内容空间分离。终版删除编辑行键,并给建议条 chip 容器(浅底、描边、插入图标),使其在无 hover 的触摸端读作可点:内容即标签,是最易懂的形态,也与业界移动建议 chip 一致。随键删除的还有 `composerMobile.fillFollowup` 目录键。

第四轮评审在编辑行尾侧(default 变体、触摸)加入始终有活功能的编辑键:↑/↓ 在*屏幕上显示的行*之间移动光标——只在光标邻域用缓存镜像测视觉软折行(每个 textarea 只保留一个镜像,替换即移除,草稿清空与编辑器卸载时 discard;行顶二分查找,不做全草稿逐字素矩形循环;字素步进本身不枚举视觉行,滚动揭示可读取有界镜像,因为原生程序化选区可能把远端光标留在视口外(见 Chromium 对照);20k/50k 草稿按键期间仍不逐字素重测全篇;布局不可用时回退逻辑 `\n` 行),步进与钳制都落在字素边界(光标绝不落入代理对中间),折行行的内容末尾取折行边界本身(仅显式 `\n` 跳过),空行用下下行行首哨兵保留零长度边界,连续垂直移动期间保持目标字素列(仅垂直移动写入;→、/、草稿编辑与用户跳选区时清除;我们自己的程序化选区变化豁免于跳选区清除),短行钳制、首/末行出界钳到文档首/尾,并把光标行滚回高度上限的滚动窗口;以上一次垂直移动实际落到的显示行为下一次按键的锚点,连续上移越过折行边界而不重选同一偏移。→ 右移一个字素,且仅当补全相对草稿确有剩余时兼作桌面 ArrowRight 式接受——完全匹配的草稿落到光标移动分支,键的 aria-label 用同一判据——接受时整草稿替换为补全(遥测 method `right`);/ 插字面斜杠——textarea 后端没有 slash 菜单,该键是字符便利键,命令浏览仍在加号抽屉。IME 组合期间按键让路;纯光标移动不碰草稿与其持久化。simple 变体与语音通话时编辑行不渲染,键排缺席。历史召回仍走搜索面板:不复活步进回调,故 #14220 移除步进的 inline-tag-chip 限制不适用。

对抗审计后的精化:镜像缓存与垂直锚点共用布局 fingerprint(client 宽度、复制到镜像的字体/间距指标、padding、边框宽度及字体就绪状态),宽度或字体/边框改变时不再复用陈旧视觉行。普通与展开 textarea 的 callback ref 都保留供既有 focus/blur 调用使用的 `.current`,同时在各自节点替换或卸载时立即丢弃镜像和宿主的强引用。右移字素仍不枚举视觉行;滚动揭示会按需做有界镜像测量,因为真实 Chromium 对照已证明仅调用原生 `setSelectionRange` 不保证露出远端光标。只给镜像 border-box 外宽补左右边框,给揭示坐标补顶部 padding,保证末行进入滚动窗口。没有 `Intl.Segmenter` 时,高代理只与真正的低代理配对。

后续布局审计又补了多项窄范围正确性约束。纵向移动以选区活动端为准：反向选区从 `selectionStart` 起算，正向或未指明方向的选区仍取原来的末尾，水平移动不变。镜像与缓存指纹采用计算样式中的布局宽度，并按盒模型与原生滚动条轨道校正，而不是使用受 transform 影响的绘制矩形宽度。无法按数值解析布局宽度时退回未缩放的 `clientWidth`，在展开对话框缩放等绘制变换下保持布局语义。空行起始偏移处的换行符保留自身行用于滚动揭示，不再回退到上一行行顶；逻辑行行尾换行符仍按上一行的亲和性测量视觉行。盒模型换算时，border-box 宽度先减去边框，content-box 的宽度则补回 padding，避免重复计入边框。`text-indent` 也纳入同一个镜像样式/指纹属性表；小数布局变化会替换唯一镜像，不复用旧几何。原生像素目标列与触屏字素列仍明确区分：在实测缩进夹具中，原生可落到偏移 13，而触屏按字素列选择偏移 10，二者都指向预期的下一条视觉行。滚动条轨道只在 border-box 中扣除；content-box 的计算宽度已由平台扣除轨道，只补回 padding，不重复扣减。桌面 Chromium 的 15px 原生滚动条对照覆盖两种盒模型。

可见性:触摸后端已挂载、建议可见、草稿为空、composer 未禁用。开始打字即隐藏,与桌面 ghost 的前缀规则精神一致,同时保证触摸面不干扰草稿。chip 可见时触摸 textarea 保持普通占位符,建议文字只出现在一个 surface 上;早先一版曾同时留在 placeholder 里,造成同屏重复。全屏展开对话框是 chip-only 规则的唯一例外:chip 条只渲染在行内输入框,故对话框打开且草稿为空时,由对话框 textarea 的 placeholder 与 aria-label 承载建议(草稿非空后还原普通占位符),保证任何布局下建议都恰好出现在一个 surface 上。桌面仍保留空输入 placeholder、前缀 ghost 补全的渲染。

接受调用 `onAcceptFollowup('tab')` 且不带 `skipOnAccept`,复用宿主现成的 `onAccept → insertText` 接线:填入 textarea 并请求 focus。焦点时序:composer 外层点击处理先在手势内同步聚焦 textarea;宿主 accept 再经 `queueMicrotask` 延迟插入并在插入后再次请求 focus。真 iOS 上延迟插入的 focus 请求可能落在 tap 手势之外、键盘可能不弹——真 iOS 键盘行为未验证、属范围外。忽略调用 `onDismissFollowup` 并阻止点击冒泡,外层聚焦处理不再执行:未聚焦状态下点忽略后 textarea 保持未聚焦、「收起键盘」控件不出现,保留既有 ignored 遥测。不新增数据通路:daemon sidechannel、controller、insertText 触摸分支均原样复用。

保留普通文本快路径:空输入点发送仍整条直发;输入普通前缀再发送仍补全直发。建议条让第一条路径可发现,但不改变其语义。

模型补全出的斜杠命令采用更窄的触屏契约。如果当前建议给出或补全 `/clear` 这类命令,首次发送通过既有 `onAcceptFollowup` 路径把它填入可编辑草稿并消费建议,**不调用 `onSubmit`**。前缀选区会被替换,所以 `/cl` 得到 `/clear`,而不是 `/cl/clear`。用户检查或编辑后,第二次明确发送才提交。普通文本以及完全匹配的手输命令仍保留单次发送。守卫每次都根据活动建议和当前会话判定,不保存可跨会话转移的命令接受请求;接受和会话切换都会清理旧建议,避免陈旧的命令误落入新会话。桌面 CodeMirror 行为与宿主命令分派保持不变。

## 约束

- 44px 触摸目标;chip 行仅在有建议时占一行 44px,空闲布局不变。
- textarea 保持 16px 字号(iOS focus 自动缩放规则);chip 是按钮,14px 文本 + 插入图标 + 单行省略。
- chip 与其它输入框控件一样 preventDefault mousedown,避免在手势插入前丢焦点;aria-label 组合本地化动作与建议文本,屏幕阅读器两者都得。
- 「不出现模拟键盘键」的旧验收仍然成立:没有 follow-up 控件命名键盘键或光秃动词;编辑行键是有原生语义的光标/字符键,不是模拟接受/历史键。
- 编辑键在 IME 组合期间让路(compositionstart/end 门控);纯光标移动不改草稿,草稿持久化与历史浏览状态不受影响。
- 可选收起键盘按钮紧挨放大按钮之前,放大始终是编辑键组末项。两者组成不缩小的 flex 尾键组,整组换行:其它编辑键可以排在较早的行,但收起键盘与放大必须相邻,放大的右缘位于键组末尾,不缩小 44px 触摸目标也不溢出视口。
- composer 容器宽度不超过 320px 时,工作区与分支的长文字标签通过容器查询收起为图标,保留选择入口及可访问名称;方向键、收起键盘与放大仍保留,打开菜单后仍能看到完整名称。触摸编辑器把工作区菜单的首选方向设为 bottom,避免菜单展开跨行时覆盖本次触摸激活位置;其它选择器调用点保留原来的默认 top。
