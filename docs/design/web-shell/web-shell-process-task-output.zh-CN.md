# Web Shell 进程任务输出

[English](web-shell-process-task-output.md) | [简体中文](web-shell-process-task-output.zh-CN.md)

## 目标

在 Web Shell 的 Shell 和 Monitor 任务详情中直接展示捕获的输出，不依赖 Monitor
任务通知到达 Web Shell。

## 设计

- 在 Monitor 已预留的 `outputFile` 中捕获 stdout 和 stderr 的滚动尾部，最多保留
  64 KiB 加一个字节；额外字节用于保留任务输出 API 的截断信号。Shell 已经将两路
  输出写入自己的任务输出文件。
- Monitor 捕获和尾部读取使用同一个状态大小恒定的流式日志过滤器。Monitor 的每路
  输出各自拥有 UTF-8 解码器和过滤器。转义序列的载荷随到随丢，不完整或超长序列
  不会在内存中累积。换行结束不完整序列，保留后续日志行。过滤器移除控制序列，
  不模拟终端光标移动或字符集。
- 尾部读取最多解析窗口前的 4096 字节来恢复序列状态，但丢弃该前缀产生的所有文本。
  只有请求窗口内的字节参与响应。UTF-8 解码不得使响应超过调用方的字节预算。
  起点早于有界回看范围的序列不一定能被重建。
- 新增归属于实时会话 owner 的读取路由：
  `GET /session/:id/tasks/:taskId/output?kind=shell|monitor`。
- 通过所选会话的 runtime 解析请求，并在该 runtime 的 registry 中查找任务。
  不接受客户端提供的文件路径，也不回退到 primary runtime。
- 返回最多最近 64 KiB 的已清理 UTF-8 文本及 `truncated` 标志。打开任务所属文件时
  拒绝符号链接和非普通文件。折叠回车重绘时，若丢弃了非空白帧，也报告截断。
- 通过 `session_task_output` capability 声明该路由。旧 daemon 保留原来的仅元数据
  详情界面。
- 在 `MonitorTaskDetail` 和 `ShellTaskDetail` 的现有元数据下方展示输出。现有任务
  快照变化时刷新。恢复的跨会话标签页无法通过当前会话的轮询更新快照，因此在任务
  运行期间还会按相同的任务轮询周期刷新输出。
- 输出框已溢出且位于底部时，新输出继续跟随到底部；用户向上滚动后保留滚动位置。
- 提供复制当前可见输出快照的操作。
- 任务进入终态后保留最终输出。空输出和暂时不可用使用明确、非致命的界面状态。
- Monitor 捕获写入失败时，Web Shell 和 TUI 任务详情都显示本地化警告，同时保留
  已捕获的输出。警告不暴露原始文件系统错误中的路径，也不复用会替换输出内容的
  读取错误通道。成功刷新后清除警告。连续三次失败后停止继续写入；直接执行和
  沙箱执行都等待待处理的捕获写入完成后再结算终态。终态 Monitor 的输出读取也会
  等待待处理的捕获写入，避免取消任务后已停止刷新的输出面板一直显示刷新前的尾部。

## 非目标

- 完整日志归档、搜索、下载或分页。
- 修改 ACP Monitor 通知限流或 XML 信封防护。
- 将 `outputFile` 暴露为任意文件读取能力。
- 完整终端模拟。

## 验证

- Core 测试覆盖 Monitor 文件创建、stdout/stderr 捕获、有界滚动尾部、写入失败恢复
  和沙箱完成路径。
- 过滤器测试覆盖代表性转义序列的每个切分点、相邻转义、嵌入控制字符、C1 引导符和
  超长载荷。
- 尾部测试断言 8 KiB 通知预算和 64 KiB 任务输出上限，包括含可打印文本的回看前缀
  和 UTF-8 边界。
- Core、ACP 和 bridge 测试共同覆盖任务归属、类型校验、任务不存在、截断、拒绝
  符号链接以及新增状态方法。
- SDK 测试覆盖 REST 和 ACP 路由映射。
- Web Shell 测试覆盖 Shell/Monitor 输出、刷新、有条件的自动滚动、复制、截断、
  空输出、读取失败和 capability 回退。Web Shell 和 TUI 测试要求捕获失败时显示
  警告；Web Shell 保留已捕获输出，并在恢复后移除警告。
- E2E 验证运行中输出出现在任务详情中，并在任务停止后保留。审查回归验证先尝试
  全局 CLI；已发布 CLI 尚无该功能时使用精确源码测试。
