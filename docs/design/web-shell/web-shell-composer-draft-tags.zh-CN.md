# 恢复 Web Shell 草稿标签

[English](web-shell-composer-draft-tags.md) | [简体中文](web-shell-composer-draft-tags.zh-CN.md)

## 问题

桌面端输入框用内联标签展示嵌在草稿正文中的序列化引用。刷新后，Web Shell 会恢复草稿正文和已保存的文件标签。宿主定义的标签丢失位置，显示为序列化文本。

## 设计

复用宿主的 `parseUserMessageContent` 重建内联标签。解析结果必须逐字覆盖原始正文。根据各解析片段的长度推导标签区间，并丢弃空区间。

对于提供宿主解析器的桌面端输入框，在现有草稿存储格式中增加一个可选的内联区间数组。保存编辑器已知的区间，没有宿主标签时保存空数组。只持久化宿主标签的位置。解析器在记录的准确位置重建已识别的标签，因此其他位置手动输入的相同文本仍可编辑。标签元数据在恢复时重新生成。

旧草稿没有区间数组。在已有结构化文件标签区间之外，恢复解析器识别出的引用。文件标签保留已保存的位置和元数据。解析器无法重建的标签保留为可编辑文本。共享同一草稿的输入框继续使用编辑器中的实时位置。

对于至少有 64 Ki 个 UTF-16 代码单元的草稿，先显示正文和已保存的文件标签。首个渲染时机过后运行宿主解析器，再通过一次编辑器事务添加识别出的宿主标签。切换会话时只应用一次目标草稿。等待解析期间，随正文编辑映射已保存的区间，保存时保留这些区间。如果用户在解析运行前提交，先恢复待解析引用，以便提交时带上引用标注。

此改动覆盖桌面端内联输入框。触屏文本框沿用现有草稿行为。

## 验收标准

- 在正文中插入两个宿主标签，刷新后确认它们原位恢复。删除其中一个标签并再次刷新。剩余标签保留在原位置，提交时只有它的引用带有标注。
- 手动输入一处序列化引用文本，再在另一处插入对应标签。刷新后，只有插入的引用显示为标签。
- 打开含宿主引用和已保存文件标签的旧草稿。已识别的宿主引用恢复为标签，并且不会与文件标签重叠。缺少解析器或解析结果改变正文时，宿主引用保留为可编辑文本。
- 在拥有不同草稿的两个会话之间切换，确认显示的标签位置对应当前草稿。
- 打开或切入大草稿。首帧显示正文和已保存的文件标签，宿主标签在之后的一次更新中出现。如果用户编辑后立即切走或关闭编辑器，下次恢复时保留编辑结果和剩余标签的位置。
