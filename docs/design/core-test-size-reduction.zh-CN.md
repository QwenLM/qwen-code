# Core 测试代码减量

[English](core-test-size-reduction.md) | [简体中文](core-test-size-reduction.zh-CN.md)

状态：已在实验分支实现并完成测量，2026-09-27。
[实验与结果报告](core-test-size-reduction-results.zh-CN.md)汇总实测对照和证据入口。

## 背景与目标

Core 的固定主干快照包含 673,272 行测试代码和 400,027 行生产代码。
重复准备、冗长预期和重叠场景增加了阅读与维护成本。本任务降低需要维护的
测试代码量，同时测量回归检出能力与诊断信息的损失。

原始跨包方案希望总计减量 50%，各包至少减量 40%。本任务聚焦 Core，
最终相对固定主干快照**减少 223,587 行，即 33.21%**。采用与否由声明的
能力预算决定；最初的规模目标服从这些预算。运行速度与源码规模分别测量。

## 范围与基线

实现范围是 `packages/core` 内的测试、辅助代码、夹具和快照，测量工具与证据
位于 `scripts/test-loc`。Core 生产行为保持不变。其他包、集成测试、生产代码
重构和后续测试增长治理不在本任务范围内。

| 对照身份           | 提交                                       | Core 测试行数 |
| ------------------ | ------------------------------------------ | ------------: |
| 整体基线：固定主干 | `9e60263fdeff8cb5bf5fc49287a2d20cef0dbe2e` |       673,272 |
| 最终删除阶段基线   | `a270907e5f3fd6ebe26ef7d17ea7da3e92c2773a` |       490,301 |
| 最终实测测试代码   | `460151af0c6ec2a19d7a4d736aadda023a696527` |       449,685 |

每项实验都指定自己的基线、候选和范围。累计规模比较主干与最终版本。
最后阶段的覆盖与变异测量比较 `a270907e5f` 与最终版本，描述该阶段的增量变化。

## 减量方法

针对一个完整行为域选择成本最低的合适方法，让输入差异和可观察预期保持明确。

| 方法                 | 应用                                                             | 审查要求                                                           |
| -------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| 共享准备与夹具       | 用小型工厂复用请求、配置、响应和 mock 准备                       | 保留字段缺省、顺序、异步行为和每例独立状态；辅助代码与夹具计入规模 |
| 参数化场景           | 相同结构的场景使用表格和序列辅助函数                             | 每行保留输入、预期和有用名称；保留不同前置条件及断言               |
| 完整输出预期         | 手写完整结果替代测试侧解析和零散局部断言                         | 预期值独立于实现；同时检查转换结果与应保留内容                     |
| 行为契约             | 一个完整对象或生命周期检查相关结果；共享网络断言检查实际请求行为 | 保留事件分派、调用方接线、选项传递、错误和交互边界                 |
| 有预算地删除冗余测试 | 根据覆盖与故障/变异检出关系寻找重叠文件或用例，再实测精简套件    | 检出关系图用于选取候选；保留关键反例，并验证删除后的实际检出能力   |

共享辅助函数保持精简，表达容易识别的测试操作。通用场景语言可能隐藏契约，
增加维护成本。合并用例也会减少独立失败名称：前一个断言失败可能阻止后续检查。
这些代价与行数收益共同进入审查。

## 指标与统计口径

### 规模

- **S1：**全部测试分类文件的物理行数，固定仓库格式化配置。这是主要减量指标。
- **S2：**同一文件集合的字节数。与 S1 同报，识别仅靠合并行或调整排版产生的减量。
- 辅助观察：可执行测试文件数、源码用例调用估计数、实际执行用例数、执行断言数及
  S1/生产 LOC 比值。静态 `.each` 调用数与展开后的运行时用例数含义不同。

分类器包含 `.test.`、`.spec.`、`__tests__`、`__mocks__`、`__fixtures__`、
`fixtures`、`test-utils`、`testUtils` 和 `.snap` 路径，也包含非代码夹具。
当前计数器统计已跟踪及未被忽略的未跟踪文件，排除 `dist`、`build`、`out`、
`coverage`、`node_modules` 和 `vendor`。在此范围内把内容移入辅助代码、夹具或
快照仍计入规模。跨包迁移必须把目标位置纳入测量后，才能认定减量。

### 能力

| 指标             | 定义与解释                                                                                                                               |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| **C1：历史故障** | 在冻结的历史修复集合中，仅反向应用生产代码改动。检出必须是相对对应健康运行新增的已执行断言失败。按故障身份比较检出保留情况。             |
| **C2：变异**     | 在相同生产源码上，以冻结的预期清单逐个比较相同变异。报告每个旧 `Killed` 的保留、丢失或未知，以及新增检出和其他状态。单一分数会掩盖损失。 |
| **C3：覆盖集合** | 比较原来覆盖的行和分支身份。损失与新增集合分别报告，损失预算使用固定基线分母。分支形状变化和无法匹配的身份单独列出。                     |
| **C4：诊断**     | 观察 C1 的失败文件数、用例数、名称和同名相邻测试定位，显示合并带来的诊断成本。审查前一个断言失败是否会遮蔽另一个行为。                   |

`Timeout`、收集错误和缺失结果保持可见，按相应口径保留为未定。
新增变异检出不能抵消旧检出损失。覆盖与结构重复度可用于寻找候选；
它们一致仍需回归检出证据支持。

### 套件健康与执行成本

记录实际测试清单、通过/失败/待定数量、收集错误、未处理错误和进程退出状态。
与基线对照，区分新增与已有失败。构建、类型检查和定向测试验证保留的改动。

T1 为固定 worker 数的全套件耗时；T2 记录最慢文件或明确指定的固定文件。
性能结论需要重复配对运行、报告波动范围，并使用没有竞争负载的同一环境。
最终采用结果不主张提速。长期重试率、测试增长与审查成本仍属于后续测量，
并非已经完成的验收项。

## 实验流程

1. **冻结对照。**记录提交、生产/运行时指纹、格式化器、锁文件、工具版本、
   测试清单和候选哈希。在决定采用候选前，明确假设、行为映射和接受预算。
2. **准备可比环境。**在同一 Linux VM 上分别构建基线和候选，使用相同运行时和
   有限 worker 数。共享辅助代码变化必须使用完整的独立工作副本。包测试从
   `packages/core` 运行。
3. **筛选并审查。**测量 S1/S2 和定向测试健康/覆盖。审查删除的输入分区、mock、
   预期、顺序、状态隔离，以及安全、权限和数据完整性边界。
4. **测量能力。**回放前冻结 C1 补丁与定向测试范围，每组先运行无故障健康检查。
   删除场景同时记录原始范围与保留交集。比较前冻结 C2 源码、变异身份清单、
   算子、静态范围和请求/实际执行测试。纳入实现相关行为的依赖。
5. **验证候选。**比较完整原生套件健康与覆盖、构建/类型检查/lint 结果及运行后
   源码哈希。竞争能力测量任务停止后执行最终全套件对照。同时审查局部损失和
   汇总指标。
6. **归档并决定。**保存计划、命令、配置、原始报告、失败尝试、映射和候选原始
   字节及哈希。汇总与原始证据分别发布。审查接受的完整差异，记录承载实测测试
   代码的提交。

无法应用的补丁在冻结计划中两侧对称排除。已确认的环境失败可以凭证据，按完整
测试名称从定向回放中排除；原生套件保留其结果。仅有收集错误不能检出历史故障。
复用观察必须具有相同实际执行范围和相关源码/测试哈希，并标明来源。根据已观察
故障或变异修复的候选已拟合该样本；后续通过用于验证修复。

## 接受标准

### 保守压缩与契约合并

机械压缩初期保留名称与每例断言，显式记录重复用例删除。有意的契约合并在行为
映射经过审查后允许用例和断言变化。S1 与 S2 都必须下降。测量范围内已观察到的
历史故障检出和可判定的旧变异检出必须保留。覆盖差异需要证据和解释。
未知结果与未通过的严格比较器，和有条件采用决定一同记录。

### 最终有预算删除

- C1：保留已观察到的历史故障检出，显式审查安全、权限与数据完整性检查。
- C2：声明的汇总样本中，最多损失基线 `Killed` 变异的 **1%**；逐模块报告。
  新增检出不抵消损失。旧 `Killed` 的未知结果不能通过预算。
- C3：最多损失 **0.5 个百分点**，计算为
  `100 × 丢失的原已覆盖行数 / 基线插桩行数`。新增覆盖不抵消损失。
  检查集中在局部的损失。
- C4：允许减少用例、断言和独立名称；说明诊断细节减少，保留有意义的失败解释。
- 保持生产代码不变并调查新增测试失败。最终源码必须通过构建、类型检查、lint
  和定向验证；原生套件差异对照固定基线评估。

最终阶段以上述预算取代逐例、逐断言完全保留要求。样本失败则修复或缩小候选。
样本通过支持已声明范围；扩展到其他领域时，建立新的对照并补充该领域所需的
行为证据。

## 最终状态与限制

相对固定主干，S1 为 **673,272 → 449,685**，S2 为
**23,538,737 → 16,307,779 字节**。生产 LOC 保持 **400,027**，core 差异只涉及
测试分类路径。结果已实现在实验分支；[结果报告](core-test-size-reduction-results.zh-CN.md)
记录分阶段验证和复现入口。

最终删除阶段损失原已覆盖行的 **0.3041 个百分点**，四个实测模块保留
**385/385** 个旧 `Killed`。这些数值以 `a270907e5f` 为对照。
能力验证按阶段完成，尚未重新执行主干到最终版本的完整能力对照。

样本只覆盖 core 的一部分。修复后的故障样本属于拟合验证，变异超时限制严格比较，
Linux arm64 及跳过的平台/真实模型用例限定实际执行范围。一些模块的局部覆盖损失
明显高于包平均值。合并和删除减少了诊断细节、普通边界输入检查、召回质量评估及
扫描延迟评估，这些是采用结果的已记录代价。33.21% 是已经实现的减量；
最大可减量尚未确定，也未建立全包能力等价或运行提速结论。
