# Headless 记忆任务所有权

[English](headless-memory-task-ownership.md) | [简体中文](headless-memory-task-ownership.zh-CN.md)

状态：已在 PR #13885 中实现；需要维护者审阅。

## 问题与范围

Headless 回合取消后必须及时停止等待，同时保留未完成提取、整理或技能审查任务的共享跟踪。在中断前破坏性消费列表会丢失这些跟踪，使后续回合或正常 stdin EOF 无法等待这些工作。

本次变更在等待已跟踪记忆任务之前输出 headless JSON 和 stream-JSON 的最终 `result`。单次调用结束，以及 stdin 保持打开时可复用 stream-JSON 会话的回合，仍会等待这些任务。正常 stream-JSON stdin EOF 立即释放会话的记忆等待信号，前台工作完成后由一个全新的 5000 ms 窗口约束最终遗留记忆等待；单次调用的失败与取消终端各有自己的 5000 ms 窗口，成功终端无界等待，仅受运行取消信号约束。取消及预算结果，以及现有 TUI 的 `memory_saved` 交付方式保持不变。不新增任务取消 API。元数据迁移仍不属于该列表。

两种 JSON 格式已输出的 `usage`，以及成功 JSON 输出中的 `stats`，都是收尾等待前取得的快照。它们不包含等待期间才记录的记忆用量，记忆任务完成后也不会更新已输出的结果。因此，这些总量不保证涵盖完整调用的用量；详见 [Managed Memory Completion](../users/features/headless.md#managed-memory-completion)。

## 所有权与完成状态

`LlmClient.getPendingMemoryTaskPromises()` 返回副本，不转移所有权。`removePendingMemoryTaskPromises()` 仅按所提供的 promise 身份从当前队列移除。移除旧快照时保留新追加的任务。

共享的 headless 等待器立即为每个快照条目注册成功和拒绝观察器。观察器记录完成状态，不发出事件。等待器将全部观察任务与调用方取消信号竞争；在可复用 stream-JSON 会话中，还会使用独立的记忆等待截止信号。在 `finally` 中移除信号监听器。

快照中的任务全部结束时，移除所有条目。中断或截止时间到达时，只移除已观察到结束的条目，未完成条目保留在客户端队列中。不执行重新入队，因此等待器不会恢复已完成工作，也不会重新加入其他所有者已消费的任务。到期后正常返回，并报告已停止等待，不会报告全部任务已结束。真正的取消或预算中止保持现有结果，即使它与截止时间同时到达。

`consumePendingMemoryTaskPromises()` 保留现有 TUI 的破坏性消费行为，将计数 promise 一次性交给 TUI 通知处理器。随后 headless 的移除操作具有幂等性，不会重复发出 `memory_saved`。不在任务完成时自动移除条目，因为 TUI 仍需读取解析后的计数。

## 会话关闭

正常 EOF 立即释放会话的记忆等待截止信号：已经阻塞 `processingPromise` 的等待停止等待，剩余回合中之后开始的记忆等待也直接返回，未完成任务的跟踪身份保留。排队回合和控制请求随后在不受记忆约束的情况下完成——该窗口约束的是记忆等待，而不是前台工作。这些工作结束后，最终遗留记忆等待开启一个全新的 5000 ms 窗口。这里有意不设从 EOF 起算的绝对截止时间：在 EOF 处武装的窗口会被前台工作本身耗尽，之后开始的每个等待都会拿到已释放的信号而完全不等待。

到期只停止记忆等待，不会中止前台回合、取消任务、更改结果或选择取消退出码。如果窗口早于前台回合输出最终结果到期，该回合仍正常完成，之后的记忆等待不再新增延迟。最终等待使用会话取消信号，而非被中断回合的信号。等待期间收到信号仍会停止等待并执行关闭清理。已经取消的会话或错误驱动的关闭不会发起新的记忆等待。

最终窗口的定时器在完成、取消或出错时都会清除，包括等待待处理工作期间发生的错误。信号监听器会被移除；正常完成、窗口到期或等待期间取消，都会只进入一次关闭清理。现有错误恢复流程保持不变。单次调用没有会话 EOF 时刻。其失败与取消终端各自武装一个 5000 ms 窗口；成功终端则等待本回合启动的记忆写入，仅受运行自身的取消信号约束——与基线行为一致，成功路径不引入任何等待期限。stdin 保持打开的会话在其回合内等待，受会话的截止信号约束。

5000 ms 是尽力而为的关闭策略，不保证记忆更新在这段时间内完成。它约束的是每个记忆等待窗口，而非从 EOF 到进程退出的完整时长：初始化、控制请求、前台模型工作、记录落盘、输出刷新、资源释放及退出清理仍可能耗时更久。

每次等待处理一个客户端快照。进程存活期间，新条目保留给后续等待器；单独排队的提取后续任务不一定包含在该快照中。快照中的任务全部结束，不代表记忆管理器已经空闲，也不代表每次写入都成功。保留的 promise 身份只是内存中的跟踪信息，不是持久化队列，也不承诺在后续进程中恢复工作。进程退出可能放弃未完成的记忆更新，包括仍在进行的写入。

## 验证与验收

- 两次真实 runner 调用共享实际队列方法：第一次在记忆未完成时返回 130，第二次必须等到同一任务结束。覆盖等待前和等待期间中断、拒绝/完成条目及新追加工作。
- 队列测试验证快照副本、按身份移除、新工作保留，以及其他等待器移除旧身份后 TUI 计数仅消费一次。
- Session 测试及构建 CLI 重放覆盖 EOF 发生在活动回合的记忆等待期间、仅剩遗留工作的情况，以及前台工作超过任何绝对截止时间的情况：被释放的回合内等待保留任务身份，最终窗口到期后遗留路径停止等待，不得替换结果或取消前台工作。覆盖最终输出前到期、真正取消与窗口竞争、部分完成、新追加工作及延迟拒绝。定时器和信号监听器必须清理，关闭只执行一次，结果及通知计数不得重复。
- 保留单次调用和 stdin 打开时的等待、SIGINT 及预算结果、输出失败行为，以及收尾前用量快照的契约。单次调用在排空窗口到期后必须以原有错误结果结算，未完成任务保持跟踪。延迟记忆任务的构建 CLI 重放必须区分提前交付结果与有界的记忆等待。
- 移除未完成任务跟踪、跳过 EOF 等待、移除截止时间或遗漏活动回合截止信号连接的变异必须失败。运行相关套件、构建/打包、类型、格式、lint 及独立审查。继续披露历史全量套件失败和外部重放限制。

两个行为保持回归场景借鉴了 [TYY-2005 的 PR #13886](https://github.com/QwenLM/qwen-code/pull/13886)：模型正常完成后最终输出失败，仍须等待记忆任务并保留原始输出错误；缺少结构化输出且记忆任务分别成功和拒绝时，须只输出一个错误结果并返回 1。测试还检查了不同的重试错误，以及仅发生一次的输出刷新失败。

新增的跨包队列 API 和调用生命周期契约需要维护者在合并前确认。
