# 后台 Shell 任务详情

[English](2026-10-19-shell-task-detail-runtime.md) | [简体中文](2026-10-19-shell-task-detail-runtime.zh-CN.md)

状态：已在 `feat/web-shell-shell-task-detail-info` 上实现，待评审。

## 问题

web-shell 的 shell 任务面板目前只显示命令、状态、运行时长、PID、工作目录和输出文件路径。对长时间运行的任
务来说这不够：看不到任何输出，无法判断进程是否还在产出，也不知道它是从什么时候开始跑的。输出文件位于
session 临时目录，现有的工作区文件路由读不到。

## 目标

- 在面板内显示被捕获的 stdout/stderr 尾部。
- 显示输出文件大小和最后写入时间，让“还没有输出”和“一直在产出”可以区分。
- 显示 shell 进程树的常驻内存。
- 显示开始/结束的本地时刻，并让命令和路径可以复制。
- 让面板 tab 的标题从命令派生，截断后仍能辨认。

## 非目标

- CPU 占用。两个平台的口径不同（Linux 是生命周期平均，macOS 是约一分钟的衰减平均），不额外维护采样状态
  的话，单个数字会误导。
- 拆分 stdout 与 stderr。当前捕获的就是一个合并流。
- 通用进程监控（子进程树浏览、端口探测、采样历史）。

## 数据流

任务列表仍然只做轻量快照。详情由一个新的只读接口按需获取：

1. web-shell 面板请求 `GET /session/:id/tasks/:taskId/runtime`。
2. daemon 通过一个独立的状态方法转发到 session 进程。
3. session 用任务 id 在自己的 `BackgroundShellRegistry` 里查条目，调用方不提供路径。随后读取输出文件的
   stat 和尾部，并对注册的 pid 做进程树采样。
4. 响应只包含 `memoryBytes`、`outputBytes`、`outputModifiedAt`、`outputTail`、
   `outputTailTruncated`、`outputError`。

任务运行中面板每 3 秒轮询一次，进入终态后重新获取一次。每次 effect 生命周期独立限制并发，避免旧的在途请求阻止终态读取或 StrictMode 重放。请求失败显示重试按钮，终态不持续轮询。用户点击停止后，面板保持运行状态并禁用停止按钮，同时轮询原会话的任务状态；只有后端返回终态后，才显示对应结果并重新读取最终输出；停止请求被接受本身不代表任务已结束。状态查询临时失败会继续重试。未知或已被淘汰的任务返回 `runtime: null`。

ACP 同样通过 `_qwen/session/task_runtime` 提供该能力，参数为 `sessionId` 和 `taskId`，且要求连接拥有该会话。REST 与 ACP 都使用存活会话的所属 runtime。跨会话标签页恢复时，所有任务请求都绑定到原会话。

## 决策

- **按需获取，不并入任务列表。** 读输出和跑 `ps` 比快照贵，而且只有打开的面板需要。
- **路径由服务端解析。** 路由接收任务 id 而不是文件路径，session 从自己的 registry 里取路径。
- **叫常驻内存，不叫内存占用。** 数值是进程树的 RSS。共享页按进程各计一次，换出的页不计，容器沙箱下
  daemon 看到的 pid 可能只是外层包装进程。因此标签写“常驻内存”，不写“内存占用”。
- **尾部沿用完成通知的 8 KiB 上限。** 面板和完成通知通过同一个 helper 读同一段字节。
- **只在运行中采样内存。** 结束的任务没有存活的 pid，显示旧数字比不显示更糟。
- **部分失败不隐藏成功输出。** 文件信息读取失败时仍展示已读到的尾部并附加提示；任务已不可用、读取失败、运行中暂无输出和终态无输出使用不同文案。时间格式遵循应用语言，时区仍为浏览器本地时区。
- **复制在本地完成。** 复制按钮只写浏览器剪贴板，不经过 daemon。

## 限制与风险

- 沙箱（容器）里的 shell，pid 可能描述的是包装进程，内存数字会明显低于真实负载。registry 没有 pid 时
  该指标不显示。
- 输出尾部是一个快照。两次轮询之间写入的字节要等到下一次轮询才可见。
- 在读取状态和跑系统探针之间，pid 可能被复用。窗口很小，而且这个数字只用于参考。

## 验证

- 单测覆盖 `ps` 表格解析、进程树求和、环处理，以及 SDK client 调用。
- 回归测试覆盖终态与 StrictMode 的异步加载、失败重试、轮询清理、部分失败、空输出、应用语言及复制状态；标题在刷新和重复打开后保持短格式。
- 路由测试覆盖 REST 的会话所属 runtime、未知会话不回退，以及 ACP 的参数和连接归属校验；telemetry 目录与路由双向匹配。
- 跨会话恢复测试确认 runtime 请求使用原会话。停止回归测试通过实际点击按钮，覆盖属性仍为运行中的面板、状态查询临时失败及晚到的旧响应，确保最终输出与真实终态一致。
- 手工验证：跑一个后台 shell，打开面板确认输出、大小/最后写入、常驻内存、开始时间和复制动作；停止后
  确认最终尾部和退出码仍然可见。

## 验收

- 运行中的 shell 无需手动打开输出文件，就能看到输出尾部、输出大小与最后写入时间、常驻内存。
- 结束的 shell 能看到最终尾部、退出码和结束时间。
- 未知任务或非 shell 任务返回空详情，而不是报错。
