# TUI 视觉层次

[English](tui-visual-hierarchy.md) | [简体中文](tui-visual-hierarchy.zh-CN.md)

## 问题与范围

默认 CLI 已有工具摘要和虚拟历史视口，但视觉层次主要依赖前景色。用户消息、
代码、弹窗和过程摘要需要一致的背景、间距与强调规则。本次实现用户选定的
配色层次、过程摘要、对齐、弹窗一致性和动态输出稳定性。输入区整体重排、
渲染器迁移和 agent 行为变更不在第一阶段范围内。后续的
[工作区布局设计](tui-workspace-layout.zh-CN.md)涵盖悬浮弹窗、输入贴底和跨条目的
过程摘要。实现基于当前 main，不参考之前的 UI worktree。

## 设计

- 为 Qwen Dark 和 Qwen Light 设置中性的画布、表面和代码颜色，以及清晰的
  主文字、辅助文字和克制的紫色强调。增加可选语义色 `background.surface`
  和 `background.code`。未提供这些字段的已有主题、自定义主题保持透明表面。
  `NO_COLOR` 和屏幕阅读器输出不绘制背景。
- 透明区域的文字继续使用终端原生前景色。自绘背景的用户消息使用主题自己的
  前景色，代码原本已有配对的前景与背景。弹窗包含未指定颜色的文字，因此仅在
  内置主题与检测到的终端明暗一致时绘制表面背景，保证白底终端使用默认深色主题
  时仍清晰可读。
- 用户消息使用普通前景色和表面背景。流式与完成后的围栏代码使用相同背景。
  保持行数和内容宽度，使渲染与文本选择几何信息一致。
- 单工具保留描述，多工具使用本地化的分类数量摘要。保持已有工具组边界，
  保留错误、取消、审批、图片和完整详情的展开行为。
- 紧凑摘要固定为一行。活跃工具提示放在同一行，完成后的过程弱化显示，计时器
  出现前预留宽度。同步更新高度估算。OpenTUI 共享摘要语义，并保持已有的
  活跃工具显示策略。
- 模型与主题选择器使用共享弹窗框架，沿用既有内边距预算。权限视图使用相同
  表面背景，保持输入路由与权限语义。矮屏模型选择器收起详情与垂直内边距；
  窄屏或矮屏主题选择器隐藏预览并限制可见条目。权限标签、搜索宽度和列表容量
  根据可用列数、行数调整。
- 输入区域边缘和补全列表沿用历史正文的两列外边距。根据实际可用列数计算
  输入宽度，保持输入区组件结构与键盘行为。

## 影响范围与约束

变更限于 `packages/cli/src/ui` 及其相关测试。主题构造与自定义主题映射负责填充
可选颜色，Ink 的消息、代码与弹窗组件消费这些颜色，OpenTUI 将消息与弹窗背景
映射到已有调色板，其原生围栏代码的显示方式本次不变。文本选择、源内容复制
索引、历史 ID、agent 调度、终端协议和同步输出
继续保持原有职责。不增加依赖、配置项、动画循环或历史聚合层。窄终端仍须保留
可见输入和可操作的弹窗。

## 验证与验收

使用隔离运行目录，对比全局 `qwen` 基线与本地 bundle。验证确定性的中英文回答、
围栏代码、多工具读文件与搜索、主题/模型/权限弹窗、窗口缩放和完整详情展开。
覆盖深色、浅色、`NO_COLOR`、40 列宽度和矮终端。截图使用 Chrome Canary。
通过针对性测试检查工具完成前后、计时器出现前后的单行摘要高度，并验证错误与
审批仍可见。独立代码审查前运行构建、类型检查、bundle、相关单元测试、lint/
格式检查，以及连续两轮无问题的自审。

验收要求：消息和代码背景一致，多工具生成简洁的本地化摘要，提示或计时器变化
不会新增行，选择器使用统一外框，窄屏、浅色和无色模式行为完整。动态验证记录
实际观察结果，不用静态截图声称完全没有闪烁。

## 风险与待定事项

背景绘制不得改变测量高度或复制文本。主题切换应正常刷新已有颜色。ANSI 和未
提供可选背景的自定义主题必须安全回退。当前没有阻塞性待定事项；跨历史项聚合
与输入区重排留作独立工作。
