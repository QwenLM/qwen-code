# Web Shell 中 `/export` 的会话产物

[English](web-shell-export-artifact.md) | [简体中文](web-shell-export-artifact.zh-CN.md)

状态：已实现，并有仓库内回归测试。浏览器验证记录属于本地工作证据，不包含在仓库中。

## 目标与兼容性

执行 `/export md|html|json|jsonl` 后，Web Shell 必须在命令所属回合显示导出文件，并提供已有的 artifact 预览和下载控件。保持 CLI 的参数解析、路径校验、格式化、文件权限、输出位置以及成功/错误文字不变。交互式和非交互式 CLI 调用返回原有结果，不带 artifact 元数据；只有 ACP 调用在成功写入后附带描述。

侧边栏导出操作和 HTTP 导出路由保持不变。不新增存储类型、文件写入器、命令实现、daemon 路由或依赖。

## 对初版实现的重新评估

初版复用 workspace artifact、传递结构化描述而非解析成功文字，这个方向合理。但注册产物不等于用户能够找到它：回合输出选择器仅关联工具调用，而 `/export` 没有工具调用。真实本地 daemon 已复现：目录中存在可用 HTML artifact，但浏览器没有卡片或预览入口。

初版文本分页设计也不成立。限量文本读取可能返回 `truncated: true`、`hasMore: true`，却没有游标，HTML 超长行就是一种情况。文本窗口不是无损字节流，拼接不能保证还原原始文档。将没有游标当作读取完成会静默截断预览。原来的模拟分页测试没有反映这一契约。

浏览器 E2E 又暴露了第三处不兼容：导出 HTML 从带版本的 CDN 加载渲染器和样式表，而通用 artifact 沙箱刻意禁止外部资源。因此只有可见卡片，仍无法预览真实会话导出。

另外还缺少命令结果元数据的持久化，仅在主视图挂载注册逻辑，且注册失败后原先只能在切换会话后重新尝试；当前实现也允许重连后再次尝试。

## 设计

### 导出与传输

现有导出命令仍写入完全相同的 UTF-8 文件。ACP 模式额外返回标题、格式种类、规范化的 workspace 相对路径、MIME 类型和字节数。Markdown、JSON、JSONL 属于明确请求的导出，不使用面向工具自动产物的较窄扩展名白名单。

非交互命令分发器转发描述。ACP 消息发送器将其放入 `_meta.sessionArtifacts`，并标注 `source: slash_command`。使用独立字段，是因为 bridge 将 `_meta.artifacts` 保留给终态工具更新的产物摄入。不伪造工具调用，不扩大现有摄入或发布信任规则。

ACP 结果记录器将 `sessionArtifacts` 存入已有命令输出历史项。共享回放投影器恢复相同元数据，使客户端在历史重载、包括 daemon 重启后，仍可将已保存产物关联到原命令。其他命令记录保持原有回放行为。只需要普通消息结果路径：`/export` 不返回流式命令消息。

### 注册与可见输出

共享解析器仅接受来自斜杠命令、种类为 `file` 或 `html` 的 workspace 文件描述。拒绝畸形描述、绝对路径、两种斜杠形式的父目录跳转和其他定位方式。保留 POSIX 目录名中的字面反斜杠。类似盘符的路径前缀（例如 POSIX 下名为 `c:` 的目录）仍由跨平台描述符解析器保守拒绝。路径校验、workspace 所有权、配额和持久化仍由 daemon artifact API 最终决定。

注册通过现有会话 artifact hook 执行，也覆盖分栏视图。等待会话目录加载和历史追赶完成，跳过已注册路径，并将异步结果绑定到捕获的会话 owner。另一个浏览器打开会话时，不会因此改写已有产物的客户端所有权。其他客户端并发注册可能返回 `403 session_artifact_forbidden`。此时刷新当前 owner 的目录，只有确认目录包含导出的 workspace 路径才视为成功；其他失败保留多语言错误 toast。重叠的成功刷新请求可以确认注册结果，但不会覆盖更新请求的目录缓存。StrictMode 重放 effect 不会重复提交同一路径。失败路径在当前 owner、会话和连接内仍标记为已尝试，后续消息更新不会反复提交或重复弹错；重连或重新挂载后可再次尝试。不增加轮询或后台重试服务。

会话展示适配器在 assistant 消息上保留上报的产物引用。带有有效导出描述符的输出作为普通文本处理，不进入 insight JSON 分段；导出目录名类似 insight 元数据时也不会丢失引用。`/insight` 等其他命令保留原有进度和报告展示。回合输出选择器按 workspace 路径匹配真实产物目录，将已有 `TurnOutputs` 卡片挂到斜杠命令所属回合。单独的建议性描述不会生成可点击卡片，目录中必须有实际 artifact。预览、下载、workspace 选择以及沙箱 HTML 渲染继续复用共享产物组件。

### 完整预览

小文件继续使用 daemon 文本读取器及其编码检测，明确请求 256 KiB 窗口。如果结果被截断，则复用已有字节下载读取器 `readWorkspaceFileAsBlob`，再按 daemon 报告的编码解码完整字节。

这样可保留超长行、Unicode、BOM 处理和换行边界，同时复用下载读取器的 100 MiB 上限、取消检查、workspace owner 守卫以及文件大小/mtime 一致性检查。超限或读取中变化的文件显示错误，不将不完整 HTML 当作完整预览；读取失败后不再显示加载占位。下载仍返回原始字节。不拼接文本游标页面。

预览和下载共用串行的 256 KiB 字节窗口，与现有接口上限一致（客户端此前请求 100 KiB）。不改变服务端限制，也不增加并发。

### HTML 会话导出的兼容预览

所有 HTML 预览（包括聊天导出）均在不透明来源的沙箱 iframe 内加载原文档，不在宿主重建会话。可信外层 frame 继续阻止内层导航，两层都不启用 `allow-same-origin`。

对于带有 `script#transcript-document[type="application/json"]` 的文档，可信 Web Shell 加载器仅读取指定 renderer/stylesheet 元素。URL 必须精确等于 `https://unpkg.com/@qwen-code/qwen-code@<当前 Web Shell 版本>/export-transcript-document.js` 或 `.css`，不能携带 query 或 fragment，且必须带有 SHA-384 integrity 元数据。版本来自可信构建配置，不取自文档，因此任意版本路径也不能携带文档数据发送给 CDN。其他版本的导出不自动排版；原文件和下载保持不变，大文件仍默认显示源码。

父页面使用原 SRI 值请求这两个资源，省略凭据、不发送 referrer，并拒绝重定向。只有浏览器完整性校验成功的字节才会作为 data URL 嵌入预览。iframe 不获得 CDN 白名单，只允许内联/data 脚本和样式，网络请求仍被阻止；第二个外部元素或动态创建的请求不会获得出网权限。加载失败显示错误，不会一直停在加载状态。原始导出和下载字节不被改写。

生产 Web Shell 响应头允许 data 脚本/样式，以及父页面向 Qwen 包命名空间发起 fetch。子文档自身的 `default-src 'none'` 继续收紧限制，不会因此获得可用的网络权限。Vite 保留原有 CSP，开发环境的聊天导出 HTML 渲染问题延后处理，本版本不声明支持该场景。嵌入宿主需提供兼容策略。响应头修改仅影响 Web Shell 服务，不改变交互式 CLI 导出逻辑。

父页面新增权限影响整个 Web Shell，而不仅是这个加载器，需要 maintainer 明确接受；子帧沙箱不会消除父页面策略的取舍。当前实现复用原导出资源 URL 和 SRI；同源资源是另一种可选方案，并未因库构建而被排除。虽然包内 renderer 文件位于 Web Shell 目录旁边，当前静态中间件并未暴露它们。同源方案需要为 daemon 和嵌入宿主明确资源服务契约，并仍需考虑导出的完整性值及 renderer 身份；包版本相同不保证字节相同。内联已校验资源可去掉新增的 data 脚本/样式权限，但只要资源仍来自 CDN，就不能去掉 CDN fetch 权限。

源码构建可能使用已发布的包版本，却引用未发布的 renderer 哈希。这样的导出无论在 iframe 内还是下载后直接打开，都会因 SRI 不匹配而失败：仅包版本号相同不代表本地构建字节相同。现有导出构建支持通过 `QWEN_EXPORT_RENDERER_IDENTITY`、`QWEN_EXPORT_RENDERER_INTEGRITY` 和 `QWEN_EXPORT_RENDERER_CSS_INTEGRITY` 显式委托到已发布资源。修改 renderer 发布或构建选择机制不属于本次 artifact 接入范围。不新增构建命令、自动委托、SRI 绕过或旧文件改写，下载仍返回原始字节。磁盘产物变化后，运行中的 daemon/会话进程仍可能保留已导入的旧模板，仅刷新前端不会重载后端模板。

Markdown 在宿主页面中直接使用现有 Markdown 组件及样式，保留图片处理、脚注预览卡片和交互控件。不再序列化 React 标记，也不使用 Markdown iframe。HTML 继续使用沙箱 iframe。大 Markdown 文件在挂载 Markdown 组件前默认展示源码；用户主动选择完整排版时仍在主线程渲染。

### 大文件渲染

分片读取不等于增量渲染：完整读取后，旧预览仍一次性解析并挂载整个文档。实际 1.9 MiB 会话导出挂载了 757 行消息、约 4 万个 DOM 节点；实际 4.5 MB Markdown 导致浏览器操作阻塞。

HTML 和 Markdown 使用统一的字节大小规则：超过 1 MiB（1,048,576 字节）默认显示完整只读源码，恰好等于上限仍默认排版预览。workspace 文件使用 daemon 报告的文件大小，或完整下载 blob 的大小；附件保留解码前的原始 blob 大小；没有文件元数据的纯内容预览使用 UTF-8 字节数。不再使用字符数或行数判断。

保护逻辑在 HTML 解析之前生效，包括 CSP 包装和 Markdown 转换。多语言提示栏最右侧的按钮允许切换完整排版或返回源码。普通 HTML 保持现有沙箱；聊天导出 HTML 在请求排版时使用原有 document renderer，不新增聊天虚拟滚动或修改会话滚动行为。源码预览继续复用现有 CodeMirror 编辑器，并限定视口。这项排版规则覆盖普通 artifact、附件和斜杠命令导出中的 HTML/Markdown。JSON、JSONL 和其他文本格式本来就使用同一个只读源码编辑器，没有另一个可关闭的排版视图。下载不变。

## 约束与风险

- 注册仍需已连接的 Web Shell 客户端。CLI 无论如何都会写出文件，其他 ACP 客户端可忽略建议性元数据。这是一项 Web Shell 集成，不新增 daemon 产物生产者。
- 位于绑定 workspace 外的文件不能表示为 workspace artifact。此时 CLI 导出行为不变，不上报描述。worktree/runtime 映射不得回退到主 workspace。
- 现有产物的保留、容量、删除和文件缺失行为仍由原机制决定。导出描述可被回放，因此重新打开历史时，未注册路径可能再次注册；本次不新增明确的持久删除语义。
- 完整字节回退适用于所有 workspace 文本预览，包括 JSON/JSONL 和普通源码文件。这将大文件行为从拒绝无窗口文本读取，改为自动完整加载至现有 100 MiB 下载上限。1 MiB 排版规则在加载之后生效，对 HTML/Markdown 也不是读取、解码或内存预算；增加源码/排版切换不能限制这些成本。后续若限制自动读取，必须在完整字节加载之前执行。不支持的编码和文件变化显示错误；字节下载仍独立于文本渲染。
- 1 MiB 阈值是产品规则，不是渲染耗时上限。较小的复杂文档和手动完整预览仍可能阻塞页面；iframe 沙箱是安全边界，不是 CPU 隔离。
- 大文件先读取文本前缀，再读取完整字节，会增加一次请求。这样可以复用现有编码检测，而不增加解码器或端点。

## 验证与验收

1. 在真实本地 daemon 上执行 `/export html`，生成一个文件和同一回合中的一张可见卡片。打开后渲染导出的会话，下载字节与 workspace 文件一致。
2. 对 Markdown、JSON、JSONL 重复验证，使用各格式已有的预览和下载行为。
3. 测试超过 256 KiB 的大导出，包括超长行、Unicode 和文档尾部内容。确认预览完整，下载与原文件一致。
4. 刷新并重载持久化历史：不重复注册，卡片仍属于原回合。
5. 验证子目录导出和 cwd 外路径拒绝。通过共享 owner 绑定路径验证次级 workspace 路由和分栏注册。
6. 验证普通交互式和非交互式 CLI 导出保持原结果和文件写入行为。
7. 运行包内回归测试、构建和类型检查。浏览器实际结果与截图应独立于模拟单测证据记录，不将未测行为宣称为已验证。
8. 使用指向已发布 renderer 资源的模板，通过真实 daemon 导出，验证 artifact iframe 和下载后未经修改直接打开都能通过真实 CDN 响应完成渲染。记录 renderer 配置，不将这一结果当作未发布源码构建已能公开访问的证据。
9. 验证 HTML 和 Markdown 恰好 1 MiB 时默认排版、超出时默认源码，包括构造的大聊天导出 HTML。验证源码首尾可达，多语言切换按钮位于最右侧，HTML 在沙箱 iframe 内排版，Markdown 使用现有宿主组件并保留同源图片和脚注行为，下载仍与原文件字节一致。

本地 E2E 报告和截图位于 `.qwen/e2e-tests/web-shell-export-artifact/`，1 MiB 默认源码和直接 Markdown 渲染方案替代此前 10 MiB Markdown iframe 检查；历史报告仅证明各自原始范围内的行为。已发布 renderer 验证使用显式构建期委托和真实 CDN 响应。该实验使用的开发构建辅助入口随后按用户要求撤回；结果证明资源配置匹配时预览和下载兼容，不代表源码构建问题会自动修复。旧的不匹配导出保持原样。本轮未实际运行分栏和次级 workspace 的浏览器流程。

后续修复验证见本地 `final-read-race/` 报告：实际 UI 配合模拟 daemon 验证 HTML/Markdown 超过 1 MiB 且文本响应截断时的完整分片读取、源码尾部、下载字节一致，以及分片失败后不再显示加载占位。双客户端注册使用实际 hook 与 store 集成测试验证，包括目录收敛和其他 403 仍报错；这不代表已验证真实浏览器分屏或真实 daemon 文件读取。

安全后续验证：仓库内测试覆盖精确资源选择和调度器元数据转发。本地 `export-artifact-csp-probe/fixed/` 浏览器记录使用模拟 CDN 响应及生产父页面 CSP，验证 SRI 失败、子页面断网策略、重复/动态外部脚本被阻止，以及实际预览成功/错误 UI。这些本地记录不能作为仓库内可访问证据；后续 PR 需附上可评审的验证材料。
