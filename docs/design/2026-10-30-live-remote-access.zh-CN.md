# 在设置中免重启开启远程访问

[English](2026-10-30-live-remote-access.md) | [简体中文](2026-10-30-live-remote-access.zh-CN.md)

## 状态与决策

已实现设计，2026-10-30。行为是：**远程访问默认关闭，在 UI 中开启，daemon 持续运行。** 正常流程不需要额外终端命令、重启、第二个 Qwen 实例或必填启动参数。

旧版运行实例与兼容网关明确不在范围内。本地运行验收使用隔离的 daemon、浏览器及受控模型服务，没有修改已有远端服务。

## 用户体验

正常启动普通 daemon，主入口默认保持本地监听。之后随时在该 daemon 的“设置 → 连接 → 允许远程连接”打开开关。开启成功后，卡片显示实际远程地址，以及默认遮罩、支持查看/复制/重置的 bearer token。另一台机器的“添加远程连接”只需填写这个地址和 token。

明确区分两个卡片：

- **允许远程连接**：控制提供当前设置页面的 daemon 是否接受远程访问。明确显示 daemon 所在主机，仅授权的本地操作者可操作。
- **添加远程连接**：让当前客户端连接其他 daemon。添加已保存连接不能改变目标服务器的开放策略。

关闭时显示“远程访问已关闭”，不显示可用凭据。开启/关闭/重置过程中显示处理中，避免重复操作。只有监听与鉴权准备完成才显示开启成功。失败时保留实际服务状态并展示原因。页面挂载和重连时读取 daemon 状态，浏览器存储不是状态来源。

关闭开关会撤销远程凭据并断开远程客户端，主入口、本地连接、工作区、会话和 daemon 拥有的任务继续运行。重新开启生成新 token。重置 token 同样断开使用旧 token 的客户端，操作前在页面中明确说明。token 默认遮罩，仅查看后显示，不放入普通 URL 或诊断。

这是运行时设置：daemon 重启后默认关闭，不隐式持久化对外开放。本次不携带此前的 `--remote` 启动参数补丁，UI 开启不需要它。保留显式旧有 `--hostname` 部署。已有主入口本身对外监听时，不能显示“远程访问已关闭”或假装本开关能控制它；应显示“由启动配置对外开放”，说明本开关管理的是独立入口。

## 架构与归属

复用现有 LocalControlService 的方式：在同一个进程内，为原应用创建新的 HTTP(S) 监听器并挂载已有升级处理器。本地和远程入口分发到同一个工作区注册表和会话所有者。不启动另一个 agent、不复制工作区、不迁移会话。

远程访问策略与 Local Control 的私有局域网选择、配对、防休眠策略分开，只复用合适的生命周期/鉴权基础能力。通过监听器身份区分入口，每个入口拥有自己的 Host、来源匹配器、token 代次及连接。不向无关监听器增加远程权限，不替换主入口操作者 token。

远程访问状态、开启/关闭/重置及地址枚举属于**进程全局**，即使从某个工作区设置页面打开也一样。工作区数据仍限定在选定 runtime，会话仍属于原实时会话。未知、已移除、不可信或歧义 runtime 不得退回主 runtime。

本地管理 HTTP 路由沿用已有操作者权限、Host 和请求来源检查。只有经过授权的本地主入口上下文才能开启、查看/重置 token 或改变配置。远程凭据不授权这些管理路由。不能将 CORS、调用者提供的 Host/转发头或浏览器存储当作授权。需要时与已有本地操作者凭据传递整合，保证用户不必额外执行终端命令；不能为了简化 UI 将秘密开放给未鉴权浏览器。

这不是针对已获准以 daemon 系统用户执行 shell 命令者的沙箱。嵌入式/managed 部署保留自身操作者策略，不支持管理的上下文应明确解释原因，不能额外授予权限。

## 地址与端口

优先在一个明确选择的非回环网卡上沿用主入口的数字端口。主入口为 `127.0.0.1:4173` 时，尝试在所选网卡上绑定 4173，不改变原套接字。以实际 bind 成功为准，通配监听和平台行为可能造成冲突。

只有一个合适网卡时可以自动选择；有多个候选时由 UI 询问开放哪个网卡。允许显式选择本机已有的企业/VPN IPv4 地址，包括 `11.*`，不误称其为私有地址，也不采用 Local Control 的私有网段限制。不能悄悄开放所有网卡。

绑定冲突或权限不足时，开关保持关闭，显示尝试的地址和原因。高级设置允许显式选择其他端口。不偷偷分配 4174/4175，不杀其他服务，不重绑主入口。入口端口变化仍连接原会话。公布实际绑定地址，不显示 `0.0.0.0` 让用户连接。IPv6 必须在客户端 CSP、URL 校验、Host 和升级路径完整支持后才提供。

开启监听不代表防火墙/NAT 后的可达性，不自动改防火墙、路由器、DNS 或代理。适用时沿用 TLS 配置，并解释 HTTPS 页面与 HTTP 目标之间的限制。UI 区分“已开启/监听中”和“客户端已验证”。

## 鉴权与浏览器行为

接受流量前生成独立高熵远程 token 并安装策略。所有受保护 HTTP、SSE 和 WebSocket 请求都需要该 token，即使本地主入口允许无 token。使用已有浏览器 WebSocket 凭据机制，不将 token 放进查询参数。普通状态响应隐藏 token；授权的查看/开启/重置响应禁止缓存。

默认允许 `http://localhost:*`、`http://127.0.0.1:*` 和远程入口自身的规范化来源。高级设置可运行中添加精确自定义来源。不允许任意来源或 `null`。HTTP 与全部升级处理器使用相同判定。合法来源的预检不需 bearer，但实际受保护操作需要。鉴权错误返回适当 CORS 头，使客户端能读取 401/403。

保留按 origin 隔离的客户端凭据和浏览器本地文件隔离。候选 token 鉴权成功后才保存，失败不清除有效旧连接。保留准确的 401、可读 403、混合内容及无法确定的网络/CORS/证书诊断。连接配置指引指向服务器设置开关，不再要求执行命令。

当前主机的侧栏徽标跟随已有 daemon 可用状态，显示已连接、离线或未授权。选中某台主机不能代表撤销远程访问后仍保持连接。

## 生命周期与连续性

串行执行 `disabled -> enabling -> enabled -> disabling -> disabled` 状态转换。重复开启必须幂等，不轮换 token。管理响应丢失后重新读取实际状态。开启监听采用事务式处理：先准备凭据和处理器，真正监听后才提交开启状态，失败只回滚本次新资源。

关闭时先停止准入和撤销 token，再清理入口。追踪并在有界时间内关闭该入口的 keep-alive、SSE 和已升级 WebSocket。不得使用 daemon 全局关闭流程或销毁共享会话/ACP 资源。HTTP `closeAllConnections()` 本身不会关闭升级后的 WebSocket。

重置 token 撤销旧代次及其活动远程连接，但保留任务。关闭后重新开启创建新代次。daemon 退出时销毁它的远程入口；重启默认关闭，不自动恢复 UI 的运行时授权。仅刷新 UI 不会关闭远程访问。

检查断线触发取消的语义。分离远程传输不能隐式取消 daemon 任务，也不能终止无关本地客户端。重连使用原会话 ID，在支持时使用已有事件游标。不自动重放 prompt/工具修改，也不创建替代会话。客户端拥有的临时媒体流可以结束，不承诺未缓冲数据回放。

## 实施与验收

1. 基于已有能力增加 daemon 拥有的远程访问生命周期和按监听器隔离的策略，保留 Local Control 行为。
2. 增加进程全局、限本地授权操作者的状态/开启/关闭/查看/重置和来源配置操作，安全展示 token。
3. 完成设置开关、地址/token 卡片、处理中/错误状态、可选网卡/端口/来源控制，与“添加远程连接”明确区分。
4. 不携带旧的 `--remote` 补丁；两条 CLI 解析路径保持普通回环默认值以及内部/嵌入式启动契约。
5. 获得授权后做一次集中隔离验证，不使用正在运行的远端 4173 当测试夹具。

验收要求：

- 普通启动没有新增远程监听器，设置开关默认关闭。
- 先启动任务，再通过 UI 开启，从另一台机器只填地址/token 连接。无需终端命令、重启或第二个 runtime；原 PID、工作区、会话 ID 和任务进度连续。
- 任意端口本地页面的 HTTP、SSE 和每项公布的 WebSocket 功能可用；直接打开远端 Web Shell 遵循同一鉴权/来源策略。
- 关闭/重置撤销已有远程连接和旧凭据，本地客户端与 daemon 任务继续运行。重新开启和重连回到原会话，不重放修改。
- bind 失败、重复点击、多页面并发、管理响应丢失、daemon drain 和浏览器刷新都显示实际提交状态，不泄漏资源或误报成功。
- 错误 token、无关来源、伪造 Host/转发头和远程管理请求在 HTTP/升级上都被拒绝；普通日志、URL 和状态响应不出现 token。
- 多网卡选择和端口冲突明确展示。已有外部配置的主监听器不能被本开关错误显示为关闭。
- Local Control、显式绑定、managed/Desktop/IDE 部署和程序调用保留各自声明的行为。

本地验收覆盖设置页面、跨源地址/token 连接、HTTP/SSE 与 WebSocket 在关闭入口和重置 token 时的四种任务连续性场景、token/Host/来源校验、端口冲突、重启默认关闭，以及显式外部主入口的兼容性。另用两个独立配置的 daemon 验证：从一个 daemon 的页面提交的消息只由选中的远端 daemon 处理和持久化，进程 PID 不变，重连恢复同一会话。针对性测试、受影响包的类型检查和 Web Shell 页面构建已通过。验收使用本机已分配网卡地址和受控模型服务，不代表已验证其他机器经防火墙或 NAT 的可达性。未部署远端。
