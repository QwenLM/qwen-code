# 会话 cd 时保留受限 MCP 审批

[English](serve-session-cd-mcp-approval-scope.md) | [简体中文](serve-session-cd-mcp-approval-scope.zh-CN.md)

## 状态

提案。下面的契约是 issue #16058 中提出的四个选项之一，在维护者选定方向前尚未定稿。

## 问题与范围

`POST /session/:id/cd` 会迁移会话的工作目录。受限 MCP server（来自签入的 workspace `.qwen/settings.json` 或项目 `.mcp.json`）的审批按工作目录存储，因此即使会话读取的仍是同一个配置文件，迁移也会改变审批查找所用的 key。该 server 随即报告 `pending`，会话将其显示为 `disconnected`；daemon 重启后该 server 完全不会被连接。

这是 cd 的既有行为：在早于 #15323 的版本中，主 workspace 即可复现。#15323 只是让动态注册 workspace 所拥有的会话也能执行 cd，从而走到这条既有路径。

本次变更的范围：当配置来源未改变时，把已有审批决定带到新目录。不重新设计审批存储，不新增审批端点，也不固定会话的配置根。

## 契约

会话从一个目录迁移到另一个目录时，受限 server 的审批决定只在同时满足下列条件时才带到新目录：

- 新目录把该 server 的配置文件解析到与旧目录相同的真实路径；
- 已存决定为 `approved` 或 `rejected`，且其 hash 仍与会话将要使用的 server 配置匹配。

其余情况一律维持受限状态：不同的配置文件、决定之后被修改过的配置、从未作出决定的 server，以及只在新目录出现的 server。被拒绝的决定带过去后仍然是拒绝。

## 设计决策与理由

- **为什么以配置来源而不是目录为准。** 目录只是发现配置的输入，不是用户审批的对象。审批记录已经用 hash 绑定了确切的配置内容；再补上来源身份，配对才完整，同时不削弱 hash 绑定。
- **为什么不只按 hash 携带。** 相同内容位于不同文件仍是不同的信任决策位置。要求真实路径相同，可以保持既有项目边界有意义，也让变更容易解释。
- **为什么不固定配置根。** #15323 明确让指令、skill 与配置发现继续跟随会话目录。固定配置根是更大的行为变更，不在本提案范围内。
- **为什么不新增 API。** workspace 审批路由没有 session 或 cwd 参数，CLI 也无法触达运行中的 daemon，显式重新审批需要新增接口。携带已有决定则不需要。

## 约束

- 仅影响迁移时持有活动 Config 的会话；之后重新 load 会按目录重建 Config，并读取同一批已存记录。
- 决定通过既有审批文件持久化，不需要改变文件格式。
- 持久化失败只作为迁移 warning 报告，不会让 cd 本身失败；此时决定在本次进程内仍然生效，warning 是「重启后不再生效」的唯一信号。
- **携带出的记录会活过本次 cd。** 它按新目录的 key 存储，之后在该目录启动的会话会继承该决定；读取端只校验配置 hash、不校验来源文件，因此若该目录的配置之后指向另一份内容相同的文件，继承的决定仍然生效。这是既有 hash 绑定本就有的信任边界（按来源读取是 #16058 的选项 2），但携带让它可以从一个用户从未审批过的目录到达。

## 验证

- 单元覆盖：通过符号链接的配置目录得到同一来源（approved 与 rejected）、不同来源文件、文件缺失、配置 hash 已变、从未决定的 server、项目级 `.mcp.json`，以及非受限 scope。
- 按 issue #16058 的端到端复现：先审批受限 server，cd 进入 `.qwen` 符号链接到 workspace 配置的子目录，确认该 server 仍为 approved 且保持连接，并在 workspace reload 与 `forceReconnectAll` 之后仍然成立。

## 开放问题

- 维护者是否更希望让所有消费者都按配置来源绑定审批，而不是在 cd 时携带（#16058 的选项 2）。
- 是否需要在本次修复之外单独提供 session/cwd 审批端点（#16058 的选项 3）。
- 已知同类问题不在本次范围内：workspace 审批端点会清掉所有 live config 的 gate（对 workspace 维度的决定是合理的，但它同时忽略持久化结果仍返回成功），以及 workspace MCP 状态读取在 safe/bare 模式下仍会读审批文件。两者都早于本次改动，收窄它们属于独立跟进项，不并入 cd 携带逻辑。
