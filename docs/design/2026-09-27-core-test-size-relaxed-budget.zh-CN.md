## 结论与范围

本轮得到一个 **45,167 行（9.21%）** 的具体删减候选：core 测试从
490,301 降到 445,134 行，字节从 17,763,494 降到 16,149,972。
辅助代码、fixture 和 snapshot 全部沿用原统计口径。184 个测试文件实际
删除，剩余 628 个文件全部执行，没有新增失败，保留原有 prune 失败。

实际损失 1,024 个原有已覆盖行，占固定基线可检测行的 **0.3982 个百分点**。
历史图中全部 95 个已检出故障仍有已记录的检出者；3,267 个可匹配的
Killed mutant 中，3 个失去全部已记录的检出者。后两项是训练图预测，
本轮没有重新运行 C1 或 C2，不能当作实际检出率保全。

这支持把下一阶段目标提高到约 4.5 万行。10 万和 15 万行档显示了明显
增大的覆盖成本。工作分支仅增加报告和证据，删除发生在独立 VM checkout；
候选 patch 可供逐模块评估。

## 为什么改变方法

上一轮只在三个小范围中做保全已观察检出的改写，减少 1,060 行。
原设计本来允许 mutation 分数下降 1 个百分点，后续执行进一步收紧了
原有 kill 的保全要求。本轮允许主动舍弃低优先级测试，直接测量取舍。

先建立逐测试文件的覆盖归属，再按“每删除一行测试会损失多少边际覆盖”
选择整文件删除。375 个涉及权限、秘密、破坏操作或持久写入隔离的文件
被筛入硬保护清单。普通协议、展示、兼容和生命周期文件允许探索。
这份清单是语义预筛；采纳前仍须审查具体删减。

## 分支与验证限制

45k 档的参考分支覆盖率从 88.5646% 变为 87.8255%。分母从 80,146
变为 79,100，所以这不是固定身份集合上的分支损失率。精确位置匹配
发现 517 个已覆盖分支槽位丢失，另有 1,018 处分支形状变化，以及
16 组重复位置的覆盖状态变化，均单列保存。

原生 V8 可能给多个 branch ID 相同的位置，不能按行号、数量或重新编号
强行匹配。比较器先修正位置匹配，再单列重复位置歧义；旧错误、失败的
首次比较和修正前工具均保留。首次健康汇总未识别已授权 capture 命令，
修正后重新读取同一组原始报告，未重跑套件。

基线旧 runner 未把 ignored capture config/provider 放进执行期快照。
开始运行前记录的工具哈希与当前文件一致，但报告保留这一快照局限。
后续 runner 已补齐工具哈希。所有套件测量中的受测源码均未变化。

## 建议的放宽方式与下一步

- C4：允许删除用例、减少断言和降低独立失败标签数量，记录诊断成本。
- C3：先用固定分母的行覆盖损失 **0.5 个百分点**筛选；分支变化和局部
  覆盖空洞逐模块审查，不用全包平均数替代。
- C2：实际重新测量时，允许固定样本中原有 Killed 的损失不超过 **1%**；
  新增 kill 不抵扣损失，Timeout 单列。这与 mutation 分数下降 1 个
  百分点是不同分母，本轮使用前者作训练约束。
- C1 与硬边界：保留真实历史故障检出和安全、权限、数据完整性检查。

以 45k 候选作为下一阶段对象，先审查局部覆盖缺口，将必要边界恢复为
小组测试，再冻结独立于选择图的缺陷和分层 mutation 样本。对发现的
高风险模块扩大测量。完成独立能力验证后逐批采纳，不再要求所有测试名、
断言数和每条普通覆盖都不变。
