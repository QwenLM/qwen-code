# Web Shell 更新

[English](web-shell-update.md) | [简体中文](web-shell-update.zh-CN.md)

## 问题与范围

Web Shell 显示运行版本，但不能准备或应用更新。后台检查并下载，安装包就绪后，
才在左下角版本号旁显示小型**更新**按钮。点击后应用更新、重启连接的服务，
恢复连接后返回点击时所在的浏览器地址。

更新目标是连接的 daemon 安装，远程连接也是如此，不更新嵌入式宿主。
重启通过 daemon 现有的优雅关闭流程结束运行中的工作，不恢复被中断的模型轮次。

## 设计

- 需要身份认证、属于进程全局的 `GET /daemon/update` 只检查版本，不下载或安装。
  缓存检查结果 15 分钟、错误结果 1 分钟，`?refresh=true` 强制检查；并发检查复用同一请求。
- `POST /daemon/update/prepare` 下载服务端选定的版本并立即返回。
  复用独立安装包的下载与校验，或暂存受管理的 npm 安装，不改变当前安装。
  等待用户点击期间不持有安装锁。激活时在安装锁内重新检查，保留已安装的相同或更高版本。
- `POST /daemon/update/restart` 先响应，再应用准备好的安装包。
  只有这个显式操作会激活更新，随后关闭服务并通过 `process.execve` 替换进程。
  保留 PID、启动目录、主监听端口、认证令牌和 CLI 参数；清除受管理版本固定信息
  和打开浏览器参数，让启动器选择新版本。
  关闭服务前，要求独立安装启动器使用官方 shell 首行，并以重启环境执行 `--version`，
  限时 10 秒且要求返回合法 semver。检查失败时当前 daemon 继续提供服务。
  此检查覆盖实际解释器和运行时链；若检查后文件变化、进程替换失败或 serve 启动失败，
  仍不能保证服务恢复。
- 准备和重启仅支持使用 daemon 令牌认证或可信无令牌回环模式的主监听器、
  有重启回调的真实 CLI 入口、提供 `process.execve`
  的 POSIX 平台、受支持的独立安装或受管理的全局 npm 安装，且操作者设置允许
  `general.enableAutoUpdate`。此进程级决策忽略工作区设置。Windows、嵌入式服务、
  开发安装、包管理器安装和不支持的 Node 运行时不提供更新按钮。
- 状态包括 `available`、`up-to-date`、`installing`（仅后台准备）、`ready`、
  `restarting`、`unavailable`、`error`，以及当前/最新版本、`canInstall` 和可选的
  指引及消息。并发变更复用同一操作，刷新浏览器保留已准备的安装包。
  取消、激活、失败及普通 daemon 关闭时清理暂存文件。
- 发布 `daemon_update` 能力，SDK 提供仅使用 REST 的检查、准备、重启方法。
  保持现有身份认证、CORS 和严格变更授权规则。客户端不能指定安装命令、路径或版本。
- Web Shell 挂载及定期检查，支持时自动请求准备，准备/重启期间每 2 秒轮询。
  展开侧栏把版本号和按钮放在底部操作栏上方的独立一行，窄侧栏也如此。
  折叠时仅在就绪后显示带无障碍名称的图标。使用共享按钮、语义颜色和中英文文案。
- 检查和下载保持安静；显式重启失败使用现有错误通知。
  重启期间禁用按钮并容忍短暂断线；点击时记录完整 URL，运行版本变化后在当前历史记录中
  恢复该地址并重新加载页面，包括 URL 含有未变化的锚点时。重启期间会话请求可能返回 404，使界面跳到首页，
  但不能因此改变更新后的返回目标。
  60 秒后首个完成的轮询仍未确认恢复，则停止等待并显示错误。
  组件卸载停止浏览器轮询，不取消服务端操作。
- 旧服务及桌面 shell 隐藏此入口。自定义底部项目可以省略 `update`，
  同时禁用浏览器发起的准备请求。

## 归属与影响范围

路由、版本检查、安装器、暂存安装包和重启属于 **daemon 进程**，不属于选中的
工作区或会话所有者。安装检测使用启动目录及操作者设置。只有认证信息在重启后仍有效的
主连接（或可信无令牌回环连接）提供更新入口。重启仍会使其他设备的临时配对失效，
这些设备需要重新配对。消费者是 SDK 和 Web Shell，均不能将操作重定向到工作区运行时。

变更涉及 CLI serve 路由、生命周期和入口、安装器暂存辅助函数，SDK daemon 类型与
客户端导出，Web Shell 侧栏与翻译，以及协议文档。现有交互式 CLI 更新行为保持一致。

## 验证与验收

在隔离运行时用全局 `qwen serve` 确认缺少 API/UI 的基线。测试不更新用户安装。
使用本地归档和 npm 测试数据及模拟激活边界，验证准备不改变当前安装、缓存安装包可激活、
清理及现有直接更新行为正常。验证授权、主监听器归属、设置/平台/嵌入限制、并发操作、
失败恢复、先响应再重启的顺序及重启参数和环境保留。
使用独立子进程和真实 `execve` 验证不可用启动器，确认启动检查在关闭可用监听器前拒绝。
覆盖重启失败过程中的清理，确保刷新检查后仍可重新准备更新。

验证最新/下载中/就绪/重启中/错误状态、显式激活、断线恢复、超时、折叠按钮、窄布局和
双语文案。完成构建、类型检查、打包、相关包测试，验证打包后的 daemon 及浏览器流程。
将环境限制与通过的验证分别记录。
浏览器回归需要触发重启期间的会话 404，观察界面自身导航，再验证恢复后回到原任务地址。

验收：准备完成前不显示更新入口；版本号和更新按钮相邻且不与底部操作重叠；
点击一次仅应用和重启一次，恢复后返回同一任务。不支持或禁用更新的安装保持可用，
不会显示无法执行的重启按钮。

## 待决问题

无。Windows 文件替换及任意嵌入式宿主重启不在本次范围。
