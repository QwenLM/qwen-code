# Managed workspace Skill defaults

[English](2026-11-18-managed-skill-defaults.md) | [简体中文](2026-11-18-managed-skill-defaults.zh-CN.md)

An embedding host can implement `ManagedSkillCatalogSource` on its existing extension source. One catalog call returns authorized exact Skill references, compilation targets, display metadata and a default-selection flag for the trusted tenant, actor and Workspace. Catalog order is deterministic across providers. Discovery does not publish packages.

When a workspace Session has no caller skills and omits extension pins, creation imports the defaults through the ordinary authorized source-import path and admits their immutable pins together. An explicit pin list, including an empty list, owns the selection. Omitted and empty static skills keep their existing idempotency semantics. Lookup of an admitted request precedes provider I/O. Creating a Session can cache an exact package revision for other authorized callers. Explicit publications alone advance the Workspace catalog. A failed default prevents Session admission. A host without a catalog provider keeps its existing creation behavior.

The compiler supplies standalone Skill metadata from the same archive used for execution. MAS stores that metadata beside the package revision and projects the qualified name and description for the Session's initial pins. Admission validates the compiled metadata against Hosted UTF-8 limits and checks qualified names after combining them with the pinned AgentDefinition. Preparation requires a nonblank body of at most 512 KiB after expanding extension paths and records each standalone entry’s serialized UTF-8 size. Creation checks the combined catalog against the 256-entry and 2 MiB limits before recording the Session. The server adds its optional loop Skill only when it fits alongside all selected Skills. The initial selection remains visible while the first installation is preparing. Once a configuration bundle is active, its installed contributions determine the visible catalog. User-hidden skills stay hidden. The model loads instructions and assets from the pinned package via the existing initial installation flow. Source revocation affects new admissions and leaves existing snapshots and replays usable.

Acceptance covers scoped discovery, explicit selection, new and replayed Sessions across revision changes and revocation, visibility before and after bootstrap, and unchanged behavior without a provider. The managed V1 development schema records standalone Skill metadata and whether a package revision was explicitly published to the Workspace catalog. Existing development catalogs must be recreated according to the module's baseline policy.
