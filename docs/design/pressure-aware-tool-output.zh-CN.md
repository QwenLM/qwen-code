# 随上下文压力调整工具输出与结果大小统计

[English](pressure-aware-tool-output.md) | [简体中文](pressure-aware-tool-output.zh-CN.md)

## 问题和当前行为

#2566 和 #11536 针对同一种可控制的上下文输入。生产者、落盘门限、单工具/组合裁剪、聚合收尾和发送保护都可能缩短结果，而执行统计仅保留较晚的预览长度。MCP 的 500k 上限独立于全局默认值，网页抽取也有自己的输入上限。token 数属于具体聊天和 provider 路由，因此共享 Config getter 无法安全计算动态预算。

## 变更

按 #2566 的提议，将普通默认值改为 80,000 字符 / 2,000 行。这增加早期会话的数据可用量，是产品默认行为变更，并不声称原门限总会造成故障。MCP 采用全局配置，移除独立的 500k 上限。shell、grep、agent 和自行分页的工具保留现有声明上限。200k 聚合预算仍独立生效。

串行化的聊天发送边界仅使用本聊天、当前准确路由、未改变历史前缀对应的成功响应 usage。输入剩余空间等于现有强制压缩门限减去前次 prompt/output、新增非工具输入的保守估计以及工具封装/媒体开销。字符/行公式还使用现有新增内容安全系数缩放剩余空间，因此在强制准入或压缩接管前即可收紧预算。默认字符上限为 min(80k, 正剩余 token 数乘四)；默认行上限为 max(500, floor(2000 乘 min(1, 剩余 token 数 / 20000)))。采用绝对剩余空间，避免仅因占用比例高而惩罚大窗口。显式字符、行配置分别覆盖相应默认值，包括禁用值。窗口或计数未知、恢复/估计计数、历史改变、其他路由、失败或中断响应均使用静态预算。动态预算补充压缩机制，不保证精确 token 准入，也不改变压缩所有权。

内部来源信息用可枚举 Symbol 附在顶层响应 Part 上，穿过实时浅拷贝、收尾及媒体转换，不进入 JSON、hook 响应或模型载荷。仅保存数字大小、调用关联和预算来源，不保存正文、参数、路径或哈希。自行缩短结果的生产者在缩短前测量；普通生产者在执行结束时测量。深拷贝/恢复结果不能用预览反推原始大小，明确标为未知。PostToolBatch 替换结果按已有 scheduler 调用身份继承来源信息。

执行事件报告原始和处理后的字符数/token 估计。每次调用另有注入事件，在实际 content generator 调用前测量完成聚合/发送预算和模态处理的请求。每聊天 WeakSet 防止重试和后续历史重放重复计数。未提交给 generator 的调用没有注入事件。字符数测量文本结果正文；token 估计复用压缩的 Part estimator，包括封装和媒体估计。它们是内部已提交请求的估计，不是 provider 计费 tokenizer 或网络送达确认。

每个缩短层报告数字输入/输出大小、预算/来源及层。落盘操作还启用现有 persisted-result 事件，logger 排除本地文件路径。RUM 同步大小字段；字符/token 直方图区分原始/注入阶段，按工具名、类型、截断状态聚合。调用 ID 仅用于日志，公共 session 维度继续遵守现有基数控制的显式开关。统计失败不影响工具或模型请求。

## 恢复与生产者策略

完整输出 stub 保留现有 sentinel 和完整 SHA-256 标签，保证循环检测兼容。两条落盘路径都包含总字符数/行数以及明确的 read_file offset/limit 提示。大小有限的有效 JSON 使用 JSON.parse 生成小型结构/键/数组行数/样例预览；超大或非 JSON 内容保留原方向预览。这只是可恢复样例，不替代完整结构化结果，也不推断 schema。限制解析大小以避免超大结果的额外分配。

MCP 和 shell 在缩小模型输出前落盘。普通及聚合裁剪仅在尚无落盘决策时保存，复用已有文件，I/O 失败仍保留硬上限。web_fetch 的 100k 抽取上限位于摘要旁路查询之前，不是结果预算；web_search 按分区保留引用。这些具有语义的生产者缩减仍保持权威，并明确记录，避免统一字符串切片破坏它们。可测量时单独携带缩减前大小；raw 表示结果预算缩减前的语义生产者输出，不是网络字节或旁路查询完整记录。

## 影响边界与兼容性

涉及 Config 默认值/显式标记、core scheduler 转换和执行后/hook 后完成、共享裁剪/聚合、shell/MCP/web 生产者、LlmChat 请求/usage 所有权，以及统计类型、OTLP/RUM logger 和直方图。交互、headless、ACP、agent、speculation 汇入共享 converter/finalizer 和聊天发送边界。code-mode 嵌套调用保留执行测量；仅提交父调用输出时，不声称嵌套调用单独注入模型。

不添加公共配置、持久化记录格式、统计正文采集、传输 schema、存储生命周期、精确 tokenizer 或依赖。显式门限继续生效。新记录的结果可能在早期更大、临近上下文耗尽时更小。

## 验收

集中检查默认/显式/禁用设置、绝对剩余空间、独立聊天/路由、陈旧/估计/恢复 usage 回退、string 和 Part[] 大小、生产者缩减前采集、hook、并行聚合、结构化预览、落盘失败、重试及取消。重新构建相关包并 typecheck，使用控制匿名 provider 的原生 CLI 捕获下一次请求、本地统计及真实 tmux capture。公开报告标明测试源码、模拟 provider 边界及未验证的生产统计后端。合并前 issue 保持开放，不宣称已发布。

## 决策与限制

更大的默认值遵循用户授权的增强范围，尽管此前机器人在缺少失败 transcript 时建议保留 25k。评审可以明确评估这项变更。仅提供已裁剪预览且没有原始大小的生产者，以及恢复结果，raw 大小未知，绝不静默反推。网页抽取语义和合法字面结果保持完整。发送统计在 generator 边界计一次；网络发送失败与 provider 成功响应仍是不同事实。
