# 随上下文压力调整工具输出

[English](pressure-aware-tool-output.md) | [简体中文](pressure-aware-tool-output.zh-CN.md)

## 问题

#2566：长会话中上下文逐渐填满时，工具结果仍使用同一个静态预算，几次大结果就可能比必要更快地把会话推过压缩触发线。token 数归属于具体聊天及其 provider 路由，共享的 Config getter 无法选出动态预算，这个决定必须在聊天发送请求的地方做出。

## 变更

在聊天发送边界，聊天可以只依据自己上一次成功的用量报告，缩小即将发送的请求中的工具结果。只有当该报告来自同一 provider 路由、之后计数和历史都未被替换、并且它覆盖的历史仍是当前历史的原样前缀时，才能作为依据。计数是恢复或估算得来的、历史被替换、路由不同、属于另一个聊天，或报告之后又已经发出过请求，都视为没有依据，静态预算照常生效。显式设置的 `truncateToolOutputThreshold` 始终优先。

余量以自动压缩触发线而不是硬上限为基准：剩余 token =（auto − 报告中的 prompt+output token − 保守估算的、该预算无法缩减的新增输入）/ 现有的新增内容安全系数。在默认的 1M 窗口上，auto（850k）与 hard（977k）之间相差约 127k token，以硬上限为基准时，只有在压缩已经触发之后才会缩小结果。字符预算为剩余 token × 4 后向下取整，并且只在低于该批的静态容量（单工具门限 × 该预算可缩减的结果数）时才生效。该预算优先于预览长度：没有 4,000 字符下限，正余量不足一个字符时预览文本为空。达到或超过 auto 触发线时已没有余量可分，由压缩接管，因此不做任何缩小。

该预算由请求中的所有工具结果共享，并与现有的 200k 聚合发送保护取较紧的那个。发送边界会先用压缩准入的实际估算值检查候选预览；如果仍达到 auto，而仅按聚合预算处理的候选低于 hard，则选择聚合预算，避免在压缩仍会发生时丢弃文本。小窗口中聚合候选达到 hard 时保留压力裁剪。两个预览均从原始结果生成，只有最终选定的预算执行落盘和替换，因此结果不会被裁剪两次，也不为未选中的预览落盘。聚合预算配置为 `<= 0` 时保留其非有限的「已禁用」哨兵值，并关掉整段处理——与该设置在其他所有消费者上的行为一致；动态预算为零时则清空纳入预算的工具文本。同一消息中的用户文本永远不会被缩短。缩短结果前，这一步复用现有 finalizer 的落盘路径，将完整的预算内文本保存到唯一的发送边界文件。额度允许时预览保留头尾，恢复路径也计入字符预算。很短的预览可能缩短或省略指针，但原始内容仍保留在会话的 tool-results 目录。沿用现有的文件大小、会话磁盘预算及写入失败限制，落盘尽力而为。用户文本和豁免输出既不裁剪，也不为此新落盘。分配前先将受保护的计划模式生命周期文本计入余量。缩短 read_file 结果仅解除对应缓存的原文引用快路径，不撤销先读权限；缩短 shell 输出不会清空文件读取记录。

## 范围与限制

静态默认值保持 25,000 字符 / 1,000 行，本改动不上调它们。只有字符预算会动态调整，行数上限不变。由于调整区间起点贴近 auto 触发线，预算只在自动压缩前最后几千 token 左右起作用：在此之前它大于该批的静态容量，在此之后由压缩接管。上限覆盖发送保护可缩减的文本槽，包括截断提示；响应结构、媒体、豁免输出和受保护的生命周期文本沿用已有处理方式。这是对压缩的补充而不是替代，也不保证精确的 token 准入。

结果大小统计（#11536）是另一项改动。

## 验收

聚焦测试覆盖：1M 窗口上接近 auto 触发线时缩小；八条并行结果低于真实压缩准入且预览可少于 4,000 字符；带媒体的预览；小窗口发送低于 auto；正余量不足一个字符时预览为空；手动禁用预算、用户文本及豁免输出保留；压力裁剪前保存完整输出；远离或越过 auto 时不变；显式、估算、恢复、外部路由和其他聊天的归属下保持静态输出；以及报告之后又发出过请求时不再复用该报告。

实际 CLI 请求、完成路径及交互界面另以本地受控 provider 和 tmux capture 验证；这些用量不是实际模型 benchmark 或计费节省证明。
