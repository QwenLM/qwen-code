# 网页搜索来源标题

[English](2026-09-11-web-search-source-titles.md) | [简体中文](2026-09-11-web-search-source-titles.zh-CN.md)

状态：已由添加本文档的 PR 实现。设计讨论：#11564。

## 问题与范围

内置 `web_search` 工具要求模型在回答末尾给出由 markdown 链接组成的 `Sources:` 段，示例写的是 `[title](url)`。但模型收到的工具结果只列出裸 URL，因为 DashScope 的 `web_search_call` 条目只含 `{type, url}`。模型要么编造标题，要么把原始链接贴进回答。

本设计为被引用的页面提供真实标题，涵盖标题从哪里来、如何与页面匹配、如何渲染进工具结果，以及如何告知模型。不修改搜索请求的时间预算，不增加其他供应商的搜索后端，也不提供逐条摘要。

## 现状

DashScope 后端（`packages/core/src/tools/web-search-dashscope.ts`）收集搜索代理的旁白、extractor 打开的页面和搜索返回的页面。工具（`packages/core/src/tools/web-search.ts`）先输出旁白，再输出"已打开页面"段和"候选"段，每行为 `- <url>`，最后附上引用策略和安全脚注。

#11490 中的第一版实现从侧模型写的清单中读取标题，然后围绕清单编辑旁白：剥离清单块、为证据段会省略的页面保留行、恢复标题行、剥离后答案为空时回退到提取正文。端到端可用，但评审意见从 16 条增长到 29 条，几乎都落在这套编辑机制上，因此该功能被拆到 #11564。

## 目标

- 搜索代理命名过的页面在工具结果中列为 `[title](url)`，其余页面保持裸 URL。
- 解析出错最多丢一个标题，绝不改变模型读到的证据。
- 标题只能挂到搜索返回过或代理打开过的页面上。
- 没有标题的结果与之前的输出逐字节相同。
- 链接文字能在 CLI 中正确渲染。

## 设计

### 标题来源

侧请求的指令要求搜索代理在回复开头写一行只含 `Sources:` 的内容，接着为它依据的每个页面写一行 `- <页面标题> — <url>`，只列出搜索结果中出现过或它打开过的 URL，然后空一行再给出答案。清单放在开头，是因为侧请求有固定的 60 秒预算，被截断的流会从已经到达的内容中抢救结果。

搜索响应自身携带的标题（`action.sources[].title`）也会读取，但目前尚未观察到。两者都有时侧模型的标题优先，因为代理读过页面，而搜索索引只是列出了它。

标题只从侧模型自己写的内容中读取——即它的旁白或流式文本。抢救出来的 extractor 正文从不用于读取标题，因为页面可以在其中伪造自己的引用。

结构化输出已考虑但不可用：开启 `web_search` 时，DashScope Responses API 会忽略 `text.format` 的 `json_schema` 和 `json_object`（2026-09-11 探测；HTTP 200、搜索照常执行、回复仍是普通 markdown）。在提示词中要求只输出 JSON，会使被预算截断的回复整体无法解析。

### 只读提取

`readSideModelTitles(narration, knownKeys)` 返回按页面身份索引的标题，从不修改旁白。旁白按原样交给模型，包括代理自己的清单。规则如下：

1. 跳过代码围栏（` ``` ` 或 `~~~`）内的行。
2. 清单从这样一行开始：去掉首尾空白后不超过 32 个字符，且匹配带可选标题符号、加粗符号和冒号的 `Sources:`。句中出现的 `Sources:` 不会开始清单。
3. 清单内跳过空行；能解析为条目的行延续清单；遇到第一条其他行即结束。旁白中的每个清单都会读取。
4. 条目为 `[title](url)`，或 URL 位于行尾的 `title <分隔符> url`（分隔符为 `—`、`–`、`-`、`:`、`|`）。项目符号（`-`、`*`、`+`、`•`、`‣`、`1.`、`1)`）可选；没有项目符号时，该行必须是裸 URL，或在 URL 前有分隔符。只有 URL 没有标题的条目会延续清单，但不贡献标题。URL 末尾不成对的 `)` 或 `]` 会被去掉。
5. URL 不在搜索返回页面或代理打开页面之中的条目会被忽略。
6. 标题会被清洗：折叠空白；去掉首尾分隔符、包裹的 `**`/`__` 和引号；只剩强调符号的标题视为空；最多 200 个字符。空标题不贡献任何内容。
7. 同一页面以第一个标题为准。
8. 超过 2,000 个字符的行永远不是条目，标题行匹配只作用于不超过 32 个字符的行，因此可能回溯的正则永远看不到对抗性长度的输入。代码围栏检查是线性的，会作用于每一行。

### 页面身份

`packages/core/src/tools/web-search-backend.ts` 中的 `sourceKey(url)` 是匹配标题、查找标题和页面去重时使用的唯一身份。scheme、主机大小写、末尾斜杠、路径中的百分号编码和 fragment 不区分页面；端口和查询串区分页面。无法解析的 URL 回退为去掉首尾空白并转小写后的文本。已打开页面排在前面；键与已打开页面相同的候选不再重复列出；渲染的是页面的第一种写法。

### 渲染

`renderSource` 仅在以下条件全部满足时列出 `- [text](url)`，否则列出 `- url`：

- 存在标题，且净化后非空、不等于 URL 本身。净化会把 `[` 和 `]` 替换为 `(` 和 `)`，并去掉反斜杠和反引号，因为 CLI 从不反转义链接文字，并在第一个 `]` 处结束链接文字。
- URL 为 `http(s)`、不含空白，且最多一层成对括号，与 CLI 的行内链接模式（`packages/cli/src/ui/utils/osc8.ts` 中的 `MD_LINK_CAPTURE`）一致。URL 从不重新编码。
- 标题没有指向其他目的地：不含 `scheme://`，且不是仅由一个与页面主机不同的主机名或 IPv4 地址构成（忽略开头的 `www.`，允许页面主机的上级域名）。

没有标题的页面不做域名回退。

### 告知模型的内容

引用策略要求使用页面显示的标题作为 markdown 链接文字，对没有标题的页面引用裸 URL，绝不编造标题或 URL。工具描述说明结果会在代理命名页面时列出带标题的来源页面，并说明旁白自带的 `Sources:` 清单不是权威的页面列表。

## 决策与理由

| 决策             | 选择                                                        | 理由                                                                                                                                   |
| ---------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 编辑旁白还是只读 | 只读                                                        | 针对编辑机制的所有意见随机制一起消失；解析错误退化为缺少标题，而不是证据被改动。代价是代理清单中命名的页面会同时出现在旁白和证据段中。 |
| 标题来源         | 侧模型清单，其次响应标题，否则无                            | 搜索条目不含标题；端点忽略结构化输出。                                                                                                 |
| URL 身份         | 所有地方统一使用 `sourceKey`                                | 第一版实现混用精确键和归一化键，导致标题错配以及页面重复或被合并。                                                                     |
| 渲染             | 按 CLI 渲染器净化；只拒绝指向其他目的地的标题；不做域名回退 | 见下方说明。                                                                                                                           |
| 清单位置         | 放在答案之前                                                | 被预算截断的回复仍保留已流出的标题。                                                                                                   |

有意没有复刻 CLI 的 `labelMayDeceive` 检查。该检查在 CLI 中故意宽松，因为误判只会在渲染回复时保留可见的 `(url)` 后缀。放到工具层，同样的误判会直接丢弃标题，而且它会拒绝 `Node.js Releases`（`node.js` 看起来像主机名）、`Qwen3.6-Plus: Towards Real World Agents`（看起来像 scheme）这类普通标题——约占真实运行中观察到的标题的一半。工具只拒绝上面两种伪装形态；模型回复在渲染时仍受 CLI 自身检查的保护。

## 约束与风险

- 侧请求的回复格式随指令变化。所有失败模式都退化为之前的输出：裸 URL，旁白完整。
- 代理命名的页面会在工具结果中出现两次，一次在旁白中，一次在证据段中。
- 侧请求的 60 秒预算未改动。实测侧请求耗时 13–107 秒，因此部分搜索仍会进入部分结果路径，此时只有已经流出的清单中的标题能保留。

## 验证

- `sourceKey` 的单元测试（scheme、大小写、斜杠、fragment、查询串、端口、编码括号、无法解码的路径、无法解析的输入），以及每条提取规则的单元测试，包括对抗性长度的行。
- 工具层测试：带标题渲染且旁白不变、丢弃未返回的 URL、响应标题及优先级、不从 extractor 正文取标题、跨层级与不同写法去重、链接文字净化、指向其他目的地的标题、带括号的 URL，以及截断时保留带标题的来源。
- 现有 execute 测试无改动通过，确认无标题输出保持一致。
- 使用 `qwen3.8-flash` 对 Token Plan 端点的真实运行：5 个探测查询中侧模型全部以 `Sources:` 开头回复。其中 4 个查询里清单列出的每个页面都挂上了标题；第 5 个一个都没挂上，由于当时没有保存旁白原文，原因未知，立即重跑同一查询后三个标题全部挂上。端到端运行中工具结果和模型最终的 `Sources:` 段都出现了带标题的链接。

## 验收标准

- 工具结果中的旁白与侧模型文本逐字节相同。
- 只有搜索返回过或代理打开过的 URL 会获得标题；标题从不来自 extractor 输出。
- 无标题结果与之前的输出一致。
- 所有页面比较都经过 `sourceKey`。
- 渲染出的链接符合 CLI 的行内链接模式；指向其他目的地的标题回退为裸 URL。
