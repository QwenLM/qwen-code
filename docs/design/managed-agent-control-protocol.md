## 1. Transport, versions, and trusted callers

The first Session authority runs in the daemon; the Harness uses a controlled Session client. The current in-memory ACP host may use an in-process adapter. Cross-process access installs the same typed dispatcher over the existing private ACP connection, without a public Session RPC. Both adapters perform identical validation and conditional commits; an in-process implementation must not bypass the contract through direct file access.

The proposed `managed-session/1` and `managed-runtime-control/1` capabilities require explicit private negotiation; their names and versions are new protocol design, not claims of existing support. Ordinary callers cannot invoke grants, tool settlement, writer, or gate operations. Identity is resolved from authenticated connections, workspace generation, and server-side bindings. Request tenant/session/epoch fields only check consistency; they do not confer authorization.

Do not add fields in place to strict owned Tool v2, InvocationContextV1, or attestation v2. A versioned Runtime control envelope may embed the unchanged v2 operation/payload and reuse its validators/native methods. New storage/context/ACL evidence and cross-host challenge messages belong to explicitly negotiated control capabilities with closed schemas and matching TS/Java validation, not extra fields forced into v2 payloads or attestation. Unsupported versions, capabilities, or old peers are rejected before effects; no downgrade execution. Existing attestation establishes its declared identity only, not current product ACL or proof of process exit.

Activation-gated bindings accept work only through the controlled dispatcher. Runtime core entry points must reject bypass via raw local clients or direct old v2 requests. Local legacy/experimental bindings not enabling this enhancement retain their old protocol; this compatibility allowance is not a Hosted fallback.

### 1.1 Hosted security boundary (proposed, not yet implemented)

The stricter Hosted profile requires actual product ACL authority, in addition to transport/workload identity and local partition checks. Java owns product ACL, Workspace and Broker facts; qwen owns model Session history/checkpoints; Runtime produces physical execution evidence. No second execution authority, generic workflow service, or MQ is introduced.

The Harness has no Workspace mount or local Workspace side-read path. Startup configuration comes from an immutable Bundle; compaction attachments come from committed results or authorized Runtime reads. Harness-owned state still uses the established storage interfaces. A Runtime path is never interpreted as a Harness-local path. Initially only accepted Read/Write/Edit/foreground Shell capabilities may be enabled; Hosted rejects Legacy/auto-local fallback, unaccepted Hooks, MCP, background tasks, and client callbacks rather than silently executing them elsewhere. Registration in the broader local design does not enable a capability in Hosted.

Reuse [SecretHandle](managed-agent-config-extensions.md): scope, purpose, audience, credentialGeneration, expiry, and current authorization must all match the authenticated consumer and original binding/generation. A handle is a reference, not a bearer credential; possession or a matching tenantId cannot authorize redemption. Runtime must not receive model/service-admin credentials or pass its service identity to user Shell. Tools unable to meet the credential boundary remain disabled. Detailed execution-environment constraints and unresolved isolation evidence are owned by [Endpoint recovery §17](2026-09-21-managed-runtime-endpoint-recovery.md), not duplicated here.

| Check                 | Accept path required                                         | Reject path required                                                              |
| --------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Version/capability    | Matching negotiated control schema with unchanged v2 payload | Old peer, extra attestation field, or raw-client gate bypass rejected before work |
| Workspace/credentials | Authorized Runtime read and scoped handle resolution         | Harness same-path side read, handle-as-bearer, or Hosted fallback rejected        |

These are future acceptance criteria, not results from this revision.

## 2. Shared data structures

Exact encoding, ChatRecord subtype/lock schemas, typed event fields, and numeric limits follow the [storage specification](managed-agent-session-storage.md). The [full coverage index](managed-agent-full-design.md) links configuration, domain, and platform contracts. The initial recovery scope does not limit later design coverage.

These are field contracts. Implement explicit TypeScript discriminated unions and matching validators, not arbitrary JSON in place of known record types. Reuse existing content unions, model history, permission DTOs, and tool results.

| `CommandMeta`       | `v:1, commandId, sessionKey`; writes also carry a stable operation-content digest; execution commits have `expectedSequence`. Connection actor is not model-editable payload                                                                                                                                                                       |

| `CommitReceipt`     | `commandId, firstSequence, lastSequence, eventIds, duplicate`; ACK only after logical commit; duplicate requests return original positions, not new events                                                                                                                                                                                         |
| `EventEnvelope`     | `v:1, sequence, eventId, sessionKey, kind, occurredAt, payload`; execution facts also carry turn/scope/activation; authority assigns sequence, never the client                                                                                                                                                                                    |
| `DurableRef`        | `resourceId, kind, schemaVersion, byteLength, digest`; resolved, authorized, and verified by its Session; no arbitrary absolute path, URL, or disposable temporary file as a recovery reference                                                                                                                                                    |

All share stable executionCallId, input digest, and batch position; no source may forge another source's receipt |
| `WakeIntent`        | `wakeId, reason, subject, sourceEventId, requiredSequence`; reason is input/action_resolved/tool_settled/recovery; scheduling and child extensions require use-specific acceptance; never permission to replay effects                                                                                                                             |

**The v1 `tenantId` meaning remains fixed: a local partition key, not multi-tenancy.** Derived from the resolved workspace, it normalizes identity and partitions paths/indexes. It is not an authenticated tenant principal and supplies no isolation, quota, billing, or cross-tenant authorization semantics. A real multi-tenant platform remains outside [full coverage §1](managed-agent-full-design.md). Existing references to “per-tenant fairness/limits” therefore mean workspace-level fairness/limits in this local design. Keeping the field avoids a future record-format change; it does not establish tenant isolation. Do not derive cross-tenant trust, quotas, or visibility from it. Real tenant identity requires an authenticated control plane and a separately specified source/validation contract. The stricter Hosted profile adds that product authorization layer; it does not reinterpret this local key or a random startup UUID as a principal.

`ActivationSubject` is a closed union: `{kind:'turn',turnId}` or `{kind:'hook_operation',operationId,occurrenceId,event,phase,originTurnId?}`. Existing turn DTOs project the original turnId from the former, without synthetic user turns. WakeIntent and execution events carry the same subject. A prompt Hook without a live turn uses the latter, sharing the Session's monotonic epoch, single model advancer, Harness slot, and model budget. OperationGrant alone grants no model-call right.

A hook-purpose claim accepts only a durable Hook occurrence and fixed plan/input/model policy. After close/delete fences ordinary activations, only lifecycle Hook activations within the accepted maintenance operation remain eligible; they cannot admit new input or start the main Agent, tools/Goal/cron. Reuse PromptHookRunner and commit model.attempt and hook_execution results; release with hook_complete, without turn.settled or task-completion notifications. An uncertain model request retains separate attempt/cost uncertainty and is not replayed automatically. Retain writer, model credentials, and required Runtime resources until that Hook phase settles. Missing legal recovery capability means blocked, not silently skipping the Hook. This broader local Hook contract does not enable unaccepted Hosted Hooks.

commandId is idempotent within SessionKey + operation + commandId; the same ID with different operation content conflicts. expectedSequence is a concurrency precondition, not new business content when retries change it. An authenticated, still-authorized actor's duplicate lookup returns the original commit before checking a current execution fence/sequence; only a miss can proceed to execution checks. Authorization to read the receipt is always rechecked, including on duplicates. A committed old-epoch retry can return at most the original receipt, never renewed advancement rights.

Reads do not require an activation grant, but do require current read authorization. Harness cannot forge user input, final approval votes, or native Runtime results; users cannot submit model execution facts. Reject cross-workspace access, wrong generation/scope, unknown fields, and unsupported schemas before effects. Secrets, full environments, and authentication tokens never enter logs, checkpoints, or error details.

No general `executeMethod(name, args)` or actor-bypassing arbitrary append API is added. Domain commands may share an internal transaction helper, not unlimited user/Harness write rights. The current public Command union has no case-management commands. Future [UNKNOWN case operations](managed-agent-recovery-operations.md#unknown-reconciliation) reuse operation/Action authorization, idempotency, and queries but require explicit closed-schema and capability registration; they are not generic tool-terminal-state mutation.

Domain payloads are validated by registered domain/version. Their only formal event is `domain.committed {domain,version,operationId,recordRef}`; controlled resources at recordRef hold domain state. For committed delivery outboxes, configuration installation, or history maintenance, authority may issue `OperationGrant {sessionKey,operationId,domain,operationRevision,ownerId,workspaceGeneration,resourceScope,leaseDurationMs,expiresAt}` after checking original operation revision, lifecycle, trust, and resource scope. It permits only explicit phases in the original plan, not model advancement or arbitrary new business; it is not a second Session activation/epoch. Initial model-side intent still requires ActivationGrant.

Physical OperationGrant work installs a separate monotonic per-operation Runtime gate. Repeated installation/revocation is idempotent by operation revision; revoked revisions cannot reopen. A next revision first closes old admission and verifies the original phase. New operations obey maintenance barriers, shared capacity, and lifecycle. Original system status/cancel/settlement eligibility survives model-turn completion, without restoring a revoked user's read access. effectId/effectRevision fixes one-shot phase parameters; operationRevision only controls CAS/gates. Reclaiming a grant does not change phaseOperationId or replay unknown effects. Credentialed domain adapters send Channels traffic; workspace files/commands still enter Runtime.

Sessionless workspace Git/PR/directory management uses `WorkspaceOperationGrant {workspaceKey:{tenantId,workspaceId},workspaceGeneration,operationId,domain,operationRevision,ownerId,resourceScope,leaseDurationMs,expiresAt}`. **Delivery stage: R5 history/maintenance F7, not R2; during R2 these operations retain existing workspace service paths.** Only two version dimensions exist: workspaceGeneration selects the valid workspace incarnation; operationRevision controls maintenance CAS/gates. Neither adds a third version nor converts to Session activation epoch. The workspace control owner stores maintenance intent/results; Runtime retains physical receipts. Do not fabricate a Session, model activation, or primary Session ownership. These records are authoritative for Sessionless operations, not copies of Session facts. Apply the same per-operation gates, shared budgets, trust, and maintenance barriers. Conflicting Session writes must be rejected or drained within declared scope; no cross-owner background file changes.

Trusted tool definitions and registered adapters determine result sources, not Harness-declared “local success.” AskUserQuestion derives its answer from actionRequest/final decision without fake Runtime prepare. Todo/Goal changes require domain commits. Agent/child settlement references original scope/result; orchestration lacking durable takeover remains resident or blocks detach. Retain each original ToolResult/error semantic and stable call ID. Workspace tools cannot bypass Runtime through orchestration.

Versioned ChatRecord extensions represent input/formal model messages, tool associations, cancellation/approval, waits, and terminal states. Multi-row logical transactions use transaction ID, count/digest, and final commit marker for visibility; readers expose only complete commits. Unknown subtypes or incomplete transactions cannot execute as legacy sessions. Display and strict recovery keep their separate mappings. Verify compatible readers before physical writer handoff; old hosts cannot append directly to new formats.

A successful first local-backend commit means a complete transaction and file synchronization, plus parent-directory synchronization on initial creation/required lifecycle changes. No success ACK if any step fails. Verify platform semantics with existing writer/file-identity protections; synchronization does not guarantee survival of every hardware failure. After storage failure stop advancement, then strictly read the original commandId commit. Lost ACK after completion returns the original receipt; corruption/uncertainty cannot manufacture completion. The single-machine backend promises no distributed transaction.

## 4. Runtime activation gates

Runtime lease establishes original tool-environment identity only; existing `ManagedToolCallIdentity` does not include Harness activation. The new control protocol installs gates as follows. Coordinator retains the original binding; a larger epoch asserted by Harness has no authority.

1. Authority claim creates an installing activation. Coordinator sends idempotent `stageGate` to every relevant root/child binding: close old activation admission, stage the new epoch, but do not execute. Under the actual admission lock, Runtime returns closed/installed state and the admitted-invocation list.
2. After every required ACK is checked, authority conditionally commits completeActivationInstall. Coordinator calls `enableGate` with grant commit proof. Only after Runtime confirms the new epoch is active may Harness receive a runnable grant. Partial success/lost ACK uses the original installation ID for queries/retries, never early advancement.
3. First lazy Runtime creation also installs gates before tools. New child binding creation serializes with Session activation/close; no uncontrolled child may appear after the all-binding barrier.
4. Every effect admission revalidates Session/scope, Runtime lease, activation, argument/capability/permission versions. Cover beginTurn, history bind/checkpoint, prepare/build, confirm, preflight/Hook, execute, and all other local-work entry points, not only execute. Read-only manifest/status retains identity authorization.
5. `revokeGate` fences new work; it does not cancel already admitted invocations. Coordinator retains narrow status/cancel/settlement/history access. Started work may finish; gate ACK is neither process-exit proof nor a physical result.

Within SessionKey + binding incarnation, Runtime retains monotonic gate revision, maximum epoch, and revoked state. stage/enable/renew/revoke use CAS and return original ACKs idempotently. enable opens only an unrevoked staged gate with the same installation ID; renew extends only that still-active gate. A revoked epoch cannot reopen. After staging a next epoch, reject late old-epoch enable/renew; duplicate queries cannot restore rights. Lost gate state makes the original binding lost and unusable, not an empty-state restart that accepts old grants.

Gate expiry comes from authority, never Harness; coordinator renewal precedes gate renewal. The initial local deployment retains same-host timing and per-admission expiry checks. Partition, expiry, or untrusted clock sources stop new dispatch. Cross-host operation uses the [recovery specification's challenge timing](managed-agent-recovery-operations.md#trusted-control-timing) and original-binding barriers; keep that profile disabled until implemented and verified rather than copying local clock assumptions remotely.

Runtime Session IDs randomly created by Config factories, file-history owner, execution-reference Maps, and pending Promises must transfer to coordinator. A replacement Harness looks up the original Runtime through the durable binding, not a fresh factory UUID. Config shutdown and runTool finally must not terminal-release transferred invocations during recoverable detach.

### 4.1 Dynamic authorization and revocation (proposed)

Authorization comes from the actual product ACL authority and authenticated principal/resource relationship, never tenantId, a random UUID, or a local partition key. policyRevision must bind the real ACL revision and resource scope, not an actor-supplied number. Accepted input or approval is not permanent execution authorization.

| Permission change                        | Required behavior                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Effective reader/read permission revoked | Java stops subsequent SSE, history, Range, export, and receipt-content delivery, rechecking existing streams as well as new requests. Already delivered bytes cannot be recalled. If the task principal also loses eligibility to access the resource for execution, fence further execution and request cancellation. |
| operator revoked                         | Block that principal's queued Prompts, undispatched tools, and later model advancement; request cancellation of running work. Preserve independently valid reader rights.                                                                                                                                              |
| Only owner/admin downgraded              | Reject management actions no longer permitted by remaining rights; do not automatically terminate otherwise authorized ordinary tasks.                                                                                                                                                                                 |
| Approval eligibility revoked             | Revalidate dependent approvals before dispatch; if needed obtain a new request through original arbitration without rewriting old votes. Already dispatched facts are never retroactively classified as not executed.                                                                                                  |

1. Java durably commits the ACL revision and applies current rights to new requests, ongoing delivery, and grant renewal. A stale ACL cache must not renew old authority. These checks are required wherever ACL-managed entry points open, not deferred until a public administration UI exists.
2. Runtime revoke and **final native-operation admission share one serializer**. Check final arguments, current valid permission evidence, gate, and ContextBinding; durably record dispatch before entering native work. After any asynchronous wait (approval, preflight, ledger I/O, etc.), revalidate before native entry. Never treat a pre-await check as a reservation of future authority.
3. Revoke winning the admission ordering prevents new dispatch. Admission winning first leaves an original-ID operation to cancel/settle. Once dispatch is durable, a crash or interrupted handoff may be UNKNOWN even if native entry cannot be confirmed; do not infer not_started. The serialized section must not permit a revoke to acknowledge fencing while a previously unchecked continuation can still enter native work.
4. A database ACL check followed by an RPC is not a distributed atomic transaction. Report the following facts independently, with original operation/binding/generation, revisions, evidence references, and audit time through existing controlled records.

| Reported fact     | Meaning                                                                                                                                                                         | Does not prove                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `ACL committed`   | Product authority durably committed new rights                                                                                                                                  | Every Runtime has fenced or every process has stopped                              |
| `dispatch fenced` | All relevant original gates have acknowledged closure, or valid expiry evidence establishes loss of admission eligibility                                                       | Admitted processes exited, external effects rolled back, or Workspace can transfer |
| `process stopped` | Trusted original process-owner/supervisor evidence establishes exit within its declared scope; storage/node fencing is separate isolation evidence, not fabricated process exit | A physical outcome, history settlement, or Workspace occupancy release by itself   |

Use the existing **60-second lease / 20-second renewal / 10-second challenge control deadline** under [trusted timing](managed-agent-recovery-operations.md#trusted-control-timing). With no stale-ACL renewal and verified timing that accounts for suspend/resume, offline admission under old permissions lasts at most the original gate's remaining lifetime, bounded by 60 seconds. A late response never starts a fresh full lease. This is neither immediate revocation nor a process-stop SLA. Without barrier/valid expiry evidence, report execution revocation as pending/unknown, not complete. Grant expiry never releases a physical Workspace volume.

System queries, original-ID cancellation, receipt acceptance, and resource settlement keep only original-operation, purpose/scope-bound eligibility. They cannot grant new prepare/execute, model calls, or content access to revoked users, including duplicate receipt reads and exports. Closed/deleted Sessions may accept verified late receipts for accounting/cleanup but never create a model wake. Physical stop and Workspace handoff remain separate; see [tools/history](managed-agent-tools-history.md) and [recovery cases](managed-agent-recovery-operations.md#unknown-reconciliation).

| Check               | Accept path required                                                                          | Reject path required                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| ACL/roles           | Retained reader can read after operator loss; lawful task survives admin-only downgrade       | Revoked reader gets no further stream/Range/export/receipt bytes                                                 |
| Race/approval       | Dispatch-first work is cancelled/settled by original ID; valid current approval proceeds      | Revoke-first or stale approval/async continuation cannot enter native work                                       |
| Offline/late        | Valid unexpired evidence permits only its remaining window; original late receipt is retained | Late renewal, stale ACL, untrusted timing, or revoked epoch cannot extend authority; expiry cannot unlock volume |
| Close/system access | Scoped system settlement after close succeeds without waking model                            | System recovery eligibility cannot restore user read/execute access                                              |

The matrix defines future positive and negative acceptance paths; this revision executes none of them.

## 5. Receipts, resources, and recovery guarantees

| Scenario                                                           | Initial guarantee and boundary                                                                                                                                                                                                                       |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Harness replacement while coordinator and original Runtime survive | Retrieve by original invocation/status; advance model only after results/durable resources commit to Session and current rights allow it; no repeated execute or cancellation of transferred work                                                    |
| Tool completed, Session ACK lost                                   | Query/redeliver with original result digest and commandId for the same receipt; retain success and original toolUseId/Hook results; never rerun tool/Hook                                                                                            |
| Original worker lost after Session durably accepted result         | Restore committed Session results, without worker memory Maps or temporary output directories                                                                                                                                                        |
| Original worker/daemon lost with pending effects                   | Missing/404/empty Map/IPC disconnect is not non-execution proof; keep recovery_blocked. A new interface alone cannot reconstruct the original process or automatically resume across worker restart                                                  |
| Result recovery after full worker restart                          | Requires the [recovery specification](managed-agent-recovery-operations.md)'s independent durable RuntimeReceiptStore, phase journal, and old-owner checks; started without terminal evidence stays unknown; no external-effect exactly-once promise |

The precise delivery guarantee is: **while the original coordinator and Runtime binding survive, an invocation is dispatched at most once and its dispatched result is retrieved idempotently by original reference.** This is not exactly-once external effects. Stable executionCallId, gates, and receipt deduplication can establish dispatch count; this protocol cannot observe whether or how often an external effect occurred (network send, Channels delivery, non-idempotent remote API). Therefore started without terminal evidence remains unknown. Harness H04 describes the former, this table the latter; they do not conflict. Never rename at-most-once dispatch as exactly-once effects.

Initial delivery separates recoverable Harness replacement first; pending worker-restart cases remain conservatively rejected. “Worker loss does not lose the Session” does not mean all operations may replay. The original worker lifecycle exits after parent IPC loss and activator clears outputRoot after exit; daemon restart must not assume a surviving attachable worker. Any newer provider-specific takeover is limited to its independently implemented and verified profile.

Reference-based retention applies: do not proactively delete or terminal-release original Runtime results or the only output copy before Session acceptance, necessary media/backup transfer, and associated checkpoint commit. Outstanding child scopes/waits retain references afterward. Session receipt IDs/digests/references live with recoverable history; Runtime cache TTL cannot remove idempotency evidence. The first version adds no automatic TTL cleanup of pending records; deletion/archive remains subject to maintenance rules.

Original parent owner produces history revision. Coordinator durably commits snapshot/ref before advancing accepted revision; failure cannot update an in-memory mirror as success. Cleanup may read original history but cannot advance a new checkpoint. Native receipts may propose resources; authority confirms durable references are readable before ACK. Runtime absolute paths are not Harness-local paths.

## 6. Errors, limits, and cancellation ordering

Internal errors use bounded `{code, message, retryable, commandId?, currentSequence?, recoveryRef?}`, without stacks, secrets, or arbitrary file contents. Initial categories: unsupported_version/capability, invalid_payload, scope_mismatch, idempotency_conflict, sequence_conflict, stale_activation, runtime_unavailable, storage_unavailable, recovery_blocked, resource_limit. Adapters preserve legacy external errors and synchronous/asynchronous timing.

For sequence_conflict reread and reconcile the same business ID, without automatically repeating effects. stale_activation stops advancement; storage_unavailable first queries commit outcome; Runtime unknown remains recovery-blocked. retryable permits protocol queries or same-ID command retries, not tool re-execution.

Session control requests, pagination, and event batches require byte/count/depth bounds, advertised in the initial handshake. Reuse existing content-protocol limits/budget sources; count new envelope overhead separately without increasing tool/media/file-history budgets. Large checkpoints/model history/outputs use DurableRef with bounded pagination, not truncation disguised as recovery. Numeric limits and compatibility follow [storage §5](managed-agent-session-storage.md); implement actual validators/budget checks, never unconsumed limits switches. Over-limit requests cannot receive success ACKs. These retained protocol/resource limits do not add the excluded quota/billing workstream.

User cancel, lease loss, transport EOF, deadline, Harness detach, and Session close have distinct reasons. cancel ACK means only request commit. Uncommitted model-stream deltas do not enter formal history; late native success retains its success receipt. A deadline may end client waiting but leaves pending execution and unsafe-followup barriers intact; see the compatibility design. New model attempts need independent IDs; exact stream continuation or one-time billing is not promised.

This and the storage specification define command families, field typing, limits, commit visibility, installation barriers, and recovery scope.
