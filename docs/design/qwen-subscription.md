# Qwen Subscription integration

## Scope and availability

CLI (Ink/OpenTUI), Desktop and VS Code share Core subscription credentials, membership queries and OpenAI Chat inference. Subscription login, activation, model loading, inference, search and account commands are available without `DEV=true`, including packaged clients. Subscription clients use fixed production endpoints. Product simulation flags, mock transports, preview pages and native debug launchers are removed; regression-test doubles remain.

Desktop adds Qwen to the existing provider dialog, without a separate onboarding page or persistent subscription button. VS Code retains its native provider picker and opens the shared sidebar subscription flow after Qwen is selected. Native QuickPick account actions handle only logout and upgrade.

## Authorization, purchase and recovery

1. Request a device code, display/open its authorization link and poll for tokens. Core enforces the returned `expires_in`; GUI adds no fixed 600-second deadline. Link copying expires with the original grant. Legacy OAuth retains its separate title, countdown and cancellation.
2. Save the complete token pair, then query identity and `member_type`. A failed initial membership query retains credentials: Check again queries identity without reauthorizing. Browser callbacks are unnecessary.
3. Normalize case only when displaying plan names; preserve Free, Lite and other returned names. Only case-insensitive Plus/Pro qualifies for activation. Open the plans page only when the user selects View Plans, including after recovering a membership query. Fresh browser authorization still opens the authorization page without automatically opening a second tab for plans.
4. Purchase waiting checks membership every five seconds, for at most two minutes from its first confirmed unpaid state. Timeout/query failure permits manual Check again while retaining Open plans again and Sign out. Disable duplicate checks during a request.
5. Closing cancels pending work. Temporary network failures retain saved tokens. During explicit sign-in, the previous account stays available until the token exchange succeeds and the new credentials are saved. Errors distinguish authorization, exchange, storage, membership, refresh, cleanup and revoke stages without exposing arbitrary response bodies. Only refresh-stage `invalid_grant` means expired refresh credentials. Shared persisted cooldowns enforce Retry-After for device authorization, refresh and userinfo.
6. Signout deletes local credentials before remote revocation. Remote failure must still synchronize local logout and explain that remote revocation failed; failed local deletion must not announce logout. Cancelling a host view must suppress updates to a replacement owner.

## Activation, models and ownership

Callback rerenders cannot repeat activation. Pending work shows progress; ordinary failures offer explicit Retry. Cancellation, unmounting and owner replacement suppress late success. Before the first session, update the welcome composer's pending model before closing authentication so its first request cannot restore a previous provider model.

Load all IDs from `GET /compatible-mode/v1/models`, without an allowlist. The recorded preproduction catalog included `qwen3.8-max`, `qwen3.7-flash` and `qwen3.7-plus`. Every explicit subscription sign-in selects returned `qwen3.8-max`, otherwise the first model, ignoring the previous saved selection. Ordinary startup and model refresh preserve the saved choice and must not silently replace a removed model. Network/server discovery failures retain credentials and may use the last successful list; without a cache, report failure rather than inventing models. HTTP errors retain their status and display the public `error.message`, with the existing `error_description` fallback. HTTP 403 displays that description verbatim and never returns a cached list. Clear account-owned caches on logout/new authorization.

Within an authenticated Config, subscription model switches reuse the model catalog loaded for the same persisted login revision. Rebuild the model client normally so modalities, context limits and reasoning settings stay synchronized. Read the current login revision locally before reuse; token rotation preserves it, while logout and new authorization invalidate reuse. Startup, explicit authentication/catalog refresh and switching back from another provider still load the catalog. A failed explicit refresh or a login change during refresh must not authorize later reuse of that catalog. CLI, Desktop and VS Code share this Core behavior.

Subscription `qwen3.8-max` and `qwen3.8-flash` explicitly support image and video inputs in both the model registry and request configuration. Other server-returned IDs remain available with conservative text-only modalities until their gateway capabilities are confirmed.

## Protocol and credential security

| Purpose                | Endpoint                      |
| ---------------------- | ----------------------------- |
| Device authorization   | `POST /api/oauth/device/code` |
| Token exchange/refresh | `POST /api/oauth/token`       |
| Identity/membership    | `GET /api/oauth/userinfo`     |
| Revocation             | `POST /api/oauth/revoke`      |

The subscription auth origin is `https://auth.qwen.ai` and the OAuth client ID is `qwen-code-cli`. Browser authorization is `https://chat.qwen.ai/authorize?user_code=<code>&client=qwen-code`; the browser client parameter is distinct from OAuth client_id. Plans use `https://chat.qwen.ai/?memberPlan=qwen_code`, shared by upgrade and purchase actions, without device-code parameters. Both browser entries require a signed-in web account.

Core owns private atomic storage, restoration, cross-process refresh locking and revocation. Hosts share sessions only with the same effective `QWEN_HOME`. Subscription storage is separate from legacy OAuth. Refresh replaces the complete token pair; tokens and device codes never enter GUI responses.

Inference uses the fixed `https://api.qwen.ai/compatible-mode/v1` gateway with OpenAI Chat Completions. Configuration stores the auth selector, model ID, fixed gateway and placeholder credential. Supply Bearer tokens at the transport boundary; preserve proxy/cancellation and reject redirects or other destinations before sending credentials. HTTP work runs outside credential locks. Retry a rejected token once on HTTP 401, comparing current/rejected tokens inside the lock to avoid double rotation. Do not refresh for 403/404/429 or replay a delivered stream. Missing credentials fail without implicit authorization; logout clears cached credentials for later requests.

## Quota exhaustion presentation

CLI (Ink/OpenTUI), Desktop and VS Code share one Core conversion for subscription chat and MCP search errors. Only HTTP `402` together with `error.code = insufficient_quota` identifies quota exhaustion; neither message wording nor optional `error.quota` participates in classification. Known `lite`/`plus` members receive weekly-credit guidance and `/upgrade`; `pro` receives weekly-credit guidance to wait for reset. Unknown/missing tiers receive generic credit guidance without an upgrade claim. Missing or malformed quota context still produces quota guidance.

`quota.reset_at` is an integer Unix timestamp in seconds. Omit absent, invalid or elapsed timestamps. Round remaining hours up; below one day show hours only, otherwise show days and hours. Core attaches a typed subscription_quota display payload only after confirming HTTP 402 and insufficient_quota, while retaining readable English for text-only hosts. The payload carries optional tier, reset time and request ID through the existing error/tool-result channels. Both CLI renderers and shared Desktop/VS Code components format that payload through their existing i18n translators. The supplied English, Simplified Chinese and Traditional Chinese copy belongs in the corresponding locale catalogs, including reset-time templates and time units. Core shares classification and countdown calculation without selecting a locale; text-only hosts retain English fallback text. The i18n key checker includes shared Core utilities. Ordinary tool output and backend prose are never matched or rewritten as quota notices. Other backend messages remain unchanged. Authentication, retries and membership caching are outside this change.

In the sidebar purchase UI, View Plans is the primary button, Switch Provider is outlined, and Use another account is a separate centered text action below them. Preserve callbacks, keyboard focus and the existing retry action.

Verify English/Chinese text, known and unknown tiers, partial/invalid quota fields, time boundaries, stream/non-stream chat, MCP search, preserved status/code/request IDs, and sidebar action variants and callbacks. Fixture tests do not establish real gateway or native-host acceptance.
