# 托管工作区创建时选择模型

[English](2026-10-22-managed-initial-model-selection.md) | [简体中文](2026-10-22-managed-initial-model-selection.zh-CN.md)

## 问题

本地启动器为每个配置模型注册一个自定义 AgentDefinition，并将编译后的审批策略固定为 `default`。因此选择模型后，新建任务的权限菜单只剩 `default`，而内置 `qwen-code` 支持 `default`、`auto-edit` 和 `yolo`。

## 决策

将本地模型预设发布为 `{agentId: "qwen-code", modelId, label}`，兼容原有 `{agentId, label}` 预设。选择模型只改变 `modelId`，与 Agent 身份和审批模式独立。已有定义和会话保留原身份与策略，无需数据迁移。

为绑定工作区的 WebShell 创建请求增加可选 `modelId`，在会话选项中声明 `modelSelectionSupported`。要求使用内置 `qwen-code`、现有 Harness 模型选择能力，并精确匹配宿主模型目录。不支持的选择在准入前拒绝。能力缺失时，客户端不能提交目录中的模型。字段省略时，保持原请求摘要和默认行为。

将所选模型冻结在客户端持久化创建意图和服务端幂等摘要中。在现有创建事务内，先写入 `model_id` 与 `model_revision=1`，再插入首轮，使首轮同时保存模型和审批快照。空会话同样保留选择。同键重试在当前能力门禁前返回原准入；改变模型内容则冲突。清空草稿前读回并核对 Agent、工作区、模型和初始审批策略。

## 范围与风险

复用模型目录校验、用户与工作区授权、回合快照和 Harness 执行。不替换已有会话，不修改自定义定义的创建策略，不改变 Runtime 权限，不拆成多次请求而让首轮先于模型或权限选择发送。保留本地定义白名单，使已有自定义会话继续可用。新增可选字段需要匹配的控制面和前端；更新本地预览时使用匹配产物。

## 验证

以两个受控模型覆盖三种审批模式，检查首轮模型与审批快照。覆盖空会话创建、省略 `modelId`、未知模型、能力缺失、用户与工作区拒绝、冻结重试身份及不同请求内容冲突。同时操作 UI 模型和权限选择器，核对草稿保留与读回，并确认旧自定义预设兼容。更新用户预览前完成相关 Java/TypeScript 测试、API 契约检查、构建、类型检查、打包、模块验证及隔离原生测试。
