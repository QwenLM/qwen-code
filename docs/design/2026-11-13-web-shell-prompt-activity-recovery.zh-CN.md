# Web Shell 任务活动状态恢复

[English](2026-11-13-web-shell-prompt-activity-recovery.md) | [简体中文](2026-11-13-web-shell-prompt-activity-recovery.zh-CN.md)

## 问题

观察者可能在其他客户端提交任务之前就已连接，因此最初的 `hasActivePrompt`
快照为 false。之后的实时事件与归属匹配的活动轮询会确认任务正在运行。
如果活动状态覆盖丢失，现有兜底逻辑会立即将观察者置为 idle。归属不匹配的
采样也可能覆盖缓存，使后续 SSE 断流结束运行指示。之后的 active 轮询刻意
不会复活 idle 任务，导致没有新业务事件的任务执行期间 Provider 持续 idle。
这是 #17005 中已复现的部分，不代表已经确认原托管环境事故的原因。

## 范围

修复 Web Shell 观察者的活动状态恢复。保留现有 daemon 协议、常规
Last-Event-ID 续传、本地任务归属、终止事件处理，以及从未提供实时活动状态的
宿主所使用的静默启发式。网关限制、运行时部署、epoch 重置行为和重连可观测性
属于独立工作。

## 决策

当前连接仍属于已连接会话时，忽略其他归属的活动采样。会话切换正在加载目标时，
仍允许接收目标会话的采样。

运行中的观察者失去此前归属匹配的 active 状态时，复用现有同会话加载操作
重新确认状态。等待期间保留任务状态与可见聊天记录。给这次内部加载标记活动
状态恢复，使非终止性的 SSE 结束逻辑也保留运行指示。替换加载返回的快照成为
活动状态依据，包括没有运行中任务的情况。后续实时轮询不会独立复活已完成任务。

等待恢复期间收到的 inactive 实时采样会立即结束运行指示，优先于较早发起的
加载或 active 轮询的响应。

复用现有加载标识、归属检查、请求期限和 watchdog。当前恢复失败时，展示通常的
加载错误，并结束对应运行指示。后续会话切换或新提交的本地任务不能被旧恢复的
失败结束。不新增公开选项、daemon 路由、重试循环或持久化状态。

## 约束与风险

活动覆盖丢失现在会触发一次完整会话加载，代替立即置为 idle。正常成功的轮询与
SSE 游标续传保持原有行为。加载必须保留聊天记录，并使用解析后的会话上下文，
包括独立会话。缓存中的实时活动不能覆盖替换快照。旧采样与失败的加载不能影响
新归属，也不能复活已经结束的任务。

## 验证与验收

- 修复前，观察者回归测试必须因过早进入 idle 而失败。
- 等待恢复期间以及新快照报告 active 后，观察者持续显示忙碌，无需新业务事件。
- 新快照报告 inactive 时结束运行指示，即使加载期间曾收到较旧的 active 轮询。
- 恢复期间收到 inactive 实时状态时，同样优先于延迟返回的 active 快照与轮询。
- workspace/session 不匹配的采样不能清除当前可信状态。
- 恢复失败或超时后展示加载错误；后续会话归属或新的本地任务不受影响。
- 已有本地任务、恢复任务、终止事件、旧轮询和传统静默测试继续通过；构建、类型
  检查及定向测试必须通过。
- 条件允许时使用真实 App 与活动桥接执行浏览器验证；明确说明 daemon 为模拟，
  不将其描述为生产事故验证。
