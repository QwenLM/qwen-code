## Problem statement

The merged managed `/loop` slices carry review findings that were recorded as deferred under the convergence posture — acknowledged, not fixed in their rounds. Six of them are confirmed still valid on current main and are small, self-contained hardening fixes. This PR closes exactly those six; the rest of the deferred backlog (design-doc stale claims, dead Java branches, child-catalog code gaps, other probes) is left for separate follow-up.

## The six fixes

1. **Fake-model minted-id extraction pin (#17470).** Re-pointing the clear-leg pin to the assertion-side `createdScheduleId` left the fake model's own id extraction (the delete fixture's id source) unpinned. The extraction is now the top-level pure `mintedScheduleId(messages, createCallId)` — it filters tool results by structured `tool_call_id` and returns `undefined` rather than an invented id — used by both fakes and executed in the meta-test against hostile histories, with pins on both call sites and on the loud-failure `?? 'missing-schedule-id'` fallback, so a fabricated id, a dropped call-id filter or a substring match reddens the fast suite. (Round 2 consolidated the original inline regex plus filter into this helper; see Round-2.)
2. **Classifier narrowing executable witness (#17470).** The block-schema narrowing was pinned only as text (`'shouldBlock' in blockProperties`); an additive fallback that answers `shouldBlock:false` for any `respond_in_schema` query re-created the mis-answer of unrelated side queries (title, tool-use summary, next speaker) while staying green. Extracted the decision into a top-level pure `classifierBlockAnswer(blockProperties)` (returns the stage-exact answer for a block schema, `undefined` otherwise), used by both the skill and fire fakes, and executed it in the meta-test against block (stage 1/2) and non-block schemas. The additive-fallback mutation reddens the non-block directions.
3. **Sentinel allow-list (#17272).** The union/wakeup sentinel guard was a deny-list of the two known non-expanding forms (`<<loop.md>>`, `<<autonomous-loop>>`), so a newly added sentinel would ship undetected. Inverted to an allow-list: a body may carry only the wakeup-expanded `<<loop.md-dynamic>>` / `<<autonomous-loop-dynamic>>` forms (cron: none). Extracted as the pure `assertSentinelsExpanded(body, profile)` and executed against a hostile body with a brand-new sentinel.
4. **`Nd` cron semantics (#17272).** The interval table claimed `0 0 */N * *` means "every N days"; it is a day-of-month step (days 1, 1+N, … resetting at each month start), not a rolling N-day cadence. Corrected the bundled SKILL.md table row and added a caveat naming the month-boundary reset; updated the generator's managed substitution to the accurate UTC wording; regenerated the sidecars.
5. **Parsing rule inventory pin (#17272).** The drift guard checks source→body coverage, so a rule deleted from the bundled source is invisible to it. Added a parity test pinning the exact Parsing rule inventory (`Empty input`, `Leading interval token`, `Trailing "every" clause`, `Prompt-only input`), so a deletion reddens.
6. **Single-source profile set (#17272).** The profile list `['union', 'cron', 'wakeup']` was hand-kept in six test loops. Exported `MANAGED_LOOP_PROFILES` as the single source, derived `ManagedLoopProfile` from it, and replaced the hand-kept full lists; the `Record<ManagedLoopProfile, …>` asset map and the parity `it.each` now force coverage of every profile, so an added or removed profile cannot drift.

## Design decisions

- **Executable guards over text pins.** Fixes 2 and 3 follow the established pattern (assertCallerImportReplaced, assertScheduledFireWitness): a top-level pure declaration the meta-test loads and executes, so severing or drifting the guard reddens an assertion rather than merely failing a text match.
- **Allow-list, not deny-list.** Fix 3 fails closed on any unknown sentinel; the two expanding forms are the closed set a Managed body may teach.
- **Content fix flows through the generator.** Fix 4 edits the bundled source and the generator's substitution together and regenerates the committed sidecars, so the byte-for-byte parity test stays the oracle; no hand-edited sidecar.
- **No runtime code change; model-facing skill content does change.** No runtime module imports managed-loop-skill.ts — its only consumers are the regenerator and its own test — and the classifier helper lives in the E2E runner's fake model, not in shipped code. But the `Nd` fix edits the bundled `SKILL.md`, which ships with the build and is read at runtime by `readBundledReference`, so the local `/loop` guidance a model sees does change (that is the intended correctness fix), as does the Managed sidecar JSON the Java classpath copies at build. The two imports this PR adds to managed-loop-skill.ts (`LOOP_SENTINEL_DYNAMIC`, `AUTONOMOUS_SENTINEL_DYNAMIC`) are the sentinel constants the allow-list sources; they do not make the generator a runtime module.

## Third verification round: the remaining write and tool-call siblings

The third independent verification round re-measured all four round-2 survivors as closed and every new pin as load-bearing, then measured three more siblings of the same in-place-write / hand-built-tool class. All three, plus the alias write from Round-7, are closed here — in this PR, not a follow-up.

- **The writer set was not the whole set.** `Reflect.set(blockProperties, 'shouldBlock', …)` and `Object.defineProperties(blockProperties, …)` before the helper call left both suites green. The call-writer branch now keys on a name set — `Object.assign` / `defineProperty` / `defineProperties` and `Reflect.set` / `defineProperty` — still requiring the first argument to resolve to the decision or its input.
- **An alias carries the same value.** `const propsAlias = blockProperties; propsAlias['shouldBlock'] = …` moved no inventory because the write keyed on the two binding names. The tracked set now grows as aliases are declared, so a write through an alias of the decision or its input is recorded, at any chain length in source order.
- **A hand-built tool call with a computed name was invisible.** The hand-built coverage rested on counting `respond_in_schema` literals, so an element assembled without `fakeToolCall` whose name is computed moved nothing. Every element of a `toolCalls` array that is not a `fakeToolCall` call is now recorded with its callback, and the loop pin requires none.

The writer lookup is a `Map`, not an object literal: an ordinary object would resolve a receiver named `constructor` or `toString` to a prototype function and throw on the optional `.has` call. The control carries such a receiver, and reverting to the object literal fails it with `IN_PLACE_WRITERS[...]?.has is not a function`.

Each shape is in the executed hostile control (so no inventory is vacuous) and was injected into the real fire callback: `Reflect.set`, `Object.defineProperties`, the computed-name hand-built call and the alias write each redden the pin (1 failed / 87 passed), and every earlier shape still reddens — second binding, another call id, hand-built call spelling the name, `let` + inline allow, `??=`, fabricated provenance, usage-line `??`, computed tool name, widened gate, member write, template-literal sibling, `Object.assign`, short `fakeToolCall` — while a comment naming the bindings stays green. All restores byte-equal.

**Why this keeps recurring, and what ends it.** Every one of these siblings is a way to write the same value or emit the same answer without spelling it the way the scanner looks for. The scanner is a spelling-level guard over an inline decision, so its evasion surface is unbounded. The packaged `--loop-fire` arm drives the fake's actual answers end to end and is therefore the behavioural guard, while these structural pins are a best-effort fast-tier approximation; that the arm fails under each specific sibling is inferred from what the mutation does to the fake, not separately measured here. The durable fix is to draw the seam around the whole decision — schema lookup, narrowing, gate, answer — and execute one pure function per arm, retiring the inventories. That refactor, the `CronSlots.java` fixture binding, the shape-independent Java routing assertion, the single exported Parsing grammar and the derived degeneration threshold are tracked in #17673.
