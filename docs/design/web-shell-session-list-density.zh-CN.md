# Web Shell 会话列表密度

[English](web-shell-session-list-density.md) | [简体中文](web-shell-session-list-density.zh-CN.md)

## 问题与现状

长会话标题需要与行内 Pin、行尾附件和 PR 徽章竞争空间。移动抽屉最受限制，但窄桌面嵌入也有同样约束。PR 编号和状态属于有用元数据，因此隐藏可见状态并不构成可接受的密度优化。

本 PR 沿用既有会话列表、PR、组织、归档和重命名模型，只改变展示与动作路由，不引入第二套列表或持久化实现。

## 目标与范围

- 在触屏和桌面上为会话标题留出更多空间。
- 保持 PR 编号/状态图标、链接和无障碍说明可见。
- 不增加每行行高，同时保留说明/状态标记和工作流动作。
- 保留普通会话与 Recent 行的能力、禁用及 standalone 行为。
- 保留桌面普通标题双击重命名原有交互。

不涉及行布局或标题编辑器重设计、排序规则、归档语义，也不处理无关 iframe/generated-ui 行为。

## 布局与动作路由

粗指针通过 `(hover: none) and (pointer: coarse)` 使用 85% 抽屉。细指针的窄桌面视口仍按原有 70% 规则做 clamp；不能只因宽度小就当成触屏。两组计算都保留宿主显式提供的最小/最大宽度变量。

桌面默认 More 菜单承载可选 Pin 及既有 Rename、归档、分组、分屏和删除操作。细指针下，宿主显式配置的 `inlineItems` 仍渲染所请求的行内动作。粗指针则把这些动作放进 More，不再为多个持久图标预留槽位。

Recent 行保留桌面 Pin/Archive 按钮。其粗指针展示使用同一 `SessionMenu` 和 Pin/Archive 处理器，继承既有能力、忙碌、运行中/当前会话与 standalone 限制。宽度不超过 280px 的触屏视口省略装饰性的 Git/来源图标，不删除 PR 或目标信息，也不改变悬浮详情的数据。

PR 徽章只缩小间距，不删除编号、可见状态图标、链接、数量或 ARIA 说明。其他徽章消费者继续使用非紧凑样式。

## 交互边界

实时媒体查询订阅在设备变化时更新粗/细指针动作模型，并在卸载时移除监听器。它覆盖外接键盘、触控板和窄桌面宿主，不把判断留成一次渲染时的快照。

Radix 会话菜单通过 portal 落在抽屉的实际 DOM 子树之外。因此 App 抽屉在 Escape 与 `touchmove` 两层处理中，将 `[data-slot="dropdown-menu-content"]` 视为逻辑上属于本表面：第一次 Escape 关闭打开的菜单，短菜单保留原生触摸滚动，下一次 Escape 才关闭抽屉。自建的 Group 菜单也标记为同一逻辑键盘/触摸表面的一部分。

Group 菜单可能在 Radix 完成关闭 More 之前挂载。此时，More 的关闭回焦改为聚焦 Group 当前选项，而不是恢复旧触发器。随后 Group 通过 Escape 关闭时，再恢复 More 触发器。这样避免异步 More 卸载抢走或丢失 Group 的键盘焦点。

行控件已经阻止单击和键盘事件冒泡；现在也阻止双击冒泡。这样，点击菜单项或菜单空白形成的双击不会通过 React portal 触发行重命名。普通标题双击重命名仍用于桌面；不把它宣称为新增的移动端手势，因为移动端单击会话行会选择会话并关闭抽屉。

## 约束与风险

实际标题空间取决于宿主宽度、字体和本地化。因此测试断言有意义的几何空间下限、保留的控件和真实事件结果，而不是某种设备或字体固定渲染出的像素值。

base 视觉捕获仅注入缺失的场景和 fixture，预期遵循 base 的真实实现；注入测试不意味着 base 原有 PR 行为。移动端与桌面的行为检查进入阻断式 `@smoke` 车道，不只依赖可能保留部分证据的视觉捕获工作流。

## 验证计划

- 运行 sidebar、徽章、定制及菜单生命周期单测，以及 Web Shell 类型检查、构建、lint 和格式检查。
- 捕获 base/head 的 iPhone 与桌面明暗主题图片，确认预期图片真实存在且不同。
- 覆盖粗/细/粗媒体切换、显式桌面覆盖配置、More 中 Pin/unpin、能力受限的 Recent 动作和折叠表面。
- 在 Chromium 触摸仿真中使用真实 Escape 按键、菜单双击和 CDP 触摸移动，确认菜单滚动、首次 Escape 后抽屉保留、portal 双击不触发 Rename；另行确认桌面普通标题双击 Rename。
- 用独立 HOME/workspace 启动真实 daemon，通过 HTTP 创建真实会话，由 UI 驱动 Pin/unpin，再检查返回状态与磁盘持久化结果。不读取或修改用户共享 daemon 或会话状态。
- Chromium 仿真不是 Safari 或真机 iOS 认证。支持 WebKit/真机验证时，在具有相应运行库的环境中补测。

## 验收标准

1. 触摸抽屉与桌面中的长标题有可用空间，PR 状态同时保持可见和可操作。
2. 每个既有动作在原有能力与禁用规则下仍可达。
3. 菜单的键盘/触摸归属与双击隔离经真实浏览器事件验证，桌面正常重命名保留。
4. 视觉证据有真实 base 对照，行为检查不被 best-effort 捕获步骤掩盖。
5. 最终报告列明实际执行的检查、真实 daemon 持久化结果和不支持的原生设备边界。
