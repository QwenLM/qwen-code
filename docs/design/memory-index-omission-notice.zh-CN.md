# 记忆索引遗漏诊断

[English](memory-index-omission-notice.md) | [简体中文](memory-index-omission-notice.zh-CN.md)

## 问题与范围

Issue [14877](https://github.com/QwenLM/qwen-code/issues/14877) 指出，索引重建遗漏主题文件时没有列出名称。现有扫描解析所有合格文件，但只返回 200 个；随后的索引预算还可能遗漏更多条目。写入侧的通用警告未保留这两组遗漏，读取到提示词时也无法再解释。

本修复仅改变诊断。headless 写后重建、保留策略、删除主题文件、扫描信任规则和现有 PR 均不在范围内。

## 方案

仅供索引使用的扫描返回与原先相同的保留文档，以及被截去的尾部。project/user 仍按修改时间从新到旧选择；team 仍按相对路径确定性选择，并在扫描上限之后分组。其他扫描调用者保留现有 API 和行为。

写入侧分别报告索引预算遗漏的条目和扫描上限遗漏的主题文件，每组包含数量及最多三个经过长度限制的名称。不将两组数量相加：一个经过 team 分组的条目可能代表多个主题文件。仅扫描上限遗漏时，说明主题目录未列全，并建议合并主题文件或移除过时文件；只有实际触及条目预算时才说明索引过大。两种限制同时发生时，分别给出对应操作。只格式化名称样本中的遗漏文件。诊断区分候选条目过多与过长，不声称所有遗漏都必然最旧：字符预算回填可能保留后面的短条目。

写入侧建议针对底层主题文件，而不是临时编辑生成的索引。过长的写入条目已经不含描述，因此长度处理方法是缩短路径或 frontmatter 名称。只有候选正文超过字符预算，且将过长条目缩短到普通行长度上限后能够使正文回到预算内时，才给出针对过长链接的长度建议。如果候选正文在普通行长度下仍然超出字符预算，写入侧报告条目累计长度，并建议缩短主题文件路径或 frontmatter 名称/描述，也可以合并或移除文件。累计字符压力不等于条目数量超过上限。单纯行数溢出时绝不给出长度建议。读取侧还可能加载手写条目，因此只有候选字符预算实际构成限制时，才保留其独立的「移出细节」建议。

读取侧将写入侧的单段警告保留在条目预算之外，不再丢弃它或将它计为额外条目。只有位于末尾、具有已知预算/扫描上限写入侧前缀且不超过 1024 个 UTF-16 代码单元的提示才符合条件；任意过长的类似警告文本仍受预算约束。新索引指针必须插入末尾警告之前，使警告仍为最后一段；在警告之后追加指针将使其失去豁免。保存指引和用户文档说明此边界。旧预算警告前缀仍可识别。如果读取侧另有截断需求，则保留写入警告并追加自身诊断，选择长度相关建议时只考虑前 200 个候选条目。

已识别警告之前多余的空白分隔不计为索引条目。短的多行结尾仍受预算限制，不作为写入侧元数据原样保留。任意根目录重建与按作用域重建报告相同的扫描遗漏，同时保持原有的 mtime 选择，包括兼容的 team 根目录模式；通常的共享 team 重建仍保持确定性的路径排序。

## 约束与调用者

保持 200 文件扫描上限、200 行索引上限、25,000 UTF-16 代码单元的条目正文预算，以及 150 单元普通条目的优先级。主题文件保持原样。复用现有标题净化和不会切断代理对的 60 单元诊断名称。

新增内部扫描仅由 project/user/team 索引重建使用。现有构建函数通过可选参数保持兼容。重建调用者包括保存/提取、Dream、forget、托管写入刷新和元数据迁移；它们的路由与错误处理不变。所有 project/user/team 提示段使用同一识别警告的读取逻辑。不新增 daemon 路由或跨包边界。

## 验证与验收

在精确 main 上使用合成文件系统存储复现，再比较修复后的保留条目及顺序。覆盖仅字符预算、仅扫描上限及组合遗漏，预算内无警告，非尾部超长条目遗漏，受限的恶意/增补字符名称，三个作用域，提示词往返，以及不受长度限制的手写类似警告文本。新回归测试必须在原始生产代码下失败。运行相关记忆套件、build、bundle、typecheck、格式及 lint 检查。

已确认基线源码运行时复现。最终验证结果记录于 PR 报告；本文不声称执行了模型、交互 CLI 或 ACP。本地无已发布 CLI，已记录的替代验证直接执行真实文件系统写入/读取源码，不发送模型请求。
