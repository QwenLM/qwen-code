# Shell 权限规则覆盖与重定向匹配

[English](2026-11-17-shell-permission-rule-coverage.md) | [简体中文](2026-11-17-shell-permission-rule-coverage.zh-CN.md)

## 问题与范围

PR #17372 的 R5 至 R7 修订使 shell 规则建议与权限管理器实际评估的调用保持一致。调用方选择的片段、AST 命令组、注释、包装命令及重定向写法，否则可能对应不同的可执行片段，产生无法生效的持久授权，或者让宽泛的 allow 规则掩盖限制规则。

本次变更覆盖 Bash 规则生成与匹配，包括 Monitor 使用的 shell 命令，保留现有权限优先级和持久规则格式。下文验证记录区分已完成的本地检查与仍需通过的上游集成检查。

## 调用方选择与完整覆盖

建议生成器为每个命令同时保留 AST 源码范围和原始文本，并在定位范围之前一致地移除 Bash 续行。只有与 AST 命令组重叠的全部调用方片段均被选中，该组才具备生成建议的资格；组内的文本片段不会成为独立授权。

即使描述符关闭的结构性修复确定了片段范围，只要原始片段的解析有错，就不能发布派生规则，只可保留其字面量回退规则。这避免语法树凭空产生的命令成为单独授权。

生成候选规则并去重后，生成器使用权限管理器的命令分割器和规则匹配器检查完整的选中调用。必需片段来自该匹配器分割器，并与调用方选择重叠，因此 Bash 注释尾部不会单独成为覆盖要求。每个必需的可执行片段都必须被覆盖。任何片段不受支持或未被覆盖时，都不返回持久规则建议。这也避免 gate 提示展示一组保存后立即再次要求确认的 allow 规则。注释本身绝不生成执行授权。Monitor 继续保守地分割注释：包含注释的调用仍可能无法通过覆盖检查，返回 `[]`，并且没有 cron 提示。本修订不声称新增支持这些场景。

## 注释与执行包装

运算符扫描器只在已知未引用、未转义的词边界或输入起始处移除注释，紧接展开、赋值或命令组的 `#` 会保守保留。扫描器、替换检测器、重定向守卫和续行处理共享参数展开范围：`${...}` 内的井号是数据，范围闭合后恢复普通注释识别。范围跟踪包含嵌套展开、进入时的引号上下文，并区分 `$$` 与参数引入符。真实注释中的引号或反斜杠不会吞掉下一条物理行。Monitor 的保守分割可以保留注释中的运算符，但仍遵守这条物理行边界。既有算术运算符处理保持不变。

权限守卫与虚拟操作跟踪器共享透明包装命令的解析逻辑。已知选项只消耗其定义要求的参数，剩余执行内容保留原有引号。对于 `/usr/bin/setsid`、`/usr/bin/sudo` 等路径，会识别已知外部可执行文件的 basename；`exec`、`command` 和 `builtin` 仍只作为内建命令名称处理。受支持的无值选项不会使普通命令变成不受支持的语法。不受支持的选项仍不能产生授权，但限制性提取可使用已知参数位置保留执行内容的 deny 判定。GNU `env -S` 按 argv 分割，并继续解析 env 自身的选项和赋值，不把字符串当成 shell 源码：字面量 `>` 和 `;` 参数不会产生文件操作，显式 `sh -c` 内容则继续作为执行内容处理。依赖环境变量的分割字符串保持未解析状态。赋值前缀解析共享同一拼写规则，并把括号值保留为完整单词；跟踪器在遍历前缀链之前移除续行。

`eval`、`source`、`.`、`trap`、`xargs`、`parallel`、已识别的 shell 家族和 BusyBox shell applet 等未建模执行形式需要确认，包括脚本文件名、标准输入执行、`--`、POSIX `+` 选项及 fish 命令选项；帮助和版本查询仍作为控制用例。已支持的 Bash/sh 命令字符串继续保留已跟踪写入的 deny 判定。Monitor 在权限检查命令中保留未建模的包装选项，包括环境赋值前缀之后的选项；归一化不会在实际执行命令仍保留这些选项时将其从权限检查中隐藏。空 argv 单词不能促成授权匹配，限制性匹配可以忽略空参数，但不能把后续单词提升到空的可执行文件位置。普通 `git -c`、`gcc -c`、带变量的 echo 参数，以及普通参数中类似包装命令的文本，仍作为数据。这些检查不声称能通用分析解释器脚本或任意可执行程序的副作用。

未建模语法或带展开的参数可能影响显式 Read/Edit 限制时，即使仅有的 Bash allow 与调用无关，该限制仍被视为相关。因此真实调用方不会跳过权限评估并保留默认 allow，未确定的限制也会阻止提供持久 allow 建议。没有适用限制规则的调用继续遵循既有默认策略。

## 限制规则的重定向等价关系

`staticShellCommand` 仅为 deny/ask 匹配提供语义视图。移除引号时保留字面量与通配符的区别，随后对重定向目标进行有限的词法归一化：

| 输入                                        | 处理方式                                         |
| ------------------------------------------- | ------------------------------------------------ |
| `/tmp//protected`、`/tmp/./protected`       | 与 `/tmp/protected` 等价                         |
| 已知调用 cwd 为 `/project` 时的 `protected` | 可与 `/project/protected` 比较                   |
| 调用 cwd 为 `/` 时的 `protected`            | 可与 `/protected` 比较，不会凭空形成 `//` 根路径 |
| 未提供绝对 cwd 时的相对目标                 | 保持相对路径                                     |
| `..` 分量及恰好以 `//` 开头的根路径         | 保留原样                                         |
| 引号内或转义的 `*`；未加引号的 glob 目标    | 保留字面量标记；未解析的 glob 不视为字面目标     |
| 开头未加引号的 `~`                          | 使用与操作跟踪器相同的主目录展开                 |
| 未加引号的 `~user` 前缀                     | 保持未解析；引号或转义的波浪号前缀保留为字面量   |

该视图不会调用 `realpath`、解析符号链接、折叠可能受符号链接影响的 `..`，或推测 cwd。涉及父目录分量且可能适用的限制保持未确定状态，要求确认。引号内的波浪号仍是字面量。开头为通配符的模式保留既有覆盖范围。allow 匹配保持原有词法行为，新等价关系不会扩大已保存的授权。重定向运算符的前瞻长度固定为已支持运算符的最大长度，因此很长的描述符关闭链在这一扫描中仍保持线性开销。

## 复合命令中的工作目录

只有在可能改变目录的命令出现之前，调用 cwd 才是已知的。Bash 规则评估在 `cd`、`pushd`、`popd`、加载脚本代码，或无法识别命令位置的片段之后传递内部 `cwdUnknown` 标记。因此函数和带赋值前缀的目录变化不能继续把初始 cwd 视为已确定。命令位置分析复用现有分词器和静态视图；`echo "$X" cd` 中的参数不会改变 cwd。

cwd 未知时，限制规则匹配不会把后续相对重定向锚定到初始目录。可能适用的重定向限制即使遇到 `Bash(*)`，也会强制要求确认。规则相关性检查、强制确认标记和 deny 规则引用使用同一上下文：不确定的目标不会被表述为已确定命中的 deny，新增持久 allow 也不能覆盖此次确认要求。精确匹配或不依赖 cwd 的限制仍遵循正常优先级。

完整命令的虚拟操作跟踪器使用同一目录变化分类器。它在左结合的 `&&`、`||` 中分别保留成功与失败的 cwd 状态，并在无条件分隔符处合并可达路径。不同路径产生不确定的代表路径，而非已确认的目的地。成功的字面量 `cd` 后接 `&&` 可以确定目的地；`cd` 后的换行不能证明它成功。否定交换成功与失败，管道不会把子进程的目录变化传给相邻命令，后台命令列表保留前台 cwd。加载脚本和无法确定的命令位置使两种结果都变为未知。启用 shell 选项、包含选项操作数的短选项簇，以及影响执行环境的变量赋值，不会被认证为透明操作。宿主的 CDPATH 也会使裸相对 cd 目标不确定；显式 ./、../ 路径仍保留相对当前目录的含义。逐片段评估不会再次使用过时的初始 cwd 提取虚拟路径。这仍是保守分析，并非完整的 shell 解释器。

## R8 限制规则后续修复

参数展开不能使未解析的重定向限制消失；静态比较仍能证明不同目标无关时，继续保留该控制行为。显式 Read/Edit 限制也使带展开的参数路径保持未解析状态，包括受支持的 shell 包装内部；不猜测环境变量值，操作跟踪器仍不为未知路径制造操作。存在文件限制时，未引用的路径名或大括号展开、命名主目录前缀同样要求确认，字面写法继续作为对照。HOME 变更加入影响执行环境的守卫；当 env/exec 前缀清除 HOME 时，既有 shell 递归会把这种不确定性传给子 shell 的波浪号展开，字面参数、外层 shell 的展开和绝对目标仍保留各自语义。

先剥离 heredoc 正文，再连接可执行命令中的续行。因此，引号定界符正文里的字面反斜杠不能吞掉结束标记或后面的可执行命令；定界符头部的续行仍在识别正文前连接。未引用定界符的正文保留自身的反斜杠换行处理，正文内引号保持字面含义。正文之外的续行仍在复合命令拆分前连接。source/dot、trap 和 parallel 执行入口不属于可静态授权的模型。

裸主目录重定向目标使用操作跟踪器相同的主目录。即使重定向符号紧贴目标，仍保留引号元数据；引号、转义和部分引号包围的波浪号前缀保持字面含义。不折叠父目录分量和恰好两个开头斜杠。

验收场景包括：

- 调用方选择、命令组、续行和注释要么产生完整可用的规则集，要么不提供建议；Bash 和 Monitor 遵循相同的覆盖约定。

- 等价的静态重定向写法保留 deny/ask 结果，引号内通配符字面量、`..` 和 allow 规则控制用例保持原有边界。
- 对 `cd /tmp && git >protected push origin main` 设置限制规则 `Bash(git>/tmp/protected push *)` 时要求确认，且不引用过时的 `/project/protected` 规则作为已命中的 deny。绝对目标、`cd` 之前的命令、无关命令，以及作为普通参数出现的目录命令名称，继续作为有效控制用例。

针对性测试位于 shell 命令语法、重定向规则、复合命令 cwd、shell 权限边界、restricted-shell-execution 及 shell-execution-context 套件中，并结合 `packages/core/src/` 下既有的权限管理器、规则解析器、规则建议、shell 工具函数和包装命令测试。
