# Shell 权限规则覆盖与重定向匹配

[English](2026-11-17-shell-permission-rule-coverage.md) | [简体中文](2026-11-17-shell-permission-rule-coverage.zh-CN.md)

## 问题与范围

PR #17372 的 R5 与 R6 修订使 shell 规则建议与权限管理器实际评估的调用保持一致。调用方选择的片段、AST 命令组、注释、包装命令及重定向写法，否则可能对应不同的可执行片段，产生无法生效的持久授权，或者让宽泛的 allow 规则掩盖限制规则。

本次变更覆盖 Bash 规则生成与匹配，包括 Monitor 使用的 shell 命令，保留现有权限优先级和持久规则格式。本修订已准备相关实现；下文的验证约定区分针对性检查与最终集成验收。

## 调用方选择与完整覆盖

建议生成器为每个命令同时保留 AST 源码范围和原始文本，并在定位范围之前一致地移除 Bash 续行。只有与 AST 命令组重叠的全部调用方片段均被选中，该组才具备生成建议的资格；组内的文本片段不会成为独立授权。

即使描述符关闭的结构性修复确定了片段范围，只要原始片段的解析有错，就不能发布派生规则，只可保留其字面量回退规则。这避免语法树凭空产生的命令成为单独授权。

生成候选规则并去重后，生成器使用权限管理器的命令分割器和规则匹配器检查完整的选中调用。必需片段来自该匹配器分割器，并与调用方选择重叠，因此 Bash 注释尾部不会单独成为覆盖要求。每个必需的可执行片段都必须被覆盖。任何片段不受支持或未被覆盖时，都不返回持久规则建议。这也避免 gate 提示展示一组保存后立即再次要求确认的 allow 规则。注释本身绝不生成执行授权。Monitor 继续保守地分割注释：包含注释的调用仍可能无法通过覆盖检查，返回 `[]`，并且没有 cron 提示。本修订不声称新增支持这些场景。

## 注释与执行包装

运算符扫描器只在已知未引用、未转义的空白边界或输入起始处移除注释。紧接展开、赋值或命令组的 `#` 会保守保留，不再依靠括号栈猜测词边界。遇到单引号外未转义的 `${` 后，该扫描器与替换检测器都保留剩余的全部注释文本，因为参数展开有独立的词法规则，可包含空格和井号。因此 `x=(a b)#c; eval ...` 及参数展开后缀不能隐藏后续可执行片段或命令替换。这类展开之前的普通注释保持原有行为。既有算术运算符处理保持不变。

权限守卫与虚拟操作跟踪器共享透明包装命令的解析逻辑。已知选项只消耗其定义要求的参数，剩余执行内容保留原有引号。对于 `/usr/bin/setsid`、`/usr/bin/sudo` 等路径，会识别已知外部可执行文件的 basename；`exec`、`command` 和 `builtin` 仍只作为内建命令名称处理。受支持的无值选项不会使普通命令变成不受支持的语法。不受支持的选项、`eval` 或 `xargs` 等未建模的执行形式，以及无法解析的重定向展开，仍需用户确认。普通参数中看起来像包装命令的文本仍作为数据处理。赋值前缀解析共享同一拼写规则，并把括号值保留为完整单词。跟踪器在遍历与守卫相同的前缀链之前移除续行。POSIX 函数定义、未建模 shell 的已识别 `-c` 形式（包括 dash、ksh 和 BusyBox sh/ash），以及 fish 的 `--command`/`--init-command` 形式需要确认；已支持的 Bash/sh 内容继续保留已跟踪写入的 deny 判定。这不声称能通用分析解释器脚本或任意可执行程序的副作用，普通 `git -c`、`gcc -c` 和带变量的 echo 参数仍作为控制用例。

## 限制规则的重定向等价关系

`staticShellCommand` 仅为 deny/ask 匹配提供语义视图。移除引号时保留字面量与通配符的区别，随后对重定向目标进行有限的词法归一化：

| 输入                                        | 处理方式                                         |
| ------------------------------------------- | ------------------------------------------------ |
| `/tmp//protected`、`/tmp/./protected`       | 与 `/tmp/protected` 等价                         |
| 已知调用 cwd 为 `/project` 时的 `protected` | 可与 `/project/protected` 比较                   |
| 调用 cwd 为 `/` 时的 `protected`            | 可与 `/protected` 比较，不会凭空形成 `//` 根路径 |
| 未提供绝对 cwd 时的相对目标                 | 保持相对路径                                     |
| `..` 分量及恰好以 `//` 开头的根路径         | 保留原样                                         |
| 引号内或转义的 `*`；未加引号的 glob 目标    | 保留字面量标记；未解析的 glob 不视为字面目标     |
| 开头未加引号的 `~`                          | 此辅助函数保持其未解析状态                       |

该视图不会调用 `realpath`、解析符号链接、折叠可能受符号链接影响的 `..`，或推测 cwd。引号内的波浪号仍是字面量。开头为通配符的模式保留既有覆盖范围。allow 匹配保持原有词法行为，新等价关系不会扩大已保存的授权。

## 复合命令中的工作目录

只有在可能改变目录的命令出现之前，调用 cwd 才是已知的。Bash 规则评估在 `cd`、`pushd`、`popd`、加载脚本代码，或无法识别命令位置的片段之后传递内部 `cwdUnknown` 标记。因此函数和带赋值前缀的目录变化不能继续把初始 cwd 视为已确定。命令位置分析复用现有分词器和静态视图；`echo "$X" cd` 中的参数不会改变 cwd。

cwd 未知时，限制规则匹配不会把后续相对重定向锚定到初始目录。可能适用的重定向限制即使遇到 `Bash(*)`，也会强制要求确认。规则相关性检查、强制确认标记和 deny 规则引用使用同一上下文：不确定的目标不会被表述为已确定命中的 deny，新增持久 allow 也不能覆盖此次确认要求。精确匹配或不依赖 cwd 的限制仍遵循正常优先级。

完整命令的虚拟操作跟踪器继续负责自身的目录跟踪。逐片段评估不会再次使用过时的初始 cwd 提取虚拟路径。这是一条保守边界，并非完整的目录状态引擎；即使 `cd` 的目标是字面量，后续相对 Bash 重定向限制仍可能要求确认。

## 验证与验收

重定向及复合命令 cwd 的针对性回归检查已在本地通过。最终验收仍要求对最终修订执行集成构建、类型检查、受影响测试，以及独立的权限管理器验证。权限探针只检查判定结果，不执行示例 shell 命令。

验收场景包括：

- 调用方选择、命令组、续行和注释要么产生完整可用的规则集，要么不提供建议；Bash 和 Monitor 遵循相同的覆盖约定。
- 展开与赋值后缀之后的 `#` 不会隐藏后续可执行文本。在单引号外出现未转义的参数展开之前，确定由空白分隔的注释仍按注释处理；此后的注释文本会保守保留。
- 受支持的包装选项保留普通命令行为；隐藏执行和未解析重定向不能继承宽泛 allow。
- 等价的静态重定向写法保留 deny/ask 结果，引号内通配符字面量、`..` 和 allow 规则控制用例保持原有边界。
- 对 `cd /tmp && git >protected push origin main` 设置限制规则 `Bash(git>/tmp/protected push *)` 时要求确认，且不引用过时的 `/project/protected` 规则作为已命中的 deny。绝对目标、`cd` 之前的命令、无关命令，以及作为普通参数出现的目录命令名称，继续作为有效控制用例。

针对性测试位于 `shell-command-syntax.test.ts`、`redirected-command-rules.test.ts`、`compound-redirect-cwd.test.ts`、`shell-permission-boundaries.test.ts`，以及 `packages/core/src/` 下既有的权限管理器、规则解析器、规则建议和包装命令测试套件中。
