# 有界的发布收尾流程

[English](2026-10-25-bounded-release-finalization.md) | [简体中文](2026-10-25-bounded-release-finalization.zh-CN.md)

## 问题与证据

v0.26.1 的 [finalize 运行](https://github.com/QwenLM/qwen-code/actions/runs/40108617400)处理了 156 个 PR。每批八项的串行请求多次触发 180 秒请求超时，耗尽了共享的 30 分钟模型预算。成功请求耗时 126–172 秒。脚本写出了回退说明，并跳过 highlights 和 themes；35 分钟 workflow 超时并未触发。日志没有输出 token 数，因此降低输出上限并不是经过验证的延迟修复。

随后创建的[发布 PR](https://github.com/QwenLM/qwen-code/pull/15468)还缺少 main 上更新 lint 门禁的提交。只检查分支 head 的 CI 正确拒绝了旧门禁；同步 main 后补齐了缺失的祖先提交。

## 范围与决策

摘要请求每轮最多并行三个。等待一轮完成后，按输入顺序校验结果。每轮大小不得超过连续失败限额的剩余数量，使第三次连续失败后停止后续请求，不额外发出请求。成功批次重置计数。保留逐项校验、双语回退、摘要顺序、共享 30 分钟截止时间、重试、请求超时和输出 token 上限。批次大小及失败限额必须为正整数，防止调度循环出现空轮次。

找到或创建发布 PR 后，先将 main 同步进其分支，再记录该 PR 可以进入自动审批。已经合并的 PR 在同步前退出。冲突或权限错误使任务失败；不强推、不自动解决冲突、不绕过保护。这会缩短门禁过期的时间窗口，但无法阻止同步之后 main 再发生变化。

发布 tag 和已发布产物保持不可变。本次改动不触发发布、不轮换凭据。第二次审批仍受到 [#14341](https://github.com/QwenLM/qwen-code/issues/14341) 中独立身份冲突问题的影响。Runner 迁移继续由 [#15465](https://github.com/QwenLM/qwen-code/issues/15465) 跟踪。

## 风险与限制

三个并发请求可能增加提供方限流压力；既有重试、退避和全局预算继续生效。每轮有意等待最慢请求，以保持确定的校验顺序和有界失败行为。这消除了不必要的串行等待，但不承诺生产耗时，也不保证提供方故障时能完成。

更新分支需要 PR token 具有仓库写权限。main 冲突仍是需要处理的发布维护问题。main 后续变化仍可能要求再次更新，已有审批是否失效由 GitHub 判断。

## 验证与验收

通过可控的模型响应证明摘要请求重叠、同时最多三个、完成顺序不会改变输出或失败处理，以及 digest 请求会等待全部摘要。验证失败会在配置阈值处停止实际请求，成功批次则重置失败计数。既有校验、重试、渲染和截止时间测试必须继续通过。

使用替身 GitHub CLI 执行 workflow 中的 PR 步骤，覆盖新建及已有开放 PR、已合并重跑和更新失败。验证更新发生在允许审批之前，失败时不会输出审批成功资格。运行相关 workflow 合约测试、格式和针对性 lint。本次是发布自动化改动，不改变 CLI/TUI/Web 运行时行为；实际发布和付费模型调用不属于本地验证范围。
