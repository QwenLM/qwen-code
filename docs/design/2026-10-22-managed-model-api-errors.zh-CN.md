# 托管模型 API 失败提示

[English](2026-10-22-managed-model-api-errors.md) | [简体中文](2026-10-22-managed-model-api-errors.zh-CN.md)

## 问题与范围

HTTP 402 等模型 API 响应会被格式化后写入 Harness 私有日志，但模型流抛出普通 Error 时丢失了结构化状态。终态日志只记录通用失败，Java 投影器出于安全考虑会丢弃任意错误消息，导致 Web Shell 无法解释失败原因或提供处理建议。

## 改动

在模型流边界保留具有类型的模型 API 错误，将结构化 HTTP 状态映射为固定失败码，区分支付、鉴权、访问权限、超时、限流、请求被拒绝、服务不可用，以及尚未分类的模型 API 失败。只有模型 API 错误获得这些失败码；取消、截止时间、存储失败及其他已有分类保留原有优先级。

首次执行与恢复执行均通过现有终态 stopReason 和 turn_error code 字段持久化分类。CLI 和 Java 只投影固定、可操作的英文消息，不公开供应商响应体、请求头、凭据、路径或任意异常文本。Web Shell 在摘要提示中翻译已知失败码，对未知码保留原有回退行为。仅供此页面使用的译文保留在页面模块中，避免导出的会话记录捆绑这些界面提示。不增加公开 schema 或存储迁移。

## 约束与验证

本改动不改变计费、凭据、模型选择、自动重试或终态语义。不重写已有通用失败事件，也不事后推测其分类；这些事件仍以私有日志为诊断来源。验证 HTTP 状态分类、持久化失败重放、恶意诊断内容下的安全消息、中英文摘要、未知码回退，以及取消和截止时间行为不变。运行相关 TypeScript 与 Java 检查，并以确定性模型端点验证构建后的本地部署，保留用户的现有会话。
