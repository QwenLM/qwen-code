# OpenTUI guided agent creation

[English](2026-11-13-opentui-guided-agent-creation.md) | [简体中文](2026-11-13-opentui-guided-agent-creation.zh-CN.md)

## Problem and current state

The preceding manual-stage native creator supports manual creation and read-only hot/cold details, with three scoped public profile passes. It intentionally offers only Manual Creation and uses the manual step map. Ink also offers Generate with Qwen Code, accepts a description, calls the existing subagent generator, and reviews the result before saving. That production path was missing in OpenTUI. This bounded guided implementation is now implemented and source-bundle verified; it does not convert the manual results into guided or complete Agent parity acceptance.

## Proposed behavior

Offer the existing Qwen and manual choices, with the same recommended Qwen default as Ink. Use the existing reducer and method-dependent six/eight-step map. The guided description uses the native line editor, paste handling, validation and Ctrl+C clear behavior. On explicit submit, sanitize the description with the existing helper and call the public leaf `subagentGenerator` with the actual Config and an AbortSignal. Blank input does not call the generator.

Only one generation may be pending. Show the existing generating message while suppressing further description submissions and edits. Escape during generation aborts that request, returns to the editable description and preserves its text. Subsequent Escape follows the normal back/cancel navigation. A successful current request populates only the generated name, description and system prompt, then moves to tools, canonical color and confirmation. No agent file exists until the user explicitly saves through the current owner-guarded manager path. Active failures remain visible with the description retained; a new request requires another explicit submit.

Keep an AbortController reference separate from the numeric owner-generation counter introduced by the manual ABA correction. Each request captures that owner generation and its initiating Config, step and method. A completion is current only while the dialog is alive, the owner generation and Config still match, the same controller is pending, its signal is not aborted, and the expected guided step/method remains active. Close, unmount or Config cleanup aborts and permanently invalidates the request. Returning A → B → the same A object must not restore its authority. Cancellation and stale success, catch and finally continuations cannot advance a form, paint an old error or clear a newer pending request. Clear a controller reference only when it still belongs to that request.

Retain the proven save-generation checks, pending-save latch-to-close policy, conflict check, explicit confirmation, canonical colors and read-only detail behavior. The generation request is not a disk commit and does not transfer save ownership. Do not replace the current epoch fix with the older worktree's reference-only Config guard.

## Existing contracts and affected files

The public generator accepts description, Config and AbortSignal. It uses the actual main model, requests the existing schema with required `name`, `description` and `systemPrompt`, and returns validated content. Current `runSideQuery` preserves the signal, owner's output-language preference and selected model before calling the BaseLlmClient JSON path. That path uses `respond_in_schema` and its existing provider/auth/retry behavior. The UI adds no retry layer, provider choice or Core API. Preserve current main's extracted output-language helper; do not copy older Core code from the mature worktree.

Production changes stay in `SubagentCreateDialog.tsx`. Extend its collocated tests and add only the necessary guided fixture branch and complete focused case to the existing interactive suite. Reuse the mature guided implementation and tests selectively, rather than replaying its full patch or replacing the manual owner fix. The current reducer, generator and fake HTTP server already provide the needed contracts. No manager editing/deletion, external editor or Agent execution change is required.

## Validation and acceptance

First dry-run the public guided plan against the actual globally installed Ink CLI without updating it. This validates the test plan on that distribution, not the final candidate. On the frozen manual-only native candidate, record the missing generation choice with actual frames, unchanged stores and no assumed later progress. Root alone executes these baselines and all later producers under its single heavy lease.

After implementation, run affected whole CLI files, normal build, typecheck, lint, formatting and bundle. Unit tests cover blank input, Enter bursts, explicit review before save, Escape abort, late success/error, old rejection while a newer request is pending, unmount, Config replacement including A → B → A, active errors, explicit retry and missing Config. Keep the existing manual eight-step tests and save ABA regression. Unit tests must assert observable signal, form, error and save authority; they do not prove native transport cancellation or disk state.

Reuse the complete `guided-creates-project-subagent-with-cancelled-generation` public case, including its 120-second case and 12-second observation limits. Require exactly two owned loopback model requests: the first is held, explicitly aborted, and its transport closes without a completed response; releasing it late cannot advance the form or change either agent store. The second returns the required schema fields. Require no pre-save file, exact canonical-blue Markdown after explicit save, unchanged user agents, matching hot/cold details and two natural exits with zero signals. Finally capture both raw agent stores before scratch cleanup, preserving the original behavior error if evidence capture also fails. This case is deliberately HTTP2, while the existing manual control remains HTTP0.

Run guided and unchanged complete manual controls under Node/Ink, Bun/Ink and strict Bun/OpenTUI on one newly built candidate. A source bundle pass is not installed-distribution or final merged-main acceptance. Keep all earlier failures and scoped manual results, and report the new results separately.

## Scope and open work

The increment closes guided creation wiring and cancellation only. It does not qualify model quality, a real external provider, user-level disk overwrite, manager editing/deletion, external editing, Agent execution/tool enforcement, other platforms, installed artifacts or complete migration parity. Existing runtime versions, renderer defaults, time budgets and Core trust semantics stay unchanged. No product decision blocks this proposal; baseline observations may correct test setup before implementation. Root completed both baselines before implementation. Global Ink reached both generation requests and cancellation, then failed exact Markdown because the retained file contained `color: Blue`; that old distribution was not updated. The manual-only native baseline reached the actual method screen with only Manual Creation and no model request, then failed the absent Qwen choice; its forced cleanup was not a public natural quit. Both original failures remain unchanged. The combined source bundle passed build, typecheck, lint and formatting, 116 affected unit tests, and six complete public cases: guided and manual creation on Node/Ink, Bun/Ink and strict Bun/OpenTUI. The cases completed twelve natural exits and six owned loopback model requests. These results qualify this local source bundle, not installed artifacts or final merged main.
