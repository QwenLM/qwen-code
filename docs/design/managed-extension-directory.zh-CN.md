# 部署管理扩展目录

[English](managed-extension-directory.md) | [简体中文](managed-extension-directory.zh-CN.md)

## 问题与范围

不可变镜像、共享安装和托管运行环境需要向多个用户及工作区提供相同的 Qwen Code
扩展。即使扩展包已经位于磁盘上，要求在每个用户 home 中执行安装或链接，仍会使
扩展发现依赖可变的逐用户初始化步骤。

可选的 `--managed-extensions <root>` 让 CLI 和 serve 直接加载这些包，也适用于全新的
用户 home。包内容由部署方管理，启用偏好和运行时状态仍写入用户存储。每个直接
子目录复用现有 `qwen-extension.json` 格式及贡献加载器，扩展作者无需维护第二套
包格式。

该选项在进程启动时选择一个集合根目录。不增加递归扫描、公开环境变量或 settings
入口、watcher、新包格式、商店、状态格式迁移或部署专用装配。

## 启动者授权

显式进程启动参数授权加载由部署方维护的来源，包括后续通过该来源交付的包和版本。个人使用时启动者就是用户；托管产品中，部署方将该来源作为 Agent 运行时的一部分提供。会话元数据、项目设置和项目环境文件不能选择或替换该来源。首版接口不新增公开环境变量，规范化后的启动值通过现有子进程启动参数显式传递。

Managed 表示包的管理归属，不表示由 Qwen 官方编写，也不代表执行隔离。宿主产品应说明提供方及定制属性。既有工作区信任、safe/bare mode 和工具权限各自保持原有控制；来源授权不代表每个 hook 或 MCP 启动都会经过工具调用确认。用户保留默认及工作区启用控制。授权模型与同名优先级仍是 issue [#12147](https://github.com/QwenLM/qwen-code/issues/12147) 中待审查的规则选择。

## 发现与状态

CLI 按启动 cwd 一次性解析绝对根目录。显式目录不存在、不是目录、不可读或本身是符号链接时报告配置
错误；空目录有效。被接受的根目录在启动时固定为其规范路径，之后重新链接无法移动各消费方已校验的边界。 根目录之后不可用或被重定向时，仍保留其配置以检查归属和状态目录隔离。 已固定路径的文件系统根本身离线时，隔离检查暂用解析后的字面路径；初始校验与 managed 读取仍要求可验证的在线目录。managed 发现和读取免确认权限都要求固定目录重新通过验证；验证失败不能作为已撤回的证明。根目录失去验证资格时，来源重新校验会使 managed 缓存失效，包括被链接到清单元数据未变化的包的情况。ExtensionManager 接收 `managedExtensionsDir`，与可写的
ExtensionStore 分离。容器沙箱（docker/podman）将解析后的根目录以只读方式挂载到翻译后的容器内路径、启动时的路径拼写，以及自动生成的读写祖先挂载暴露的每个别名路径（包括 `/home/node/.qwen` 下的别名）。这些受保护子目录之外的设置和运行状态仍可写。如果读写挂载源是 managed 根目录或其子路径，或者所需的只读目标路径或其任意子路径已被不兼容挂载占用，则沙箱启动失败；不会静默保留冲突的可写挂载。只读子树覆盖必须解析到对应的部署子树；managed 只读子挂载覆盖的可写祖先仍受支持。运维通过 `SANDBOX_FLAGS` 设置的高级覆盖不在这项自动生成挂载保护的范围内。沙箱原样转发该参数——原始 argv 的值位置可能承载用户内容，因此绝不改写 argv；子进程在启动校验时对参数值应用同样的容器路径翻译。bwrap 与 seatbelt 后端本身已对宿主机文件系统开放读取。拒绝与可写扩展/状态目录重叠（包括符号链接和文件系统大小写别名），保证只读边界。发现和名称查找共用解析逻辑：沿用既有名称校验，忽略大小写的
重复部署管理名称报错，部署管理优先于用户包并诊断遮蔽。先确定归属再判断启用状态，禁用部署管理
不会激活被遮蔽的用户包。单份无效 manifest 会保留其声明名（当 manifest 仍可解析出名字时），否则保留其目录名，并向 stderr 告警，使同名用户包无法静默顶替；当 manifest 无法读取时，保留范围仅覆盖目录名，因此部署方应以包名命名包目录。 daemon 目录查询只读 manifest，同时采用相同的来源优先级和身份。重复读取未变化的目录时，保留已有策略与存储 generation，不加载扩展贡献。

加载结果带有 `source`（`managed` 或 `user`）。部署管理身份根据规范化名称生成，不依赖
版本或部署路径。部署管理默认启用；显式启用状态和工作区偏好保存在用户状态层，版本更新
后继续生效；既有同名用户偏好通过存储层已有的名称迁移机制继承。workspace trust、safe mode、名称筛选（`-e/--extensions`）和工具审批
保持既有的、按贡献类型区分的行为。部署管理扩展不要求、也不跟随安装元数据。

部署管理包的 CLI User scope 启用/禁用修改存储中的默认启用状态，覆盖所有工作区，
包括用户 home 以外的工作区。显式部署管理 User scope 操作和管理 API 的默认启用状态
变更（包括批量操作）清除继承的旧路径规则，
避免旧规则悄悄覆盖当前操作；精确工作区覆盖规则保留既有优先级。存储默认值让用户
对部署托管包的显式选择在各工作区一致生效。用户安装扩展保留原有 home 路径范围
语义，以保持兼容性。

managed 范围切换和默认启用状态变更会在没有更早暂存时保留晚到的 legacy 路径规则。已有的 managed 之前的启用快照在交还时仍具有优先权，不被 managed 期间的写入替换。

启停变更会先对已配置的 managed 来源进行协调。确认撤回后，变更在交还完成后作用于返回的用户包。如果来源未配置、不可用或仍有歧义，使该用户副本继续保留 managed 归属，则以冲突明确拒绝变更，不再报告会被后续交还抹除的成功。这覆盖单项/批量默认启停、工作区启停、范围变更及技能 overrides。存储写入在锁内检查所选来源与当前归属是否一致；仍在部署的 managed 包继续只修改 managed 期间的启停状态，保留用户原有基线。

发现时将每份扩展的来源传给状态存储。现有 V2 policy 增加可选的 `managed: true` 标记，用于区分外部发现的包与安装器管理的文件，不迁移状态路径，也不改变状态版本。保留已有启用偏好和继承的安装记录。批量启停只对非 managed 策略检查用户安装文件是否缺失；正常运行时在确认撤回后重新发现用户包，或完成符合接管条件的安装/更新事务时清除该标记。仅有偏好声明的 managed 包被发现时，不虚构安装器 generation。这样旧用户副本移除后，批量及单项启停仍保持一致，无需等待后续刷新修复状态。

成功发现 managed 包时，还会记录它所在的直接子目录及实际出现过的精确名称拼写。没有适用清单的目录无法可靠归属：它可能是辅助目录，也可能是迁移到未观察过目录名的扩展。它不会占用发现名称，但会使所有保留 managed 策略的撤回都无法确认，因此自动交还、交还后的读取投影和销毁性释放都需等待目录被移除或完整清单发布。无清单的资源及 staging 目录也会产生相同的保守阻断。空集合仍能证明缺席；部署应在集合外暂存并发布完整包，因为本功能不会使部署变更具有原子性。显式释放在策略锁内、删除前重新加载当前部署证据，包括等待期间在同一目录重新出现的包。这收窄了锁前旧快照窗口，但不将外部部署与存储事务串行化。成功发现新目录中的包后更新关联；记录相对子目录名，因此集合根目录整体移动后仍有效。凭据探测与清理覆盖所有已记录拼写，包括中间的大小写变更，不改变既有凭据 service 名称格式。managed 归属尚未释放的记录不能改成大小写折叠后不同的名称，应先完成归属交还或释放。旧记录在下一次成功发现时补齐目录证据，并保留已知名称拼写；此前已经丢失的目录关联或历史拼写无法重建。

## 贡献与刷新

复用扩展 skills、subagents、hooks、MCP、context、commands 和既有运行时刷新链路。已有根目录
变量在内存中按实际扩展目录替换，包括过去在安装阶段改写的文本，不改写部署管理文件。
子代理 YAML 先解析，再递归替换结构化字符串值；替换后保留现有最终配置校验。
这样部署路径中的反斜杠和引号不会被 YAML 重新解释。
来源指纹覆盖部署管理 manifest 元数据及成员变化，沿用现有重新校验机制；显式全量刷新
重新读取贡献，包括仅内容变化、替换及移除。正文变化、禁用或移除（包括版本回滚）时，刷新使已加载 skill 的当前名称缓存失效；
未变化的正文继续沿用已有去重。历史会话记录和上下文统计保持完整。重复刷新不能重复注册
贡献；禁用或移除后按现有刷新语义撤销旧贡献。部署管理目录不加入用户扩展的文件 watcher；部署变化后使用显式刷新或重启。

## CLI、daemon 与 API

常规解析和 serve fast path 接收相同字符串参数，将同一绝对路径传入运行时创建。
每个 workspace 和 ACP 子进程的新建、加载/恢复、替换都通过现有启动配置和参数继承。
会话请求不能覆盖进程级目录选择。既有选定工作区管理和活跃会话协调机制负责刷新实际
Agent，不只刷新父进程缓存。既有 channel worker 和独立 channel ACP 启动链路
也传递同一目录，不改变 channel 生命周期或刷新行为。`-e/--extensions` 保持普通 CLI
的名称筛选语义，serve 不新增独立筛选选项。

管理 CLI、daemon 状态和既有扩展 UI 显示来源及 manifest 版本。API 增加可选的
`extensionSource` 判别字段，保留已有表示 URL 的 `source`。`extensionSource` 描述条目
所表示包的来源，不表示保留的 managed 策略或变更许可；该策略保留期间，即使是 `user`
条目也可能以 `extension_managed_read_only` 拒绝变更。核心操作拒绝部署管理卸载、
更新和替换，不依赖权限或 UI。update-all 清楚报告跳过部署管理并继续更新用户包。配置及
启用状态只写用户状态。Web UI 隐藏部署管理包路径及不支持的包管理菜单，context 文件
显示相对名称；保留启用/禁用控件。CLI/API 继续保留路径供诊断。

## 风险与后续

目录列表、文件读取和图片缩放在权限检查及文件系统访问前规范化已验证的绝对路径。两个阶段使用同一规范化路径，避免符号链接后跟 `..` 时检查一个目标却访问另一个目标。已存在的符号链接目标由文件系统解析，保留链接目标内部的实际遍历语义。managed 根目录本身不会为解析到其外部的链接授予读取豁免。

部署管理优先确保出现同名用户包时，仍由部署方选定的包提供实现。遮蔽警告让冲突可见；
禁用部署管理包不会切换到另一份实现。需要同时使用两份包时，应为它们使用不同的名称。

按名称保持身份，使启用偏好在包升级或根目录移动后仍然有效。这也意味着另一份包
如果复用相同名称，就会继承已有偏好。部署方应保持名称稳定，避免将旧名称用于无关
扩展。

managed 包从来源中撤除后，若没有已安装的用户包，显式安装同名用户包可以接管保留的启用状态和资源偏好。安装提交前会再次检查 managed 来源，预先准备的安装也不例外；不能把过滤后的发现结果当作来源已撤除的证据。存储层原子地把策略转移到用户身份，并移除 managed 标记。原先已安装而被遮蔽的用户包按正常发现流程恢复。自动交还后，恢复的用户声明在尚无包文件时，后续安装仍可保留 managed 之前的启用偏好；该资格在交还时恢复，而非在首次 managed 接管时获得。显式释放仅在没有已知的同名用户归属（包括保留的用户策略或缓存中的用户包）时，清理所有已记录拼写的 settings-only 目录及名称偏好。即时清单检查覆盖非标准子目录；用户包有歧义或列表不可读时，保守保留共享设置及偏好。过期的 managed 身份不能卸载替换后的用户包。 如果排队操作中的刷新将策略迁移到用户身份，卸载旧 ID 会报告冲突或保留 managed 归属时的拒绝，不会误报移除成功。 若安装目标仅为配置目录，且为空或只包含普通 `.env` 文件，则可接管；保留已有值，显式准备的新值优先。未知内容、符号链接、既有包和秘密 selector 元数据仍视为冲突；提交失败时恢复原目录和策略。

**建议决策——等待维护者确认（R3-1）：** 保留当前已实现的默认行为：managed 包撤回后，用户显式安装同名包时继承保留的偏好，无需额外 opt-in。符合条件的安装继承 managed 期间的默认/工作区启用状态及各工作区 skill overrides，维持同名扩展的偏好连续性。同名包可能来自不同发布者；是否接受这种连续性，是需要维护者在[这条评审](https://github.com/QwenLM/qwen-code/pull/12183#pullrequestreview-5347007520)中明确选择的取舍。来源撤回仍须得到确认，探测到的存储凭据会阻止接管，上述仅含设置的目录规则仍适用。如果维护者希望单独确认偏好复用，则以显式 opt-in 作为另一方案。

部署撤回扩展包后，CLI 的扩展/MCP 只读列表、TUI 已安装/来源标签页加载、设置和商店查询、channel 发现、MCP reconnect 发现、transcript 回放，以及 daemon 的目录、扩展状态、技能及状态查询、传统及排队 V2 检查更新保留 managed 标记、暂存偏好和 managed 密钥。辅助 workspace MCP discovery 与临时 source-copy 初始化也保留归属和凭据；copy 操作仍持久化所请求的目标元数据，普通 daemon/session 初始化继续正常协调。这些读取过程（包括 MCP reconnect 初始化的临时 Config）不执行自动交还，查询视图使用用户包原有的启用与技能偏好，但不消耗暂存值；由显式释放操作或正常的运行时刷新完成该迁移，单纯打开页面不会删除凭据；修改某个扩展的设置也不会交还其他无关包。 写入工作区范围的敏感设置前，先在当前 Qwen home 下的私有非敏感元数据中记录扩展的精确名称、身份及写入进程的 cwd。每个 cwd 使用独立原子记录，不依赖策略生命周期，清理后也保留。索引目录参与 managed 来源与可写状态的隔离检查，自定义扩展存储目录时也不例外。密钥探测和清理共用记录路径、调用方传入路径及其真实文件系统路径的并集，因此之后在工作区 A 启动的进程无需 daemon 注册，也能找到 B 写入的凭据。已有凭据 service 名称不变。记录损坏或不可读时，凭据探测或清理调用失败；记录写入失败时不能存入新的工作区密钥。

旧版未建立记录且位置未知的工作区凭据，无法通过 keychain API 完整重建；已知工作区路径仍作为回退线索。记录覆盖使用同一 Qwen home 的写入方，不新增跨 home 的 keychain 命名空间隔离，也不将设置写入与归属转换串行化。缺少可选原生 keychain 模块时，文件后端仍正常工作。模块可加载而后端不可用时，探测不能证明凭据缺席，会阻止接管；显式清理先继续尝试其他后端及坐标，再沿既有 warning 路径报告未完成。归属转换后的清理仍为尽力而为；模块本身已不可加载时，无法检测历史原生值。记录保留位置，供之后显式探测或清理。

只读加载不会让部署变更具备原子性，也不新增 watcher。部署工具仍需负责发布完整
