# 设置与沙箱后续修复（#12417）

[English](2026-10-01-settings-sandbox-followups.md) | [简体中文](2026-10-01-settings-sandbox-followups.zh-CN.md)

## 问题与当前状态

PR #13119 已使设置替换具备原子性。剩余启动路径对损坏的 operator 设置报错不一致，布尔参数解析会丢失具名沙箱选择，而恢复元数据仍指向 User 设置，尽管现在只有 Workspace 设置可能恢复。沙箱命令等待背压，却可能在最后一次缓冲写入完成前退出。两种后端的 relay 都会提前读取共享普通文件 stdin，并可能在 payload 结束后继续阻塞于闲置命名 FIFO。

## 目标与范围

保留 operator 策略，提供可操作的拒绝信息，报告实际边界，并保持普通命令的输入输出语义。保留现有沙箱策略和原子发布算法。补充 BOM 重新加载、私有保存目录事件与失败、原生 Windows 替换的回归覆盖。这是缺陷修复，不增加沙箱配置接口。

## 设计

Operator 读取和解析失败使用现有致命配置错误契约（退出码 52）。入口只报告一次错误，不输出堆栈或参数帮助。修复说明指出原文件；User 保留副本不代表允许清空 operator 设置。Workspace 恢复保持独立，通过精确匹配的 Workspace 路径将元数据传递给重启流程和现有对话框。成功保留副本后，重置写入失败只警告并继续使用内存中的空 Workspace 设置；无法保留副本时仍拒绝启动，不清空原文件。再次复制前替换已有损坏副本，使只读原文件在连续启动时也能恢复。若副本与原文件解析为同一路径，先拒绝操作，避免原文件链接到副本时删除唯一字节。损坏恢复仅接受规范 Workspace 设置路径上的单链接普通文件；在修改原件或已有副本前拒绝软链接、硬链接和链接设置目录。有效的链接 JSON 仍可加载。通过不跟随链接的源描述符保留原始字节，以独占方式创建副本并保留原权限。重置时先以不截断方式打开并核验相同 inode，再截断写入；不重置替换后的文件。启动警告只报告保留副本，不声称重置成功。若退出/恢复无法覆盖原文件，只有原件与保留副本字节完全相同才视为已经恢复，不修改权限；字节不同或无法读取时保留副本并报告原始失败。快照和保留损坏文件的调用方仍遵守原有拒绝语义。

由 yargs 解析沙箱选项取值和子命令别名，将空值或 true/1 转为 true，将 false/0 转为 false；重复选择以最后一个值为准。默认命令与沙箱检查器共享同一取值转换，包括大小写规范化。会话沙箱选项不会静默地把子命令变成提示词。`--` 前统一使用具名选项语义。这会改变原有裸 `--sandbox <query>` 便捷写法：自动选择应使用 `--sandbox=true <query>` 或 `--sandbox -p <query>`，提示词中的字面选项文本使用 `-p "..."`。两个 SDK 将布尔沙箱选项序列化为 `--sandbox=true`，使追加的文本参数保持独立。`--` 会停止选项解析，但其后的 token 不会作为默认命令的提示词传递。沙箱检查器分别报告继承的 whole-CLI 标记与工具隔离。迁移检查规范化两个环境标记。将 npm 显示为未探测，并在模型提示中加入已准入的命令网络策略。

等待 stdout 和 stderr 写入完成，包括低于背压阈值的最后一次写入。执行取消不取消输出完成：SIGINT/SIGTERM 仍在退出 130/143 前等待已接受字节写完。每个输出流独立处理错误取消，因此 EPIPE 退出 141 时仍排空另一个有效流。保留下游错误处理器直到两路刷新均结束。

对普通文件和命名 FIFO，通过关闭 payload 写半部的私有 Unix stream socket 转发字节，不暴露宿主文件描述符。原生辅助程序监督后端：普通文件使用按位置读取，运行期间不改变共享偏移；子进程结束后，通过保留的 socket 读端非阻塞读取并统计实际剩余字节，再以已写字节减去剩余量推进共享偏移。不使用 `FIONREAD` 统计剩余量，因为原生部分读取验收已暴露该计账方式不准确。Payload 不能通过 `/dev/stdin` 或 `/proc/self/fd/0` 重开此 socket，也不能向自己的接收队列写回。应直接读取 fd 0；重开这些路径或依赖 FIFO 类型的工具可能需要适配。同时轮询非阻塞 FIFO 输入与子进程结束，闲置写端不会延长退出。直接继承的匿名管道、socket 和字符设备仍属于调用方显式授予的能力。关闭网络禁止新建普通 IP 连接，不撤销已有标准流能力。

## 约束与风险

只为继承 stdin 的启动解析可选输入辅助程序。捆绑辅助程序缺失或不可执行不会阻断 bwrap 探测和直接继承管道/TTY 的启动；没有桥接程序时，宿主文件类输入在执行前被拒绝。Landlock 的自定义路径同时用于两种辅助程序角色；接收宿主文件类输入的自定义辅助程序必须实现新增的内部 relay 模式。显式 `stdio-setup-failed` 记录证明后端 exec 前失败，执行后的 `stdio-failed` 仍为未知，除非已观察到 payload 退出；不得仅凭退出码 125 推断空 bwrap 状态。需要时两种后端 relay 使用输入辅助程序；其他 Linux 架构保留直接继承管道/TTY 的执行能力，但没有支持的辅助程序时拒绝宿主文件类 stdin；状态传输、payload 执行证明和取消行为必须保持不变。捆绑的 Linux x64 和 arm64 辅助程序必须用固定编译器可复现地构建。普通文件偏移统计针对操作系统描述符已消费的字节，不针对应用层解析器消费量。不支持多个并发读者共享 stdin 的偏移统计。不得隐式授予 linked worktree 外部 Git 元数据的写权限。后端探测成功说明已准入，不保证每种 TMPDIR 或环境设置下完整会话都可运行。

## 验证与验收

使用隔离的全局 CLI 作为基线，再用构建后的 CLI 重复交互、headless、MCP、serve 和 ACP 启动测试。要求只输出一次可操作拒绝、非零退出，损坏的 operator 文件不变。覆盖具名参数、别名、布尔参数、`--` 停止选项解析与显式提示词中的字面文本；BOM 重新加载与只读 Workspace 文件连续三次启动，包括保留副本的路径别名、原件或父目录的外部链接及重置前替换；正常退出及 SIGINT/SIGTERM 后真实慢速管道中的 stdout/stderr 尾部字节；另一路仍有效时的下游关闭；普通文件零读取与部分读取；FIFO 的私有 socket 类型和写端仍打开时退出；Linux 写重开被拒绝且退出码与偏移保持；已连接描述符继承；原生 Windows 共享冲突时原文件保留。Linux 内核边界测试与假后端传输测试分开执行。必须完成构建、类型检查、定向单测、独立验证和评审。平台测试只有在对应平台执行后才算已验证。

原生 CI 还使用 runner 自身 UID 运行 public CLI 验证矩阵和普通 shell 工具调用。原生 CLI 测试脚本是长期回归资产；手动 POSIX smoke 模式提供未隔离的假 provider 对照。本地假模型端点驱动真实 agent/工具循环；它不证明已认证 provider 或完整会话可运行。原生 Windows 发布测试独立执行，避免无关全量测试失败遮蔽结果。

在后端探测前创建宿主验证 fixture，使不可用 TMPDIR 明确报告宿主原路径和修复动作，不暗示已测试沙箱边界。准入或验证失败后清理该 fixture。仅检查策略和显式执行命令时不创建验证 fixture。
