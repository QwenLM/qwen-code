# 无界面模式的使用统计提示

[English](2026-11-12-headless-usage-statistics-notice.md) | [简体中文](2026-11-12-headless-usage-statistics-notice.zh-CN.md)

## 问题

使用统计默认开启。交互式会话通过认证对话框中链接的隐私声明进行披露，但无界面的 `qwen -p` 运行不渲染任何对话框，因此会在没有任何披露的情况下上传使用统计。CLI 的任何输出都没有给出收集端点的主机名。该缺口已在 #17052 中确认。

## 决策

在无界面运行开始时、紧接会话初始化系统消息之后，显示一次性提示：给出使用统计主机名（`USAGE_STATS_HOSTNAME`，现由 core 遥测常量共享）、说明不收集提示词、代码和文件内容、给出环境变量和设置两种退出方式、指出退出同时会停止 models.dev 目录刷新，并链接到隐私声明。

沿用现有的无界面提示约定：文本模式下将提示写入 stderr，使 stdout 对脚本保持干净；JSON 与 stream-JSON 模式下发出子类型为 `usage_statistics_notice`、带 `data.notice` 的系统消息。若在 JSON 模式下跳过，最需要披露的自动化运行反而看不到；忽略未知系统子类型的消费者不受影响。

仅向依赖默认值的用户显示：使用统计已关闭，或 `QWEN_USAGE_STATISTICS_ENABLED` 或 `privacy.usageStatisticsEnabled` 被设置为任意值时跳过，因为显式开启本身已是知情选择。在安装 ID 旁的 `~/.qwen/usage-statistics-notice-shown` 记录已显示。标记文件无法读取或写入时绝不抑制提示，下次运行会再次显示。同一进程内最多显示一次，因此运行多轮的持久 stream-JSON 会话不会重复显示。

## 范围与风险

该提示仅用于披露，不征求同意，也不改变收集内容。models.dev 刷新在配置初始化期间启动，略早于提示输出；使用统计会被缓冲，按间隔或在退出时上传，晚于提示。交互模式不变。主目录为空的临时环境每次运行都会看到提示，这是预期行为，因为每次都是全新安装。与其他无界面 stderr 提示一样，文本仅提供英文。

## 验证

单元测试覆盖：仅显示一次并写入标记、同进程仅显示一次、使用统计关闭或通过环境变量或设置显式配置时跳过，以及标记无法写入时再次显示。无界面测试覆盖：文本模式输出到 stderr，以及 JSON 与 stream-JSON 模式下在 `init` 之后发出 `usage_statistics_notice` 系统消息。
