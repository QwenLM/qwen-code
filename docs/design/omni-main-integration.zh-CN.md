# 将 Omni 实验集成到 main

[English](./omni-main-integration.md)

## 范围

通过 `lazzy/omni-main-integration` 将已经完成的 `omni-experiment` 功能集成到
当前 main。实验源版本为 `a7ab939cc3624c1dfc1629015e0af50ec77ab4b5`，初始 main
基线为 `eb3bcc62f1afd3438f42d1d05679d6f5084720f4`。

功能包括媒体识别与上传投递、处理策略及工具、媒体记忆与召回、存储治理，以及
独立的上传和推理配置。已有实验设计定义这些行为；本次工作将实现适配到 main
的当前入口，不重新设计功能。

## 集成决策

- 从实验分支建立集成分支，将 main 合入其中。在保留实验新增内容的同时，保留
  main 的包版本、依赖、运行时归属和公共兼容导出。
- 将媒体超限恢复迁入实际使用的 `LlmChat` 实现。`geminiChat.ts` 保持 main 的
  兼容导出，不产生第二套运行时。
- 将查询准备与取消状态适配到 `use-llm-stream.ts`，保留 main 当前的 ACP、工具
  调度、会话记录和 UI 契约。
- 在工具预热后归一化处理策略，覆盖临时工作区激活路径。通过 Config 延迟加载
  媒体读取器，保持 utils 层的依赖边界。
- 将媒体策略可见性和执行来源校验适配到 CodeModeOnly。外层 exec 保留上传媒体、
  标注及工具输出，覆盖 hook 追加上下文与后续脚本失败。导出时从当前转录分支
  提取嵌套工具结果的执行 ID，不伪造模型发出的调用；识别 Omni 召回记录类型。
- 保持 `omni.enabled` 默认关闭，保留现有环境变量启用方式和 bare-mode 覆盖。
- 保留已经接受的全局 250 张图片上限和音频请求格式扩展。现有用户没有启用过
  Omni 的历史会话，失效 Omni 媒体的重试行为不在本次集成范围内。
- 为实验新增的测试依赖更新两份锁文件，保留各消费方需要的包导出和源码别名。

## 验证

前期评估已经通过隔离的 loopback 控制测试执行全局 CLI 和精确实验版本。对
集成后的 bundle 扩展测试计划：普通文本、文件读写、工具续接、普通会话恢复和
Omni 开启时的投递链路。使用本地协议替身确定性验证上传、推理及凭据分离，
将这些结果与真实 provider 验证分别报告。

执行 build、typecheck、bundle、两份锁文件与启动导入检查，以及 core、CLI 和
媒体相关的定向测试。在 main 的实际入口验证冲突适配。提交这一个面向 main
的 PR 前，完成连续两轮无发现的自审及代码审查。

## 边界

本次集成不默认启用 Omni，不新增 provider 策略、重新设计存储或另开功能 PR。
创建 PR 的授权不包含合并 PR 或开启 auto-merge。当前没有待定的设计决策。
