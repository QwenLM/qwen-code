# Shell 进程组取消

[English](posix-shell-cancellation.md) | [简体中文](posix-shell-cancellation.zh-CN.md)

状态：已实现并通过 Linux 回归验证。关联 issue：#13441。

## 问题与范围

普通 Linux Shell 的组长可能在组 SIGTERM 后退出，而后代忽略该信号。
此前组长退出会阻止升级信号，并移除清理所有权。这影响 child-process
和 PTY 执行。修复仅限于这两条路径的 Linux 进程组清理；Windows 和其他
POSIX 路径保留现有行为。Managed runtime 清理不在本次修改范围内。

## 所有权与身份

发信号授权要求 `/proc` 是可信的内核视图，且属于调用者的 PID 命名空间。
发现 `/proc` 使用非 proc 挂载时，即使记录看似匹配也拒绝信号。挂载检查不
认证未知过滤、子挂载或命名空间不匹配；这些配置不受支持。

在 spawn 后立即记录原组长的 Linux boot/start 身份。在 TERM 前，只有原有
身份仍匹配该组与会话时才记录组成员。每次破坏性信号前要求已记录成员
身份保持一致；只有连续性仍成立时才接纳新成员。僵尸进程身份可以证明
连续性，但僵尸不属于仍在运行的存活成员。PGID 无效或没有可读且未改变的
已记录身份时，拒绝破坏性信号。不可读记录不提供发信号权限；另一个正向
匹配的记录仍可授权自有进程组。ESRCH 永久结束所有权。权限错误不证明进程已终止。

这些检查认证观测到的进程组，而不只依据数值 PGID。进程枚举和身份检查
到发信号之间的操作并非原子操作；新成员出现和检查到发信号之间的竞态
仍然存在。进程元数据读取失败会限制终止确认，但进程消失产生的 ENOENT
除外。旧身份仍锚定进程组时，仍可记录可读的成员。

清理确认要求 `/proc` 提供调用者 PID 命名空间的普通、未过滤视图。每次检查
读取 `/proc/self/mountinfo`，要求 `/proc` 上只有一个 procfs 根挂载，且
`hidepid` 缺省、为 `0` 或 `off`。其他模式即使存在 `gid` 豁免，以及挂载
元数据不可读、缺失或有歧义，均会阻止通过枚举确认终止；当前所有权正向
认证成功时，它们不会阻止 TERM 或 KILL。确认时限结束时可见性仍不完整，
返回清理未确认的诊断；不能仅因可见成员停止就报告清理成功。终止性的组
ESRCH 不依赖此视图。可见性检查不认证枚举完整性。PID 子挂载、其他过滤、
命名空间不匹配及并发挂载变更不受支持。僵尸见证旁一个未记录的运行成员被
静默省略时，仍可能产生错误的成功结果。不能保证受限 `/proc` 总会保守拒绝。
参见 [Linux procfs 挂载语义](https://docs.kernel.org/filesystems/proc.html#mount-options)。

转移到其他组或会话的进程不在此修复范围内。其他 POSIX 系统需要更强的身份
来源，才能启用这条受保护的清理路径。

## 取消与结果结算

在 TERM 前公布唯一的完成 promise。组长退出后保留所有权，使用 200 ms
宽限期 timer 预算，然后对仍有存活成员的已认证组最多发出一次 KILL。再用
200 ms timer 预算确认受支持视图中没有运行成员。两个时限均使用单调时钟，
不是严格的实际耗时上限；同步 `/proc` 扫描和调度可能超时，传输输出排空也
会增加延迟。清理不完整时通过既有结果的
`error` 字段返回；成功发出信号本身不等于终止已完成。
`aborted` 与该诊断保持独立。两种 TUI shell 处理器保留取消状态、取消标记和
诊断，与捕获的输出一起显示；写入 LLM history 的文本也包含这些信息。

同步 service/app-exit 清理消耗同一个 force 动作并取消宽限期升级。真正的
应用退出无法等待确认，但 KILL 发出是同步的。自然完成立即释放所有权；
后台提升不发信号，转移所有权。已释放的所有者和延迟 timer 不能再次对组
发信号。执行结果仍只结算一次。
PTY 取消在既有的 200 ms 输出排空 timer 预算内，结合输出屏障等待原生退出
信息。预算内未收到原生事件时，不可用的退出字段仍为 null；不增加额外
timer 预算，也不无限等待。
清理后保留现有输出排空屏障；组长仍存活时，在错误结果
结算前解除前台捕获。
清理结算待完成时 timer 保持引用；unref 可能让仅等待结果的调用者在确认前
退出。完整的同步扫描与见证重读仍是已披露的延迟取舍，未进行性能基准测试。
已复用共享 boot-id 读取器；registry 存活 helper 允许身份缺失，不提供发
信号所需的单次读取的严格进程组/会话身份。共享纯 stat parser 可另行考虑。

## 验证

确定性矩阵覆盖身份替换或不可读、无效 PGID、ESRCH、权限及其他错误，
以及 cancel/exit/force/timer 竞态。mock 挂载/可见性用例覆盖未记录的隐藏
存活成员、受限及有歧义的视图，以及 TERM 后的可见性变化。这些用例不等于
真实 `hidepid` 运行时验证；未改变挂载或凭据。真实 Linux child-process 和 PTY fixture
覆盖存活后代、无存活成员、重复清理、自然完成与后台提升，以及模拟受限
元数据下的已认证与缺失/被替换身份。进程真实接收信号；限制使用 mock。
处理器测试通过 Ink/OpenTUI 处理器路径覆盖携带清理诊断的取消显示、实际
LLM history 文本及普通错误对照。延迟 PTY callback 测试包括确定性 timer
与真实自有传输中的模拟 callback 延迟，不证明自然运行时出现该时长的延迟。
stat 格式错误和外来会话表测试模拟无效输入，不代表内核可产生同 PGID、
不同 session 的状态。工具测试固定既有的取消/超时优先级及 hint 抑制。
更广泛的 scheduler 和 sandbox 诊断投影不在本次修复范围内。fixture 具有
独立生存时间上限、身份检查的回收逻辑，以及专用 subreaper。
Windows 单元用例验证既有路径得以保留；这些测试不验证 macOS 运行时
行为或模型/provider 工作流。
