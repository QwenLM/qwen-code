# Managed Event Envelope (cross-node EventTransport v1)

[中文版](./2026-10-06-managed-event-envelope.zh-CN.md)

> **Status:** Contract shipped as schema + fixtures with a structural gate proving no TypeScript production consumer. Part of the cross-node EventTransport design (`2026-10-04-managed-agent-event-transport.*`) — the deferred MQ/Redis transport scope of #12380. The Java control plane mirrors it and, behind the default-off event-transport flag, produces and consumes it (MQ2b, MQ2c); MQ2c extended it with the `public_event` stream (see [Extension](#extension-the-public_event-stream-mq2c)).

## Problem

Every asynchronous capability on the Managed path is a durable resource plus a trigger intent, so a cross-node EventTransport distributes only committed facts — never Session truth, never a browser cursor, and an MQ offset is never recovery evidence. The shape every such fact travels in is the one contract all future transports must carry, whatever their vendor. Freezing it now pins the dedupe, ordering, and leak-guard semantics independent of the eventual transport, exactly as H0b pinned the Stage H record contract ahead of every slice that reads it.

## Decisions

1. **Committed facts only.** The envelope carries `tenantId`, `workspaceId`, `sessionId` (flattened from the row's `sessionKey`), a version (`v: 1`), `stream` (`authoritative_journal`; MQ2c adds `public_event`, see the Extension section), `sequence` (starts at 1), `eventId`, `kind` (on the journal stream, the shared kind vocabulary mirrored exactly from the record contract — the mirrored list is fixture-pinned, so drift in any mirror fails loudly), `occurredAt`, and a `payloadRef.digest`, never the payload body, which stays in the SQL record. The digest is SHA-256 over the canonical JSON of the single announced event as a one-element list — the same canonical form the commit marker's transaction-wide `eventsDigest` uses, but not that marker value: the two are equal only for a single-event transaction, so a multi-event transaction stores no column equal to it. The receiver verifies the announced fact by recomputing the digest over the single event it reads back.
2. **Time.** `occurredAt` is the writer's recorder timestamp committed with the event — the original event's time, not a commit time, and not a Session order. Ordering per Session is decided within one stream by `(tenantId, sessionId, stream, sequence)`.
3. **Dedupe key is tenant-scoped.** Identity-dedupe is exact-key equality on `(tenantId, sessionId, stream, sequence)` — `stream` is the parent design's source discriminator (§6 of `2026-10-04-managed-agent-event-transport.md`): the journal commit sequence and the public `managed_agent_event.sequence_id` reuse the same numbers for different facts. As first frozen, v1 named only `authoritative_journal` and refused any other stream at parse time, so the key's `stream` term was vacuous; MQ2c admits `public_event` and pins the owed discriminating dedupe row, `same-sequence-different-stream`, so the term is now load-bearing (see the Extension section). A stream outside the vocabulary is still refused at parse time (fixture `stream-unknown`). A Session only ends identity inside its tenant (the journal head is keyed by `(tenant_id, session_id)`), so an identical session id under another tenant is another Session, and never redelivers (fixture `different-tenant-same-key` flips false to pin the boundary). Different surroundings with the same key still name one fact — and every dedupe row declares its operands' parseability, so a `false` always means refused-for-the-declared-reason rather than degraded past the comparison.
4. **No internal leaks.** A named forbidden-field set (`absolutePath`, `localPath`, `pid`, `pod`, `runtimeBindingId`, `runtimeEndpoint`, `secretHandle`, `sidecar`) is rejected by name before shape checks, each with a fixture; nothing in an envelope exposes Runtime internals, local paths, or credentials.
5. **Non-enablement by construction.** The contract adds no registry entry and is consumed by no TypeScript runtime path — the structural gate (a source scan asserting that no production file imports the module) is the proof an early transport cannot consume it quietly until its own phase lands. The scan walks every workspace package's `src/`, or the package tree when it has none (that is what covers `packages/web-shell/client`), plus the root `scripts/` and `integration-tests/` trees, skipping only `node_modules/`, `dist/`, symlinks and test files, and it matches import/export/dynamic-`import()`/`require()` specifiers through the TypeScript AST rather than raw text, so comments, strings and interpolated templates can neither mask nor forge an import; a workspace that disappears fails the gate instead of being skipped. Its blind spots stay named, not implied: re-exports, computed or interpolated specifiers, symlinks (never traversed, so a directory link hides its target), and languages outside the scanned extension set — the Java mirror, which the MQ2b and MQ2c transports run, is beyond this scan by construction.

## Extension: the `public_event` stream (MQ2c)

The MQ2c slice of [2026-10-12-managed-agent-event-transport-mq2](2026-10-12-managed-agent-event-transport-mq2.md) admits the second stream the dedupe key was built for. The extension is additive inside v1 (`v`, `contract` and `contractVersion` unchanged): every envelope valid before stays valid with the same meaning.

- **Vocabulary.** `streams` is `authoritative_journal`, `public_event`. The kind vocabulary is the stream's: the journal keeps the closed record vocabulary; a `public_event` kind is the public event type, an open set checked by shape — lowercase dot-separated segments, each starting with a letter, at most 128 characters (`managed_agent_event.event_type` and the public API both cap a type at 128). A journal envelope with a public type is still refused (fixture `journal-stream-public-kind`).
- **Row and digest.** A `public_event` envelope names one committed row of `managed_agent_event`: `sequence` is `sequence_id`, `kind` is `event_type`, `occurredAt` is `created_at`. `payloadRef.digest` is SHA-256 over the canonical JSON of the one-element list `[row]` — the journal derivation's canonical form — over nine fields (`tenantId`, `sessionId`, `sequence`, `eventId`, `turnId`, `type`, `data`, `terminal`, `createdAt`). Item/Part identity and the schema/projection versions are left out. A stream reconciliation rewrites rows in place — it empties a retracted delta's `data` as well — so the digest binds the row as published: a receiver that recomputes a different digest reads the row as changed since publication.
- **Workspace.** The public row carries no workspace, so `workspaceId` is the Session's binding — for an unbound Session, the workspace its journal records carry (the session store's configured workspace), so a Session's two streams name the same workspace. A Session with neither has no envelope identity and is not distributed; the scheduled SQL materialization pass covers it.
- **Dedupe.** The key's `stream` term is now load-bearing, and the owed discriminating row is pinned: `same-sequence-different-stream` (same tenant, Session and sequence on the two streams) compares false. The former refusal row `stream-public-event` is now valid, and `stream-unknown` keeps the closed-vocabulary refusal.
- **Enablement.** The TypeScript module still has no production consumer (the structural gate is unchanged); the Java control plane produces and consumes both streams, and its fixture consumer covers the new `fromPublicEventCases`.

## Record-of-pending-open (deliberately not frozen)

- `payloadRef` carries digest only; cross-version location references (a durable ref) are an open question for the design slice.
- Per-commit batch distribution (one notice per commit marker vs per event) is a sibling contract question, left open.

## Validation

- `npx vitest run src/managed-runtime/managed-event-envelope.test.ts` — 106/106, including: derivation-from-row cases with real digests; dedupe pairs (identical redelivery, differing surroundings, tenant boundary at false, unparseable operands) whose per-operand parseability is declared and asserted before each comparison, so a degraded row cannot pass silently; every forbidden field rejected; every kind of the 17 mirrored from the record contract in one valid envelope; accepting- and refusing-side rows at every declared limit (the `sequence` floor `sequence-one`/`sequence-zero` and safe-integer ceiling `sequence-at-max`/`sequence-max-safe`, the `occurredAt` ceiling `occurred-at-exactly-max`/`occurred-at-over-max`, and the stable-id ceiling in characters and UTF-8 bytes, `session-id-exactly-512-chars` and `session-id-exactly-512-bytes` against the four `*-over-512-bytes` rows), with the schema's `stableId.maxLength` and `occurredAt.maximum` literals pinned to `MANAGED_SESSION_LIMITS` in both directions; per-field UTF-16/NFC/byte-limit/control-character rows for all four id fields; the stream vocabulary pinned end to end (module constant, fixture `streams`, the schema's top-level `streams` const and the nested `envelope.properties.stream.enum`), with `public_event` refused at parse time — that refusal, not a dedupe row, is v1's journal-versus-public guarantee, and a discriminating dedupe row is owed when a second stream is admitted; the schema kind enum equal to the record's, not a superset; the literal idempotence key; deep-frozenness on both construction paths; the two-way schema-to-module agreement pin, with the beyond-schema rows named; the structural non-enablement scan.
