# 会话忙碌状态诊断

[English](session-busy-diagnostics.md) | [简体中文](session-busy-diagnostics.zh-CN.md)

## 问题与范围

`/branch`、`/fork` 和 `/cd` 在会话忙碌时返回相同的通用提示。没有新内容到达的
模型请求、上下文压缩、工具审批，以及尚未提交的工具结果，都可能让用户觉得会话
处于空闲。原始报告尚不能证明当时究竟是哪种活动阻塞了命令。

本次修改解释具体阻塞原因，保留现有的流状态保护，并在移动或复制会话前检查待处理
的斜杠命令。不增加 `/branch --why`，不改变压缩策略，也不修复尚未证实的工具生命周期卡死。

## 设计与理由

交互应用通过现有的 action 桥接向斜杠命令上下文提供实时原因读取函数。使用 ref
保持读取函数的新鲜度，避免每次流更新都重建命令上下文。函数在命令调用时读取当前
聊天的压缩活动，因为压缩的开始和结束可能不触发 React 更新。聊天统计正在执行的
压缩服务调用，每次调用结束时释放计数，包括失败和取消。这只是观测状态，不改变
压缩准入、历史、持久化或返回结果。

共享的 CLI 辅助函数依次报告待处理的上下文压缩、工具审批、子代理审批、具名工具的
执行/调度/验证状态，以及尚未提交给模型的具名工具结果。其余情况区分正在接收模型
内容和没有新内容到达的模型请求。待处理的斜杠命令有独立说明。没有读取函数的上下文
保留通用忙碌提示。每条拒绝信息都标明操作，并提供对应的等待、审批或取消建议。
提示只包含工具名称，不包含工具参数。

OpenTUI 的实时会话驱动通过稳定的 host 和命令上下文提供仅检查压缩的读取器。
OpenTUI 会在实时轮次中将这三个命令排队，因此工具和响应诊断在该路径中没有可达的
使用方。保留现有队列准入行为；真正派发的命令实时读取压缩和待处理的斜杠命令活动。
Ink 也会在实时轮次中推迟执行键入的这三个命令。完整的 action 执行时分类在命令边界
提供防御性诊断，包括子智能体审批；审批期间输入框隐藏。这些分类用例不能证明对应
状态下键入命令可以直接到达 action。两个渲染器都使用完整句子的翻译 key。
所有内置语言都翻译操作前缀和原因，由必译列表及占位符一致性检查保证覆盖。

涉及聊天压缩服务边界、交互应用、斜杠命令 action/context 桥接、三个命令的保护逻辑、
共享原因辅助函数、翻译，以及针对性的回归测试。

## 约束与风险

非交互上下文可以不提供原因读取函数。仅有后台代理运行不会阻塞这些命令。读取函数
不能保留过期的压缩标志，也不能把尚未提交的结果描述成工具仍在执行。
新增的待处理项目检查可在模型流空闲时阻止手动压缩过程中的会话切换。

压缩方法的核心调用方（自动发送前压缩、响应式恢复，以及通过 client 执行的手动压缩）
保持原有行为。新增活动查询接口的使用方是 Ink 和 OpenTUI 的原因读取器。

## 验证与验收

- 三个命令都说明传入的阻塞原因，并在修改会话或文件系统前返回；空闲路径保持可用。
- 分别覆盖审批、工具执行/调度/验证、未提交的成功/错误/取消结果、流式输出，以及没有
  新内容的请求。已提交的结果不会使会话继续忙碌。
- 手动压缩的待处理项目即使在流空闲时也会阻塞。自动压缩状态实时读取，并在服务成功
  或失败后清除。
- 运行相关 CLI/core 测试、构建、类型检查、lint/格式检查和打包。
- 重跑基线命令级复现并检查实际消息。完整交互复现依赖可用的 CLI/终端测试环境；
  PR 必须如实记录无法验证的层次。

## 待决问题

诊断范围没有待决问题。仅有后台压缩时是否允许会话切换，以及原报告是否涉及工具结果
卡死，仍需维护者和报告者另行调查。
