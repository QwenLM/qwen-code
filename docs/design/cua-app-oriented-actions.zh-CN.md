# 面向 App 的 Computer Use

[English](cua-app-oriented-actions.md) | [简体中文](cua-app-oriented-actions.zh-CN.md)

## 问题与证据

Computer Use facade 要求模型跟踪进程 ID、窗口 ID、不透明的元素令牌和输入投递模式。AX 文本重复包含令牌、边框和默认属性。即使使用 Node REPL，这些成本也仍然存在。

本次变更基于 PR #11683 的 `9ad582281de6d79350b255a63b7f7757e14ec11e`。独立参考包括用户提供的 Qoder Computer Use Dev.app（9999.0.0；运行时 SHA-256 为 `777e909734044f0b3de199e37ff4a680bbfb5800026553b1d4da8f9480a3da44`），以及 ChatGPT.app 26.901.51231、build 8109（`@oai/cua` 0.2.4 / `@oai/sky` 0.6.26）。包清单和提取的符号作为本地审计证据保留；参考二进制及提取的实现不包含在本 PR 中。

可读的 Codex JavaScript 将应用字符串绑定到简短的动作方法，AX 文本由其原生服务提供。提供的 Qoder 二进制包含应用解析、按应用管理快照、合成焦点处理和 AX 树变换实现。此前的基准轨迹独立确认了应用字符串定位、紧凑数字元素 ID 和运行时管理窗口变化。仅凭符号不能确定全部原生路由或裁剪条件。本次实现未复制专有实现。

## 深入审计后的原生对齐状态

2026-09-12 的原生审计固定使用 SkyComputerUseService 26.831.1000926，SHA-256 为 `25e9141499b94c396f39afbdb7b19ed8f49e45dc8c61be61028ceab8f3807ce6`。反汇编、元数据、调用点证据和自有文档探针保留在本地。PR 的 E2E 报告记录验证结果和限制。

已确认的原则包括规范化安装身份、按应用串行执行、focused/main/last AX 窗口选择、独立的打开菜单上下文、在生成修订输出前进行结构投影，以及原生语义或合成输入且不进行通用的前台重试。Qwen 使用现有驱动实现这些原则，并未复现全部 Codex 私有变换或其三个字段的合成焦点控制器。应用专用的日历和 attributed-text 变换仍未验证，不根据名称推断行为。

## 原生逆向后的实现

原生应用列表从实际运行应用的 bundle URL 获取规范化路径，并按路径对安装去重。facade 将解析后的路径同时作为缓存身份和刷新选择条件。已发现的已安装应用可以由 getState 通过现有后台启动器打开；动作不得重启已经终止的应用。

类型化窗口列表和观察输入中的可选 app-context 标记，将应用句柄连接到原生 AX 选择和紧凑采集。原生窗口选择读取 focused/main/last AX 窗口及附属 sheet，在返回前验证窗口的实际所有者。facade 使用该选择结果，不自行计算 z-index 策略。精确窗口调用方保留原有行为。App 上下文使用现有元素缓存、变更协调器和修订存储；通过新鲜的原生读取处理焦点、菜单变化及进程替换。

App 观察先采集结构树，再执行投影。投影保留可操作身份和描述性状态，删除空的冗余容器，合并安全的纯文本结构，并在普通窗口观察中仅包含菜单栏的直接入口。观察到的打开菜单成为菜单根节点，保留其后代及禁用状态说明。裁剪不得仅依据 enabled 状态。紧凑渲染及其修订序列与旧版完整树输出分开。对于未知的应用专用 Codex 变换，不根据名称猜测实现。

App 键盘动作使用原生后台焦点准备和 PID 投递。facade 不再根据缓存的能力或角色启发式选择模式，也不在拒绝后重试。原生代码根据当前目标事实选择语义输入或合成输入。缺少证明或效果未确认时，返回错误或 unverifiable 回执，不重放动作。显式使用前台模式的精确窗口调用方保留该选项。原生修复覆盖文本控件未声明支持的 press，以及未验证的文本写入和确认，避免已知的无效果与重复输入路径。

验证计划位于 `.qwen/e2e-tests/cua-native-alignment.md`：覆盖路径冲突和终止、堆叠顺序相反时的 AX 焦点选择、菜单和对话框上下文及过期 ID、full/diff/no-change、精确 Unicode 和标点输入，以及后台动作期间的前台归属采样。最终模型运行使用 MRKey GPT-6，并记录实际请求配置。本次不引入新的进程、传输或权限所有者。

## 运行时与归属

现有拓扑保持为 Node REPL → 独立 CU facade → 类型化原生 SDK → 现有平台驱动。不增加进程、可执行文件、网络服务、包安装或权限所有者。现有可信会话归属、目标检查和清理规则继续生效。

模型通过已发现的名称、应用标识或启动路径获取应用句柄。该句柄管理当前窗口、观察和短 ID 映射。公开工作流不再接受进程、窗口、令牌或输入模式选择。现有精确窗口 API 继续供程序化 SDK 调用方使用；模型使用的标准 Skill 改为 App API。

## 行为与范围

App 工作流在 macOS 上实现。现有精确窗口 API 保留各自的平台契约。可用时，应用身份使用规范化安装路径。名称和标识必须唯一解析；原始路径消失时，句柄不得转而使用另一份安装。getApp 只绑定身份。getState 可通过类型化 launch_app 方法启动已发现但未运行的应用，然后刷新进程身份。动作从不启动应用。进程、窗口所有者、窗口 ID 和连接变化均使旧 ID 失效。

AX 采集保留结构节点及有意义的 disabled/focused/selected 状态。投影删除不含描述的布局容器、已标注祖先下的冗余文本和纯文本兄弟节点重复，同时不丢弃任何可寻址节点。文本合并保留网页内容边界和辅助语义。原生 app-tree-v1 修订序列使用短 ID 渲染，省略不透明令牌、逐节点边框和默认属性。full/diff/no-change 选择仍使用原生身份和重放校验。旧版 full-tree-v1 游标独立维护。

App 点击和键盘输入使用原生后台路径。在投递前选择受支持的语义动作；对于不支持 Press 的控件，使用可写的文本焦点或精确指针目标处理。投递后发生错误不会触发另一种执行方式。AX 文本写入的读回结果未知或未变化时停止，不通过 Unicode 再发送。仅经过证明的完整插入才能确认文本；移除子串匹配和仅依据长度的部分后缀重试。保留 Unicode CGEvent 投递。

发送后台 PID 按键前，原生代码检查精确窗口，发送 AppKit 合成激活通知（type 13、subtype 1），等待通知被消费，再次检查目标。已经位于前台的目标跳过通知。该通知不调用真实应用激活或全局 HID 队列。这实现了已确认的“先激活准备、后输入”原则，没有引入 Codex 私有的 event-tap belief 缓存；不宣称该状态机完全相同。

App 拖拽携带内部 app-context 标记。投递前，原生驱动选择其支持的前台 HID 路径，仅抬起精确 AX 窗口，并在发送鼠标输入前检查拖拽起点的系统命中测试是否属于该窗口。仅进程位于前台不足以证明窗口顺序。守卫随后恢复先前的应用，不会先发送一次后台拖拽。这是 Qwen 的平台限制，不宣称复现了 Codex 的拖拽投递方式。

对于同一进程中的多个窗口，后台键盘投递要求新鲜的 AXFocusedWindow，以及带有 AXFocused 状态且祖先链匹配所选窗口的第一响应者。焦点准备后、PID 事件发送前再次执行该检查。语义菜单动作可以使用指向应用新鲜 AXMenuBar 的独立证明，同时确认目标是其焦点窗口；该证明不能授权指针或键盘投递。过期窗口、外部窗口、可见性及缺乏证明的元素检查继续生效。

## 影响组件与验证

变更覆盖 facade、类型化契约和生成绑定、macOS 应用及窗口解析、原生 AX 采集、投影和修订渲染、输入路径、标准 Skill、包内容及 0.20.6 发布元数据。运行时拓扑、授权归属和精确窗口的平台支持保持不变。

运行 SDK 测试和类型检查、相关原生测试和 core Skill 测试、build/typecheck/bundle、包验证及 `.qwen/e2e-tests/cua-native-alignment.md`。GUI 检查使用自有测试夹具，并通过独立 AX 和文件验证效果。最终 smoke 使用 MRKey GPT-6，记录实际请求参数和全部推理用量。字符数和一次 smoke 不能证明 20 个任务基准的整体收益。
