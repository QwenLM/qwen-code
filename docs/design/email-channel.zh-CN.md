# Email Channel

[English](email-channel.md) | [简体中文](email-channel.zh-CN.md)

## 问题与范围

Issue [#8281](https://github.com/QwenLM/qwen-code/issues/8281) 要求通过不绑定服务商的 IMAP 和 SMTP 接入专用 Agent 邮箱。main 尚无邮件适配器。本次增加内置的私有工作区包，复用 ChannelBase 的访问控制、会话、命令、附件和 Agent 桥接。OAuth、邮箱管理、日历及加密邮件、任意邮件撰写、HTML 输出不在范围内。

## 架构

`packages/channels/email` 负责配置、MIME 解析、状态和协议连接。CLI 注册器导入插件；包清单、TypeScript 引用及构建/测试前置项发现该包。CLI 启动、daemon worker 和 Web Shell 管理共用描述符。core 行为保持原状。ChannelBase 在队列入口及桥接调用前增加可选的执行检查，默认允许执行；Email 将该检查关联到连接生命周期，阻止停止后的排队任务启动 Agent。这样避免在适配器内复制现有会话队列。

连接时加载 ImapFlow、Nodemailer 和 MailParser。使用隐式 TLS 或强制 STARTTLS，并验证证书。现有顶层环境变量引用机制解析密码。关闭协议日志，以操作名称替换底层连接错误。管理界面与运行时复用配置校验规则。

## 接收与执行

以只读方式选择一个文件夹。首次持久化 UIDVALIDITY，并将 UID 游标设为 UIDNEXT 减一，从而跳过历史邮件。UIDVALIDITY 变化时建立新基线。搜索新的 UID，每轮获取不超过 100 封邮件，检查大小与邮件头，规范化唯一的 From 地址，并在解析正文及写入附件前经过现有发件人准入规则。拒绝有歧义的 From、自身邮箱、值不是 no 的 Auto-Submitted、列表/bulk/junk 邮件、空退信地址、投递报告及出站标记。From 白名单不能证明发件人身份：运营者需使用过滤伪造邮件的邮箱服务。

从纯文本或 HTML 提取文字，不获取远端资源。限制解码后的文本，裁剪常见引用和签名，并限制邮件大小、附件大小及数量。非图片文件保存在私有消息目录中的生成文件名下，处理结束后删除目录。图片使用现有 base64 附件流程。主题、正文及附件名均作为不可信用户输入。

Email 支持 followup 和 steer 分发；collect 缓冲消息的生命周期超出接收处理函数，因此拒绝该模式。接收流程启动有记录的 ChannelBase 任务，不等待 Agent 回合结束，因此权限回复能进入系统。最多允许 32 个普通任务运行或排队；额外保留一个槽位接收控制回复，并向超额任务发送繁忙提示。在内容进入桥接前，持久化处理声明并推进接收游标。停止后，排队任务会在调用桥接前被阻止；进入桥接的操作可能完成，并保留结果不确定的声明。处理完成且适配器仍在运行时移除声明；分发失败保留声明并停止接收。进程崩溃会留下结果不确定的声明：启动时拒绝重放或丢弃，显示 UID，由运营者检查副作用后在状态文件中确认。不承诺 Agent 或 SMTP 外部副作用的“恰好一次”。

## 状态与线程

使用权限受限的原子 JSON 状态文件及独占进程锁。路径由 Channel 名、规范化工作区及邮箱端点/用户/文件夹决定，不包含密钥。状态损坏或不可读时拒绝启动；文件不存在时建立基线。保存声明和回复元数据，不保存正文或凭据。近期消息标识与回复路由有数量上限；淘汰条目不会授权备用目标。

线程身份结合账号/工作区状态命名空间、规范化发件人及 References / In-Reply-To / Message-ID 根标识。已知回复标识映射回保存的路由。另一发件人不能通过复制邮件头进入默认情况下属于他人的会话。支持 allowlist、open 和 disabled 私聊策略，配对流程留待后续。默认 sessionScope 为 chat_thread；其他显式通用 scope 保留 ChannelBase 语义。邮件线程身份和接收进度跨重启保存。Agent 会话恢复由运行时负责：当前独立 Channel 冷启动不恢复保存的会话，daemon worker 则恢复路由。分别记录每封来信的回复上下文，避免并发来信改变当前响应的父邮件。

## 投递

Base 的每条发送路径经过适配器的目标校验。回复需要已知的发件人/线程上下文及当前仍获准的发件人。SMTP 收件人来自上下文，不来自 Reply-To、CC、BCC 或模型输出。设置 In-Reply-To、References、Auto-Submitted: auto-replied、X-Qwen-Code-Agent 和 Agent 显示名。抑制向 no-reply 邮箱的回复。后台工作结束时，复用现有后台回复入口，通过保存的会话目标找到已知且当前获准的发件人/线程；回复原线程不要求新增主动邮件的权限。

主动发送要求收件人精确匹配显式配置列表。带线程的目标还须存在已知路由；未知线程报错，不改为新邮件。不设置备用收件人。每次 SMTP 发送均有持久化 outboundPending 消息标识，主动发送也不例外。SMTP 错误不含凭据；发送结果不确定时不自动重试，主动投递错误标为 permanent。交互命令保留现有文本命令流程。

## 验证与验收

先验证全局 CLI 缺少该功能，再检查本地 bundle 配置，并通过本地 TLS IMAP/SMTP 夹具和可控 Agent 响应验证行为。测试覆盖初始跳过、新邮件处理、同线程续接、发件人隔离、正文暴露前的准入检查、HTML 及附件、畸形及超限邮件、循环头、收件人限制、凭据脱敏、重连、UIDVALIDITY 变化、重启、不确定声明、状态隔离和关闭。加入延迟任务及后续权限/命令回复，证明接收流程保持可用。执行 build、typecheck、bundle 及聚焦的包/注册器/构建配置测试。记录覆盖限制，不从本地夹具推断所有服务商兼容性。
