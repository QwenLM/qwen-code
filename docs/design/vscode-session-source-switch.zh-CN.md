# VS Code 统一会话历史

[English](./vscode-session-source-switch.md)

## 背景

用户应能在 VS Code 中直接打开终端创建的会话。#11584 引入的来源切换不符合这一要求：创建来源只是元数据，不是历史列表或编辑权限的分界。

## 决策

历史弹窗在同一列表中展示当前工作区的普通会话，包括 VS Code、终端、浏览器和未标记来源的旧会话。不提供来源标签页或来源标识，也不按来源限制重命名、删除。保留禁止删除当前打开会话的既有保护。

删除普通会话的影响会超出本客户端：daemon 会关闭该会话，并执行与任何删除相同的、经过归属校验的 worktree 清理。有未提交改动的 checkout 会被保留；否则 checkout 会被移除，其 worktree 分支仅在非强制的 `git branch -d` 接受时才删除——已合并的分支随 checkout 一并消失，尚未合并的提交则保留在分支上。

Companion 复用现有的工作区 organized 目录，查询未归档会话和所有分组，不携带来源过滤。它使用不透明、同时间戳安全的分页游标，无须修改 daemon 协议。列表排除子会话和已有明确标记的后台任务、频道会话。“加载更多”按钮确保整页均被过滤时仍能翻页。请求失败保留已显示的行和游标以供重试；目录被截断时显示历史不完整提示。

仅创建新会话时传入 VS Code 来源；恢复任何已有会话时均不传入，包括扩展重载后的恢复。宿主继续保存既有的字符串会话 ID，不再依赖来源旁路状态。已保存的来源状态不再读取，旧会话存储保持不变。统一查询已包含旧 daemon 会话，不再需要白名单。Bootstrap 会作废未完成的历史请求，并清空上一 runtime 的列表和游标。

## 范围

本次仅修改 VS Code companion，不修改共享 Web Shell、daemon 的归属和分页、Live 来源标记或终端行为。机器生成会话缺少来源标记属于独立的后端问题，界面无法可靠推断。

## 验证

- 无须选择来源，同一列表显示普通 VS Code、终端、浏览器和旧会话。
- 打开已有会话及宿主重载后的恢复均不传入新的来源归属；新建会话仍标记为 VS Code。
- 普通会话共享相同的行操作，保留当前会话的删除保护。
- 稀疏页面可以继续加载，失败后可以用原游标重试，历史不完整时有明确提示。
