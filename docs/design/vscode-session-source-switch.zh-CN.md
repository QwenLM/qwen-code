# VS Code 会话来源切换

[English](./vscode-session-source-switch.md)

## 背景

同一工作区的 VS Code、终端和浏览器会话都保存在 daemon 中。VS Code 默认只展示自身会话；#11495 增加的升级恢复路径也只恢复扩展曾记录的旧会话 ID。直接移除来源过滤会混入无关会话，并让重命名和删除超出 VS Code 的归属范围。

## 决策

历史会话弹窗继续默认展示 **VS Code** 来源，并新增显式的 **终端 / Web** 来源。两个视图都复用 daemon 现有的按来源查询；不发起无过滤目录请求，也不修改 daemon 或 core 的分页协议。

VS Code 视图保留 #11495 的旧会话白名单扫描。白名单内的未标记会话会从终端 / Web 视图排除，避免重复展示。终端 / Web 会话可以打开，但在当前界面只读：重命名和删除仍仅限 VS Code 视图。对于侧栏宿主，companion 会在现有字符串会话 ID 状态旁保存一份与该 ID 绑定的历史归属记录，因此重载或写入中断都不会破坏外部会话边界，同时保留降级兼容。打开终端 / Web 会话时，companion 不携带 VS Code 恢复归属，因而不会改写已持久化的来源。

切换来源时会替换当前列表、游标、搜索条件和错误状态。请求代次用于阻止上一来源的慢响应覆盖当前视图。

## 范围

本次是 VS Code companion 的界面改动，不改变 daemon 的会话归属、core 的目录分页、Live 会话标记，也不改变默认 Web Shell 和终端体验。

## 验证

- 弹窗默认展示 VS Code 会话，并继续包含白名单内的升级前会话。
- 切换到终端 / Web 后发送 `sourceType: default` 查询，并排除旧会话白名单。
- 较晚返回的 VS Code 响应不能覆盖已经选中的终端 / Web 页面。
- 终端 / Web 行不显示重命名或删除操作，打开后也不会被标记为 VS Code 来源。
