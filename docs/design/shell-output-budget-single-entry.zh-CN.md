# Shell 输出预算：每个正文只决策一次

[English](shell-output-budget-single-entry.md) | [简体中文](shell-output-budget-single-entry.zh-CN.md)

## 问题

Shell 输出在到达模型之前要穿过两条相互独立的大小策略，而在默认配置下二者并不一致。

工具自身按它声明的预算截断——默认 30,000 字符，或在显式配置了
`truncateToolOutputThreshold` 时按该值——并返回约 4,000 字符的头尾预览，
使结尾的退出码与错误摘要得以保留。

调度器随后再运行一道以*全局*阈值为键的通用持久化闸门：
`getTruncateToolOutputThreshold()`（默认 25,000）加 3,000 字符的余量，即约
28,000。该闸门只保留很短的一段头部。

由于通用闸门*低于*工具自己的预算，落在两者之间的输出实际由闸门而不是生产
者决定：

| 格式化正文       | 模型侧结果          |
| ---------------- | ------------------- |
| 至多约 28,000    | 完整输出            |
| 约 28,000–30,000 | 只剩短头部          |
| 超过 30,000      | 约 4,000 字符的头尾 |

因此，越过 28,000 字符反而*丢失*了越过 30,000 时仍能保留的结尾退出码与错误
摘要。这个窗口只在默认配置下存在：显式阈值会把闸门变成 `T + 3000`，始终高
于生产者预算 `T`。

同样的窗口也作用于失败路径。非零退出把处理后的正文作为 `error.message` 上
报，超时路径则把处理后的正文作为其明细传入，因此两者都会被这道保留不同文
本部分的闸门再次限界。

## 不变量

1. 一个正文只由一条策略决定大小。已经应用过自己声明预算的生产者不会再被
   通用闸门限界。生产者的定界覆盖整个装配后的正文：Shell 把它随后追加的
   有界元数据（长运行建议、AI 署名警告）从正文预算中预留出来，因此标记所
   担保的字符串正是调度器收到的字符串。
2. 标记记录的是“大小决策已做出”，而不是“确实发生了截断”。适合预算的输
   出同样携带它——这正是该窗口此前掩盖的情形。
3. 标记只在真正执行过该检查的路径上设置，绝不从工具身份或输出文本推断。
4. 持久化状态保持独立。`persistedOutputFiles` 维持其三态语义（`undefined`
   未做决定、`[]` 已决定但无可复用文件、非空数组为可复用路径），使聚合收尾
   仍能持久化生产者留在内存中的正文。
5. 标记本身不设任何边界。每工具预算仍然生效——成功路径上直接生效，超时
   路径上表现为按生产者声明的预算对明细重新限界——一同生效的还有聚合批
   量预算与发送边界的无 I/O 上限。针对追加元数据的合并 pass 只在成功路径
   上运行，因此追加到超时明细的失败 hook 上下文仅由这两道界约束。在普通失
   败路径上，该上下文按闸门阈值单独设上限。
6. 失败消息只有在*仍是*带标记正文本身时才被豁免。

## 设计

### 生产者标记

`ToolResult` 携带内部的 `outputBudgetApplied?: boolean`。它是供调度器消费
的运行时状态；不会序列化到 hooks、ACP 载荷、JSON 输出、遥测或持久化的 UI
元数据中，也不会复制到 `ToolCallResponseInfo` 上。

Shell 在其前台截断块的末尾设置它，在该块内无条件设置——包括输出适合预算、
没有发生任何截断的情形。提前返回的路径永远到不了它，因此显式的后台启动
不带标记，并保留通用闸门。

### 调度器

通用闸门对带标记的正文退让：

- 成功路径——闸门接收标记。紧随其后的每工具 pass 保持不变，成为唯一权威，
  使用工具自己的阈值与保留方向。
- 超时路径——闸门为明细正文接收标记；当生产者声明了预算时，明细会按该预
  算重新限界（仅按字符，与成功路径的每工具 pass 对齐），使标记之后追加的
  内容也保持有界；超时摘要与错误类型不受影响。
- 普通失败路径——只有当 `error.message` 在字节层面仍是带标记的
  `llmContent` 时才跳过闸门。单独构造 `error.message` 的生产者（如 spawn
  与 setup 失败）会改变该字符串，因此这些情形保留闸门。失败 hook 上下文只
  在闸门之后追加，因此不会重新触发闸门。

其余顺序不变。在成功路径上，hook 上下文与技能或规则提醒仍在正文限界之后
追加，合并 pass 仍按两倍预算限界装配后的字符串。两条失败分支都在正文限界
之后追加失败 hook 上下文。普通分支按闸门阈值单独为该上下文设上限，而不运行
合并 pass：对装配后的字符串重新限界会再次截断生产者的正文，而且它的
`error.message` 还会进入遥测与会话记录，而批量预算不约束这两处。超时分支让
`error.message` 保持为操作摘要，只把上下文追加到 response part，且不运行合
并 pass，因此在那里该上下文仅由聚合批量预算与发送边界上限约束。聚合批量收
尾仍在其后运行。

### 预算之外追加的元数据

Shell 在截断之后追加进程元数据——长运行建议与 AI 署名警告——刻意置于截
断封装之外。它们的合计大小从正文预算中预留，因此装配后的字符串仍适合声明
的预算，标记所担保的是最终字符串。预留量以声明预算的一半为上限：显式阈值低于约
两倍元数据大小时本就无从足额预留，而把整份预算花在预留上会让预览小到
留不住结尾的退出码行。每个追加的字符串也各自有界：普通失
败路径没有每工具 pass，而超时路径只按生产者预算对明细重新限界，因此两者
都不单独约束追加的元数据。建议是固定模板，署名警告的异常分支现在把异常文
本限制在 120 字符，与同一函数中的兄弟分支一致。完整文本保留在调试日志中。

### 结果

在默认配置下，不超过 Shell 预算的输出——减去 Shell 随后追加的有界进程元
数据——完整地到达模型；超过预算的输出保留现有的头尾预览及其持久化文件引
用。只保留头部的窗口不复存在。

## 非目标

退出码、信号与超时状态仍嵌入在格式化正文中，而不是作为独立字段传递，因此
后续的聚合缩减仍可能裁剪它们。把这些状态元数据与日志文本分离是下一步工
作，不在本次范围内。

本次改动也不增加按调用的大小或 token 遥测，不触碰聚合分配算法，也不为其
他预算高于通用闸门的工具（agent 32k、web-search 102k、MCP 500k）重新审视
同一窗口。
