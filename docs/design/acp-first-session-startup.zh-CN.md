# ACP 首会话启动

[English](acp-first-session-startup.md) | [简体中文](acp-first-session-startup.zh-CN.md)

## 问题与目标

在 watcher 修改前，ACP 子进程会在进入协议循环前启动 CLI 的递归 Extension 文件监听。其刷新状态由交互界面消费，而 ACP 不会启动该界面。因此，较大的 Extension 目录带来了没有 ACP 消费者的额外工作。

目标是先删除这部分工作，再优化剩余初始化，使首个新会话在不依赖通道预热的情况下于 500 ms 内完成。目标计时包含在会话请求中启动并初始化此前不存在的 ACP 子进程。另行报告 daemon 进程启动和首次 prompt 的开销；在必要初始化完成前返回会话不算达标。

## 方案与决策

对 `--acp` 和 `--experimental-acp` 均跳过交互式 Extension watcher 的创建。其他调用保留已有的安全模式、bare 模式和执行沙箱条件。保持设置热更新、SkillManager 订阅、Extension 解析、Hooks 及会话生命周期行为。

在当前 main 基线上测量剩余冷路径，确定开销及其消费者后才继续修改。必须保持会话标识、录制与 writer 所有权、认证、工作区信任、运行时覆盖、Hooks、工具和资源发现的正确性。不共享可变的会话 Config，也不隐藏初始化错误。

ACP Config 初始化还会在绑定会话执行引擎后启动已有的 ripgrep 健康检查，与资源加载重叠。原工具注册位置等待同一结果，保留后端选择和回退诊断。此优化仅用于启用 ripgrep 的本地 ACP 配置；Managed 执行、委托执行、Shell 沙箱和 bare 模式沿用原路径。安全模式保持原有 ripgrep 选择。

初始化拥有独立的取消控制器，并合并调用方与执行环境关闭信号。初始化结束时始终取消并排空探测，包括资源加载失败的情况。失败后的工具注册表重建仍重新执行普通检查，不跨 Config 缓存失败 Promise，也不让派生子 Agent 配置继承它。

实现涉及 CLI 启动入口、Core Config 初始化、ripgrep 健康检查辅助函数及其同目录测试。可选的注册表 Promise 仅由初始化传入；直接创建注册表的调用方保留原行为。

命令注册同步保留 attach 与导出命令的元数据，仅在执行 attach 时加载 daemon 客户端构造器，在选中有效会话后加载导出收集、归一化和格式化实现。attach 保留原有中止与退出期限，模块加载期间发生退出后不会继续连接；导出保留路径复验、文件权限和工作区制品。现有纯文件名工具仍同步可用。定时任务来源标识改用已有的独立导出，避免加载整个 ACP bridge。

读取每个 Qwen Extension 的 manifest 后，并行发现命令与上下文、Skill、agent 及 workflow，如外层持有 store 读锁，等四项读取全部结束后才释放；直接调用者不会因该 join 获得新锁。保留结果数组顺序、发现错误元数据和原拒绝优先级；不同资源类别的警告与文件读取可能交错，包括旧串行路径在前项失败后不会执行的读取。跨 Extension 的批处理与第二次完整扫描均保留。

### 按需注册 CLI 命令

本地命令注册实现保留现有 CLI 解析器和完整 ACP 启动链。基线配置模块即使选择默认 ACP 命令，也会导入 15 个顶层命令实现。注册元数据需要同步可用，但 builder、handler 及其子命令依赖仅在选中对应命令时才需要。无需另建 ACP 解析器或复制启动初始化器。

以一份纯注册元数据表作为原命令对象和按需注册的共同来源。保留真实命令语法、别名、描述和注册顺序；现有 `TOP_LEVEL_COMMANDS` 帮助展示表保持不变，因为展示标签不等同于解析器语法。原命令对象复用共享元数据。两个本地化特例显式保留原行为：auth 在构造其元数据对象时立即执行 `t(...)`，update 保留 `describe` getter。共享表可保存二者的英文消息 key，但不能通过展开已求值的 getter，把 update 的描述变成固定字符串。

注册层与原 auth 模块共享一个小型 auth 元数据叶模块，在延迟加载命令实现时保留早期翻译快照；仅导入纯表不会提前固定 auth 的语言。按需注册的 update 描述转发 getter，不复制其求值结果。

解析前，只要任一原始参数中出现命令名或别名，就保守加载对应的原命令对象；这也覆盖 `--_=update` 等 yargs 形式。选项值或路径中的假阳性只会多加载一个实现。其余命令注册元数据，由原有 yargs 解析器选择实际命令。选中命令保留原同步 builder 和 handler 引用、嵌套命令、选项、默认值、校验、中间件及等待 handler 完成的行为。默认命令 builder、严格解析、失败处理、弃用提示和参数后处理均沿用原路径。不新增配置开关或 ACP 专属参数解释；设置、认证、信任、能力处理、运行时初始化及会话就绪语义均保留。

当前安装的 yargs 接受异步 builder，但其后发生的校验错误可能绕过同步错误渲染路径；默认 completion 路径也会在调用 builder 后不等待其 Promise。普通解析保留同步 builder；任一 raw token 包含保留的 `get-yargs-completions` 标记时，提前加载全部原命令对象。假阳性只恢复现有提前加载行为，仍执行全部解析和校验。

修改范围限定为 CLI 注册、纯元数据表及原命令对象的少量元数据复用。不做 Core import sweep，不推迟业务工具首次使用的初始化，也不删除启动检查。最终同 main 组合源码现已测量，但结果不分离命令注册的贡献；静态可达性或字节数本身不能证明时间收益。

## 范围与约束

验收结果不得依赖预建业务会话、后台通道预热、空资源替代或关闭安全校验。进程冷启动测试可能命中文件系统页缓存；报告必须说明，不得描述为物理磁盘冷启动。外部模型和 MCP 延迟与本地初始化分别计量。

公开文档和性能证据不得包含凭证、用户或租户标识、内部域名、私有资源内容、内部制品地址或个人绝对路径。公开复现使用可重复生成的合成负载，私有负载仅发布聚合统计。

## 验证与验收

- 验证 ACP 不创建交互 watcher，且交互启动仍创建它。
- 对比基线的完整 Skill 行和菜单、外部文件变更、重载、会话隔离、认证和信任变更、运行时覆盖及退出行为。
- 基准显式关闭自动预热，证明计时首请求前通道不存在。计时包含子进程启动、ACP 初始化及新会话创建。
- 使用新进程和状态，多轮交错运行基线与候选。报告所有样本、中位数、最大值及样本量限制。诊断采样与验收计时分开。
- 提交 PR 前运行构建、类型检查、针对性单测、功能验证及连续两轮无发现的自审。
- 验证 attach 模块加载期间的中断仍以 130 退出且不建立连接，并保留四种导出格式、非法路径、无会话、文件权限及 ACP 制品行为。
- 实施命令按需注册前，保存原 15 个命令注册对象的快照，建立全局 CLI 命令/help/completion 及精确发布对照制品的基线。对照快照比较真实命令语法、别名、本地化和属性描述符，保留语言切换前后 auth 的立即翻译与 update 的 getter。
- 验证顶层和嵌套 help、completion、默认值、coerce、非法参数、弃用选项、handler 完成及退出和输出行为。覆盖选项缺值、`--_=command`、选项值中的保守名称匹配与保留 completion 标记假阳性，并保留现有 fast-help 与完整解析器的展示差异。
- 重建后检查实际 ACP 冷依赖图，再复测完整设置/认证/信任/会话/退出检查以及受控 SDK 与总耗时。不得复用旧 chunk 图的代码缓存，验收时不与无关性能修改混合。
- 完整性能目标要求首请求低于 500 ms 的验证证据；仅取得部分改善时必须标记为未完成。

## 状态与待解问题

watcher 修改已通过独立 PR #17177 合并。最终本地整合基于 main 6f754be6548903e545e6ff0ed43a34927fe3bfb9，包含保守初始化改动、[有界重复 YAML 解析](yaml-frontmatter-parse-cache.zh-CN.md)与 CLI 按需注册。测量快照的 25 个生产及 11 个测试文件通过构建、类型检查和打包；PR 随后仅修正另一份受管初始化测试的可选参数断言，生产文件不变。CLI 定向测试 1,110/1,110 通过；Core 为 2,090/2,091，唯一既有断言也在精确干净 main 上复现。独立功能 E2E 两侧各通过 59 项，并保留普通旧目录快照的时序差异。上述验证不替代正常 Core/maintainer 评审。

同 main 八对交错纯源码对照的完整首 SDK 中位数为 815.994 到 706.277 ms，均值为 833.257 到 719.861 ms。第 7 对候选更慢，仍保留；两侧均为 0/8 低于 500 ms。组合结果不能拆为各项源码贡献。[完整评估](../performance/acp-initialization-evaluation.zh-CN.md)保留所有行与独立历史队列，包括较早 799.173 到 723.808 ms 的组件实验及其 1,310.803 ms 观测，不能将这些结果与原 1,662 ms 观测或彼此拼成同一对照。

较早独立 YAML/缓存四条件队列保留原父参数且无 flush。其 installed-cache 条件中位数为 521.601 ms，四次中两次低于 500 ms，总耗时均值略高于对照；它不是最终整合或默认结果。更早 GC/flush、resolver 和 AOT 诊断也分别保留。

最终构建原生诊断在三个会话内观察到对照父/子进程 414/397 个生成 ESM 目标、候选 420/369 个。初始仅按全部 787 个候选 main-build 输出选择目标的无 trace 资格试验到达标准求值前链接屏障，并独立证明缓存写入；该试验没有 consumer 或运行时计时结论。后续独立八对已安装缓存/resolver 队列的候选首 SDK 中位数为 559.677 ms，低于 500 ms 为 0/8，其独立 producer/consumer 与原生消费证据见性能报告。安装与受管 launcher 集成仍未实施。源码候选尚未发布，不包含实验 resolver、已安装缓存或 launcher/GC 策略。完整 500 ms 目标尚未完成，本地 Node26.7 结果不验证下游 Node22.23.4 镜像或线上部署。
