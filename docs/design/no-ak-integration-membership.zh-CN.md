# 免 API Key 集成测试的成员检查

[English](no-ak-integration-membership.md) | [简体中文](no-ak-integration-membership.zh-CN.md)

状态：已实现

## 问题与范围

免 API Key 脚本与逐字节匹配的元测试可能彼此一致，却同时漏掉新增的集成测试。
文件存在检查也会接受被 Vitest 排除的路径，并且无法暴露一次匹配多个文件的子串
过滤器。Issue #14807 要求添加静态检查，不扩大限时 20 分钟的 CI 作业。

## 设计

在现有免 API Key 工作流约束测试中增加一个测试。直接读取集成测试的 Vitest
配置，通过已有 `glob` 依赖应用其中的 include/exclude 模式，再与
`git ls-files` 结果取交集，检查已跟踪的 `*.test.ts` 文件，包括暂存的新增文件。

解析脚本中的相对文件参数，排除 `--root` 的参数。按不区分大小写的子串语义
解析每个过滤器，每项必须匹配一个候选文件。唯一例外是
`./test-helper.test.ts`，其现有的两个匹配文件被显式固定，防止第三个 helper
文件悄悄加入。

其余每个候选文件都必须有逐文件列出的豁免及原因。真实模型测试需要凭据；其他
现有未登记测试暂时保留，待评估运行预算后再决定是否纳入。这不意味着所有暂缓
测试都很慢。比较完整的未登记集合，也会拒绝过期豁免，并要求在登记文件时删除
对应豁免。

## 约束与风险

保持原脚本、逐字节匹配、顺序及存在性检查不变。不新增依赖、配置、脚本或自动
登记机制，也不在检查内部启动 Vitest 子进程。不影响产品代码及运行时行为。
之后清单发生变化时，有意要求明确选择登记或豁免；本地未跟踪文件不属于基于
Git 的检查范围。

## 验证与验收

- 原始清单在 macOS 与 Docker Linux 上通过。
- 已跟踪但未登记的 `cli/zz-probe.test.ts` 导致失败，并显示文件名。
- 从两份清单同时删除 `cli/tool-hook-updated-input.test.ts` 导致失败。
- 把条目替换为被排除的 `hook-integration/hooks.test.ts` 导致失败。
- 新增意外的子串匹配导致失败，包括第三个 helper 匹配。
- 删除新增测试后，上述探针恢复原有的错误通过行为。
- 运行完整的免 API Key 约束测试，以及格式、lint、构建和类型检查。

## 待定问题

本检查没有待定问题。纳入现有豁免测试属于后续工作，需要评估凭据条件和作业的
运行预算。
