# 稳定的旧版记忆目录快照

[English](stable-memory-catalog-snapshots.md) | [简体中文](stable-memory-catalog-snapshots.zh-CN.md)

## 问题与范围

现有旧版目录是追加在请求尾部、仅供该请求使用的数据。#15020 在选择缓存断点时跳过
整个带目录的可变消息，保护缓存锚点。但未变化的目录仍会随每次请求移动，无法留在
可复用的对话前缀中。本次 #15027 后续工作将完整快照保留在聊天历史中，同时继续避免
将可变目录放入系统前缀（#11550）。不引入增量引擎、新配置或结构化记忆检索变更。

## 设计

`LlmChat` 在加入待处理用户消息及完成压缩之后、图像载荷替换和重新附加之前准备快照。
它将当前渲染的目录与历史中最后一个带有 `qwen-code:memory-catalog-snapshot` 标记的
存活部分比较。目录未变化时不追加，重试也不例外；目录变化时追加新的完整快照。因此
A → B → A 会产生三个快照，旧快照的内容和位置保持不变。快照明确声明替代之前所有
目录，包括已删除的条目。现有目录渲染器继续转义数据并限制大小，新增标题是固定的应用
文本，不是插入的目录指令。

最后一条用户内容接收复制后的 parts 数组，保留原始部分及图像身份。历史为空或以模型
消息结尾时，添加新的 user 角色内容。快照是持久内容，不携带仅用于请求的图像重附加
边界标记。可变目录绝不插入历史或系统提示词的头部。
单次调用 `GeminiClient.generateContent` 保留其有作用域限制的请求尾部行为。
快照先放入候选历史，只有图像与模态处理成功后才提交；初次请求中，这是输出长度限制
计算之后的最后一个准备步骤，因此准备失败不会产生持久快照。临时输出恢复控制消息
及其估算调用不能拥有保留快照：目录缺失或变化时，它们收到带可变边界标记的仅供请求
使用的完整快照，下次持久请求再保留它；目录未变化的恢复请求复用现有快照。
目录变化沿用现有配置刷新时机，不新增文件系统轮询。

待发送输入的 token 估算会在压缩门槛判断前、强制救援压缩后以及最终输出长度限制前，
计入缺失或已变化的快照。估算不会修改历史或记录快照；每个边界都会重新读取当前目录，
因此被压缩移除的快照也会重新计入预算。

`ChatRecordingService` 写入 subtype 为 `memory_catalog_snapshot` 的 `system`
记录，将完整的带标记部分放在 `message.parts` 中。普通用户记录不变。API 历史回放
采用同样的追加布局；新 subtype 已注册到转录解析器和 managed-session sink。
重试可能在仅追加的日志中留下重复且未变化的快照记录。回放只将每个快照与当前 API
历史中最新的带标记快照比较，文本相同时跳过。日志和父记录链保持不变，A → B → A
仍会保留，不对所有历史版本做全局去重。
压缩检查点本来就保留部分元数据。如果压缩移除最后一个带标记快照，回放会接受后续
记录的相同快照；如果下次请求时仍缺少快照，则重新追加当前完整快照。

`getAutoMemoryContext()` 为空表示禁止访问旧版目录（关闭记忆、结构化模式，或受限的
记忆维护配置）。请求历史和整理后的 `getHistoryShallow(true)`（包括压缩输入读取路径）仅过滤带
标记部分，不修改保留历史或普通用户文本。整理后的完整历史和尾部投影也会过滤这些部分，
避免 advisor 序列化转录或非缓存 follow-up 向模型发送时携带被禁用的目录。原始完整历史、尾部读取及默认或 false 的浅拷贝读取保留序列化、写回及索引契约。
`/summary` 会先从请求投影中移除历史快照，再仅在启用时附加当前目录。
recap 和标题旁路请求先从原始浅拷贝历史中移除带标记的目录快照，再应用各自已有的对话过滤，无论旧版记忆是否启用。这样保留消息边界和标题的 hook 上下文过滤，也避免目录标题进入展示元数据的输入。已记录的标题展示文本仍优先使用；保留历史和普通用户原文不变。子聊天已过滤缓存和 fork 请求，因此这些路径不额外过滤。
重新启用记忆后，仍与最新保留快照比较。

保留快照从被抑制变为可见时，之前的用量可能不包含它们，例如通过 `/cd` 从结构化记忆
切换到旧版工作区。采用任一路由计数前，清除当前及保留路由用量，本次转换改用已有的
完整历史估算。反向翻转（可见变为被抑制）则刻意保留权威计数：此时计数会比下一个请求
实际发送的内容多出被剥离的快照，偏差方向是更小的输出预算和更早的压缩，而不是溢出，
下一次 usage 报告会替换该计数；若改为丢弃计数，则会退回到遗漏整套系统提示词与工具
开销的历史遍历。估算开销余量与响应溢出恢复因此只作为少计方向的安全网。恢复计数采用
当前目录可见性：启用旧版记忆时保存的会话已计入可见快照，
因此恢复的权威计数继续可用。较少见的“保存时被抑制、恢复时启用”情况依靠估算开销余量
和响应溢出恢复，而不是丢弃所有恢复计数。显式的当前投影计数仍可使用；
普通历史写回不会使计数失效。这种有限回退会失去原先的权威前缀基准，仍沿用估算开销
余量和响应溢出恢复。正常启用状态下的发送继续使用权威累计计数。

AUTO 权限分类器在投影用户文本前始终排除带标记快照，即使记忆处于启用状态；内容相同
但没有标记的用户文本仍会保留。可信标记也将仅含快照的条目识别为结构上下文，包括在
响应溢出压缩以模型确认消息结束后重新注入的快照。这样的条目不会产生用户提示或占用
fork 窗口的用户轮次；混合真实用户提示和快照的条目仍算作用户轮次。已投递通知的分类也
忽略带标记快照，但仍要求存在通知封套且没有真实用户文本，从而保持 ACP 回退轮次正确。

快照记录归属于追加它的那个轮次的持久请求。通过消息组删除该轮次时，记录会随之移除，
因此恢复不会把已删除轮次的目录重新挂到更早的轮次上；当存活历史不再匹配当前目录时，
下一次持久请求会重新追加当前目录。压缩载荷中内嵌的快照仍属于该压缩历史，只由具备
压缩感知的删除路径裁剪。

上下文用量将请求中的所有带标记快照计入记忆 token 一次，并从对话 token 中排除。
单次请求目录的归类仍然受支持。UI 用户消息投影不会新增虚构的用户记录。

## 约束与风险

每份快照仍受现有渲染器的大小限制，但历史快照总量会随目录变化增长，直到常规压缩。
这不是全局记忆预算，也不是自动清理机制。未变化目录可改善前缀复用，但依旧占用上下文，
并且仍需发送给无状态提供商。缓存命中和延迟需要真实请求验证，仅靠历史表示不能保证。
记录写入沿用现有的尽力写入错误处理行为。

## 验证与验收

聚焦回归覆盖：未变化请求的稳定前缀、A → B → A、重试去重、复制后的图像部分身份、
仅按标记过滤、快照删除后重新注入、真实记录器/JSONL/完整与选择性恢复、压缩元数据
保留、managed 投影以及记忆 token 归类。还覆盖待发送快照预算、AUTO 分类器输入、实际
advisor 和非缓存 follow-up 输入，以及响应溢出后仅含快照的重新注入与用户/fork 轮次分类。
还覆盖原始浅拷贝索引和写回，以及实际 summary、recap 和标题请求。
现有单次请求辅助函数测试继续适用。真实运行时
目录测试必须使用当前有效的项目路径 `.qwen/memory`，不能误用 `.qwen/memories`。

在 `packages/core` 中运行：

```sh
npx vitest run src/memory/request-context.test.ts src/memory/prompt.test.ts src/core/llm-chat.test.ts src/core/client.test.ts src/permissions/classifier-transcript.test.ts src/services/session-transcript-reader.test.ts src/managed-runtime/managed-session-record-sink.test.ts src/core/loggingContentGenerator/context-usage-snapshot.test.ts src/services/sessionRecap.test.ts src/services/sessionTitle.test.ts
```

然后在 `packages/cli` 中运行：

```sh
npx vitest run src/ui/commands/summaryCommand.test.ts src/ui/commands/contextCommand.test.ts
```

构建、类型检查、格式检查以及独立的真实运行时请求/回放验证由外部协调。实现交接不代表
这些检查已通过。验收要求：历史前缀不变、重试不重复追加快照、回放布局一致、禁用时的
请求及压缩输入没有带标记快照、UI 用户消息不受污染、压缩后重新注入当前目录。
