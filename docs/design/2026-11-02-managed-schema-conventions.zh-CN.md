# Managed 数据库规约

[English](2026-11-02-managed-schema-conventions.md) | [简体中文](2026-11-02-managed-schema-conventions.zh-CN.md)

## 范围

按照《阿里巴巴 Java 开发手册（黄山版）》的 MySQL 规约整理共享的发布前 V1 数据库基线。
Server 和 Broker 必须继续在 MySQL 8.4 与 H2 上初始化和校验同一套数据库。
物理删除及保留期策略不在本次修改范围内。

参考来源为[官方黄山版手册](<https://github.com/alibaba/p3c/blob/6c59c8c36ecd8722c712d5685b8c3822c1c8b030/Java开发手册(黄山版).pdf>)
中印刷页码 32–35 页的 MySQL 章节。

## 决策

- 每张表增加无符号自增 `id` 主键。原业务主键保留为唯一约束。
  业务身份、租户范围、幂等及防止旧执行者写入的检查继续使用这些业务键。
- 沿用现有 `gmt_create`、`gmt_modified` 命名及所有毫秒时间字段。
  应用时钟、租约截止时间及有序分页依赖现有时间戳约定。不新增重复时间字段。
  数据库生成的行 ID 不进入领域投影和 CSI 证据。
- 布尔字段采用 `is_` 命名及无符号微整型。保留可空标志的可空性、派生标志的计算方式。
  同步调整 SQL 消费者和行数据的布尔解码；序列化 API 及日志载荷的字段名保持原样。
  用范围检查在两种数据库上保留 0/1 值域，避免 H2 对常量 `IN` 列表的优化依赖初始化连接。
- 非负计数、版本、代次、大小及序号使用无符号整数声明。
  MySQL 校验覆盖所有整数类型的符号属性。H2 忽略无符号存储范围，因此仍需真实 MySQL 验证。
- 普通索引使用 `idx_` 前缀，唯一约束使用 `uk_` 前缀。
  MySQL 始终将主键索引显示为 `PRIMARY`；DDL 在支持时为主键约束声明表内唯一的 `pk_` 名称。
- 移除数据库外键。现有应用准入、所有权及事务检查继续控制关联写入。
  保留原父子身份索引和业务唯一约束。
- 固定宽度 SHA-256 字符串使用 `CHAR`。多个命名空间存储不同摘要格式的共享回执和操作摘要列，
  继续使用变长类型。
- 短判别字符串保留完整索引：覆盖查询和有序查询需要完整值，截短会丢失信息。
  较长的主机身份查询使用有界前缀。通过 MySQL 可执行注释声明前缀，H2 使用对应完整列索引。

## 数据库校验

标准资源继续使用 V1。已有开发数据库需要重建，不引入修复、升级迁移或历史改写。
校验必须拒绝缺失的行 ID、错误的主键或业务唯一键、缺少自增行为、错误的整数类型或符号属性，
以及变化的索引前缀。继续拒绝旧版、不完整及包含其他业务对象的数据库。

## 验证与验收

- 在新建 H2 和临时 MySQL 8.4 数据库上验证 Broker、Flyway 初始化、重复校验、行 ID 生成行为。
- 验证重复业务身份仍被拒绝，标志值及可空性保持一致，代表性的 Server/Broker 存储仍能读写更名后的列。
- 检查快照和投影约定、结构偏移拒绝行为，以及相关队列、发布、调度、Workspace 和 Runtime 消费者。
- 在模块共享验证预算内运行针对性的本地 Maven 检查；将全量测试及原生进程验证缺口交给 CI 并明确记录。
