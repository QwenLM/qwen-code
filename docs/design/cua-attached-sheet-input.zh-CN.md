# 在精确窗口输入校验中识别附着窗口

[English](cua-attached-sheet-input.md) | [简体中文](cua-attached-sheet-input.zh-CN.md)

## 问题与范围

App 观察可以选中一个附着的 macOS 文件选择窗口，但其 CGWindowID 可能不在应用直接的
AXWindows 数组中。后台输入校验随后会以 `off_space_or_ax_unresolved` 拒绝这个已观察的
窗口。最初的 VLC 复现使用旧版 App 键盘和指针路径。当前 App 键盘、指针和粘贴操作
使用上游的激活路径；App 语义操作（`setValue`、`performSecondaryAction`、`selectText`）、
观察中的能力检查及程序化后台输入仍调用精确窗口校验，需要识别附着窗口的归属。

## 预期行为

保留已有直接窗口路径。仅当目标不在 AX 记录中时，对仍被持有的根窗口调用已有的
有界附着窗口发现。只有根窗口和附着窗口发现都完整、附着窗口自身 ID 可映射、根窗口也有映射记录时，
才加入记录。附着窗口随根窗口一起最小化，因此继承其最小化状态；未知状态仍为未知。
不重复已有记录。沿用上游窗口 ID 映射契约；附着窗口发现不另加几何推断规则。

WindowServer 所有权、元素归属、隐藏和最小化状态、键盘焦点与其他输入目标的检查
仍在相应路径中生效。投递方式继续由调用方选择，包括上游的 App 激活路径。
本修改不增加投递回退、重试或范围更大的应用级目标。
未映射或发现不完整的附着窗口仍被拒绝。已有直接目标不增加一次发现遍历。

## 验证与接受条件

测试已映射和未映射的附着关系、未知和已最小化的根窗口、重复记录，并保留已有的
同进程其他窗口键盘歧义检查。在不操作宿主桌面的前提下，构建并运行针对性的原生
单元测试。随后在独立的 guest Qwen MCP 会话中，通过 App 语义操作选择或修改观察到的
字段，确认结果属于目标附着窗口。程序化后台键盘输入需要单独验证投递。
后续基准测试保留失败尝试并记录时间和 token；早期 VLC 结果不能证明新版 App 路由的行为。
