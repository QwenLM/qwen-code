# 为打包启动分片建立索引

[English](2026-11-18-serve-chunk-resolution.md) | [简体中文](2026-11-18-serve-chunk-resolution.zh-CN.md)

## 问题

打包后的 daemon 及其第一个 ACP 子进程，启动期间需要解析大量生成的 ESM 分片之间的精确相对导入。把导入挪到监听之后可以提前监听，但工作区仍需等待大部分模块解析。

## 方案

打包版 serve 和 ACP 入口启动时，一次读取已安装分片目录中的常规 esbuild 分片。在支持同步解析钩子的 Node 上，为来自打包入口和已知分片的精确相对导入使用索引查找。返回相同的文件 URL，由 Node 加载并缓存模块。其他说明符、自定义加载器和未打包入口继续使用 Node 的常规解析器。

## 验证

从同一源码基线构建基线和候选，在弹内预发 Linux 沙箱使用同一 Node 可执行文件和单 CPU。使用新的 runtime、1 个主工作区和 6 个恢复登记工作区交替冷启动。测量 deep health 和目标根目录 stat，再创建一个会话并通过同一回环模型夹具发送首问。门槛为工作区就绪 P50 至少缩短 30%。核查首会话和首问 P50/P95、工作区归属、会话持久化和首次探针后的关闭取消。
