# Web Shell 繁体中文

[English](2026-11-16-web-shell-zh-tw.md) | [简体中文](2026-11-16-web-shell-zh-tw.zh-CN.md)

## 问题

CLI 已经有完整的 `zh-TW` 界面。Web Shell 没有。繁体中文设置或浏览器语言
（`zh-TW`、`zh-HK`、`zh-Hant`、`zh-MO`）在 Shell 里会停在英文，VS Code
配套外壳则把所有 `zh*` 都当成简体中文。

## 目标

- 选择 `zh-TW`，或用繁体中文区域设置打开 Shell 时，界面显示繁体中文。
- `zh` 和 `zh-CN` 仍然是简体中文。
- 导出的 HTML 不携带第二套完整中文词表。

## 非目标

- 不为 `de`、`ja`、`pt`、`fr`、`ca` 新增词表。
- 不重做 CLI 里已经手工维护的 `zh-TW` 词表。终端词表维持原样。
- 不改变模型输出语言。那是另一项设置。

## 方案

Web Shell 增加 `zh-TW` 词表。它由现有简体词表经 OpenCC（`cn` → `twp`）生成，
并套用 CLI 繁体词表已经在用的台湾用词修正（`伺服器`、`參數`、`週額度`、
`實例`、`系統`、`帳號`）。语言选择器显示为 `繁體中文 [zh-TW]`。保存时把
`general.language` 写成 `zh-TW`，CLI 已经接受这个值。

词表放在独立模块。transcript 构建把该模块换成空表，因此 `zh-TW` 的导出 HTML
回退英文，而不是把文档渲染器撑过体积上限。交互式 Shell 和 VS Code
配套外壳使用完整词表。

`zh-HK` 和 `zh-MO` 使用这同一套台湾词表，不另做香港或澳门用词。

## 决策

- 不把 `zh-TW` 别名成 `zh-CN`。简体文案正是要修的问题，不能当作 CLI
  已经按严格对齐维护的语言的回退。
- 不在浏览器里做转换。OpenCC 词典会进入客户端，导出体积也放不下一整套额外词表。
- 生成后的文件是权威来源。之后的用词修正改这个文件；重新跑一遍转换会抹掉手工修正。

## 约束

- `zh` / `zh-CN` / `中文` 继续表示简体中文。
- 缺失的 `zh-TW` 键仍回退英文，和其他词表一样。
- 配套外壳和加载提示语使用同一套语言标签划分。

## 风险

OpenCC 加用词修正是机械转换。有些句子仍会像译过来的简体，而不是台湾编辑会写的句子。CLI 繁体词表最初也是这样起步的。让 `zh-TW` 继续显示英文或简体的问题更严重。

简体词表新增句子时，繁体词表可能没有对应项。单测固定了额度和文件相关句子的行为；缺键回退英文，而不是简体。

## 验证

- `normalizeLanguage('zh-TW' | 'zh_TW' | 'zh-Hant' | 'zh-HK')` 为 `zh-TW`。
- `normalizeLanguage('zh' | 'zh-CN')` 仍为 `zh-CN`。
- `getTranslator('zh-TW')` 对同一键返回与 `zh-CN` 不同的繁体字符串（`檔案` 对比 `文件`，以及 `週額度`）。
- transcript stub 导出空表。

## 验收标准

- Web Shell 语言列表包含 `zh-TW`。
- `general.language` 为 `zh-TW` 时，交互式 Shell 显示繁体中文。
- VS Code 配套外壳在 `zh-TW` 下使用繁体中文，在 `zh-CN` 下使用简体中文。
- HTML 导出包不嵌入繁体词表。

## 后续

Web Shell 仍然缺少的其他 CLI 语言（`de`、`ja`、`pt`、`fr`、`ca`）另做。审阅后替换剩余生硬 OpenCC 用词也另做。
