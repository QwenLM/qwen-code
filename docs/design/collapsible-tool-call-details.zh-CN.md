# 可折叠的工具调用详情

[English](collapsible-tool-call-details.md)

## 问题

代码模式的 `exec` 调用可能把很长的结果直接放进会话记录。现有的紧凑渲染器只汇总读取、搜索和列表工具，因此代码执行仍会占用大量屏幕空间。

## 设计

新增面向用户的布尔设置 `ui.showToolCallDetails`，默认值为 `true`，以保留现有显示方式。设为 `false` 后，普通工具组只显示一行状态、工具名称、数量、耗时和展开提示。参数、结果、图片及通知仍保留在历史项中，只由渲染器隐藏。

在启用鼠标追踪的 Virtualized History 中，单击折叠行会展开对应工具组。单击已完成且展开的工具组首行会再次收起；结果内容中的单击、链接单击、多击文本选择、拖动选择和上下文菜单操作都不会切换状态。运行中的工具组可以展开，但完成前不能收起。由调度器创建的工具组通过 `batchId` 保留该状态，因此从实时 pending 行转为已提交历史时仍保持展开；没有 batch id 的适配器工具组则在其挂载生命周期内保留状态。在追加式终端模式下，提示行会指向 `Ctrl+O`，该快捷键已经可以打开完整会话详情。审批提示、用户发起的 shell 调用和已聚焦的交互式 shell 始终保持展开，因为折叠会隐藏必要的交互。

该设置只影响运行时 UI 状态，不会改变工具执行、记录、模型上下文或序列化历史。

## 测试计划

- 验证该设置已注册到 schema、在 `/settings` 中可见，且无需重启。
- 验证折叠的工具组不显示描述和结果。
- 验证一次完整单击会展开工具组，再单击其首行会将其收起。
- 验证结果正文单击、链接单击、多击选择、拖动选择和上下文菜单操作都不会切换工具组。
- 验证 pending 工具组可以展开，但完成前不能收起。
- 验证审批提示以及已聚焦或由用户发起的 shell 始终保持展开。
- 验证 `Ctrl+O` 仍会强制显示完整详情。
