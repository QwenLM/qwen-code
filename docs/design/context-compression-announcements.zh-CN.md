# 上下文压缩播报

[English](context-compression-announcements.md) | [简体中文](context-compression-announcements.zh-CN.md)

## 问题

[#11810](https://github.com/QwenLM/qwen-code/issues/11810) 报告了一个问题：
输入框上下文卡片和上下文详情面板同时显示同一次压缩的反馈时，会产生重复的实时播报区域。
两个界面各自挂载和关闭反馈，仅删除其中一处的播报会让部分使用流程失去通知。

## 设计

两个界面保留可见反馈，移除实时播报角色。失败颜色由明确的错误状态决定，
不依赖无障碍角色。可见反馈和播报共用现有翻译文案。

现有压缩 hook 在接受的操作开始和结束时发送内部通知，包含操作标识、工作区、
session 和阶段。现有保护逻辑继续拒绝在 session、工作区切换或卸载之后返回的旧结果，
并区分取消、提供商失败、用量刷新失败和操作所属连接中断。
通知不会发送额外提示词，也不会重新收集用量。

App 保存每个工作区和 session 的最新通知。主界面的 hook 通过回调发送通知；
分屏 hook 通过私有 React context 使用相同回调。播报组件与现有 portal provider
一同保持挂载，通过 Web Shell portal root 为每个仍然存在的工作区和 session
渲染一对初始为空的实时播报节点。进度和正常结果使用 polite 状态播报；
失败及刷新失败保留 assertive 警示。

重复的操作和阶段通知只处理一次。跨反馈界面及操作所属组件的重新挂载，记住已播报事件；
操作所属组件离开后，丢弃尚未播报的旧通知。插入新播报前先清空文本，并在之后的任务中
更新，使重试得到相同结果时仍可播报。不使用 App 为显示反馈而保留的历史压缩结果。

新增内容仅在 Web Shell 内部使用。daemon 协议、公开 SDK、压缩操作及两个界面
独立关闭可见结果的行为保持不变。

## 验证

- 仅卡片、仅面板和两者同时可见：当前阶段只有一份实时播报，两个界面的进度提示和
  错误颜色均保留。
- 关闭某个界面或其结果、切换当前附件页签及重新挂载：不重播已完成结果，
  不丢失仍在进行的操作通知。
- 重试得到相同结果：播报新操作，忽略旧操作重复发送的通知。
- 切换 session、工作区及使用分屏：独立操作互不覆盖，所属组件消失后不播报旧结果。
- 验证普通和 Shadow DOM portal root，包括模态界面，确认无障碍工具仍能访问播报节点。
- 除浏览器 DOM 断言外，在 macOS 使用 VoiceOver 验证实际语音。仅统计 DOM 节点
  不能证明屏幕阅读器的朗读行为。如果无法验证语音，PR 保持 Draft 并记录缺少的检查。

使用聚焦的 hook、组件测试和现有浏览器压缩场景，在 PR 中记录已完成检查、运行环境版本
及修改前后的证据。
