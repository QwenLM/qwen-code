# OpenTUI 语音输入对齐

[English](2026-10-26-opentui-voice-input-parity.md) | [简体中文](2026-10-26-opentui-voice-input-parity.zh-CN.md)

## 状态与证据

当前正在实现，尚未完成验证或验收。基线为 main `162ad9f8b2d4ce14bdafcc2c08e843dbd4739644`。使用真实 OpenTUI shell 和 composer 的 mock 测试失败：启用 tap 模式后，Space 插入普通空格，没有调用 recorder.start。禁用语音、已有文本两项控制通过。原始 Ink InputPrompt 与共享语音 hook 整文件共 295 项通过，保留 1 项原有跳过；共享 hook 的 24 项全部通过。这证明组件接线缺口，不代表原生麦克风或平台故障。全局 CLI 为 0.22.0，仅作为环境记录。

## 问题与范围

共享 /voice 命令及辅助语音模型选择器能够持久化有效设置并提示听写，但 OpenTUI 未消费已配置的语音功能。Ink 已支持 hold/tap 输入、权限提示、批量及流式转写、可选润色、取消和录音指示器。不能将入口注册视为行为一致。

本批次使用现有实现和依赖补齐完整语音能力。shell 转后台／焦点、渲染模式切换、安装／平台验收、屏幕阅读器及迁移默认值继续单独跟踪。不增加音频后端、协议、产品假开关、框架或库升级。

## 共享配置与归属

将 Ink 现有语音配置流程提取为两种 composer 共用的 hook。useVoiceInput 仍是唯一状态机，保留录音器生命周期、流式传输选择、网络策略检查、重试行为、关键词回声过滤、转写润色和过期结果取消。保持模型／设置语义及权限提示去重。会话级警告 ref 属于 UI 所有者，不属于一次录音或临时对话框。

共享 hook 接收当前设置／配置、真实文本缓冲、历史写入及提交回调。OpenTUI shell 必须在实际 composer 挂载点传入配置；仅声明字段而没有生产调用方不足以完成接线。错误及权限提示应写入当前所有者的历史，不能只显示瞬时横幅。现有 Ink 行为继续作为兼容性控制。

## 按键与提交

只有聚焦、空白、普通聊天输入框才能启动听写。遵循 Ink 的模态、shell、搜索、补全、附件及 Vim 按键归属顺序；活动录音／转写的取消必须到达现有 hook。被听写消费的 Space 不得同时插入原生空格。关闭语音或卸载时，通过现有生命周期取消待处理工作。保留共享 hook 的模型变更语义：有效模型之间的直接替换本身不触发取消；打开模型对话框则通过卸载 composer 取消。

转写应走普通 composer 提交路径，保留清理控制字符后的精确 Unicode 文本；tap 模式只提交一次，hold 模式保留编辑行为，不添加剪贴板框架，也不错误恢复导入输入的来源标记。不能绕过待处理草稿／附件所有权、队列或活动 turn 策略。

## 展示

使用现有翻译标签和指示器语义展示 recording、transcribing、refining 状态，包括音量表及转义后的实时文本。对齐当前 Ink 展示，但不向原生渲染器导入 Ink 组件。使用现有 RGBA.fromIndex 的 9/6/8/3 槽位对应 Ink 的 redBright/cyan/gray/yellow，保留终端调色板定制，不猜测 RGB，也不增加调色板探测。实时文本保持变暗且不强制前景色，对齐 Ink 的继承颜色语义。使用现有的按显示宽度截断工具，以终端宽度减行内边距执行末尾截断。原生 truncate 标志会从中间截断，与 Ink 不符。除 Ink 窄宽正向对照外，还通过真实原生测试渲染器验证末尾省略号。等待状态标签使用现有 wrap-ansi 依赖和 Ink 完全相同的 hard/trim 选项预先换行，再关闭原生二次换行；仅用原生 word 模式会在 12 列视口把标记移到额外一行。仅在两种渲染器都消费时共享小型展示逻辑，不增加新的 UI 抽象。

完整块对比保留四项 12 列录音状态差异：Ink 参考会丢失录音标记和两个音量格，并挤叠标签；原生行则在更多行保留这些信息。这些属于已知参考缺陷和未裁决的一致性差异，需要维护者明确决定。保留原始对比失败，不修改参考或删除信息来制造相同结果。

## 验证与回归

保留原始失败测试及 1F2P 原始结果。实现前，由 test-engineer 独立检查失败的正向断言及 Ink／共享 hook 控制。实现后重跑同一判别用例，不弱化启动／停止、精确转写、单次提交及普通 Space 断言。针对模态／焦点归属、hold/tap、取消、禁用／卸载、过期完成、权限去重和可见状态补充聚焦覆盖，复用已有 hook 测试，不重复整套状态机测试。

从对应包运行受影响整文件，再执行 build、typecheck、lint 和 bundle。由 test-engineer 验证修复后的集成并注明证据范围。完整 diff 进行开放式自审，直至连续两轮干净；修复后重跑受影响检查。两种语言文档保持同步，保留原始跳过和失败。按完整能力批次提交，优选 2–3k 改动行，按实际 PR base 计算新增加删除硬上限为 6000，并提供当前 head 的 CI 和审查证据。

## 验收与剩余门槛

验收要求生产 shell 配置语音，空输入 Space 只启动一次，tap 完成只提交一次精确文本，控制场景保持普通输入，并在不访问设备或网络时通过取消／生命周期／展示测试。mock 成功不能证明 Bun 原生录音二进制、真实流式供应商、操作系统麦克风权限、hold 时序、设备变化或无障碍能力。这些仍需最终平台／人工证据。本批次不授权默认渲染器切换、发布、自动合并或移除 Ink。
