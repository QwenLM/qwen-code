# Web Shell 继续被中断的会话

[English](web-shell-interrupted-session-continue.md) | [简体中文](web-shell-interrupted-session-continue.zh-CN.md)

## 问题与范围

打开已保存的会话能够恢复历史，但 Web Shell 没有显式继续上一轮中断执行的操作。
现有重试操作用于失败的提交，不能替代进程重启后的服务端恢复判定。daemon 已提供
`POST /session/:id/continue`，core 也已能识别中断的用户请求和缺少结果的工具调用。

本次将这些已有能力接入界面。打开会话不会启动任务。缺少持久化结束状态的部分助手
文本仍不在现有中断分类器的支持范围内；本次不新增历史记录类型或供应商专用预填充。

## 设计

现有会话 context 响应增加可选的 `recovery` 摘要，包含 `kind` 和 `canContinue`。
ACP session 使用已有恢复计划生成摘要，并用同一判定决定是否接受续接。已知历史
缺失禁止续接。正在运行的轮次或可恢复的用户问题不提供续接。旧服务端省略摘要，
界面保持现有行为。

临时恢复状态清理后，会话仍保留已知历史缺失信息。加载过程可能已将缺失的工具结果
替换为中断错误；此时已有分类器会将等待模型回答的状态识别为中断的用户请求。

context 路由继续归属 live-session-owner。已有 continue 修改操作同样指向会话
实际所属运行环境，并保留工作区和 standalone 工作目录检查。不新增回退到主运行
环境的行为。消费链路为 ACP context 状态、daemon bridge/HTTP context 转发、
daemon SDK context 类型、Web Shell connection 状态及恢复提示组件。

daemon SDK 提供 REST 续接方法和绑定会话的包装。Web Shell 将接受结果接入已有
请求跟踪、事件游标及 epoch、轮次结束事件、取消和会话切换保护。不发送合成用户
文本，不插入乐观用户消息。并发续接请求检查 bridge 的请求接收状态，只有空闲会话
能够接受续接。接受响应允许旧版 daemon 不提供事件 epoch。取消会使尚未完成的
续接预检查失效，阻止其随后启动任务。预检查后若会话正在关闭或等待关闭授权，
同样拒绝接收续接。
取消成功后，仍然属于当前会话的取消操作主动刷新恢复状态，不依赖取消事件，因为
重复的空闲取消事件可能被去重。该读取不会延长取消操作。

主聊天和附加聊天面板共用输入框上方的提示组件。中断的用户请求和工具轮次显示本地化
说明及“继续执行”按钮。历史缺失只显示说明。加载中、断线、事件追赶中、正在执行、
等待授权、只读及已接受新会话建议后的交接状态不提供按钮。提交时立即隐藏按钮，
使用已有进度控件。执行结束后刷新恢复元数据，
开始新任务和切换会话时使旧状态失效；延迟响应不能更新其他会话，也不能在重连后
覆盖新事件流订阅读取的恢复状态。
恢复状态合并仅保留同一会话的缓存，包括切换会话后结束事件先于首次元数据读取
完成的情况。
元数据、轮次结束事件和明确拒绝后的刷新共享会话内的恢复读取顺序；本地续接和新
活动使旧读取失效。配置刷新保留已缓存的恢复状态，配置修改不会丢弃有效的恢复刷新。
续接会登记到现有结束通知机制（包括快照回放），不新增用户
轮次或导航条目。如果重载快照先于准入确认到达，其结束事件暂存在本地续接操作中，
直到服务端返回的任务 ID 能精确匹配；无关历史轮次不能使当前续接结算或触发通知。
准入确认在重新挂接间隙返回时，也会保留通知登记。无论准入确认先于还是晚于快照返回，
快照已应用过的结束事件仅结算其续接结果并触发通知，不能结束后续轮次的流式显示或解除后续轮次的输入锁。
准入确认之前收到的实时结束事件同样等待任务 ID 匹配，后续排队轮次不能消费原续接结果。
自动重新挂接同一会话时，保留续接跟踪及失败结算。显式加载会话会使该操作的归属
失效；明确拒绝后的刷新使用当前连接对象，并遵守其恢复读取顺序。

已接受轮次的执行错误由会话记录报告，不显示为续接准入失败。
失败提示在错误回调执行时捕获会话身份及恢复代次。后续恢复读取或活动会使该提示
失效，即使 React 将失败与后续任务合并到首次渲染中。

提交结果未知时从会话和事件流核实，不自动再次发送续接请求。缺失的工具结果使用已有
合成中断错误表达，恢复层本身不重新执行工具。

## 文件与边界

- ACP bridge 状态类型、续接请求接收及聚焦测试。
- ACP session 恢复判定、context 响应及聚焦测试。
- daemon SDK context/结果类型、HTTP/会话客户端、导出及测试。
- Web Shell 会话操作、恢复提示组件、两个聊天入口、国际化及测试。
- 不新增 daemon 路由、core 恢复算法、CLI 参数或自动续接。

## 验证与验收

1. 打开保存的中断请求后，点击按钮前不发生模型调用。
2. 续接保留会话 ID 和原上下文，不重复用户消息；工具中断使用合成错误结果。
3. 正常结束、执行中、等待用户回答、历史缺失及不支持恢复的状态不会误启动续接。
4. 双击和多个标签页并发操作不会重复排队续接。
5. 完成、拒绝、失败、重连和切换面板后，会话状态正确且输入框可用，取消仍有效。
6. 工作区归属及 standalone 检查保持有效。
7. 执行聚焦测试、仓库构建/类型检查/打包、隔离的全局 CLI 基线与本地 daemon 验证，
   随后进行完整差异自审及代码评审。
