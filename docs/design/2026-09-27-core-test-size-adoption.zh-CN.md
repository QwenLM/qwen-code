# Core 测试规模：验证并采纳有明确预算的删减

[English](2026-09-27-core-test-size-adoption.md) | [简体中文](2026-09-27-core-test-size-adoption.zh-CN.md)

状态：第 8 轮完成，在所述预算下采纳冻结的第 2 版候选。

## 起点

[第 7 轮](2026-09-27-core-test-size-relaxed-budget.zh-CN.md) 在生产基线
`a270907e5f3fd6ebe26ef7d17ea7da3e92c2773a` 上得到删除 184 个测试文件、
45,167 行的候选。core 全套没有新增失败，基线行覆盖损失为 0.3982 个百分点。
其故障与 mutation 检出保留情况来自历史图预测。本轮验证实际检出能力，
准备可以采纳的测试改动。

## 已接受的预算

- 允许删除用例、减少断言和独立失败标签。
- 按固定基线可检测行分母，已覆盖行损失不超过 0.5 个百分点；新增覆盖不抵扣。
- 固定配对样本中，原有 Killed mutant 的聚合损失不超过 1%；各模块单列，
  新增 kill 不抵扣，Timeout 保持未确定。
- 保留历史故障检出和安全、权限、数据完整性检查。局部覆盖缺口单独审查。
- 保持生产实现不变。

## 候选审查

将删除用例与保留测试及其对应生产分支逐项比较。若删除暴露必要行为，
恢复少量用例组。重点检查压缩、记忆发现、文件缓存新鲜度、流式与工具协议、
进程清理和持久状态。完成调整后、能力比较前冻结最终测试文件哈希。

## 测量设计

C1 在完整与删减后的独立 checkout 中回放真实历史反向补丁。保留每个故障
原有的基线定向测试范围，明确记录它与候选保留文件的交集。删除文件导致的
收集失败不能算作检出。保留范围为空、补丁不适用和原有失败均单列。
条件允许时补充选择语料之外的故障，并标明训练语料内的回放。
C1 两侧仅按完整用例名排除已知 prune 失败；最终原生全套仍执行该用例，
并保留其实际结果。

C2 在原有 19 个 mutation 训练模块之外冻结分层样本，纳入覆盖损失集中的
模块及行覆盖重叠的模块。两侧生产源码与 mutant 身份保持一致，记录算子、
静态 mutation 范围、请求和实际执行的测试以及所有排除项。在候选运行前
冻结预期身份集合。若根据测量结果修复候选，应明确这是针对该样本的调整。

使用独立 Linux VM checkout，并限制 worker 数量。定向能力测量可并行；
本轮不评估运行速度。最终验证包括 core 全套原生覆盖、套件健康、build 和
typecheck。原有 prune 失败和新增失败均保留，原始健康状态如实记录。

XML 的完整导入关联范围在 40 分钟后终止，结果保持不完整。基线逐文件
覆盖显示，大部分关联只来自模块初始化。执行修订按基线 `coveredFunctions`
中存在非 `<static_initializer>`、`<instance_members_initializer>` 函数的
规则选取 owner：XML 3 个，文件缓存 19 个；候选执行其保留文件交集。
修订仍使用整模块、全部算子和静态变异。两个范围的结果分别记录；
修订范围的成功不能替代原完整导入范围的缺失结果。已完成的计费与工作流
预算测量保留原计划来源。预冻结的另三个补充模块本轮不运行。

## 第 1 版的实际检出能力

语义审查后，第 1 版保留 648 个测试文件，净减少 43,199 行；恢复的
20 个文件共 84 个用例通过定向测试，build、typecheck、ESLint 通过。
固定 257,159 行分母上，覆盖损失为 834 行，即 0.3243 个百分点。

| 实测样本                       | 完整基线 | 第 1 版 | 结论             |
| ------------------------------ | -------: | ------: | ---------------- |
| 用于选样的 95 个历史故障       |  检出 95 | 检出 95 | 保住已知语料     |
| 选样语料之外的 8 个历史故障    |   检出 8 |  检出 0 | 需要恢复回归检查 |
| 用量计费的原有 Killed mutant   |       32 | 保留 22 | 损失 10/32       |
| 工作流预算的原有 Killed mutant |       77 | 保留 62 | 损失 15/77       |

新增的 8 个历史故障针对被删测试关联的模块，按预先冻结的提交顺序与
补丁可适用性选取。它们揭示了候选的真实缺口，不能用于估计全包漏检率。
两侧均无健康、收集或超时问题；基线的 20 条新失败均能追溯到实际断言。
用量计费模块没有行覆盖损失，仍丢失了 31.25% 的原有 mutant 检出。
这说明行覆盖与历史观察者图需要配合独立能力验证。

第 1 版全套有既有 prune 失败及一次 code-mode 的 50 ms 预算失败。
两组交替基线/候选定向复跑均通过，相关源码与构建产物哈希相同；
该结果尚不能确认失败原因。保留原始失败，并在能力测量结束后单独执行
最终全套验证。

## 观测后的修复

保留计费用量、工作流预算、进程存活性、XML 恢复协议和文件缓存的完整
原测试；XML 围栏预期进一步加强。前两个 mutation 模块已明确否决第 1 版，
后两个模块停止尚未启动的第 1 版测量，直接验证第 2 版；它们的第 1 版
结果保持“未运行”。针对独立历史故障，
补回 Git/Qwen 忽略规则的空格语义、Schema 转换、流式调用索引碰撞、
Skill 结果压缩与 dotfile 语言识别的小组用例。语义审查另补回媒体来源
隔离、持久数据不可读时的保护、句柄绑定、工作区真实路径约束、运行时
sidecar 所有权和内置技能授权边界，并修正 XML 围栏断言互相掩盖的问题。

这些修复使用了第 1 版的失败结果。后续重放属于针对已观察样本的修复验证；
原始独立样本的失败与修复后的结果分开报告。普通输出格式、诊断、部分错误
输入以及召回质量和扫描延迟评测仍有删减，其风险不会被包级平均值抹去。

## 第 2 版实测

第 2 版冻结候选净减少 40,616 行（8.28%），S1 从 490,301 降至 449,685。
S1 包括测试辅助代码、快照和 fixture；这些附属文件的 5,365 行保持不变。
可运行测试源文件从 812 个降至 662 个：删除 150 个，精简或加强 29 个。
生产实现保持原字节。34 个相关文件共 271 个定向用例通过，build、typecheck
和 ESLint 通过。

训练语料中的 95 个历史故障全部保留检出：10 个用第 2 版重新回放，
85 个复用执行范围和源码哈希完全相同的第 1 版观测。两条历史反向补丁
在两侧都伴随收集错误，检出依据来自另外实际执行的新失败断言；相关诊断
单独保留。这 95 条由新执行与复用观测共同组成。

新增的 8 个故障中，7 个在第 2 版首轮检出，1 个在单独补测中检出。
首轮 `b6103543f5` 的健康检查达到 600 秒上限，其不完整结果继续保留。
其他能力测量停止后，补测沿用完整测试范围、2 个 worker 和 600 秒上限：
健康检查通过，注入故障后产生 1 个真实失败断言。汇总逐条标明观测来源，
原首轮严格比较失败的记录继续保留。

| 变异模块   | 基线 Killed | 保留 | 损失 | 原有 Killed 中未确定 |
| ---------- | ----------: | ---: | ---: | -------------------: |
| 用量计费   |          32 |   32 |    0 |                    0 |
| 工作流预算 |          77 |   77 |    0 |                    0 |
| XML 恢复   |         147 |  147 |    0 |                    0 |

四个配对模块共 454 个 mutant，符合聚合损失不超过 1% 的预算。

Killed；它们的基线状态仍为未确定，均不计入原有 Killed 或新增检出。
