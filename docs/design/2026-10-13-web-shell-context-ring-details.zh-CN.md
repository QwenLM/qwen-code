# Web Shell 上下文圆环打开详情面板

[English](2026-10-13-web-shell-context-ring-details.md) | [简体中文](2026-10-13-web-shell-context-ring-details.zh-CN.md)

## 问题与范围

点击 composer 的上下文圆环会往对话记录里插入一张 `Context Usage` 快照卡片，而这张卡片自己的详情入口又会插入第二张。长会话里查看几次用量，对话中就会留下好几张几乎相同的卡片，各自冻结在不同时刻，而且每次点击都会把对话拉回末尾，即使用户当时正在往上翻。见 issue #14051。

悬停已经展示了摘要，所以点击只是把同样的内容换个地方再说一遍，而不是进入下一层。

## 设计

复用已经存在的那一个详情界面：右侧面板的上下文用量标签页。它的 id 是 `context-usage:${sessionId}`，打开逻辑遇到同 id 的标签页是替换而不是追加，所以重复点击在结构上就不可能叠出第二份。它已经渲染了逐分类的明细、可展开的条目、刷新、压缩，以及加载和错误状态。

因此这次改动是改绑入口，而不是新做一套界面：

- 圆环点击打开该面板，不再插入卡片。
- 对话内上下文卡片的详情入口打开同一个面板，不再插入第二张卡片。
- 悬停行为不变；弹层保留自己的详情入口，因为键盘和触屏没有悬停。
- 手动输入 `/context` 或 `/context detail` 仍然输出到对话记录：那是用户明确要求放在那里的。

锚定弹层和对话框方案被否决。把完整明细放进锚定在工具栏上的弹层，需要处理碰撞、滚动和焦点陷阱；做成对话框则必须走 portal root。两种方式都会让同一份数据存在两个详情界面，除非同时把面板删掉。

### 回落

宿主没有提供详情入口的 composer 保留快照行为。目前只有内嵌的 side-task 面板属于这种情况——它本身就在右侧面板里，没有地方再开一个标签页。它的圆环仍会在自己的对话中生成 `/context`，并且只有这种情况才显示说明这一点的悬停提示，否则旧文案就是不成立的。主 composer 恒定有面板，所以它的快照接线被直接删除，而不是留成一条永远走不到的分支。

## 已知限制

面板已经打开时再次打开不会重新读取。面板是一个带自己刷新控件的持久界面，和文件预览一样：再点一次它的入口是聚焦，而不是重新加载。后续可以改成重新打开时刷新，或者切成开合切换。

## 文件与验证

`client/components/ChatEditor.tsx`、`client/App.tsx`、它们的单元测试，以及两个断言了旧卡片堆叠行为的浏览器 spec。包 README 和上下文用量回调设计文档的中英版本都要改，因为宿主回调现在也会收到圆环点击和卡片详情点击。

验证：悬停摘要不变；点击打开一个面板标签页，再点仍是一个；点击不会往对话记录里加卡片；`/context` 和 `/context detail` 仍会输出卡片；卡片的详情入口打开面板；内嵌 side-task 的圆环仍生成快照并仍显示提示；分屏打开自己会话的标签页。执行构建、类型检查、lint、web-shell 单元测试和两个上下文浏览器 spec。

## 验收与风险

查看上下文用量不再写入对话，所有入口都收敛到同一个详情界面。风险：依赖圆环点击产生对话卡片的宿主，现在会拿到面板或自己的回调；内嵌面板是有意保留旧行为的。不改变 daemon 路由或数据协议。
