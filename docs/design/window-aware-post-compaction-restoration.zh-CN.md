# 感知上下文窗口的压缩后恢复

[English](window-aware-post-compaction-restoration.md) | [简体中文](window-aware-post-compaction-restoration.zh-CN.md)

## 问题

摘要成功后，恢复最近访问的文件可能使下一轮会话再次超出较小的上下文窗口（#15487）。现有的 50,000-token 文件内容预算不随窗口大小变化。图片恢复有数量限制，但没有总 token 预算。仅检查候选历史是否比原历史更小，无法防止这种溢出。

## 行为

压缩服务为恢复的文件内容分配 `min(50_000, floor(effectiveWindow / 4), floor(autoThreshold / 2))` token 的预算。当现有路由检查接受服务端报告的较小总窗口上限时，有效窗口采用该上限。自动压缩阈值包含用户配置的比例。为摘要和其他上下文预留阈值的一半，使较低阈值下仍能部分恢复文件，包括 40K 窗口的默认阈值。

文件内容及其恢复大小均使用现有的 CJK 感知文本 token 估算器。单文件读取器的字符大小上限和文件数量限制继续生效。超出内容预算的文件保留为路径引用，优先考虑最近访问的文件。直接调用恢复逻辑且未传入预算的调用方使用 50,000-token 默认值。

溢出检查计入摘要、恢复内容、现有不可见上下文和待提交工具结果。如果候选计数达到或超过有效窗口的自动压缩阈值，则重新组合历史，移除全部恢复文件块、路径引用和图片。服务从现有 token 计数中扣除两份历史在本地估算的大小差，保留摘要及不可见系统／工具上下文的计数。返回的计数排除待提交结果，由调用方在提交时计入。调试日志记录阈值、待提交结果估算，以及移除附件前后的计数。

第二次组合仍保留计划模式提醒、运行中的后台代理提醒，以及与待提交结果配对所需的末尾工具调用。它不会再次请求摘要，也不会再次触发压缩 hook。现有的载荷超限恢复限制和托管场景文件恢复排除规则继续生效。

## 范围与限制

本修复只处理恢复阶段。压缩请求准入（#9455 / #15936）和后续请求计数（#15486）保持独立。本地 token 计数是近似估算；这些限制不保证每个服务商都能精确接纳请求，也不能让过大的摘要自动适配窗口。现有的空摘要、输出截断和计数膨胀失败处理保持不变。

## 验证

- 使用五个真实文件和已完成的模拟摘要，复现成功候选仍超出 16K 窗口的情况。
- 验证 16K 和 32K 窗口仅保留预算容纳的文件内容，其余文件保留为引用。
- 验证 128K 和 200K 窗口的恢复行为不变，并在 1M 窗口、提高文件数量限制时验证 50K 上限。
- 覆盖文件内容剩余预算为零的情况。
- 覆盖服务端报告的总窗口上限、仅输入上限和路由不匹配情况。
- 验证 40K 窗口以及较低的用户配置阈值下仍能部分恢复文件。
- 验证 CJK 内容消耗文本 token 预算，放不下时保留引用。
- 将待提交工具结果计入溢出判断，并在报告计数中保留较大摘要的体积。
- 对比用户配置和默认自动压缩阈值，并检查附件移除的调试日志。
- 分别在有、无摘要 usage 元数据时，让恢复的文件和图片超出自动压缩阈值；验证附件被移除，不可见上下文计数、提醒和待提交工具调用配对得到保留。
- 运行现有压缩、附件和 token 估算测试。服务级测试将该阶段与压缩请求准入隔离，不代表真实服务商的端到端验证。
