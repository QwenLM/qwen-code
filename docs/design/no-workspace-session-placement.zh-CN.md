# 无工作区会话的位置

[English](no-workspace-session-placement.md) | [简体中文](no-workspace-session-placement.zh-CN.md)

## 问题与范围

Issue #15309 描述了一个可发现性问题：无工作区会话分组嵌套在工作区内部，
折叠工作区后便不可见。分组自身的折叠状态在刷新后也会重置。
该分组应与工作区同级。

经讨论，请求者已确认名称为“No-workspace sessions / 无工作区会话”。
两种语言均保留该名称。

## 设计

将 `WebShellSidebar.tsx` 中活动会话的 `StandaloneRecents` 节点移动到工作区
主体之后、已归档之前。保留现有属性与可见性判断，包括原本由外层容器提供的
Live 视图限制。继续使用当前聚焦 daemon 的客户端，不增加其他主机的会话。
锁定工作区及特定分区视图继续遵守原有限制。

在 `StandaloneRecents.tsx` 中复用 `workspaceExpansion.ts` 读写现有展开状态，
分别使用 `standalone:active` 和 `standalone:archived` 偏好 id。
没有偏好时默认展开。搜索仍会在分组已保存为折叠时显示匹配条目，且不覆盖
已保存偏好。搜索期间禁用分组标题的折叠按钮；清除查询后恢复按钮和已保存状态。
折叠时仍重置分页展开状态。归档会话仍位于已归档区域内。

从最近会话、深链接或分组的新建任务入口打开会话时，用户明确选择的折叠状态
仍优先。这些操作不自动展开分组，也不覆盖折叠偏好。这遵循普通工作区分组的
约定，并保留已有创建行为；用户仍可通过标题和搜索显示会话行。

最近会话继续有意汇总无工作区会话，因此同一会话可同时出现在来源分组和
最近会话中，与普通工作区会话的展示方式一致。main 中已有来源感知的选中
逻辑负责跟踪被点击的副本。本次移动不改变最近会话成员或分配新的会话归属。

## 约束与风险

保留创建、打开、选中、搜索、分页、生命周期操作、能力检查与 daemon 归属。
无需修改后端、SDK、存储迁移、文件系统权限或自动工作区关联。
布局只调整位置，复用现有分组标题与会话行。
localStorage 不可用时仍采用现有安全默认值。

## 验证与验收

新增浏览器覆盖，确认折叠工作区后无工作区分组仍可见，两个分组的折叠状态
分别跨刷新保留，搜索及打开匹配的独立会话仍然正常。保留能力限制覆盖。
新增组件覆盖以验证活动与已归档分组的展开偏好互不干扰。
使用模拟 daemon 捕获修改前后的浏览器证据，并明确区分真实 daemon 测试。
