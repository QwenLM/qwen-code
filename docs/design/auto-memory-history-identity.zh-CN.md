# 自动记忆提取的历史身份

[English](auto-memory-history-identity.md) | [简体中文](auto-memory-history-identity.zh-CN.md)

状态：已实现 #13158 默认关闭窗口实验的 Critical 修复；受控输入验证与模型验收分开。

## 问题与范围

启用 `preserveUnprocessedHistory` 后，项目游标的 `processedOffset` 成为内容选择器。其他会话、压缩或历史替换会使它指向无关内容。仅比较当前长度无法检测压缩后重新增长或同长替换。直接从最后 40 项开始也会遗漏长工具轮开头的用户偏好。

保持默认提取路径和 40 项窗口上限不变。本修复不解决积压调度、部分写入重试，也不证明模型质量或 token 节省。

## 决策

为游标添加可选的 `processedHistoryHash`，仅窗口实验读写它。使用 Node 的 SHA-256 对已处理原始历史前缀计算指纹，包含结构前缀长度，但排除其中的合成内容。逐项输入，避免分配完整历史的 JSON 字符串。只有会话、边界和前缀指纹都匹配时才能复用偏移量。

缺少身份或切换会话时，从最近真实用户提示开始，通过有界窗口保留整个待处理工具轮。复用现有用户提示分类器，排除已投递的任务通知。同会话身份失配时从首条真实历史重新开始，因为指纹无法恢复具体变更位置。遇到压缩前缀时，即使是旧版游标，也从合成条目之后开始，让后续全部真实事实仍可到达。

在历史整理之前调用带 `includeCompressed: true` 的 `getStartupContextLength`。保留压缩前缀末尾的函数调用，使它与响应一起处理。从所选原始历史中排除摘要和完整文件附件。不要裁剪已整理的前缀：整理可能把附件与下一条真实提示合并。

在调用异步提取器前计算起点和终点指纹。持久化实际写入偏移量对应的指纹，包括末尾零工具调用时保留起点、无用户消息时提前返回这两条路径。默认路径写入时省略此字段，因此在默认提取后启用实验会重新初始化，而不是信任未经认证的索引。

## 约束与风险

可选实验的前缀校验 CPU 成本与已处理原始内容量成正比。结构化启动信息刷新不会使索引失效，但已处理会话内容的变化会有意重启提取，可能重复事实。项目游标仍由多个会话共享，切换会话时从当前用户轮初始化。已经被压缩丢弃的事实无法恢复。纯媒体提示分类和合成前缀识别保留现有辅助函数的限制。

## 验证与验收

回归测试必须覆盖合法新会话继承长历史、首次长工具轮、压缩摘要和附件、缩短后重新增长、边界条目不变的同长替换、启动提醒刷新、异步期间历史变化，以及调用与响应配对。原有空窗口和零工具调用保留游标测试在已认证游标下必须继续通过。

执行构建、打包、类型检查，以及受影响的提取、规划器、管理器和客户端测试。在修复后的源码上重复受控原生 composer 输入选择复现。验收要求真实压缩后事实仍可到达、合成用户上下文不进入所选窗口，且默认提取行为不变。受控 fork 只证明输入选择，不证明提供商执行、记忆质量或成本降低。
