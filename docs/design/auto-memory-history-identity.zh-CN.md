# 自动记忆提取的历史身份

[English](auto-memory-history-identity.md) | [简体中文](auto-memory-history-identity.zh-CN.md)

状态：已实现 #13158 默认关闭窗口实验的历史身份和无可提取文本尾部修复；受控输入验证与模型验收分开。

## 问题与范围

启用 `preserveUnprocessedHistory` 后，项目游标的 `processedOffset` 成为内容选择器。其他会话、压缩或历史替换会使它指向无关内容。仅比较当前长度无法检测压缩后重新增长或同长替换。直接从最后 40 项开始也会遗漏长工具轮开头的用户偏好。

保持默认提取路径和 40 项窗口上限不变。在可选实验中，压缩前冲刷待处理窗口。退出重放、部分写入重试，以及模型质量与 token 成本验收仍需单独完成。

## 决策

为游标添加可选的 `processedHistoryHash`，仅窗口实验读写它。使用 Node 的 SHA-256 对已处理原始历史前缀计算指纹，包含结构前缀长度，但排除其中的合成内容。逐项输入，避免分配完整历史的 JSON 字符串。只有会话、边界和前缀指纹都匹配时才能复用偏移量。

缺少身份或切换会话时，从最近真实用户提示开始，通过有界窗口保留整个待处理工具轮。复用现有用户提示分类器，排除已投递的任务通知。同会话身份失配时从首条真实历史重新开始，因为指纹无法恢复具体变更位置。遇到压缩前缀时，即使是旧版游标，也从合成条目之后开始，让后续全部真实事实仍可到达。

在历史整理之前调用带 `includeCompressed: true` 的 `getStartupContextLength`。保留压缩前缀末尾的函数调用，使它与响应一起处理。从所选原始历史中排除摘要和完整文件附件。不要裁剪已整理的前缀：整理可能把附件与下一条真实提示合并。

在调用异步提取器前计算起点和终点指纹。持久化实际写入偏移量对应的指纹，包括末尾零工具调用时保留起点、无用户消息时提前返回这两条路径。默认路径写入时省略此字段，因此在默认提取后启用实验会重新初始化，而不是信任未经认证的索引。

保持 fork 所选窗口的上限；当整个剩余尾部都没有可提取的用户文本，且所选窗口取得真实进展时，在同次执行中消费尾部。复用无用户消息门槛的逐 part 分类：工具响应、模型文本、运行时提醒和隐藏推理本身不需要再次 fork。无用户消息的提前返回路径也可以消费这种尾部。只要尾部还有任何可提取的用户文本，就保留原有窗口边界，让整个剩余部分继续待处理。零工具调用完成时仍按原规则推进有上限的历史窗口，或保留实时末尾的起点；免费消费尾部不能把它变成会触发冷却的空操作。在异步 fork 之前认证可消费尾部，使这些内容的变化能在下次执行时使游标失效。

### 压缩前冲刷

启用冷却实验和托管记忆时，共用压缩入口在 PreCompact 钩子和摘要之前冲刷主会话的原始浅拷贝历史。复用现有提取器、历史身份和 40 项窗口，不额外保留历史队列或新增调度器。排除子代理身份上下文，避免记忆 fork 递归冲刷。现有主会话通知边界同时退出 agent frame 和独立的身份／名称上下文，防止继承的 worker 身份绕过冲刷。

全部窗口共用两分钟取消截止时间和调用者的取消信号。已有提取任务、窗口暂停、失败或未推进时，保留原历史并返回记忆冲刷导致的压缩失败。沿用现有压缩失败限制。后续尝试从最后已提交窗口继续；实时末尾的零工具调用完成仍保留原有游标暂缓规则。

把取消信号传入提取 fork，并在原子游标提交时检查。保留失败 fork 有效写入的恢复；文件系统恢复可能在模型取消后完成。此边界不实现退出重放，也不证明记忆质量和成本。

## 约束与风险

可选实验的前缀校验 CPU 成本与已处理原始内容量成正比。结构化启动信息刷新不会使索引失效，但已处理会话内容的变化会有意重启提取，可能重复事实。项目游标仍由多个会话共享，切换会话时从当前用户轮初始化。已经被压缩丢弃的事实无法恢复。纯媒体提示分类和合成前缀识别保留现有辅助函数的限制。

提前消费尾部会改变未来提取的输入：后续用户提示无法再把这些旧工具或模型上下文带入下一个待处理窗口，而此前在下一次无用户消息执行消费尾部之前仍可能带入。仅凭用户文本的提取门槛，不能证明记忆质量不变。启用实验之前仍必须完成代表性质量与成本验收。

## 验证与验收

回归测试必须覆盖合法新会话继承长历史、首次长工具轮、压缩摘要和附件、缩短后重新增长、边界条目不变的同长替换、启动提醒刷新、异步期间历史变化，以及调用与响应配对。验证有 fork 和无 fork 时的无可提取文本尾部消费、fork 前的尾部认证、后续用户事实仍待处理，以及没有增加 fork 或扩大 agent 预算。原有空窗口和零工具调用保留游标测试在已认证游标下必须继续通过。

执行构建、打包、类型检查，以及受影响的提取、规划器、管理器和客户端测试。在修复后的源码上重复受控原生 composer 输入选择复现。验收要求真实压缩后事实仍可到达、合成用户上下文不进入所选窗口，且默认提取行为不变。受控 fork 只证明输入选择，不证明提供商执行、记忆质量或成本降低。

压缩前验证必须覆盖原始与整理后历史的区别、冷却积压的连续窗口、提取失败与暂缓、已有运行任务、取消后的游标不提交，以及记忆 fork 排除。构建、打包、类型检查和受影响的失败状态消费者测试必须通过。离线受控验证仍不能替代真实提供商质量与成本验收。
