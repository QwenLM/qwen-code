# Responses HTTP 错误与 assistant phase

[English](responses-http-phase.md) | [简体中文](responses-http-phase.zh-CN.md)

## 问题

Responses 丢失 HTTP 响应头和后面的诊断字段，遗漏 408/409 重试，忽略明确的重试指令，并在手动回传历史时丢弃 assistant 消息的 phase。

## 设计

使用 Responses 专属错误类型保存白名单响应头和结构化错误字段。保留 request/trace ID 及结构化网关诊断信息，排除无关的账号元信息。沿用错误正文读取上限、凭据脱敏和非结构化错误的有界摘要。取消和永久配额耗尽仍优先处理。

共享重试调用点识别该错误类型，遵循明确的 x-should-retry 值，默认重试 408/409/429 和 5xx，并使用已有的尝试次数及可取消的服务端指定等待。普通 404 仍不重试，其他提供商保留原有分类。共享延迟解析器也支持 retry-after-ms。

把消息 ID 和可选 phase 存为文本 Part 上可序列化的元信息，根据消息生命周期事件更新，在合并时保留消息边界。Responses 回传发送合法的 assistant phase，不发送本地元信息。断流和截断恢复保留不同消息的边界，包括文字完全重叠但 phase 不同的消息。没有元信息的旧历史保持原有行为。

## 验证与限制

通过本地端点并开启 code mode，对比已复现的打包基线和重新构建的 CLI。覆盖恢复、停止指令、普通 404、延迟和取消、脱敏、晚到的 phase、多消息、JSON 历史及下一轮工具调用。运行相关单元测试、构建、打包和类型检查。

这些修复不能确定生产网关找不到的资源，也不能证明分数提高。本次不包含线上评测。
