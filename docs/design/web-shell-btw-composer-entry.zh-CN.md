# Web Shell 输入框 BTW 入口

[English](web-shell-btw-composer-entry.md) | [简体中文](web-shell-btw-composer-entry.zh-CN.md)

## 问题与当前行为

Web Shell 主聊天已经支持 `/btw <question>`，并在现有临时面板中展示回答。
用户必须知道命令或等到自动意图建议出现；输入框没有明确入口。
`/btw side` 是独立的既有侧任务命令。

## 提议方案

在桌面端和移动端主输入框的添加菜单中增加“顺带一问”。展示 `/btw`，
并用单行短文案说明用途：中文为“临时提问，不打断任务”，英文为
“Keep the main task running”。回答不进入主对话。点击后给当前文本添加
`/btw ` 前缀并将焦点还给输入框，不自动发送。已有 `/btw` 前缀时保留原文，
其中大写形式会统一为小写，以匹配命令路由。
用户可以编辑或删除前缀。

仅在主聊天会话存在且宿主未通过 `hiddenSlashCommands` 隐藏 `btw` 时展示入口。主任务执行期间仍可使用。在 Shell 模式中
隐藏；存在图片、文件、输入标签或正在读取的图片时禁用并说明原因，因为
BTW 只接受文本问题。沿用现有的准备中和输入框禁用状态来阻止交互。

## 决策与范围

复用 AddMenu 的下拉菜单、移动抽屉和关闭后恢复焦点的机制。文本本身就是
模式提示，不增加持久模式、快捷键、公共定制选项、daemon 路由或发送路径。
由主 App 显式启用 ChatEditor 的入口。ChatPane 具有不同的命令路由，
没有本地 BTW 回答面板，因此不启用此入口。

涉及 packages/web-shell/client 下的 App.tsx、ChatEditor.tsx、
composer/AddMenu.tsx、i18n.tsx，以及对应的输入框和浏览器测试。
继续以既有 `/btw` 和 `/btw side` 路由为准。

## 验证与验收标准

- 桌面端和移动端菜单均提供中英文 BTW 说明。
- 空白和已有草稿只添加一个 `/btw` 前缀；选择入口不会发送。
- 已有小写前缀的草稿保持不变，大写前缀统一为小写，焦点回到输入框。
- 选择入口后发送普通问题，调用既有 BTW 接口并展示回答面板，不提交或
  取消主任务。
- 操作不会丢弃附件；Shell 模式和不可用的输入框不提供可操作入口。
- 定向测试、构建、类型检查和浏览器测试通过。E2E 计划记录环境限制，
  明确区分模拟传输与真实模型调用。

## 待决问题

本次范围内无。独立输入模式或 ChatPane 的 BTW 面板可以按需单独考虑。
