# 设计文档要求

[English](README.md) | [简体中文](README.zh-CN.md)

设计文档用于说明拟议变更、设计理由及验证方式。文档存放在 `docs/design/`
下，新增或修改设计文档时应遵循以下要求。

## 文件命名与导航

- 在同一目录中维护两个完整版本：英文使用 `<name>.md`，简体中文使用
  `<name>.zh-CN.md`。文件基础名称及日期前缀（如有）必须一致。目录入口页使用
  `README.md` 和 `README.zh-CN.md`。
- 在每份文档标题下方紧接着放置指向两个语言版本的相对链接。
- 尽量保留现有文档路径。路径或标题锚点发生变化时，在同一次变更中更新引用它们的链接。

## 内容对齐

- 两个版本都必须完整覆盖设计内容，不能用摘要或指向另一语言的链接代替翻译。
- 保持章节顺序和标题层级一致。适用的章节应在语义上对齐，包括问题描述、现状、目标、
  范围边界、拟议方案、设计决策及理由、约束、风险、验证计划、验收标准和待定问题。
- 保持技术标识符、文件路径、命令、配置键、协议字段、示例值和数值限制一致。
  翻译说明文字及图注时，不得改变其描述的行为。
- 文档中如有状态、日期、里程碑和后续要求，也必须同步。两个版本都应区分拟议方案、
  已实现行为和已验证结果；翻译不得改变设计状态。
- 尽量共享图表及其他资源。共享资源中包含特定语言的文字时，应提供含义一致的说明。

## 后续变更要求

- 在同一次变更中新增或更新两个版本，并在同一个 PR 中一并提交。
  可以先编辑任一语言，但只有消除两个版本的差异后，文档工作才算完成。
- 修改现有单语设计文档时，补齐缺失的语言版本并对齐完整文档。
  翻译应保留原设计含义；实际设计变更应在两个版本中作出一致说明。
- 随设计演进，在两个版本中同步新增决策、实现约束、验收标准和后续工作。
  不得让一个版本保留旧要求，或保留另一个版本已经解决的待定问题。

## 审查清单

- 两份文件均存在，且双向语言链接有效。
- 章节结构与实质要求一致，两个版本均未遗漏决策、限制、验收标准或后续工作。
- 技术标识符、示例、链接和共享资源正确。
- 两个版本的状态一致，且均反映 PR 中拟议的变更。
- 已检查 Markdown 格式和相对链接。
