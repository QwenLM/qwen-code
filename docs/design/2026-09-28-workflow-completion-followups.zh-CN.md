# 工作流完成通知后续修复

[English](2026-09-28-workflow-completion-followups.md) | [简体中文](2026-09-28-workflow-completion-followups.zh-CN.md)

## 问题与范围

Issue #12908 跟进 #12415 的四项非阻断发现：失败运行以 run ID 作为标签、嵌套 Error 原因丢失、显式关闭通知缺少单测，以及前台通知出现在工具卡片和更早的后台通知之前。本次涵盖 Ink 工作流完成路径和共享结果格式化，不增加 OpenTUI、ACP 或 headless 通知投递。

## 设计

在执行前注册编译所得的元数据，由注册表使用工作流名称生成运行描述。这样覆盖成功、脚本失败，以及先于 runner 结算的审批失败。保留调用者指定的描述及独立的 run ID。

保留既有 Error 字符串表示，追加有界的聚合错误成员和 cause。使用跨 realm 的原生 Error 检测。单个错误输出限制为 4,096 个 UTF-16 码元，避免切断代理对；最多访问 32 个值、根节点下 4 层、每个聚合错误 8 个成员。标记循环和截断，省略堆栈，读取 cause/errors 数据属性而不执行 getter。非 Error 原因使用其字符串表示。类型转换或读取 Error 属性抛错时，为当前值输出无法显示的标记，保留外围结果与同级错误原因。外层 JSON 兜底、终端清理和通知长度预算继续生效。

前台完成通知保留显示项，直到所属调度批次提交工具卡片。通过运行的 toolUseId 找到当前挂载内的既有批次身份，不把 wire call ID 当作持久身份。与前台显示项一起保留排在前面的终态通知，使可见顺序与到达顺序一致。中间态 monitor 消息保留现有排空行为。批次提交后，在卡片后追加待显示内容，并在同一通知对象上标记 displayed。模型准入继续使用现有队列，因此重试或重新入队不会重复显示。即使队列准入丢弃模型通知，也保留前台显示引用。切换会话时清除待显示状态。没有活跃所属批次的完成通知无需等待。

显示屏障与模型准入分离：模型回合被拒绝或失败不能隐藏完成结果。不把模型提交移入调度回调，不引入第二个模型投递队列。

队列在准入或重新入队发生溢出时，标记被丢弃的通知对象。延后显示时跳过这些对象，但保留该显示批次所属的前台完成结果，即使对应的模型通知被丢弃。这样避免捕获的后台结果在淘汰后出现，并保留前台结果的可见性保证。

如果结果在淘汰前显示，即使模型通知随后被丢弃，界面历史也保留该结果。共享溢出汇总明确说明通知没有送达模型。界面汇总与模型丢失记录保留任务 ID；显示过结果不改变淘汰优先级，也不省略丢失记录。这项文案修改适用于现有 Ink 与 ACP 汇总消费方，不改变队列准入、模型载荷或持久化结果的统计语义。

## 验证与验收

- 有名称的失败运行在前台及模型通知中保留名称与 run ID，覆盖注册表先于脚本完成而结算的情况；后台标签和显式描述正确。
- 跨 VM 的聚合错误和 cause 结果保留内部原因；无法显示的成员不会破坏其他结果字段与同级原因；普通 Error 输出兼容。测试固定深度、成员数与访问次数上限两侧的行为，并覆盖循环、长度、跳过 getter 与省略堆栈。
- 显式 false 返回工具结果而不通知；true 作为正对照。删除 enabled 条件必须让新测试失败。
- 调度的工作流卡片先于更早后台通知及前台通知。模型失败时，各通知保持一次可见。溢出和会话重置不能泄漏或丢失待显示的前台结果。被淘汰的后台结果与取消后的中间态 monitor 消息不能在前台显示阶段出现。
- 结果在准入或重新入队淘汰前显示时，界面保留一次显示，模型载荷不含该结果，界面与模型汇总记录模型漏收。
- 运行相关 core 与 CLI 测试、构建、类型检查、格式和 lint，以及使用模拟提供方的交互式工作流完成测试。主机无全局 qwen，无法用它执行 E2E 基线；测试脚本的基线复现单独记录。

## 风险

嵌套错误格式化在新增的单错误上限内扩展错误内容。显示排序保留运行批次的引用，必须在批次完成或会话重置时释放。模型通知准入、取消语义和成功结果持久化应保持原行为。
