# 工作区 Skill 后台刷新

[English](workspace-skills-background-refresh.md) | [简体中文](workspace-skills-background-refresh.zh-CN.md)

## 问题

此前的[工作区 Skill 读取模型](workspace-skills-read-model.zh-CN.md)将状态响应缓存五秒。窗口内的读取无法观察 watcher 更新，
窗口外的首次读取则需要等待 ACP。ACP 不可用时，重放保留快照还会重置时间戳，
使调用方无法了解数据实际保留了多久。

## 设计

默认和指定工作区的 Skill 清单查询都立即返回已有快照。查询最多每秒触发一次
后台重新验证，间隔从任务启动时计算。并发查询复用当前任务；没有快照时，
查询共享并等待前台观测。冷读若在启动后一秒内失败，窗口剩余时间内的普通读取
直接返回不可用状态。较慢的失败不留下节流窗口，客户端应自行进行重试退避。

热读的后台重新验证在五秒后释放共享任务位置，让后续查询可以重试；
期限只停止等待，不终止观测或子进程执行。冷读和变更操作则等待 ACP 自身配置的请求期限
（默认十秒），ACP 不可用后再执行 daemon 本地枚举。门面不为这段前台序列另设期限，
较慢但成功的 ACP 或本地结果必须仍然可用。

任务位置超时后，成功的观测仍可发布，即使重试正在进行。发布要求失效代际未变、
所属工作区运行时仍然开放，且读取启动序号比最近发布的观测更新。使用序号而非
墙上时钟时间戳，避免时钟回退时旧结果覆盖较新的观测。已失效的观测不能发布；
只有占据共享位置的任务才能清除它。被取代的成功冷读会优先返回较新的保留快照；
没有替代快照时，才返回自身未缓存的观测，且不携带快照元数据。

只有已初始化且没有错误的观测才能原子替换快照。观测时间取任务开始时间，保守计入采集
耗时。重放保留数据、失败和释放任务位置都不能重置观测时间；迟到的成功发布
记录该次观测的开始时间。两个来源都无法枚举时，冷读
返回 `initialized: false`、错误信息且没有快照。客户端必须将其视为可重试的不可用
状态，不能当作成功初始化的空清单。

响应中的可选 `snapshot` 对象包含 `observedAt`（Unix 毫秒）、`ageMs`、
`refreshing` 和 `stale`。每次响应重新计算年龄；距上次观测至少一秒时标记过期。
`refreshing` 表示共享任务位置是否被占用，不包括位置超时后仍在继续的观测。
这些字段描述 daemon 的观测时间，不代表文件年龄，也不保证所有会话已经同步。
ACP 和 SDK 类型中的字段为可选：只有携带 daemon 保留观测的响应才提供这些
元数据。例如，直接运行时/配置状态、会话资源清单及旧 daemon 的响应均不提供。

显式失效会移除已知无效清单、清除节流并取代旧任务。在超时前完成的显式 ACP 预热成功也会使
已有快照失效，即使子进程此前已存活，让下一次清单读取看到子进程状态。预热超时后才发现通道在线时
同样报告成功，但会保留已有快照，因为子进程启动可能仍未完成；下一次读取返回这份保留数据，
并在每秒启动节流允许后进行后台重新验证，随后替换它。删除 Skill 和解析启用身份时，
均绕过保留快照和普通读取节流，等待独立观测；即使已有快照，ACP 不可用后仍尝试
本地枚举；只有两个新来源都失败时，才改由保留快照应答，而不是退化为旧名称启发式。
运行时删除被拒绝时保留已有清单，成功变更仍使其失效。状态查询不会
调用影响会话的 Skill 刷新控制命令。
前台回退仅使本地枚举器的缓存失效，以观察外部安装，同时保留门面快照。

## 范围与约束

失效代际和发布顺序保护快照，任务身份保护共享位置的清理，独立的运行时守卫检查归属。外部文件修改继续依赖 Skill watcher
和 Extension 来源重新验证；本次不引入跨进程文件系统版本。
不增加空闲轮询、自动会话修改或前端定时器。客户端可以显示响应中的快照年龄。
现有响应字段保持兼容。

涉及的层包括工作区服务的清单缓存及删除消费方、ACP/SDK 状态类型、针对性门面
测试和协议文档。

## 验证与验收

虚拟时间测试覆盖立即返回旧快照、精确的一秒边界、超过五秒的共享冷读、后台五秒
超时、ACP 超时后较慢的本地回退、重试、后台迟到成功/拒绝、持续轮询下每次变化的
六秒观测、乱序完成、失效、运行时关闭、
时钟回退和空闲回退时年龄不重置。覆盖不同名称的并发删除、拒绝删除后的清单保留、
冷读节流窗口内的单个/批量启用，以及预热后重新读取。现有变更操作和回退测试必须继续通过。使用构建后的 CLI 验证 HTTP
接口，不调用模型。执行构建、类型检查，以及受影响代码的格式和 lint 检查。

五秒预算为初始值，调整前应测量正常重新验证耗时和超时率；不能每秒重复取消慢
操作。运行时长期不可用时可以保留旧数据，但持续增长的年龄必须可见。
