# Web Shell 会话内搜索

[English](2026-09-19-web-shell-conversation-search.md) | [简体中文](2026-09-19-web-shell-conversation-search.zh-CN.md)

## 问题与范围

Issue #12231 要求在置底按钮旁提供搜索弹框，并直接定位命中内容。#10261 / #10612 的侧边栏搜索查找会话，每个会话只返回一段摘要，不能定位单条消息。#6824 和 #11111 涉及其它会话搜索界面。本次搜索当前 Web Shell 会话的用户和助手正文，包括 Markdown 和代码；不改动跨会话搜索、工具、思考内容或模型请求。

## 设计

在 `WebShellProps` 增加 `conversationSearchThreshold`，默认 10。用户和助手消息数严格超过阈值时显示搜索图标，不依赖置底按钮是否可见。图标位于左侧会话时间轴下方，采用 14px 图标与 20px 宽按钮，适配窄导航栏；时间轴刻度隐藏时同步隐藏搜索入口。各嵌入入口继承此配置。

复用 `DialogShell`、本地化文案、语义颜色和 portal root。打开时聚焦输入框；搜索防抖，展示高亮摘要，支持选择结果、上一个/下一个结果，Escape 关闭。保留输入草稿，不干扰进行中的回复。搜索专用文案随交互组件加载，不进入只读 HTML 导出。

通过会话所属的 turn-navigation client 分页扫描持久化 transcript，每页独立投影。先从 head index 获取快照，再带该快照请求指定起始位置；后续索引页复用同一快照。最多保留 200 条命中摘要，不把完整会话载入 live store。展示当前可用结果数量及截断状态。空查询结合 `stopAfterMessages` 用于探测显示阈值，无需扫描整个历史。按字面量进行大小写不敏感匹配，支持中文。

结果携带持久化 record 身份，以及从 turn index 获得的所属 turn ordinal。渲染消息 ID 在不同投影之间不稳定。定位复用历史浏览窗口：先定位轮次，必要时继续向后分页，将持久化 record 映射到当前 block/message，展开折叠内容、居中并短暂高亮。历史页继续遵守现有 LRU 缓存预算。实时消息从当前 transcript 快照搜索，按 source 身份与持久化结果合并。

## 生命周期与限制

关闭弹框、修改查询或切换会话会使未完成搜索失效。定位拒绝过期会话或修订版本的结果，并核对持久化轮次身份。部分回放和请求失败必须明确展示并支持重试，不能误报为已搜完且无结果。不支持 turn navigation 的旧 daemon 只能搜索已加载消息，界面明确提示范围受限。不新增 daemon API、全文索引或设置持久化。

## 文件与验证

实现涉及 Web Shell 入口 props、搜索组件、i18n、turn-navigation store、历史浏览 hook/handle、README 和同目录测试。仅使用合成会话数据。

验证 10/11 条边界和自定义阈值；live window 之外的旧消息；用户/助手/代码及中英文正文；多条命中消息；空查询/无结果；过期请求与会话切换；折叠与虚拟列表定位；草稿保留及流式回复连续性。覆盖浅/深主题、中/英文、桌面/移动端与 portal 行为。基线和本地构建 E2E 证据与单测/build/typecheck 结果分开记录。

## 待决问题

无。阈值属于宿主组件配置；设置页控件和跨会话搜索不属于本 issue。

## 宿主公开消息定位

嵌入组件通过 `shellRef` 提供 `WebShellApi.navigateToMessage({ sessionId, recordId, signal? })`，请求和结果类型从包入口导出。宿主先经既有 provider 生命周期选中会话与工作目录；此接口不负责切换会话或发送消息，也不依赖时间轴可见性、搜索弹框或消息数阈值。

`recordId` 必须是持久化转录记录 ID，不是渲染块 ID、时间或摘要。定位按冻结快照扫描历史，找到该用户/助手记录即停止，只保留一个目标，然后复用既有有界历史视图加载、滚动并高亮。重复文本不会定位到另一条记录；很旧的目标仍有线性读取成本，没有新增服务端记录索引。

返回 `status`：`located` 表示目标已激活，滚动与高亮在随后 React 渲染生效，不代表动画结束；`not_found` 表示没有该持久化用户/助手记录；`not_ready` 表示会话、历史或视图未就绪；另有 `session_mismatch`、`unsupported`、`cancelled` 和 `error`。宿主应响应就绪状态，不能把未就绪当成没有命中。AbortSignal、通过校验的新定位请求、会话/工作目录或转录版本变化、组件卸载都会使旧请求失效。过期 API、已取消的信号、会话不匹配或空记录 ID 等被拒绝的调用，不会取消当前有效定位。

现有跨会话搜索仍只返回会话与一条摘要，不带消息记录 ID。宿主搜索结果需保留该 ID 才能接入精确定位；扩展搜索接口、归档搜索和宿主界面是独立工作，不能因公开定位 API 已提供便认为这些能力也已具备。
