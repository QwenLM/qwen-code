# 转录区搜索与结构导航设计

[English](transcript-search-navigation.md) | [简体中文](transcript-search-navigation.zh-CN.md)

状态：已在 Ink 虚拟视口中实现。
关联：PR #17024，需求 #16995 和 #16996。

## 1. 背景与目标

开启 `ui.useTerminalBuffer` 时（默认的 Virtualized History 路径），会话显示在应用内部的视口中。宿主终端的滚动历史和搜索无法访问这些内容，此前只能按距离移动：逐行、逐页、到开头、到末尾。用户无法直接找到早先某条命令的输出，也无法直接向前跳一轮。

本功能有两个目标：

- 允许用户搜索**整个当前会话**，并将视口锚定到某个结果，包括结构化工具结果内部的文本。
- 允许用户一次移动一个**轮次**或**工具输出块**，而不改变已有逐页滚动键的含义。

### 1.1 范围

支持 Ink 渲染器，即 `ui.useTerminalBuffer` 为 true 时由 `MainContent` 返回的虚拟视口。

本次不支持：采用独立 scrollbox 的 OpenTUI、旧 Static 历史模式、渲染后的 Markdown 中每次命中的行内高亮，以及自动展开包含命中的已折叠工具块。搜索不跨会话。

### 1.2 术语

| 术语         | 含义                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 条目         | 虚拟视口渲染的一条历史，而不是一行文本。                                                                               |
| 轮次         | 从 `type === 'user'` 且 `sentToModel !== false` 的用户条目开始，到下一个这样的条目之前的内容。steer 注入不开始新一轮。 |
| 工具输出     | 一个 `tool_group` 条目，可以包含多个工具调用及结果。                                                                   |
| 读取位置锚点 | `getScrollIndex()`：向上滚动时的顶部条目，或跟随输出时的最后一个条目。                                                 |
| 导航游标     | 单独记录请求的导航目标，不是滚动偏移量。                                                                               |

## 2. 共享条目模型

`MainContent` 使用 `buildVirtualItems` 构造虚拟列表。搜索和结构导航使用**同一个函数和同一批条目引用**。索引约定如下：

| 索引     | 内容                                                                       |
| -------- | -------------------------------------------------------------------------- |
| `0`      | `vp-banner` 哨兵项，永远不是导航锚点或搜索命中。                           |
| `1..N`   | 已提交的历史，按显示顺序排列。                                             |
| `N+1..M` | 使用负 ID 的待处理条目；与已提交条目区分，避免以后提交历史时发生 ID 冲突。 |

如果实时待处理工具组与其已提交副本具有相同的 `batchId`，构建器会去掉已提交副本。互不相关的批次不按 `callId` 去重，因为 core 历史压缩和 provider 适配器可能重新生成或重用这些 ID。因此，即使发生了上述去重，搜索返回的索引仍然指向视口实际显示的条目。

这里刻意共享构建器，而不是独立搜索 `uiState.history`。如果不同功能各自过滤和去重相同的历史，容易出现跳转错一项的问题，在长会话中也很难排查。

## 3. 搜索处理与渲染

### 3.1 匹配

`searchTranscriptItems` 将每种受支持的条目转换为可搜索文本：

- 普通带文本的历史：使用 `item.text`，包括用户提问、助手回复、思考、提示和错误。
- 工具组：工具名称、说明、原始参数、结果展示内容（结构化结果序列化为 JSON）、Ctrl+O 完整详情和提示信息。
- 工具使用摘要：其摘要文本。

匹配在原始文本上执行，不区分大小写，每个条目最多一条命中。没有面向用户的文本字段的其他变体（例如 `about`、`help` 或 `stats`）不提供可搜索文本。

搜索结果结构如下：

```ts
interface TranscriptSearchMatch {
  index: number; // 在 buildVirtualItems 输出中的索引
  itemType: string; // 例如 'user' 或 'tool_group'
  snippet: string; // 适合终端显示的单行上下文
}

interface TranscriptSearchResult {
  matches: readonly TranscriptSearchMatch[];
  truncated: boolean; // 只有确实省略了更早的命中时才为 true
}
```

`getSearchableText` 使用以条目对象身份为键的 `WeakMap` 缓存。因此，普通重新渲染不会重复提取稳定的已提交条目的文本。待处理条目通常会重新创建，因而不会命中缓存，也就不会错误地复用旧结果。

### 3.2 上限与顺序

匹配器从最新内容向最早内容扫描，再将结果反转后显示。最多返回 500 个命中条目。有 501 条命中时，第 501 条（最新一条）仍会保留，结果按视口索引升序排列。

在**添加下一条命中之前**判断 `truncated`。因此，结果恰好达到上限时，不会错误地显示 `500+`；必须另外存在一条被省略的命中，才算截断。

### 3.3 摘要与终端安全

摘要在**原始**命中位置前后各扩展 48 个字符，再执行 `sanitizeTerminalText`，最后折叠连续空白。它不会在展平文本后重新搜索查询词。这对以下两个具体场景很重要：

```text
"beta  gamma"
  => 在原始文本中匹配 "beta  gamma"
  => 摘要在命中处包含 "beta gamma"，而不是回到条目起点 0

"before\x1b]0;ATTACK\x07 after"
  => 摘要不包含原始 ESC 或 BEL 字节
```

搜索仍在原始文本上执行，因此含控制字节的内容也可以被查询；只有渲染内容经过安全清理。这里不新增“所有外部工具生产方都已净化数据”的安全承诺：搜索显示边界本身也必须执行清理，并由测试覆盖。

## 4. 搜索模式仲裁

`InputPrompt` 已经复用同一个输入缓冲区来执行 Ctrl+R 反向搜索。转录区搜索沿用这套模式，而不是另加一个输入组件或新的模态状态。

| 输入                              | 搜索打开时                                                              | 关闭时                                               |
| --------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------- |
| `Alt+S`                           | 进入搜索，保存草稿、光标和读取位置锚点；清空缓冲区用于新查询。          | 不适用。                                             |
| 可打印查询文本                    | 更新查询并重新匹配，不接受提示建议或听写输入。                          | 只有搜索关闭后，输入文本才重新交给普通提示词输入框。 |
| 上 / 下方向键                     | 跳到上一个 / 下一个命中，可循环切换。                                   | 不适用。                                             |
| `Ctrl+R`                          | 忽略：两个模式不能共用草稿存储槽。                                      | 一次 `Esc` 恢复原草稿。                              |
| `!`、`?`、`Tab`、`Right`、`Enter` | 不切换 shell 模式、不打开快捷键面板、不执行格式补全，也不接受提示建议。 | Enter 保留选中的命中。                               |
| `Esc`                             | 关闭搜索，恢复原草稿和保存的视口状态。                                  | 按下节规则恢复跟随状态。                             |

模式保护不仅覆盖命名快捷键，也覆盖普通输入、粘贴和 `/export` 补全。否则，`/export` 或可打印字符 `!` 可能绕过已有快捷键保护，将格式补全或建议文本插入查询。

## 5. 视口恢复

打开搜索时，保存 `getScrollIndex` 返回的索引。视口跟随输出时，该索引是最后一个渲染条目的索引。条目构建器在搜索打开和关闭时都保持可用；若激活时使用的是“未打开时为空”的列表，就会丢失尾部状态。这样才能正确识别从实时尾部开始搜索的情况。

```text
Enter：将视口保留在已接受的命中位置，恢复草稿。

Esc，且已保存跟随状态：
  scrollToEnd() -> 重新启用跟随。

Esc，且此前正在阅读其他位置：
  scrollToIndex(saved index) -> 恢复该读取位置，必要时按滚动范围裁剪。

没有保存的索引：
  scrollToEnd() -> 安全回退到跟随状态。
```

当最后一条助手回复高于终端时，这一区分很重要：`scrollToIndex(last)` 会把该消息的开头放到视口顶部，但关闭后续自动跟随。这并不等于恢复到底部。

## 6. 结构导航

### 6.1 按键分发

| 按键            | 操作                                     |
| --------------- | ---------------------------------------- |
| `Alt+PgUp`      | 上一个轮次锚点。                         |
| `Alt+PgDn`      | 下一个轮次锚点；越过最新一轮后恢复跟随。 |
| `Ctrl+Alt+Up`   | 上一个工具输出组。                       |
| `Ctrl+Alt+Down` | 下一个工具输出组。                       |

`ScrollableList` 负责所有滚动相关按键，由条目所有者提供 `onNavigateStructure`。列表本身不理解转录区语义。结构导航匹配在普通逐页滚动**之前**执行，因为普通 `pageup` 绑定刻意不限制修饰键。

修饰键是必要条件：`Meta+PgUp` 不等于普通 PgUp。负向绑定测试保证普通翻页键不会意外变成轮次跳转。未提供 `onNavigateStructure` 时，Alt+PageUp 保持原有的逐页向上滚动行为。

### 6.2 导航游标与重置

`findAdjacentAnchor(items, from, direction, kind)` 不包含起点。因此：

- 从第 N 轮中间的条目向前跳时，先落到该轮自己的用户提问，而不是更早一轮；
- 从已经位于第 N 轮提问处的条目向前跳时，落到第 N - 1 轮；
- 找不到匹配时返回 -1，不会绕到会话的另一端。

视口会把请求的滚动位置裁剪到最大允许偏移量。目标已经在最后一页内时，后续调用可能不再改变其锚点。因此，连续结构跳转不能使用新的锚点作为下一次起点。`createTranscriptNavCursor` 另外记录所请求的目标；即使视觉偏移量被裁剪，连续按键也会每次前进一个边界。

当读取位置因其他原因发生变化时，游标会重置：

1. 键盘逐行 / 逐页滚动。
2. 鼠标滚轮或拖动滚动条。
3. 外部条目定位，例如通过 `ScrollActions` 执行的搜索跳转。
4. 内容追加**确实移动了**读取位置锚点（自动跟随）。如果追加后锚点未变，不清除游标，避免持续的流式输出反复重放同一次被裁剪的跳转。

导航游标不负责跟踪自动跟随：自动跟随状态仅由视口自身使用；越过最新锚点时，可通过 `scrollToEnd` 恢复。

### 6.3 合并输入

滚轮和拖动事件可能在同一帧内合并。结构跳转会在分发前取消已排队的滚动冲刷，避免排队的滚轮增量在跳转后执行，将视口移出请求的条目。

### 6.4 外部接口与失败情况

这是本地 UI 功能，没有服务端 API 或错误码接口。失败情况限定如下：

| 情况                  | 行为                                                                                       |
| --------------------- | ------------------------------------------------------------------------------------------ |
| 没有更早 / 更晚的锚点 | 显示 `At first turn` / `At latest turn`，不循环跳转。                                      |
| 旧 Static 模式        | `scrollToIndex` 返回 false，搜索提示需要 Virtualized History。不把未实现的模式宣称为可用。 |
| 目标已在最后一页      | 滚动裁剪可能使画面保持不动，但游标仍会前进。这是裁剪，不是未执行跳转。                     |
| 空查询                | 不执行匹配。                                                                               |
| 空搜索结果            | 命中位置为 -1。随后出现新命中时钳制到 0，继续用方向键导航不会因 -1 出现死键或错一项。      |
| 搜索时出现新输出      | 重新钳制活动命中位置，不跳到最新命中。                                                     |
| 导航时出现新输出      | 仅在实际读取位置锚点移动时重置。                                                           |

## 7. 验证证据

以下测试类型已经作为固定测试保留，不是计划：

- 匹配包含结构化工具输出和 Ctrl+O 详情文本。
- 待处理条目和去重后的条目，其索引计算仍与渲染结果对齐。
- hook 测试覆盖初始选择、循环切换、负位置、列表增长和方向对称性。
- 函数级测试覆盖命中上限顺序、恰好满额、含大量空白的摘要和控制序列。
- 按键测试包含缺少修饰键时的负向断言。
- 搜索模式测试覆盖草稿、查询接受、输入清理、语音抑制，以及保存的视口 / 跟随状态恢复。
- 导航游标测试覆盖裁剪后的连续跳转、锚点不变的追加、真正的自动跟随和手动滚动重置。
- 合并的滚轮输入不会移走跳转目标。

验证计划还包括真实 tmux 交互，不会以仅由测试输出的“门禁通过”代替真实交互行为。

## 8. 兼容性与限制

已有逐行 / 逐页滚动键保持原有行为。没有新增设置、迁移、服务端路由、外部协议或安全配置变更。源码搜索仅限当前会话。

OpenTUI 未修改。已有 `<Static>` 历史不能按条目定位，明确不支持。不能仅因其他实现使用了本文相同的术语，就将其问题标记为已经测试。
