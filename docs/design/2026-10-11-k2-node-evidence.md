## Problem and supported boundary

Application `DRAINED` does not prove that a container or its descendants stopped, or that the original CSI target was unpublished. Containerd events lack a durable replay cursor, and CSI's successful empty-target retry cannot reconstruct an earlier publication. Diagnostic logs cannot supply these missing facts.

The first source supports an isolated Linux node, cgroup v2, one nonprivileged bare Pod with `restartPolicy=Never`, the reviewed file-only runtime, and a continuously observed original container. It excludes cgroup delegation, process escape or migration, extra containers, exec, unsupported admission changes, and runtime/plugin/source restart. Qualification must verify these properties on the actual pinned ACK artifacts. Signatures authenticate a source; they do not prove containment or completeness.

## Two source roles

Add a standalone Go module under `packages/k2-node-evidence`. One binary has two explicit roles. `gateway` owns the containerd socket and projects only fixed original task and CRI identity reads; it exposes no generic gRPC relay, shell, path, PID, kill, exec or create API. A read-only socket mount is still an administrative runtime capability, so this small helper is part of the trusted implementation.

`source` owns the continuous cgroup custody, CSI frontend and durable journal. It has no raw runtime socket. Its gateway channel and coordinator control/read channel authenticate fixed certificate principals. Control accepts only reviewed prospective Pod identities, their later exact UID association, and the persisted normal-stop intent. Workers and tools have no source control privilege. Configuration and image/binary digests are deployment-owned and must be reviewed before qualification.

Custody requires the actual host PID namespace, restricted host /proc observation and retained descriptors below the host cgroup v2 root. The deployment must document these permissions and the source's inability to mutate or delegate the original cgroup. Host namespace access is part of the trusted boundary; container-local PID/cgroup observations cannot qualify the original task. The gateway retains the first complete terminal observation and rejects any changed exit status, timestamp or identity on later reads.

The source does not persist credentials, environment, CSI secrets, VolumeContext or unrestricted RPC payloads. Record only fixed identity projections and operation results. Unsupported methods or parser versions fail closed for a registered original scope.

JSON control, configuration and gateway response fields require their exact declared spelling. Reject unknown fields, duplicate names and case aliases, including aliases inside nested objects. The HTTP routes are node-source scoped: coordinator-only original registration on the gateway, source-only runtime/original reads, and coordinator-only ARM, UID binding, stop intent and journal reads on the source. None selects a user workspace or grants a worker runtime privilege.

## Durable journal and incarnation

The next journal format, `qwen-k2-node-source/4`, closes the interval between
the saved stop and backend unpublication. While awaiting unpublication the
source continues checking the retained original pidfd, leaf, Pod parent and
events descriptor. Immediately before forwarding NodeUnpublishVolume and
after the actual backend success, it requires the same complete terminal,
unpopulated custody tuple as ORIGINAL_STOPPED. It persists these fresh
observations in UNPUBLISH_BEGIN and UNPUBLISH_OK, alongside the unchanged saved
terminal runtime identity. An observation error, populated descendant, object
replacement or lost descriptor permanently blocks the scope. The Java reader
requires both observations to equal the original stop; a rehashed substitute
or a journal without them cannot supply current unpublication evidence. Old
v1–v3 journals remain historical artifacts and are rejected by the v4 reader.
This closes a later observation interval; it does not establish confinement
before first execution or authorize physical release.

The journal is on a separate source disk outside the worker and its PVC. It uses exclusive ownership, bounded length-delimited records, contiguous sequence numbers, predecessor hashes and `fsync` before acknowledging a source transition. Each record binds its format, source incarnation and exact original scope. The reader rejects truncation, gaps, duplicate sequence numbers, hash mismatch and unknown fields. A write or sync failure poisons the live source; later calls cannot repair an unknown append outcome.

Readers require the independently retained durable head cursor as well as the journal bytes. A hash-valid shortened prefix cannot replace that head. Each CSI completion must bind its durable begin cursor and the exact publication/stop dependencies; a record's sequence alone cannot establish those dependencies.

The initial process creates a fresh incarnation and records its actual node boot, runtime and plugin identities before accepting ARM. A source restart never continues an old live scope. A coordinator restart may read the unchanged, verified original journal, including a committed unpublish outcome. Retention cannot remove a prefix needed by an unreleased retirement. Journal verification alone never grants `OriginalStopped` or `OriginalUnpublished` qualification.

Runtime and plugin identity include actual Unix peer PID, process start time and executable digest. The source also binds the gateway incarnation. The frontend retains the first kubelet and registrar process identities; CSI begin records bind the actual kubelet caller. A backend reconnect, daemon exit or executable replacement invalidates the live chain. The gateway and plugin backend each use one retained connection and cannot silently reconnect to a replacement process.
