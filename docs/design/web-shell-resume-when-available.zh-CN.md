# 模型可用时继续中断任务

[English](web-shell-resume-when-available.md) | [简体中文](web-shell-resume-when-available.zh-CN.md)

## 问题与范围

Issue #13784 希望任务因模型限流停止后，由用户选择等待恢复。现有恢复提示和
继续执行入口已经保留上下文并修补悬空工具结果。本次仅增加该入口的延迟触发，
不修改核心恢复算法或请求进行中的自动重试策略。

等待由用户明确选择，有可见状态，也可以取消。仅打开中断会话不会开始执行。
普通认证、计费、传输错误，以及结果不确定的提交，会终止本次等待。

## 设计

恢复提示检查最新的有效对话块。只有终止任务的模型错误明确包含限流文案、429
错误码、带恢复时间的额度耗尽文案，或反馈中的周期 Token 额度文案时，才在
**继续执行**旁显示**可用时继续**。后续用户、模型、工具或取消内容会使旧错误失效。
这项界面识别不会把普通 HTTP 403 变成可重试错误。会话恢复状态必须独立允许
继续执行；正常或历史缺失会话不会因此获得恢复权限。

点击后等待 60 秒，再调用现有继续入口。后续明确的限流失败将等待间隔翻倍，
最大五分钟。总等待期限为六小时，与持续重试的期限保持一致。提示展示下次尝试
时间及“取消等待”。已传到界面的错误文案中若明确给出重试间隔或恢复时间，
优先采用它；“每五小时”这种周期描述不等于明确的恢复时刻。

当前没有模型健康探测接口。会话状态读取只返回恢复信息，不能检测模型可用性。
每次尝试都是真实的继续执行。执行成功后结束等待；已接收的请求若再次明确限流，
只有最新恢复状态允许继续时才安排下次尝试。现有会话入口负责提交、请求关联、
事件回放和完成处理，不重放已完成的工具，也不添加模拟用户消息。缺失的工具
结果继续使用已有中断错误修补；点击新按钮即授权现有修补行为。

等待绑定当前提示组件、会话连接、工作目录、模型及中断任务。取消、组件卸载、
连接替换、模型切换、断连、其他任务活动和阻塞状态会停止后续尝试。由本次等待
启动的请求执行期间，使用已有进度和取消控件。提交结果不确定时停止等待，不
自动重复提交。原有继续按钮仍然立即执行，同时取消已安排的等待。

## 文件与边界

- Web Shell 恢复提示、限流文案辅助函数、翻译和针对性组件及辅助函数测试。
- 使用现有模拟 daemon 传输的浏览器回归覆盖。
- 不增加 daemon 路由、SDK 字段、核心错误分类器或恢复算法。
- 现有继续请求仍按当前会话所属运行时处理，保留工作目录和提交检查。
- 当前终止错误没有透传模型响应头。本次只遵循已到达界面的文案中的重试或恢复
  时间；响应头透传及统一请求重试进度仍属于 #12020。
- 等待不会在离开界面、关闭界面或重启后保留。

## 验证

覆盖主动选择、中文周期额度及 429 识别、普通 403、退避、服务时间提示、取消、
会话与模型切换、其他活动、恢复状态刷新顺序、成功后仅恢复一次、非限流错误、
提交结果不确定及历史缺失。在真实浏览器中使用合成错误验证按钮位置和传输
请求，并通过本地模拟模型验证全局 CLI 基线及构建后的继续执行链路。
随后完成构建、类型检查、针对性测试、完整差异自查及独立审查。
