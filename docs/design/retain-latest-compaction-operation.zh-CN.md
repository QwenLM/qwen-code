# 压缩时保留最近一组完整操作

[English](retain-latest-compaction-operation.md) | [简体中文](retain-latest-compaction-operation.zh-CN.md)

## 问题

全量历史摘要可能丢失模型刚看到的精确测试错误、编辑参数或结果。#4599 将早期按比例保留尾部改成全量摘要加恢复；本设计只保留一组完整响应，不恢复按历史百分比切分的方案。

## 设计

用最新 model Content 作为响应边界：main 将一次接受的响应汇总到这一条记录。保留它及随后已存储的 user 记录，前提是前面存在可摘要的非合成模型响应。验证每条工具结果恰好匹配一个调用，包括待提交结果；不完整或有歧义的组不保留。待提交输入只参与验证，由发送路径负责提交，不复制到替换历史。

冷请求和缓存共享请求都只摘要旧前缀。从前缀恢复最近文件、图片和计划/子代理状态，保留标准摘要/确认前缀，接一条包含恢复上下文与时序提醒的 user 过渡消息，再原样附上尾部。显式标记三条记录的合成前缀，供启动/回退检测与检查点往返恢复使用。时序提醒明确尾部发生在摘要覆盖的历史之后。保留原内容对象以保留签名、工具回执和 prompt 归属。

包含待提交结果的完整操作，按既有估算器必须不超过 min(20,000 tokens, 配置窗口的 20%)，否则全量压缩。请求载荷超限和截图超限恢复也保留既有全量摘要行为。现有膨胀检查与发送硬门禁不变；本改动不解决独立的恢复附件总预算问题（#16895）。

冷请求有 provider 用量时，只扣掉被摘要的前缀，再加新摘要与恢复成本；保留操作已包含在原始计数中；若 provider 计数只包括 prompt 而不含最新模型输出，由调用方显式补充这一项。无可用用量或使用缓存共享时，用可见历史差值记账，保留不可见的 system/tool 余量。从图片恢复额度中扣除已保留的工具图片。在普通、延迟硬恢复和 hosted 检查点中显式记录合成前缀长度，避免删除/恢复将原始操作误认成生成摘要。

## 范围与风险

不新增设置，不修改阈值，不重写协议，不扩大历史保留范围。无法识别或不完整的工具操作回退既有全量压缩。有限尾部以部分压缩率换取精确近期信息。不声称真实模型质量或延迟改善。缓存共享仍遵循既有 provider 和容量门禁；只摘要前缀可能复用较短前缀。

## 文件与验证

改动涉及压缩服务、一个纯边界辅助函数、压缩元数据和三处检查点写入，以及针对性测试。验证多工具配对、缺失 ID、重复/无匹配结果、待提交结果、签名/归属、恢复组装失败与计划提醒、大尾部、超限路径和重复压缩。验证两条摘要请求路径排除尾部，以及检查点前缀长度。运行相关测试、构建、类型检查与 lint。本环境没有全局 CLI 基线；脚本级证据与真实 CLI/模型测试分开报告。

## 验收与开放问题

被选尾部的内容与身份均保留，待提交输入只出现一次，摘要只包含旧历史，不安全选择回退既有行为。本有限迁移没有待决设计问题。真实模型任务质量、token 成本和延迟留待后续测量，不作为本 PR 已达成的收益。
