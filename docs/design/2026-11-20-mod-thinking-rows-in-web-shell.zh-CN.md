# Web Shell 中的 Mod 思考行

[English](2026-11-20-mod-thinking-rows-in-web-shell.md) | [简体中文](2026-11-20-mod-thinking-rows-in-web-shell.zh-CN.md)

状态：已实现。本文让 Web Shell 绘制 Mod 对思考行的改写，在 #13749 跟踪。它接在 [Web Shell 中的 Mod 回复行](2026-11-18-mod-rows-in-web-shell.zh-CN.md) 之后，把终端里来自 [Mod 思考行](2026-11-16-mod-thinking-rows.zh-CN.md) 的 `Thinking` 站点带到 Web Shell。

## 问题与现状

Web Shell 会话的 Mod 能改写用户看到的回复块，但改写不了模型的思考。bridge 只声明了 `AssistantMessage`，所以会话不提供 `Thinking` 站点，它的 hook 永远不会运行。一个翻译模型英文输出的 Mod，在 Web Shell 里只翻译回复，每段思考都保持模型的原文；而两个终端都会在思考展开后翻译它。

Web Shell 在两个地方绘制思考。旁边没有工具的思考自成一行，折叠为"思考完成"。紧挨着工具调用的思考，会作为一行折进紧凑工具摘要。紧凑视图始终开启，所以大多数思考画在这里。子代理的思考画在它的工具卡片里；卡片离开对话记录窗口后，这些思考会被画成普通思考。

## 目标与非目标

目标：

- Web Shell 中的 `Thinking` 站点，覆盖独立的思考行和折进工具摘要的思考行，契约与终端相同。
- 一段思考只有在被展开且出现在屏幕上时才运行 hook。再次展开、刷新页面或打开第二个标签页时，只要答案仍在缓存中，就会复用它。
- 存储的思考和模型读到的内容保持原文。

非目标：

- 折叠行（"思考完成"、"已思考 12s"），由宿主绘制。
- 子代理的思考，无论在工具卡片内还是卡片外，与终端的子代理视图相同。
- 导出的对话记录，按原样绘制思考。
- 在 `$.ui.invalidate('ui.render')` 时重绘页面已经持有的思考，与回复行相同。
- 移除 `MessageRewriteMiddleware`。两个站点都绘制之后 Web Shell 不再需要它，但 VS Code companion 仍会显示它的改写消息，所以是否移除需要单独决定。

## 兼容契约

以下部分遵循 Mod 作者契约和终端的 `Thinking` 站点：

- `Thinking` 仍是 Qwen Code 独有的站点。Web Shell 的事件就是终端的事件，只是画在 desktop 上：`{ surface: 'desktop', component: 'Thinking', requestId, props: { text } }`。`text` 是思考的 markdown，不带尾部空白。hook 用 `next(...)` 传下改写后的 props；`next(e)` 保持原样。
- props 保持唯一的键。改写后的 `text` 最多 100,000 个字符，除制表符和换行外不含控制字符。思考需要有非空白文本才会被提供。
- 与回复行一样，`requestId` 是 component 和 props 的摘要，所以文本相同的思考和回复块是不同的行。
- 没有 `component` 匹配条件的 hook 也会收到思考行，与终端相同。

## Qwen 的设计决策

### 与回复行一起声明

bridge 在 `_meta["qwen.modRows"]` 中声明 `["AssistantMessage", "Thinking"]`，子进程把 `Thinking` 及其唯一的字符串 prop 加入它检查的行。路径上其他环节都不按站点区分。路由、SDK、会话的行队列和页面的 asker 原样服务两个站点。

不新增能力标签。Web Shell 向较旧的 daemon 请求思考行时会得到 `unhooked`，因为那里的子进程不认识 `Thinking` 行。页面随后不再为该站点请求，回复行照常请求。

### 由展开后的正文发起请求

独立的思考行和工具摘要里的思考行用同一个正文组件绘制展开后的思考。在实时对话记录中，这个正文会换成向会话的 Mod 请求的版本。正文只在思考及其所在的工具摘要均展开时挂载。折叠思考或摘要都会撤回尚未开始的请求，工作流摘要保留工具详情时也一样。

正文在思考完成、文本非空白且与视口相交时发起请求，使用与回复行相同的一次一个的 asker。新工具调用把已展开的思考从摘要末尾移到该工具之前时，思考保持展开。流式输出时显示流式内容，完成后才请求。思考和回复共用会话缓存，最多保留 1,000 条非活跃行。只有正文读取 asker，所以思考的标题行保持它们的 memo 边界，不会随每个流式分片重新渲染。

### 哪些思考

页面提供会话自己模型的思考。画在工具卡片里的子代理思考不提供。卡片离开对话记录窗口后，子代理的思考也可能画在卡片外。这时页面会在思考上保留父工具，与它对子代理文本的做法相同。这样的思考不会并入它前面的模型思考，也不会被提供，无论它自成一行还是折进工具摘要。

### 什么保持原文

页面只在展开后的正文里绘制改写。存储的思考和折叠行保持模型的原文。思考旁的内置翻译按钮翻译的是原文，与翻译类 Mod 的工作重复，所以页面一旦绘制了 Mod 对某段思考的改写，就隐藏该思考的翻译按钮。如果重放给这一行带来了不同的文本，或者展开后的正文恢复为原文，按钮会重新显示。hook 保持原样的思考保留按钮，子代理的思考也保留。

### 导出

导出构建会把可替换的正文换成普通正文，机制与回复行相同。导出的文件绘制原始思考，不带任何 Mod 代码。

## 验证与验收

单元测试：

- ACP：声明两个站点的客户端得到两个站点，只声明一个的得到一个。思考的 props 必须恰好是 `{ text }`，且为字符串。
- bridge：`initialize` 声明两个站点。
- Web Shell 的思考行：同一个 root 依次经历流式输出、完成、展开、折叠、再次展开。只有在思考完成、展开且出现在屏幕上时才请求，并去掉尾部空白。离开屏幕后保留答案，再次展开时绘制保留的答案，不再请求。改写后隐藏翻译按钮，折叠后也保持隐藏。
- Web Shell 的其他情形：折叠的思考、空白思考和子代理的思考都不请求。紧凑工具摘要中，折进的思考展开后请求，随后不再显示翻译按钮；子代理的折进思考不请求，保留按钮。会话对思考行答 `unhooked` 后，页面不再请求思考，回复行照常请求。
- Web Shell 的紧凑摘要：新工具调用结束已展开的流式思考，并把它移到工具之前。该思考保持展开并显示改写。关闭工作流摘要后，在可见性观察器报告折叠之前，已排队的思考请求会被撤回。
- Web Shell 的对话记录：缺少父工具的思考与模型的思考保持分开并保留父工具，紧凑折叠会带上父工具。
- Web Shell 的会话重放：独立思考行和摘要内复用的思考行，如果当前文本未改写，就会显示翻译按钮。已展开的思考行即使保留相同文本，只要新的会话连接未改写它，也会恢复翻译按钮。
- 变异检查：去掉子代理判断、尾部空白处理、合并时的父工具规则、折叠中的父工具或翻译按钮的隐藏任一项，相应测试都会失败。

一个集成测试运行真实的 `qwen serve`，其中探针 Mod 挂了 `Thinking`，模型分两个分片流式输出一段思考：

- 思考行被改写，第二个客户端得到第一次的答案。
- 带有回复标志的 props 会失败，Web Shell 不绘制的站点答 unhooked。
- 回放的思考文本就是被请求的那一行的文本。

在真实 Web Shell 中做了浏览器检查，共两个回合：

- 第一个回合里，文件读取前后各有一段思考，都折进了工具摘要；第二个回合有一段独立思考。
- 所有思考折叠时，hook 没有运行。
- 展开后，独立思考显示第 1 次渲染；折叠再展开后仍是第 1 次。折进的两段思考分别显示第 2、3 次。
- 刷新后和在第二个标签页中，三段思考都显示第一次的渲染，Mod 日志里仍是三次渲染。

导出渲染器增加了 343 字节，从 2,146,831 字节变为 2,147,174 字节，预算为 2,148,200 字节。

验收：在 Web Shell 中打开 `experimental.mods` 并安装一个改写 `Thinking` 的 Mod 后：

- 屏幕上每段已完成且展开的思考都显示改写后的文本，无论它自成一行还是在工具摘要中。
- 刷新后显示缓存中的改写，无需再次运行 hook。
- 一直折叠的思考永远不会运行 hook。

## 风险与待定问题

- hook 需要等待模型调用的思考，展开时先显示原文，答案到达后高度会变化。
- 工作流摘要折叠时仍保留各行。重新展开摘要后，思考恢复先前的展开状态，并显示缓存中的答案。
- 页面只有在绘制了改写之后才知道一段思考已被改写。因此折叠的思考在展开前仍显示翻译按钮，刷新后也是如此，尽管会话已经保留了答案。
- 本步之后，导出渲染器距离预算还有 1,026 字节。
